## 3. 차이 목록 (D1–D26)

### 3.1 평가 설정

- **D1 시뮬 에피소드 수.** 논문 표 1 캡션은 "across 400 rollouts"라고 씁니다. 저장소 `configs.py`의 `_ise()`는 `n_episodes=800`을 pick_bar, push_bar, brick에 씁니다. faucet과 box는 400입니다. `README.md`도 같은 값을 적습니다. 표준오차 해석이 √2배 달라집니다(`03` §1.2).
- **D2 실패 처리.** 원문은 실패 에피소드를 어떻게 세는지 적지 않습니다. `scripts/rollout.py`와 `scout/envs/metaworld/rollout.py`는 `max_attempts = 14` 시도를 실패로 보고 14를 씁니다. 평균 시도 수가 이 상한에 직접 의존합니다.
- **D3 문 최대 시도.** 논문 표 2 캡션은 "a maximum of 20 steps"입니다. `configs.py`의 문 설정은 `max_attempts=30`입니다.
- **D5 문 평균 스텝.** 논문 §5.1은 "average number of steps used for successful trials"라고 씁니다. `scout/envs/door/rollout.py`의 `save()`는 `avg_steps = mean(step_ids)`로, 실패도 포함합니다. 실패 시도는 `finish(step_id, False, ...)`에서 마지막 인덱스를 씁니다.
- **D16 문 롤아웃의 행동 선택.** 논문은 가장 높은 가중치의 제안을 실행한다고 씁니다. 저장소의 `teleport()`(`scout/envs/door/suction_sim.py`)는 가중치 순서대로 후보를 시도해 **접촉이 되는 첫 후보**를 고릅니다. 접촉이 실패하면 `continue`로 시도 한 번을 쓰고 이력에 기록하지 않습니다. `closest_point=True`(기본)에서는 제안을 대상 링크의 가장 가까운 점으로 옮기는 후처리도 합니다. 논문은 이 두 단계를 적지 않습니다. 성공률과 평균 스텝 모두에 영향이 있을 수 있습니다.
- **D17 "w/o TTT" 정의.** 논문 B.3의 "Raw GMM"은 q가 없는 **독립 학습 정책**이며, 실로봇 "w/o TTT"도 이것입니다. 저장소 README의 "without test-time adaptation"은 SCOUT 가중치에 `--ttt-steps 0`(q = q0, 샘플링)을 준 것입니다. 저장소에는 B.3 기준선을 만드는 설정이 없습니다(`grep -rniE 'raw.?gmm'` 0건). 실로봇 비교의 "적응 효과"는 이 차이 때문에 분리되지 않습니다(`03` §3.5).

### 3.2 학습과 손실

- **D4 내부 손실 스케일과 α.** 논문 식은 시점 평균의 **제곱 노름**입니다. `inner_update()`는 `F.mse_loss`로 시점과 잠재 차원을 모두 평균합니다. 같은 α에서 기울기가 잠재 차원 64배 작습니다. 논문은 ISE의 α를 주지 않으므로, 저장소 값 0.1은 논문 식과 같은 효과인지 확인할 수 없습니다.
- **D6 내부 기울기 정규화.** 논문 갱신식 q ← q − α∇L에는 정규화가 없습니다. `inner_update()`는 기울기 노름이 1보다 크면 1로 나눕니다(`q_grad / grad_norm`). 이 규칙은 학습과 테스트 모두에 적용됩니다.
- **D7 내부 스텝 수.** 논문 Algorithm 1은 K개의 내부 스텝을 씁니다. 저장소 `trainer.py`는 `inner_update()`를 **한 번만** 호출합니다. 문 과제는 학습 1 스텝, 테스트 5 스텝으로 평가합니다(`configs.py`의 `rollout.ttt_steps=5`). 논문 표 2의 "5 스텝"이 학습 설정과 다르다는 뜻입니다.
- **D8 이력 드롭아웃.** `TrainConfig.history_dropout`은 ISE 0.3, 이진 과제(Open Box, Faucet) 0.0, 문 0.3입니다. 확률적으로 이력을 0으로 두는(q = q0) 설정입니다. 논문 본문에는 SCOUT의 이 설정이 없습니다. 부록 B.2의 20%는 PEARL 계열 기준선에만 있습니다.
- **D9 학습 증강.** `AttemptHistoryDataset.__getitem__()`은 `augment_prob = 0.1`(ISE)의 확률로 **질의 시도의 정답 상호작용을 이력 끝에 덧붙입니다**. 그러면 학습 중 이력에 정답 결과가 들어갑니다. 테스트 롤아웃에서는 성공한 시도가 `break`로 빠져나가므로 이력에 들어가지 않습니다(`scout/envs/metaworld/rollout.py`). 학습과 테스트의 이력 분포가 다릅니다. 검증 세트는 증강 없이 만들어서 모델 선택 지표에는 드러나지 않습니다. 논문에는 없습니다.
- **D10 점별 성분 구조.** 정책은 N = 1200개의 점마다 K개 성분을 냅니다. 혼합은 N × K = 4800 성분입니다(`gmm_head.py`). 논문 "K = 4 components"는 점마다 4개를 뜻하는지 전체 4개를 뜻하는지 불분명합니다. 코드는 전자입니다.
- **D11 ISE 정규화.** ISE 입력(점군과 이력 행동)과 정답 행동은 질의 점군의 중심과 반지름으로 정규화합니다(`normalize=True`). 문은 원래 좌표입니다. 논문에는 이 정규화가 없습니다. 재현에 필수입니다.
- **D12 미기재 하이퍼파라미터.** 학습률 1e-3 (Adam, ISE; AdamW, 문 weight decay 1e-4), 기울기 클리핑 1.0 (ISE)과 5.0 (문), 유효 배치 64, 에폭 (과제별: pick 2000, push 1000, faucet 2000, box 2000, brick 900, door 100), 드롭아웃 0.1, q0 초기화 N(0, 0.1²), FiLM 초기화 Xavier gain 0.5, 동역학 3 층. 원문에는 없습니다.
- **D13 재구성 손실 혼합.** 원문 A.4는 질의와 이력 모두에서 합산한다고만 씁니다. `reconstruction_loss()`는 질의와 이력 손실을 **0.5 : 0.5**로 섞습니다. 가중치 λ = 1은 두 쪽 모두 일치합니다.
- **D14 문 과제의 q0 기울기.** 논문 §4.3은 외부 손실을 내부 갱신을 통해 q0까지 미분한다고 씁니다. 문 설정은 `detach_q=True`여서 q0는 선형 항만 받습니다. 원문은 이 차이를 적지 않습니다.
- **D15 목표 기울기.** `detach_outcome_target=False`입니다. 내부 손실의 목표 E(o_{t+1})도 기울기를 받으므로 E가 상수로 붕괴할 여지가 있습니다. 원문 A.4의 붕괴 논의와 맞는 설정입니다. 이 선택은 원문에 없습니다.
- **D26 체크포인트 선택.** 학습은 `best.pt`(검증 사후 NLL 최소), `best_gap.pt`(사전−사후 차이 최대), `latest.pt`를 저장합니다. 논문은 어느 것으로 평가했는지 적지 않습니다. ISE 검증 세트는 파일의 마지막 10%입니다(순차 분할, `load_split`).

### 3.3 구현 환경

- **D22 MuJoCo 버전.** Slide Brick은 MuJoCo ≤ 2.3.7에서만 원본과 같습니다. README 표는 전문가 성공률이 MuJoCo 2.3.7에서 0.90, 3.15에서 0.07이라고 보고합니다. 논문에는 MuJoCo 버전이 없습니다. 나머지 과제는 MuJoCo 3에서 학습되었습니다. Meta-World는 v3.0.0 포크를 씁니다(`third_party/metaworld/`). 포크 변경점은 논문에 없습니다.
- **D23 맥 렌더링 가정.** `scripts/rollout.py` 등은 `MUJOCO_GL=egl`을 기본으로 설정합니다(`setdefault`). `diag_render.py`와 README의 문제 해결도 Mesa EGL을 전제합니다. macOS에서 이 경로는 지원되지 않습니다. 이 맥에서 쓰려면 렌더러 설정을 바꿔야 하고, 이 변경은 확인하지 않았습니다.

## 5. 이 대조에서 확인하지 않은 것
