# 04. 논문 ↔ 공식 코드 대조 (코드 검증)

공식 저장소 `RoboFlywheel-com/RoboFlywheel-Soft`(Apache-2.0)를 `repo/`에 얕게 clone해서 **정적으로만** 읽었습니다. 실행, import, 설치, API 호출은 하지 않았습니다. 확인 기준은 커밋 `5373cd9`(2026-11-20, 얕은 clone)입니다. 저장소 내부의 줄 번호는 이 커밋 기준입니다.

대조는 논문 본문과 부록의 **구체적인 상수와 규칙**을 기준으로 했습니다. 각 항목은 "일치", "불일치", "확인 못함" 중 하나로 적었습니다. 불일치나 빈칸은 D1–D18로 번호를 붙였습니다.

## 1. 요약

- 저장소 안의 코드는 논문의 핵심 상수(프로브 밴드, 임계값, 손상 식, 그리퍼 규칙, 예산, 부트스트랩 방식)에 대부분 **일치**합니다.
- 실제 불일치는 적고 작습니다. 가장 중요한 것은 (D1) 정착 판정의 정의가 두 곳에서 다르다는 점, (D15) 부트스트랩 시드가 두 개라는 점, (D11) 공개 CSV만으로는 "같은 후보"라는 논문의 전제를 확인할 수 없다는 점입니다.
- 저장소는 논문 수치의 **재계산**(`paper/build_support/`)과 **합성 픽스처**만 포함합니다. 실제 시뮬레이션 결과(100K 자산, 물리 번들, 궤적)는 ModelScope에 따로 있고(`docs/DATA.md`), 이 대조에서는 받지 않았습니다.

## 3. 불일치와 빈칸

### D1. 정착 판정이 두 곳에서 다릅니다 (중요)

- `code/src/softsim_genesis_runner/genesis_worker.py:367`: `settled = max_speed_m_s < 0.05`(절대 최고 속도, m/s).
- `code/scripts/genesis_behavior_runner.py:1584`: `settled = tail_mean <= 0.05 * peak`(꼬리 평균 / 최고, 비율).
- 논문 표 12는 **비율** 정의를 씁니다. 그런데 `_E2_LOSS_METRICS`(`__init__.py:95`)에 `settled`가 들어 있어서, 어느 워커가 돌았는지에 따라 식 (4)의 부울 항목이 달라질 수 있습니다.
- `03` V3의 "부울 항목 하나 불일치"가 정착 판정일 가능성은 이 정의 차이에 따라 달라집니다. 어느 판정이 공개 기록에 쓰였는지는 CSV로 확인할 수 없습니다.

### D2. 보정 제안의 온도 0.2는 설정 파일에서 찾지 못했습니다

- 표 3은 "production correction" 온도 0.2를 씁니다. 저장소에서 0.2는 `qwen_proposer_transport.py:106`(에이전트 제안기)과 `gen_deligrasp_prior_cache.py:54`(힘 사전 캐시)에만 있습니다.
- `asset_pipeline/configs/physical_100k_v1.json`의 온도는 0.1입니다. 보정 단계의 설정 파일은 찾지 못했습니다. 판정: 확인 못함(값은 맞아 보이나 위치가 불명확).

### D3. 역추적 상한 3은 논문에 없습니다

- `__init__.py:753`: Swim2Real형 방법은 `backtracks < 3`일 때만 역추적합니다. 논문 E.1절은 "역추적을 더한다"고만 적고 상한을 쓰지 않습니다. 완전 수치 에이전트(H)에는 상한이 없습니다.
- 영향: 표 15의 Swim2Real형 행이 논문 설명보다 제약이 있습니다.

### D4. 무손상 기준의 경계가 두 워커에서 다릅니다

- `genesis_worker.py:747`: 손상 < 0.25(엄격).
- `__init__.py:915`: `integrity >= 0.75` ⇔ D ≤ 0.25(허용).
- 논문은 D < 0.25. 두 워커가 같은 기록을 만든다면 D = 0.25 정확히인 경우만 다릅니다. 실제 최소 손상 0.2653이라 결과에는 영향이 없습니다.

### D5. 예산 규칙 "3개에서 시작, 2씩 늘려 최대 8"은 부분만 확인

- `softsim_physical_agent/agent.py:507`: `max_iterations` 기본값 3. `agent.py:512`: 상대 개선 임계 0.05(논문과 같음). `agent.py:392`: 연장 게이트.
- `configs/e2_formal.json:6`: 후보 예산 [1, 2, 4, 8](파라미터 비교 실험의 예산과 일치).
- 생산 실행이 "2씩 연장"하는 설정 파일은 찾지 못했습니다. 판정: 부분 확인.

### D6. held-out 분할 목적이 본문에 없습니다

- 파지 실험은 660 교정 / 340 held-out을 씁니다. 고정 명령과 슬립 피드백은 학습이 없으므로, 분할이 무엇을 위해 있는지 본문에 없습니다.
- 공개 CSV에서 고정 명령과 슬립 피드백의 held-out 결과는 340개 인스턴스 전부에서 같습니다(`03` V5). 분할 설계 설명이 필요합니다.

### D7. 특권 기준은 작업 성공 상한이 아닙니다

- `genesis_worker.py:750–753`(주석) 부근: 무손상 성공이 없는 물체에서는 "작업 실패가 거의 확실하다"고 적혀 있습니다. 즉 이 기준은 손상 최소화기이고, 표 7의 "Privileged reference" 행을 성공 기준선으로 읽으면 안 됩니다. 논문 표 7 자체는 이를 맞게 설명합니다(부록 F). 본문 표 해석 주의.

### D8. 조건 열(low/medium/high)과 밴드 키의 대응은 코드에만 있습니다

- `genesis_worker.py:149–151`의 밴드 키는 `low/medium/high`입니다. 공개 CSV의 `condition` 열도 같은 값을 씁니다. 그러나 두 값의 대응을 문서에서 명시하지는 않습니다(`03` V4).

### D9. 무손상 경계 (D4와 같은 항목의 다른 측면)

- D4와 같은 내용입니다. 재계산에서는 논문 정의(< 0.25)를 썼습니다.

### D10. 저장소 문서의 "중국어 README" 및 기타 문서는 확인하지 않았습니다

- `README_zh.md`는 읽지 않았습니다(내용은 영문 README와 같은 것으로 보임, 확인 안 함).

### D11. 공개 CSV만으로는 "같은 초기 후보"를 확인할 수 없습니다 (중요)

- 논문 E.1절: "방법들은 자산/예산 그룹 안에서 같은 초기 파라미터 값을 공유한다." 그러나 `parameter_initialization_audit.csv`는 **사전(prior)** 수준에서만 0개 불일치를 보고합니다. 후보 파라미터 값은 CSV에 없습니다.
- 피드백이 없는 fixed profile과 one-shot prior는 같은 후보를 평가해야 하는데, 교정 오차와 독립 오차가 같은 그룹은 거의 없습니다(`03` V2).
- 판정: 논문 전제는 공개 기록으로 검증되지 않았습니다. 저자에게 후보 파라미터와 프로브 시드 기록을 요청할 항목입니다(§5).

### D12. 저장소에만 있는 미실행 변형

- `structure_cases.csv`의 `surface_fix_flexible_garment`(8행)는 `status = not_executed`입니다. 논문 5.2절과 표 5, 13에는 없습니다. 재계산에서 제외했습니다(`03` V6).

### D13. 프로젝트 페이지가 저장소와 맞지 않습니다

- 프로젝트 페이지(`roboflywheel-com.github.io/RoboFlywheel-Soft/`)에는 "Code SOON, Dataset SOON"이 적혀 있습니다. 그러나 GitHub 저장소는 공개되어 있고(Apache-2.0, 2026-11-20 푸시), README에는 ModelScope 데이터 링크가 있습니다. 프로젝트 페이지가 뒤처진 것으로 보입니다.
- v1 PDF의 프로젝트 링크(`sjijs.github.io/RFW-S_website/`)는 v2에서 바뀌었습니다. 이 URL은 현재도 200 응답이지만 내용은 확인하지 않았습니다.

### D14. 물리 파라미터 기록은 저장소에 없습니다

- 4.2절과 3.2절의 파라미터(예: 두부 블록 재생 실험: E = 28 kPa, ν = 0.32, ρ = 950 kg/m³, 항복 응력 5 kPa, 입자 6,460개; F.1절)는 저장소 설정에서 찾지 못했습니다. 기록은 외부 증거 경로(`external-evidence/…`)에 있다고 되어 있어서 확인 못함.
- 파지 실험의 `damage` 구현도 "연속체 손상 대리 모델"이고 명시적 파괴가 아니라는 점을 저장소가 직접 밝힙니다(`configs/formal_method_contract.json:15`). 논문 6.3절과 일치합니다.

### D15. 부트스트랩 시드가 두 개입니다

- `paper/build_support/build_results.py:168`: `bootstrap_seed = 20260926`, 5,000회(논문과 일치).
- `configs/analysis_summary.json:12`: `bootstrap_seed = 20260828`, `confidence_interval = cluster_bootstrap_95`.
- 논문 결과는 전자로 재현됩니다. 후자는 다른 분석 요약에 쓰이며, 논문 본문에는 나오지 않습니다. 어느 쪽이 공개 표에 쓰였는지 명시가 필요합니다.

### D16. 재계산 스크립트의 자산 수준 CI

- 저장소의 `verify_analysis.py`와 `build_results.py`는 해시가 맞는지만 확인합니다. 실행하지 않았습니다(규칙). 해시는 우리가 직접 21개 모두 검증했습니다(`03` 시작부).

### D17. 전문가 평가 기준은 같은 데이터로 조정되었습니다

- `genesis_behavior_runner.py:2232–2233`: "사람이 0.97까지 허용하므로 드롭 변형 상한을 0.9에서 0.98로", "복원 하한을 0.84에서 0.45로" 바꿨다는 주석이 있습니다. 즉 밴드는 같은 150개 클립의 평가로 맞춰졌습니다(논문 6.2절은 별도 검증 세트가 없다고 인정). 밴드 평가에 순환성이 있습니다.

### D18. 저장소 공개 날짜

- README 뉴스는 "2026년 10월 공개"라고 하고, 분석 스냅샷은 2026-10-25/26, GitHub 생성일은 2026-09-17, 첫 커밋 날짜는 2026-11-10입니다. arXiv 제출은 2026-11-17입니다. 날짜가 서로 맞지 않지만 논문 수치는 스냅샷과 일치합니다(`03` 재계산).

## 4. 구현 가능성 (이 맥 기준)

**판정: 논문 전체 재현은 이 맥에서 불가능합니다. 공식 재계산은 끝냈습니다. 축소판 구현은 조건부로 가능합니다.**

| 구성 요소 | 필요 자원 | 이 맥(M4 Pro, 24 GiB, MPS, CUDA 없음) | 판정 |
|---|---|---|---|
| 공개 CSV 재계산 | numpy, scipy | 가능 (완료) | **가능** |
| 저장소 설치와 테스트 (`pytest`) | Python 3.10+, 의존성 | 설치 필요 (사용자 승인 필요) | 조건부 |
| Genesis 1.3.3 시뮬레이션 (MPM/PBD) | Genesis 설치, GPU 권장(확인 못함: Metal/CPU 성능) | 불명 | 확인 못함 |
| 100K 자산 생성 (TRELLIS.2, Qwen-Image-2.0) | GPU, 생성 모델 가중치 | 불가 (GPU 필요) | 불가 |

| 전문가 평가 재현 | 평가자 10명 | 불가 | 불가 |

**노력 추정**
- 공식 파이프라인 재실행(Genesis + API + 데이터 수 TB 가능성 있음): 1–2주 이상, GPU 기기 필요. 이 맥으로는 우선 설치 가능성부터 확인해야 합니다.
