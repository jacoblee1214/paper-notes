VolumeDP: 분석 리포트

arXiv:2603.17720v2 (2026-07-01) · IROS 2026 (채택) · Tianxing Zhou, Feiyang Xue, Zhangchen Ye 외 (Tsinghua IIIS) · 공개 코드: 단일 커밋 `d2ec13a` (ManiSkill 포크, Apache-2.0) · 분석일 2026-11-11 · 논문 라이선스 arXiv nonexclusive-distrib (CC BY 아님)

핵심 요약

  1. 무엇을 하는가: 이미지 특징을 40³ 복셀 볼륨으로 올리고(deformable attention), 학습된 가중치로 200개 공간 토큰을 골라, DiT 블록 디퓨전 디코더에 넣습니다. RGB만 씁니다. 카메라 보정이 필요합니다.
  2. 공개 코드에는 방법이 없습니다: 저장소는 ManiSkill 3.0.0b19 상류 구조이고, 볼륨, 토큰, 디코더 구현은 찾지 못했습니다(검색 0건). 프로젝트 페이지의 LIBERO 코드 링크는 404입니다.
  3. 승격 조건 (LIBERO DP 기준선이 같은 레시피로 재학습되었는가): 해결되지 않았습니다. DP 행에 자체 실행 표시가 없고, 인용 출처로 보이는 IB-BC [32]에는 같은 수치가 없습니다. 같은 표의 BC 행은 [32]와 소수점까지 일치합니다. 공정성은 확인할 수 없습니다.
  4. 실물 46/80 대 61/80: 과제 무시 Fisher p = 0.018, 과제 층화 Mantel-Haenszel p = 0.060입니다. 과제별로는 Holm 보정 후 유의하지 않습니다. 과제당 n = 20은 검정력이 부족합니다(팔당 약 98회 필요).
  5. LIBERO-Plus 평균 불일치: 열 단순평균은 DP 31.17, DiT 31.81인데 표에는 31.7과 31.1로 적혀 있습니다(뒤바뀐 모양). 결론(1위, 약 21포인트)은 바뀌지 않습니다.
  6. 과제명 불일치: 본문은 Hook Cube와 Stack Pyramid를 쓰지만, 공개 환경에는 이 둘이 없습니다. Fig. 3은 Pull Cube Tool을 보입니다.
  7. 토이 결과: 깊이가 관측에 들어가야 z 예측이 좋아집니다(2D 투영은 평균 수준). 가림이 있으면 깊이 표현도 오차가 큽니다. 이 토이는 VolumeDP의 우위를 증명하지 않습니다.
  8. 구현 가능성: 공식 재현 경로는 모두 열려 있지 않습니다(LIBERO 코드 없음, 실물 없음, ManiSkill은 macOS 미지원). 이 맥에서 방법 구현은 MPS로 소규모 시도가 가능할 수 있으나 미확인입니다.

직접 계산: Table V 과제별 성공률(n = 20)과 Wilson 95% 구간. 과제별 구간이 크게 겹칩니다.

Table I 값을 옮긴 그래프(재계산 아님). DP 행의 출처가 불명확합니다.

CPU 토이: 관측 표현별 z 예측 RMSE. 점 요약 선형 0.000은 구성상의 누출입니다(03 §6).

2. 문제와 주장

  • 문제(§I): 2D 이미지 특징을 3D 행동으로 바꾸는 과정의 2D–3D 불일치가 공간 추론을 해친다고 봅니다. 깊이 센서가 있는 포인트 클라우드(DP3 류)는 비용이 크므로, RGB만 쓰면서 3D 표현을 만드는 것이 목표입니다.
  • 핵심 주장: (i) 이미지 특징을 복셀 볼륨으로 올리면 공간 추론이 좋아진다, (ii) 학습된 가중치로 200개 공간 토큰만 골라도 충분하다, (iii) 토큰 전체를 조건으로 주는 다중 토큰 디코더가 한 벡터로 압축하는 방식보다 낫다.

4. 실험 설정 (원문에 있는 것만)

  • LIBERO: 4 suite(Spatial, Object, Goal, Long), 과제당 시연 50개, no-op 제거와 실패 시연 제외. 3 시드.
  • ManiSkill: 5과제(Poke Cube, Place Sphere, Hook Cube, Stack Pyramid, Insert Peg), 과제당 평균 150개 시연(스크립트 정책). 3 시드.
  • LIBERO-Plus: LIBERO로만 학습한 뒤 7종 교란(카메라, 로봇 초기 상태, 언어, 조명, 배경, 센서 잡음, 배치)으로 평가.
  • 실물: Galaxea R1 Lite(양팔 6-DoF 2개 + 그리퍼), 과제당 시연 100개, 시험 과제당 20회. 4과제(Placing Bowl, Microwave, Door Opening, Nut onto Screw).
  • 입력: 256×256 RGB, 프레임 2장(t, t−1), 언어 지시, 8D proprio.
  • 기준선: BC(LIBERO는 [32]에서 인용, ManiSkill은 ManiSkill 코드베이스의 BC), DP(ManiSkill, LIBERO), DiT-Block Policy.
  • "All methods are uniformly trained and evaluated with 100 denoising steps." (§IV-A) 이 문장이 공정성 주장의 근거입니다. 다만 epoch 수, 배치 크기, 학습률, 샘플러, 이미지 전처리를 기준선별로 적지 않았습니다.

6. 원문 안의 불일치와 주의점

  1. Table III 평균 불일치. 열 단순평균은 DP 31.17, DiT 31.81인데 표에는 DP 31.7, DiT 31.1로 적혀 있습니다. 두 값이 서로 뒤바뀐 것처럼 보입니다. 원본 데이터 파일이 없어 가중평균 여부는 확인하지 못했습니다. 텍스트 본문도 31.7과 31.1을 그대로 인용합니다. 차이는 0.5포인트 이하라 결론은 바뀌지 않습니다. 다만 "DP 대비 +21.3"의 기준값이 흔들리는 셈입니다.
  2. Fig. 3과 본문의 과제명 불일치. 본문은 ManiSkill 과제로 Hook Cube를 쓰고, Fig. 3 캡션 그림은 Pull Cube Tool을 보입니다(렌더링으로 확인). 공개 코드에는 PullCubeTool-v1과 PokeCube-v1, PlaceSphere-v1, PegInsertionSide-v1이 있고, HookCube와 StackPyramid는 등록되어 있지 않습니다(04 D10).
  3. DP 행의 출처가 표시되지 않음. Table I에서 DP에는 별표가 없고, 별표는 DiT-Block에만 있습니다. 같은 표의 BC 행은 32의 수치와 소수점까지 일치합니다(BC-Trans 67.83±10.42 → 68.0±1.0 등, 02 §2). 그러나 DP 행의 suite별 값(78.3, 92.5, 68.3, 50.5)은 [32]에 없습니다. 같은 [32]의 부록 C.3.1은 DP를 LIBERO-Long에서 78.0(50 epoch, 배치 64, 1e-4, 90M 헤드, 128×128, 필터링 없음)으로 보고합니다. 본 논문의 DP Long 값 50.5와 다릅니다. 웹 검색으로도 해당 수치 조합의 출처를 찾지 못했습니다(02 §2).
  4. "same recipe" 주장의 근거 부족. 기준선에 대한 명시는 "uniformly trained"뿐입니다. 특히 LIBERO의 DP 행이 재학습인지 인용인지 원문으로 확정할 수 없습니다. 이것이 승격 조건의 핵심입니다(02, 03 §8).
  5. 컴퓨트 주장 미검증. §III-B는 토큰 축약으로 계산을 줄인다고 하지만, 파라미터 수, FLOPs, 지연, 학습 시간을 보고하지 않았습니다. 볼륨 40³×32 채널은 약 2.05M 값을 한 장면에서 만듭니다.
  6. Ablation 범위. 표 IV는 LIBERO-Spatial 한 suite에서만, 시드와 오차 없이 보고했습니다.
  7. LIBERO ± 정의 없음. ± 값이 SD인지 SE인지, 3 시드 기준인지 밝히지 않았습니다.
  8. GT depth 대조(표 IV e)의 해석. "GT depth"는 복셀 선택을 점 개수 상위 N으로 하는 휴리스틱입니다. 깊이 센서를 쓰는 기존 3D 방법(DP3 류)과 직접 비교한 것이 아닙니다.
  9. 카메라 보정 필요. 식 2는 외부·내부 행렬을 요구합니다. "RGB only"이지만 보정과 과제별 작업 공간 범위 r은 미리 필요합니다.

7. 추가로 확인할 질문

  • LIBERO DP 행을 같은 학습 조건으로 다시 학습했는가? (논문에서 확인 불가, 코드도 없음)
  • DP와 제안 방법의 학습 epoch, 배치, 샘플러가 같은가?
  • 실물 20회 시험의 초기 배치 분포와 시험 순서(무작위화 여부)는 무엇인가?
  • 복셀 점유를 만드는 이미지 특징 백본은 DP의 ResNet-18인가, 다른 것인가? 원문에는 "shared backbone"이라고만 적혀 있습니다.

02. 선행연구와 비교 대상

1. 계보

  • 행동 복제와 확산 정책: BC(Ross 2010/2011 [9][10]), 가우시안 혼합·이산 행동·잠재 행동 계열 [11]–[15], 확산 정책 DP [2](IJRR 2025), 조건부 DDPM [16].
  • 확산 트랜스포머: DiT-Block Policy [6](ICRA 2025)은 adaLN-Zero 블록으로 다중 토큰을 조건으로 줍니다. VolumeDP 디코더는 이 블록을 그대로 씁니다(§III-C).
  • 3D 표현 정책: DP3 [3](포인트 클라우드), Act3D [4], RVT [25], PerAct [23], GNFactor [24]. 모두 깊이 또는 점군 입력을 요구합니다.
  • 3D 점유 예측 계열: Occ3D [28], CVT-Occ [29], BEVFormer [27]. VolumeDP의 deformable 볼륨 리프팅은 이 계열의 기법(deformable attention [26])을 가져옵니다.
  • 토큰 축약: TokenLearner [31]. 학습 가능한 softmax 가중치로 복셀을 N개 토큰으로 줄입니다.

새로움: 기법 조합은 기존 요소의 결합입니다(원문도 TokenLearner와 deformable attention을 명시합니다). 새로움은 "RGB만으로 볼륨을 만들고, 볼륨에서 토큰을 골라 DiT 디코더에 넣는다"는 파이프라인과 실험 설계에 있습니다.

8. 승격 조건 판정: "LIBERO DP 기준선이 같은 레시피로 재학습되었는가?"

판정: 해결되지 않았습니다. 원문과 공개 코드로는 공정성을 확인할 수 없습니다.

근거:

  1. DP 행에 자체 실행 표시가 없고, 캡션 규칙("*는 자체 구현")에 따르면 인용값입니다.
  2. 인용 출처로 보이는 [32]에는 같은 DP 수치가 없습니다(Long 한 셀 78.0, 본 논문 50.5와 다름).
  3. 공개 코드는 ManiSkill 포크이며 LIBERO 코드가 없습니다. 프로젝트 페이지의 LIBERO 코드 링크는 404입니다.
  4. 따라서 "같은 시연 수, 같은 epoch, 같은 샘플러"는 검증할 수 없습니다.

이 판정이 바꾸는 것: LIBERO의 +16.4%p는 "재학습 비교"가 아니라 "인용값 대 자체 측정"으로 읽어야 합니다. ManiSkill 결과(+19.3%p, 자체 실행)와 LIBERO-Plus 결과(+21.3%p, 자체 실행)가 더 믿을 만한 비교입니다. 다만 LIBERO-Plus 평균에도 0.5포인트 계산 불일치가 있습니다(§1).

재확인 방법(재현 시 수행할 일, 실행하지 않음): 공개 ManiSkill 포크에서 DP 기준선을 같은 시연·epoch·샘플러로 학습해 보는 것입니다. 그러나 LIBERO에는 코드가 없어 같은 실험은 불가능합니다.

9. 컴퓨트 비용 추정 (원문 미보고, 계산으로만 추정)

  • 볼륨 40×40×40×32 = 2,048,000 값. fp32 기준 약 8.2 MB 활성화 메모리 per 샘플, 프레임 2장이면 2배 가까이 됩니다. 이는 중간 텐서이며 학습 배치에 곱해집니다.
  • deformable 샘플링은 복셀 64,000개 × 샘플점 수 × 헤드 수 만큼의 바이리니어 보간입니다. 실제 시간은 구현에 따라 다릅니다.
  • 토큰 축약(N = 200)으로 디코더 입력은 202개 토큰입니다. DiT-Block 디코더와 같은 크기의 어텐션 비용이 남습니다.
  • 원문에는 파라미터 수, FLOPs, 지연이 없습니다. "computation 크게 축소" 주장은 검증되지 않았습니다.

3. 기준선 설정에서 드러난 공정성 문제 (D8, D9)

  • 관측 모드 불일치 가능성(D8). 논문은 "RGB만 사용"이 핵심 차별점이라고 주장합니다(§I). 그런데 공개된 상류 RGB-D 기준선의 기본값은 rgb+depth입니다. 원문 DP의 ManiSkill 결과(Table II)가 이 기본값으로 돌렸다면, 기준선은 깊이를 쓰고 제안 방법은 쓰지 않는 셈입니다. 그러면 비교는 "깊이 있는 DP 대 RGB 전용 VolumeDP"가 되어 방향이 바뀔 수 있습니다. 원문으로는 확인할 수 없습니다.
  • 학습 설정 미공개(D9). 논문은 학습 epoch나 배치를 보고하지 않습니다. 상류 기본값(total_iters 1M, batch 256)과 예시(30k–100k)가 서로 크게 다르므로, 기준선 설정에 따라 결과가 크게 달라질 수 있습니다.
  • LIBERO 행(D13). 코드가 없으므로 LIBERO 기준선 설정을 대조할 수 없습니다. 02 §2의 출처 문제와 합쳐 보면, LIBERO의 +16.4%p는 검증 불가입니다.

4. 구현 가능성 판정 (이 맥 기준, 정적 판단)

판정: 논문 방법은 공개 코드로 재현할 수 없습니다(구현 없음). 공식 재현 경로는 세 가지 중 하나도 현재 열려 있지 않습니다.

재현 경로 공개 여부 이 맥(Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음, torch 미설치)에서 필요한 자원 노력
공식 ManiSkill 재현 기준선 DP만 공개, VolumeDP 방법 없음 불가능. ManiSkill README는 macOS를 지원하지 않음(GPU 시뮬 Linux 전용). CPU 시뮬도 macOS에서 불가로 명시 Linux + NVIDIA GPU(GPU 시뮬), Vulkan 렌더링 방법을 직접 구현해야 함(큼)
공식 LIBERO 재현 코드 없음(404) 불가능. 코드 없음. LIBERO 자체는 MuJoCo 기반이라 헤드리스 렌더링 확인 필요 학습 GPU, 데이터 구현 필요, 기준선 재학습 필요
실물 재현 (Galaxea R1 Lite) 코드 없음 불가능. 하드웨어 없음 로봇, 텔레오퍼레이션 장비 불가
아이디어 재구현 (볼륨 + 토큰 + DiT) 해당 없음 중간~높은 난이도. 모델 구현 자체는 PyTorch로 가능하나 MPS에서 40³×32 볼륨 학습은 메모리·시간 면에서 제한적(추정, 미확인). torch 설치 승인 필요 기존 DP 기준선 코드 + 구현 큼
  • 노력 추정 (구현 가능성): 공개된 것은 DP 기준선뿐이므로 방법 전체를 새로 짜야 합니다. 볼륨 리프팅(식 1–3)과 토큰 생성(§III-B), DiT 디코더(§III-C) 세 모듈입니다. 보조 감독(§III-B)과 카메라 투영 정확성을 검증하려면 대조 실험도 필요합니다.
  • 하드웨어: 학습에는 GPU가 필요합니다. 이 맥에서는 토이 수준 검증까지만 CPU로 가능합니다(03 §6).
