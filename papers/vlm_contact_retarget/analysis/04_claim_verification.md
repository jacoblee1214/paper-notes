## 2. 주장별 검토 메모

- **C1–C4 (리타게팅).** 가장 강한 근거는 재현율의 큰 격차(OmniRetarget 대비 +37.3%p, Stage 2 효과 +44.6%p)입니다. 그러나 **효과의 대부분은 VLM이 아니라 접촉 공동 최적화에서 나옵니다.** 제목과 초록은 "VLM-guided"를 앞세우지만, VLM 필터를 빼도 재현율은 58.0%입니다(표 1). VLM 필터의 이득은 정밀도 +2.6%p와 사용자 순위 0.30에 있고, 사용자 연구는 필터가 만든 "더 깨끗한 접촉"이 보이는 차이로 이어진다는 방향의 증거입니다.
- **C5.** 사용자 연구는 설계가 좋습니다(무작위 위치, 해시 기반 순서, 순위, 세 질문, SEM 보고). 약점은 70% 참가자만 분석한 것과, 순위가 합 10이라 방법 사이 음의 상관이 있다는 것 정도입니다.
- **C6–C7.** 교사 표는 3개 행동만 있고(hand-shake, pat-on-back 없음) 평가 시드만 바뀝니다. 메시 접촉 보상의 이득은 큽니다. 다만 비교 기준인 "링크 수준 보상"은 모든 마디 수준 항(방향, 힘 밴드)도 같이 뺀 것이어서, 이득이 "메시 대응" 때문인지 "방향·힘 항" 때문인지 분리되지 않습니다(§4.2).
- **C8–C9 (생성 모델링).** 가장 흥미로운 주장이고 가장 단서가 많습니다. hug에서 미래 생성은 해롭고(−8.7), high-five는 결정적 변형이 최고이며(33.9 대 13.1), 이득의 대부분은 link-arms 한 행동(+23.3%p)입니다. 표 3은 ±가 없고 체크포인트 하나입니다. 주장은 "일부 행동, 일부 구간에서 가능성이 있다"까지가 안전합니다.
- **C10–C11, C32.** 표 7의 분할 표기가 가장 큰 단서입니다. 서론과 4.3절은 보류 분할(표 3)을 말한 뒤 75%를 인용하는데, 계산 대상은 훈련 분할입니다.
- **C13–C16 (실로봇).** 31/50과 성공 횟수는 맞지만, 정책이 이전 설정이고 성공 기준이 다르며, 시험 설정(파트너 위치, 반복, 실패 모드)이 거의 없습니다. 힘과 안전 주장(C15)은 시뮬 설계일 뿐 실로봇 측정이 없습니다.
- **C17.** 인루프 렌더링이 핵심 기여로 서술되지만 절제가 없습니다. 같은 학생을 캡슐 깊이로 학습한 비교가 있어야 "간격을 닫았다"를 정량화할 수 있습니다.
- **C20.** 표 8은 P와 R은 표 사이에서 일관되지만(평균 행, 본문 상대 개선율), F1 열이 정의와 맞지 않습니다. 이는 계산 정의나 평균 대상의 차이일 가능성이 높고 결론을 뒤집지는 않습니다.
- **C24 (순환 평가).** 정책 평가용 "접촉 재현율"이 VLM 검증 주석을 정답으로 씁니다. 따라서 "VLM 필터 없음" 변형은 필터 없는 주석으로 학습하고 VLM 필터 있는 주석으로 평가받는 셈입니다. 이 설계는 필터를 쓰는 쪽에 유리한 방향의 편향을 만들 수 있습니다. 논문은 수작업 주석이 확장되지 않는다는 이유를 밝히고 있고, 80개 클립의 수작업 정답 평가(표 1, 8)가 별도로 있어 완전한 순환은 아닙니다.
- **C29.** 프롬프트가 `hug`의 필수 접촉(손바닥-등, 팔뚝-어깨), `high-five`의 필수 접촉(손바닥 대 손바닥) 등 행동별 표를 이미 담고 있어, VLM은 "새로운 의미 추론"보다 **사람이 쓴 규칙표에 시각 증거를 대조**합니다. 행동 5개에서는 효과적이지만, 규칙표를 쓰지 않는 새 행동으로의 확장성은 이 논문으로는 알 수 없습니다.

## 3. 본문과 부록의 불일치 목록

1. 표 1의 "Ours w/o VLM contact annotation ... (Sec. 3.2.1)" 참조는 §3.1이어야 합니다(본문 §4.1).
2. 표 1의 ± 의미가 열마다 다릅니다. 지터, 관통, 재현율, 정밀도는 클립 간 표준편차이고, 사용자 순위는 SEM입니다(캡션 미기재, 부록 E.5).
3. 표 10의 재현율 총합이 행동 평균과 0.2–0.35 어긋납니다 (Ours 59.4 대 59.08, `03` V1).
4. 표 8의 F1 열이 같은 표의 P, R과 일관되지 않습니다 (`03` V11).
5. "75% (30 cm)"는 훈련 분할 값인데 본문은 보류 분할을 논한 뒤에 인용합니다 (`03` V8).
6. 표 5의 E2E 열이 이전 설정이어서 표 3과 pat-on-back 23.8 대 51.1, link-arms 30.1 대 67.8로 어긋납니다. 표 5의 hand-shake 78.6은 표 7의 hand-shake 학생 15 cm 값 78.6과 같습니다 (`03` V9).
7. λ_gen, λ_pose = 0.5의 해석이 "combined pose loss weight 0.5"와 충돌할 수 있습니다 (`03` V14).
8. 학생 풀의 크기와 보류 분할의 모션 수가 어디에도 숫자로 없습니다 (`03` V12).
9. 학습 총 반복 수, 학습 시간이 없습니다 (교사 PPO와 학생 DAgger 모두).
10. 프로젝트 페이지의 "significantly"는 논문 초록에는 없는 표현이고, 실로봇 시연 영상은 논문 실험과 다른 깊이 입력(Fast-FoundationStereo)을 씁니다.
11. 힘 게이트 φ의 정의가 단위가 있는 값의 지수이고 F = 0에서도 0.37이라 "force-gated"의 설명과 약간 다릅니다 (`03` V13).

## 4. 구현 가능성 판정 (구현할 수 있는지)

**판정: 이 맥(Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)에서 논문의 파이프라인을 구현해 수치를 재현하는 것은 불가능합니다. 표 재계산은 이미 끝났고, 핵심 아이디어의 축소 토이는 CPU로 가능합니다.**

### 4.1 이 맥에서 되는 것

| 항목 | 가능 여부 | 비고 |
|---|---|---|
| 표 재계산, 일관성 검사 (V1–V16) | 완료 | `analysis/recompute.py` |
| 보상 형태, 임계값 민감도 계산 | 완료 | `03` §5 |
| 접촉 기반 리타게팅 토이 (2D 또는 단순 3D 팔 링크, 접촉 목표를 팔 끝에 고정 대 자세 유사도) | 가능 (numpy, 수 분) | 논문 설정이 아니라 아이디어의 축소판 |
| 보조 파트너 예측 손실 토이 (작은 시계열 모델, 부분 관측, 결정적 대 확산 헤드) | 가능 (torch CPU/MPS, 수 시간 추정) | 설계 선택(게이트, λ)이 결과를 바꾸는지 확인용 |
| 후보 접촉 + 규칙 필터의 라벨 품질 평가 (합성 접촉 데이터) | 가능 (numpy) | VLM 호출 없이 규칙표만으로 |
| 학습 코드 정적 대조 | 불가 (코드 없음) | 공개 후 가능 |

### 4.2 이 맥에서 안 되는 것

| 항목 | 이유 |
|---|---|
| 교사 학습 (Isaac Sim, 8,192 환경, L40S) | Isaac Sim은 NVIDIA RTX GPU와 Linux를 전제함. MuJoCo MJX나 CPU로 옮기면 다른 실험이 됨 |
| 학생 학습 (128 환경, 렌더 깊이, SMPL-X 배치 순전파) | 같은 이유. 렌더링 경로가 GPU 시뮬에 묶임 |
| 접촉 주석 파이프라인 전체 | SMPL-X 모델 파일(등록 필요), Inter-X 데이터(받지 않음, 용량·약관 미확인), Gemini API 호출(금지) |
| 표면 대응(ICP) 재구현 | SMPL-X 메시와 G1 메시 필요. SMPL-X는 별도 등록·라이선스 필요 |
| 실로봇 시험 | Unitree G1, RealSense D435, 온보드 컴퓨트, 파트너 필요 |
| HOMIE 보행 제어기 | 사전 학습 체크포인트(공개 여부 미확인) |

### 4.3 공수 추정 (분석자 추정, 측정 전)

- **전체 재구현(코드 없이):** 접촉 주석, 리타게팅 2단계, 교사, 학생(렌더링 포함)까지 한 사람이 약 2–3개월, GPU 시간 수백 시간(Isaac Sim)로 추정합니다. 실로봇이 없으면 시뮬 결과까지만.
- **공식 코드 공개 후:** 학습 설정과 평가 코드를 정적으로 읽는 것은 1–2일. 실행은 GPU가 필요해 이 맥에서는 불가능.
- **축소 토이 두 개(리타게팅, 보조 예측):** 각각 2–5일 추정. 패키지 설치는 필요 없음(numpy, torch가 이미 있음).
