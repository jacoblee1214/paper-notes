# 01. 논문 분석: RoboCasa

*RoboCasa: Large-Scale Simulation of Everyday Tasks for Generalist Robots* (Nasiriany, Maddukuri, Zhang, Parikh, Lo, Joshi, Mandlekar, Zhu). UT Austin, NVIDIA Research. arXiv:2406.02523 **v1 (2024-06-04) 하나**. 원문은 `paper/paper.pdf`(16쪽, 8.3 MB)입니다. 본문 인용의 Fig., Table, 절 번호는 이 PDF 기준입니다.

## 1. 한 문단 요약

RoboCasa는 주방 중심 가정 환경을 MuJoCo 기반 RoboSuite 위에 만든 시뮬레이션 프레임워크입니다. 배치 10개, 스타일 12개로 장면 120개를 만들고, 객체 2,509개(153개 범주)와 가전 기구를 넣었습니다. 과제는 원자 과제 25개(8개 기술)와 LLM으로 만든 복합 과제 75개, 합쳐서 100개입니다. 사람 시연(과제당 50개, 1,250개)을 MimicGen으로 늘려 생성 데이터를 만들고, 원자 과제 24개에서 BC-Transformer를 학습해 규모에 따른 성능 상승을 보였습니다. 실로봇 주방 실험에서는 시뮬 데이터 공동학습이 보이는 객체 성공률을 13.6%에서 24.4%로 올렸습니다.

## 2. 문제 설정과 동기

- **문제:** 로봇 데이터는 인터넷 텍스트·이미지처럼 쉽게 모이지 않습니다. 실세계 수집은 비용이 커서 시뮬레이션으로 데이터를 확장하자는 주장입니다(I).
- **요구 조건 세 가지:** 물리와 렌더링의 실세계 전이, 장면·에셋·과제의 다양성, 대규모 로봇 데이터셋(I).
- **기여:** (1) 시뮬레이션 프레임워크, (2) 100개 과제의 체계적 평가 세트, (3) 생성 데이터를 포함한 대규모 다과제 데이터셋(I의 기여 목록).

## 3. 방법

### 3.1 시뮬레이션 (III)

- **플랫폼:** RoboSuite [51] 위에 이동 조작기(바퀴 기반, 휴머노이드, 팔 달린 사족 로봇)를 추가했습니다(III-A). 렌더링은 NVIDIA Omniverse 옵션이 있습니다.
- **장면 (III-B, Fig. 3).** 배치 10개(원룸형부터 U자형 섬 있는 배치까지). 스타일 12개(Industrial, Scandinavian 등). 조합하면 120개 장면입니다. 텍스처 100개씩(벽, 바닥, 조리대, 캐비닛 패널)은 MidJourney로 만들었습니다. 텍스처를 교체하는 것이 **도메인 무작위화**입니다.
- **에셋 (III-C).** 주방 가구와 가전은 3D 모델 저장소에서 가져와 MJCF로 변환하고, 문과 손잡이를 관절체로 분할했습니다(Fig. 4). 객체 2,509개는 Objaverse(917)와 Luma.ai 텍스트→3D(1,592)에서 왔습니다(Fig. 5).

### 3.2 과제 (IV, VIII)

- **원자 과제 25개 (IV-A).** 기술 8개: 집기·놓기, 문 열고 닫기, 서랍, 손잡이 돌리기, 레버, 버튼, 끼우기, 이동(navigation). 과제 대부분은 객체 종류 변형이 있습니다(예: PnP 과제는 범주별 변형).
- **복합 과제 75개 (IV-B, Fig. 6, 12).** GPT-4에게 일상 활동 30개를 묻고 20개를 골랐습니다. 그다음 GPT-4와 Gemini 1.5에게 활동별 과제를 제안받아 블루프린트 75개를 만들었습니다. 논리 오류(없는 객체, 잘못된 기술 사용, 잡으면 안 되는 물체)는 사람이 걸러냈습니다(VIII-B).

### 3.3 데이터 (IV-B, IV-C)

- **사람 시연:** 4명이 3D SpaceMouse로 원자 과제마다 50개씩, 총 1,250개(IV-B). 무작위 장면에서 수집했습니다.
- **생성:** MimicGen으로 확장합니다. 원천 시연을 객체 중심 하위 과제로 나누고, 새 장면의 객체 자세로 변환해 이어 붙이고, 성공한 시도만 저장합니다(거절 샘플링). 생성 횟수와 성공률은 보고하지 않습니다.
- **규모:** 원자 24개(이동 제외) × 3000 = 72,000개. AI 생성 객체 궤적 약 28,000개를 더해 "100K+"라고 씁니다(주석 1).
- **렌더링:** 데이터셋은 AI 텍스처로 렌더링하고, 평가는 사람이 고른 텍스처에서 합니다(V-A). 빠른 MuJoCo 렌더러를 씁니다(VIII-C).

### 3.4 정책 (IX)

- **BC-Transformer:** 과거 관측 10개와 언어 목표(CLIP)를 입력으로 받습니다. 손목 카메라와 작업 공간 카메라 2대를 ResNet-18로 인코딩하고 FiLM으로 합칩니다. 6층 Transformer, 약 20M 파라미터, 행동 10개 출력, 500k 스텝, 학습률 1e-4.
- **Diffusion Policy:** RoboMimic 구현, 관측 2개. 본문은 단일 과제 PickPlaceCounterToSink에서 BC-Transformer 56%, DP 12%라고 씁니다(IX). 이 수치는 Fig. 13과 맞지 않습니다(03 K7).

## 5. 주장과 한계 (논문 스스로 밝힌 것)

- **생성 데이터의 질.** 생성된 궤적은 성공으로 판정되지만 떨림과 충돌을 보일 수 있습니다. 시뮬 상태로 걸러낼 수 있다고 씁니다(VI).
- **복합 과제 성능이 낮다.** 미세 조정도 대부분 낮습니다(V-B). 정책 구조와 학습 방법이 원인일 수 있다고 합니다.
- **범위.** 주방 중심, 변형체와 양팔 조작 없음(VI).
- **LLM 과제 설계는 아직 사람 손이 필요.** 구현은 사람이 씁니다(VI).

## 6. 이 분석이 본 것 (요약)

- 과제 평균, 규모 추세, 실로봇 향상은 재계산과 일치합니다(03 §1–2).
- 생성 100개는 사람 50개와 차이가 없습니다(03 §1.2, C3).
- 실로봇 미본 객체의 향상은 방향만 맞고 통계적으로 확실하지 않습니다(03 §2, C5).
- 공식 코드의 데이터 구성은 논문과 대체로 맞지만, 사람 시연의 범위(100개 과제 중 30개)와 평가 세부는 맞지 않거나 확인되지 않습니다(04 D1, D9).
