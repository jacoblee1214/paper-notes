# 04. 논문 ↔ 공식 코드 대조 (FingerEye)

공식 저장소 `ariszxxu/FingerEye`(master, 커밋 `2466c11`, 2026-06-08, 라이선스 없음)를 **정적으로만** 읽었습니다. 실행, import, 설치는 하지 않았습니다. 큰 자산(Isaac 자산, HDRI, 티저 PNG)은 받지 않는 희소 clone이고, 읽은 파일은 약 1.5 MB입니다. 저장소는 세 부분입니다: `FingerEyePolicy/`(정책, 전처리, 학습), `FingerEyeRW/`(실세계 수집·배치·섬세 파지), `FingerEyeLab/`(Isaac Lab 디지털 트윈과 시뮬 평가). 저장소의 마지막 푸시(2026-06-08)는 arXiv v3(2026-06-06) 이틀 뒤이고 v4(2026-10-06)보다 앞섭니다. 따라서 v4에서 추가된 항목(A.5.3 W+T, A.5.4 손목 입력, A.1.6 태그 수)은 코드에 없을 가능성이 높고 실제로 없습니다(D13).

## 2. 논문과 다른 곳 (D1–D14)

각 항목은 코드 위치와 논문 위치를 함께 적었습니다. "다르다"는 정적 대조 결과이고 실험에 쓰인 코드가 공개본과 같은지는 확인할 수 없습니다.

### 정책 구조

**D1. 모달 그룹 구성.** 논문 4.2절은 관측 그룹을 "손목 RGB, 고유감각, 손가락별 FingerEye RGB"로 쓰는데(per-fingertip), 코드는 FE 토큰 전체(4개)를 **하나의 그룹**으로 묶어 하나의 교차 어텐션과 하나의 인코더로 처리합니다(`fingereye_encoder.py:90–92`, `act_blocks.py:284–290`). A.4의 표 7은 "FE, Wrist, Proprio 세 그룹"이라고 쓰므로 후자와 같습니다. 그룹 수 M = 3(코드), 손가락별이면 M = 6(Coin, 4FE)입니다.

**D2. 그룹 디코더에서 토큰 하나뿐인 그룹.** `StructuredACTDecoderLayer`(`act_blocks.py:323–`)는 joint(고유감각 1토큰), wrist(1토큰), FE(4토큰)에 각각 다른 교차 어텐션을 두고 세 잔차를 평균합니다(`:408`, 식 15의 1/M). 키가 하나인 어텐션의 softmax 가중치는 항상 1이라, joint와 wrist 그룹의 출력은 행동 쿼리와 무관하게 같은 벡터(값 투영의 선형 결과)입니다. 무작위 가중치 토이에서 쿼리 16개 사이의 최대 편차는 2e-7이었고, 키가 2개나 4개면 0.34였습니다(`analysis/toy_group_decoder.py`). 결과적으로 이 구현에서 쿼리 의존 정보를 만드는 것은 FE 그룹뿐이고, 그 몫은 평균에서 1/3입니다. 식 15 자체와는 모순되지 않지만, "각 그룹이 직접 경로를 갖는다"는 설명이 손목·고유감각 그룹에는 상수 편향에 해당합니다. 표 7의 "어텐션 질량" 진단은 이 구현의 그룹 디코더에는 정의되지 않습니다(키가 하나라 항상 1).

**D3. 플랫 디코더의 고유감각 처리.** 논문 식 15의 FlatDec와 A.4(표 7)는 고유감각이 컨텍스트 토큰으로 FE·손목과 한 번의 softmax를 나눈다고 설명합니다(균등 기준 6개 토큰 중 1/6 = 16.7%). 코드의 비그룹 디코더(`group_decoding=False`)는 고유감각 상태를 투영해 **행동 쿼리에 더하고**(`fingereye_decoder.py:77`) 교차 어텐션 컨텍스트는 FE 4개 + 손목 1개뿐입니다. 그룹 디코더에서만 고유감각이 컨텍스트 토큰이 됩니다(`:75`). 따라서 공개 코드의 NoEnc+FDec나 GEnc+FDec는 표 7의 진단 대상과 구조가 다릅니다. 표 3·7의 FDec 행이 이 저장소의 코드가 아닌 다른 구현에서 나왔을 가능성, 또는 논문 설명이 구현을 단순화했을 가능성이 있습니다.

**D4. 변형과 크기 맞춤.** 코드에서 `group_encoding`이 False이면 인코더는 항등이어서 NoEnc이고, FlatEnc(전체 토큰 자기어텐션)는 구현되어 있지 않습니다. 따라서 표 3의 FEnc+FDec(48.5) 행은 공개 코드로 만들 수 없습니다. 논문은 변형들을 은닉 폭을 조정해 크기를 맞췄다고 쓰지만(5절, A.5.2) 폭을 바꾼 설정은 없습니다. 기본 차원에서 파라미터 수는 NoEnc+FDec 31.7 M, NoEnc+GDec 40.1 M, GEnc+FDec 44.3 M, GEnc+GDec 52.7 M으로 최대 1.66배 차이 납니다(`03` V11; 직접 센 값이며 무작위 입력 한 스텝 측정에서도 52.7 M).

**D5. 손실과 기타 학습 설정.** 본문과 부록에는 손실이 적혀 있지 않지만 코드는 정규화된 행동에 대한 **L1 손실**입니다(`fingereye.py:179`). `accelerate`의 bf16 혼합 정밀도(`workspace.py:28`), post-norm(`pre_norm: False`), 학습 중 검증 없음(`val_ratio: 0.0`; 체크포인트 상위 k 설정은 `val_loss`를 보지만 계산하지 않음, 마지막 체크포인트만 의미가 있음)도 논문에 없는 설정입니다. 상태는 limits 정규화, 행동은 gaussian 정규화입니다(`fingereye_dataset.py`).

**D6. 과제별 Ta와 에폭.** 표 9는 시뮬 Coin과 Peg의 Ta = 16, Peg의 에폭 300을 적지만 `configs/fingereye.yaml`의 기본은 Ta = 8, 에폭 500(커밋 `2466c11` "500 default epochs")이고 설정 파일에는 덮어쓰는 값이 없습니다(`configs/setting/*.yaml`). 표 9의 값은 실행 시 인자로 바꿨을 수 있습니다.

### 데이터와 평가

**D7. 데모 수 상한.** `max_train_episodes`(`downsample_mask`의 상한, 데이터가 더 적으면 의미 없음): coin_fingereye 50, **coin_wrist 100, coin_fingereye_mono 100**, nut(pn) 50, peg(cih) 200, chip 100(표 9: 30개), letter 100(60개), syringe 100(40개). 논문은 한 과제의 모든 모달리티·구조 절제가 같은 데이터셋을 쓴다고 쓰므로(A.5.2) 상한 차이는 실제 사용 데모 수가 같다면 영향이 없습니다. Coin에서 W와 W+M의 상한이 W+FE의 2배라는 점은 확인이 필요합니다(데이터셋 크기를 알 수 없음).

**D8. 섬세 파지 임계값.** `FingerEyeRW/configs/delicate_grasp.yaml`의 `z_translation_thredshold`(코드가 mm로 취급, `delicate_grasp.py:101–102`)와 표 6을 대조하면: 칩 0.10, 김 0.01, 콘 0.10, 쿠키(웨이퍼) 0.05, 풍선 0.05, 연필심 0.02, 달걀 0.05는 일치하고 프레임 수(15, 30, 10, 150, 10, 20, 20, 5, 3)도 모두 일치합니다. **종이컵(디저트 컵) 0.005(논문 0.05), 포도 0.006(논문 0.06)**은 10배 작습니다. 설정에는 열 번째 물체 `paper`(0.01 mm, 50프레임)도 있습니다(논문은 아홉 가지). 두 값이 Δl_min 0.0135 mm와 35태그 지터 0.012 mm보다 작아 `03` V8에서 따로 다뤘습니다.

**D9. 섬세 파지 정지 규칙.** 논문 CH4는 "각 손가락이 닿는 순간 멈춘다"고 쓰지만 코드는 첫 프레임을 기준으로 |Δz|를 구하고 `delta_T_z > th and delta_I_z > th`(엄지와 검지가 **모두** 넘을 때)에서 루프를 끝냅니다(`delicate_grasp.py:122–142`). 손가락별 정지가 아니라 손 전체 보간이 멈추는 구조이고, 필터나 연속 프레임 조건은 없습니다(단일 샘플 문턱). 임계값이 지터 근처인 물체에서는 오검출 여부가 중요합니다.

**D10. 자세 추정과 카메라.** 논문 식 1은 EPnP 후 LM 정제라고 쓰지만 코드는 `cv2.solvePnP(..., SOLVEPNP_ITERATIVE)` 후 `solvePnPRefineLM`입니다(`recorder_tag_detector.py:186–190`). 모든 보이는 태그 모서리를 한 번에 푸는 점은 같습니다. CLAHE 대비 향상은 A.1.5의 서술과 일치합니다. 카메라 내부 파라미터는 fx ≈ 342–352 px(640 x 480)로 수평 시야가 약 86°이고(논문의 모듈 공칭 120°), 37 px 태그 폭은 거리 약 18.7 mm에서 나옵니다(본문 "약 10 mm", `03` V7).

**D11. 시뮬 판 스프링.** `fingereye_env_cfg.py`의 판 가상 관절 강성은 힘 70 / 29.17 / 100, 토크 0.50 / 0.20 / 13.33, 감쇠 2.37 / 1.53 / 2.83, 0.010 / 0.0063 / 0.052입니다. 논문은 "실측 포즈-힘 관계로 맞췄다"고 쓰고 값을 싣지 않습니다. 부록의 감도 결과에서 역산한 강성과 비교하면 힘은 0.09–0.22배, 토크는 21배입니다(`03` V7).

**D12. 시뮬 성공 판정.** `FingerEyeLab/scripts/record.py:461–465, 616–618`은 매 스텝 보상 > 0.5를 보고 한 번이라도 넘으면 성공으로 **고정**합니다(`success_flags | new_success`). Coin 보상은 코인 법선 z가 sin 10° 미만(거의 수평)이고 두 지(指) 끝 사이 거리가 0.12 m보다 클 때 1입니다(`fingereye_cs_env.py:73–84`). 실세계 Coin의 서술("분리한 뒤에도 서 있어야 성공", 5절·그림 6 캡션)과 달리 유지 시간 조건이 없습니다. Peg: xy 오차 < 0.8 mm, z 오차 < 0.29 mm, 축 기울기 cos > 0.996(`fingereye_cih_env_cfg.py`)로, 반지름 여유(0.6 mm)보다 xy 임계값이 큽니다(z 조건이 림 위 정지를 거르는지는 확인하지 않음). 에피소드 길이 Coin 20 s, Peg 20 s, Nut 30 s(제어 0.1 s). 3개 학습 시드를 도는 스크립트는 없고(config seed 42) 평가 시드 0, 1, 2만 자동화되어 있습니다.

**D13. v4 항목의 부재와 v1 잔재.** 코드에 없는 것: 손목(FT) 입력 그룹(A.5.4), W+T 접촉 깊이 맵(A.5.3 식 18), 태그 수 절제 설정(A.1.6), FlatEnc(D4), 시뮬 Nut·Peg의 W, W+M 설정(설정 파일은 `pn_fingereye`, `cih_fingereye`뿐이고 wrist·mono 설정은 coin, chip, letter, syringe에만 있음). 남아 있는 것: v1의 시뮬 증강 표현 학습에 쓰인 `use_sim_pose_decoder`, `sim_M9` 헤드와 손실 가중치 0.1(`fingereye.py:183–190`), 시뮬 배치 보조 입력. v3·v4 본문에는 이 실험이 없습니다.

**D14. 데이터·데모 출처.** 데모 데이터와 체크포인트는 공개되지 않았고(`zarr_path: your_zarr_path.zarr`), README 예시 경로는 옛 프로젝트 이름("ConTacRW")을 포함합니다. Nut 시뮬 환경(`fingereye_pn_env.py`)에는 스크립트 전문가(`get_expert_action`, 단계·잡음·재시도 상태 등 241곳)가 있지만 공개 스크립트(`record.py` 등)는 호출하지 않아, 시뮬 데모가 텔레오퍼레이션인지 전문가 생성인지 이 저장소만으로는 알 수 없습니다. 논문 4.1절은 시뮬·실세계 모두 리더-팔로워 수집으로 서술합니다.

## 3. 읽기 메모

- `FingerEyeRW/main.py`는 하드웨어(xArm, LEAP, RealSense, 카메라 포트)를 전제로 하며, 정책 호출·청크 실행 구조는 논문과 같습니다. 카메라 스트림은 MJPEG 25 fps이고 기록은 10 Hz입니다.
- `FingerEyeLab/`의 시뮬 정책 평가는 `record.py mode=policy` 하나이고 롤아웃 영상과 시드별 성공률을 출력합니다.
- 저장소에는 LICENSE가 없습니다. 코드는 ACT(MIT) 블록을 복사하고 Apache-2.0 헤더를 달고 있습니다(`act_blocks.py` 앞부분).

## 4. 구현 가능성 판정 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)
