# 04. 주장 검증과 구현 가능성: Real-Time Execution with Autoregressive Policies (arXiv:2606.13355)

공식 코드가 없어서(§1) 논문 ↔ 코드 대조(D 항목) 대신, 논문의 주장 C1–C26을 표·그림·본문 수치로 대조했습니다. 계산 근거는 `03`(V, K 항목)에 있습니다. 판정 표기: 일치 / 일치하나 조건 있음 / 불일치 / 검증 불가(자료 부족) / 버전 사이 변경. 비판의 대상은 논문의 서술과 표이며, 저자의 의도에 대한 추정은 하지 않습니다.

## 1. 공개 자료 현황 (2026-11-24 확인)

- **방법 코드는 공개되어 있지 않습니다.** 프로젝트 페이지(`oddqueue.github.io/realfast`)가 "Code (Coming soon!)"로 표기하고, 저자 계정의 `oddqueue/realfast`는 `main`이 openpi의 포크(업스트림 대비 앞선 커밋 0개)이며 `page` 가지에 프로젝트 페이지 HTML만 있습니다(`02` §2). 체크포인트, 평가 스크립트, RTC 기준선 구현도 없습니다.
- 논문은 구현 기반으로 openpi(JAX)를 밝히고, RTC는 "공식 릴리스에 없어서" 저자가 직접 구현했다고 적습니다(부록 A). 따라서 기준선 π0 + RTC, π0.5 + RTC의 구현 세부(접두 고정 방식, 가이던스 가중치, 디노이징 설정)도 이 분석에서 확인할 수 없습니다.
- openpi 저장소의 LIBERO README와 평가 스크립트는 읽었습니다(표 1의 m = 0 행 대조, 시행 수 가정). 이 파일들은 저자의 코드가 아니라 기반 저장소의 것입니다.

## 3. 본문에 없어서 재구현에 필요한 정보

1. RTC 기준선 구현: 접두 고정과 인페인팅 가이던스 설정, 디노이징 5단계 외의 가이던스 가중치, 사용한 π0·π0.5 체크포인트(LIBERO용, DROID용)와 학습 스텝. 논문은 "공식 릴리스에 없어 직접 구현"이라고만 적습니다.
2. LIBERO 시뮬레이션: 시행 수(스위트·시드당), 시드 정의(학습 시드인지 평가 시드인지), π0-FAST 기준선(m = 0 행)의 학습 설정, 관측 지연을 흉내 내는지(접두 고정만 하는지)의 명시.
3. REALFAST 학습: 토크나이저의 DCT 스케일 γ, 어휘 크기, FAST+ 재학습 여부(논문은 1초 청크용 토크나이저를 그대로 씀), 데이터 필터링(DROID 유휴 구간), LIBERO 데이터 크기(에폭 수 환산에 필요).
4. 가중치 감쇠: 표 B는 1e-8입니다. openpi의 AdamW 기본값(`src/openpi/training/optimizer.py`, 포크 스냅샷)은 β = (0.9, 0.95), 기울기 클리핑 1.0으로 표 B와 같지만 weight_decay는 1e-10입니다. 기본값을 바꾼 것인지 확인이 필요합니다.
5. 디코딩: EOS 토큰의 용량 처리, 빔 서치 폭(τ = 0, N > 1), "제약 없음" 변형의 무효 처리.
6. DROID 평가: 과제별 초기 배치 통제 방식, 성공 판정 기준(사람 판정인지), 시행 순서, 처리율의 과제별 값(그림 C에 막대만 있음).
7. 지연 측정: 종단 지연 분포(백분위), 클라이언트·서버 사이 통신 구간, GPU 점유 상태.
