# 03. 수치 재계산과 일관성 검사

이 문서는 논문의 표와 본문 수치를 다시 계산하고, 논문 안에서 서로 맞지 않는 곳을 위치와 함께 적고, 주장별로 근거를 판정합니다. 계산은 `analysis/recompute.py`(수 초, 결과는 `recompute_results.json`)이고 이 문서의 번호 **V1–V12**가 그 검사 번호입니다. **K1–K17**은 논문 안의 서술 일관성 검사, **C1–C14**는 주장 판정입니다. 학습이나 실험 재현은 하지 않았고 CPU에서 도는 계산만 했습니다.

> **가정 (결과마다 문장에 다시 적습니다).**
> - 표 1: 캡션이 "100 trials per run, mean ± SD over 3 runs"입니다. 실행 3회 × 100회 = 과제당 300회, 시행은 서로 독립이라고 가정합니다(시행 수 300 가정). 보수적으로 한 번의 100회만 쓴 경우도 함께 냈습니다(시행 수 100 가정).
> - 표 4: 캡션이 "100 trials per task"입니다(시행 수 100 가정).
> - 그림 4: 막대 위 숫자를 읽은 값(그림 판독 값)이고 시행 수는 논문에 없습니다.
> - 성공 횟수는 보고 퍼센트 × 시행 수를 반올림한 값입니다.

## 1. 표 1 (실로봇) 재계산

### 1.1 평균과 본문 서술의 일치 (V1)

| 본문 서술 (4.2절) | 본문 값 | 표에서 계산 |
|---|---|---|
| Full 평균 | 84.1 | 84.1 |
| π0 평균 | 48.6 | 48.575 → 48.6 |
| Full − π0 | 35.5 | 35.5 |
| Peg-in-Hole에서 Full − π0 | +46.3 | 46.3 |
| ACT 평균 | 34.9 | 34.875 → 34.9 |
| ACT (w/ Tactile) 평균 | 47.0 | 47.0 |
| HSA-Only 평균 | 54.7 | 54.725 → 54.7 |
| Dream-Only 평균 | 71.0 | 71.0 |
| Full − HSA-Only / Full − Dream-Only | 29.4 / 13.1 | 29.4 / 13.1 |
| 시뮬 Full / HSA-Only / Dream-Only 평균 | 96.6 / 86.7 / 91.9 | 96.6 / 86.7 / 91.85 → 91.9 |

- **산술은 모두 맞습니다.** 표 1과 표 4의 평균 및 차이에 어긋나는 값은 없습니다.
- 표 4는 모든 과제에서 ACT < Diffusion Policy < π0 < HSA-Only < Dream-Only < Full 순서가 유지되고, 표 1은 모든 과제에서 π0 < HSA-Only < Dream-Only < Full 순서가 유지됩니다(순서 위반 0건, V8). 표 1에서 ACT는 USB Insert(62.6)에서 π0(59.4)와 Diffusion Policy(56.3)보다 높아 기준선 사이 순서는 과제마다 다릅니다.
- ACT (w/ Tactile)의 ACT 대비 변화는 Peg +10.4, USB +0.5, Gear +17.8, Tool +19.8 %p입니다. USB Insert에서는 촉각을 더해도 변화가 거의 없습니다.

### 1.2 평균의 정수 가능성 (V2)

시행 수 300 가정, 즉 "실행 3회, 각 100회"에서 각 실행의 성공률은 정수 %이고 평균은 (정수 합)/3입니다. 그러면 소수 첫째 자리는 .0, .3, .7 중 하나여야 합니다(예: 35.0, 35.3, 35.7).

- 표 1의 28칸 중 **21칸이 이 격자 위에 없습니다** (예: ACT Peg-in-Hole 35.2, USB 62.6, Gear 22.4; π0 USB 59.4; Full Gear 81.1, Tool 74.6). 격자 위에 있는 칸은 7개입니다.
- 모든 칸이 가능해지는 실행 수는 10회(또는 10의 배수)입니다. 3회, 5회로는 불가능했습니다(V2).
- 해석 가능성: (a) 각 실행의 시행 수가 100이 아닌 경우, (b) "mean ± SD"가 실행 3회의 평균이 아니라 다른 집계인 경우, (c) 실행마다 시행 수가 다른 경우. 어느 쪽인지 본문만으로는 정할 수 없어 **저자 확인이 필요합니다**.

### 1.3 SD의 정수 가능성 (V3)

같은 가정에서 세 실행이 정수 %이면 0이 아닌 SD의 최솟값은 표본 SD(분모 n−1) 0.577, 모집단 SD(분모 n) 0.471입니다(숫자 전수 계산).

- 표 1의 보고 SD 중 **5칸이 0.47보다 작습니다**: Full Peg 0.2, Full Gear 0.4, ACT (w/ Tactile) Peg 0.3, USB 0.4, Gear 0.2.
- 평균과 SD가 **함께** 정수 격자에서 나올 수 있는 칸은 28칸 중 3칸입니다 (ACT Tool 19.3 ± 0.6, π0 Tool 41.0 ± 0.8, Full USB 85.7 ± 0.6).
- 이 역시 위 (a)–(c) 중 하나일 수 있고, SD가 표준오차 등 다른 양일 가능성도 있습니다. SD의 정의가 본문에 없습니다.

### 1.4 보고 SD와 시행 변동의 크기 (V5)

(그림: 표 1 각 칸의 보고 SD와 이항 SD.) 성공 확률 p에서 100회 한 번의 이항 SD는 100·√(p(1−p)/100)입니다. 표 1 각 칸에서 이 값은 2.2–5.0 %p이고, 보고 SD(0.2–1.1)는 그 **4–22% (중앙값 16%)** 입니다.
- 세 실행이 서로 독립인 시행으로 이루어져 있다면 실행 간 SD는 이항 SD 근처가 되고, 학습 시드까지 달라지면 더 커질 것입니다. 보고 SD가 이보다 작은 것은 (i) 평가가 거의 결정적(E절: 고정된 초기 위치)이거나, (ii) 한 정책 체크포인트를 세 번 돌린 것이거나, (iii) SD가 다른 양일 때 가능합니다. 어느 쪽인지는 논문에 없습니다.
- 그래서 이 문서의 검정은 **SD를 쓰지 않고 성공 횟수만** 씁니다.

### 1.5 구간과 검정 (V5, V6)

그래프(아래 그림)는 시행 수 300 가정의 Wilson 95% 구간입니다. 예를 들어 Full Peg-in-Hole 95.0%는 [91.9, 96.9], π0 48.7%는 [43.1, 54.3]입니다. 시행 수 100 가정이면 구간은 약 1.7배 넓어집니다(Full Peg [88.8, 97.8]).

Fisher 정확 검정(양측)과 Holm 보정(28개 검정 전체에 한 번 적용)입니다.

| 비교 (과제별) | 시행 수 300 가정, Holm p | 시행 수 100 가정, Holm p |
|---|---|---|
| Full 대 π0 | Peg 1e-38, USB 1e-11, Gear 2e-18, Tool 2e-15 | Peg 2e-12, USB 6e-4, Gear 5e-6, Tool 4e-5 |
| Full 대 Dream-Only | Peg 1e-10, USB 0.023, Gear 2e-4, **Tool 0.86** | Peg 0.002, **USB 0.95, Gear 0.26, Tool 1.0** |
| Dream-Only 대 HSA-Only | Peg 0.002, USB 0.028, Gear 0.012, Tool 7e-9 | **Peg 0.70, USB 1.0, Gear 1.0**, Tool 0.011 |
| HSA-Only 대 π0 | Peg 0.041, **USB 1.0, Gear 0.99, Tool 1.0** | 모두 1.0 |
| HSA-Only 대 ACT (w/ Tactile) | Peg 0.004, **USB 1.0, Gear 0.078, Tool 1.0** | 모두 비유의 |
| ACT (w/ Tactile) 대 ACT | **Peg 0.10**, **USB 1.0**, Gear 5e-5, Tool 3e-6 | 모두 비유의 (Tool 0.052) |
| Full 대 HSA-Only | Peg 2e-24, USB 1e-8, Gear 3e-13, Tool 8e-14 | Peg 1e-7, USB 0.011, Gear 5e-4, Tool 2e-4 |

네 과제를 합산(시행 수 1200 가정)하면: Full 1009/1200 대 π0 583/1200 (p ≈ 4e-78), Full 대 Dream-Only 853/1200 (p ≈ 2e-14), Dream-Only 대 HSA-Only 656/1200 (p ≈ 1e-16), HSA-Only 대 π0 (p = 0.003), HSA-Only 대 ACT (w/ Tactile) 564/1200 (p = 2e-4)입니다.

**읽는 법**
- **Full이 π0와 모든 기준선보다 낫다는 결론은 어느 가정에서도 흔들리지 않습니다.** 시행 수 100 가정에서도 Holm p < 1e-3입니다.
- **Dream이 HSA보다 더 크게 기여한다**는 서술(4.2절 "HSA alone 54.7%, Dream-only 71.0%")은 시행 수 300 가정에서는 4과제 모두 유의하고, 시행 수 100 가정에서는 Tool Stabilize에서만 유의합니다.
- **HSA의 추가 기여(Full 대 Dream-Only)** 는 Peg-in-Hole에서 어느 가정에서나 유의하지만 Tool Stabilize에서는 어느 가정에서도 유의하지 않고, USB와 Gear는 시행 수 300 가정에서만 유의합니다(p = 0.023, 2e-4). 초록의 "complementary" 서술은 Peg-in-Hole과 합산에서 뒷받침되고 과제별로는 균일하지 않습니다.
- **HSA 단독의 효과**는 Peg-in-Hole에서만 확인됩니다. USB, Gear, Tool에서 HSA-Only는 π0와 구분되지 않고(시행 수 300 가정 Holm p ≥ 0.99), ACT (w/ Tactile)와도 구분되지 않습니다(Gear 0.078).

## 2. 표 4 (IsaacSim) 재계산

### 2.1 소수 값과 시행 수 (V4)

- 캡션은 "100 trials per task"인데 24칸이 모두 소수 첫째 자리 값입니다(정수 값 0칸). 100회 한 번의 성공률은 정수 %여야 합니다.

## 3. 실로봇과 시뮬레이션의 차이 (V8)

- 시뮬 성공률에서 실로봇 성공률을 뺀 값(%p, Peg / USB / Gear / Tool): π0 34.8 / 26.5 / 32.0 / 33.6, HSA-Only 28.3 / 26.7 / 33.1 / 39.8, Dream-Only 18.4 / 19.4 / 24.0 / 21.6, Full 3.6 / 12.2 / 14.1 / 20.1.
- Full − π0 격차는 실로봇에서 46.3 / 26.3 / 35.9 / 33.6, 시뮬에서 15.1 / 12.0 / 18.0 / 20.1입니다. 실로봇의 격차가 모든 과제에서 더 큽니다.
- 시뮬이 쉬운 설정이라는 점(천장 효과)과 실로봇 기준선의 학습 조건 차이가 함께 작용할 수 있습니다. 이 표만으로 원인을 가를 수는 없습니다. 그리고 4.1절은 정책이 실로봇 시연만으로 학습된다고 쓰는데 표 4는 시뮬에서 정책을 평가합니다(K2).

## 4. 그림 4 (V9, 그림 판독 값)

- 크기 증가분: 300M → 600M +10.7, 600M → 1B +5.9. 본문의 "+10.7%"와 맞습니다.
- 데이터 증가분: 20 → 40% +17.6, 40 → 60% +15.7, 60 → 80% +4.6, 80 → 100% +3.3. "60% 부근에서 완만해진다"는 서술은 증가폭이 줄어드는 것과 맞고, 60%에서 100%까지는 +7.9가 더 늘어납니다.
- **표 1과의 관계가 본문에 없습니다.** 본 모델의 세계 모델은 ViT-L(300M)(B.1)인데, 300M의 값은 68.5이고 표 1 Full의 네 과제 평균은 84.1입니다. 데이터 100%의 값 86.4도 84.1이나 시뮬 평균 96.6과 같지 않습니다(K10). 한 과제의 값, 다른 평가 설정의 값일 수 있습니다.
- 오차 막대가 그려져 있으나 정의(SD, 신뢰구간, 시행 수)가 캡션과 본문에 없습니다.

## 5. 구현 수치와 기하 점검 (V10–V12)

### 5.1 어댑터 파라미터 수 (V10)

부록 B.1의 구조(층 정규화, 3층 MLP 은닉 512, 스케일 1개, 8헤드 어텐션 풀링, 쿼리 토큰, 정규화)를 d = 1024에 대입해 센 값:

| 구성 | 파라미터 |
|---|---|
| 어댑터 (LN + MLP + 스케일) | 1,314,817 (MLP만 1,312,768) |
| 어텐션 풀링 (MHA + 쿼리 + LN) | 4,201,472 |
| 합 | **5,516,289 (300M의 1.84%)** |

본문의 "5.5M (1.8% overhead)"와 맞습니다. 부록 B.1 앞부분의 "~1.5M additional trainable parameters per tactile encoder"는 어댑터 MLP만의 1.31M에 가깝고 풀링을 뺀 값으로 읽힙니다(추정, K9). ViT-G(d = 1408)로 바꾸면 합이 약 9.6M입니다(헤드 수 8 가정).

### 5.2 카메라 행렬과 패치 격자 (V11)

- 부록 C.1의 3인칭 카메라 외부 행렬의 회전 블록 diag(1, −1, 1)의 행렬식은 **−1**입니다. 순수 회전(행렬식 +1)이 아니라 반사 성분을 포함합니다. 아래를 보는 카메라라면 diag(1, −1, −1) 같은 값이 나올 것으로 기대됩니다(추정). 표기 단순화일 수 있으나 이 행렬만으로는 확정할 수 없습니다(K7).
- 내부 행렬의 주점 (c_x, c_y) = (653, 364)는 표 5의 RGB 입력 해상도 640 × 480을 벗어납니다(c_x > 640). 1280 × 720 해상도에서 보정한 값으로 보입니다(추정). 이 외부 행렬이 세계→카메라라고 보고 점 (0.3, 0, 0.1)을 투영하면 픽셀 (1175, 110)이 되어 640 × 480 영상 밖입니다(V11).
- C.3은 "CLIP-ViT-large-patch14", "patch size 16", 격자 "16 × 16"을 함께 쓰고 수식은 14로 나눕니다. 224/16 = 14, 224/14 = 16입니다(K6). 어댑터의 "196 patches"(B.1)는 14 × 14 격자와 맞습니다.

### 5.3 데이터 구성 (V12)

- 시뮬 시연 1000개/과제 × 4 = 4000, 실로봇 100개/과제 × 4 = 400이면 시연 수 기준 시뮬 비율은 90.9%입니다. 논문의 "약 80% 시뮬"(그림 5)은 프레임 수 등 다른 기준일 수 있으나 기준이 적혀 있지 않습니다(K3).
- 공개 실로봇 데이터셋의 에피소드는 usb 50, gearassemb 50, peginhole 52개(HF 데이터셋 카드)입니다. 공개 코드의 에피소드 최대 길이(50 Hz)는 350/700/500 스텝이고 이를 곱한 상한은 약 7.8만 프레임으로, 논문의 "2M 샘플"과 같은 단위인지 알 수 없습니다(실로봇 부분만).

## 8. 이 문서의 한계

- 시행 수 300 가정과 100 가정으로 두 번 계산한 것은 논문이 시행 구조를 밝히지 않았기 때문입니다. 실제 시행이 서로 독립이 아니면 p 값은 작게 나옵니다(학습 시드 분산 미반영).
- 그림 4는 판독 값입니다. 시행 수가 없어 검정을 하지 않았습니다.
- 토이 실험은 하지 않았습니다. 중심 주장(Dream)의 핵심 구성 요소가 공개 코드에 없고(`04` D1), 축소판이 논문이 아니라 우리 해석을 검증하게 되기 때문입니다.
