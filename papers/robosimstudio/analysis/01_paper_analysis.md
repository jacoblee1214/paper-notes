## 1. Abstract (한 줄 요약과 주장)

**한 줄 요약:** 시뮬레이터의 **solver, 접촉 모델, 물성 값을 명시적으로 드러내고 바로 고칠 수 있게** 만든 Newton 기반 도구입니다. 사람(브라우저 화면, 슬라이더, 힘 피드백 리더 암)과 코딩 에이전트(Claude Code, Codex)가 같은 장면을 고쳐 가며, 실제 영상과 비슷하게 움직이는 다중 물리 시뮬레이션(Real2Sim)을 빠르게 만들게 하려는 것입니다.

기여는 세 가지입니다(Sec. 1).

1. 접촉 모델과 물성을 바꿀 수 있는 contact-rich 조작용 시뮬레이션 도구 RoboSimStudio(RSS)
2. 사람과 코딩 에이전트가 함께 쓰는 Real2Sim 인터페이스
3. 시각·힘 피드백으로 만든 조작 과제 18개, 그리고 스마트폰 영상에서 코딩 에이전트가 다중 물리 시뮬레이션을 만든 Real2Sim2Real 파일럿 1건

논문은 스스로를 "개발 중인 시스템과 파일럿 연구"라고 부릅니다(Sec. 5). 정량 실험은 거의 없고, 대부분의 결과는 정성적 시연입니다.

## 2. Method

### 2.1 구조 (Fig. 2, Sec. 3)

```
영상·사진 (사람·로봇 시연, 스마트폰)
        │  사람: 브라우저 studio (Viser) — 선택·드래그·인스펙터 슬라이더
        │  코딩 에이전트: scene.py를 고치고 실행·관찰하는 반복 루프
        ▼
장면 = 로봇 + 물체 + 물리 배치(arrangement)
   물체는 "무엇인지"(강체, 관절, 천, 케이블, 스펀지 …)만 선언
   장면이 "어느 solver가 어떤 물리를 맡는지" 선언 → 바꿔도 과제 코드는 그대로
        ▼
Newton (Warp)  ─ 관절·강체: MuJoCo-Warp   ─ 천·케이블: VBD
        └─ 외부 엔진 co-sim: SuperDex(FEM 스펀지), Genesis   ← 접촉력·자세·wrench 교환
        ▼
변형(물성 E, 공간 배치) → Graph-as-Policy(GaP)로 정책 개선 → 실제 로봇
```

### 2.2 로봇 인터페이스
Franka Panda, UR5e, 단팔·양팔 YAM의 공통 인터페이스가 있습니다(Sec. 3). IK는 PyRoKi 같은 solver를 바꿔 끼울 수 있고, 계획은 cuRobo를 씁니다. 정책은 관절 공간이나 엔드이펙터 공간으로 명령합니다. **조작 물체의 privileged 상태는 로봇이 볼 수 있는 관측과 분리**합니다.

### 2.3 다중 물리와 결합
기본값은 다음과 같습니다. 관절 로봇은 MuJoCo-Warp, 케이블과 천은 Vertex Block Descent(VBD), 연성체는 외부 엔진(SuperDex, Genesis)과 co-sim입니다. Newton 내부 solver끼리는 접촉력을, 외부 엔진과는 자세와 접촉 wrench를 주고받아 결합합니다. solver, 결합 방식, 접촉 모델, 재료 값은 장면의 명시적 항목이라 과제를 다시 쓰지 않고 바꿀 수 있습니다(Fig. 3).

### 2.4 사람용 인터페이스 (Fig. 4)
Viser 기반 브라우저 studio입니다. 물체를 선택·드래그·검사하고 로봇 팔을 직접 움직일 수 있습니다. 인스펙터는 물성을 **단위·범위와 함께** 보여 주고, 실행 중 바꿀 수 있는 값과 장면을 다시 만들어야 하는 값을 구분해 표시합니다.

### 2.5 에이전트용 인터페이스
코딩 에이전트는 사람과 같은 루프를 돕니다. 장면을 고치고, 행동을 실행하고, 결과를 관찰합니다. RSS는 rollout을 로봇 동작 primitive로 나누고, 시뮬레이터 상태를 **시공간 텍스트 피드백**으로 바꿔 줍니다. 피드백에는 목표 오차, 물체 움직임, 접촉 사건, 잡기·미끄러짐, 과제 진행도가 들어갑니다. 사람은 에이전트가 작업하는 동안 비동기로 같은 화면을 보며 값을 고치거나 지시할 수 있습니다(human-in-the-loop).

## 3. 사례 연구 (Sec. 4)

### 3.1 시각 피드백으로 하는 사람 Real2Sim (Sec. 4.1, Fig. 5)
사용자가 자산을 고르고 배치하고 물리 모델을 고른 뒤, 실제 거동과 시뮬레이션이 **정성적으로** 맞을 때까지 접촉·재료 값을 조정했습니다. 이렇게 과제 18개를 만들었습니다. 예로 든 것은 세 가지입니다.

- **커넥터 삽입:** USB-C를 1 mm 미만 여유로 꽂으려고 메쉬 기반 접촉과 충돌 해상도를 조정했습니다.
- **잎 누르기:** 쉘 시뮬레이션으로 얇은 잎의 휨과 회복을 표현했습니다.
- **띠 연마:** 접촉력에서 Preston 식으로 재료 제거량을 계산했습니다.

본문은 한 문장 안에서 "세 과제"와 "다섯 예"를 함께 쓰고, 실제로는 셋만 나열합니다. 편집 흔적으로 보입니다.

### 3.2 힘 피드백으로 하는 사람 Real2Sim (Sec. 4.2, Fig. 6)
저가 리더 암(논문은 GELLO[58] 인용)으로 시뮬레이션 로봇을 조종하고, 시뮬레이션 접촉을 리더 모터 토크로 되돌려 줍니다. 명령 자세와 시뮬레이션 자세의 차이가 피드백 신호입니다. 시뮬레이션 지연을 접촉으로 착각하지 않도록 속도 의존 deadband를 두고, 시뮬레이션이 멈추거나 뒤처지면 피드백을 끕니다. 그리퍼는 명령값이 아니라 측정된 열림을 씁니다. 공구 걸기 과제를 시연했지만 정량 결과는 없습니다.

### 3.3 에이전트 Real2Sim2Real (Sec. 4.3, Fig. 7)
양팔 스펀지 닦기 과제입니다. 한 팔이 막대를 잡고 다른 팔이 폼 스펀지로 마커 줄을 지웁니다.

| 단계 | 보고 내용 |
|---|---|
| 구축 | CAD도 보정 카메라도 없는 스마트폰 영상 하나로 Claude Fable 5.1(Claude Code)과 GPT-6 Astra(Codex)가 각자 "약 1시간"에 다중 물리 시뮬레이션을 만듦. 한 에이전트는 56분에 검증 완료(14분 팔·막대, 42분 첫 닦기, 51분 배경, 56분 검증) |
| 물리 | MuJoCo-Warp(Newton) + SuperDex(스펀지 FEM). 접촉력과 압력 분포 확인 |
| 변형 | 스펀지 강성 6·20·100 kPa, 막대·스펀지 배치 30개 |
| 정책 | GaP가 14번 반복으로 시뮬레이션에서 닦인 면적을 0% → 100%로 올림(반복 9: 29%, 11: 71%) |
| 실제 | 개선된 정책을 실제 로봇에서 실행해 닦기 완료. 한 rollout에서는 시뮬레이션에서 고정했던 막대 받침이 밀려나 실패 |
| 정제 | 실패 영상과 설명을 받은 에이전트가 고정 제약을 자유 강체로 바꿈 → 수정된 시뮬레이션은 막대가 밀리고 기우는 현상을 재현 |

## 4. 해석

- **이 논문의 실체는 도구입니다.** 성능 표가 없고, Table 1은 다른 프레임워크와의 기능 비교입니다. 그런데 이 표에서 RSS는 10개 행이 모두 ✓이고, RSS만 ✓인 5행은 전부 이 논문이 정의한 워크플로입니다(`04` C1). 비교라기보다 기능 목록에 가깝습니다.
- **GaP 곡선의 단위가 그림마다 다릅니다.** Fig. 1은 y축을 "completion rate"라고 쓰고, 본문과 Fig. 7f는 "simulated wiped area"라고 씁니다. 29%와 71%는 30개 배치의 성공 비율로는 나올 수 없는 값입니다(k/30 = 26.7, 30.0, 70.0, 73.3%). 따라서 닦인 면적 같은 연속량이거나 다른 분모입니다(`04` C2).
- **실제 로봇 결과는 시행 횟수가 없습니다.** "실제 로봇에서 닦기를 완료했다"와 "한 rollout이 실패했다"만 있습니다. 시뮬레이션-실제 일치도는 "주로 정성적 관찰"이라고 저자들도 씁니다(Sec. 5).
- **공식 저장소가 논문보다 훨씬 구체적입니다.** 다음 사실은 저장소에서만 드러납니다.
  - 공개 twin의 스펀지는 friction만으로 잡히지 않습니다. 그래서 패드 주변 폼 노드 106개를 손에 고정(latch)하고, 영상의 부엌 스펀지(약 20 kPa) 대신 80 kPa 폼을 씁니다(`04` D3·D4).
  - 18개 과제 대부분과 UR5e, GaP 닦기 정책, 30개 배치는 공개 저장소에 없습니다(`04` D1·D2·D6).

## 5. Limitations

### 5.1 저자가 밝힌 한계 (Sec. 5)
- 개발 중인 시스템이고 파일럿 연구입니다.
- 에이전트의 시뮬레이션 구축은 RSS가 제공하는 재료 모델, 물리 결합, 로봇 자산에 의존합니다.
- 외부 엔진 co-sim은 계산 부담이 있습니다.
- sim-to-real은 과제 하나로만 평가했고, 일치도는 주로 정성적입니다.
- 향후 과제로 시뮬레이션 정확도, 접촉력, 물체 궤적, 구축 시간, 실제 성공률의 체계적 정량 평가를 들었습니다.

### 5.2 분석하면서 추가로 발견한 한계와 의문점
1. **"영상과 맞을 때까지"의 판정 기준이 없습니다.** 맞았다는 판단이 눈으로 하는 정성 비교입니다. 영상만으로는 강성 같은 값이 잘 정해지지 않습니다. toy로 계산하면 1080p 영상에서 판독 잡음이 0.5 px만 있어도, E가 약 100 kPa를 넘으면 E 추정의 상대 표준오차가 50%를 넘습니다. 80 kPa와 100 kPa는 0.4σ 차이라 구분되지 않습니다(`03` §2). 논문이 강성을 "맞추기"보다 6–100 kPa로 "변형"한 이유로 읽을 수 있습니다.
2. **공개 twin은 물리적 잡기를 우회합니다.** 마찰만으로는 세 take 모두 폼이 손에서 69–226 mm 미끄러졌고, 닦인 비율도 0.69–0.76에 그쳤습니다. 30회를 더 시도해도 미끄럼을 10 mm 아래로 줄이지 못했습니다(`04` C4). 같은 저장소의 에이전트 작업 규칙은 latch·weld·attachment를 금지합니다(`examples/live/AGENTS.md`, 2026-10-22 추가). 즉 논문 시점의 데모가 이후 규칙을 어깁니다.
3. **강성 변형 범위가 실제 잡기 가능 범위와 겹치지 않습니다.** Fig. 7e의 6·20 kPa는 공개 twin의 집게 조건에서 스펀지가 패드 사이로 흘러나가는 범위입니다(`04` C6). GaP가 이 범위에서 어떻게 닦았는지는 공개 자료로 알 수 없습니다.
4. **에이전트의 기여와 사람의 기여가 분리되지 않았습니다.** "human-in-the-loop"를 강조하지만, 56분 동안 사람이 몇 번 개입했는지 기록이 없습니다. 저장소 README의 팁("가끔 물리와 기하를 재구성하라고 상기시켜라")은 개입이 필요했다는 뜻입니다.
5. **재현에 필요한 자산 상당수가 비공개입니다.** 18개 과제의 정의(테스트 코드가 `vabar` 컬렉션이라고 부르는 것), UR5e, 실제 로봇 실행 코드, GaP 닦기 그래프가 없습니다. 논문 시점에는 CPU 실행도 지원되지 않았습니다(2026-10-18 추가).
