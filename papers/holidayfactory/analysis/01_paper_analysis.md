## 0. 한눈에 보기

이 논문은 **시뮬레이터, 자동 월드 생성기, 반복 작업 벤치마크를 하나의 기술 보고서로 묶은 프레임워크**입니다. 세 기여는 다음과 같습니다.

1. **HOLIDAY-SIM**(§3): Newton의 희소 SDF 기반 수압 탄성(hydroelastic) 접촉에 압력 법칙 확장, 원시-쌍대 반복 솔버(CDMM), 상태를 가진 액추에이터, 자기 촉각 센서를 더했습니다.
2. **에이전트 월드 구축**(§4): 자산 생성기 ERIS(§4.1), 역방향 장면 생성 ISG(§4.2), 사람이 확인하는 평가 생성(§4.3).
3. **24/7-BENCH**(§5): 장면을 리셋하지 않고 작업(job)을 반복하는 산업 작업 7개와 그 지표(처리량, 지연, 실패, 미완료, 모터 에너지).

논문이 **보여주지 않은 것**도 분명합니다. 저자들은 결론(§7)과 §5.3, §6.6에서 "정책을 persistent run으로 비교한 적이 없다"고 적었습니다. 따라서 24/7-BENCH의 정책 순위, 기준선(baseline), 유의성 검정 결과는 **본문에 없습니다.** 실물 로봇과의 비교도 없습니다(§6.1: "No result has been compared with measurements from a physical robot").

## 1. 문제 설정 (§1, §2)

- 동기: 로봇 평가는 보통 리셋에서 시작하는 에피소드로 이뤄지지만, 산업 작업은 이전 작업이 다음 작업의 상태를 바꾸는 연속 작업입니다. 독립 성공률 95%면 20개 연속 작업 성공 확률은 36%, 99%면 82%라는 계산을 서론에서 듭니다(0.95^20 = 0.359, 0.99^20 = 0.818로 재계산 일치, `analysis/04_claim_verification.md` C10).
- 세 연구 질문: RQ1 접촉·구동·감지 시뮬레이션, RQ2 과제 조건 월드 구성, RQ3 지속 상태에서의 반복 작업 측정(§1.1).
- 형식 정의(§2.1, 표 1–2): 작업장 W, 과제 T, 월드 ξ = (S, E). 시나리오 S = (scene variants s_1..s_Ns, 공정 논리 ℓ), 평가 E = (job j, 지표 m_1..m_Nm, 루브릭 c). 식 (2): S ∼ G(T, W), E ∼ A(T, S). 여기서 G는 장면 생성, A는 평가 생성(사람 확인 포함)이고 V_scen, V_eval은 각각 검사입니다.
- 로봇: FRIDAY 휠형 휴머노이드, 75개 관절(활성 64, 수동 11), 머리·손목 카메라, IMU, LiDAR, 촉각 피부(표 46). 기본 시간 설정은 제어 주기 1/60 s, 물리 하위 단계 4개(1/240 s)(표 47).

## 2. HOLIDAY-SIM (§3, 부록 A·B)

### 2.1 접촉 (§3.1)

- 동기: 볼록 분해와 점 접촉(표 4의 대부분 벤치마크)은 분포 하중을 몇 점으로 모읍니다. 수압 탄성(Elandt 2019; Drake 구현)은 사면체 메쉬가 필요합니다. Newton은 메쉬 없이 희소 SDF에서 같은 원리를 씁니다(식 (3): 두 물체의 압력이 같은 면).
- 압력 법칙 식 (4): p = k_h [−φ]_+ (기본 선형). 식 (5): p = k_h x (1 + β (x/ℓ)²), β ≥ 0, x = [−φ]_+. β = 0이면 선형으로 돌아갑니다. 깊이에 따른 강성 증가를 넣은 확장입니다. 소성, 크리프, 측면 팽창은 모델에 없습니다(§A.2).
- 지면 접촉 식 (6): 무한 평면에는 SDF를 두지 않고 패치를 2차원 구적으로 적분합니다. 바퀴의 미끄럼 속도가 바퀴 폭 방향으로 달라지므로 패치 압력이 필요하다고 설명합니다.
- 힘과 모멘트 식 (7). 마찰 식 (8): µ(v) = µ_s [r + (1 − r) e^{−v/v_c}]. 정지 마찰은 µ_s, 빠른 미끄럼에서는 r µ_s로 줄어듭니다. 이 식은 r = 1이면 쿨롱 마찰로 돌아갑니다.
- 감쇠: Hunt–Crossley 형태 f_n = K δ [1 − α v_n]_+(α는 s/m, v_n > 0은 분리). 접촉이 깊을수록 같은 접근 속도에서 감쇠가 커지고, 힘은 음수가 되지 않습니다.
- 솔버: CDMM(Constrained Dynamics via Method of Multipliers)의 원시(운동)–쌍대(접촉 반력) 반복. 접촉 블록 전처리, 충돌 간격 재샘플링에 따른 임펄스 웜스타트, 하위 단계 분할을 씁니다(§3.1.2, §A.2).
- 검증 근거: (a) 손가락 끝 패치 마찰 반경은 같은 법칙의 수치 구적과 비교(그림 5a, d), (b) 손가락 하중·제하 루프에서 감쇠가 침입 깊이에 따라 커지는지(그림 5b, e), (c) β에 따른 힘 곡선(그림 5c, f), (d) 바퀴 폭에 따른 요(yaw) 이득 감소(그림 6). 모두 **수치 기준과의 비교**이며 하드웨어 측정이 아닙니다(§6.1).
- 배터리 들기 비교(표 5): CDMM 20/20 성공, MuJoCo 반복 15회 1/20, 100회 0/20. 시간 간격 4개 × 5회씩이라 방법당 20회입니다. **단서:** 파지 자세와 목표값을 CDMM으로 튜닝했다고 적혀 있습니다(§3.1.2 본문). 이 비교는 솔버만의 효과를 분리하지 못합니다.

### 2.2 촉각 (§3.1.3, §A.4)

- 피부 안의 자석이 접촉 압력으로 옮겨지고(식 (9)의 Green 함수 형태 중첩), 홀 센서 값은 쌍극자 장(식 (10))으로 계산합니다.
- 접촉 패치에서 나온 하중 분포를 쓰므로 같은 순 하중이라도 패치 모양이 다르면 다른 판독이 나옵니다(그림 8, 그림 9). 그림 9는 같은 1 N 하중의 세 프로브가 다른 판독을 낸다는 **정성 예시**입니다. 측정과 비교하지 않았습니다.
- 결합은 한 방향입니다. 복원된 변형은 충돌 기하나 동역학으로 되돌아가지 않습니다.

### 2.3 상태를 가진 액추에이터 (§3.2, 부록 B)

- 모터 전기식 식 (11): L di/dt = V − R(T) i − k_e ω_m, τ = k_t i. 전류와 전압 한계, 열 상태(구리 손실, 권선 온도) 포함.
- 전달 기구는 기하 변환 식 (12): θ_m = φ(q), r(q) = dφ/dq, I_ref = I_r r(q)². 오프셋 슬라이더-크랭크 예시로 관절 위치에 따라 토크와 반사 관성이 달라짐을 보입니다.
- 마찰은 LuGre 모델(bristle 상태)입니다. 저속 미끄럼 전·미끄럼 중 전환과 반전을 설명하려고 추가했습니다.
- 암묵(implicit) 결합 식 (13): M_aug = M + diag(I_ref) + h D_act + h² K_act. 제어기 이득, 수동 스프링, LuGre 강성 근사가 관절 임피던스로 들어갑니다.
- 단일 작용 유압 손가락의 예(그림 10): 구동은 한쪽 방향으로만 힘을 냅니다. 모델은 chamber 힘 상태를 씁니다.
- 텔레메트리 식 (14): τ̂ = a_τ η r(q) k_t î + b_τ + ε_τ. 전류 기반 추정은 내부 마찰 때문에 실제 관절 토크와 다릅니다. 보정 오차와 Ornstein–Uhlenbeck 잡음도 넣었습니다.
- 비교(표 6): LIBERO, RoboCasa365, ManiSkill3는 "이상적 토크 또는 PD 구동, 내부 상태 없음"입니다. 이 점이 HOLIDAY-SIM의 차별점입니다. 다만 **모델 파라미터가 어떤 실물 장치에 맞춰졌는지 논문에 없습니다.**

## 3. 에이전트 월드 (§4)

### 3.1 자산 생성 ERIS (§4.1)

- 과제 지시에서 LLM이 타입 있는 제약 집합을 뽑고, 결정론적 식 (15)로 세 분기 중 하나를 고릅니다. 메쉬(MESH: 텍스트→이미지→3D 메쉬), 코드 강체(CODE-RIGID: Blender 프로그램), 코드 관절(CODE-ARTICULATED: 관절 선언 포함).
- 검증 단계(표 7): 적합성(conformance), 충돌체(collider: SDF 해상도, 충실도, 배치 보존), 관절(articulation), 상호작용(interaction: 삽입, 굴림, 운반, 보유). 단계 적용 여부는 분기에 따라 다릅니다(표 8). 한 라운드 안에서 모든 단계를 끝까지 돌려 위반을 한꺼번에 피드백합니다.
- 충돌체 목적 식 (16): min M_SDF(Π, Δ_vox) 제약은 FSDF. 라운드 중 SDF를 구운 뒤 22% 콜라이더가 재작성되었습니다(표 12).
- 수정 식 (17): X_{t+1} = F_b(X_t, R, C⁻, C⁺). 성공한 제약 C⁺를 함께 주어 후퇴를 막습니다.

**실험(§4.1.5, 부록 C):**
- 분기 선택(표 10): 시각 충실도는 메쉬가 VLM 판정 80%(60건), 코드는 0%. 치수·구조 항목은 코드가 100%, 메쉬는 0–37.5%. 다만 60건은 **자산 30개를 두 번씩 판정한 것**이라 독립 표본이 30개입니다. 판정자는 claude-fable-5-1입니다.
- 첫 라운드 검증 실패(표 11): 72개 중 34개(47%) 탈락. 적합성이 주원인(28개, 고유 실패 24개).
- 수정 피드백(표 13, 32개, 같은 1차 자산): 1차 실패 12개 중 E RIS는 11개를 한 번에 고쳤고 나머지 1개도 두 번째 라운드에서 고쳐 Success@3 = 32/32. 독립 재생성 27/32(84%), 거친 피드백 26/32(81%).
- 백본 5종(표 14): 20과제 × 2회, 40쌍. E RIS가 독립 재생성보다 Success@4를 25–35 pp 높임. 예: opus 26/40 → 40/40.
- 생성 효율(표 15): 해결당 라운드 3.81(독립) → 1.70(E RIS), 해결당 비용 $5.00 → $2.48. 라운드당 비용은 오히려 늘었습니다.

### 3.2 장면 생성 ISG와 배경 (§4.2, 부록 D)

- 알고리즘 1: 과제 계획 Γ(예측 상태 그래프, 1차 검사 + 계획 비평가, 점수 ≥ 0.8 필요)와 장면 명세 Ŝ(자산 선택, 변형 해석, 정적 검사, 장면 비평가)를 순서대로 검증합니다. 정적 기준: 겹침 5 mm 이하, 지지 여유 1 cm 이하. 계획 검사는 술어 상태 10⁴개까지만 탐색하므로 식 (18)의 전칭 조건을 **완전히 보장하지 못합니다**(논문도 인정).
- 피드백 효과(그림 14 우): 시도 5회 안의 성공이 gpt-6-astra 3/9 → 9/9, gpt-6.1-sol 2/9 → 7/9. 합치면 5/18 대 16/18입니다. 계획 검사 생략(그림 14 좌): 전체 검사를 통과한 후보가 1/10 대 5/10.
- 비평가 의존성(표 17, 그림 15): 같은 후보를 다른 비평가로 평가하면 장면 수용률이 달라집니다. 공통 비평가 opus에서 gpt-6.1-sol과 sonnet 모두 3/10으로 같습니다.
- 병목(표 19): 예산을 두 배로 늘려도 자산 부족이 대부분 실패의 원인입니다. 어포던스를 프롬프트에 적은 것만 수용 2/10을 늘렸습니다.
- 배경(§4.2.2, 부록 D.2): 파노라마 → 가우시안 스플랫. 독점 서비스(World Labs 계열)와 공개 체인 두 경로. 블라인드 VLM 판정은 독점 배경을 18번 비교에서 모두 선택, 평균 2.85 대 1.78(5점). 논문은 "두 배경 모두 사용 가능 수준은 아니다"라고 적었습니다. 배경은 관측 모델 O_s에만 들어가고 물리 F_{s,ℓ}은 바뀌지 않습니다(그림 17의 아홉 장).
- 공정 논리(§4.2.3): 효과, 이벤트, 큐, 유휴 목표의 네 종류. 스키마 검증만 하고 **의도한 공정을 구현했는지는 확인하지 않습니다.**

### 3.3 평가 생성 (§4.3, 부록 E)

- 에이전트가 과제·장면에 대해 모호한 점을 질문하고, 사람이 확인한 제안(작업, 지표, 루브릭)을 결정론적 컴파일러가 실행 가능한 평가로 바꿉니다. 모델 호출 없이 이뤄집니다.
- 세 가지 검사(표 21): 정적, 리셋(4 s 자유 물리), 유휴(로봇 제어 없이 실행). 이 검사로는 **과제 의도**를 판정할 수 없습니다(논문도 인정).
- 실험(그림 19, 표 43): 단일 tote 이송 한 과제, 모델 4종 × 3시행, 기록 15개(성공 4, 실패 11) 대조. 직접 생성 수용 6/12 → 검증 피드백 후 12/12. 질문 유도 생성은 10/12, 피드백 후 11/12. **질문 유도 생성은 15개 기록과 모두 일치**했지만, 시뮬레이션 사용자가 고정된 과제 의도 명세로 답합니다. 즉 의도 명세가 사용자 쪽에 들어 있어 순환성이 있습니다.
- 검증 피드백은 판정을 한 번도 바꾸지 못했습니다("does not correct any of the 21 misclassified recording pairs").

| 지그 적재 | 트레이의 지그를 벤치 지그에 끼우고 빈 지그를 보관 | 보관된 지그 | 없음(고정된 초기 집합) |
| 프레스 작업 | 2손 제어로 프레스를 가동하고 찍힌 부품을 배출 | 출력 부품 | 이벤트 5 |
| 밸브 조작 | 입구 쪽에서 비커를 채우고 출구 쪽 밸브를 잠금 | 채워진 비커 | 없음(고정된 초기 집합) |
| 바코드 분류 | 바코드를 스캔해 벨트 끝에서 목적지 tote로 | 목적지 tote | 벨트 1, 이벤트 2 |

- 평가 구조: 작업 정의는 특권 시뮬레이터 상태에 대한 이벤트 집합입니다(표 23). 이벤트는 술어가 K_hold 스텝 연속 참일 때 발생(식 (19): r_t = b_t (r_{t−1} + 1), e_t = 1[r_t = K_hold]). 작업이 끝나면 완료, 실패 이벤트, 시간 초과, 실행 종료에 의한 검열 중 하나입니다.
- 장면 변형(scene variant)이 평가 단위이고, 배경만 다른 변형은 F_{s,ℓ}을 공유합니다(§5.3).

### 4.2 지표와 루브릭 (§5.2–5.3)

- 처리량: 3600 N_done / T_run(작업/시간, T_run은 초). 지연은 완료 작업만 보고하면 쉬운 작업 쪽으로 편향될 수 있어, 미완료는 Kaplan–Meier형 검열, 실패는 경쟁 위험(Fine–Gray)으로 다루겠다고 합니다. 논문은 이 추정량을 **실제로 계산하지는 않았습니다.**
- 모터 에너지: 모터 단자 전력의 인출·회생 에너지와 작업당 인출 에너지(실패 시도 포함). 계산과 센서 부하는 제외.
- 루브릭: 목표 작업 수 N_goal 도달, 시간 한계, 비활동 한계. 통과(식 (45))는 실패·시간 초과·정지·위반이 없을 때만.
- 검증(§5.2.3): 과제 6개(컨베이어 적재 제외)에 대해 영역 검사 185개, 시작 상태 탐침 20개, 스크립트 궤적 32개. 모두 기대 결과와 맞았다고 보고합니다. 이는 **이 평가 정의가 테스트한 사례에 맞는다**는 뜻이지 정책 성능이나 과제 완전 포괄을 뜻하지 않습니다(논문도 명시).
- 비교 원칙(§5.3): 같은 변형, 같은 초기 조건 분포에서 여러 정책을 비교하고, **실행(run)을 통계 단위**로 씁니다. 작업들이 상태를 물려받기 때문입니다(§6.6도 같은 말을 합니다).

### 4.3 결과

- **정책 결과 없음.** 표 21(검사)과 그림 21(채점표 모양, 개략도)만 있습니다. 그림 21 왼쪽의 프레스 주기 기록도 "개략도"로 표시된 예시입니다.
- 평가 실행의 반복 횟수, 시드 수, 신뢰구간은 제시되지 않았습니다.

## 5. 논의와 한계 (§6, §7)

저자들이 스스로 든 한계를 그대로 옮기면 다음과 같습니다.

1. **물리 모델의 실물 검증 없음**(§6.1): 접촉·액추에이터·센서 모델은 "명시된 동작"과만 비교했습니다. 물리 세부 사항이 정책 순위를 바꾸는지는 **측정되지 않았습니다**.
2. **자동 검증의 한계**(§6.2): 장면 수용은 비평가에 따라 달라지고, 평가 검사는 의도를 보지 못합니다. 라벨 없이는 검증 피드백이 판정을 고치지 못했습니다.
3. **장면 다양성 미측정**(§6.3): 생성 장면이 다양한지는 정의만 있고 정량화하지 않았습니다.
4. **코딩 에이전트 의존**(§6.4): 파이프라인 구성 요소의 필요성은 에이전트 버전마다 다시 검증해야 합니다. 생성 세계는 에이전트와 하니스 버전에 묶입니다.
5. **학습된 평가자 감독**(§6.5): 물리가 준 작업 기록을 진행률 감독으로 쓸 수 있다고 제안하지만 실험은 없습니다.
6. **통계적 신뢰성**(§6.6): "정책 두 개를 구별하려면 실행을 몇 번 해야 하는지는 알 수 없다"고 적었습니다. 이 분석의 토이(`analysis/power_toy.py`)가 이 질문을 조금 채웁니다(`03` §4).

추가로 분석에서 확인한 한계:
- 생성 실험은 대부분 **작은 표본**입니다(n = 3–40). 많은 비교가 쌍 설계인데 쌍 정보를 공개하지 않았습니다.
- 여러 실험이 같은 과제·같은 모델 기반이라 일반화 범위가 좁습니다. 평가 생성은 과제 1개, 기록 15개입니다.
- 로봇은 FRIDAY 하나입니다.
- 공식 코드, 자산, 장면 파일이 공개되지 않았다는 근거는 §6의 "open-source ecosystem" 문장뿐이고 **공개 링크는 없습니다**(`02` §4).
