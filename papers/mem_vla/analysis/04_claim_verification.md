# 04. 주장 검증과 구현 가능성

공식 코드가 없어서(`02_prior_work.md` §4) 논문 대 코드 대조 대신 **논문 주장을 그림 수치로 다시 확인**합니다. V 번호는 `03_analysis.md`, 그림과 절은 논문 v2 기준입니다. 판정 표현은 "확인됨 / 부분 확인 / 이 자료로는 확인 안 됨"으로 씁니다. "확인 안 됨"은 틀렸다는 뜻이 아니라 시행 수나 설계가 그 서술을 뒷받침하기에 부족하다는 뜻입니다. 수치는 그림에서 읽은 값이고 시행 수는 가정입니다.

## 1. 주장 검증 (C1–C14)

| 번호 | 주장 (위치) | 확인한 것 | 판정 |
|---|---|---|---|
| C1 | 장기 과제에서 영상·언어 기억이 둘 다 필요하다 (Sec. IV-A, 그림 6) | MEM 대 네 변형: 레시피 +23~+35%p, 부엌 청소 +48~+70%p. 정규 근사 p ≤ 0.011, 롤아웃 단위 Welch(부엌 청소 n = 10, 레시피 n = 5 또는 10)에서도 p ≤ 0.034(V3, V22) | 확인됨 |
| C2 | 압축하지 않은 "naive" 언어 기억은 학습-추론 분포 이동으로 나쁘다 (Sec. IV-A) | naive 대 MEM 차이는 확인(V3). 분포 이동이 원인이라는 부분은 직접 측정이 없음. 토이 T2는 재시도가 흔할 때 이력이 학습 모양을 벗어나는 비율만 계산(f = 0.2에서 0.83, 가정) | 부분 확인 (성능 차이는 확인, 원인은 이 자료로 확인 안 됨) |
| C3 | 교정 데이터를 기억과 함께 쓰면 맥락 안에서 전략을 바꾼다 (Sec. IV-B, 그림 7) | 냉장고 +61.9%p(7/21 대 20/21 가정, p = 5×10⁻⁵). 젓가락 +10.6%p는 시행 수 가정에 따라 p 0.39–0.023(V19). 실제로 전략을 바꾸는지의 행동 분석은 정성 그림만 | 부분 확인 (냉장고 확인, 젓가락은 시행 수 불명) |
| C4 | MEM이 모든 기억 능력에서 강하다 (Sec. IV-C, 그림 8) | 평균 +34~+44%p (p < 10⁻⁷). 과제별로는 머그 교체, 물체 찾기, 창 닦기에서 모든 기준선 대비 유의. 커피 스쿱(p 0.12–0.24)과 그릴드 치즈(풀링 대비 +3.4%p, p = 0.80)는 구분되지 않음(V6) | 부분 확인 |
| C5 | 풀링 기억은 장기 기억 과제에서, 고유수용 기억은 환경 상태 기억에서 약하다 (Sec. IV-C) | 풀링: 머그 교체 31.7, 식료품 13.3(기억 없음 33.3보다 낮음, 시행 수 15에서 2/15 대 5/15 p = 0.39). 고유수용: 물체 찾기 29.7(기억 없음 31.3과 같음), 머그 교체 51.7(기억 없음 10.0보다 높음) | 부분 확인 (대략 서술과 맞고 풀링의 식료품 하락은 구분 안 됨) |
| C6 | 사전학습이 기억 활용을 크게 높인다 (Sec. IV-C, 그림 9) | 평균 +22.6%p (p = 0.0003), 창 닦기 +47.1%p만 개별 유의, 나머지 다섯 과제는 방향만 양(V10) | 부분 확인 |
| C7 | 사후학습만 변형도 풀링 기억보다 영상 인코더 설계가 낫다 (Sec. IV-C) | 평균 +16.1%p (p = 0.011), 머그 교체 +36.7%p. 다른 과제는 구분 안 됨(V11) | 부분 확인 |
| C8 | 기억이 필요 없는 과제에서 π0.6과 동등하다 (Sec. IV-C, 그림 10) | 평균 +0.5%p [−5.7, +6.7]. 과제별 부호 3 양, 3 음. 구간이 ±10%p에 들어가는 칸은 평균 포함 세 칸뿐(시행 수 10–45, V12) | 부분 확인 (평균은 지지, 과제별 동등성은 확인 안 됨) |
| C9 | 영상 인코더가 많은 프레임을 실시간 기준 안에서 처리한다 (Sec. III-C, 그림 3) | 16프레임 0.208 s, 선형 맞춤 18–19프레임 0.23–0.24 s(외삽). 인코더 없음은 4프레임에서 0.341 s(V1). H100 1장, 카메라 4개 | 확인됨 (측정 범위 안). 고수준 정책 지연은 그림에 없음 |
| C10 | 어텐션 비용이 O(n²K²)에서 O(Kn²+nK²)로 준다 (Sec. III-C) | 식은 맞고 n = 1,024, K = 6에서 36배 대 6.01배, 시간 항 비중 0.15%(V15). 4층마다 시간 어텐션을 넣은 점은 비용 식에 반영돼 있지 않음(더 작아짐) | 확인됨 |
| C11 | K = 1이면 인코더가 원래 ViT와 정확히 같다 (Sec. III-C) | 시간 마스크가 자기 시점을 제외하거나 시간 항이 영초기화일 때만 성립. 대각 포함 마스크면 차이 0.27–1.25(평균 출력 크기 0.129, 토이 T1). 본문에 규약 없음 | 확인 안 됨 (서술되지 않은 규약이 필요) |
| C12 | 인과 혼동 완화용 보조 목적 없이도 성능이 높고, 다양한 사전학습 데이터 덕분이다 (Sec. I, IV-C) | 그림 10의 성능은 확인. "다양한 데이터 덕분"은 데이터 구성을 바꾼 절제가 없음 | 부분 확인 (성능) / 확인 안 됨 (원인) |
| C13 | 최대 15분 과제를 수행한다 (초록, 그림 1, 5) | 레시피 준비와 부엌 청소 점수는 확인(그림 6). 에피소드 소요 시간은 보고되지 않고 그림 5의 장면 구성만 있음 | 부분 확인 (시간 길이는 서술만) |
| C14 | 최신 수준의 성능이다 (Sec. I, V) | 비교는 자체 재구현(풀링, 고유수용, 사후학습만)과 π0.6. MemoryVLA, MemER 등 공개된 기억 방법과 같은 과제 비교는 없음 | 확인 안 됨 (비교 범위가 이 설정 안) |

덧붙임: "현재 세대 LLM이 요약을 잘한다"(Sec. III-B)는 요약 품질 평가나 LLM 이름이 없고, "기억이 있는 정책이 인과 혼동으로 성능이 떨어진다는 선행 보고"(Sec. II)는 이 논문에서 측정하지 않았습니다.

## 3. 공개 π0/π0.5 코드(openpi)와의 정적 대조 (O1–O7)

MEM 공식 코드는 없으므로 저자 소속 기관의 공개 저장소를 커밋 `215abfb`(2026-08-24)에서 정적으로 읽어, MEM을 구현하려면 무엇이 비어 있는지 정리했습니다(실행·설치 안 함).

| 번호 | 항목 | openpi | MEM 논문 |
|---|---|---|---|
| O1 | 입력 해상도 | 224×224 (`model.py`의 `IMAGE_RESOLUTION`) | 448×448 (Sec. III-D) |
| O2 | 비전 인코더 | SigLIP So400m/14 (폭 1152, 27층, 16헤드, `siglip.py`) → 224에서 이미지당 256 토큰 | SigLIP 400M, 448에서 이미지당 1,024 토큰(14 패치, 가정) |
| O3 | 언어 백본 | Gemma 2B (폭 2048, 18층, `gemma.py`) | Gemma3-4B |
| O4 | 액션 전문가 | gemma_300m (폭 1024, 18층) | 860M |
| O5 | ViT 블록 | `Encoder1DBlock`은 표준 MHSA + MLP. 시간 축, 과거 프레임 입력, 이력 인자가 코드에 없음(검색으로 확인) | 4층마다 시간 어텐션, 상위 층에서 과거 토큰 삭제 |
| O6 | 상태 입력 | π0는 `state_proj` 선형 한 토큰(`pi0.py`), π0.5는 이산 상태 경로(`discrete_state_input`) | 과거 상태 K개를 선형 사영한 토큰 |
| O7 | 고수준 하위 과제·언어 기억 | 해당 경로 없음 (π0.5도 공개 코드는 흐름 정합만 지원, 별도 분석 참조) | 고수준 정책이 하위 과제와 기억 m을 출력 |

따라서 영상 인코더는 `siglip.py`의 블록을 수정(시간 어텐션 추가, 토큰 삭제)하고 입력을 (B, K, H, W, C)로 넓히는 변경이 되고, 사전학습 가중치와 π0.6 레시피는 없습니다.

## 4. 구현 가능성 판정

**판정 (이 맥: Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음)**

**논문 결과의 재현은 불가능하고, 방법의 소규모 재구현과 수치 재계산은 가능합니다.**

| 단계 | 판정 | 이유와 노력 |
|---|---|---|
| π0.6-MEM 사전학습·사후학습 (약 5.3B: 4B + 0.4B + 0.86B) | 불가 | 가중치, 코드, 데이터(42 레시피 외 대규모 혼합) 없음. bf16 가중치만 약 10.6 GB이고 학습 상태까지 더하면 24 GiB 초과 |
| 실로봇 평가 (레시피 준비, 부엌 청소, 그릴드 치즈) | 불가 | 로봇, 주방 환경, 최대 15분 과제 |
| 요약 라벨 생성 (기성 LLM 호출) | 보류 | 외부 API 호출은 승인이 필요. 규칙 기반 요약으로 대체 가능 |
| **영상 인코더 층의 소규모 재구현과 동치 검사** | **가능** | 작은 ViT(폭 128–384, 6–12층, 224px)에서 시공간 분리 어텐션, 과거 토큰 삭제, 파라미터 수 동일 확인, MPS/CPU 지연 측정. 토이 T1이 층 단위 검사를 이미 수행(1.5초). 1–2일(추정) |
| **언어 기억 방식의 축소판** | **가능** | 격자 세계나 MuJoCo의 다단계 과제에서 작은 트랜스포머 정책 + 규칙 기반 압축 기억 대 naive 지시문 이력 비교. 재시도 확률을 바꿔 분포 이동 효과 측정. 3–5일(추정) |
| 그림 수치 재계산 | 완료 | `analysis/recompute.py`, 토이 `analysis/toy_memory.py` |

**노력 추정 (추정, 측정 전)**

| 작업 | 시간 |
|---|---|
| 시공간 분리 어텐션 ViT와 K = 1 동치, 토큰 삭제 후 FLOPs·지연 측정 | 1–2일 |
| 합성 장기 과제 환경과 규칙 기반 기억 압축 | 2–3일 |
| 작은 정책으로 naive 대 압축 기억, 영상 이력 길이 비교 학습 | 2–4일 |
| 공개 openpi의 π0.5 가중치에 인코더를 붙이는 실험 | 불가에 가까움 (JAX, GPU 전제, 사전학습 없이는 논문 설정과 무관) |
