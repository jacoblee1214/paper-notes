# 01. 논문 분석: EagleVLA (arXiv:2607.12659 v7)

*EagleVLA: Towards Onboard Real-Time Robot Control via Foresight-Aligned Asynchronous Inference*. 저자 Zebin Yang, Qi Wang, Yunhe Wang, Xiurui Guo 외 5인 (Peking Univ., TLAIC, AIRS, PrimeBot Research Institute). 학회는 CoRL 2026 스포트라이트(공식 채택 목록에서 확인, `02` §0). 분석 대상은 **v7(2026-10-23, 최신)**이고, v1부터 v6까지의 차이는 §6과 `03` §5에 적었습니다.

## 0. 한눈에 보기

- **문제:** 온보드 장치(Jetson Orin)에서 VLA의 추론 지연이 길어 제어 주기가 낮습니다. 비동기 추론은 지연을 가리지만 두 가지 문제를 만듭니다. 추론이 끝날 때 환경이 이미 바뀌었고(지각-실행 불일치), 환경 변화에서 반응까지 시간이 청크 길이와 지연에 묶입니다(§1, §3).
- **방법:** (a) 가벼운 **미래 보정 모듈**(약 40M 파라미터, 논문 §4.1)이 VLM의 압축된 최종 층 표현을 실행 예정 행동 조건으로 t+∆ 시점 값으로 예측하고, 행동 전문가는 그 값으로 미래 시점부터 행동을 냅니다(FAAC). (b) 보정 모듈이 내는 **신뢰도**로 VLM 호출 여부를 정합니다(§4.2, Alg. 1). (c) llama.cpp 기반 엔진에서 CUDA 그래프 재사용, GPU 상주 버퍼, 흐름 매칭 unroll을 씁니다(§4.3).
- **주장 수치:** Orin에서 제어 주기 14.71×(naive PyTorch 대비), 9.20×(vla.cpp 대비), LIBERO에서 VLASH 대비 14.8 %p(§5.1, §5.2, 초록).
- **가장 중요한 주의:** 같은 논문의 헤드라인 수치가 v1 8.66× → v6 9.85× → v7 14.71×로 세 번 바뀌었습니다. 최종 행 측정치는 공식 저장소의 '최신 FP16 최적화 구성'(GEMM 튜닝 등)과 같고, 저장소는 그 Thor 구성의 정확도 게이트 미통과를 적어 두었습니다(`04` D12–D14, `03` §5).

## 1. 문제 설정과 동기 (§1, §3, Fig. 1–4)

- **배터리 수명:** RTX 4090을 쓰면 Jetson Orin보다 배터리 수명이 6.0배 짧다고 주장합니다(Fig. 1a, 500 Wh 배터리, 로봇 기계 전력 포함). Fig. 1a의 측정 조건(부하, 시간)은 본문에 없습니다.
- **지연:** π0.5는 Orin에서 약 1.4 s, 0.7 Hz입니다(§1, Table 1). Table 1은 π0, π0.5, 여러 장치(Orin 30 W·50 W, Thor, A6000, 4090)의 ViT, LLM, 행동 전문가 지연을 보여 줍니다. 원 표는 `03` §1.4의 합 검사를 보세요.
- **지각-실행 불일치(§3, Fig. 3a,b):** π0에서 LIBERO-Spatial/Goal을 ∆(지연을 행동 단계로 환산)별로 돌려, naive 비동기와 RTC는 ∆가 커질수록 떨어지고 VLASH는 긴 ∆에서 떨어집니다(Fig. 3의 값은 그래프에만 있어 재계산하지 않았습니다).
- **반응 시간(§3, Fig. 4):** 반응 시간은 ∆에서 ∆+L 사이이고(L은 청크에서 실행하는 행동 수), L이 커지면 성공률이 떨어집니다(Fig. 3c,d). 논문은 반응 시간을 **정의만** 하고 측정 절차는 쓰지 않습니다.
- **VLM과 행동 전문가를 병렬화하지 않는 이유(§4.2, Table 2):** RTX 4090에서는 VLM이 계산 바운드, 행동 전문가가 대역폭 바운드지만, 온보드 장치에서는 둘 다 대역폭 바운드라 병렬화하면 경합으로 둘 다 느려진다고 주장합니다. 이 주장의 계산 형태는 `03` §1.4에서 확인했습니다.

## 2. 방법 (§4, Fig. 5–6, 부록 A–C)

### 2.1 미래 보정 모듈 (§4.1, 부록 B, Fig. 10)

- **입력:** VLM 최종 층 출력(t 시점)을 Q-Former 블록으로 T' = 4 토큰에 압축하고, 실행 예정 행동 a_t … a_{t+∆−1}은 MLP와 Transformer 블록을 거쳐 마지막 토큰을 씁니다(부록 B).
- **출력:** 보정 항목(t+∆ 시점 압축 VLM 출력 예측)과 신뢰도 ĉ. 보정 항목은 행동 전문가에 KV 대신 한 개의 추가 조건 토큰으로 들어갑니다(Fig. 5, §4.1).
- **학습(두 단계, Eq. 1):** 1단계는 실제 h_{t+∆}로 압축기와 행동 전문가를 행동 손실로 학습합니다. 2단계는 보정 모듈을 L_predict = ‖ĥ_{t+∆} − h_{t+∆}‖² + λ‖ĉ + L_predict‖²로 학습합니다. 즉 신뢰도 ĉ가 −L_predict를 맞히도록 회귀합니다. ∆는 학습 중 무작위로 뽑습니다(§4.1).
- **Table 6 (부록 D):** 1단계 30,000 스텝, 2단계 25,000 스텝, 배치 32, 학습률 3e-4, AdamW, 코사인 스케줄, 워밍업 500, A100. 학습 결과의 총 파라미터 수와 λ 값은 본문에 없습니다.

### 2.2 신뢰도 기반 스케줄링 (§4.2, Alg. 1, Fig. 6)

- ĉ > θ이면 VLM을 건너뛰고 보정 모듈만으로 다음 청크를 냅니다. ĉ ≤ θ이면 VLM을 다시 돌려 KV 버퍼와 은닉 상태 버퍼를 갱신합니다. Alg. 1은 θ < 0.0을 요구합니다.
- 초기값 ĉ = 0.0이고, 실행 중에 청크 두 개를 병렬로 돌리지 않습니다(Alg. 1의 일련 루프).

### 2.3 시스템 (§4.3)

- **CUDA 그래프 재사용:** 토큰 길이가 고정되도록 언어 지시를 고정 길이로 패딩합니다.
- **GPU 상주 중간 버퍼:** 구성 요소 사이 중간 결과의 크기가 정해져 있으므로 CPU로 쓰지 않습니다.
- **흐름 매칭 unroll:** 여러 디노이징 반복을 한 그래프로 합칩니다. 그래프 생성은 첫 추론에서만 듭니다.
- 양자화, 가지치기 등 다른 가속과 직교한다고 주장하며, 계산을 바꾸지 않는 시스템 최적화만 다룹니다(§4.3 끝).

## 3. 실험 설정 (§5, 부록)

- **시뮬레이션:** LIBERO 4개 군집(Spatial, Object, Goal, LIBERO-10), π0.5. 비교 대상은 Sync(지연 0, 상한 기준), RTC, VLASH입니다(§5.1). 시행 수, 시드 수, 신뢰구간은 없습니다.
- **지연:** Orin(30 W·50 W 표기는 Table 1에만 있음)과 Thor에서 π0.5 지연과 반응 시간을 재고, vla.cpp의 Orin 지연 893.0 ms를 인용합니다(§5.2, Table 4).
- **실로봇:** PrimeBot X2-W, 카메라 3대(224×224), **XR-1 모델**을 Orin에서 돌리고, 옷 개기 과제를 3개 소과제(과제당 10회)로 나눕니다. 실행 주기는 15 Hz입니다(§5.3, Fig. 7). 실로봇 모델이 π0.5가 아니라는 점은 §5.1과 맞지 않습니다(`01` §6).
- **신뢰도 임계값:** Fig. 8(LIBERO-Spatial, Orin)에서 θ = −0.2, −0.3, −0.4를 비교하고, Fig. 9는 θ = −0.2 예시입니다(§5.4). Table 3의 θ 값은 본문에 없습니다.

## 4. 결과

### 4.1 LIBERO (§5.1, Table 3)

- Table 3은 ∆ = 1..9, 네 군집, 네 열(VLASH, RTC, Ours, +Sched)과 Sync 행을 줍니다. Avg 행은 ∆ = 1..9의 평균이고(재계산과 일치, `03` §1.1), 본문은 "네 군집과 ∆에 걸친 평균에서 VLASH보다 14.8 %p, RTC보다 3.9 %p 높다"고 씁니다. 이 수치는 **+Sched 열**로 계산한 값입니다(Ours 열이면 14.4와 3.5).
- ∆ = 9에서 +Sched는 VLASH보다 45.6 %p, RTC보다 7.0 %p 높다고 씁니다(같은 열 기준).
- Sync 대비 +Sched: Spatial 97.4 대 97.3, Object 98.6 대 99.6, Goal 96.8 대 96.7, LIBERO-10 92.5 대 93.5(Avg 행). 지연 제거의 정확도 비용은 최대 1.0 %p입니다.

### 4.2 지연과 제어 주기 (§5.2, Table 4)

- **Orin:** Naive 1420.8 ms → +Schedule 674.9 ms 반응 → +Graph reuse 184.0 ms → +Intermediate Buffer & Unroll 97.1 ms 반응 시간, 제어 주기 0.70 → 10.30 Hz.
- **Thor:** 457.9 → 244.7 → 134.6 → 61.1 ms, 2.18 → 16.37 Hz.
- 본문 배율: 스케줄 2.11×(Orin) 1.87×(Thor), 그래프 재사용 3.67×, 1.82×, 버퍼·unroll 1.89×, 2.20×, 전체 14.71×, 7.51×, vla.cpp 대비 9.20×.
- 재계산 결과 배율은 대부분 맞습니다. 다만 14.71×는 반올림된 Hz(0.70, 10.30)로 계산한 값이고, 반응 시간(ms)으로 계산하면 14.63×입니다(`03` §1.2).

### 4.3 실로봇 (§5.3, Fig. 7)

- 과제당 10회, 세 과제(개기, 펴기 후 접기, 보관)를 합쳐 Picking 10/10, Folding 8/10, Placing 9/10(EagleVLA), RTX 4090 기준 10/10, 7/10, 10/10, Orin 나이브 비동기 6/10, 0/10, 5/10입니다(Fig. 7의 표).
- 본문은 "RTX 4090 대비 거의 손실이 없다"고 씁니다. 세 과제 합계 27/30 대 27/30이고, 나이브 비동기는 11/30입니다(`03` §3).

### 4.4 신뢰도 임계값과 예시 (§5.4, Fig. 8–9)

- θ가 클수록 VLM 호출이 잦아 제어 주기가 조금 낮아지고, θ가 작을수록 반응 시간은 줄지만 예측 오차가 커진다고 씁니다. 수치는 그래프에만 있어 재계산하지 않았습니다.
- Fig. 9는 "pick up the black bowl ... place it on the plate" 한 번의 실행에서 신뢰도가 잡기와 놓기 단계에서 떨어져 VLM 호출을 촉발한다는 예입니다.

## 5. 한계 (저자 서술과 독해)

- **저자 서술(§7):** 온보드 장치의 계산과 대역폭 한계로 GPU 배치에 비해 격차가 남을 수 있다고 씁니다. 실험 한계나 실패 사례는 쓰지 않습니다.
- **독해:** (1) 시뮬레이션은 LIBERO 하나에 π0.5 하나입니다. 다른 VLA나 다른 과제 계열 검증이 없습니다. (2) 실로봇은 과제당 10회로, 차이를 구분할 힘이 없습니다. (3) 지연은 P50 등 집계 방식과 측정 조건(전력 모드, 시작 시 그래프 생성 제외 여부)이 없습니다. (4) 반응 시간의 정의와 계산이 없어 Table 4의 "반응 시간" 열을 재현할 수 없습니다. (5) VLM 호출 비율을 보고하지 않아 "VLM 생략으로 얻은 이득"의 크기를 가릴 수 없습니다.

## 6. 기록에 남길 특이점 (논문 내부와 버전)

1. **헤드라인 수치 세 번 변경(H1):** 초록과 §5.2의 Orin 배율이 v1–v5 8.66×, v6 9.85×, v7 14.71×입니다. 최종 행 Orin 제어 주기는 6.06 → 6.93 → 10.30 Hz입니다. 같은 기간 Naive 행과 "+Schedule" 행은 바뀌지 않았습니다. arXiv에는 변경 사유가 없습니다(`03` §5).
2. **§5.2 문장의 귀속 변화:** v6은 버퍼·unroll 단계를 "action expert 가속 1.33×, 1.46×"로 썼고, v7은 "반응 시간 1.89×, 2.20×"로 씁니다. v6의 1.33×, 1.46×은 v6 표의 값과도 맞지 않습니다(표 값 1.275×, 1.379×, `03` §1.2).
3. **행 라벨과 내용 불일치:** 논문 Table 4의 최종 행은 "+Intermediate Buffer & Unroll"인데, 같은 수치는 공식 저장소에서 "+ time cache, and GEMM tuning (PR #6)"라고 적힌 행입니다. 저장소는 이 행이 통제된 절제 실험이 아니라고 적습니다(`04` D12).
4. **Thor 정확도 단서 누락:** 논문 Thor 최종 행(132.8 ms, 16.37 Hz, 7.51×)은 저장소가 "정확도 게이트(cosine > 0.9994) 미통과, 정확도 승인 기본값 아님"이라고 명시한 구성의 값입니다. 논문 본문에는 이 단서가 없고 "negligible success rate loss"만 있습니다(`04` D13).
5. **Table 1 합 불일치:** Orin 50 W 행에서 목록 합(ViT + LLM + AE)과 총합이 π0은 100.0 ms, π0.5는 100.7 ms 차이 납니다. 다른 행은 맞습니다(`03` §1.3).
6. **Table 2 계수:** 균형 강도 열은 2 × TOPS / 대역폭 × 1000으로 맞지만 RTX 4090 행만 618이 되려면 대역폭 1000 GB/s가 필요합니다(표는 1024). 계수 2의 근거는 본문에 없습니다(`03` §1.4).
7. **Table 3의 "%"는 %p:** 초록의 "14.8%"는 평균 성공률의 차이(%p)입니다. 비율 차이로 읽으면 안 됩니다.
8. **시행 수 불일치:** Table 3의 값 대부분(148개 중 85개)은 LIBERO 군집당 500회(공식 README "50 trials/task")의 단일 집계와 맞지 않습니다(`03` §2.1). 시드 평균이나 다른 분모를 썼을 가능성이 있고, 논문에는 적혀 있지 않습니다.
9. **실로봇 모델:** §5.1은 π0.5, §5.3은 XR-1입니다. 실로봇 실험의 학습 데이터, 시연 수, 보정 모듈 재학습 여부가 없습니다.
10. **학습 설정 불일치(공식 코드와 비교):** 본문 Table 6은 두 단계(30k·25k, 배치 32)인데, 공식 README와 스크립트는 세 단계(30k·15k·55k, 배치 16)입니다(`04` D6).
11. **H 값 불일치:** Fig. 3은 H = 20인데, 공식 학습과 평가 기본값은 H = 10입니다(`04` D7).
12. **보정 목적함수:** 논문 Eq. 1은 평균 제곱 오차와 신뢰도 회귀입니다. 공식 기본 레시피는 이분산 가우시안 음의 로그우도(NLL)로 μ와 로그 분산을 함께 학습합니다. 로그 분산 보정 손실은 옵션에만 있습니다(`04` D1, D2).
13. **vla.cpp 893.0 ms:** vla.cpp arXiv v2 본문에서 893이라는 값을 찾지 못했습니다(검색 0건, 2026-11-22). 출처와 측정 조건을 확인할 수 없습니다(`03` §4.3).
14. **반응 시간 정의:** "반응 시간"의 계산이 없어 Table 4의 +Schedule 행(674.9, 244.7 ms)이 어떻게 나왔는지 재현할 수 없습니다.

## 7. 요약 판단

- **방법의 아이디어(미래 조건 보정과 신뢰도 기반 VLM 호출)는 명확하고 짧게 적혀 있습니다.** 공식 코드도 같은 구조(보정 모듈, 신뢰도, 두 가지 스케줄)를 가집니다.
- **그러나 수치 주장은 논문만으로는 검증할 수 없습니다.** LIBERO 표는 시행 수와 시드가 없고, 지연 표의 최종 행은 세 번 바뀌었으며 그 값은 저장소의 최적화 구성(일부는 정확도 미승인)에서 옵니다.
- **재계산으로 확인한 것:** 표 3의 평균과 본문 차이 값(14.8, 3.9, 45.6, 7.0 %p, +Sched 기준), 표 4의 배율 대부분, 표 2의 대역폭 제약 라벨, 실로봇 합계와 검정 결과(`03`).
- **확인하지 못한 것:** 시행 수, 시드, 반응 시간 정의, VLM 호출 비율, Fig. 3, 8의 수치, 실로봇 조건, vla.cpp 893 ms.
