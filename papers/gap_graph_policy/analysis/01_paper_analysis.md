## 1. 한 문단 요약

GaP는 코딩 에이전트(Claude, Gemini 등)가 로봇 정책을 "타입이 있는 방향 계산 그래프"로 쓰게 하는 하네스입니다. 그래프의 노드는 MORSL(Modular Open Robot Skill Library, 초기 51개 스킬)에서 가져오며, 오케스트레이션 에이전트가 과제를 구간으로 나누고 스킬 에이전트가 구간별 부분 그래프를 만들어 이어 붙입니다(§1, §4). 만든 그래프는 내부 시뮬레이션에서 N개 인스턴스로 병렬 리허설하고 실패를 분석해 LLM이 고칩니다(§4.2, 알고리즘 1). 최종 그래프는 에이전트 없이 가장자리 기기의 인터프리터가 실행합니다(§3). 평가는 "Variational Automation"(VA, 객체 형상·자세가 변하지만 작업 셀은 고정된 반복 과제) 벤치마크 8개(시뮬 4, 실로봇 4)입니다(§5.1).

## 2. 문제 설정과 방법

### 2.1 VA 과제 튜플 (§3)

- 과제 T = ⟨L, E, R, O, X, B, J⟩: 언어, 고정 작업 환경, 로봇·센서 구성, 객체 집합, 상태 공간, 믿음 공간(자세 분포), 보상 J = w_s·I(success) + w_t·Φ. 처리량 Φ는 "성공률 / 주기 시간"으로 정의됩니다(§2, §3).
- 가정: 작업 셀, 로봇, 센서가 알려져 있고 고정이며, 객체 메시와 자세 범위가 입력입니다. 저자는 이것이 "oracle 정보가 아니라 VA 설정의 일부"라고 씁니다. 내부 시뮬레이션은 장면 복원, 시스템 식별, 도메인 무작위화 없이 이 입력에서 바로 만듭니다(§3).
- 정책 표현: 그래프 G = (V, E). 노드는 입출력 타입이 있는 원자 기능, 데이터 간선은 실행 순서를 암시하고 독립 가지는 동시에 실행될 수 있으며, 제어 간선은 노드 출력에 대한 조건 분기입니다(§3). 목표는 G* = argmax_G E_{x∼B}[J(π_G)] 입니다.

### 2.2 MORSL과 에이전트 구조 (§4.1, 부록 D)

- 스킬은 Anthropic Skill.md 규약에 그래프 선언을 덧붙인 형식으로, 입력, 출력, 의미 매개변수, 사전 조건을 선언합니다. 51개의 내역은 인지 15, 파지 계획 5, 모션 계획 8, 2D·3D 비전 유틸 15, 검증·제어 프리미티브 8입니다(합 51, `03` V13).
- 부록 D는 모든 스킬이 공통 타입 시스템(Se3Pose, OrientedBoundingBox, PointCloud, Mask, Image, Trajectory, JointState 등)을 공유해 자유롭게 조합된다고 씁니다.
- 에이전트: 오케스트레이션(행동) 에이전트가 최상위 노드 그래프만 만들고, 부분 그래프 내부는 별도의 스킬 에이전트가 채웁니다(부록 F.1). 생성과 시험을 분리해 에이전트가 "속이는" 유인을 줄인다는 것이 논문의 동기입니다(§1).

### 2.3 자기 학습: 리허설 기반 그래프 최적화 (§4.2, 부록 E)

알고리즘 1(부록 알고리즘 2와 같은 내용): G0를 언어에서 만들고, M번 반복합니다. 매 반복에서 B에서 N개 인스턴스를 뽑아 병렬 리허설하고, 인스턴스별로 실패를 분석(F_i)한 뒤, F들로 LLM이 그래프를 갱신(Graph Update)합니다. 본문 설명에 추가된 규칙은 다음과 같습니다.

- 피드백은 각 리허설 노드의 전후 로봇·객체 상태와 로봇-객체 접촉 질의의 차이에서 얻습니다(부록 E.2의 예: 팬이 버너 밑면의 70% 이상을 덮는지).
- 갱신은 타입이 있는 다섯 가지 동작으로 제한됩니다: 노드 입력 설정(인지 프롬프트 등), 입출력 재배선, 인라인 파이썬 스크립트 다시 쓰기, 스킬 노드 교체, 정적 타입 검사와 시뮬레이션으로 검증.
- 새 task instance 100개에서 성공률이나 주기 시간이 떨어지는 갱신은 거부되고, 성능이 정체할 때까지 반복합니다(§4.2, 그림 3 캡션).
- M, N의 값은 본문에 없습니다. 부록 E.2의 예는 환경 30개 병렬(N = 30), 그림 2는 10회 반복(M = 10)입니다.

## 3. 실험 결과

### 3.1 시뮬레이션 비교 (표 1, §5.2–5.3)

각 칸은 task instance 100개입니다(표 1 캡션: "5500 trials"). 7개 방법 × 8개 열에서 CaP-X의 LIBERO 칸이 "-"라 55칸 5,500회입니다. 모든 값이 100개 중 정수 개수와 맞습니다(`03` V1).

| 방법 | LIBERO object | LIBERO-Pro swap | X-Y 20×20 | basket swap | permutation | mixed all | pack fixed | pack varied |
|---|---|---|---|---|---|---|---|---|
| CaP-X | - | 0.22 | 0.07 | 0.05 | 0.11 | 0.10 | 0.01 | 0.01 |
| π0.5 | 0.96 | 0.24 | 0.78 | 0.15 | 0.20 | 0.20 | 0.17 | 0.18 |
| MolmoAct2 | 0.97 | 0.43 | 0.90 | 0.26 | 0.10 | 0.20 | 0.18 | 0.18 |
| TipTop | 0.22 | 0.22 | 0.29 | 0.24 | 0.31 | 0.24 | 0.34 | 0.46 |
| π0.5 w/GaP | 0.85 | 0.60 | 0.79 | 0.32 | 0.50 | 0.39 | 0.67 | 0.66 |
| MolmoAct2 w/GaP | 0.70 | 0.62 | 0.84 | 0.58 | 0.39 | 0.66 | 0.59 | 0.59 |
| GaP | 0.95 | 0.95 | 0.95 | 0.97 | 0.93 | 0.97 | 0.99 | 0.98 |

- 설정: GaP와 CaP-X는 Gemini-3.1-Flash-Lite(온도 0.1)를 씁니다. VLA는 LIBERO 학습 데이터로 미세조정한 공식 체크포인트이고, TipTop은 cuTAMP 128 입자, 계획 제한 60초입니다(§5.2). Benchmarks I, II의 GaP는 "첫 그래프가 높은 성능을 내서" 자기 학습을 하지 않습니다(§5.2).
- 하이브리드(행 5, 6)는 GaP가 손목 카메라를 대상 위로 옮긴 뒤 VLA에 넘깁니다. 저자는 이를 "두 배 넘는 개선"이라고 씁니다(§5.3.1).
- 실로봇(표 2): Fulfill Grocery Orders GaP 25/25 대 TipTop 8/25(하위 조건 다섯 개 각 5회), Pack Grocery Items 28/30 대 10/30, Make Popcorn 18/20 대 0/20. 단일 pick-and-place 평균 완료 시간은 TipTop 95초, GaP 67초입니다. GaP의 지각 14.1초와 하강·파지·운반 36.4초가 따로 적혀 있습니다(§5.3.2).

### 3.2 절제 (§5.4)

세 가지가 글로만 보고됩니다. (1) 그래프 없이 LLM 하나가 파이썬 스크립트를 쓰면 성공률이 0으로 "무너진다", (2) 전문 작성 에이전트를 LLM 하나로 합치면 0이고 모든 시행이 실행 전 정적 구조 검증에서 실패한다, (3) 그래프 검증이 연결성을 개선한다. 이 절에는 표가 없고 시행 수도 적혀 있지 않습니다(`03` V17).

### 3.3 자기 학습 (§5.5–5.6, 그림 2, 그림 3, 표 3)

- Make Popcorn: 초기 그래프는 성공률 33%이고, 10회 반복으로 시뮬 94%, 실로봇 90%(18/20)에 이릅니다. 변화는 파지 → 파지 방식과 지각 프롬프트 → 놓기 오프셋 순으로 서술됩니다(§5.5).
- 주기 시간: 성공률이 이미 포화인 Benchmarks I–III에서 처리량 항으로 다시 자기 학습하여 "주기 시간을 최대 57% 줄이되 성공률 손해가 없다"고 씁니다(§5.6). 표 3의 처리량은 I 49.7 → 124.1, II 7.3 → 16.2, III 30.5 → 76.6 cycles/hr입니다.
- 비용: 그래프 생성은 Gemini 호출 30회 미만(약 $0.01, 1초 지연), 자기 학습은 반복당 약 15분이며 Make Popcorn은 총 150분까지입니다. 배포 후에는 에이전트가 필요 없다고 합니다(§5.6).

### 3.4 USB-C 케이블 삽입 (표 4, §5.7, 부록 B)

UR5와 ZED Mini, 7개 포트. 포트 위치(5 cm 간격 세 거리)와 각도(15° 간격 세 각도), 다섯 가지 목표 문장(개별, 오름차순, 내림차순, 홀수, 짝수)을 바꿉니다. GaP가 만든 그래프는 ROS 노드 네 개(align to port, touch port, insert, extract)를 호출합니다. 130번 삽입 중 121번 성공(0.93)입니다. 힘 조건은 진행 >3 mm, <10 N, 삽입 확인은 깊이 >6 mm, 30 N입니다.

### 3.5 Wash Crates (표 5, §5.8)

Franka 두 대의 양팔 협동으로 상자를 들어 뒤집어 놓는 시뮬레이션. 150회에서 GaP 0.953(143/150), 전문가 손 설계 그래프 0.987(148/150), 평균 주기 179.13초 대 176.47초입니다. 3시간 연속 실행에서 양쪽 모두 59번 시도해 GaP 55번, 손 설계 58번 성공(시간당 18.33 대 19.33)입니다.

### 3.6 저자가 한계로 인정한 것 (§6)

실행 신뢰도가 산업 수준에 못 미치고 추가 자기 학습과 매개변수 조정이 필요합니다. 실행 시간은 산업 기준 시간당 500개(인스턴스당 7초)에 크게 못 미치며, VLM 추론 요청과 IK 모션 계획 시간을 줄여야 합니다. 8개 벤치마크는 준정적 pick-and-place이고 케이블 삽입만 힘 센싱을 씁니다. 변형체, 동적 힘, 움직이는 목표는 후속 과제입니다.

## 4. 주장과 근거의 간격 (요약)

자세한 수치는 `03`에 있습니다.

1. **"위치 변화에서 GaP가 기준선을 크게 앞선다"는 대부분의 열에서 큰 차이로 확인됩니다.** 다만 X-Y 20×20 열은 GaP 0.95 대 MolmoAct2 0.90이라 100회 대 100회의 Fisher p = 0.28이고, LIBERO object 열은 GaP가 0.95로 VLA(0.96, 0.97)보다 낮습니다(`03` V3).
2. **"VLA 성능이 LIBERO-PRO에서 0.20까지 떨어진다"는 서술은 표 1의 열과 위치가 맞지 않습니다.** 0.20은 mixed all(π0.5, MolmoAct2)과 permutation(π0.5) 열에서 보이고 LIBERO-Pro 열의 값은 0.24, 0.43입니다. 표 전체의 VLA 최솟값은 0.10입니다(`03` V2).
3. **"두 배 넘는 개선"은 위치 변화 열에서 성립하고 모든 열에서 성립하지는 않습니다.** X-Y 열은 1.01배와 0.93배이고, LIBERO object에서는 오히려 낮아집니다(`03` V4).
4. **표 3의 처리량은 "성공률 / 주기 시간"이 아니라 3600 / 주기 시간(cycles/hr)과 일치합니다.** §2의 Φ 정의와 읽는 방식이 다릅니다(`03` V8).
5. **"주기 시간 최대 57%"는 표 3에서 계산하면 60.0%, 54.9%, 60.2%입니다.** 세 벤치마크 중 어느 것도 57%가 아닙니다(`03` V8).
6. **그림 2의 반복별 값은 환경 30개(N = 30)일 때의 정수 비율과 맞고(30%, 43%, 70%, 80%, 90%, 93%), 마지막 94%만 30개 중 정수 개수가 아닙니다**(그림 판독 값, `03` V9).
7. **절제(§5.4)는 시행 수와 표가 없어 재계산할 수 없습니다.**
8. **공식 코드는 v1 범위(LIBERO와 실 Franka/UR의 pick-and-place)만 담고, 자기 학습 루프는 별도 저장소로 갔습니다.** 논문 §5.5의 Make Popcorn, USB-C, Wash Crates, GraspGen에 해당하는 그래프와 스킬은 이 저장소에 없습니다(`04` D1–D3).

## 5. 재현에 필요한 정보와 빠진 정보

- **있음:** 과제 튜플, 벤치마크 변형(위치 20×20 cm, 바구니 교환, 순열), LLM(Gemini-3.1-Flash-Lite, 온도 0.1), TipTop 설정, 케이블 삽입의 힘·깊이 임계값, 부록의 프롬프트와 그래프 예.
- **없음(본문 기준):** 자기 학습의 M, N과 종료 조건("정체"의 정의), 채택 규칙이 쌍체 비교인지 여부, 그래프를 몇 번 생성했는지(셀당 그래프 한 개인지 인스턴스마다 새로 생성했는지), 절제의 시행 수, 하이브리드 VLA 전달 지점의 세부, 처리량의 정의(§2의 Φ 대 표 3), 3시간 실행의 시도 사이 간격.
- **외부 의존:** 시뮬레이션은 RoboSimStudio(arXiv:2610.18835)이고, 인지는 SAM 3와 Grounding DINO, VLM은 Gemini 계열 API, 계획은 cuRobo입니다(§4.1, `04` §1).
