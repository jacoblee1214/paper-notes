# 04. 주장 검증과 구현 가능성

공식 코드가 공개되어 있지 않아(`02` §2) 코드 대조(D 항목) 대신 논문의 주장 C1–C17을 표, 그림, 부록의 수치와 맞대어 검증했습니다. 재계산은 `03`, 위치 표기는 논문의 절, 표, 그림 번호입니다. 판정 어휘는 다음과 같습니다. **지지**: 보고된 증거가 주장을 뒷받침. **부분**: 일부만 뒷받침하거나 증거의 범위가 주장보다 좁음. **구별 안 됨**: 보고된 표본으로는 비교가 갈리지 않음. **확인 불가**: 증거나 정의가 논문에 없음.

## 1. 공개 자료 현황 (확인 2026-11-25)

| 항목 | 상태 |
|---|---|
| 코드 | 없음. 프로젝트 페이지의 Code 링크 칸이 비어 있고(`main.js`의 `code: '#'`) 렌더된 버튼은 비활성입니다. 저자와 프로젝트 계정의 공개 저장소는 프로젝트 페이지 하나입니다 |
| 가중치, 데이터 | 확인되지 않음. 논문에는 코퍼스 이름(Panda-70M, Action100M, Something-Something-V2, EPIC-Kitchens, LVP 메타데이터 [54])과 과제당 클립 수(20k)가 있으나, 선별된 클립 목록과 자체 수집 영상(push-T, cable routing 각 1시간)의 공개 여부는 알 수 없습니다 |
| 프로젝트 페이지 | 영상, 요약, 슬라이더 시각화. 수치 표는 논문과 같은 73%, 28%, 19/30입니다 |
| 평가 자료 | 시도별 기록(영상, 로그)은 프로젝트 페이지에 정성 영상 외에는 없습니다. 이 분석의 수치는 논문 그림 12, 13의 막대 라벨에서 옮긴 것입니다 |

## 3. 저자에게 확인하고 싶은 것

1. 그림 6의 20k 점(약 73%)과 그림 12·5의 binning(21/30)이 같은 평가인가, 다른 학습 실행인가(`03` V10).
2. 개루프 기준선에서 "같은 f_θ를 한 번만 질의"하는 변형이나 Veo 영상을 창 단위로 재질의하는 변형의 결과가 있는가(`03` §1.2).
3. 그림 5의 바이올린은 어떤 분포의 모양인가(`03` V9b).
4. 그림 7의 "episode reward"의 정규화(스텝 평균인가), 그리고 "epoch"이 PPO 반복을 뜻하는가(`03` K8, K9).
5. 시나리오 세 개가 어떤 요인의 어떤 조합인지, 요인별 결과가 있는가(C2).
6. 영상 선별 기준과 걸러 낸 비율, 코드·가중치·선별 클립 목록의 공개 계획(C10).

## 4. 구현 가능성 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**판정: 논문 전체의 재현은 이 맥에서 불가능합니다. 코드가 공개되지 않아 공식 설정과의 대조도 불가능합니다. 이 맥에서 할 수 있는 것은 (1) 보고 수치의 재계산(완료), (2) 폐루프·일회 질의 구조의 토이(완료), (3) 축소판 구현(점 토큰 의도 모델, MuJoCo 추적 정책)입니다.**

| 구성 | 필요한 것 | 이 맥에서 | 비고 |
|---|---|---|---|
| 실로봇 평가 (그림 5, 12, 13) | UR5e + LEAP 손 + 평행 그리퍼, Gemini 305 손목 카메라, 외부 RGB-D, RTX 5090, Veo 3.1 접근 | **불가** | 장비와 생성 모델 접근이 저장소 밖 |

| 의도 모델 f_θ 학습 | CoTracker3 가중치(초기화), A100 노드, 클립 감독 | **불가** (원규모) | 코드 없음. 점 토큰 트랜스포머 축소판은 합성 점 궤적으로 MPS에서 가능(아래) |
