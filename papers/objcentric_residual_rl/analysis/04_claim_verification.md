# 04. 주장 검증과 구현 가능성

공식 코드가 없어서 **코드 대조(`04_code_verification`)는 하지 않았습니다.** 대신 논문의 주장 C1–C16을 표 재계산, 그림 읽기, 토이 실험으로 확인했습니다. `repo/`는 만들지 않았습니다.

검사 범위는 세 가지입니다. 표와 본문 수치의 산술, 통계 검정(`03`), 토이 C(`03` §3)입니다. 시뮬레이션과 실로봇은 직접 돌리지 않았습니다.

## 1. 판정 기준

- **확인**: 표나 그림의 수치로 다시 계산해 맞음
- **부분**: 방향은 맞지만 크기나 통계 근거가 약함
- **확인 안 됨**: 논문 자료로는 검증할 수 없음 (측정 없음, 수치 없음)
- **과장**: 수치와 서술이 어긋남

## 4. 구현 가능성 판정 (이 맥)

**환경:** Apple M4 Pro, 약 24 GiB 통합 메모리, MPS 있음, CUDA 없음. 설치는 승인된 것만 씁니다. torch 2.15와 mujoco 4.0은 이미 설치되어 있고 승인되었습니다. 이 분석에서 새로 설치하거나 다운로드한 것은 없습니다.

### 4.2 판정

**부분 구현 가능(조건부).** 구체적으로는 다음과 같습니다.

- **구현할 수 있는 것:** 잔차 RL의 골격(관측 구성, 포즈 잡음과 드롭아웃 증강, TD3 학습 루프)과 MuJoCo 기반 5과제 시뮬레이션. 기반 행동은 GR00T 대신 작은 정책이나 고정 정책으로 바꿉니다. 이것은 논문과 다른 실험입니다.
- **구현할 수 없는 것:** 논문의 실로봇 42 → 76%와 GR00T-N1.5 기반의 시뮬레이션 전체 수치. 실로봇 평가, 포즈 추정 파이프라인, 자기 개선 SFT는 이 맥에서 불가입니다.
- **가장 큰 불확실성:** GR00T-N1.5의 MPS 추론과 미세조정. 이 세션에서 확인하지 않았습니다.

## 5. 저자에게 확인할 질문

1. 실로봇 과제별 시도 수, 시드, 초기 배치 분포는 어떠했는가 (과제당 20회가 전부인가)
2. 시뮬레이션 "±"는 표본 표준편차인가 모집단 표준편차인가
3. 증류 베이스라인과 이미지 베이스라인의 학습 스텝과 네트워크 구조는 Ours와 같은가
4. SFT 실험의 롤아웃 수, 평가 시도 수, 시드 수는 얼마인가
5. 포즈 잡음 5 mm, 0.1 rad는 FoundationPose 측정치의 분포에서 나온 값인가, 깊이 카메라 사양에서 나온 값인가
6. 기반 행동과 잔차 학습에 쓴 기반 행동이 시뮬레이션과 실로봇에서 같은 청크 길이(H = 16)와 제어 주파수로 실행되었는가
7. 공식 코드나 시뮬레이션 자산(FR3 MJCF, 과제 씬)을 공개할 계획이 있는가
