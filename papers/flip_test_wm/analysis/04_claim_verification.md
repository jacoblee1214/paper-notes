# The Flip Test: 주장 검증 (04)

공식 코드와 원자료가 아직 공개되지 않았습니다(블로그 [Code&Data] "expected Dec 2026", GitHub 검색 결과 없음). 그래서 **코드 대조(D1–Dn) 대신 주장 검증(C1–Cn)**으로 씁니다. 원문 표와 본문 수치를 재계산하고, 부록의 설계 주장(상수, 프롬프트, 정답 규칙)을 원문 안에서 대조했습니다. 외부 코드는 실행하지 않았습니다.

판정 기호: **일치** = 재계산이나 산술로 맞음, **주의** = 맞지만 해석이나 검정력에 문제, **확인 불가** = 원자료나 그림 없이는 판단 못함, **불일치** = 원문 안에서 어긋남.

## 2. 설계 수준의 검사 (원문 내부)

- **라벨 정의 (V4 관련).** 시뮬 과제 정답은 해석적 임계값(±δ)과 시뮬레이터 확인을 결합했습니다(부록 A). 그러나 "시뮬 정답 = 시뮬레이터 결과"이므로, 시뮬레이션 에이전트(MuJoCo)가 스윕과 시뮬 쌍에서 "잘 맞는다"는 것은 물리 엔진 자체와 정답의 공유 가능성이 있습니다. 실사 쌍은 편집 생성기가 라벨을 고정하므로, 편집이 현실적 결과 차이를 만드는지는 판단이 필요합니다(확인 불가).
- **프롬프트 대칭성.** 비디오 모델 프롬프트는 두 결과를 중립적으로 이름 붙이고(그림 11), 같은 쌍의 두 멤버가 같은 프롬프트를 씁니다. 좋은 설계입니다. 그러나 "정답 알려 주기" 조건에서는 51개 조건 프롬프트가 쓰였고, 그 프롬프트가 정답 결과를 밝히는 문장을 어떻게 썼는지 샘플(예: 상자 예)만 있습니다. 조건 사이의 문장 길이 차이는 확인하지 않았습니다.
- **판정 프롬프트의 규칙 문장 (그림 14).** 상자 과제 규칙은 "떨어짐의 시작만 있으면 fall", "중력 방향 위로 날아가면 unclear" 등 자세합니다. 판정 규칙 문장이 결과 분포를 결정할 수 있으므로, 시뮬 과제 판정이 시뮬 정답과 비슷하게 나오는 것은 판정 규칙의 영향일 수 있습니다(확인 불가).
- **시뮬 상수의 내부 일치.** 루프 높이 0.776 m가 표 1의 "release height 0.776 m"와 맞습니다(C25). 상수 몇 개가 본문과 부록 사이에서 맞아 떨어져 부록의 구성 설명은 신뢰할 만합니다.

## 3. 원문 내 불일치나 빈칸

1. **판독 상한 대 told-outcome 값.** 사람 라벨 일치 79%에서 독립 가정 상한 62.4%, 본문 실사 86.7% (V11). 원인 설명이 없습니다.
2. **판정 규칙 혼용.** 중립 18.3%(이중 규칙)과 told 73.7%(단일 판정기) (V10).
3. **"우연 25%"의 적용.** 3지선다 과제가 있는데 기준선은 모든 쌍에 25%로 씁니다(V4).
4. **"실사 상위 두 모델이 우연을 넘음".** Omni 단측 p = 0.047, MiniMax 미유의 (V6). 본문은 유의성을 주장하지 않지만 "surpass chance"라는 표현이 그렇게 읽힙니다.
5. **측정 에이전트 대 VLM의 실사 강조.** 짝지음 없는 검정 p = 0.12 (V9).
6. **CI 보고 부재.** 본문 L1 결과에 신뢰구간이 없습니다. 본문 L2의 CI만 있습니다.

## 4. 구현 가능성 판정 (맥, Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**결론: 논문의 수치 재현은 이 맥에서 불가능합니다. 축소판 벤치마크(시뮬 쌍 + 해석적 정답 + 작은 모델)는 CPU로 가능하지만, "이 논문의 주장을 검증한다"는 목적에는 대체가 안 됩니다.**

| 구성 | 필요 자원 | 맥에서 | 이유와 노력 |
|---|---|---|---|
| 11개 영상 모델 생성 (21,240 영상) | GPU 여러 장(모델당 수십 GB 가중치), 일부 API 전용 모델 | **불가** | Wan2.2-I2V-A14B는 14B 한 전문가만 fp16으로 약 28 GB(추정, 파라미터 수 기준)라 24 GiB를 넘습니다. CogVideoX1.5-5B도 영상 한 개의 MPS 시간을 측정하지 않았음. 600 영상 x 11 모델은 현실적이지 않음 |
| 소형 영상 모델 1개(예: CogVideoX1.5-5B) 쌍 몇 개 | 체크포인트 수 GB, MPS 추론 | 조건부 | 처리량 미측정. 몇 쌍(예: 10쌍) 정도는 시간 검토 후 가능할 수 있음. 승인과 다운로드 필요 |
| 판정기(Gemini 3.6/3.8 Flash) | 상용 API | **불가** (재현에 키와 비용) | 공개 VLM 대체는 판정 일치를 새로 재야 함 |
| 시뮬 쌍 10과제 재구성 (MuJoCo, 부록 A 상수) | mujoco 4.0 (프로젝트에 설치됨), CPU | **가능** | 과제별 MJCF와 임계값 검증 작업. 추정 1–2주. 새 설치 없음 |

| 로봇 실험 | 로봇 | 불가 | 이 논문은 로봇 제어를 평가하지 않음. 해당 없음 |

- **노력 추정.** 축소판 쌍 벤치(시뮬 10과제 + SS/스윕 지표 + 공개 소형 모델 1개로 몇 쌍): 2–4주. 공식 수준 재현(11모델 + 상용 판정기): 현실적으로 불가. 맥에서는 메모리(모델 한 개가 24 GiB 근처)와 처리량(영상 생성 시간 미측정, 수 분 단위 추정)이 막습니다.
- 이 판정은 처리량을 실제로 측정하지 않았다는 전제입니다. MPS 영상 생성 속도는 측정하지 않았습니다(확인 불가).
