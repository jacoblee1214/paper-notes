# 04 주장 검증과 구현 가능성

공식 코드가 없어서(§3) 코드 대조(`04_code_verification.md`) 대신 **주장 검증**으로 씁니다. 각 주장을 논문 절·표·그림에 붙이고, 우리 재계산(`03`), 판독 검정(`stats_check.py`), toy 결과로 판정했습니다. 판정 기준은 다음과 같습니다.

- **지지**: 논문 수치 또는 우리 재계산이 주장과 맞고, 유의하다.
- **부분**: 방향은 맞지만 범위, 유의성, 조건 중 하나가 빠졌다.
- **약함**: 방향은 맞아 보이나 통계적으로 확정되지 않는다(판독 오차 안).
- **반박**: 논문 수치 또는 toy가 주장과 반대다.
- **검증 불가**: 필요한 정보(코드, 평가 횟수, 시드별 값, 그림 수치)가 없다.

판독 기반 판정은 모두 근사입니다(`03` §1.1 가정).

## 2. 빠진 정보

논문 본문과 그림에서 확인되지 않는 항목입니다. 재현과 비교에 필요합니다.

1. 시뮬 평가 에피소드 수와 오차막대의 정의(SD 또는 SE), 시드별 값.
2. 학습 예산(에포크 또는 스텝)이 N에 따라 같은지. 같지 않으면 N 효과는 학습량 효과와 섞입니다(`contact_disassembly`의 D1–D2에서 같은 문제를 확인, 시뮬 데모 수 90과 30이 에포크 555와 1666으로 바뀜).
3. 시연 생성기의 시작점 분포, 목표 배치, 반지름 r의 단위, 경유점 높이 Δz, 플래너 실패 처리.
4. 시작–목표 거리(정규화 분모). 표 I 크기를 결정합니다(`03` §2.2).
5. T(재표집 점 수)를 T = 50으로 고정한 이유, 다른 T에서의 민감도.
6. ÷(M−1) 대 ÷M 여부(λ 정의). Fig. 2의 안정성은 ÷(M−1)을 전제합니다.
7. 실물에서 세 명의 수집자가 어떤 H 설정을 맡았는지. 수집자와 설정이 섞이면 H 효과가 수집자 효과와 교란됩니다.
8. Fig. 3b(PegInsertion)의 설정 목록과 H 값.
9. Fig. 4(π0.5)의 시드 수, 평가 횟수, 학습 설정, 낮은 H 설정(0/0, 0.05/1)을 포함하지 않은 이유.
10. Fig. 6의 기준선 수치, LogDet의 α, kNN의 k.
11. 전이 구간 분할의 세부(그리퍼 이벤트의 임계값, 최소 길이).
12. 성공하지 못한 시연을 어떻게 다뤘는지. Eq. 3은 성공 시연만 씁니다. 실패가 설정(r, k)에 따라 다르면 H는 선택 편향을 가집니다.

## 4. 구현 가능성 판정

**결론: 공식 재현은 불가능하고, 아이디어(H_G 계산과 역U 실험 설계)는 옮길 수 있습니다. 실험 재현에는 GPU와 시뮬레이터 설치가 필요합니다.**

| 항목 | 판정 | 근거 |
|---|---|---|
| 공식 재현 | **불가** | 코드, 시연 생성기, 학습 설정이 없다. 프로젝트 페이지에는 코드 링크가 없다(§3) |
| H_G 계산 (식 1–3) | **가능** (이 맥, CPU numpy) | `entropy_toy.py`의 `align()`과 `h_g()`가 정렬과 식 1–2를 수십 줄로 구현. 이미 실행됨. 실제 궤적 입력만 있으면 된다 |
| 시연 생성기(ManiSkill, 경유점 삽입) | **조건부**: 설치 승인 필요, 플래너 CPU 실행 여부 미확인 | 논문은 PandaArmMotionPlanningSolver를 쓴다. ManiSkill(Apache-2.0, 3504 별, 2026-08-04 최근 푸시)는 시뮬 설치가 필요하고 카메라 렌더링에 GPU가 필요할 수 있다. 상태 기반 플래너만 쓰면 CPU로 가능할 가능성이 있으나, 이 맥에서 실측하지 않았다 |
| DP 학습 (N 스윕, 그림 3) | **불가 (현재 환경)** | 공개 DP 코드(MIT, 4721 별, 최근 푸시 2024-12-24, `5ba07ac`)는 사용 가능하다. 학습에는 CUDA GPU가 권장된다. 이 맥은 CUDA가 없고 torch가 없다. MPS로 소형 모델은 가능할 수 있으나 StackCube 성공률 평가는 시뮬이 필요하다 |
| π0.5 미세조정(그림 4) | **불가** | openpi(Apache-2.0, 14603 별, `215abfb`)와 3B급 모델 미세조정에는 GPU가 여러 장 필요하다. 체크포인트 다운로드도 승인 대상 |
| ACT 실물(그림 5) | **불가** | ARX 로봇 팔이 필요하다. 시뮬 재현도 없다. ACT 코드(tonyzhaozh/act, MIT, 2335 별, `742c753`)는 쓸 수 있다 |
| 판독 검정(`03` §1) | **가능** (완료) | 이 맥에서 완료. 판독 오차의 영향은 `stats_check.py`에서 흔들기로 확인 |
| 재구현 노력 | H_G 계산 0.5일, 시연 생성기와 평가 1–2주(GPU 포함), 실물 재현 별도 | 추정. 실제 노력은 ManiSkill 설치와 플래너 호환에 크게 좌우됨 |
| 필요한 하드웨어 | GPU 1장 이상(CUDA, 소형 DP 학습 기준 수 GPU-시간), 실물 팔 1대 | 논문 설정 기준 |

**이 맥(Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음, torch 미설치)에서 할 수 있는 것:** H_G 정의의 검산, 합성 궤적에서 N·T·정규화·노이즈 민감도, 2차원 BC toy, 판독 값 검정. 이것들은 모두 완료했습니다.

**할 수 없는 것:** 논문 수치 재현, DP·ACT·π0.5 학습과 평가, 실물 실험. 이들은 설치·다운로드·GPU 승인이 필요하며 현재 계획에 없습니다.

**H_G를 실제 데이터 감사에 쓰려면:** 시연 궤적(위치 시계열)과 목표 프레임(목표 자세)이 있으면 됩니다. 이 조건은 텔레옵 데이터셋에서 대부분 충족될 가능성이 있으나, 목표 자세 추정이 없으면 정렬이 불가능합니다(C1). 과제 분할 이벤트(그리퍼)도 필요합니다.

## 5. 기준선 공정성 메모

- kNN(Kozachenko–Leonenko) 엔트로피는 D = 150, M ≤ 1000에서 대역폭 k에 민감합니다(T5, k = 3 → 20에서 −210 nats). 같은 자료에서 H_G는 0.005만 움직입니다. 이 비교는 "H_G가 안정적"을 보이기는 하지만, 기준선이 약하게 설정된 것입니다. 공정한 기준선은 차원을 줄인 뒤의 가우시안 엔트로피나, 같은 PCA 차원에서의 H_G 변형일 것입니다.
- 평균 분산(σ²_avg)은 임의의 순서를 무시합니다. 논문이 든 (0,0), (0.01,0), (0.03,0)의 붕괴는 이 기준선의 정의상 예상되는 결과이므로 증거로서 약합니다.
