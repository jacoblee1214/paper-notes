# WAMotor 논문 분석 (arXiv:2611.25413)

*WAMotor: Accelerating World Action Models via Speculative Inference under Dual Nonuniform Denoising Dynamics*. Zexun Lin, Yuan Feng, Xike Xie (USTC). 분석 대상은 arXiv v1 (2026-11-19 제출, 버전 1개). 원문 `paper/paper.pdf`(20쪽, 본문 8쪽 + 참고문헌 + 부록 A–C). 표·그림·식 번호는 원문 기준입니다.

## 1. 초록과 문제 설정

월드 액션 모델(WAM)은 비디오 생성과 행동 생성을 함께 다루며, 행동은 보통 flow matching으로 N번의 Euler 스텝을 거쳐 만듭니다(§4.1). 이 다단계 잡음 제거가 지연의 주된 원인입니다. 투기적 추론(speculative inference)은 초안 궤적을 만들고 병렬로 검증해 여러 스텝을 한 번에 넘기는 방법인데, 기존 방법은 과제별 초안 모델을 따로 학습해야 합니다(§1, §2.2).

이 논문은 학습 없이 **이전에 계산한 속도(velocity)를 재사용해 초안을 만드는** 접근(FlowCast 계열, [1])을 WAM에 맞추려고 합니다. 저자들은 이 접근이 가정하는 "속도의 매끄러움"이 WAM에서 **두 가지로 깨진다**고 주장합니다(§1, Fig. 2).

1. **속도 매끄러움이 균일하지 않다.** 인접 속도의 차이(Fig. 2a)는 처음과 끝 스텝에서 크고, 가운데는 작습니다. 부록 Table 7에서 처음과 마지막 전이의 MSE 비중은 Joint-WAM 66.43%, Fast-WAM 79.88%, Faster-WAM 78.98%입니다(균일 기준 22.22%).
2. **적분 시간 간격이 균일하지 않다.** 같은 속도 잔차라도 간격 Δt_k에 따라 상태 오차가 다릅니다. Lemma 4.4는 국소 상태 MSE가 h_k²·‖r‖²임을 보입니다(식 (5)).

이 두 관찰을 바탕으로 제안하는 방법은 다음과 같습니다.

- **RAVS (Reliable Anchor Velocity Selection, §4.3):** 첫 Euler 스텝을 한 번 표준으로 수행한 뒤 u_1을 앵커로 씁니다. 처음 속도 u_0를 재사용하지 않습니다.
- **TSAV (Time-Step-Aware Verification, §4.4):** 재사용 잔차를 검증할 때 ‖u_M − v̂‖²·(h_k/h_mid)² ≤ ε (식 (6))으로 씁니다. h_mid는 적분 간격의 중앙값입니다. 간격이 큰 스텝은 더 엄격하고 작은 스텝은 느슨합니다.

결과 요약: LIBERO에서 3.05×–4.19×, RoboTwin 2.0에서 2.86×–4.02×, LIBERO-Plus에서 3.13×–4.28×의 종단 지연 감소를 주장하고, 성공률은 "comparable"하다고 씁니다(초록, §5.2). 기준선은 VLA-Cache, TeaCache, BAC(캐시), ParaStep, SpeCa(캐시 기반 투기), FlowCast(속도 재사용 투기)입니다(§5.1).

## 2. 방법 (§4)

### 2.1 표기

흐름 적분은 a_{k+1} = a_k + Δt_k v_θ(a_k, t_k; c_k)입니다(식 (1) 앞, §4.1). 투기 샘플러는 앵커 m에서 u_m = v_θ(a^s_m, t_m; c^s_m)을 계산하고, 후보 j번째 상태를 â_{m,j} = a^s_m + u_m Σ_{i<j} Δt_{m+i}로 만듭니다(식 (1)). 후보 w개(창 상한)를 한 번의 배치 호출로 검증하고, 허용되는 가장 긴 접두사를 커밋합니다(Alg. 1).

### 2.2 이론 (§4.2, 부록 A)

- **정리 4.3 (궤적 δ-오차 허용 한계):** ‖a^s_N − a_N‖ ≤ δ = Σ_{k∈I} G_k h_k ‖r_{M_k,k−M_k}‖ + B_cond (식 (4)). G_k는 전파 계수이고 I는 재사용 스텝 집합입니다. 증명(부록 A.1)은 Lipschitz 가정(Assumption 4.2, ‖v(x)−v(y)‖ ≤ L_k‖x−y‖ + C_k‖c−c′‖)에 기댑니다. 부록 A.1의 귀납 부등식은 일관됩니다.
- **정리 4.5 (TSAV 보장):** 임계 ε를 쓰면 δ_time = h_mid √ε Σ_{k∈I} G_k + B_cond입니다(식 (7)). 식 (6)을 √ 취하면 h_k‖r‖ ≤ h_mid√ε가 나오고, 이를 정리 4.3에 넣으면 됩니다(부록 A.3). 유도는 맞습니다.

이론의 실무적 한계는 세 가지입니다. (i) L_k, C_k는 측정하지 않고, δ의 수치도 보고하지 않습니다. 따라서 "보장"은 조건부 상계입니다. (ii) 부록 A.2의 Lemma 4.4는 "MSE"라고 쓰지만 식 (5)의 좌변은 상태 차이의 제곱노름입니다(표현상의 혼동). (iii) ‖·‖_A를 "토큰별 최대 MSE"로 정의합니다(§4.2, 식 (2) 아래). 이것을 노름으로 볼 수 있는지 명시가 없습니다(max 연산 아래 √ 취하면 노름이 됩니다. 사소한 문제).

### 2.3 모델별 적용 (§4.5, 부록 B.5)

- **Joint-WAM:** 비디오 잠재와 행동을 함께 denoise합니다. 미래 상태 ĉ와 행동 â를 같은 앵커로 초안하고, 검증은 **행동 속도 잔차**로만 합니다(Alg. 2). 비디오 상태는 검증 없이 커밋됩니다.
- **Fast-WAM:** 관측 프레임의 고정 시각 캐시를 쓰고 행동만 투기합니다.
- **Faster-WAM:** 희소 비디오–행동 상호작용과 캐시된 미래 문맥을 씁니다.

Joint-WAM은 "controlled implementation"이라고 적혀 있고(§4.5 및 §3 본문), 인용은 [49] 하나인데 이 번호는 Fast-WAM 논문입니다. 즉 Joint-WAM은 공개 모델이 아니라 저자들이 만든 대조 구현입니다.

## 3. 실험 (§5, 부록 B–C)

### 3.1 설정

- 장비: RTX 5090 (§5.1 Implementation Details). 입력 224×448, 10 denoising steps (Fig. 3 설명).
- ε = 10⁻², K = 1 (첫 Euler 한 번 뒤 투기), 창 상한 w = 총 스텝 수(§5.1).
- 벤치마크: LIBERO 4개 스위트 × 10과제 × 50시행(= 2000), RoboTwin 2.0 50과제 × 100시행 × (clean, rand), LIBERO-Plus 10,030 과제 × 3시행(§5.1, §B.2).
- 지연: 30회 측정, 워밍업 5회(Fig. 3 설명). 표의 지연은 LIBERO-Plus 평가 로그에서 옵니다(추정; 원문에 명시 없음).

### 3.3 구성 요소 분해 (§5.3, Table 4)

Table 4의 "neither" 행은 RAVS와 TSAV를 모두 끈 상태입니다. 이 행은 Table 3의 **FlowCast 행과 세 모델 모두에서 같은 값**입니다(검산 완료). 즉 제거 실험의 기준선은 FlowCast와 같은 알고리즘이라는 뜻이고, 본문에는 이 점이 적혀 있지 않습니다.

- RAVS 단독: 평균 +1.05 / +1.06 / +1.52 pp, 지연은 거의 그대로.
- TSAV 단독: 평균은 오르고 지연은 7.0%–10.6% 줄어듭니다.
- 둘 다: 평균 +1.43 / +3.03 / +2.13 pp, 지연 −13.4% / −25.1% / −24.8%(Faster는 본문 범위 안).

### 3.4 민감도 (§5.4, 부록 B.4, Table 5–6)

- K ∈ {1,2,3,4}: K=1이 정확도와 지연 모두 최고입니다. K가 커질수록 지연이 늘어납니다.
- ε ∈ {10⁻³ … 5×10⁻²}: 세 모델 평균 성공률 범위가 최대 0.57 pp입니다(Joint). 지연은 ε가 작을수록 늘어납니다.

### 3.5 메커니즘 검증 (부록 C)

- C.2 (Table 7): 처음과 끝 전이가 MSE의 66–80%를 차지합니다. 이는 RAVS의 근거입니다.
- C.3 (Table 8): 4가지 적분 스케줄(Uniform, Shift-5, Shift-0.2, Cosine)에서 중앙값 참조가 평균 성공률이 가장 높습니다. 다만 Uniform에서는 참조 값이 모두 같아서 중앙값만 보고합니다.
- C.4 (Table 9): 행동 엔트로피가 Joint 2.31→2.01, Fast 2.15→1.80, Faster 2.09→1.87 bit로 줄어듭니다. 이것을 "더 일관된 행동"의 근거로 씁니다(효과 크기 0.6–2.1 SD). 다만 어떤 샘플에서 쟀는지(50개 균등 샘플, 쌍체) 외에 검정이 없습니다.
- C.5 (Table 10): VLA-Cache, TeaCache, BAC, SpeCa 위에 WAMotor를 얹으면 12쌍 모두 정확도와 지연이 함께 좋아집니다. SpeCa+WAMotor(Fast)는 65.05 ms로 6.02×입니다.

## 4. 한계와 저자들의 서술 (§6, §7, 본문)

- 결론은 "velocity smoothness의 잠재력"을 강조하고 한계 절은 본문에 없습니다. 부록에도 한계 절이 없습니다.
- 성공률은 **시드 변동을 보고하지 않습니다**. 표준편차는 Table 7과 Table 9에만 있습니다.
- 투기 샘플러의 **수용률이나 평균 모델 호출 수(NFE)를 보고하지 않습니다**. 지연만 보고합니다. 코드에는 이 값을 재는 추적기가 있습니다(`04_code_verification.md` D7).
- 지연 비교에서 **투기 경로만 `torch.compile(mode="reduce-overhead")`를 씁니다**(CUDA에서). 기준(Vanilla) 경로는 쓰지 않습니다(`04` D5). 논문 본문에는 이 점이 없습니다.
- 기준선(TeaCache, BAC, ParaStep, SpeCa, VLA-Cache, FlowCast)의 구현 출처가 적혀 있지 않습니다. 저장소에도 없습니다.
- LLM 사용 고지(§7)에는 "GPT6-Astra through Codex"로 구현 코드 보조, 수식 점검이 적혀 있습니다.
