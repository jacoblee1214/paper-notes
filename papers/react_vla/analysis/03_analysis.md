# 03. 수치 재계산, 일관성 검사, 토이, 주장 판정

계산은 `analysis/recompute.py`(수 초)와 `analysis/toy_rolling_modes.py`(약 1초)가 하고, 결과는 `recompute_results.json`, `toy_rolling_modes_results.json`에 있습니다. 논문 표 값만 쓰며 학습이나 평가는 돌리지 않았습니다. 검사 항목은 V1–V14, 토이 결과는 Y1–Y3, 주장 판정은 C1–C16으로 번호를 붙였습니다.

## 0. 가정

- 시뮬레이션: 과제와 조건마다 100회(부록 C.6). 합산 시 과제 7개 × 100회 = 700회.
- 실세계 일반 과제: 과제당 30회(§4.1, 부록 C.6). 표는 정수 %이므로 시행 수는 k = round(p × 0.3)으로 복원했습니다(**시행 수 30 가정**). 6개 쌍 합산 180회.
- 특수 과제(표 3): 시행 수가 적혀 있지 않아 **30회 가정**하고 20회, 50회 가정도 함께 냈습니다.
- 모든 검정은 평가 롤아웃의 표집 잡음만 반영합니다. 학습 시드가 하나(§6)라 시드 간 변동은 어떤 검정에도 들어 있지 않습니다. 시뮬에서 방법 사이에 같은 환경 시드를 썼는지 논문에 적혀 있지 않아 짝지은 검정은 하지 않았습니다.
- 합산 z 검정은 과제를 같은 확률로 섞은 것이라, 과제 층을 나눈 Cochran–Mantel–Haenszel(CMH) 검정과 과제 단위 부호 검정을 함께 냈습니다.

## 1. 표 1·2 평균과 표기 (V1–V3)

### V1. 표 1 평균: 일치

6개 방법 × 2조건 = 12개 평균이 7과제 단순 평균과 모두 일치합니다(소수 둘째 자리까지). 예: H50E50 Clean = 262/7 = 37.43, REACT w/o DD Clean = 348/7 = 49.71.

### V2. 표 2 평균: 한 칸만 계산 규칙이 다릅니다

로봇별 평균 12개 중 11개는 표에 적힌 정수 세 개의 평균과 일치합니다(예: ARX H50E50 (73+36+56)/3 = 55.0). Franka H50E10만 표기 27.8이고, 정수 평균은 27.67(27.7), 시행 수(30회 가정) 복원 평균은 25/90 = 27.78입니다. 차이는 0.1%p입니다. 전체 평균 35.9는 로봇 평균 두 값(44.0, 27.8)의 평균입니다. 이 한 칸은 결론에 영향이 없습니다.

복원 평균과 정수 평균의 차이가 큰 칸은 ARX REACT w/o DD(정수 평균 68.3, 복원 68.9)와 ARX H50E50(55.0 대 55.6)입니다. 표에 적힌 값은 정수 평균 규칙입니다.

### V3. 30회 과제의 소수 백분율 표기가 한 가지 규칙이 아닙니다

시행 수 30 가정에서 k/30이 정수가 아닌 칸은 36칸 중 22칸입니다(나머지 14칸은 k/30이 정수 %인 칸, 즉 0, 30, 50, 60, 70, 80 등). 그 중 .33 값 8칸은 반올림과 내림이 같아 구분되지 않고, **.67 값 14칸은 10칸이 내림, 4칸이 올림**입니다.

## 4. jerk (표 8, 그림 3) (V7)

### 평균 일치와 과제 집합

표 8의 로봇·방법별 평균 중 비어 있지 않은 값은 모두 과제 값의 평균과 일치합니다(예: Sim H10E10 (1341.8+1784.5+1425.7+1638.8+1153.1)/5 = 1468.8). "–"인 칸은 표 1·2에서 성공이 0인 칸과 맞습니다. 하나 예외로 보이는 칸이 있습니다. pick_diverse_bottles의 H10E10은 표 1에서 Clean 0%, Randomized 1%이고 표 8에서는 "–"입니다. 표 8이 어느 조건의 값인지 적혀 있지 않은데, Clean 값만으로 만든 표라면 맞습니다(`recompute_results.json`의 V6c).

### 방법마다 평균 과제 집합이 다릅니다

평균은 성공 에피소드가 있는 과제만 평균합니다. 예를 들어 ARX Async+RTC의 284.1은 Bowl과 Cable 두 과제(Bottle Cap은 성공 0%)의 평균이고, REACT의 90.1은 Bottle Cap(87.3)을 포함한 세 과제의 평균입니다. 성공이 더 많은 방법이 더 어려운 에피소드를 포함하므로 jerk 비교는 성공 에피소드 집합에 의존합니다. 모든 방법에 성공이 있는 과제만 비교하면 다음과 같습니다.

| 비교 | 시뮬 (7과제) | ARX (Bowl, Cable) | Franka (Bowl, Keyring) |
|---|---|---|---|
| REACT 대 H50E50 | 1219.0 대 658.9 (1.85배) | 91.5 대 62.1 (1.47배) | 27.6 대 13.6 (2.03배) |
| REACT 대 H50E10 | 1219.0 대 1463.7 (0.83배) | 91.5 대 86.1 (1.06배) | 27.6 대 28.5 (0.97배) |
| REACT w/o DD 대 H50E10 | 1064.7 대 1463.7 (0.73배) | 79.2 대 86.1 (0.92배) | 24.9 대 28.5 (0.87배) |
| REACT 대 Async+RTC | 1219.0 대 2022.2 (0.60배) | 91.5 대 284.1 (0.32배) | 28.6 대 31.6 (0.91배, 세 과제) |

- **Async+RTC보다 낮다는 서술은 세 곳 모두 방향이 맞습니다.** 시뮬 0.60배, ARX 0.32배(3배 이상)이고 Franka는 0.91배로 차이가 작습니다. jerk는 평균만 보고되어 분산 정보가 없으므로 Franka의 차이는 방향만 있습니다.
- **H50E10(자주 다시 계획) 대비 "더 매끄럽다"는 시뮬에서만 확인됩니다.** 실로봇의 공통 과제에서 REACT는 H50E10과 같거나 약간 높습니다(ARX 1.06배, Franka 0.97배). REACT w/o DD는 세 곳 모두 H50E10보다 낮습니다. 초록의 "smoother than frequent-replanning and asynchronous baselines"에서 앞 부분은 w/o DD와 시뮬에서 확인되고, DD를 넣은 실로봇에서는 구분하기 어렵습니다.
- **DD를 넣으면 jerk가 올라갑니다.** w/o DD 대비 시뮬 +14.5%, ARX +18.6%, Franka +7.9%입니다. 본문(§4.2)은 DD가 매끄러움을 해치지 않는다고 쓰지만 표 8에서는 세 곳 모두 올라갑니다.
- 가장 매끄러운 것은 세 곳 모두 H50E50이고, REACT는 1.5–2배입니다(표 8과 그림 3, 본문도 이 점을 인정합니다). 시연 데이터는 시뮬 570.1이고 REACT는 2.14배입니다.

## 5. 처리량과 지연 산술 (V8, V12)

### V8. 표 5, 표 7, 식 4–15: 일치

식 6–15를 T_VLM = 37 ms, T_DiT = 3 ms, N = 10, f_cam = f_ctrl = 30 Hz로 다시 계산하면 표 5의 17개 행이 모두 반올림 범위에서 같습니다. 예: 동기 H_e=50은 T = 67 + 1666.7 = 1733.7 ms(표 1734), Φ_in = 0.577(0.58), Φ_out = 28.84(28.8). REACT w/o DD K=5, S=10은 T = 37 + 3 + 333.3 = 373.3 ms, Φ_in = 2.68, Φ_out = 26.8. 표 7의 속도 향상 66.04/39.96 = 1.653(1.65배)이고 모델값 67 ms와 40 ms도 측정값과 가깝습니다.

관찰 두 가지입니다.
- REACT(S=10)의 처리량 3.0/30.0 Hz는 Async+RTC(H_e=10)의 3.00/30.0 Hz와 **같습니다**(표 5). 그림 1의 "높은 입력, 높은 출력" 영역에서 둘이 같은 칸에 있는 것과 맞습니다. REACT의 이점은 처리량이 아니라, 같은 처리량에서의 성공률과 jerk입니다(본문도 같은 말).
- REACT w/o DD 한 갱신의 40 ms 중 VLM이 37 ms(92.5%)입니다. 단일 Euler 단계로 얻는 속도 향상은 이 구조에서 1.65배로 묶입니다. 실행 행동 10개당 DiT 호출 수는 기준선 H50E10이 10번, REACT가 1번입니다.

### V12. 임베딩 나이 (§3.2)

평균 233 ms, 95백분위 383 ms, 최대 416 ms는 선택 관측 주기 333 ms와 비교됩니다. 최대 416 ms는 주기를 넘고(1.25배) 2주기(666 ms)보다 작으므로 "한 선택 관측 이상 뒤처지지 않는다"는 문장은 "방금 캡처된 프레임이 아직 인코딩 중일 때 직전 프레임의 임베딩을 쓴다"는 뜻으로 읽을 때 맞습니다. 나이의 평균(233 ms)이 VLM 지연(약 37 ms)보다 훨씬 큽니다. 센싱 루프와 DiT 갱신 루프가 위상이 맞춰지지 않은 독립 타이머라면 나이의 대부분은 두 루프의 위상차에서 올 수 있습니다(가능성. 공개 코드의 구조가 그렇습니다, 04 D14). 위상을 맞추면 나이를 줄일 여지가 있습니다.

### V10. K와 지평 H가 함께 변합니다

S=10에서 K를 1→5로 올리면 H = KS도 10→50으로 커집니다(그림 11의 "K=1, 2, 3, 4, 5"는 H = 10, 20, 30, 40, 50). 본문은 이를 "더 많은 관측이 한 블록을 형성해 수렴한다"로 해석합니다(부록 E). 이 해석은 "더 긴 지평"과 가려지지 않습니다. 지평을 H=50으로 고정한 칸만 비교하면 (K, S) = (5, 10) 49.7%, (10, 5) 33.1%, (25, 2) 22.3%, (50, 1) 17.4%로, 블록 길이가 클수록(그리고 K가 작을수록) 높습니다. 같은 H에서는 K를 올리는 것이 오히려 성공률을 낮춥니다. "K를 올리면 일관되게 좋아진다"는 문장은 S=10, H가 함께 늘 때의 서술입니다(`own_ablation.png`). 두 가지를 갈라 보려면 K 증가와 H 증가를 분리하는 설계(예: H=50 고정에서 S와 K를 함께 바꾸고, K 증가가 H에 따른 것임을 보는 짝 실험)가 필요합니다. 700회 기준 (5, 10)의 Wilson 95%는 46.0–53.4, (10, 5)는 29.8–36.7입니다.

## 7. 토이: 롤링 버퍼가 모드 유지와 반응 사이에서 하는 일 (Y1–Y3)

`analysis/toy_rolling_modes.py`는 학습 없이 해석적 베이즈 최적 흐름 정책(두 갈래 모드의 가우시안 혼합)으로 §3.1의 설명을 확인합니다. 행동 청크는 a_j = m + 0.3 z_j(m ∈ {−1, +1}), 관측은 o = m*(t) + σ_o ε, 참 모드 m*(t)는 평균 200스텝(최소 60)마다 바뀝니다. 400 에피소드 × 600 스텝, numpy, 시드 고정입니다. 최적 속도는 v = (x − E[a|x,o]) / τ이고, E[a|x,o]는 관측 우도와 버퍼 우도로 모드를 가른 뒤 계산합니다. REACT는 K=5, S=10, 블록마다 새 관측, 워밍업 K−1회, 앞 블록은 §2.1 검산 2대로 â를 실행합니다.

버퍼 증거 신뢰도 β ∈ [0, 1]를 하나 더 두었습니다(β=1은 "버퍼가 현재 관측과 같은 청크의 전방 과정에서 나온 표본"이라고 믿는 정확한 베이즈, β=0은 버퍼 무시). 학습된 실제 모델이 버퍼를 얼마나 신뢰하는지는 알 수 없으므로 β를 훑었습니다.

### Y1. 정확한 베이즈 정책(β=1)은 버퍼에 고착됩니다

σ_o = 0.5, 1.0, 2.0 모두 정확도가 0.51–0.55(우연 수준)이고 블록 부호 전환이 0입니다. 첫 관측에서 정해진 모드를 에피소드가 끝날 때까지 유지하고, 참 모드가 바뀌어도 따르지 않습니다. 이유: 이미 부분적으로 디노이징된 버퍼 블록이 모드에 대한 강한 증거를 지니고, 같은 모델이 그 증거를 "현재 관측과 짝인 표본"으로 취급합니다. 학습된 정책에서 이 고착이 어느 정도 나타나는지는 이 토이로 알 수 없습니다. 다만 부록 C.5의 일치 논증은 (시간, 위치) 쌍만 맞추며, 서로 다른 관측에서 온 블록으로 이루어진 버퍼는 학습 분포에 없습니다(04 D13).

### Y2. 증거 신뢰도가 중간일 때 REACT는 H50E10보다 전환이 적고 H50E50보다 정확합니다 (σ_o = 1.0)

| 방법 | 정확도 | 에피소드당 블록 부호 전환 (참 2.65 포함) | 반응 지연 중앙값/평균 (스텝) | 미반응 비율 |
|---|---|---|---|---|
| H50E50 | 0.728 | 4.4 | 20 / 25.8 | 0.116 |
| H50E10 | 0.782 | 20.1 | 5 / 6.5 | 0.014 |
| REACT β=0.03 | 0.716 | 1.9 | 51 / 57.8 | 0.300 |
| REACT β=0.01 | 0.889 | 3.5 | 25 / 27.0 | 0.061 |
| REACT β=0 (버퍼 무시) | 0.884 | 5.9 | 18 / 20.2 | 0.041 |
| REACT-stale β=0.01 (관측이 한 블록 묵음) | 0.849 | 3.5 | 34 / 36.5 | 0.090 |

- β=0.01에서 REACT는 H50E10보다 블록 부호 전환이 5.7배 적고(3.5 대 20.1), 정확도가 높고(0.889 대 0.782), 대신 반응 지연이 약 4배입니다(평균 27 대 6.5 스텝). H50E50과 비교하면 전환 횟수와 지연이 비슷하고(3.5/27.0 대 4.4/25.8) 정확도가 높습니다. 논문이 말하는 "모드 일관성은 유지하면서 신선도를 얻는다"의 구조는 이 영역에서 나타납니다.
- **다만 이득의 상당 부분은 버퍼 기억이 아니라 "표본 대신 사후 평균을 실행"한 효과입니다.** β=0(버퍼 무시)도 정확도 0.884입니다. H50E10과 H50E50은 사후에서 표본을 뽑는 정책이고, REACT의 마지막 단계는 â(조건부 평균)를 냅니다(§2.1 검산 2). 논문의 H50E10 기준선에 "마지막 단계에서 평균을 쓰는" 변형은 없습니다. 버퍼 기억 자체의 효과는 β=0 대비 전환 횟수(5.9 → 3.5)와 반응 지연(20 → 27 스텝)의 교환으로 나타납니다.
- 관측이 한 블록(10스텝, 333 ms) 묵으면 지연이 +9–10스텝, 정확도 −0.04입니다(§3.2의 "작은 격차"와 같은 방향).

### Y3. 토이가 말해 주는 것과 말하지 않는 것

말해 주는 것: 롤링 버퍼는 모드 전환의 빈도와 반응 지연을 교환하는 장치이고, 그 교환 지점은 모델이 버퍼 증거를 얼마나 믿는지에 따라 달라집니다. 정확한 베이즈 극한에서는 반응이 완전히 사라집니다. 말하지 않는 것: 실제 π0.5가 어느 지점에 있는지, 실제 청크의 위치 간 상관, 접촉 물리, 관측 잡음의 구조. 1차원, 모드 두 개, 독립 관측 잡음, 사후를 아는 정책이라는 한계가 있습니다. 실로봇 Reaction Game에서 REACT가 약 734 ms로 반응한 것(표 3)은 학습된 모델이 버퍼를 완전히는 믿지 않는다는 쪽과 맞습니다.

## 9. 요약

- 표 1, 표 5, 표 7, 그림 11–12의 산술은 모두 맞습니다. 표 2의 소수 표기와 한 칸의 평균(Franka H50E10 27.8)만 다른 규칙으로 보입니다(V2, V3).
- 성공률의 큰 그림(롤링이 Async+RTC와 단축 지평 기준선보다 높음)은 시뮬과 실세계에서 모두 통계적으로 견고합니다. 반면 **가장 단순한 기준선 H50E50과의 실세계 차이, 반응 지연의 순서, DD의 jerk 이득, 학습 효율은 현재 자료로 구분되지 않거나 해석이 섞여 있습니다.**
- 절제 해석은 K와 H를 분리해야 하고, 학습 효율 주장은 추론 방식을 맞춘 비교가 필요합니다.
