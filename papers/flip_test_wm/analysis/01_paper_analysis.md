## 1. 문제와 주장

- 질문: 비디오 세계모델은 현재 장면에서 미래를 예측할 때 **세계의 상태**(예: 책이 탁자 모서리에서 몇 mm 나와 있나)를 추적하는가?
- 방법적 착상: 미래를 뒤집는 작은 변화(tipping point 양쪽의 **시각적 최소 쌍**)를 만들고, 모델의 예측이 같이 뒤집히는지 봅니다. 한 영상만 평가하는 기존 물리 플라우저빌리티 벤치마크(VideoPhy, PhysicsIQ, WorldModelBench)가 놓치는 "같은 그럴듯한 영상을 두 장면에 모두 만들어 내는" 실패를 잡으려는 것입니다(§1, §2).
- 핵심 주장(저자 표현): 비디오 세계모델은 **무엇이 어떻게 보이는지는 배웠지만 무엇이 결과를 결정하는지는 배우지 못했다.** 실패의 주된 원인은 렌더링보다 초기 프레임에서 물리 상태를 읽는 단계에 있다.

## 2. 방법

### 2.1 세 단계 계층 (FlipTest)

| 수준 | 질문 | 자료 | 지표 |
|---|---|---|---|
| L1 (탐지) | 경계를 넘을 때 예측이 바뀌나 | 300쌍(600프레임): 시뮬 10과제 x 15쌍 + 실사 15과제 x 10쌍 (§3.2, 표 1·2) | 쌍 정확도(두 프레임 모두 맞아야 함). 우연 25% |
| L2 (선택성) | 경계 건너에서만 바뀌나 | 시뮬 10과제 x 제어 집단 15개 x 4상태 = 600프레임 (§3.2, 그림 4a) | SS = CFR − SFR (경계 건너 뒤집힘 비율 − 같은 쪽 뒤집힘 비율) |
| L3 (국소화) | 경계가 어디에, 얼마나 날카롭게 있나 | 시뮬 4과제 x 4장면 x 30상태 = 480프레임 (§3.2, 그림 5) | P(event | m) 곡선의 위치와 기울기 |

- 시뮬레이션 과제는 MuJoCo로 만들었고, 쌍의 두 상태는 임계값 ±δ에 놓입니다. 카메라 지터와 시각 테마는 쌍 안에서 고정합니다(부록 A).
- 실사 과제는 241개 프레임이 실사 사진의 **반사실 편집**(또는 제품 사진, 스테이징 스틸)이고 59개가 경계 근처에서 실제 촬영한 영상의 초기 프레임입니다(§3.2, 부록 A). 편집 쌍은 결과를 바꾸는 변수만 바꾸도록 만들었다고 합니다.
- 정답 라벨은 시뮬에서 해석적 임계값(§부록 A의 상수)으로 정하고, 쌍은 두 방향이 모두 물리 시뮬레이터 결과와 맞을 때만 씁니다("All 300 members pass this check").

### 2.2 판독

- 비디오 모델은 초기 프레임과 중립 프롬프트(그림 11)만 받습니다. 생성된 영상은 **두 VLM 판정기**(Gemini 3.6 Flash, Gemini 3.8 Flash)가 정답 자체와 무관하게 "영상이 보여 주는 결과"를 읽습니다(부록 B, 그림 14). 블라인드 프로토콜이고 "unclear"(판단 불가)를 허용합니다.
- L1: 두 판정기가 **모두** 정답을 말해야 프레임이 맞고, 판정기 불일치와 unclear는 틀린 것으로 셉니다(보수적 규칙).
- L2, L3: 두 판정기의 라벨을 모두 써서 전이 통계를 냅니다.
- 실험 설정: temperature 0, 8 fps 샘플링(기본 1 fps는 빠른 낙하를 놓친다고 설명), 판정기 JSON 스키마(§3.3, 부록 B).

### 2.3 진단 실험 (§5)

- 같은 초기 프레임을 세 예측기가 처리합니다: (a) 직접 VLM(Gemini 4 Argon, 도구 없이 한 번 답변), (b) 측정 에이전트(Python으로 기하 측정 후 답변), (c) 시뮬레이션 에이전트(측정 + MuJoCo 재구성·롤아웃). 세 방식 모두 같은 모델(Gemini 4 Argon)이고, 샌드박스에 네트워크와 물리 엔진 import를 막은 상태입니다(부록 C). 각 780회 실행.
- 추가로 정답 결과를 프롬프트에 넣은 "told-outcome" 조건으로 같은 영상 모델을 다시 돌려 렌더링 능력을 따로 잽니다(§5, 그림 8, 51개 조건 프롬프트).

## 4. 주요 결과 (논문 수치 그대로, 재계산은 03)

### 4.1 L1: 쌍 정확도 (그림 3, 표 3)

- 전체 평균(시뮬과 실사 단순 평균): Gemini Omni 18.3%가 최고, 최저 CogVideoX 5.7%(§4.1).
- 시뮬: 최고 5.3%(4개 모델 동률, 8/150). 11개 모두 우연(25%)보다 낮음(F1).
- 실사: Omni 31.3%, MiniMax-H3 25.3%, Wan2.2 24.7%, CogVideoX 9.3%.
- 실사가 시뮬보다 7–26 pp 높음. 본문은 실사에서 "시각적 선입견(semantic shortcut)"이 도움이 된다고 해석합니다.
- 실패 양상: 두 프레임에 **같은 결과**를 내는 경우가 명확히 판정된 쌍의 대부분입니다(시뮬 89%, 실사 72%, 본문; 재계산 03 §3).
- 규모, 세대, 물리 사전학습, 추론 튜닝 효과 작음(F2): Cosmos-Predict2.5 10.3% → Cosmos3-Super 13.7%, Wan2.2 14.0% = VBVR-Wan2.2 14.0%.

### 4.2 L2: 선택성 (그림 4)

- VLM(Gemini 3.6 Flash, 직접 답변): 경계 건너 뒤집힘 61%, 같은 쪽 15%, SS = +0.46 (95% CI [0.36, 0.56]).
- 비디오 11개: SS가 −0.07(Cosmos-Predict2.5)에서 +0.07(VBVR-Wan2.2) 사이이고 모든 CI가 0을 포함(F3). 즉 "얼마나 자주 바뀌는지"는 경계와 무관합니다.

### 4.3 L3: 경계 위치 (그림 5)

- 비디오 3개(Omni, Cosmos3-Super, VBVR-Wan2.2)와 Nano Banana Pro는 평평한 곡선, 경계 건너 확률 차이 0.00–+0.06.
- VLM 2개(Gemini 4 Argon +0.62, Gemini 3.8 Flash +0.58)는 S자 곡선이지만 m = 0보다 앞에서 올라감(과대 예측, 경계 흐림).
- 본문 주장: 비디오는 경계를 "등록조차 하지 않는다", VLM은 "체계적 이동이 있는 경계를 탐지한다"(F4).

### 4.4 원인 진단 (§5, 그림 7–10)

| 예측기 | 실사 쌍 | 스윕 프레임 | 비고 |
|---|---|---|---|
| 최고 비디오 모델 (Omni) | 31.3% | 평평 | 중립 프롬프트 |
| Omni, 정답을 프롬프트에 명시 | 86.7% (시뮬 60.7%, 평균 73.7%) | — | 판정 단일 판정기 3.8 (§5, 부록 E) |
| 직접 VLM | 87.3% | 74.2% (m ≈ 0 근처 38%) | 같은 모델 |
| 측정 에이전트 | 93.3% | 99%+ (오류 3개) | 시뮬 실행 없음 |
| 시뮬레이션 에이전트 | 91% 이상 | 98% | 사전 판단 96.0% 실사 / 97.5% 스윕, 롤아웃이 4/761회만 바꿈 |

- 결론 F5: 초기 프레임에서 상태를 측정하면 실사 쌍의 93% 이상을 풀므로 물리 시뮬레이션은 추가 이득이 작음. F6: 비디오 모델의 실패는 주로 상태 **읽기**에서, 부차적으로 **렌더링**에서 생김(정답을 알려 줘도 4분의 1 이상 틀림).
- 에이전트 비용: 측정 에이전트 중앙값 615 s, 시뮬 636 s(§5, 부록 C.1). 롤아웃은 실행 시간의 약 10%.

### 4.5 제안 (§6, 부록 F)

- 모듈형 블루프린트: 에이전트가 상태를 추정 → 전용 시뮬레이터/수치 해석기 → 영상 모델은 **결과가 주어졌을 때** 렌더링만 담당.
- 대조 시각 스키마(부록 F): 결정 조건이 다른 두 예시를 같이 보여 주는 방식. 미래 연구로 남김(실험 없음).

## 5. 주장과 증거의 틈 (본문 기준)

1. **학회·공식 코드 없음.** 쌍 정확도 계산의 재현 근거는 본문 부록과 블로그뿐입니다. 판정 프롬프트와 샘플링 설정은 부록에 있지만, 영상 샘플과 판정 결과 원자료는 없습니다(Code&Data 예정).
2. **판독 정확도의 모델별 값 없음.** 사람 라벨 600개로 판정기(3.6)가 79%를 맞혔다는 값만 있습니다(§3.3). 이 값이 비디오 모델 전체와 같은 분포인지, 왜 완벽한 생성기도 쌍에서 86.7%를 넘지 못하는지 설명이 부족합니다(03 §5).
3. **단일 판정기 대 이중 판정 규칙.** §5의 told-outcome 73.7%는 판정기 3.8 하나로 읽은 값이고, 중립 18.3%는 이중 규칙입니다. 같은 영상에서 실사 Omni는 단일 판정기 34.7%, 이중 규칙 31.3%입니다(§3.3). 두 값을 "18.3 → 73.7 상승"으로 직접 비교하는 것은 판정 규칙이 달라서 과장될 수 있습니다(03 §6).
4. **우연 25%의 가정.** 3지선다 과제(본문: 뉴턴 요람, 실사 시소)가 있어 쌍 우연은 11%입니다. 전체 우연은 약 24%입니다(03 §2).
5. **신뢰구간이 쌍 단위 이항 가정.** 실사 쌍 150개는 15과제 x 10쌍으로 묶여 있습니다. 과제 효과를 고려하면 구간은 더 넓어집니다(03 §4). 본문은 L1의 CI를 보고하지 않습니다.
6. **측정 에이전트 대 직접 VLM.** 실사 쌍 93.3% 대 87.3%(140/150 대 131/150)는 짝지음 없이 Fisher 검정 p ≈ 0.12로 구분되지 않습니다. 스윕(99.4% 대 74.2%)의 차이는 큽니다. 본문의 "거의 모든 경계 흐림을 없앤다"는 스윕 결과에 근거하고, 실사 쌍 차이의 강조는 과합니다(03 §5).
7. **시뮬레이션 정답과 시뮬레이션 에이전트의 독립성.** 시뮬 과제 정답은 MuJoCo 기반 해석적 임계값이고, 시뮬레이션 에이전트도 MuJoCo로 장면을 다시 만듭니다. 스윕 정답은 시뮬 장면 기준이므로 에이전트 성공은 "지각(측정)"의 성공이 주된 근거이고 물리 엔진 검증은 약합니다. 실사 쌍에서 에이전트가 91% 이상이라는 값은 실사 정답 라벨(편집으로 정한)에 의존합니다.
8. **판정기와 피검사 모델이 같은 개발사.** 판정기(Gemini 3.6/3.8 Flash)와 VLM·에이전트(Gemini 4 Argon)가 Google 계열이고, Gemini Omni Flash 1.1도 같은 계열입니다. 블라인드 설계이지만 계열 편향이 가능합니다. 본문은 이를 언급하지 않습니다(확인 불가).
9. **L2 제어 집단의 n.** 시뮬 10과제 x 15집단 = 150 집단입니다. CI는 "장면과 판정기 한 명 샘플링"의 부트스트랩이라고 적혀 있습니다(§3.3). 근사 계산과 대체로 맞습니다(03 §4).
10. **판정기 일치도.** 두 판정기 일치 85.8%, κ = 0.85(§부록 B). 판정기 불일치를 틀린 것으로 세기 때문에 쌍 정확도는 보수적입니다. 반대로 같은 규칙이 모델 간 비교를 공정하게 만드는지는 검증되지 않았습니다.
11. **범위.** 강체 물체의 임계값 동역학, 단일 초기 프레임, 단일 결정 요인. 저자도 한계로 인정(부록 G). 실제 로봇 장면의 접촉, 변형, 다중 요인은 대상이 아닙니다.
12. **제목과 결론의 강도.** 제목 "Fail to Learn the World State"는 "L1–L3 테스트에서 실패"를 넘어 "세계 상태를 학습하지 못했다"는 일반 명제로 읽힙니다. 측정은 특정 과제 집합(25과제, 1,680프레임)과 11개 모델에 한정됩니다.
