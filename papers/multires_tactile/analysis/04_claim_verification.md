# 04. 주장 검증과 구현 가능성

공식 코드가 없어서(2026-11-26 기준, `02` §2) 코드 대조(D 항목) 대신 **논문과 프로젝트 페이지의 주장을 표, 본문, 부록의 수치로 검증**했습니다. 판정 근거는 `03`의 재계산(V, K 항목)입니다. 주장 번호는 C1–C17입니다.

## 0. 대상과 방법

- 대상: arXiv v2(2026-10-21, 23쪽), v1(2026-06-04)과의 차이(`01` §0), 프로젝트 페이지 `mitas-touch.github.io`, Hugging Face 데이터셋 `RKrohn/MiTaS`의 파일 목록과 크기(API 메타데이터).
- 방법: 표 값을 옮겨 재계산, 표 사이와 본문 사이 일치 확인, 시행 수 제약 확인, 시행 단위(Fisher)·층화(CMH)·정책 단위 검정, 그림 판독. 학습, 실행, 설치, 데이터 다운로드는 하지 않았습니다.
- 판정 용어: **맞음**(재계산과 일치하고 근거가 충분), **방향만**(방향은 맞으나 표본이 구분하지 못함), **서술과 표가 다름**, **근거 약함**(검증 가능한 지지가 적음), **확인 불가**(공개 자료로 확인할 수 없음).

## 2. 주장 판정 (C1–C17)

| 번호 | 주장 (출처) | 판정 | 근거와 비고 |
|---|---|---|---|
| C1 | MiTaS 평균 80%, 시각 전용 35.5%, 시각촉각 55.5%와 63% (초록, 그림 4, 표 8) | **맞음(산술), 모집단 주의** | 160/200, 71/200, 111/200과 일치(`03` V1, V2). 55.5%는 두 데이터셋 합 200회, 63%는 데이터셋 2의 Q-Former 100회입니다. 같은 데이터셋 2에서 MiTaS 80% 대 Q-Former 63%(+17%p, p = 0.012), 대 Sparsh-X 57%(+23%p, p = 7e-4)(`03` V4) |
| C2 | 모든 과제에서 MiTaS가 기준선보다 높다 (그림 4 캡션, §4.2) | **순서는 맞음, 과제별 구분은 일부** | 합친 40회에서 MiTaS가 모든 과제에서 가장 큽니다. 개별로 구분되는 것은 Gear(85 대 45, p = 3.4e-4)와 Key(75 대 35, p = 6.5e-4)이고(Holm 후에도 0.05 이하), Board(95 대 80, p = 0.087), Lamp(82.5 대 67.5, p = 0.20), Lightbulb(62.5 대 50, p = 0.37)는 구분되지 않습니다(`03` V4) |
| C3 | MiTaS는 "모든 과제를 일관되게 푼다" (§4.2) | **근거 약함(표현)** | "일관성"의 기준이 없습니다. Lightbulb 25/40(62.5%, Wilson [47, 76]), Key 30/40(75%)이고 학습 실행과 데이터셋 변동은 V7에서 보입니다 |
| C4 | Sparsh-X는 "키를 여러 번 넣었지만 한 번도 완료하지 못했다" (§4.2, v1에도 있음) | **서술과 표가 다름** | Sparsh-X V+G+E의 Key는 데이터셋 1에서 2/20, 데이터셋 2에서 12/20, 합계 14/40(35%)(표 9, 10, 8)입니다(`03` V1). 어느 모델·세션을 가리키는 문장인지 저자 확인이 필요합니다 |
| C5 | 시각 전용 모델은 Key와 Lightbulb를 일관되게 풀지 못한다. 원인은 "가림과 복잡한 접촉 동역학" (§4.2, 그림 4 캡션) | **방향만, 원인은 시험하지 않음** | 합친 값은 Key 17.5와 22.5%, Lightbulb 15와 10%입니다. 데이터셋 1에서는 0%이고 데이터셋 2에서는 Key 35–45%, Lightbulb 20–30%입니다(`03` V7). 가림을 바꾼 실험이나 가림 정도의 측정은 없습니다 |
| C6 | 융합 구조 비교: MiTaS가 PolyTouch, Q-Former, Sparsh-X보다 높고, "융합 방식 말고 조건 토큰의 모양이 중요하다" (표 1, §4.2) | **방향은 맞음, 원인은 분리되지 않음** | 데이터셋 2 합계 80 대 63(Q-Former, p = 0.012), 58(PolyTouch, p = 0.0012), 57(Sparsh-X, p = 7e-4)(`03` V4). 과제별로 구분되는 칸은 Board와 Gear 정도입니다. 세 기준선은 서로 구분되지 않습니다(57, 58, 63%). **Sparsh-X도 조건 토큰이 640개**(표 5)여서 "토큰이 많다"만으로는 57%와 80%의 차이를 설명하지 못합니다. 기준선 구조는 논문이 CNN 스템으로 다시 구현한 것이고(§4), 파라미터 수도 다릅니다(표 5의 Sparsh-X 29.2 M 대 24.5 M). 융합 방식, 층 수, 사전학습 여부의 차이가 함께 있습니다 |
| C7 | 센서 절제: 시각 + 멀티 촉각 모델이 가장 높고 이질 촉각 센서가 상보적 정보를 준다 (표 2, §4.2) | **맞음(데이터셋 1 한정), 과제별은 일부** | MiTaS V+G+E 80% 대 V+G 51%(p = 2.6e-5), Sparsh-X 54% 대 33%(p = 0.0042)(`03` V5). 과제별로 구분되는 것은 MiTaS의 Gear(+45%p)와 Lightbulb(+45%p)입니다. 이 절제는 데이터셋 2에 없습니다 |
| C8 | Evetac 단독 촉각은 일부 과제에서 유용하지만 "손 안 물체 위치가 필요하면 완전히 실패"한다 (§4.2) | **맞음(0%), 해석은 시험하지 않음** | V+E는 Gear 0/20, Key 0/20(표 2). 같은 스템의 시각 전용(ViT-CNN)은 Gear 8/20이어서 Evetac를 더한 모델이 낮습니다(p = 0.0033). Lamp(13/20 대 4/20), Lightbulb(8/20 대 0/20)에서는 높습니다(`03` V5). "손 안 위치가 필요해서"라는 설명은 시험하지 않은 해석입니다 |
| C9 | MTD가 MiTaS의 3/5 과제, Sparsh-X의 2/5 과제에서 성능을 높인다 (§4.2, 표 3) | **부호는 맞음, 효과는 구분되지 않음** | 과제별 부호는 표와 맞습니다. 개별로 구분되는 칸은 모델마다 하나(MiTaS Key −35, p = 0.048 하락 / Sparsh-X Board +35, p = 0.041 상승), 합계 변화는 +2(p = 0.89), +4%p(p = 0.66)(`03` V6). 드롭아웃 확률은 0.5 하나만 시험했습니다 |
| C10 | Key in Lock에서 MTD가 낮아지는 것은 "GelSight의 손 안 위치 특징을 교란하기 때문" (§4.2) | **근거 약함** | 시험하지 않은 설명입니다. 데이터셋 2의 MTD V+G는 Key 65%(13/20)로 데이터셋 1의 같은 모델(20%, 4/20)과 p = 0.0095로 다릅니다. 한 데이터셋 한 번의 결과로 특정 과제에서의 기전을 말하기 어렵습니다(`03` V6, V7) |
| C11 | MTD는 "반응성이 작은 섭동에 중요한 과제"에서 시각촉각 정책을 개선한다 (기여 2) | **방향만** | 어떤 과제가 이 부류인지 정의가 없습니다. 본문은 Board Wiping에서 두 모델이 모두 올랐다고 짚는데(+15, +35%p) 구분되는 것은 Sparsh-X의 칸 하나입니다(`03` V6). 사후적 분류에 가깝습니다 |
| C12 | MTD 모델에서 추론 때 Evetac를 쓰면 성능이 약간 오른다 (§4.2, 부록 A.8) | **방향만** | 표 10: V+G+E 63/100 대 V+G 60/100, p = 0.77(`03` V6) |
| C13 | 어텐션 분석이 다중 해상도 가설을 "검증"하고, Evetac는 표현을 주도하지 않지만 결정적 단계에서 관련 특징을 제공한다 (§4.3, 그림 5, 9) | **방향만** | 성공 에피소드 과제당 1개입니다. 판독한 모달리티별 평균 어텐션은 Evetac 0.11–0.28로, 토큰 수에 비례한 균등 몫 0.30보다 낮고 접촉 구간에서 일시적으로 오릅니다(`03` K1, `own_attention.png`). 어텐션은 입력 중요도의 인과적 지표가 아니고 층·헤드·평균 방식이 적혀 있지 않습니다. 센서 제거 절제(C7)가 더 직접적인 증거입니다 |
| C14 | "프레임 방식 촉각 센서와 이벤트 방식 촉각 센서를 결합한 첫 연구" (§1, §3) | **확인 불가** | 인용된 문헌 안에는 직접 대응하는 연구가 없습니다(`02` §4). 이 분석은 인용 밖으로 검색을 넓히지 않았습니다 |
| C15 | 시연 30개만으로 높은 성공률. 두 데이터셋을 합친 비교가 "더 견고하다" (§4.2) | **방향만, 데이터셋 이질성 주의** | 데이터셋 1의 시연 수 30은 일관되게 서술되지만 데이터셋 2의 시연 수는 적혀 있지 않습니다(공개 파일은 세션당 31–33개, §1). 25칸 중 5칸이 데이터셋 사이에서 구분되고 대부분이 Key in Lock입니다. 합치면 시행 수는 늘지만 학습 실행 변동은 같은 칸을 두 번 평균해도 칸 수만큼만 줄어듭니다(`03` V7, K4) |
| C16 | "다중 해상도 촉각 데이터셋"을 기여로 제공 (기여 3) | **맞음(공개 확인), 대응 서술 부족** | Hugging Face에 5개 과제 데이터가 있고 카드 라이선스 태그는 CC BY 4.0입니다(§1). 논문의 두 데이터셋과 세션의 대응, 추가 세션(`session_ut_texas`, `lamp_install_dual_gelsight`)의 용도는 서술이 없습니다 |
| C17 | 모델 크기와 추론 속도(표 5): 센서를 더해도 추론 시간이 작게 늘고 모든 모델이 같은 머리(13,701,508)를 쓴다 (부록 A.2) | **산술은 맞음, Hz 열은 정의 불명** | 9행 모두 인코더 + 머리 = 총합이 맞고, MiTaS 인코더는 센서별 스템의 합과 정확히 같습니다. 보고된 Hz는 1000 / ms의 약 7.9–8.4배입니다(`03` V8). 토큰 수에는 설명 없는 +4가 있습니다(`03` K1) |

## 3. 저자 확인이 필요한 항목

1. 표 5의 Hz 열 정의(1000 / ms와 약 8배 차이, `03` V8).
2. N_cond = 644에서 센서 토큰 640개 외 4개의 정체와 어텐션 분석에서 이 4개의 처리(`03` K1).
3. Evetac 16프레임과 0.06 s 표본화 창의 관계(`03` K2).
4. 논문의 데이터셋 1, 2와 공개 세션의 대응, 데이터셋 2의 시연 수, `session_ut_texas`와 `lamp_install_dual_gelsight`의 용도(§1).
5. 학습 에폭이나 스텝 수, 모델 선택 기준, 학습 시드 수, 평가 초기 상태의 선택과 모델 사이 공유 여부.
6. 융합 트랜스포머의 깊이와 헤드 수, 스템의 채널과 커널.
7. Sparsh-X 기준선의 사전학습 사용 여부(본문은 "pretrained 모델 대신 CNN 스템"이라고 PolyTouch와 연결해 적음)와 PolyTouch, Q-Former의 정확한 구성.
8. 어텐션 분석의 층, 헤드, 평균 방식과 그림 9, 10의 에피소드·시간 단위(`03` K1).
9. "Sparsh-X는 키를 한 번도 완료하지 못했다"(C4)가 가리키는 모델과 세션.

## 4. 구현 가능성 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**판정: 논문의 성공률 재현은 불가능합니다(실로봇 평가). 구조 재구현은 이 맥에서 가능하고, 공개 데이터로 한 오프라인 학습·평가는 데이터 다운로드 승인 후 조건부로 가능하지만 성공률의 대리 지표로는 약합니다. 공식 코드가 없어 정적 대조와 체크포인트 검증은 지금 할 수 없습니다.**

|---|---|---|---|

**노력 추정(측정 전).** 구조 재구현과 파라미터·지연 측정은 3–5일. 공개 데이터 로더와 오프라인 학습 루프는 1–2주(다운로드 승인과 HDF5 구조 확인 포함). 오프라인 절제 한 세트(V, V+G, V+E, V+G+E, MTD)의 학습 시간은 미측정입니다. 이 맥의 MPS에서 입력 640개 토큰, 배치 64, DiT 10층의 한 단계 속도를 먼저 재야 합니다.

**한계.** 오프라인 행동 예측 손실이 낮다고 폐루프 성공률이 높은 것은 아닙니다. 접촉이 많은 과제에서는 분포 이동(자기 롤아웃이 만드는 상태)이 성공을 가르기 때문에, 오프라인 결과는 "구조가 학습되는지"와 "센서별 정보가 있는지"에는 쓸 수 있어도 논문의 성공률 순서를 검증하지는 못합니다.
