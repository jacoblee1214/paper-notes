# 04. 논문 ↔ 공식 코드 대조 (π0)

대상: 논문 arXiv:2410.24164 v4(2026-01-08, 최신)와 공식 저장소 `Physical-Intelligence/openpi`(Apache-2.0), 커밋 `215abfb`(2026-08-25 클론 시점의 HEAD, 마지막 push 2026-08-24). 클론은 `repo/`에 얕게 받았고(`--depth 1`), **실행, import, 설치, 가중치 다운로드는 하지 않았습니다.** 읽은 파일은 `src/openpi/models/pi0.py`, `pi0_config.py`, `gemma.py`(get_config), `model.py`(IMAGE_RESOLUTION), `models_pytorch/pi0_pytorch.py`, `training/config.py`, `training/optimizer.py`, `examples/libero/main.py`입니다.

이 저장소는 **π0의 모델 구조와 학습·추론 코드(JAX, PyTorch 포팅)와 base 체크포인트의 설정**을 공개합니다. **사전학습 데이터 혼합, 사전학습 코드, π0-small, 실로봇 평가 코드는 공개되지 않았습니다.** 그래서 대조는 "모델 수식과 구조"에 집중되고, 학습 레시피(§3)는 빈칸으로 남습니다.

## 2. 차이와 빈칸 (D1–Dn)

**D1. 시간 방향 반대 (의미는 같음).** 논문은 τ=0 잡음, τ=1 데이터, 코드는 t=1 잡음, t=0 데이터입니다(`pi0.py` 226–227 주석: "this is the opposite of the pi0 paper, and I'm sorry"). 변환 $t=1-\tau$를 대입하면 보간, 목표, 적분 방향이 모두 맞습니다. 재구현할 때 한쪽으로 통일하지 않으면 위치 임베딩과 시간 분포를 뒤집는 실수가 생깁니다.

**D2. 행동 차원 32 대 18.** 논문은 가장 큰 로봇(양팔 + 이동 베이스 + 토르소)의 18차원으로 패딩한다고 씁니다. 공개 설정은 32차원 고정입니다(`action_dim=32`). 공개 체크포인트가 32차원으로 학습됐는지는 코드만으로 확인할 수 없고, 논문의 18은 사전학습 데이터 기준이고 공개 설정은 다른 임베딩 크기를 쓴다는 뜻으로 읽었습니다. 확정하려면 체크포인트의 입력 가중치 형상을 봐야 합니다(미확인).

**D3. 손실 스케일.** 논문은 제곱 노름(행동 차원에 대한 합)이고, 코드는 행동 차원 평균입니다. 32 대 신 차원이면 상수가 32배 다릅니다. 학습률과 상호작용하므로 같은 학습률을 가정하면 안 됩니다.

**D4. 상태 토큰의 위치.** 논문은 상태 $q_t$가 자기 블록이라고 씁니다. 코드도 상태를 접미 시퀀스의 첫 토큰으로 넣고 `ar=True`로 둡니다(157). 어텐션 결과는 같지만, 추론 KV 캐시는 상태가 행동 토큰보다 앞에 놓여 있다는 전제 위에서만 맞습니다. 논문 App. D의 "접두부 KV 캐시"와 일치합니다.

**D5. 입력 해상도와 토큰 길이 (논문 무기재).** 이미지는 224×224로 리사이즈합니다(`model.py` 47). 최대 프롬프트 토큰 길이는 48입니다(`pi0_config.py` 38–39). 논문 본문과 부록에는 둘 다 없습니다.

**D6. 정규화 (논문 무기재).** π0 경로는 z-score 정규화를 씁니다(`training/config.py` 187: `use_quantile_norm = model_type != PI0` → π0이면 False). 분위수 정규화는 π0.5 경로입니다. 논문은 상태와 행동의 정규화를 설명하지 않습니다.

**D7. 실행 청크 길이.** 논문은 20 Hz 로봇에서 16 스텝, 50 Hz 로봇에서 25 스텝을 실행하고 재추론한다고 씁니다(App. D). 공개 LIBERO 예제는 `replan_steps=5`입니다(`examples/libero/main.py` 29, 146–148). 예제는 시뮬레이션용이고 실로봇 예제 설정(`examples/aloha_real`의 `action_horizon=25`)은 논문과 맞습니다. 즉, **재추론 빈도는 예제마다 다르며 논문 값을 기본으로 가정하면 안 됩니다.**

**D8. 시간 임베딩 상수 (논문 무기재).** `posemb_sincos`의 주기 범위는 4e-3에서 4.0입니다(`pi0.py` 161, `min_period=4e-3, max_period=4.0`). 논문 App. B는 "sinusoidal positional encoding [51]"이라고만 씁니다.

**D9. PyTorch 포팅.** `pi0_pytorch.py`는 같은 시간 분포(182–185)와 같은 구조를 포팅합니다. `pytorch_compile_mode` 기본값은 `max-autotune`입니다(`pi0_config.py` 35). 두 구현이 수치적으로 같은지는 확인하지 않았습니다(실행 금지).

**D10. 사전학습 재현 불가 (빈칸).** 공개물은 `pi0_base`(JAX 체크포인트)와 미세조정 설정입니다. 논문의 10,000시간 혼합, 데이터 가중치 n^0.43(§V-A), 태스크 정의, OXE 부분집합(OXE Magic Soup)은 코드에 없습니다. 직접 재현할 수 없습니다.

**D11. 학습 하이퍼파라미터 (논문 무기재).** 논문은 배치 크기, 학습률, 옵티마이저, 스텝 수, EMA, 기울기 제한을 쓰지 않습니다. 공개 미세조정 기본값은 다음과 같습니다.

- 배치 32, 학습 30,000 스텝, 체크포인트 간격 1,000 (`training/config.py` 506, 511, 516)
- AdamW, b1 0.9, b2 0.95, eps 1e-8, weight decay 1e-10, 기울기 노름 제한 1.0 (`optimizer.py` 66–74)
- 코사인 스케줄, 워밍업 1,000, 최고 학습률 2.5e-5, 끝 2.5e-6, 감쇠 30,000 (`optimizer.py` 16–30)
- EMA 0.99 (`config.py` 490). `pi0_libero`는 이 기본값을 씀 (`config.py` 653–680 부근)

이 값은 공개 미세조정 설정이며 논문의 사전학습 또는 실험 설정과 같다는 근거는 없습니다. 논문 v4는 700k 스텝 사전학습과 160k 패리티 실험을 말하지만(§VI-A), 이 설정 중 어느 것도 확인되지 않습니다.

**D12. π0-small (재현 불가).** π0-small(470M, DistilBERT, ResNet-ViT 하이브리드, 교차 어텐션, DiT의 AdaLN-Zero, App. C)은 코드에 없습니다. 따라서 §VI-B, C의 "VLM 초기화 효과" 비교는 외부에서 확인할 수 없습니다.

**D13. 평가 코드 (공개 안 됨).** 논문 표와 그림의 점수 루브릭(App. E)은 설명만 있고, 채점 코드, 시도 로그, 시험 수 기록이 없습니다. 이 저장소로는 Fig. 7, 9, 11, 13을 다시 만들 수 없습니다(`03_analysis.md`).

## 4. 구현 가능성 (코드 기준)

이 맥(Apple M4 Pro, 24 GiB, MPS, CUDA 없음)에서 나눠 보면 다음과 같습니다. 판정은 코드를 읽은 결과이고, 실행으로 확인한 것은 없습니다.

- **모델 구조와 흐름 매칭 손실의 재구현:** 가능. 공개 코드가 명확하고 수식이 짧습니다. 전체 3.2B 모델 대신 `gemma_*` 차원을 줄인 소형 설정(`dummy` 변형이 코드에 있음, `gemma.py` 60–67)으로 CPU 검증이 가능합니다. 다만 설치(JAX 또는 PyTorch)와 코드 실행은 실행 승인이 필요합니다.
- **추론(3.2B, bf16):** 메모리는 약 6–7 GB로 24 GiB에 들어갑니다. 그러나 속도와 정확도는 측정하지 않았습니다. 논문 Table I은 RTX 4090 기준이고, 이 맥에서 MPS 경로가 같은 수치를 내는지는 모릅니다. JAX 경로는 Apple GPU를 쓰지 못할 가능성이 있어 확인이 필요합니다(추정).
- **미세조정(전체 모델):** 불가. 3.2B 파라미터의 학습 상태는 이 맥의 메모리를 넘습니다(추정). 고정(freeze) LoRA 설정(`pi0_libero_low_mem_finetune`)도 CUDA 기기를 전제로 합니다.
- **사전학습 재현:** 불가. 데이터와 혼합이 공개되지 않았고, 규모(10k시간)가 맞지 않습니다.
- **실로봇 평가:** 불가. 하드웨어와 데이터가 필요합니다.
- **노력(추정):** 구조 재구현과 CPU 검증은 2–4일, 공개 체크포인트로 추론 파이프라인 재현은 1–2주(장비와 경로 확인 포함), 미세조정은 CUDA 기기 확보가 전제입니다.

## 5. 저자에게 물을 질문 (정리)

1. 공개 체크포인트의 행동 차원은 32인지 18인지, 패딩 규칙은 무엇인지.
2. 논문 App. D의 재계획 16/25 스텝과 공개 예제의 5 스텝이 다른 이유.
3. 사전학습의 배치 크기, 학습률, 스텝, EMA 설정.
4. 시간 임베딩 주기 4e-3–4.0의 선택 근거.
5. 표 3 같은 평가에서 시도 수와 객체 수의 정의(`03` §1).
