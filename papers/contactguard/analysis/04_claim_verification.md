# 04. 주장 대조 (공식 코드 없음)

공식 코드와 프로젝트 페이지를 확인하지 못해(2026-11-26, `02` §4) 논문 ↔ 코드 대조(D 항목) 대신 **주장 C1–C16을 표, 본문과 대조**했습니다. 수치 재계산은 `03`(V 항목)에 있고, 이 문서는 각 주장이 어떤 증거로 얼마나 뒷받침되는지를 적습니다. 판정 표기: **일치**(표와 본문이 같고 해석에 이견 없음), **부분 지지**(방향은 맞으나 크기나 범위가 제한), **미검증**(자료가 없어 판정 불가).

## 2. 평가 설계와 정보 흐름에서의 점검

1. **임계값 선택.** τ는 검증 분할에서 방법마다 Youden-J로 고릅니다(표 7). 시험에서 방법 간 정밀도, FAR 비교는 같은 작동점이 아닙니다. AUC는 임계값 무관이어서 방법 비교의 주 지표로 적합하나 N = 50에서 구간이 넓습니다.
2. **라벨 정의.** 성공/실패는 파지 시도마다 수동으로 붙이고(그림 2, 3), 평가 시에는 5초 정지 후 재개한 결과가 라벨이 됩니다(§4.1). 정지가 결과에 주는 영향(물체가 움직이지 않는 사전 접촉 상태에서의 정지)은 "통제된 반사실 대리"라는 저자의 가정입니다.
3. **트리거 조건.** 모니터는 정책의 그리퍼 닫힘 명령 전이를 찾는 순간만 활성화됩니다(§3.5). 닫힘 명령이 없는 실패(접근 중 충돌)는 대상이 아닙니다. 표 7은 트리거가 켜진 시도만 셉니다(§4 서두: "All metrics evaluate the predictor's decision at the triggered pre-contact state, not the trigger itself").
4. **다중 비교.** 한 표본(과제당 50개)에서 표 1, 2, 3, 4, 6, 7의 많은 비교를 하며 보정이나 신뢰구간이 없습니다.

## 4. 구현 가능성 판정 ("구현할 수 있는지")

**이 맥(Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음)에서 모델 자체는 구현해 돌릴 수 있습니다. 논문의 수치를 재현할 수는 없습니다. 공식 코드와 데이터가 없고, 실로봇이 필요합니다.**
