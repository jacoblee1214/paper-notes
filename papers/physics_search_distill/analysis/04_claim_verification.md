# 04. 주장 검증 (공식 코드 없음)

공식 코드와 프로젝트 페이지를 찾지 못했으므로 `04_code_verification.md`(논문 ↔ 코드 대조)는 만들지 않았습니다. 대신 **논문 안의 주장을 표·부록 수치와 대조**하고, 실행 가능성을 판정했습니다 (`02` §4, 검색 결과 참조).

판정 기호: **일치** (재계산 또는 본문과 표가 맞음), **일치(반올림)**, **확인 불가** (필요한 자료가 공개되지 않음), **주의** (맞지만 해석에 조건이 붙음), **소수 불일치** (본문 값과 정수 계산의 차이가 작음).

## 2. 차이를 만드는 조건 (해석 주의)

1. **정보 차이 (C4):** PGSD는 지도와 ego 상태, 실행 모델을 더 씀. 표 1의 "단일 시점 최고" 주장은 **센서 입력만 같다는 조건**에서만 맞습니다. 실행 검증 정보 자체가 이득의 원인일 수 있습니다. 논문이 이를 분리한 실험은 없습니다 (EAS 선택만의 이득 +1.4가 가장 가까운 대조).
2. **기준선 재현 (C18):** v2에서 WorldDrive를 다시 돌렸습니다. 같은 설정이 아니면 격차가 달라질 수 있습니다.
3. **목표 선택 효과의 범위:** 목표 선택 실험은 **241개 개발 참조 한 세트**에서 얻었습니다. NAVSIM 12,146 장면 전체에서 확인된 것이 아닙니다.
4. **검정 부재 (C12):** 주 결과 표에 구간이 없습니다. 0.56점 차이는 독립 가정에서 대체로 유의할 것으로 보이지만, 세션 묶음 구조를 반영하면 실효 표본이 줄어듭니다.

## 3. 주장 대비 증거 요약

- **강하게 뒷받침:** 목표 선택이 수락을 높인다 (C8–C10). 롤아웃 비용이 크게 줄어든다 (C6, C14). 구조 파라미터가 맞다 (C16).
- **조건부로 뒷받침:** 단일 시점 SOTA (C3, C4, C18). NAVSIM 점수 개선 (C12). 보유율 73.2% (C7).
- **검증 불가:** 학습 하드웨어와 재현 설정 (C17), 교사-학생 공유 규칙 (C27), 정성 사례 (C29).

## 4. 구현할 수 있는지 (판정)

**판정: 논문 수치의 전체 재현은 이 맥에서 불가능합니다. 핵심 알고리즘의 축소판 구현은 가능합니다.**

이 맥은 Apple M4 Pro, 약 24 GiB 메모리, MPS 가속, CUDA 없음입니다.

| NAVSIM v1 navtest 12,146 장면 PDMS | NAVSIM 데이터 (OpenScene 파생, 크기 미확인), 플래너 체크포인트, devkit | 데이터와 체크포인트 다운로드가 금지 범위. 이번 분석에서는 받지 않음 | **불가** (지금 조건에서) |

**축소판 구현 노력 (추정, 미측정):** 2D 도로 다각형, 자전거 모델, LQR 추종, 여유 계산, EAS, SRV, CAST 탐색, 목표 선택 비교까지 약 300줄 규모의 numpy 코드. 3–5일. 실제 NAVSIM 수치와 비교할 수는 없습니다.

**전체 재현 노력 (추정):** 데이터와 체크포인트 준비 1–2주, 장면별 평가 수 시간에서 하루 (GPU 기준). 이 맥에서는 메모리와 추론 시간을 먼저 확인해야 합니다.

## 5. 저자에게 물을 것 (이 분석이 확인하지 못한 것)

5. 실행 피드백 제거 실험의 입력별 분리 결과 (논문은 세 입력을 묶어서 뺌).
