## 1. Abstract (한 줄 요약과 주장)

**한 줄 요약:** 학습된 정책 없이, VLM(Gemini Robotics-ER 1.6)이 지시를 원자 과제로 나누고 각 시점 이미지에 2D 키포인트를 찍으면, 보정된 4개 RGB 카메라의 시점 쌍 삼각측량과 재투영 합의로 3D로 올린 뒤, 파지 생성기와 팔-손 모션 생성기로 dexterous hand(Inspire)가 실행하는 zero-shot 시스템입니다.

논문이 내세우는 기여는 세 가지입니다(Sec. I).

1. VLM 과제 계획 + 다시점 3D 그라운딩 + 재사용 가능한 원자 동작 라이브러리를 묶은 zero-shot long-horizon dexterous 조작 프레임워크
2. 시점별 2D 예측을 교차 시점 합의 삼각측량으로 3D에 올리는 다시점 VLM 그라운딩. 가림과 부분 가시성에 강건하다고 주장합니다
3. 같은 그라운딩이 실행의 두 부분을 모두 맡는다는 점. 키포인트는 저장된 6D 도구 궤적을 장면에 맞추는 대응점이 되고, 파지 키포인트는 기능적 3D 어포던스 영역으로 확장됩니다

헤드라인 수치는 세 개입니다. 반복성이 MOKA의 단일 RGB-D 역투영보다 3배 이상 좋고(σ 2.5 vs 8.1 mm), zero-shot 기준선(MOKA 0.40, ReKep 0.55)보다 성공률이 높으며(0.85), 100개 시연으로 미세조정한 VLA(GR00T 0.30, Being-H0 0.00)를 시연 없이 이깁니다(0.95).

## 2. Method

### 2.1 전체 구조 (Fig. 1, Eq. 1)

```
보정된 다시점 RGB I = {I_v} (4대, 스테레오 쌍 포함) + 지시 l
  │
  ├─ (A) 기준 시점 의미 그라운딩: VLM이 기준 시점 r, 모드 z ∈ {pick, tool}, 대상·도구·기술 범주 c를 고름 (Eq. 3)
  │       → 기준 시점에서 원시 동작열 Q_r = {(m_t, 2D 키포인트 + 텍스트 설명)} (Eq. 2, 4)
  │         m_t ∈ {grasp, apply_action, waypoint, release, hold}
  ├─ (B) 다시점 3D 올리기: 키포인트마다 각 시점에 다시 질의 → 시점 쌍 삼각측량 → 재투영 합의 최대 후보 (Eq. 5–6)
  ├─ (C) 물체 궤적 T_obj: pick-and-place는 현재 자세 → 경유점 → 놓을 곳(자세 유지),
  │       도구 사용은 Bag of Atomic Actions에서 기술 범주 c로 궤적을 꺼내 두 앵커로 정렬 (Eq. 7),
  │       끝점은 충돌 없는 가장 가까운 격자점으로 보정 (Eq. 8)
  ├─ (D) 파지·모션: 시점별 어포던스 박스 → 메쉬 꼭짓점 투표로 3D 어포던스 영역 (Eq. 9)
  │       → 원통 템플릿 또는 BODex 최적화로 파지 후보 → 물리 시뮬레이션으로 안정성 검사
  │       → 팔-손 모션 생성기(cuRobo v2 + Natural functional gradients)로 T_obj를 따라가는 궤적, 실행 가능성 η (Eq. 10)
  └─ (E) long-horizon: 실행 후 새 관측으로 VLM이 continue / retry / replan / done 결정, 텍스트 메모리 갱신 (Eq. 11)
```

### 2.2 다시점 3D 올리기 (Sec. III-B, Eq. 5–6)

키포인트마다 각 시점에서 VLM 예측 p̄_v를 받고, 시점 쌍 (a, b)마다 삼각측량한 후보 X_{a,b}의 지지 수를 셉니다.

```
S_tri(X) = Σ_v 1( ||π_v(X) − p̄_v|| ≤ ε_tri )        (Eq. 5)
(a*, b*) = argmax_{a<b} S_tri(X_{a,b}),  X* = X_{a*,b*}   (Eq. 6)
```

평균을 내지 않고 가장 넓게 합의된 후보를 고르므로, 한 시점이 가려져서 엉뚱한 곳을 가리켜도 버틸 수 있다는 설계입니다. v3 본문에는 ε_tri 값과 동률 처리 규칙이 없습니다. v1 부록 D.1은 ε_tri = 20 px(640×480)이고, 지지 수가 τ_tri = 0.5·M을 넘지 못하면 **reference-view ray voting**으로 대체한다고 적었습니다. v3에서는 ray voting이 방법에서 빠졌고, 합의가 실패했을 때 무엇을 하는지는 적혀 있지 않습니다(`04` C7).

### 2.3 물체 궤적 구성 (Sec. III-C, Eq. 7–8)

- **Bag of Atomic Actions:** 각 항목 A = (c, T, X^s, X^e)는 기술 범주, 도구 자세열 T ⊂ SE(3), 시작·끝 앵커를 저장합니다. 기록된 시연이나 VLMPose[45](같은 그룹)로 만든 궤적에서 오프라인으로 구축합니다. 붓기, 쓸기, 망치질, 웍 토스 네 가지가 예로 나옵니다(Fig. 2, v1 부록 A.2).
- **정렬 (Eq. 7):** 저장 앵커 (X^s, X^e)를 장면의 (X^app, X^term)에 맞추는 변환을 구하되, 회전을 미리 정한 축으로 제한합니다. 대응점이 두 개뿐이라 일반 회전은 두 앵커를 잇는 축 둘레로 1자유도가 남기 때문입니다(`03` §3). 축척은 바꾸지 않으므로, 두 앵커 간 거리가 장면과 다르면 앵커에 잔차가 남습니다.
- **충돌 고려 끝점 보정 (Eq. 8):** 놓을 위치 주변 격자에서 침투 깊이 φ = 0인 가장 가까운 점을 고릅니다. v1 부록은 ±4 cm, 2 cm 간격, 연직 방향 우선입니다. 이 보정으로 모션 계획 성공이 7/10에서 10/10이 됐다고 보고합니다(Sec. IV-D).

### 2.4 파지와 모션 (Sec. III-D, Eq. 9–10)

- **어포던스 영역 (Eq. 9):** 시점마다 VLM이 잡을 수 있는 2D 박스 B_v를 그리고, 물체 **메쉬** 꼭짓점 q_i가 몇 개 시점의 박스 안에 투영되는지 비율 s(q_i)를 셉니다. s ≥ τ_aff인 꼭짓점이 영역입니다. v1 부록의 τ = 0.65는 4개 시점이면 3개 이상의 박스에 들어가야 한다는 뜻입니다. 가시성 검사가 없으므로 이는 박스 시야뿔들의 투표형 교집합(visual hull)입니다(`03` §4).
- **파지 생성:** 손잡이형 영역은 원통 템플릿(손바닥을 표면 법선 방향 0–3 cm 떨어뜨려 놓고 Dexonomy식 손가락 닫기), 일반 형상은 BODex[48]에 어포던스 거리·방향 항을 더한 최적화를 씁니다(v1 부록 B). 후보마다 시뮬레이션에서 여섯 축 방향 외력·토크로 안정성을 검사합니다.
- **모션:** 팔-손 모션 생성기[52, 53]가 파지 γ로 T_obj를 운반하는 궤적을 찾고, 기구학·충돌 제약을 만족하면 η = 1입니다. 가능한 쌍이 없으면 실패를 보고합니다.

### 2.5 long-horizon 확장 (Sec. III-E, Eq. 11)

VLM이 하위 과제 큐와 텍스트 메모리를 관리하고, 시도마다 새 관측을 보고 continue / retry / replan / done을 고릅니다. v3 실험은 하위 과제당 재시도 1회 예산이고, v1은 4회였습니다.

## 3. Experiments

### 3.1 설정 (Sec. IV-A, IV-B)

- **로봇:** Franka + Inspire 손(zero-shot 기준선 비교), xArm + Inspire 손(VLA 비교, 텔레옵 장비가 xArm에 있어서). 정성 결과는 둘 다 씁니다.
- **센서·인식:** 보정된 RGB 카메라 4대(스테레오 쌍 포함), FoundationStereo[43]로 깊이, FoundationPose[44]로 다중 물체 6D 자세입니다.
- **VLM:** 모든 질의에 Gemini Robotics-ER 1.6(medium thinking)을 씁니다. v1 부록에는 `gemini-robotics-er-1.6-preview`로 적혀 있습니다. v3는 "프롬프트는 보충 영상에 있다"고 적었고, 텍스트 원문은 v1 부록 D.2에 있습니다.
- **기준선:** MOKA[6](단일 RGB-D 시점에서 키포인트 역투영, 경유점 높이 선택지를 저자들이 늘려 줌), ReKep[32](공개 구현의 키포인트 제안과 제약 생성, 같은 실행 스택). 두 방법은 같은 파지·모션 스택을 써서 **그라운딩만 다르게** 했습니다. VLA는 GR00T[20], Being-H0[22]이고, 100개 텔레옵 pick-and-place 시연(약 1시간)으로 각자 공식 설정에 따라 사후학습했습니다(H = 16, 배치 64, LR 1e-4, 30k step, A6000 4장).

실패 단계(Table II, n=20): MOKA는 그라운딩 6, 파지 3, 실행 3이고, ReKep은 그라운딩 7, solver 2입니다. Ours는 파지 3뿐입니다.

해석 (재계산은 `04_claim_verification.md`, `analysis/table_check.py`):

- **표는 내부적으로 일관됩니다.** All은 두 조건의 평균이고, Table II의 실패 합(12, 9, 3)은 Table I의 실패 수와 정확히 맞습니다.
- **zero-shot 기준선과의 차이는 시행 수에 비해 확실하지 않습니다.** 전체 17/20 vs MOKA 8/20은 Fisher p = 0.008이지만, ReKep 11/20과는 p = 0.08입니다. 조건별(n = 10)로는 Cluttered에서 MOKA 대비(p = 0.02)만 5% 수준을 넘습니다. 모든 결과가 장면당 한 번의 시행이고, 시행별 짝 정보(같은 장면에서 둘 다 성공했는지)가 없어 대응 검정은 할 수 없습니다.
- **VLA와의 차이는 큽니다**(19/20 vs 6/20, p = 4×10⁻⁵). 다만 성격을 봐야 합니다. 두 VLA 모두 목표에는 거의 항상 다가가고(0.95, 1.00), **잡기에서 실패합니다**(0.35, 0.05). GR00T는 잡은 7번 중 6번을 성공했습니다. 즉 이 비교는 "VLA가 1시간 시연으로 새 dexterous 손의 파지를 배우지 못한다"는 결과에 가깝습니다. 과제도 하나(Throw Away Trash)뿐입니다.
- **정보량이 다릅니다.** ZeroDex는 보정된 카메라 4대, FoundationStereo·FoundationPose, 물체 메쉬, 파지 시뮬레이션, 충돌 고려 모션 계획을 씁니다. VLA는 이미지 1–2개만 봅니다. 저자들은 "같은 xArm, 같은 장면 목록, 같은 성공 기준이라 matched"라고 썼지만, 입력과 사전 정보는 같지 않습니다.

### 3.3 3D 그라운딩 품질 (Table IV)

| | σ (mm) | δ_max (mm) | | P_max | P_avg | Coll% | IK% |
|---|---|---|---|---|---|---|---|
| MOKA | 8.1 | 64.9 | Tool (5 장면) | 20.4 | 20.4 | 20 | 30.3 |
| **Ours** | **2.5** | **3.9** | | 20.3 | **4.7** | **5** | **35.0** |
| (10 장면 × 8회) | | | P&P (10 장면) MOKA | 37.2 | 36.3 | 100 | 24.2 |
| | | | **Ours** | **32.6** | **16.3** | **17** | **37.2** |

- **"3배 반복성"은 맞지만 한 장면에 크게 좌우될 수 있습니다.** 8.1 / 2.5 = 3.24입니다. 그런데 δ_max가 "장면별 σ의 최댓값"이라면, MOKA의 나머지 9개 장면 σ 평균은 1.79 mm로 Ours(2.5)보다 오히려 작습니다. δ_max가 "한 실행의 최대 이탈"이라면, 그 장면의 σ는 24.5 mm 이상이고 나머지 9개 평균은 6.3 mm 이하입니다(`04` C4b). 어느 해석이든 MOKA의 평균은 이상치 장면이 끌어올렸습니다. 장면별 중앙값을 함께 보고했어야 합니다.
- **침투 지표도 소수 장면이 지배합니다.** 비충돌 waypoint를 1 mm 이하로 보면 P_avg, Coll%, P_max가 동시에 성립하기 위한 최악 장면의 P_max 하한을 계산할 수 있습니다. MOKA 도구 행은 5개 장면 중 한 장면이 약 9.5 cm 이상 침투해야 하고(P_max 질량의 94%), Ours 도구 행도 6.7 cm 이상인 장면이 하나 있어야 합니다. Ours P&P도 8.8 cm 이상인 장면이 있어야 합니다(`04` C4). Tool 행의 차이는 사실상 "같은 실패 장면에서 몇 개의 waypoint가 충돌하는가"의 차이입니다.
- **IK%는 여전히 낮습니다.** Ours도 도구 35%, P&P 37%입니다. 파지 후보 셋 중 둘은 기구학적으로 실행할 수 없습니다.
- ReKep은 목표가 범위(예: 키포인트 위 5–10 cm)로 주어져서 이 지표에서 제외했다고 설명합니다.

괄호는 재시도 없음입니다. 단계별 분모가 이전 단계의 성공 수와 정확히 이어집니다(`04` C5). 재시도 1회로 End-to-End가 6/10 → 8/10, 9/10이 됩니다. 남은 실패는 팔 관절 한계와 환경 충돌이라고 보고합니다. n = 10이라 Wilson 구간은 8/10이 [0.49, 0.94], 6/10이 [0.31, 0.83]으로 겹칩니다.

### 3.6 실행 시간

다시점 그라운딩 한 번에 19.4 s(기준 시점 6.7 + 시점별 질의 4개 9.6 + 삼각측량 3.1, 합이 맞음)이고, 팔-손 모션 생성에 4.8 s(장면 구성) + 9.4 s(계획)가 듭니다. 파지 시뮬레이션 검증 시간은 후보 수에 비례해서 보고하지 않았습니다. 하위 과제 하나에 파지 검증을 빼고도 약 34 s입니다. 키포인트가 3–4개면 VLM 질의는 하위 과제당 약 19–23회로 추정됩니다(`04` C6).

## 4. Limitations

### 4.1 저자가 밝힌 한계 (Sec. V)
2D VLM의 추론 신뢰도가 상한을 정합니다. 외부 팔-손 모션 생성기의 특이점, 충돌 검사 시간 초과, 불안정한 파지로 실패할 수 있습니다. Bag of Atomic Actions에 없는 도구 동작은 바로 실행할 수 없습니다(다만 라이브러리는 확장 가능한 캐시라고 설명합니다). 변형 물체와 손 안 조작(물체 돌리기, 가위)은 다루지 않습니다.

### 4.2 분석하면서 추가로 발견한 한계와 의문점
1. **물체 메쉬가 필요하다는 가정이 본문에 드러나 있지 않습니다.** Eq. 9의 어포던스 영역은 "물체 메쉬의 꼭짓점"으로 정의되고, FoundationPose 자세 추정, 침투 깊이 φ, BODex 파지 최적화, 파지 안정성 시뮬레이션도 모두 메쉬가 있어야 합니다. 그런데 메쉬를 어디서 얻는지(스캔, CAD, 복원)는 v1, v3 모두 적혀 있지 않습니다. "처음 보는 물체로 zero-shot"은 학습 없이라는 뜻이지, 메쉬 없이라는 뜻이 아닙니다.
2. **v1 → v3 사이에 실험이 거의 다시 만들어졌습니다**(`04` C7). 핵심 기여였던 ray voting이 빠졌고, 기준선이 바뀌었으며(단일 RGB-D → MOKA, ReKep), VLA 시연이 과제당 30개 → 100개로 늘었습니다. 시행 수도 과제당 5 → 조건당 10으로 늘었고, long-horizon 성공률은 4/6, 1/3에서 8/10, 9/10으로 올랐습니다. 프로젝트 페이지 초록은 아직 ray voting을 설명합니다. 개선 자체는 좋지만, 어떤 변경이 수치를 바꿨는지는 추적할 수 없습니다.
3. **v1에서는 다시점 그라운딩의 침투 개선이 없었습니다.** v1 Table 3은 침투 오차가 RGB-D 9.91, Ours 9.81로 거의 같았습니다. v3 Table IV의 Coll% 100 vs 17은 지표 정의와 기준선이 바뀐 뒤의 결과입니다. 같은 현상을 다른 지표로 재본 것인지 판단할 근거가 본문에 없습니다.
4. **합의 규칙이 덜 명시되어 있습니다.** ε_tri 값, 동률 처리, 합의 실패 시 동작이 v3에 없습니다. toy에서 Eq. 6을 그대로(동률이면 첫 쌍, 재적합 없음) 구현하면 기선이 짧은 스테레오 쌍을 골라 꼬리가 매우 길어집니다. inlier 전체로 다시 삼각측량하면 이 꼬리가 사라집니다(`03` §2). 구현에 따라 결과가 크게 달라질 수 있는 부분입니다.
5. **4개 시점에서 버틸 수 있는 이상치 시점은 하나입니다.** toy에서 VLM이 엉뚱한 곳을 가리킨 시점이 1개면 합의가 강건하지만(중앙값 7 mm), 2개면 꼬리가 커지고(p90 약 10 cm), 3개면 실패합니다. "가림에 강건"은 4개 중 3개 시점이 같은 곳을 가리킨다는 조건에서만 성립합니다.
6. **폐쇄형 VLM 의존성:** Gemini Robotics-ER 1.6 preview 버전에 묶여 있습니다. 모델이 바뀌거나 내려가면 같은 결과를 재현할 수 없고, v3는 프롬프트를 영상으로만 제공합니다.
7. **통계 정보가 부족합니다.** 모든 성공률이 n = 10–20의 단일 시행이고, 신뢰구간이 없습니다. ReKep 대비 전체 우위도 p = 0.08입니다.
8. **느립니다.** 하위 과제마다 30초 이상 걸리고(파지 검증 제외) VLM 호출이 약 20회입니다. 닫힌 루프 반응 제어는 아니며, 저자들도 반응형 저수준 정책 결합을 향후 과제로 남겼습니다.
