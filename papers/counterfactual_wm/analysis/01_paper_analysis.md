## 1. 한 줄 요약

관측 결과 하나가 있으면, 같은 외란을 가정한 다른 행동의 결과를 **관측값 + (사실 세계모델이 예측한 행동 차이)** 로 추정하는 "잔차 전달(residual reuse)" 규칙을 제안합니다. 사실 데이터만으로는 개별 반사실이 식별되지 않음을 증명하고(§2.2), 행동과 외란이 별도 힘 채널로 들어가는 짧은 물리 전이에서 이 규칙의 오차가 O(h²)임과 그 속도가 최소최대(minimax)에서 최적임을 보입니다(§3, Thm 3.4, 3.6). 실험은 렌더링된 시뮬레이터 5종(주 비교 HandReach, Ball-in-Cup, FetchReach, PassWater, BlueROV2)과 동결된 자기지도 인코더(DINOv2, MAE)에서 수행합니다(§4.2).

## 2. 방법: 식 (1), (6), (7), (8)

- 관측 `z_t = f(o_t)`, 사실 예측기 `µ(z_t, a)`. 관측 전이 `(z_t, a_t, z_{t+1})`에 대해
  `ẑ_{t+1}(a′) = z_{t+1} + µ(z_t, a′) − µ(z_t, a_t)` (식 1, 6).
- 읽기 헤드 `π`(물리량)를 쓰면 `π(z_{t+1}) + π(µ(z_t, a′)) − π(µ(z_t, a_t))` (식 7). 저자들은 이 "읽기 후 전달"이 "특징 공간 전달 후 읽기"보다 모든 환경에서 1.4–25.9 점 낫다고 보고합니다(§4.3, 표 5).
- 추가 학습, 추가 파라미터, 반사실 데이터가 없습니다. 예측기는 사실 전이만으로 학습합니다(식 31, 2층 1024 폭 Transformer 블록, §4.2).

핵심 질문은 "사실 예측기가 같은 외란의 다른 행동 결과를 알 수 있는가"입니다. 저자들은 알 수 없다고 답합니다(Prop. 2.1, Thm. 2.2, Thm. H.2). 따라서 잔차 전달은 **추가 가정**(행동과 외란이 별도 채널이고 전이가 짧다)에 기대는 방법입니다.

## 4. 실험 (수치 정리)

모든 R² 값은 물리 좌표 기준이며 시드 3개, 전체 부모 부트스트랩 95% 구간입니다(표 5, 6).

### 4.1 물리 근사 검증 (§4.1, 그림 3–4, 표 3–4)

- 관심 양 `ρ(a,a′) = tr Var(Y(a′)−Y(a)) / tr Var(Y(a′))`(§4.1). 작을수록 잔차 전달이 좋습니다.
- 작동 영역: 액추에이터 오프셋 `ρ ≤ 0.033`, HandReach 손끝과 BlueROV2 몸체 속도 `ρ ≤ 0.12`(표 3).
- 실패 영역: 접힌 피치 `cos(pitch)` `ρ = 1.666`, Push-T 블록 속도 `ρ = 1.49–1.89`. 이 경우 정확한 평균으로도 잔차 전달 R²가 음수입니다(표 3, 블록 `vx`–`ω`에서 5.6, −15.5, −44.4%).
- 오프셋에서 게인 고장으로 가는 보간(λ = 0, 0.5, 1): 측정 `ρ` 0.033 → 0.497 → 2.006(HandReach), 예측 0, 0.5, 2(표 4). 저자들의 평형 모형은 `ρ = 2λ²`와 같은 형태로 보입니다. 유도는 App. D에 있고 이 분석에서는 확인하지 않았습니다.

### 4.2 픽셀에서의 반사실 예측 (§4.2, 표 5, 6, 7, 8)

표 5 (MAE-B, 8k 사실 에피소드, 한 프레임):

| 환경 | 오라클(결과 없음) | 학습 예측기 | 특징 공간 전달 | 읽기 후 전달 |
|---|---|---|---|---|
| HandReach | 49.1 | 38.1 | 82.4 | 85.6 |
| Ball-in-Cup | 51.1 | 41.6 | 92.0 | 94.2 |
| FetchReach | 50.0 | 44.8 | 94.0 | 95.7 |
| Liquid transport (PassWater) | 50.6 | 42.1 | 82.3 | 94.8 |
| BlueROV2 (8k) | 51.8 | 31.1 | 47.7 | 73.6 |
| BlueROV2 (128k, 16배) | 51.8 | 47.4 | 72.2 | 93.5 |

- 초록의 "네 환경에서 38–46 → 86–96"은 이 표의 MAE-B와 DINOv2 값 범위와 맞습니다(`03` §3–§4).
- 다른 인코더 4종(DINOv3-B, SigLIP 2-B, CLIP-B, EVA-02-B)에서는 읽기 후 전달이 81.0–95.3%입니다(표 6, 같은 네 환경).
- 셔플 대조(다른 외란 추첨의 결과를 씀)는 −14.6–6.3%이고, 사실 결과 복사는 6.7–43.5%입니다(표 5 설명). 개선이 "복사"나 "예측기 개선"으로 설명되지 않는다는 주장의 근거입니다.
- 데이터 규모 (표 8): MAE-B, HandReach 819 → 6,553 에피소드에서 69.8 → 85.6. 같은 예측기는 그대로 두고 예측기 학습 데이터만 늘렸습니다.
- 기록 길이 (그림 8): 외란의 고정 성분이 늘면(무작위 비율 25 → 100%) 학습 예측기는 71.7 → 38.1, 반사실은 91.4 → 85.6입니다. 과거 프레임을 늘린 효과는 일관되지 않았습니다(−2.3 ~ +2.1 점).

### 4.3 조건과 한계 (§4.3, 그림 9–11, 표 9–11)

- 외부 하중(HandReach 손바닥)은 ρ ≤ 0.001로 잘 맞고 반사실 R²는 88.7%(MAE-B)입니다(그림 9).
- 공간적으로 빠르게 변하는 해류: 와류 파장 L이 줄면 `ρ`가 1/L²로 커져 L = 1.25에서 0.49입니다. 시간 변화(위상 속도)에는 영향이 작습니다(그림 10, 표 20).
- 픽셀 전달: 보트 그림에서 상호작용 비율이 2.13이고, 픽셀 공간 전달의 상대 위험은 5.86입니다. 특징 공간 전달은 0.31, 읽기 후 전달은 0.002입니다(§4.3 본문). 즉 **픽셀을 예측하는 세계모델에서는 이 규칙을 그대로 쓸 수 없습니다**.
- 게인 고장 λ = 1: 특징 전달 6.4–11.0%, 읽기 후 −11.8 ~ −12.8%로 학습 예측기(41–42%)보다 나쁩니다(표 11). 저자들은 이 셀이 외란 회복률 95% 기준을 못 넘었으므로 진단용이라고 씁니다.

### 4.4 계획 (§4.4, 표 15–17, 그림 11, 14–17)

- 한 번 계획(표 15): 반사실 모델 35–69%, 학습 예측기 9–25%, 오라클(결과 없음) 14–23%, 실제 외란을 아는 오라클 100%.
- 같은 사건 재시도(표 16): 세 번째 시도에서 반사실 51–97%, 예측기 9–24%.
- 3단계 재계획(표 17): 지속 고장에서 반사실 11–51%, 예측기 4–25%. 독립 외란에서는 −4 ~ +6 점, 외란이 없으면 −4 ~ −15 점입니다.
- 계획은 교차 엔트로피 탐색(후보 256, 엘리트 32, 4회 반복), 성공 기준은 표준화 거리 0.2 미만입니다(`repo/experiments/configs/planning/oneshot.json`과 일치).

## 5. 저자 주장과 근거의 간격

1. **"사실 데이터로는 개별 반사실을 알 수 없다"**: 증명으로 뒷받침됩니다(§2.2). 이 결과는 강합니다.
2. **"잔차 전달이 정확하다"**: 가법 세계에서만 정확합니다(Prop. 3.2). 실제 개선의 크기는 환경을 어떻게 설계했는지에 크게 의존합니다. 저자들은 시뮬레이터 외란을 **오라클 기준이 약 50%가 되도록 보정**했다고 씁니다(§4.1, 표 9의 게이트 "50 ± 8%"). 따라서 "38–46 → 86–96"의 크기는 벤치마크 설계의 영향을 받습니다. 기준선 자체가 설계된 값이라는 점을 독자가 알아야 합니다.
3. **"상태 라벨 없이도 된다"**: 특징 공간 전달(라벨 없음)은 73–94%입니다(§4.2). 그러나 BlueROV2에서는 특징 공간 전달이 46–72%로 낮고, 실제 개선은 상태 라벨로 학습한 읽기 헤드가 필요합니다. 초록의 "no counterfactual data" 주장은 맞지만, 라벨 없는 버전은 환경에 따라 약합니다.
4. **"계획에서 오라클보다 낫다"**: 오라클(결과 없음)은 기대 제곱거리를 최소화하는 계획이고, 임계 성공률의 상한이 아니라고 저자들도 씁니다(§4.4). 비교가 공정한 기준은 아닙니다. 실제 외란을 아는 오라클의 100%가 더 적절한 상한입니다.
5. **실로봇 결과 없음**: 모든 실험은 시뮬레이터입니다. 인코더를 통한 픽셀 처리는 있지만, 실제 카메라와 실제 외란의 검증은 없습니다.
6. **시뮬레이터 개수**: 초록은 "네 시뮬레이터 + 하나의 수중 차량"(다섯), 본문 §4.2와 그림 5는 "일곱 시뮬레이터", 공식 README도 "seven rendered simulators"입니다. 일곱은 Racetrack과 Push-T를 포함하고, 두 개는 진단용입니다. 숫자의 기준이 다르지만 모순은 아닙니다.
7. **"minimax 최적"**: 최악 경우 클래스에 대한 결과이며, 저자들도 이를 명시합니다. 실제 시스템에서의 최적성은 주장하지 않습니다.
