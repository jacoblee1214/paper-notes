핵심 요약

  1. 무엇을 하는가: ViViDex의 state-policy RL에서 PPO가 학습하던 행동 잡음 σ를 얼리고, 학습 step에 따라 0.20 → 0.04로 줄인다. 손실·구조·보상·최적화 설정은 그대로 두고, 결정론적 실행(σ_eval = 0)으로 비교한다. PPO, critic 없는 GRPO 연속 학습, flow 평균 PPO("FPO")에 적용했다.
  2. 표 수치는 모두 맞는다: Overall 평균, 8개 물체 평균, 본문 seed별 값, Table II·III·V·VII을 재계산하면 일치한다.
  3. 효과는 작거나 특정 물체에 몰려 있다: PPO는 +3.7%p(물체 2개 증가·2개 감소, seed 수준 p ≈ 0.39)다. GRPO 이득의 대부분은 설탕·토마토, FPO는 머스터드·토마토에서 나온다. seed 간 SD가 50%p를 넘는 칸도 있다.
  4. 기준선은 짧은 예산의 거의 고정된 σ다: 5M step은 ViViDex 기본 설정(1억 step)의 1/20이다. Adam(lr 1e-5)으로 log σ가 움직일 수 있는 폭은 약 0.98이라, 학습 σ는 원리상 0.04에 도달할 수 없다. 실제로는 0.202 → 0.185에 머물렀다.
  5. 공개 코드와 논문이 다르다: 공개 GRPO advantage는 Eq. 5(나이별 할인 reward-to-go)가 아니라 궤적 총 보상을 쓴다. HF 메타데이터는 grpo_rtg 모듈을 가리킨다. GRPO 연속 학습 스케줄도 코드에 없다. ViViDex 공개 환경의 목표 성공 기준은 3 cm가 아니라 5 cm다.
  6. 하드웨어 이득은 크지만 조건당 모델 하나다: 시행 단위로는 p < 10⁻⁴이지만, 학습 seed 분산은 검정에 들어가지 않는다.
  7. 구현 가능성: 스케줄 자체는 수십 줄이다. ViViDex 공개 환경에 callback을 붙이면 PPO 비교는 이 맥 CPU에서도 다시 만들 수 있어 보인다(설치 확인 필요). GRPO와 하드웨어 결과는 공개 자료로 재현할 수 없다.

우리 분석: 논문과 코드의 σ 스케줄, 그리고 학습 σ가 5M step 안에 갈 수 있는 범위(회색).

1. Abstract (한 줄 요약과 주장)

한 줄 요약: 사람 영상에서 얻은 손-물체 궤적을 RL로 다듬는 ViViDex의 state-policy 단계에서, PPO가 학습하던 행동 잡음 σ를 학습 step의 함수로 미리 정해 줄이는 것만으로 최종 결정론적 성공률이 오른다고 주장합니다. 손실, 구조, 보상, 최적화 설정은 쌍마다 그대로 둡니다.

논문이 내세우는 기여는 세 가지입니다(Sec. I).

  1. 탐색 잡음 스케줄이 세 가지 정책 최적화 설정(PPO, critic 없는 GRPO 연속 학습, flow 평균을 쓰는 PPO 변형 "FPO") 모두에서 결정론적 Target 성공의 평균을 올린다. 시뮬레이션과 실제 로봇 모두에서 그렇다.
  2. PPO 구성 요소 선별에서 "잡음 제어"가 "최적화기 수축"(학습률·clip·epoch 감소)보다 낫고, 고른 스케줄이 같은 끝점의 선형 감쇠보다 세 물체에서 평균이 높다.
  3. 학습 return, 결정론적 Target 성공, 실행 잡음 내성이 서로 어긋난다. 따라서 스케줄은 의도한 실행 조건에서의 최종 과제 성공으로, 과제·최적화 설정마다 따로 판단해야 한다.

2. Method

2.1 문제 설정 (Sec. III, Eq. 1–3)

ViViDex state-policy 단계: 영상에서 얻은 손-물체 궤적(DexYCB) → RL로 물체 재배치(relocation) 정책 학습
   (원래 ViViDex는 이후 visual policy로 증류하지만, 이 논문은 state policy까지만 다룸)

행동 정책  q_{θ,k}(a_t | o_t) = N( μ_θ(o_t), σ_k² I )        (Eq. 1)
   μ_θ : MLP(PPO, GRPO) 또는 flow로 만든 결정론적 평균(FPO)
   σ_k = σ(s_k) : 누적 환경 step s_k의 함수, 모든 행동 차원이 공유하는 스칼라
   rollout 수집과 모든 update epoch 동안 같은 σ_k → ratio의 분자·분모가 같은 σ를 씀   (Eq. 2)
PPO 목적함수: clipped surrogate                               (Eq. 3)

평가는 **결정론적 실행(σ_eval = 0)**을 기본으로 합니다. 학습 중 잡음 크기가 다른 두 조건을, 평가 때 잡음을 빼고 같은 규칙으로 비교하려는 설계입니다(Sec. I, V-A).

2.2 PPO + DexPolicy (Sec. IV-A, Eq. 4)

기준선 PPO는 ViViDex 설정 그대로 log σ를 학습합니다(초기 log σ = −1.60, 즉 σ ≈ 0.202). DexPolicy는 log σ를 얼리고 다음 곡선으로 정합니다.

σ(s) = 0.20 − 0.10·s/2M            0 ≤ s < 2M
       0.10 − 0.05·(s − 2M)/2M      2M ≤ s < 4M
       0.04                          s ≥ 4M

학습률 1e-5, clip 0.20, 5 epoch, 기울기 norm 상한 0.50은 그대로입니다. 곡선은 2M에서 연속이고 4M에서 0.05 → 0.04로 떨어집니다. 동기로 든 관찰은, 머스터드 기준선 세 실행에서 학습된 σ가 5M step 뒤에도 0.185–0.186에 머문다는 것입니다(Sec. I).

2.3 GRPO + DexPolicy (Sec. IV-B, Eq. 5)

value baseline 없이, 완료된 궤적의 할인 reward-to-go를 같은 에피소드 나이끼리 표준화한 것을 advantage로 씁니다.

G_{i,t} = Σ_{u=t}^{T_i−1} γ^{u−t} r_{i,u},   γ = 0.95
I_t = { j : T_j > t }  (나이 t에 도달한 완료 궤적)
Â_{i,t} = (G_{i,t} − mean_{j∈I_t} G_{j,t}) / (std_{j∈I_t} G_{j,t} + 1e-8)     (Eq. 5, |I_t| ≥ 2)

잘린 조각과 완료 궤적이 둘 미만인 나이는 advantage 0입니다. value loss, bootstrap, reference KL은 없습니다. 두 조건은 같은 물체·seed의 PPO 체크포인트(약 5M step)에서 출발합니다. 기준선은 물려받은 σ를 계속 학습하고, DexPolicy는 σ를 얼린 채 다시 키운 뒤 줄입니다(아래 3.3).

2.4 FPO + DexPolicy (Sec. IV-C)

MLP 평균 대신 조건부 flow를 씁니다. 0에서 시작하는 8단계 적분기가 정규화된 상태를 결정론적 행동 평균으로 바꿉니다. 그 위에 Gaussian likelihood와 PPO clip update를 그대로 씁니다. 논문도 밝히듯 McAllister et al.의 FPO[17]나 FPO++[18](flow matching 손실로 ratio를 만드는 방법)과는 다른 알고리즘입니다. 기준선은 σ = 0.10 고정이고, DexPolicy는 5M step에 걸쳐 0.20 → 0.05로 선형 감쇠합니다. 따라서 FPO 비교는 "PPO 곡선(Eq. 4)"이 아니라 선형 감쇠 대 고정 잡음 비교입니다.

3. Experiments

3.1 설정 (Sec. V-A)

  • 과제: ViViDex 다지 손 재배치, YCB 물체. 22차원 행동, 32개 학습 환경. 물체마다 정책을 따로 학습하므로 "물체 간 전이"는 정책이 아니라 스케줄 규칙의 전이입니다.
  • 스케줄 선별: 머스터드로 곡선을 고르고, 머그·바나나·설탕·피처·나무 블록에 다시 조정하지 않고 적용합니다.
  • 지표: Target(지정 접촉 + 최종 위치가 목표에서 3 cm 이내)이 주 지표이고 Lift(지정 접촉 + 높이 5 cm 초과)가 보조 지표입니다. 학습 곡선 쪽은 정규화 reward AUC, 접촉 비율, 들어 올린 높이를 진단용으로 봅니다.
  • 평가량: PPO·FPO는 체크포인트마다 확률적 100회 + 결정론적 100회입니다(체크포인트 96개, 19,200회). GRPO는 최종 모델마다 결정론적 200회, 확률적 200회, 공통 σ 0.03·0.10에서 각 100회입니다(모델 30개, 18,000회).
  • 통계: 평균과 seed 3개의 표본 SD만 보고하고, 유의성은 주장하지 않는다고 밝힙니다(Sec. V-B).

  • PPO의 이득은 작고 엇갈립니다. 다섯 물체 중 2개 증가, 2개 감소, 1개 동일이고, 8개 물체 평균은 seed 3개 중 1개에서만 올랐습니다(본문 Sec. V-B). seed 수준 Welch 근사 p ≈ 0.39입니다. "세 설정 모두에서 오른다"는 기여 문장은 평균 기준으로만 맞습니다.

3.3 GRPO 연속 학습과 잡음 내성 (Sec. V-C, Table II)

  • 연속 학습 설계: 두 단계로 507,904 step(학습률 1e-4)과 253,952 step(5e-5)을 더합니다. 둘 다 rollout 8,192의 정수배(62, 31)입니다. 토마토는 세 번째 단계(253,952 step, 3e-5)가 더 있습니다. DexPolicy 쪽은 σ를 0.20으로 다시 키운 뒤 0.20 → 0.10 → 0.03으로 줄입니다. 토마토 세 번째 단계는 0.10에서 0.02로 줄입니다. 그래서 이 개입에는 잡음 재확대, 얼림, 감쇠가 함께 들어 있고, 논문도 이 셋을 분리하지 못했다고 밝힙니다(Sec. VI).
  • 개발용 seed: 원래 네 물체에서 seed 0은 개발에 썼고 seed 1, 2가 재현입니다. seed 0을 빼도 다섯 물체 평균은 15.3 → 37.2%로 오릅니다. Table II의 seed 1/2 행 평균 차이(+21.9%p)와 일치합니다.
  • 머스터드는 뒤집힙니다. seed 1/2에서 46.25 → 1.75%입니다. 머스터드의 평균 이득은 seed 0(0 → 100%)이 만든 것입니다.
  • 잡음 내성: 공통 σ_eval = 0.03이면 14.8 → 41.8%로 이득이 유지됩니다. 0.10이면 16.1 → 8.7%로 뒤집힙니다. 작은 σ로 학습한 정책은 결정론적 성공은 높지만 큰 실행 잡음에 약합니다. 논문의 세 번째 기여(지표 해리)의 핵심 증거입니다.

4. Limitations

4.1 저자가 밝힌 한계 (Sec. VI)

  • 물체마다 레퍼런스 하나로 학습한 정책이라 zero-shot 일반화를 보이지 않습니다. 8개 중 3개 물체는 사실상 풀리지 않았고, 긴 학습은 머스터드만 했습니다.
  • ablation은 최적화기 수축 하나와 고정 FPO 잡음 하나뿐입니다. 잘 조정한 고정 저잡음 PPO 기준선이 없어서, 똑같이 조정한 대안보다 우월하다고 말할 수 없습니다.
  • GRPO의 머스터드 뒤집힘이 재현성을 제한합니다. 연속 학습이라 처음부터 학습할 때의 효율이나 방법 간 비교를 말할 수 없고, 재확대·얼림·감쇠를 분리하지 못했습니다.
  • seed 3개, 하드웨어 모델 1개, 플랫폼 1개입니다. 하드웨어 시뮬레이터가 벤치마크와 달라 sim-to-real 간극을 측정하지 않습니다.

4.2 분석하면서 추가로 발견한 한계와 의문점

  1. 공개 GRPO 코드는 Eq. 5가 아닙니다(04 D1). algos/grpo.py는 완료 궤적마다 할인 없는 총 보상을 rollout 전체에서 표준화해 그 궤적의 모든 step에 같은 값을 줍니다. 나이별 그룹도, γ = 0.95 할인도 없습니다. Hugging Face 메타데이터의 GRPO 모델은 credit_module: grpo_rtg(reward-to-go)로 적혀 있어서, 실험에 쓴 모듈이 공개되지 않은 것으로 보입니다. toy에서 두 advantage의 상관은 0.73, 부호 불일치는 7.6%였습니다(03 §3).
  2. 기준선 PPO는 원래 ViViDex 예산의 1/20로 학습되었습니다. ViViDex 공개 설정의 기본 학습량은 1억 step(total_timesteps: 100000000)이고, 이 논문의 비교는 5M step입니다. 이 예산에서 Adam(lr 1e-5)이 log σ를 움직일 수 있는 폭은 약 0.98입니다(03 §2). 0.20에서 0.04로 가려면 1.62가 필요해서, 학습된 σ는 원리상 DexPolicy의 최종 잡음에 도달할 수 없습니다. 따라서 PPO 비교는 사실상 "스케줄 대 거의 고정된 σ ≈ 0.19"이고, 저자가 한계로 든 "고정 저잡음 기준선 부재"가 정확히 이 지점입니다.
  3. Target 기준이 공개 환경과 다릅니다(04 D6). ViViDex 공개 코드의 목표 성공은 최종 물체 위치 오차 ≤ 0.01 × 5 = 5 cm입니다(rewards.py: success_goal). 논문 정의는 3 cm이고, Lift(5 cm 높이) 판정도 ViViDex에는 없습니다. DexPolicy가 환경·평가 코드를 수정했지만 공개하지 않아 확인할 수 없습니다.
  4. 논문 실험의 일부 설정이 코드에 없습니다(04 D2·D3). GRPO 연속 학습 스케줄(0.20 → 0.10 → 0.03, 토마토 0.10 → 0.02)과 최종 정책 선형 대조(0.20 → 0.04)는 preset에 없습니다. 반대로 preset에는 A2C, TRPO 훅, "std_centered", 진행도 트리거, GRPO 재확대·해제 같은, 논문에 보고되지 않은 변형이 많습니다.
  5. 스케줄을 고른 물체와 seed가 평가에도 들어갑니다. 머스터드 seed 0으로 곡선을 고르고(Table IV·V), Table I 평균에 머스터드와 seed 0이 들어갑니다. GRPO는 네 물체에서 seed 0이 개발용이었습니다. 논문이 이를 밝히고 seed 0을 뺀 값도 주지만, PPO·FPO 쪽에는 같은 분리가 없습니다.
  6. "FPO"라는 이름은 혼동을 부릅니다. 이 논문의 FPO는 0에서 출발하는 8단계 결정론적 적분으로 평균을 만드는 네트워크에 Gaussian PPO를 붙인 것입니다. 사실상 가중치를 공유하는 8블록 잔차 MLP 평균입니다. flow matching 목적함수도, 확률적 flow 샘플링도 쓰지 않습니다(04 §1). 저자도 published FPO와 다르다고 밝힙니다.
  7. 재현에 필요한 환경, 레퍼런스 선택, 보상 수정, 하드웨어 모델이 공개되지 않았습니다. 물체마다 어떤 DexYCB 시퀀스를 썼는지도 없습니다(ViViDex 자산에는 논문의 8개 물체마다 시퀀스가 18–20개 있음). 공개 체크포인트는 머스터드 seed 0의 6개뿐입니다.

1. 잡음 크기에는 왜 "넓게 시작해 좁히기"가 맞는가

1.1 가우시안 보상 모형에서의 최적 σ

보상이 목표 근처에서만 큰 경우를 가우시안 bump r(a) = exp(−‖a − a*‖² / 2w²)로 단순화합니다. 행동이 N(μ, σ²I_d)를 따르고 평균이 목표에서 Δ = ‖μ − a*‖만큼 떨어져 있으면, 기대 보상은 닫힌 꼴입니다.

E[r] = ( w² / (w² + σ²) )^{d/2} · exp( −Δ² / (2(w² + σ²)) )

v = w² + σ²로 두고 log E[r] = −(d/2) log v − Δ²/(2v) + 상수를 v로 미분해 0으로 놓으면 다음을 얻습니다.

σ*² = Δ² / d − w²     (음수면 σ* = 0)

해석:

  • 최적 탐색 크기는 평균이 목표에 다가갈수록 줄어듭니다. 학습이 진행되며 Δ가 줄면 σ*도 줄어야 합니다. "넓게 시작해 좁히기"가 이 모형에서는 최적 경로입니다.
  • 차원이 크면 차원당 σ는 작아야 합니다. 잡음 벡터의 크기는 대략 σ√d입니다. ViViDex 행동은 22차원이므로 σ = 0.20이면 잡음 벡터 크기가 약 0.94, σ = 0.04이면 0.19입니다(정규화 행동 단위). 예를 들어 Δ = 0.5, w = 0.05, d = 22이면 σ* ≈ 0.094이고, Δ = 0.3이면 0.040입니다. 논문 스케줄의 범위(0.20 → 0.04)와 자릿수가 맞습니다.
  • 이 모형은 실제 dexterous 보상(접촉, 들어 올리기 보너스, 추적 오차)을 크게 단순화합니다. 수치가 아니라 방향만 읽어야 합니다.

1.2 정책 기울기의 신호 대 잡음

Gaussian 정책의 score는 ∇_μ log π = (a − μ)/σ²이므로 크기가 대략 √d/σ입니다. σ가 작으면 평균에 대한 기울기 신호가 커지고, 목표 근처에서 정밀하게 맞출 수 있습니다. 대신 목표에서 멀 때는 보상을 받는 표본 자체가 없어서 신호가 사라집니다. §1.1과 같은 결론입니다.

2. 학습된 σ는 5M step 안에 얼마나 움직일 수 있는가

PPO 기준선은 log σ를 다른 매개변수와 같은 Adam(lr 1e-5)으로 학습합니다. Adam의 한 step 변화량은 대략 lr 이하이고, 기울기 부호가 일정할 때 lr에 가깝습니다. 5M step 동안의 Adam step 수는 rollout 크기와 관계없이 다음과 같습니다.

(5,000,000 / 256 minibatch) × 5 epoch = 97,656 step
→ log σ 최대 이동 ≈ 97,656 × 1e-5 ≈ 0.98
양 log σ 변화
5M step 동안 가능한 최대 이동(근사) ±0.98
실제 기준선 변화(0.202 → 0.185, Sec. I) −0.085 (최대의 9%)
DexPolicy 최종값(0.04)까지 필요한 변화 −1.62
  • 학습된 σ는 이 예산 안에서 0.04에 원리상 도달할 수 없습니다. 최대 이동 폭 0.98보다 필요한 변화 1.62가 큽니다. 엔트로피 보너스(계수 0.001)는 σ를 오히려 키우는 방향입니다.
  • 실제 이동은 최대치의 9%뿐입니다. 최적화기 상한만의 문제가 아니라 log σ에 대한 기울기가 약하거나 부호가 자주 바뀐다는 뜻입니다. toy(§4)에서는 신호가 강하면 같은 lr × step(0.9)으로 σ가 0.20 → 0.07까지 줄었습니다.
  • ViViDex 원래 예산이면 결론이 달라질 수 있습니다. 공개 설정의 기본 학습량은 1억 step이라 최대 이동 폭이 약 19.5입니다. "학습된 σ가 줄지 않는다"는 동기 관찰은 5M step이라는 예산 조건에서의 관찰입니다.
  • GRPO 연속 학습은 학습률이 커서 사정이 다릅니다. 1e-4로 9,920 step, 5e-5로 4,960 step이라 최대 이동 폭이 약 1.24입니다.

2. 불일치와 논문에 적히지 않은 구현 요소

# 내용 영향
D1 공개 GRPO advantage가 Eq. 5가 아닙니다. trajectory_group_advantages는 완료 궤적마다 rewards[start:end].sum()(할인 없음)을 구해 rollout의 모든 완료 궤적끼리 표준화하고, 그 값을 궤적의 모든 step에 넣습니다. 나이별 그룹도, γ = 0.95도 없습니다. README도 "returns across complete episodes"라고 적어 코드와는 일치합니다. 반면 HF 메타데이터의 GRPO 두 모델은 "credit_module": "grpo_rtg"라서 실험에는 reward-to-go 모듈을 쓴 것으로 보입니다. 공개 코드로는 Table I·II의 GRPO 결과를 재현할 수 없습니다. toy에서 두 advantage의 상관은 0.73이고 부호 불일치는 7.6%였습니다(03 §3).
D2 GRPO 연속 학습 스케줄이 preset에 없습니다. 논문은 σ를 0.20으로 다시 키운 뒤 0.20 → 0.10 → 0.03으로 줄인다고 합니다(토마토는 세 번째 단계 0.10 → 0.02). preset의 GRPO 항목(grpo_hold_010_5m, grpo_reexpand_018_5m, grpo_contract_release_5m, grpo_early_release_5m)은 모두 0–5M 절대 시계의 다른 곡선입니다. README는 "GRPO plateau experiment"에 grpo_hold_010_5m(0.10 유지)를 쓰라고 하는데, 이 실험은 논문에 없습니다. HF 메타데이터의 GRPO 모델은 source_steps: 507904, additional_steps: 250000, lr 5e-5, σ 0.10 → 0.03입니다. 논문의 "약 5M 초기화 + 0.762M step"과 표현이 다르고, 253,952가 아니라 250,000으로 적혀 있습니다. 연속 학습의 시작점(source)과 단계 구성을 공개 자료만으로는 확정할 수 없습니다.
D3 최종 정책 선형 대조(0.20 → 0.04, Sec. V-E)의 preset이 없습니다. LINEAR_5M은 0.20 → 0.05(Table V의 uniform linear)입니다. 사소하지만 "같은 끝점의 선형 감쇠"를 재현하려면 직접 추가해야 합니다.
D4 FPO 설정 파일의 기본값이 논문 실험과 다릅니다. fpo.yaml 기본값은 actor_objective: fpo(flow matching ratio), gaussian_action_std: 0.05 고정, max_grad_norm: 1.0, save_best_model: True입니다. README대로 actor_objective=gaussian_ppo, trust_region_mode=ppo, action_head_mode=flow_residual과 σ 0.20·감쇠 5M·min_scale 0.25를 덮어써야 논문 설정이 됩니다. save_best_model이 켜져 있으면, 최종 체크포인트가 아니라 평가 최고 체크포인트를 쓸 위험이 있습니다. 논문은 "final" 체크포인트를 평가한다고 적었지만, 어느 파일을 평가했는지는 확인할 수 없습니다.
D5 논문에 보고되지 않은 변형이 코드에 많습니다. A2C preset 2개, TRPO용 기울기 0 훅, std_centered(학습을 유지하면서 평균을 목표 σ로 옮김), 진행도 트리거(사전 파지 성공 95% 이후 시계 시작), GRPO 변형 4개, selected_10m, full_20m(20M, 다단계 최적화기 수축). README도 "research ablations"라고 합니다. 여러 갈래를 시험한 뒤 일부만 보고했을 수 있으므로, 개별 비교의 p값을 더 보수적으로 읽어야 합니다.
D6 Target·Lift 정의가 공개 환경과 다릅니다. ViViDex 공개 코드의 목표 성공은 success_goal: 최종 물체 위치 오차 ≤ thresh × 5 = 0.01 × 5 = 5 cm이고, 접촉을 함께 요구합니다(rewards.py). 논문 Target은 3 cm입니다. ViViDex에는 높이 5 cm Lift 판정이 없고, 들어 올리기 보너스 기준은 바닥 + 2 cm입니다. DexPolicy의 평가 코드가 공개되지 않아 3 cm 판정을 확인할 수 없습니다. 공개 환경으로 재현하면 성공률 숫자가 달라집니다.
D7 레퍼런스 시퀀스 선택이 없습니다. ViViDex 자산(zerchen/object_sim)에는 물체마다 DexYCB 시퀀스가 여럿 있습니다(논문의 8개 물체는 각 18–20개, 예: 머스터드 18개, 바나나 20개). 논문은 "물체마다 레퍼런스 하나"라고만 하고, HF 메타데이터도 물체 이름(ycb-006_mustard_bottle)만 적었습니다. 같은 물체라도 시퀀스에 따라 난이도가 다를 수 있어, 물체별 수치를 그대로 재현하기 어렵습니다.
D8 기준선 PPO 학습 예산이 ViViDex 원래 설정의 1/20입니다. ViViDex config.yaml의 기본은 total_timesteps: 100000000, n_envs: 32, 평가 주기 1M step입니다. DexPolicy는 5M step, 평가 250k step마다입니다. ViViDex PPO 설정의 warm_start_mean: True(평균을 초기 자세 근처로 시작)는 DexPolicy ppo.yaml에 없습니다. 환경 쪽에서 처리하는지는 확인할 수 없습니다. 5M step에서는 학습된 log σ가 최대 약 0.98만 움직일 수 있어 0.04에 도달할 수 없습니다(03 §2). 논문의 PPO 비교는 짧은 예산 조건의 결과로 읽어야 합니다.
D9 엔트로피 보너스가 기준선 σ를 키웁니다. PPO·GRPO 모두 ent_coef: 0.001입니다. 얼린 σ에서는 상수라 영향이 없지만, 학습 σ 쪽에서는 σ를 키우는 방향의 기울기를 더합니다. 기준선 σ가 거의 줄지 않은 원인 중 하나일 수 있습니다. 논문의 PPO 고정 설정 목록에는 엔트로피 계수가 없습니다.
D10 연속 학습에서 스케줄 시계가 모호합니다. callback은 self.num_timesteps를 시계로 씁니다. 약 5M step 체크포인트를 불러 계속 학습할 때 reset_num_timesteps를 어떻게 했는지에 따라, 0–5M preset이 처음 단계로 시작하거나 마지막 단계(0.04)에 머뭅니다. 연속 학습 스크립트는 공개되지 않았습니다. D2와 함께, GRPO 결과를 재현하려면 공개되지 않은 학습 스크립트가 필요합니다.
D11 공개 체크포인트는 6개뿐입니다. 머스터드 seed 0의 PPO·GRPO·FPO × 기준선·DexPolicy입니다. 논문 평가 모델은 PPO·FPO 96개, GRPO 30개, 하드웨어 18개입니다. 하드웨어 모델과 하드웨어용 시뮬레이터(RM75 + RH56)는 없습니다. seed 0 머스터드는 스케줄을 고른 바로 그 조건이라, 대표 예시로는 가장 유리한 쌍일 수 있습니다.

공정한 기준선 중간 저자가 빠뜨린 "잘 조정한 고정 저잡음 PPO", 엔트로피 계수 스케줄, 충분한 예산의 학습 σ를 함께 둬야 결론을 낼 수 있습니다

3. 이 저장소의 다른 논문과의 관계

논문 관계
FlashDexRetarget (flashdexretarget/) 같은 문제(사람 시연을 로봇 궤적으로)를 다른 쪽에서 풉니다. FlashDexRetarget은 레퍼런스 수백 개를 off-policy(FlashSAC) 정책 하나로 추적했고, 같은 예산에서 PPO는 거의 0이었습니다(Fig. 4(d)). DexPolicy는 물체마다 PPO 정책을 따로 두고, 학습된 σ가 줄지 않는 문제를 스케줄로 우회합니다. 두 결과를 합치면, 넓은 상태 분포나 정밀 추적에서 PPO의 탐색 크기 조절이 약점이라는 같은 관찰이 됩니다. SAC 계열은 목표 엔트로피로 온도를 자동 조절해서 이 문제를 구조적으로 다룹니다.
Do as I Do (do_as_i_do/) 영상 → 손-물체 궤적 → 로봇이라는 흐름이 같습니다. Do as I Do는 sampling MPC에서 노이즈 커널을 반복·horizon 방향으로 annealing했습니다(SPIDER 계열). DexPolicy는 같은 "넓게 시작해 좁히기"를 RL 학습 step 축에서 합니다.
DexScrew (dexscrew/) 둘 다 PPO로 손가락 기술을 배웁니다. DexScrew 분석에서 정리한 검정력·시행 수 계산(dexscrew A1)이 이 논문의 seed 3개, 하드웨어 모델 1개 설계에 그대로 적용됩니다.
Contact-Grounded Policy (contact_grounded_policy/) 결정론적 평가와 작은 시행 수라는 통계 문제가 같습니다. CGP 분석의 "점추정 1위 ≠ 유의한 우위" 교훈이 DexPolicy의 PPO 결과(+3.7%p, p ≈ 0.39)에 그대로 해당합니다.
DDPG (ddpg/) 탐색 잡음을 어떻게 정하느냐가 성능과 재현성을 가른다는 점이 같습니다. DDPG의 OU 잡음 dt 누락처럼, DexPolicy도 스케줄의 시간축(누적 환경 step인지, 연속 학습에서 어디서 다시 세는지)이 재현의 핵심 세부입니다.
ZeroDex (zerodex/) 같은 Inspire 손을 씁니다(ZeroDex는 실물, DexPolicy는 RH56 모델과 실물).
