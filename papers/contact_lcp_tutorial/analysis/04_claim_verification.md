# 04. 주장 검증 (공식 코드 없음)

이 논문에는 공식 저장소가 없습니다(`02_prior_work.md` §4). 그래서 코드 대조(D1–Dn) 대신 **주장별 검증(C1–Cn)**을 했습니다. 검증 방법은 세 가지입니다: (a) 식을 다시 유도하거나 대수로 확인, (b) `analysis/formulation_checks.py`의 토이 V1–V10으로 수치 확인, (c) 문헌 주장은 확인할 수 없다고 표시. 코드는 아무것도 실행하거나 설치하지 않았습니다.

## 1. 판정 기호

- **맞음(수치):** 토이로 확인함.
- **맞음(대수):** 손으로 다시 유도해서 맞음. 수치 토이는 없음.
- **일부 맞음 / 과장:** 주장의 방향은 맞지만 문장이 넓거나 극한에서만 성립함.
- **불일치:** 논문 문장이 계산과 맞지 않음.
- **미검증:** 확인 수단이 없음 (문헌, 구현, 성능).

## 3. 발견 요약

1. **식 수준에서 틀린 곳은 거의 없습니다.** C1, C2, C3, C8–C12, C22는 맞습니다.
2. **문장 수준에서 넘치는 곳이 두 개 있습니다.** C13(네 모서리 상자의 "합만")과 C14(정규화의 최소 노름 선택)입니다. 둘 다 고칠 수 있는 문장이고 저자에게 물어볼 가치가 있습니다.
3. **조건이 빠진 곳이 하나 있습니다.** C10은 접촉마다 스칼라 R이라는 조건이 필요합니다. 논문은 R_ii를 쓰지만 스칼라 조건을 명시하지 않습니다.
4. **논문이 말하지 않은 추가 효과가 있습니다.** C5처럼 완화가 접선 응답도 바꾼다는 점은 "들림"을 해석할 때 중요합니다.

## 4. 구현 가능성 판정 (이 맥)

**이 튜토리얼의 주장은 이 맥(Apple M4 Pro, 24 GiB, MPS, CUDA 없음)에서 전부 확인할 수 있습니다.** 식 검증과 토이 실험은 CPU에서 몇 초 안에 끝났습니다. 이 맥에서 실행하기 어려운 것은 다음과 같습니다.

- **시뮬레이터 대규모 비교(표 2, 3의 성능 주장):** 공식 구현(MuJoCo, Drake, Kamino, PhysX)을 설치하고 실험해야 합니다. MuJoCo와 Newton은 CPU로 돌릴 수 있지만 튜토리얼이 주장하는 GPU 배치 성능(§6.4)은 CUDA 기기가 필요합니다.
- **정책 학습 파이프라인:** 튜토리얼 범위가 아닙니다.
- **노력 추정:** 주장 검증은 이미 끝났습니다(약 반나절). 공식 시뮬레이터에서 논문 주장(C4, C5, C6)을 실제 시뮬레이션으로 확인하는 작업은 1–2일이 걸릴 것으로 추정합니다. 이 작업은 필요할 때만 합니다.
