# FR-VLA 주장 검증 (공식 코드가 없어 논문 내부 대조)

공식 코드를 찾지 못했으므로(`02_prior_work.md` §2) 코드 대조(D1–Dn) 대신 **주장 대 본문·부록·표·그림 수치**를 대조합니다. 판정은 다음 기준입니다.

- **산술 일치**: 적힌 수치를 다시 계산해서 맞음.
- **통계적으로 확정 아님**: 계산은 맞지만 검정 결과가 유의하지 않거나 시도 수가 부족함.
- **부분 지지**: 증거가 정성적이거나 일부 과제에만 있음.
- **검증 불가**: 필요한 원자료가 없음.
- **긴장**: 본문 안의 다른 서술과 어긋나거나 해석 여지가 큼.

## 2. 판정 요약

- **숫자는 대체로 맞습니다.** 평균, 차이, 표 3–4의 산술, 식 2의 성질, 위상 설정은 다시 계산해도 맞습니다(C1, C2, C4, C5, C7, C8, C14, C19).
- **통계적 확실성이 약합니다.** 단계별 우위(C3), 크기 기반 게이팅 비교(C6), 섭동 우위(C7)는 시도 수가 작아 유의하지 않습니다.
- **가장 큰 방법론 문제는 위상 평가입니다**(C9). 평가 정답이 학습에 쓴 힘 규칙과 같아서, 표 1은 독립된 "시각-언어 추론" 증거가 아닙니다.
- **해석 주장이 정량 검증을 넘어섭니다**(C10, C13). "힘 크기가 아니라 위상"이라는 결론은 궤적 사례와 그림에 기댑니다.

## 3. 원자료 없이 확인할 수 없는 것

- 위상 평가의 rollout 수와 혼동 행렬(C9).
- 힘 코드와 사건의 연관 횟수(C11).
- 기준선 구현 출처와 학습 설정(`01_paper_analysis.md` §4).
- 어블레이션의 정의(`w/o force admission`이 $g = 0$인지 힘 경로 전체 제거인지, `01` §4의 5번).

## 4. 구현 가능성 판정

### 4.1 판정

- **원 논문 결과의 재현: 불가.** 공식 코드가 없고, 실로봇(UR5e와 UR3e)과 과제당 70–90회의 시연 데이터가 필요하며, 학습은 RTX A6000 두 장에서 했습니다. 이 맥(Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)에서는 실로봇 평가를 할 수 없습니다.
- **구성 요소의 재구현: 조건부 가능.** 위상 라벨러(식 12–13), admission 게이트(식 2)와 admission 주의(식 3–5), 힘 VQ 토크나이저(식 8–11)는 PyTorch(MPS 또는 CPU)로 옮길 수 있습니다. 합성 힘 궤적으로 단위 검사를 하는 것은 가능합니다.
- **VLA 본체 학습: 불가에 가깝습니다.** 백본 이름과 학습 설정이 빠져 있어 필요한 계산량을 추정할 수 없습니다. 백본 크기가 확인되면 다시 판정해야 합니다.
- **노력 추정(추정, 측정 전):** 구성 요소 재구현 1–2주(위상 라벨러와 토크나이저는 각각 2–3일, 게이트와 주의는 1–2일). 실로봇 재현은 저장소 밖 장비가 필요합니다.

### 4.3 결론

**구현할 수 있는가?** 구성 요소는 구현할 수 있습니다. 그러나 논문 결과를 재현할 수는 없습니다. 이 판정은 코드 부재와 백본 미공개를 근거로 한 것이므로, 코드나 학습 설정이 공개되면 다시 판정합니다.
