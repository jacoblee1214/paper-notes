## 1. 풀려는 문제와 기여

사람의 전신 동작을 RGB 카메라 하나로 읽어 실물 풀사이즈 휴머노이드(Unitree H1)가 실시간으로 따라 하게 합니다(§I). 선행 모델 기반 방법은 단순화된 동역학 모델과 접촉 측정(외골격, 힘 센서)에 의존해 동적 동작으로 확장하기 어렵다는 것이 동기입니다. RL로 이를 푸는 시도는 시뮬레이션 아바타 쪽(PHC 등)에는 있었지만 하드웨어 한계(토크, 관절 한계)를 무시한 상태 공간 때문에 실물 이전이 불확실하다고 봅니다.

기여 세 가지(§I):
1. 사람 모션 대규모 데이터를 H1이 실제로 할 수 있는 동작으로 거르는 **"sim-to-data" 재타겟팅 절차**.
2. 많은 동작에 확장되는 **전신 추적 RL 컨트롤러의 sim-to-real 이전**.
3. RGB 카메라와 3D 포즈 추정기로 만든 **실시간 원격조작 시스템**(걷기, 물건 옮기기, 유모차 밀기, 권투, 손 흔들기, 공 차기).

초록의 "learning-based real-time whole-body humanoid teleoperation의 첫 시연"은 우선권 주장이고, 같은 시기의 ExBody(arXiv:2402.16796, 논문 참고문헌 [22])는 상체 동작과 하체 속도 추적이라 다르다고 §I에서 구분합니다.

## 2. 방법

### 2.1 문제 정식화 (§III)

목표 조건부 RL입니다. 상태 s_t = (s^p_t, s^g_t), 행동 a_t ∈ R^19(PD 목표 관절각), 보상 r_t = R(s^p_t, s^g_t), PPO로 누적 할인 보상을 최대화합니다. 사람 모델은 SMPL(β ∈ R^10, θ ∈ R^{24×3}, 전역 이동 p)이고 데이터는 AMASS(논문 §III-B: "40시간").

### 2.2 리타게팅과 sim-to-data (§IV, 그림 2, 3, 4)

1. **형상 맞춤.** H1과 SMPL 사이 대응하는 12개 관절의 거리를 줄이도록 공통 서기 자세에서 SMPL 형상 β′를 경사 하강으로 찾습니다(그림 2). 이유: H1은 서 있을 때 두 발 사이 간격이 커서 평균 체형으로 발 위치를 맞추면 안쪽으로 모인 "in-toed" 동작이 나옵니다(그림 3).
2. **자세 리타게팅.** 원래 이동 p와 자세 θ에 β′를 써서 키포인트 위치를 얻고, 12개 관절 위치 차이를 Adam으로 줄여 H1 관절각을 얻습니다. 발목, 팔꿈치, 손 같은 말단을 맞춥니다. "앉기" 같은 안전하지 않은 시퀀스는 휴리스틱으로 거릅니다. AMASS 약 13k 시퀀스에서 10k가 나옵니다(Q̂_retarget).
3. **sim-to-data 필터.** DR 없이, 특권 정보(모든 몸체의 전역 위치, 회전, 선속도, 각속도)를 쓰는 모방 정책 π_privileged를 PULSE 방식(같은 상태 공간, 제어 파라미터, hard-negative mining)으로 10k 전체에 학습합니다. π_privileged가 따라 하지 못하는 시퀀스를 "H1에게 불가능"으로 보고 지웁니다. 결과는 약 8.5k(Q̂_clean).
   - 특권 정책의 상태 차원은 S ⊂ R^778(표 III). 고유감각은 [p, θ, v, ω]이고 목표 상태는 다음 프레임 기준과 현재의 차이들입니다.

### 2.3 상태 공간, 행동, 보상, DR (§V)

- **고유감각 s^p_t = [q, q̇, v, ω, g, a_{t-1}]**: 관절각 19, 관절속도 19, 루트 선속도 3, 루트 각속도 3, 투영 중력 3, 이전 행동 19 → 66차원. 루트 선속도는 실물에서 MoCap으로 얻습니다(§VI-B).
- **목표 상태 s^g_t = [p̂^kp_t, p̂^kp_t − p^kp_t, ṗ̂^kp_t]**: 8개 기준 키포인트(어깨, 팔꿈치, 손, 발목)의 위치, 현재와의 차이, 기준 선속도 → 3 × 24 = 72차원. 전체 138차원(`03` V2에서 재구성). 비교 기준 "reduced"는 위치 p̂^kp만 써서 24차원, 전체 90차원입니다.
- **행동.** 19차원 관절 목표, PD 제어기 τ = K_p(a_t − q_t) − K_d q̇_t. 그림 4: 정책 50 Hz, PD 200 Hz, 포즈 추정 30 Hz.
- **보상(표 I).** 벌점(토크 한계 −0.2, 관절 위치 한계 −100, 종료 −200), 정규화(관절 가속도, 속도, 행동 변화율, 토크, 발 체공 시간 +800 등), 과제 보상 여섯 개(관절 위치 24, 속도 24, 몸체 위치 40, 회전 16, 속도 60, 각속도 60). 목표 상태는 8점뿐이지만 보상은 전신 항을 씁니다(§V-B, 밀도 높은 신호).
- **DR(표 II).** 마찰 U(0.2, 1.1), 기저 CoM ±0.1 m, 링크 질량 ×U(0.7, 1.3), PD 이득 ×U(0.75, 1.25), 토크 RFI 0.1 × 토크 한계, 제어 지연 U(20, 60) ms, 5초마다 0.5 m/s 밀기, 지형(평지, 거침, 낮은 장애물).
- **조기 종료(§V-D).** 기저 높이 < 0.3 m, 투영 중력 x 또는 y > 0.7, 로봇과 기준의 평균 링크 거리 > 0.5 m.

### 2.4 배포 (§VI-B, 그림 4)

1080P 웹캠 + HybrIK(30 Hz)가 3D 인체 자세를 주고, 정책(50 Hz)이 이를 따라 H1의 관절 목표를 냅니다. 루트 선속도는 MoCap(50 Hz), 나머지 고유감각은 H1 내장 센서(200 Hz)입니다. 선속도는 온보드 시각/LiDAR 오도메트리로 대체할 수 있다고 적었지만 이 논문에서는 하지 않았습니다.

## 3. 실험 결과

### 3.1 시뮬레이션 (§VI-A, 표 III, IV)

평가는 **Q̂_retarget 전체(10k, 지우기 전)** 에서 합니다. 성공은 PHC 방식입니다: 모방 중 어느 시점에 몸체 평균 거리가 0.5 m를 넘으면 실패.

표 III (논문 쪽 6, 값은 논문 그대로):

| 방법 | 상태 차원 | Sim2Real | Succ ↑ | 전체: Eg-mpjpe / Empjpe / Eacc / Evel | 성공 시퀀스: Eg-mpjpe / Empjpe / Eacc / Evel |
|---|---|---|---|---|---|
| Privileged policy | R^778 | ✗ | 85.5% | 50.0 / 43.6 / 6.9 / 7.8 | 46.0 / 40.9 / 5.2 / 6.2 |
| H2O-reduced | R^90 | ✓ | 53.2% | 200.2 / 115.8 / 11.2 / 13.8 | 182.5 / 111.0 / 3.0 / 8.1 |
| H2O-w/o-sim2data | R^138 | ✓ | 67.9% | 176.6 / 95.0 / 10.2 / 12.2 | 163.1 / 93.8 / 3.0 / 7.5 |
| H2O | R^138 | ✓ | 72.5% | 166.7 / 91.7 / 8.9 / 11.0 | 151.0 / 88.8 / 2.9 / 7.0 |

표 IV (데이터 크기, 같은 평가):

| 학습 데이터 | Succ | Eg-mpjpe | Empjpe | Eacc | Evel |
|---|---|---|---|---|---|
| Q̂_clean의 0.1% | 52.0% | 198.0 | 107.9 | 12.4 | 13.7 |
| 1% | 58.8% | 183.8 | 96.4 | 10.7 | 12.0 |
| 10% | 61.3% | 174.3 | 92.3 | 10.8 | 12.1 |
| 100% | 72.5% | 166.7 | 91.7 | 8.9 | 11.0 |

본문 해석(§VI-A):
- sim-to-real 정책이 특권 정책보다 낮은 이유는 (1) 덜 정보적인 관측과 (2) sim-to-real 정규화와 DR 두 가지입니다.
- "sim-to-data"는 학습 데이터가 더 적은데도 성공률을 올립니다(72.5 대 67.9). 불가능한 동작에 자원을 쓰지 않기 때문이라고 설명합니다.
- 목표 상태에 위치 차이와 속도를 넣으면 대규모 모방에 일반화가 좋아집니다(72.5 대 53.2).
- 데이터가 늘수록 계속 좋아지지만, 0.1%(약 9개 시퀀스)로도 52%가 나오는 것은 DR(특히 밀기)이 상태 분포를 넓히기 때문일 것이라고 추정합니다.

### 3.2 실로봇 (§VI-B, 그림 1, 5, 6, 7)

정성적 시연뿐입니다. 그림 1(펀치, 옆걸음 + 공 차기, 유모차, 상자 전달), 그림 5(좌우 차기), 그림 6(걷기, 연속 뒤로 점프), 그림 7(강한 발길질에 균형 유지). **성공률, 오차, 시도 횟수, 지연 측정이 없습니다.** 초록의 "turning, waving, boxing"은 본문 그림에서 직접 확인하지 못했고 영상(프로젝트 페이지)에 있다고 봅니다.

## 4. 한계와 논문이 스스로 인정한 것 (§VII)

- 표현 격차: 목표 표현이 풍부할수록 RL 표본 효율이 나빠지는 상충.
- 체현 격차: 어떤 동작이 로봇에게 가능한지 체계적으로 판단하는 알고리즘이 없음(이 논문의 필터는 한 정책의 성공 여부로 정의).
- sim-to-real 격차: 정규화와 DR이 과하면 모방이 안 되고 적으면 이전이 안 됨. 최적 균형은 미해결.
- 지연과 오차: RGB와 포즈 추정의 지연, 오차 때문에 효율과 정밀도가 상충. 조작자는 시각 피드백만 받음.
- 하체 추적의 필요성: 발차기, 디딤돌, 다리 벌리기에서 필요.

## 6. 이 논문을 읽는 방법

- **강한 부분:** 설계 판단이 명확하고 단순합니다(전신 키포인트 8점 + 선속도 입력, 특권 정책으로 데이터 거르기). 표 IV의 곡선과 §VII가 정직하게 한계를 적습니다.
- **약한 부분:** 정량 근거가 시뮬 표 두 개뿐이고, 평가가 학습 집합과 겹치며, 학습 시드와 하이퍼파라미터, 실물 시도 수가 없습니다. 공식 코드는 논문 6개월 뒤에 나온 OmniH2O 코드베이스이고 H2O 재현용 설정이 논문 표와 다릅니다(`04` D1–D17).
