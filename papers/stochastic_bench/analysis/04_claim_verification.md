# 04. 주장 검증 (공식 코드 없음)

벤치마크 생성기와 서버 코드는 공개되어 있지 않으므로(`02` §4) 코드 대조(D 항목) 대신 **논문의 주장(C 항목)**을 재계산(`03`)과 공개된 부수 자료에 맞춰 확인했습니다. 쓴 자료는 (a) 논문 v1과 부록, (b) 프로젝트 페이지 HTML(2026-11-23 내려받음), (c) 프로젝트 페이지 저장소 파일 목록, (d) KLX Benchmark 사이트의 **클라이언트 번들**(`main.d68d1172.js`, 약 210 KB, 정적으로만 읽음. 실행·로그인·API 호출 없음)입니다. 내려받은 내용은 신뢰하지 않는 데이터로 취급했습니다.

판정 표기: **지지**(재계산·근거와 맞음), **부분**(조건이 붙음), **불가**(수치가 성립하지 않음), **미보고**(근거가 논문에 없음), **확인 불가**.

## 2. 정적으로 읽은 웹 앱에서 확인한 사실 (C13, C15, C16 근거)

- 요청: `/auth/github/login`, `/auth/me`, `/challenges/`, `/challenges/latest`, `/get-inserts`, `/run-challenge`, `/leaderboards/<종류>?limit=20`. `run-challenge` 본문 변수는 `selectedInserts`, `seed`, `empty_probability`, `noInserts`, `challengeType`입니다. 과제 유형은 "Open Inserts", "Find Object", "Move Object" 세 가지입니다(논문 §4의 Open, Pick, Place/Move에 대응).
- 리더보드 행은 시드·과제·구성 ID와 `p=…`, 삽입물 종류 수, 최대 사용 횟수를 보여 줍니다. 즉 **분포 변수(빈 확률, 삽입물 선택)를 사용자가 바꿀 수 있고 결과는 구성별로 집계**됩니다. 서로 다른 설정의 점수를 같은 "분포"의 점수로 합치려면 설정을 고정하는 규칙이 필요한데 논문은 그 규칙을 적지 않았습니다.
- 리더보드는 시도 수, 성공 수, 실패 수, 성공률만 보이고 신뢰구간, 검출 한계, 필요 시드 수 같은 통계 계산에 해당하는 문자열은 번들에서 찾지 못했습니다(`confidence`, `Wilson`, `Welch`, `interval` 0건). 논문의 통계 틀은 사이트에 구현되어 있지 않은 것으로 보입니다(번들 한 파일의 정적 읽기이며 서버 응답은 보지 않음).
- 이 읽기는 클라이언트 쪽 문자열에 근거한 것이라 서버 동작(시드 선택 규칙, 결과 저장 규칙)은 확인하지 못했습니다.

## 4. 구현할 수 있는지 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**판정: 논문의 핵심 기여인 통계 틀(필요 시드 수, 시드 공유 설계, 검정)은 이 맥에서 구현하고 시험할 수 있습니다. 논문의 실험(Spot·Stretch로 두 연구실에서 568회)은 로봇, 두 연구실, 시드 구성, 성공 판정 인력이 필요해 재현할 수 없습니다. 벤치마크 생성기와 서버는 공개되지 않아 재구현해야 합니다.**
