# 03. 재계산, 검정, 일관성 검사

이 문서의 숫자는 모두 `analysis/recompute.py`가 `analysis/recompute_results.json`에 남긴 결과입니다(수 초, numpy·scipy). 그래프는 `analysis/plot_figures.py`가 그립니다. 논문 수치는 원문 표에서 옮겼습니다. **재실행은 하지 않았고 새 실험도 하지 않았습니다.** 검사 항목은 V1–V15입니다.

표준편차 규칙: 표 1의 ± 값은 **3 실행의 표본 SD(ddof = 1)로 가정**했습니다. 논문은 SD의 정의를 밝히지 않았습니다.

## 1. 실물 (표 2, 12장면 × 10회 × 정책 2개 = 240회)

### 1.1 표 평균 재계산 (V1)

장면별 값에서 평균을 다시 냈습니다.

| 지표 | πpre 재계산 | πpre 보고 | RL 재계산 | RL 보고 | 판정 |
|---|---|---|---|---|---|
| PSR | 0.450 | 0.45 | 0.883 | 0.883 | 일치 |
| SR | 0.217 | 0.217 | 0.750 | 0.75 | 일치 |
| DFR | 0.667 | 0.667 | 0.183 | 0.183 | 일치 |
| SFR | 0.183 | 0.183 | 0.067 | 0.067 | 일치 |
| TF (장면 평균의 평균) | 12.35 (11장면) | 11.5 | 10.32 (12장면) | 10.2 | **불일치** |

- 표 2의 "−"(RL 장면 4, 5)는 SR = 1.0이라 실패가 없습니다. 0으로 두면 DFR 평균이 2.2/12 = 0.183으로 맞고, 빼고 나누면 0.22가 됩니다. 보고값은 0으로 둔 쪽과 맞습니다.
- **TF는 재현되지 않습니다.** 장면별 TF는 성공한 에피소드만 평균한 값으로 보입니다(본문: "TF is averaged over successful episodes only" 문구는 표 1에 있고, 표 2에는 그 문구가 없습니다). 가중 평균이 필요한데 원자료가 없어 1.13배 속도 향상을 확인할 수 없습니다. 장면 평균을 그대로 쓰면 12.35/10.32 = 1.20배입니다(V11).

### 1.2 성공률 구간과 검정 (V2–V4)

| 정책 | 성공 / 시도 | SR | Wilson 95% | PSR 성공 / 시도 |
|---|---|---|---|---|
| πpre | 26 / 120 | 21.7% | 15.2–29.9% | 54 / 120 |
| RL (N = 100) | 90 / 120 | 75.0% | 66.6–81.9% | 106 / 120 |

- **Fisher 정확 검정(비대응):** 차이 53.3 pp, p = 7 × 10⁻¹⁷.
- **장면 쌍 비교(V4):** 12장면 모두에서 RL의 SR이 IL보다 높습니다(12/12, 동점 0). 부호 검정 p = 0.0005, Wilcoxon 정확 p = 0.0005 (양측).
- **해석:** "실물 성공률이 올랐다"는 것은 강하게 뒷받침됩니다. 하지만 **정책 한 개(한 체크포인트), 로봇 한 대, 장면 12개, 장면당 10회**라서 장면 간 차이와 체크포인트 간 차이는 여기서 나오지 않습니다. 장면 하나의 10회 결과는 구간이 넓어서(예: 9/10의 Wilson 95%는 약 0.60–0.98), 장면별 수치는 방향만 씁니다.

### 1.3 실패 분해 (V5)

- 실패 = 1 − SR이고, DFR과 SFR은 겹칠 수 있다고 논문이 씁니다. 두 값의 합이 실패율보다 작은 장면은 없습니다(위반 0). 
- πpre에서는 표의 장면 번호 3, 4, 10, 11(0부터 셈)에서 DFR + SFR이 실패율을 넘어 겹침이 있습니다. 평균 겹침은 6.7 pp입니다. RL에서는 겹침이 없습니다.
- 해석: 실패의 주된 원인이 실행(DFR)이라는 결론은 두 정책 모두에서 성립합니다. RL의 SFR 감소(18.3 → 6.7%)는 장면 수가 적어 불확실합니다.

## 2. 시뮬레이션 (표 1)

### 2.1 ∆G 재계산 (V7)

∆G = SR(ID) − SR(OOD)입니다. 보고된 ∆G를 모두 다시 계산했습니다.

- **OOD 행 6개**(N = 1, 3, 10, 25, 50, SE): 모두 일치합니다.
- **외부 세트 20개**(SimplerEnv 6, Google 7, Hunyuan 7): 모두 일치합니다. 기준이 되는 ID 값은 N = 1–50은 해당 N의 ID 평균, N = 100은 W 평균(78.9), SE 행은 SimplerEnv 정책이 자기 장면에서 얻은 96.7입니다. **기준값이 행마다 다르다는 점을 표만 봐서는 알기 어렵습니다**(본문에 정의가 없습니다).

### 2.2 혼합 평가 W와 ID, OOD의 관계 (V8)

- N = 50에서만 W = (ID + OOD)/2가 성립합니다. 계산값 79.2, 보고값 79.2입니다. ID 50장면과 OOD 50장면이 나뉘어 있어서입니다. 다른 N은 ID 장면 수가 N이라 이 식이 성립하지 않습니다.

### 2.3 장면 수에 따른 차이의 검정 (V9)

3 실행, 표본 SD 가정의 Welch 검정입니다. 검정력이 낮습니다.

| 비교 (OOD 성공률) | 차이 (pp) | p |
|---|---|---|
| N = 1 대 N = 3 | −8.1 | 0.11 |
| N = 3 대 N = 10 | −11.1 | 0.007 |
| N = 10 대 N = 25 | −5.2 | 0.002 |
| N = 25 대 N = 50 | −0.3 | 0.69 |
| N = 1 대 N = 50 (본문 24.7 pp) | +24.7 | 0.014 |

| 비교 (전체 W) | 차이 (pp) | p |
|---|---|---|
| N = 25 대 N = 50 | +0.9 | 0.07 |
| N = 50 대 N = 100 | −0.3 | 0.63 |

- **읽는 법:** N = 10 이후 OOD 성능이 여전히 오른다는 것(N = 10 → 25)은 분명합니다. N = 25와 50 사이는 차이가 없습니다. 저자들의 "포화" 해석과 맞습니다. 다만 저자들이 밝힌 대로, 고정 배치라서 큰 N이 장면당 샘플을 덜 받습니다. 포화가 다양성의 한계인지 연산 한계인지는 이 데이터로 구분할 수 없습니다(V9, 01 §5).
- **N = 1 대 N = 3의 차이는 통계적으로 확실하지 않습니다**(p = 0.11). 본문은 "increasing N produces a clear trade-off"라고 쓰지만, 이 구간의 근거는 약합니다.

### 2.4 초록의 헤드라인 수치 (V6, V10)

- **79.8%는 표 1의 평균이 아닙니다.** 표 1의 N = 100 평균은 78.9 ± 0.9(3 시드)입니다. 79.8은 표 B.1의 K = 1 행(79.75, **단일 실행**)과 같습니다. 본문도 "N = 100 checkpoint that achieves 79.8%"라고 써서, 실물에 쓴 체크포인트가 어떤 것인지 명확하지 않습니다.
- 초록의 시뮬 향상 70.1 pp = 79.8 − 9.7로 맞습니다. 평균 기준으로는 69.2 pp(78.9 − 9.7)입니다.
- **OOD 24.7 pp**(53.2 → 77.9)는 평균끼리의 차이로 맞습니다(V10).
- **실물 53.3 pp**(21.7 → 75.0)는 맞습니다(V10).

### 2.5 평가 표본 수와 잡음 (V16)

장면당 100 에피소드로 평가했으므로, 이항 표본 오차(sqrt(p(1-p)/n))와 보고된 SD를 비교했습니다.

| 칸 | 에피소드 수 | 이항 SE (pp) | 보고 SD (pp) | 비율 |
|---|---|---|---|---|
| N = 1, ID (1장면) | 100 | 2.3 | 2.6 | 1.1 |
| N = 1, OOD (50장면) | 5,000 | 0.7 | 5.5 | 7.8 |
| N = 50, ID (50장면) | 5,000 | 0.6 | 0.4 | 0.7 |
| N = 50, OOD (50장면) | 5,000 | 0.6 | 0.9 | 1.5 |
| N = 100, W (100장면) | 10,000 | 0.4 | 0.9 | 2.2 |
| N = 100, SimplerEnv (3장면) | 300 | 2.5 | 4.1 | 1.6 |

- **N = 1의 OOD 변동 (SD 5.5)은 표본 오차가 아닙니다.** 이항 SE의 약 8배입니다. 어느 장면 부분집합으로 학습했는지(실행 간 차이)가 변동의 대부분입니다. 그래서 "N = 1의 OOD는 53.2%"라는 값은 실행 선택에 따라 크게 달라집니다.
- **N = 50 칸은 SD가 표본 오차 수준입니다.** 장면 분포가 안정적이라는 뜻입니다.
- **3 실행으로 추정한 SD는 불안정합니다.** Google N = 25의 SD 0.6은 이항 SE(1.1)보다 작습니다. 3 실행 SD로 차이를 판단할 때는 이 점을 감안해야 합니다.

- K = 10의 RL 성공률과 학습 시간은 "N/A"입니다. 그래서 K = 10의 학습 성능 비교는 없습니다.

### 3.3 설정의 시간 환산 (V14–V15)

- 제어 5 Hz, 청크 C = 4이면 한 결정은 0.8 s입니다. 에피소드 길이 25를 청크 단위로 보면 최대 20 s, 실물 TF 10.2 s는 약 12.7 청크입니다. 에피소드 길이가 청크인지 환경 스텝인지는 논문에 없습니다(01 §6).
- 로그-σ 범위 [-2.5, -2.0]은 σ ∈ [0.082, 0.135]입니다.

## 4. 생성 파이프라인 (표 C.1, V13)

- 객체 수: 516 / 100 = 5.16. 보고값과 맞습니다.
- 시간: 장면당 **25.0 + 3.9 × 5.16 = 45.1분**이 나옵니다. 보고된 46.8분과 **1.7분(3.6%)**이 차이 납니다. 나머지 시간(QA, 배치 처리 등)은 표에 없습니다.
- QA 통과율 곱 0.833 × 0.752 × 0.919 = 0.576입니다. "자산당 평균 1.37회 시도"와는 정의가 달라 직접 대조할 수 없습니다.
- 100장면 순차 생성은 78시간입니다(RTX 4090 한 장).
- **수용률 85%의 해석:** 나머지 15%는 "최소한의 수동 조정"으로 고쳤다고 씁니다. 학습에 쓴 100장면이 수정 후 장면인지 원래 장면인지 본문에 없습니다. 이 점은 재현 가능성과 직결됩니다.

## 7. 재계산하지 못한 것

- 표 2 TF의 원자료(에피소드별 시간) 없이는 평균 정의를 확정할 수 없습니다.
