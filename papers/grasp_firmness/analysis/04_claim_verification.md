# 04. 주장 검증과 구현 가능성 (공식 코드 없음)

공식 코드를 찾지 못해 코드 대조(D 항목) 대신 논문의 주장을 표·그림·부록 수치와 맞춰 보았습니다(C1–C14). 재계산 세부는 `03`에 있습니다. 판정은 "확인됨 / 부분 확인 / 판단 보류(근거 부족)"로 씁니다. 이 문서는 논문 비판이 아니라 어떤 서술이 어떤 근거에 서 있는지를 정리한 것입니다.

## 2. 코드와 데이터 현황

- **코드:** 찾지 못함(`02` §4). 논문에 코드 약속도 없음. 그래서 하이퍼파라미터·손실·평가 프로토콜은 부록 S2–S3의 서술만으로 대조해야 합니다. 논문에 있는 값: CfC 은닉 256, 임베딩 128, N = 512, K = 127, λ = 0.1, lr 1e-4, 에폭 500, 배치 8, Δt 4 ms.
- **논문에 없는 값(재구현 시 가정 필요):** 시퀀스 길이 T, 보간 방법, 이미지 해상도 H×W, GelSight 이미지 전처리, 온도 β 초깃값, CfC 구현체와 층 수, Direct predictor 구조, Slip-reactive의 임계값, 제어 이득(PID), µ·τ 분리에 쓴 위치별 곡률 변화 범위, 그림 2에 쓴 τ와 R*의 값.
- **데이터:** Squash는 프로젝트 웹페이지로 제공된다고 각주 1에 적혀 있습니다. 라이선스와 크기는 확인하지 못했고 내려받지 않았습니다.
- **시뮬레이터:** UIPC에 접착을 넣은 수정판. 수정 내용은 본문에 한 줄뿐입니다.

## 3. 관찰 요약

- 표 1의 두 행(Ours, Slip-reactive 이미지)은 편향과 과잉 − 부족이 맞지 않습니다. 인쇄 값 사이의 관계이며 원인은 알 수 없습니다. 저자 확인이 필요합니다.
- 그림 6d의 막대 25개와 본문의 29개 사이가 맞지 않습니다. 저자 확인이 필요합니다.
- 구간과 SD의 계산 단위가 본문에 없어 유의성 판단이 어렵습니다.

## 4. 구현 가능성 판정 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**논문 결과의 재현은 불가능합니다. 방법의 핵심 구조를 합성 데이터로 축소 구현하는 일은 이 맥의 CPU로 가능합니다.**

| 구분 | 가능 여부 | 이유 |
|---|---|---|
| 공식 코드 실행 | 해당 없음 | 코드 미공개 |
| 200k 시퀀스 UIPC 시뮬 생성 | 불가 | GPU IPC 솔버, 논문은 다중 GPU 노드 |
| 모델 학습(500 에폭, RTX 6000 Ada 8장 48 h) | 불가(원 설정) | 이 맥 MPS로는 규모 불일치. 축소판은 가능 |
| 실물 실험(UR5, WSG50, GelSight Mini, 로드셀 보드, Raspberry Pi) | 불가 | 장비 필요 |
| 식 1, 2, 5와 최소 힘 풀이, 그림 2 계열 민감도 | 가능(완료 일부) | `analysis/toy_hertz_reduction.py`, numpy, 수 초 |
| 해석적 Hertz 접촉으로 합성 시퀀스를 만들어 작은 순환망(GRU 등)과 InfoNCE로 사후를 추정하고 Class prior와 비교 | 가능(조건부: 학습 코드 새로 작성) | torch가 설치되어 있고 모델이 작음(은닉 256). CfC 구현은 없으므로 GRU로 대체 |
| MuJoCo로 변형체 대신 단순 접촉·접착 모델을 만들어 최소 힘 곡선 확인 | 가능 | mujoco 설치됨, 변형체 IPC 수준의 충실도는 아님 |
| Squash 내려받기와 class별 통계 재구성 | 조건부 | 크기·라이선스 확인과 사용자 승인 필요 |

**노력 추정(측정 전 추정):** 해석적 합성 데이터 + GRU 사후 추정 토이 1–2주. 변형체 시뮬(IPC)까지 가면 GPU와 UIPC 환경이 있어야 하며 수 주. 실물은 장비 한 벌(UR5급 팔, 평행 그리퍼, GelSight, 로드셀)이 있어야 시작합니다. 위 판단은 `03` T1과 부록 서술에서 나온 것이며 이 분석에서 학습·실행은 하지 않았습니다.
