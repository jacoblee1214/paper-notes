## 한 줄 요약

로봇 시연을 모으지도, 정책을 학습하지도 않습니다. VLM(Gemini Robotics-ER 1.6)이 지시를 원자 과제로 나누고 이미지에 2D 키포인트를 찍으면, **보정된 카메라 4대의 시점 쌍 삼각측량과 재투영 합의**로 그 점을 metric 3D로 올립니다. 도구 사용은 저장해 둔 물체 중심 6D 궤적을 장면에 맞추고, 파지는 여러 시점의 어포던스 박스로 정한 3D 영역에서 생성한 뒤, 팔-손 모션 계획기가 실행합니다.

## 1. 왜 다시점인가

MOKA나 ReKep 같은 zero-shot 방법은 VLM이 찍은 픽셀을 **단일 RGB-D 시점의 깊이**로 역투영합니다. 그런데 깊이는 물체 경계에서 불연속이라, 2D 오차 몇 픽셀이 용기 테두리를 넘으면 3D 점이 탁자로 떨어집니다. ZeroDex는 같은 질문을 여러 시점에 던지고, 시점 쌍마다 삼각측량한 후보 가운데 **가장 많은 시점과 재투영이 맞는 후보**를 고릅니다. 평균을 내지 않으므로 한 시점이 가려져 엉뚱한 곳을 가리켜도 버틸 수 있습니다.

이 메커니즘을 toy로 구현해 봤습니다. VLM 2D 출력에 시점별 편향, 실행별 흔들림, 5% 이상치를 넣고, Table IV처럼 10개 장면을 8번씩 반복했습니다.

![다시점 합의 toy](images/grounding_toy.png)

- 단일 RGB-D는 테두리에서 깊이가 튀어 긴 꼬리가 생깁니다. 다시점 합의에는 이 꼬리가 없습니다.
- 4대 구성에서는 **이상치 시점 하나까지만** 확실히 버팁니다. 둘이면 꼬리가 10 cm 수준이 되고, 셋이면 실패합니다.
- 주의할 점도 있습니다. 논문 식(Eq. 6)을 글자 그대로, 즉 지지 수가 같으면 먼저 나온 쌍을 쓰는 식으로 구현하면, 기선이 짧은 스테레오 쌍을 골라 미터 단위로 튀는 장면이 나옵니다. 최다 지지 후보의 inlier 시점 전체로 **다시 삼각측량하면** 해결됩니다. 합의 임계값 ε_tri도 VLM의 픽셀 오차보다 커야 합니다. v3 본문에는 이 값과 동률 규칙이 없고, v1 부록에만 20 px(640×480)라는 값이 있습니다.

## 2. 표를 다시 계산해 봤다

![Table I 다시 그리기](images/headline_success.png)

표 자체는 일관됩니다. All 열은 두 조건의 평균이고, Table II의 단계별 실패 합(12, 9, 3)은 Table I의 실패 수와 정확히 맞으며, Table V의 단계 분모도 이전 단계 성공 수와 이어집니다. 걸러 읽어야 할 점은 세 가지입니다.

- **표본이 작습니다.** 전체 17/20은 MOKA 8/20보다 확실히 높지만(Fisher p = 0.008), ReKep 11/20과는 p = 0.08입니다. 조건별로는 n = 10입니다.
- **VLA와의 격차는 파지에서 나옵니다.** 100개 시연으로 미세조정한 GR00T는 목표에 거의 항상 다가가지만(0.95), 잡기는 0.35뿐입니다. 잡은 7번 중 6번은 성공했습니다. 즉 "VLA가 1시간 시연으로 새 dexterous 손의 파지를 배우지 못한다"는 결과에 가깝습니다. 과제는 하나이고, ZeroDex는 카메라 4대, 자세 추정, 물체 메쉬, 파지 시뮬레이션을 쓴다는 점도 다릅니다.
- **"3배 반복성"은 평균이 만듭니다.** σ 8.1 대 2.5 mm는 3.24배입니다. 그런데 MOKA의 최악값 δ_max가 64.9 mm라서, 이것이 장면별 σ의 최댓값이라면 나머지 9개 장면의 σ 평균은 1.79 mm로 ZeroDex(2.5 mm)보다 오히려 작습니다. 침투 지표도 같은 구조입니다. P_avg, 충돌률, P_max가 동시에 성립하려면, 도구 사용 5개 장면 중 한 장면에서 MOKA는 9.5 cm 이상, ZeroDex도 6.7 cm 이상 박혀 있어야 합니다. 장면별 중앙값이 있었다면 해석이 훨씬 쉬웠을 것입니다.

## 3. v1과 v3는 거의 다른 논문이다

arXiv v1(6월)과 v3(10월)를 나란히 놓으면 바뀐 것이 많습니다.

| 항목 | v1 | v3 |
|---|---|---|
| 다시점 올리기 | 삼각측량 합의 + reference-view ray voting | 삼각측량 합의만 |
| zero-shot 기준선 | 단일 RGB-D 1개 | MOKA, ReKep |
| 시행 수 | 과제별 5회 | 조건별 10회 |
| VLA 미세조정 | 30개 시연, 둘 다 0/5 | 100개 시연, GR00T 0.30 |
| 침투 오차 | RGB-D 9.91 vs Ours 9.81 (거의 같음) | 충돌률 100% vs 17% (다른 지표) |
| long-horizon | 4/6, 1/3 (재시도 4회) | 8/10, 9/10 (재시도 1회) |

더 강한 기준선과 더 많은 시행으로 바꾼 것은 좋은 변화입니다. 하지만 핵심 기여였던 ray voting이 왜 빠졌는지는 설명이 없고, 프로젝트 페이지 초록은 아직 ray voting을 소개합니다. 하이퍼파라미터와 VLM 프롬프트 원문은 v1 부록에만 있습니다.

## 4. 본문에 드러나지 않은 가정: 물체 메쉬

어포던스 영역은 "물체 메쉬의 꼭짓점"을 박스에 투영해 투표하는 방식으로 정의됩니다(Eq. 9). 자세 추정(FoundationPose), 침투 깊이 계산, BODex 파지 최적화, 파지 안정성 시뮬레이션도 모두 메쉬가 필요합니다. 그런데 메쉬를 어디서 얻는지는 v1, v3 모두 적혀 있지 않습니다. "처음 보는 물체로 zero-shot"은 학습이 필요 없다는 뜻이지, 메쉬가 필요 없다는 뜻은 아닙니다.

## 5. 직접 구현할 수 있나

| 경로 | 판단 |
|---|---|
| 공식 코드 그대로 | 지금은 불가능합니다(코드 미공개). 공개되더라도 Franka나 xArm + Inspire 손, 보정 카메라 4대, NVIDIA GPU(FoundationStereo·Pose, BODex, cuRobo), 물체 메쉬, Gemini API가 필요합니다 |
| 그라운딩 계층만 | 가능합니다. VLM 질의와 다시점 합의는 API와 numpy면 되고, 스마트폰 카메라 몇 대와 체커보드 보정으로 실험할 수 있습니다. 이미지를 외부 API로 보내야 한다는 점은 고려해야 합니다 |
| 실행 계층 | 의존 코드는 대부분 공개되어 있지만, CUDA GPU와 로봇 하드웨어, 손 모델 설정이 관건입니다 |

## 6. 정리

- 아이디어는 단순하고 설득력이 있습니다. VLM의 2D 출력을 다시점 합의로 3D에 올리면, 깊이 센서의 경계 오류 없이 metric 목표를 얻습니다.
- 구현할 때는 inlier 재적합, VLM 오차에 맞춘 ε_tri, 합의 실패 감지가 필요합니다. 4개 시점은 이상치 하나까지만 버팁니다.
- 수치는 일관되지만 표본이 작고, 평균은 소수 장면이 좌우합니다.
- 물체 메쉬 가정과 v1 → v3 변경 이력을 알고 읽어야 합니다.
