## 1. Abstract (한 줄 요약과 주장)

**한 줄 요약:** 나사산처럼 시뮬레이션하기 어려운 접촉은 시뮬레이터에서 아예 빼고, **회전 동작만** 단순화된 모델(회전 관절 하나)로 RL 학습합니다. 그 정책을 텔레옵의 "손가락 회전 버튼"으로 써서 실제 촉각 데이터를 모으고, BC로 팔과 손가락을 함께 제어하는 촉각 정책을 학습합니다.

논문의 주장은 세 가지입니다.

1. 접촉이 많은 조작의 **기본 동작(finger gait)은 정확한 물리 모델 없이도 학습된다.** 너트와 볼트를 회전 관절로 근사해도 실제로 옮겨 쓸 수 있는 회전 gait가 나옵니다.
2. **시뮬레이션 정책을 기술 단위(skill primitive)로 쓰는 텔레옵이 다지 손 데이터 수집을 쉽게 만든다.** 사람은 손목만 조종하고 손가락은 RL 정책에 맡깁니다.
3. 촉각과 관측 히스토리를 쓰는 BC 정책은 직접 sim-to-real보다 진행률이 크게 높고, 처음 보는 너트 모양과 외란에도 강건하다.

## 2. Method

### 2.1 3단계 구조 (Fig. 2)

```
(A) 시뮬레이션 RL  ─ IsaacGym, 8,192 env, XHand 12-DoF, 200 Hz sim / 20 Hz 제어
    단순화 물체 = 고정 원기둥 받침 + 회전 관절(revolute)로 연결된 너트·손잡이 (나사산 없음, 축 방향 이동 없음)
    oracle(PPO, privileged info) → sensorimotor(proprio 30스텝 히스토리로 latent 추정, DAgger식 증류)
                │  JIT로 변환한 회전 정책 π_RL
                ▼
(B) 기술 기반 텔레옵 ─ Quest 2 컨트롤러: 조이스틱으로 손목 평행이동·yaw·pitch, 버튼으로 손목 상하 이동, 트리거로 π_RL 켜기
    기록: a_t = [a_t^Hand(12, π_RL 출력 또는 현재 관절), a_t^Arm(6)], q_t(18), 촉각 c_t ∈ R^{5×120×3}
                ▼
(C) BC ─ 입력: 최근 K=5 스텝의 (q, c), 촉각은 MLP로 압축 → hourglass encoder → H=16 action chunk
```

### 2.2 시뮬레이션 RL의 설계
- **단순화 물체 (Fig. 3):** 너트 작업에는 두꺼운 삼각 너트를 씁니다. 두꺼운 이유는 아래에서 밀어 올리는 편법을 막기 위해서입니다. 드라이버 작업에는 8각과 12각 손잡이를 씁니다. 저자들은 학습 물체의 모양이 gait의 성격(높은 clearance, 보수적인 동작)을 결정한다고 설명합니다.
- **행동:** 상대 목표 a_t^Hand = η·f(o_t) + a_{t−1}^Hand이고 PD 제어기로 토크를 만듭니다. 코드상 η는 0.05(드라이버), 0.04167(너트)이고 `clipActions 1.0`입니다. 따라서 관절 목표 속도는 20 Hz에서 최대 약 1.0 rad/s와 0.83 rad/s로 묶입니다.
- **보상:** 다음 항들의 가중합입니다(가중치는 Table IV).
  - 회전 속도 보상(±4 rad/s로 clip)
  - 근접 보상(엄지·검지 거리)
  - 토크 페널티와 일(work) 페널티
  - 초기 자세 이탈 페널티
  - 과속 페널티(10 rad/s 초과. 드라이버는 7.5에서 15로 커리큘럼)
- **종료 조건:** 손가락이 물체에서 멀어짐(너트 7 cm, 손잡이 10 cm), 회전 정체(3–3.5 s), 무접촉 지속
- **랜덤화 (Table V):** 마찰 계수 [0.5, 8.0], 질량 [0.04, 0.06] kg, 스케일, PD 게인, 관측·행동 잡음, 확률 0.25의 외력

### 2.3 기술 기반 텔레옵
- 사람이 직접 하는 일은 **손목 위치를 맞추고 회전 기술을 켜는 것뿐**입니다. 사람과 로봇 손의 형태 차이 때문에 생기는 손가락 텔레옵의 어려움을 이렇게 우회합니다.
- 나사산 때문에 생기는 **축 방향 하강은 시뮬레이션에서 일부러 뺐고, 사람의 팔 조작이 이것을 보완합니다.** 이 부분이 핵심 설계입니다.
- 수집량: 너트 작업은 사각·삼각 너트 각 50회(약 80 s/회), 드라이버 작업은 72회(120–180 s/회)입니다.

### 2.4 BC
- 비전은 쓰지 않고 관절 위치와 촉각만 씁니다. 손실은 action chunk 전체의 L2이고, Adam으로 200 epoch 학습합니다.
- 배포 코드는 겹치는 chunk를 **균등 평균하는 temporal ensembling**(`temporal_ensemble_mode="avg"`)을 씁니다. 논문 본문에는 언급이 없습니다.

### 3.3 시뮬레이션 ablation (Fig. 7, 시드 5개)
privileged info를 쓴 oracle이 가장 좋았고, asymmetric actor-critic(critic만 privileged)이 그다음, privileged info를 전혀 쓰지 않은 경우가 가장 나빴습니다. 학습을 더 오래 해도 격차가 줄지 않았다고 보고합니다.

### 3.4 해석: 수치를 어떻게 읽을 것인가 (`03_analysis.md` §1에서 재계산)
- **촉각+히스토리가 히스토리만 쓴 경우보다 낫다는 주장은 너트별로는 유의하지 않습니다.** Welch p는 0.16–0.37이고 드라이버는 0.31입니다. 4종을 합친 40회 기준으로는 평균 차이가 경계선(순열검정 p≈0.04)이고, 순위 기준(Mann-Whitney)으로는 유의하지 않습니다(p 0.10–0.36).
- **촉각의 효과는 "실패 꼬리 제거"로 보는 편이 정확합니다.** 진행률 75% 미만인 시행이 히스토리만 쓰면 40회 중 5–8회이고, 촉각+히스토리는 0회입니다(Fisher p 0.005–0.055). 평균을 올린다기보다 최악의 경우를 없앱니다.
- **히스토리의 효과가 더 뚜렷합니다.** 삼각 너트에서 p=0.007, 십자 너트에서 p=0.007입니다.
- **촉각 단독의 효과는 거의 없습니다.** 너트(사각·육각)와 드라이버 모두 차이가 0에 가깝습니다(드라이버 p=0.92). 저자들도 "히스토리가 없으면 촉각의 이득이 제한적"이라고 썼습니다.
- **"BC가 데이터를 만든 정책보다 낫다"(69.2 vs 50.8)는 주장도 n=10에서는 유의하지 않습니다**(p=0.17). 저자들이 근거로 든 filtered BC(성공 시행만 학습)도, 공개된 데이터 변환 코드에는 성공 여부로 거르는 단계가 없습니다(`04` D5).

## 4. Limitations

### 4.1 저자가 밝힌 한계
- 텔레옵에 여전히 사람이 필요합니다.
- 너트가 이미 볼트에 걸려 있고 드라이버가 이미 나사에 꽂혀 있는 상태에서 시작합니다(장기 조립은 다루지 않음).
- 비전과 정밀한 힘·토크 센싱을 쓰지 않습니다.
- 과제가 두 개뿐입니다.

### 4.2 분석하면서 추가로 발견한 한계와 의문점
1. **공개 코드의 privileged info가 논문 설명과 다릅니다.** 인덱스가 겹치는 버그 때문에 oracle은 물체 질량·마찰·스케일·각속도·접촉 여부를 보지 못합니다(`04` D1, 상위 코드 penspin과 대조해 확인). 따라서 Fig. 7의 "privileged info가 중요하다"는 결과는 "**동역학 파라미터 식별**"(RMA식 해석)이 아니라 "**너트 회전 상태와 손끝 상태 관측**"의 효과로 다시 읽어야 할 수 있습니다. 다만 논문 실험에 이 코드 버전이 쓰였는지는 확인할 수 없습니다.
2. **통계적 검정력이 낮습니다.** 조건당 10회로는 σ≈20, 효과 10%p를 80% 검정력으로 검출할 수 없습니다(필요 n≈63). 신뢰구간이나 검정이 하나도 보고되지 않았습니다.
3. **진행률 지표의 정의가 불완전합니다.** "필요한 회전 수"가 명시되지 않았습니다. Table I의 16칸은 모두 8회전(12.5% 단위) 가정과 정확히 맞으므로 데이터는 내부적으로 일관됩니다. 드라이버 표는 단위가 일정하지 않아 연속값으로 측정한 것으로 보입니다.
4. **수치 불일치가 있습니다.** 본문은 oracle 학습을 1.5×10⁹ step이라고 하고, Table VI와 Fig. 7의 x축은 3×10⁹입니다. Table III은 손끝 2개(엄지·검지) 기준 97차원이라고 하지만, 코드는 손끝 5개 기준입니다(드라이버 84차원, 너트 127차원).
5. **보상에 정의되지 않은 항이 있습니다.** Table IV의 λ_pc-z(−1.0)는 본문에 정의가 없습니다. 코드를 보면 물체 point cloud의 z 범위에 대한 페널티인데, 물체 받침이 고정되어 있어서 **행동과 무관한 상수**가 됩니다(`04` D3).
6. **"시뮬레이션이 불완전해도 된다"는 범위가 좁습니다.** 실제로 빠진 것은 나사산이 만드는 회전-하강 결합 하나이고, 이 결합을 사람이 대신 해 줍니다. 더 복잡한 접촉(마찰 변화, 걸림)을 다루는 과제로 일반화될지는 보여주지 않았습니다.
