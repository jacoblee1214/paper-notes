# 04. 주장 대조와 구현 가능성

공식 코드가 아직 없습니다(`02` §2: 프로젝트 페이지의 코드 칸이 "Code Coming soon", 저자 계정의 저장소는 정적 사이트뿐). 그래서 코드와 논문의 대조(D 항목) 대신 **논문의 주장(C 항목)을 표·그림 수치와 대조**합니다. 근거는 `03`의 계산(V, K 항목)과 원문 위치입니다. 판정 어휘는 다음과 같습니다.

- **지지**: 표·그림 수치가 주장과 맞고 가능한 대안 설명이 약함.
- **부분 지지**: 수치는 맞지만 비교 조건이나 해석이 열려 있음.
- **방향만**: 효과의 방향은 맞지만 시행 수나 시드 때문에 크기·순서를 확정하기 어려움.
- **미검증**: 논문 안의 증거로는 판단할 수 없음.

## 2. 판정 요약

- **지지:** C2(산술), C4, C21.

- **방향만:** C3, C5, C9, C10, C12, C13.
- **미검증 또는 조건 불명:** C14, C16, C17, C18, C19, C22, C23.

핵심 인상: 이 논문의 표 산술은 모두 맞고(V1, V2, V13) 성공률 순서도 일관됩니다(LiMA가 어떤 과제에서도 최고에서 밀리지 않음, 과제 단위 부호 검정 VPP·Cosmos-Policy 대비 p = 0.031). 그러나 **과제당 20회로는 강한 VLA 기준선(GR00T N1.6, InternVLA-A1)과의 5–10 포인트 차이를 구분할 수 없고**(검출 한계 약 28–34 포인트, `03` V16), 절제 표 3은 시행 수가 적혀 있지 않습니다. 설계 주장 중 가장 얇은 곳은 **브리지가 가우시안 시작 + 교차 주의나 흐름 정합보다 낫다는 인과 주장(C9, C15)**과 **식 5의 시작 분산과 표 3(c)의 지연 양립(C14, C12)**입니다. 공식 코드가 공개되면 우선 C14(σ_1), C23(슬롯 대응), C19(지연 측정)를 코드에서 확인할 수 있습니다.

## 3. 구현에 필요하지만 논문에 없는 설정

코드가 없으므로 아래 항목은 재구현 때 정해야 합니다(`01` §6).

1. 학습 때 Z_int의 출처(Dreamer 실제 출력인지 정답 기반인지), 기울기 흐름, 두 손실의 가중치 λ.
2. 경계 쌍의 슬롯별 대응과 X_1 = Z_int가 Z_out과 같은 모양이 되는 방식(K8).
3. β 스케줄, σ_1, 이산 스텝 수, 샘플러(K7, C14).
4. 학습과 추론의 디노이징 스텝 수(Dreamer, Refiner)와 표 3(b), (c)의 정의.
5. Refiner 1B의 깊이·폭·헤드 수, 조건화 모듈, 행동 토큰 길이, "multi-action tokens"의 정의.
6. 총 학습 스텝, GPU 수, 시드의 의미, 표 3의 과제와 시행 수.
7. 제어 주기와 청크 중 실행하는 행동 수, 비동기 실행 구현(Dreamer 호출 스레드 분리 방식).
8. 기준선 학습 설정(Cosmos-Policy, VPP, InternVLA-A1), 시연 데이터(과제당 100)의 공개 여부.

## 4. 구현할 수 있는가 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**논문 수치의 재현은 이 맥에서 불가능합니다. 구조의 축소판 재구현(소형 Dreamer–Refiner + 브리지)과 수치 검증은 가능하고 후자는 끝냈습니다.** 공식 코드가 없고, 가중치와 시연 데이터가 공개되지 않았으며, 실험이 특수 하드웨어(양팔 UR5 + SharpaWave 22-DoF 손 두 대)를 전제합니다.

| 단계 | 필요한 것 | 이 맥 | 노력 (추정) |
|---|---|---|---|
| 표 재계산, 일관성 검사, 정확한 디노이저 토이 | 논문 PDF | 가능, 완료 (`recompute.py`, `toy_bridge_posterior.py`) | 완료 |
| 브리지 사후분포 + x_0 예측 Refiner를 작게 직접 구현(수 M 파라미터, 합성 궤적 과제)해 "구조화된 시작 대 가우시안 시작 + 교차 주의"를 학습으로 비교 | torch(설치됨), 새 코드 작성, 합성 데이터 | 가능 (CPU/MPS, 시드 여러 개). 논문 수치와 직접 비교 불가 | 3–5일 |

- **GPU·로봇·데이터가 필요한 것:** Dreamer 미세조정과 Refiner 학습, 표 1–3과 그림 5의 실로봇 평가, 시연 600개(6 × 100), 지연 측정(H100).
- **이 맥에서 할 수 있는 것:** 구조의 소형 구현(브리지, x_0 예측, 비동기 주기), 논문 수치의 재계산과 검정(완료), 지연 산술(FLOPs 어림, `03` V15).
- 공식 코드와 체크포인트가 공개되면 체크포인트 추론의 MPS 포팅 가능성을 다시 볼 수 있습니다(가중치 크기는 공개 전이라 모릅니다). 3B 파라미터(bf16 약 6 GB)는 24 GiB 안에 들어가지만 Cosmos 계열 코드가 CUDA 전제라 포팅이 필요할 것으로 어림합니다(공식 코드를 열어 보지 않은 추정).
