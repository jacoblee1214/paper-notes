# 04. 주장 검증 (공식 코드 없음)

분석일 2026-11-21. 공식 코드는 아직 공개되지 않았습니다(프로젝트 페이지 "Code (Coming Soon)", ). 그래서 코드 대조 대신 **논문 주장 C1–C18을 표·그림 수치, 재계산(`03`), 본문 서술과 맞춰 판정**했습니다. 저장소를 clone하지 않았고 아무 것도 실행하지 않았습니다.

판정 기준
- **확인**: 표 값과 재계산이 주장과 맞고, 검정으로도 뒷받침됨
- **부분**: 방향은 맞지만 범위, 검정, 교란 중 하나가 문제
- **미확인**: 근거가 없거나 원자료·코드가 필요
- **불일치**: 표 값이나 재계산이 주장과 어긋남

## 2. 판정 요약

- **확인**: C2, C3, C4, C5(세 과제), C8, C12, C16 (방향), C29
- **부분**: C1, C7, C9, C10, C13, C15, C17, C18, C19, C20, C27, C28
- **미확인**: C6(차이 없음), C11, C14, C21–C26

**요약**: 힘 생성 과제(E2E 대 E2C)와 닦기 등 접촉 타이밍 과제의 결과는 강하고 재계산으로도 맞습니다. 동적 과제(무게 분류, 던지기, 지연)는 교란이 있거나 신호가 약합니다. 논문이 주장하는 "모든 과제에서 일관된 우위"는 **지지되지 않습니다.**

## 3. 교란과 재현 장벽

1. **추론 방식 교란**: π0 Sorting, Tossing에서 EC2C만 inpainting입니다(`03` §1.3). 같은 추론 방식의 대조가 없습니다.
2. **seed와 반복 없음**: 모든 값이 단일 실행입니다. 시도 20회 중 16회처럼 작은 차이는 학습 변동과 구분할 수 없습니다.
3. **데이터 교란**: 조작자는 측면 카메라와 질량 정보를 씁니다. 방법마다 데이터가 같았는지 명시되지 않았습니다.
4. **하이퍼파라미터 누락**: d_max, DP 학습 설정, 조건별 데모 수가 없습니다.

## 4. 구현 가능성 판정 (이 맥 기준)

**판정: 방법은 쉽게 구현할 수 있습니다. 논문 수치는 이 맥에서 재현할 수 없습니다.**

- **구현 가능 (코드 수준)**: EC2C는 입력 인코더만 바꾸고 손실과 샘플러는 그대로 둡니다(B.3). DP와 π0 입력 인코더에 명령 이력과 마스크를 붙이는 변경은 수백 줄 이내입니다. 추정 노력 **2–4일**(측정 전).
- **이 맥 (Apple M4 Pro, 24 GiB, MPS, CUDA 없음)에서 가능한 것**: 소형 DP를 CPU 또는 MPS에서 돌리는 토이(시뮬 1-DoF 또는 합성 데이터). 수 분 단위. 추정 노력 1–2일. 이는 방법이 "작동하는 구조인가"만 확인합니다. 논문 수치와는 무관합니다.
- **불가능한 것**:
  - π0 (3B) 학습: A100 80GB 전제, 30,000 스텝. 이 맥에서 실용적이지 않습니다.
  - 실로봇 (ARX-R5/X5, 힘 측정 스케일): 장비가 없습니다.
  - 공식 코드: 미공개.
- **가장 실용적인 검증 경로**: 이미 있는 저비용 텔레옵 로그(같은 mismatch 정의 ε = C − E)에서 E2C와 EC2C 입력만 바꾼 MLP 대조. 이는 실물 2×2 대조와 같은 질문이며 CPU로 가능한 범위입니다.
