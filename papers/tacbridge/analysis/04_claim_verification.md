# 04. 주장 검증: TacBridge (arXiv:2611.20939)

## 0. 검증 방식과 이유

**공식 코드와 프로젝트 페이지가 없어 04_code_verification.md 대신 이 문서를 씁니다.** 코드 대조(D1–Dn)는 할 수 없고, 논문의 주장(C1–C14)을 논문 안의 수치와 식, 그리고 `03_analysis.md`의 재계산으로 판정합니다.

확인 내역은 `02_prior_work.md` §1–2에 있습니다: arXiv 연결 없음, GitHub 검색 0건, 프로젝트 페이지 없음, 학회 표기 없음.

판정 기호: **지지** (논문 수치와 재계산이 일치), **부분 지지** (방향은 맞으나 증거가 약함), **미검증** (필요한 자료가 없음), **충돌** (논문 내부 또는 주장과 수치가 맞지 않음).

## 2. 충돌 세부

### C5: TacQuad 쌍의 정렬

- Introduction (33–35행): "TacQuad provides synchronized real observations from DIGIT, GelSight Mini, and DuraGel."
- §IV-C (321행): "Real TacQuad pairs are progress-matched rather than synchronously recorded, so they are used for cross-sensor correspondence learning but not as ground truth for frame-level translation evaluation."

두 문장이 충돌합니다. §IV-C가 더 구체적이므로 실제 정렬은 진행률 맞춤이라고 보는 것이 자연스럽습니다. 그러면 Introduction의 "synchronized"가 틀렸거나 과장입니다. 이 차이는 **사전학습 손실의 프레임 단위 의미**에 영향을 줍니다. 진행률 맞춤이면 프레임 k의 X_a와 X_b가 같은 시점이 아닐 수 있으므로, 식 (3)의 프레임 대응과 차분 손실 (V_b, ΔX̄_b)이 잘못 짝지어질 수 있습니다. 논문에 정렬 방법(예: 동적 시간 정렬)이 없어 확인할 수 없습니다.

### C8과 C9: 일반화 주장의 범위

§IV-D의 OOD 테스트는 **5 직물, 1 센서 (GelSight)**입니다. 기준선과의 차이 2.8 pp는 직물 단위 분산 가정에 따라 유의할 수도 있고 아닐 수도 있습니다 (`03` §3.2). "새 실로봇 데이터에 대한 일반화를 보였다"는 표현은 방향성 증거 수준입니다.

## 3. 저자 주장 중 검증이 가장 필요한 것

1. **C10 (쌍의 기여).** 이 논문의 핵심 차별점인데 절제 실험이 없습니다. 쌍 없는 같은 구조(마스크 재구성만, 같은 데이터)와 비교해야 주장이 성립합니다.
2. **C14 (기준선 공정성).** AnyTouch, Sparsh MAE/V-JEPA의 사전학습 데이터와 예산이 TacBridge와 같은지 모릅니다. TacBridge는 TacQuad와 ToucHD-Sim 쌍을 쓰므로 데이터가 더 많을 수 있습니다.
3. **C5 (TacQuad 정렬).** 사전학습 손실의 의미를 바꿉니다.
4. **C8 (OOD 검정력).** 5 직물로는 2–3 pp 차이를 판정하기 어렵습니다. 직물 수를 늘린 평가가 필요합니다.

**노력 추정 (측정 전):**
- 식 (3)–(12)를 PyTorch로 옮기고 장난감 데이터 (합성 촉각 클립 몇백 개)로 형상과 손실 값을 확인하는 작업: 약 1주.
- 공개 데이터 일부로 축소 사전학습 후 선형 탐침 비교: 약 2–4주. 데이터 준비와 MPS 학습 시간이 주된 변수입니다.

이 맥에서는 설계 검증 (식 (11) 검산, 쌍 손실 절제의 장난감)까지만 합리적입니다. 장난감 실험은 C10 (쌍의 기여)을 **방향만** 확인할 수 있습니다.
