# 04 서베이 주장 검증 (claim verification)

**왜 코드 대조가 아니라 주장 검증인가.** 이 서베이는 새 방법을 제안하지 않습니다. 대조할 구현이 없습니다. 공식 저장소(`NTUMARS/Awesome-World-Model-for-Robotics-Policy`)는 큐레이션 목록이라 방법의 구현이 아닙니다(02 §5). 그래서 `04_code_verification.md` 대신 서베이 자신의 주장(C1–C16)을 검증했습니다. 저장소는 얕게 클론해 README 구조와 링크만 정적으로 읽었습니다.

**판정 기준.** 지지 = 재계산이나 문헌 확인으로 맞음, 부분 = 맞지만 조건이나 범위가 있음, 불일치 = 틀렸거나 출처가 맞지 않음, 확인 불가 = 서베이 밖의 자료가 필요함.

## 2. 가장 중요한 불일치

1. **Table 1의 저자 오류(C9).** 명백한 오기입니다. 본문에는 맞게 적혀 있어서 편집 과정의 실수로 보입니다.
2. **Motus와 LingBot-VA의 분류(C10).** 서베이 안에서 세 곳이 서로 다릅니다. 분류를 재정의하지 않으면 독자는 어느 쪽을 믿어야 할지 모릅니다. 세계 모델 결합 방식의 기준으로는 Table 1의 MoT가 더 일관됩니다.
3. **UniPi 수치의 출처(C8).** 원논문과 맞지 않는다면 표 5·6 전체의 신뢰도가 떨어집니다. 서베이 저자에게 확인을 요청할 수 있는 항목입니다.

## 4. 구현 가능성 판정

**서베이 자체의 주장 검증: 이 맥에서 가능하고, 이번 분석에서 완료했습니다.** 재계산, 문헌 대조, 저장소 정적 읽기는 CPU와 메모리 몇 GB로 충분합니다.


**CPU 축소판:** 서베이의 분류 자체는 실험으로 검증할 대상이 아닙니다. 그래서 축소판 toy는 만들지 않았습니다. 표 5의 500회 정수 검사와 검정 가정 민감도는 이미 CPU로 확인했습니다.

**노력 추정(미측정, 대략):** 남은 일인 원논문 본문에서 표 값 확인과 저자 문의는 방법당 수십 분 수준으로 보입니다. 표에 있는 방법 수를 고려하면 하루 안팎의 작업으로 추정합니다.
