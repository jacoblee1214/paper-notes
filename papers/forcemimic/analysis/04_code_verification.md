## 3. 차이와 빈칸 (D1–D23)

### 3.1 학습과 모델

- **D1. 에포크 수.** 본문은 500 에포크라고 쓰고, 공식 학습 설정은 `num_epochs: 1000`이며, 배포용 설정은 `model_epoch_1000.pth`를 씁니다. 논문 결과가 500인지 1000인지 알 수 없습니다. 체크포인트 저장 간격은 200 에포크입니다.
- **D6. 점군 인코더.** 본문은 "MLP"라고 하고, 코드는 PointNet입니다(공유 MLP 1D 합성곱 + 최대 풀링). 최대 풀링으로 점 순서에 무관한 전역 특징을 얻습니다. 논문의 "MLP"는 PointNet을 가리키는 것으로 보이지만, 본문만으로는 구분할 수 없습니다.
- **D8. 이력 조건.** Fig. 2는 "history pose" 조건을 보여 주지만, 설정과 실행 모두 `observation_horizon = 1`(이력 없음)입니다.
- **D10. 손실 가중치.** 본문은 "MSE loss"라고만 씁니다. 코드는 노이즈 예측 손실을 **위치와 쿼터니언(처음 7차원)에 0.7, 힘-토크(나머지 6차원)에 0.3**으로 나눕니다. 이 가중치는 논문에 없습니다.
- **D17. 확산 세부.** 코드는 DDIM(10 추론 스텝, ε 예측, squaredcos 스케줄, 학습 스텝 100), UNet 채널 256/512/1024, 커널 5, EMA **끄기**를 씁니다. 논문은 이 가운데 어느 것도 쓰지 않습니다.
- **D18. 검증과 시드.** 검증 세트가 없고(`validate: false`), 시드는 1 하나입니다. 논문은 시드 수와 검증 방법을 쓰지 않습니다.
- **D11. 자세 증강(본문에 없음).** `get_item`은 항상 `_augmentation_pose`를 호출합니다. 무작위 변환의 범위는 x ±5 cm, y ±4 cm, z −4~5 cm, 수직축 회전 ±60°입니다. 점군, 자세, 행동 위치와 쿼터니언에 적용하지만, **힘-토크 열은 회전하지 않습니다**. 힘의 좌표계가 증강 프레임과 같다면 힘도 같은 회전을 받아야 합니다. 저장소에는 이 점을 설명하는 주석이 없습니다. 영향은 실험으로 확인하지 않았습니다.

### 3.2 데이터 수집과 전처리

- **D2. 주파수.** 본문은 F/T 1000 Hz라고 씁니다. 코드는 두 브랜치 모두 힘 센서를 `fps = 200`으로 엽니다. 드라이버 내부 기록 주파수가 1000 Hz일 수 있으므로 결정적이지 않습니다. 엔코더 30 Hz는 일치합니다.
- **D7. 점군 크기.** "10,000 크기로 복셀화"는 복셀 크기 1 mm와 무작위 샘플 10,000점으로 구현됩니다(`pc_num = 10000`, `voxel_size = 0.001`). 본문 표현은 두 가지 모두로 읽힙니다.
- **D12. 프레임 선택(본문에 없음).** 병합 단계는 자세 변화 3 mm, 힘 변화 3 N(`pyft_f_threshold = 3`) 기준으로 프레임을 고릅니다. 힘 변화 기준은 `delta_xyz`로 계산합니다. 선택된 프레임 수와 탈락 비율은 본문에 없습니다.
- **D14. 행동 시차.** "행동을 관측보다 3스텝 앞당김"을 구현하는 코드는 저장소에 없습니다. `action_with_wrench` 키는 설정과 데이터셋 로더에만 나오고, 생성 스크립트는 없습니다. 따라서 데이터 구조의 정확한 정의(프레임 정렬, 힘의 좌표계)는 확인할 수 없습니다.
- **D13(참고). 중력 보정.** `tare_pyft.py`는 준정적 기록 뒤 최소제곱으로 질량, COM, 오프셋을 추정합니다. 본문과 맞습니다. 보정 정확도는 저장소에도 본문에도 없습니다.

### 3.3 추론과 로봇 실행

- **D3. 프리미티브 스위칭 규칙.** 본문은 "6 N을 **연속된** 스텝에서 넘으면" 하이브리드 제어로 바꾼다고 씁니다. 코드(`eval.py`)는 **예측 구간 전체의 비율**로 판단합니다. 처음에는 힘이 6 N을 넘는 스텝이 20%(`force_num_threshold = 0.2`)를 넘는지 보고, 이후에는 **모든 스텝**(`== Na`)이 넘는지, 또는 20%를 넘는지에 따라 바꿉니다. 연속성 조건은 코드에 없습니다. 임계를 바꾸면 결과가 달라질 수 있습니다.
- **D4. 접촉 전 누르기.** 본문은 접촉 전에 힘 방향 반대로 누르는 제어를 쓴다고 하지만, 저장소에서 해당 코드를 찾지 못했습니다. 로봇 SDK(`flexivrdk`) 쪽에서 처리하는지는 알 수 없습니다.
- **D5. 힘 제어 축과 방향 정의.** 코드는 `setForceControlFrame("BASE")`와 `setForceControlAxis([F, F, T, F, F, F])`를 씁니다. 즉 **BASE 좌표계의 z축 하나만 힘 제어**합니다. 논문의 "움직임 방향에 수직인 평면에서의 힘 제어"와 같은 뜻인지 확인할 수 없습니다. 움직임 방향 `cvt_hybrid_parameters`가 계산한 직교 힘은 6차원 목표로 보내지고, 제어기가 그중 z축만 쓰는지는 로봇 SDK 설명에 달려 있습니다. 정적 읽기로는 결정할 수 없습니다.
- **D22. 실패 조건.** 예측 구간의 끝과 시작 사이 거리가 5 mm보다 짧으면 `RuntimeError`를 냅니다(움직임 방향을 정할 수 없음). 저자들의 실행 기록에서 이 경우가 얼마나 자주 나왔는지는 없습니다.
- **D9. 실행 구간.** 예측 지평 20, 실행 구간 10입니다(`act_horizon = 10`). 10스텝을 실행한 뒤 다시 추론합니다. 본문에는 실행 구간이 없습니다.
- **D15(참고). 입력 키.** `eval.py`는 `robot0_eef_wrench`를 서버로 보내지만, 학습 설정의 관측 모달리티에는 없습니다. 따라서 정책은 힘을 **입력으로 받지 않습니다**. 이는 HybridIL의 설계와 맞습니다.
- **D19. 환경.** Python 3.8, diffusers 0.11.1, pin 3.4.0, flexiv_rdk 0.9.1이 고정되어 있고, 로봇 IP와 절대 경로가 코드에 하드코딩되어 있습니다. 저장소를 다른 환경에 옮기려면 수정이 필요합니다.

### 3.4 저장소에 없는 것

- **D16. 원격조작 비교 코드.** RH20T 설정을 따른 원격조작 수집 코드는 없습니다.
- **D20. 데이터셋.** 처리된 데이터셋은 Google Drive에 있습니다. 이번 분석에서 받지 않았습니다. 크기와 구성은 확인하지 않았습니다.
- **D21. 기준선.** Raw DP, Force DP, Force+Hybrid DP의 학습 코드와 설정이 없습니다. 공식 설정은 `train_dp_ftout.json`(힘-토크 출력, 힘 입력 없음)뿐입니다. 표 I의 기준선은 이 저장소로 재현할 수 없습니다.
- **D23. 평가.** 성공 판정(동작 올바름, 10 cm 기준)과 수집 효율 측정 코드가 없습니다.
- **D24. 체크포인트.** 학습된 체크포인트는 공개되지 않았습니다. 설정이 가리키는 `logs/...` 경로는 로컬 산출물입니다.

## 4. 구현 가능성

**판정: 이 맥(Apple M4 Pro, 24 GiB, MPS, CUDA 없음)에서 논문 결과를 재현할 수 없습니다. 정책 학습 코드의 구조는 CPU로 옮겨 볼 수 있지만, 데이터, 로봇, 기준선이 없습니다.**

| 무엇 | 이 맥에서 | 근거 |
|---|---|---|
| 손 장치 수집 (F/T 센서, T265, L515) | **불가** | 하드웨어 필요. L515와 T265는 단종(README). 센서는 Flexiv 제품(README) |
| 로봇 실행 (Flexiv Rizon 4, RDK 0.9.1) | **불가** | 로봇과 실시간 제어기 필요. 맥에서 SDK 지원 없음 |
| 학습 (30,199 시퀀스, 1000 에포크) | **불가(추정)** | 배치 32, 점군 10,000점 PointNet + 1D UNet, 확산 학습. GPU 권장, 시간 미측정. MPS에서 pin 3.4.0과 open3d 설치 여부 미확인 |
| 데이터 처리 파이프라인 | **조건부** | 원시 데이터가 없음. 저장소의 스크립트는 Linux 전제(pyrealsense2 2.53.1, open3d 0.18, Linux 경로) |
| 정책 구조의 CPU 축소판 (PointNet 64차원 + 확산 1D UNet, 합성 힘 데이터) | **조건부** | torch는 설치되어 있으나 diffusers 0.11.1과 robomimic 기반 코드는 새로 설치가 필요함(승인 필요, 노력 2–3일 추정) |
| 힘 프리미티브 로직 (임계, 사영, 방향 정의)의 순수 계산 검증 | **가능** | numpy만으로 `cvt_hybrid_parameters`와 스위칭 규칙을 옮길 수 있음 |
| 표 I 재계산 | **완료** | `03` §1 |

- **노력 추정.** 축소판 정책 학습까지 2–3주. 공식 학습 파이프라인을 CUDA 기기에서 돌리는 데 데이터 내려받기와 환경 구성 2–3일, 학습 하루 이상(에포크 수에 따라 변동). 실로봇 재현은 장비를 갖춘 뒤 수 주입니다.
