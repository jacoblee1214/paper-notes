# 04. 주장 검증과 구현 가능성: DexFLEX (arXiv:2610.14372)

공식 코드가 없어(`02` §4, 2026-11-22 확인) 논문↔코드 대조(D 항목)는 할 수 없습니다. 대신 논문과 프로젝트 페이지가 말하는 **주장 C1–C12**를 표·그림·본문 수치로 재계산하고, 증거가 주장을 얼마나 지지하는지 판정합니다. 재계산의 상세는 `03`(V, K 번호)에 있습니다. 판정 어휘는 **지지됨**, **부분 지지**(방향은 맞으나 크기·원인이 미확정), **미확정**(증거가 구분하지 못함), **확인 불가**(필요한 정보가 없음)입니다.

## 2. 코드 없이 검증한 것과 못 한 것

**한 것:** 표 2 전 셀, 평균, 정수 가능성, 본문 문장 수치(`03` V1–V4), 풀링·과제별 검정(V5, V6), 그림 5 막대 라벨과 비율(V8), 그림 3 벡터 판독과 표 1 대조(V9), 검정력(V10), 선택 toy(K2).

**못 한 것:** 방법의 어떤 구성 요소도 실행하지 않았습니다. 시뮬레이션 평가(표 1, 그림 3)의 값은 판독만 했고 독립 재현은 없습니다. 영상(프로젝트 페이지)은 열지 않았습니다.

## 4. 구현할 수 있는지 (이 맥 기준)

**판정:** **논문의 결과는 이 맥에서 재현할 수 없습니다. 핵심 알고리즘(상태 조건 프라이어, 후보 선택 루프, 대조 점수)은 MuJoCo 축소판으로 구현해 볼 수 있지만, 논문 수치와 직접 비교할 수는 없습니다.** 코드가 없고 부록이 없어 논문 그대로의 재구현 자체가 막혀 있습니다.

### 4.1 이 맥(Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음)에서 가능한 것

| 항목 | 가능 여부 | 이유 |
|---|---|---|

### 4.3 노력 추정 (추정, 측정 전)

- **알고리즘 코드(축소판):** 프라이어 + 세계모델 + 대조 점수 + 선택 루프 + 해독기를 소형으로 짜면 500–800줄. 이 맥에서 수 시간 학습으로 추정.
- **축소 환경과 데이터:** MuJoCo LEAP 손으로 물체를 쥔 채 손끝 움직임을 수행하는 과제, 접촉력 기반 대리 촉각(손끝 센서 사이트별 힘), 전문가는 IK + 스크립트로 만들면 1–2주. RL 전문가를 학습하면 추가 2–3주(이 맥 CPU 처리량은 측정하지 않음).
- **열화 평가:** 논문의 네 가지 열화를 구현하는 것은 수십 줄. 해석은 "논문 수치의 재현"이 아니라 "선택 단계가 접촉 상실을 줄이는가"의 질적 점검입니다.
- **합계:** 축소판 약 2–4주(추정). 논문 수치의 재현은 노력이 아니라 **자원(GPU, 로봇, 부록 정보)** 이 막습니다.

### 4.4 한 줄 결론

`구현할 수 있는지`: 논문 재현은 **불가**, 핵심 선택 루프의 MuJoCo 축소판은 **조건부 가능**(2–4주 추정). 지금 당장 이 맥에서 끝낸 것은 표·그림 재계산과 후보 선택 toy입니다.
