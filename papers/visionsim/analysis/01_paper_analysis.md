## 1. 한 문단 요약

VisionSIM은 Blender로 노이즈 없는 장면과 조밀한 정답(깊이, 법선, 광류, 장면 흐름, 분할, 점 지도, 직간접 조명, 온도 지도)을 한 번 렌더링하고, 그 결과를 센서별 물리 모델에 흘려 보내 원시 측정(광자 히스토그램, 상관 탭, 비동기 이벤트, 열 복사)을 만드는 시뮬레이터입니다(Sec. 3, 그림 1). 단일 광자 dToF LiDAR, iToF LiDAR, 열화상, 이벤트 카메라, 수동 SPAD, 일반·고속 카메라, 스테레오, IMU를 지원한다고 주장합니다(표 1, 표 2). 핵심 주장은 두 가지입니다. 첫째, 센서를 이상화하면 파일업, 위상 접힘, 불응기, 열 관성 같은 실패 모드가 사라져 sim-to-real 간격이 숨겨집니다(Sec. 1). 둘째, 렌더링과 센서 에뮬레이션을 분리하면 한 장면을 여러 센서 설정으로 추가 렌더링 비용 없이 비교할 수 있습니다(Sec. 3, Sec. 5). 증거는 사례 연구 세 개(dToF 디지털 트윈, 데이터셋 이식, 센서 묶음 비교), 네 모달리티의 실사진 대조(그림 5), 100개 실내 장면 데이터셋입니다. 모든 평가는 열린 고리(open-loop)이며 로봇 폐루프 검증은 없습니다(Sec. 8).

## 3. 방법

### 3.1 분리 구조 (Sec. 3, S.1, S.2)

- **세계 시뮬레이션 층:** Blender(Cycles)로 정답을 만듭니다. Blender의 프레임율 한계와 시스템 부하의 들쭉날쭉함을 피하려고 RPC 클라이언트/서버, UDP 레지스트리, HTCondor 컨테이너 작업을 씁니다(S.2.2). 키프레임을 시간 방향으로 늘려(`keyframe remapping`, S.2.3) 임의의 프레임율에서 물리 시뮬레이션을 샘플링하고, 고정 비율 N배는 RIFE로 보간합니다(S.2.7).
- **센서 에뮬레이션 층:** 보간된 선형 강도 프레임 위에 센서별 모델을 얹습니다. 장면은 한 번만 렌더링합니다.
- **키프레임 배수 탐색(식 S8):** 장면마다 95퍼센타일 광류가 목표값(예 1 px)이 되는 배수 K를 `K_{i+1} = K_i + α^i [K_i (V̂_q(K_i)/V_target − 1)]` 꼴로 찾습니다(감쇠 α = 0.95, 구간 클램프). 흐름이 1/K에 비례한다는 1차 근사입니다.

### 3.2 센서 모델

| 센서 | 모델 | 위치 |
|---|---|---|
| dToF (SPAD LiDAR) | 시간 구간 b마다 T[b] = η Σ I[bΔt ≤ t_p < (b+1)Δt] α_p/z_p² W(p) (식 1, S10). 도착률 λ(t) = (T∗g)(t) + λ_ambient (S11), 비균질 포아송, 비마비형 데드타임, EWH와 EDH 히스토그램, 시야 마스크 W | Sec. 4.1, S.5.2 |
| iToF | B̃_i = Q(β F_i(Γ) + A + η_i) (식 2). 위상 접힘 Γ_max = c/2f, 포화, 주변광, 탭 간 움직임, 잡음과 양자화 | Sec. 4.2, S.5.3 (S12–S14) |
| 열화상 | 열전도 ρc ∂T/∂t = ∇·(k∇T) (S3), 경계 Robin 조건(복사+대류, S4), 복사 선형화(S6), 후방 오일러(S7). 흡수 전력 q_abs = (1−a) E (S1–S2)는 Cycles 확산 조도 패스에서 읽음. 복사 L_out = ε U(T) + (1−ε) L_in (S15), 마이크로볼로미터 IIR y[n] = a y[n−1] + (1−a) x[n], a = e^{−Δt/τ} (S20) | Sec. 4.3, S.2.5, S.5.4 |
| 이벤트 | v2e 기반. 로그 강도 변화 임계(사건마다 확률적으로 뽑음, L1552), 1차 저역 통과, 중심-주변 커널, 불응기 | S.3 |
| 수동 SPAD | 베르누이 1 − e^{−ϕτ}, 선형 강도에 보정 계수 f를 곱해 플럭스로 바꿈. 암계수, 충전율은 f에 흡수 | S.3, S.5.1 |
| RGB | I = Γ(min(∫ϕ dt, FWC) + N) (식 S9). 고속 프레임 합으로 모션 블러 | S.3 |
| IMU | 이산 랜덤 워크(Crassidis, Leutenegger 표 I 값) | S.3 |

dToF는 PyTorch로 구현되어 미분 가능하다고 합니다(S.5.2.1, L1708, L1717). 디지털 트윈에서는 상관 손실 `Cor_loss = mean(1 − max(pred∗gt)) + λ TV(b_i − b_{i+1})`(식 S21)로 IRF를 1000 epoch 학습합니다(S.6.3).

## 5. 데이터셋과 배포

- 배포 대상은 정답 구성요소, 재생성 스크립트, 자산, 체크섬입니다. 센서 원시 데이터는 용량 때문에 직접 배포하지 않습니다(Sec. 7 Release). 100개 리깅 장면은 BlendSwap과 Blender 예제 장면에서 가져왔고 "CC BY 4.0 또는 비슷한 허용 라이선스"로 풀 계획입니다(S.7).
- 재생성 명령 `scripts/mkdataset.py create-datasets ...`와 Docker, CI, HTCondor 작업 설명이 있습니다(S.7).
- 프로젝트 페이지는 데이터셋을 "Coming soon. The prerelease is available in the meantime."이라고 적습니다(2026-11-22 확인). 장면 자산과 체크섬은 공식 저장소에도 없습니다(`04` D13).

## 6. 한계 (논문 Sec. 8과 우리의 관찰)

논문이 인정하는 것: 디지털 트윈은 기기 하나와 소수 장면, 센서 묶음 비교는 단일 과제, 모든 평가가 열린 고리, 데이터셋은 실내만, 중간 표현(깊이와 알베도) 때문에 볼륨 효과와 고차 광수송을 못 다루며 회절 때문에 mmWave 레이더는 어렵습니다.

우리가 추가로 본 것:

- **주장 대비 공개 코드의 간격이 큽니다.** dToF, 데드타임, 글레어, IRF 학습, 마이크로볼로미터, iToF 잡음과 포화는 공식 저장소 main에 없거나 문서가 "미구현"이라고 적습니다(`04` D1–D5). 논문이 "플랫폼을 공개한다"고 쓴 문장은 현 시점 코드의 상태와 맞지 않습니다.
- **정량 검증이 약합니다.** 사례 연구와 그림 5는 모두 1개 장면, 1개 기기이고 통계가 없습니다(`03` V11). 본문 RMSE 1.53 m와 보충 그림 4의 0.33 m가 어긋납니다(`03` V10).
- **본문의 산술이 몇 군데 어긋납니다.** 열확산도 비 500배(실제 194배), iToF 위상 0.13 rad의 깊이 환산(7.75 cm이지 5.3 cm 아님), 마이크로볼로미터 90% 도달 프레임 수(1.4프레임이지 약 3프레임 아님)입니다(`03` V6–V8).
- **센서 묶음 비교는 센서 비교가 아니라 파이프라인 비교입니다.** 재구성 모델과 검출기를 모두 제로샷으로 썼다고 논문이 인정합니다(Sec. 5).
