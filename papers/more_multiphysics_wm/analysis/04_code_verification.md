### 2.1 D1의 해석 주의

이 판정은 **공개 코드 브랜치**에 대한 것입니다. 논문 결과를 만든 코드가 같은지는 모릅니다. 그래도 두 가지는 확실합니다. 첫째, 공개 평가 경로는 특권 라벨로 라우팅합니다. 둘째, 공개 학습 경로에서 게이트는 학습되지 않습니다. 따라서 논문 §4.3의 "특권 라벨 없음"과 표 5의 96.7%는 이 공개 코드로 확인되지 않습니다. 저자에게 답을 받아야 할 질문입니다.

### 2.2 표 2의 "Ours"와 "Privileged Expert"가 가까운 이유 (가설)

표 2에서 MoE와 특권 전문가 값이 0.001 안쪽으로 가까운 칸이 많습니다. D1이 맞다면, 평가에서 MoE도 정답 체제를 받으므로 두 방법이 같은 라우팅을 쓰는 셈입니다. 이 가설은 검증하지 못했습니다. 저자가 표 2의 라우팅 조건을 밝혀야 판단할 수 있습니다.

## 3. 공개 코드와 논문의 일치 확인 요약

- 구조 수치(D15)는 논문과 맞습니다.
- 라우팅 설계(D1–D4)와 학습 설정(D7–D9)은 맞지 않습니다.
- 평가 방법(D10–D11)은 정의가 여러 개이고 평가 표본이 작습니다.
- 재현에 필요한 기준선, MPC, 실험 스크립트(D12)는 공개되지 않았습니다.

## 4. 구현 가능성 판정 (이 맥: Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음)

**판정: 논문 규모 재현은 이 맥에서 불가합니다. 구조 축소판 구현과 라우팅 설계 검증은 가능합니다. 공식 코드 평가는 승인과 포팅 후 조건부입니다.**

| 항목 | 판정 | 근거와 노력 (추정) |
|---|---|---|
| 공식 코드 학습 (표 2, 3, 4의 학습) | **불가** | `.cuda()` 하드코딩과 DDP(D13), PointNet2 CUDA 확장, 데이터 **약 10.6 GB**(306 파일, 승인 필요: 1 GB 이상), 학습 시간 미공개. CPU 측정 없음 |
| 공식 코드 추론과 평가 (소량) | **조건부** | 체크포인트 730 MB, 데이터 일부, `.cuda()`를 MPS로 바꾸는 포팅, DDP 제거, `sdp_kernel` 제거, PointNet2 대체. 노력 **3–5일**(추정). 평가는 D1로 특권 라우팅이므로 논문 §4.3의 주장은 검증할 수 없음 |
| 라우팅 설계 검증 (학습 가능한 게이트를 실제로 학습) | **가능** | 게이트 CE를 손실에 넣는 수정(D2)과 정답 라벨 없는 경로를 만든 뒤 CPU 또는 MPS 축소판에서 확인. 노력 **1–2주**(추정) |
| 구조 축소판 (점군 인코더 축소, SE(3) 강체 헤드, 변형 변위 헤드, 게이트, 자기 롤아웃) | **가능** | 노력 **1–2주**(추정). 정적 기하 인코더를 Uni3D 대신 작은 PointNet 류로 바꿔야 함 |
| 실로봇 MPC (그림 4) | **불가** | 로봇, 카메라 4대, 상자와 장난감 |
| 시뮬 MPC와 DROID 평가 (표 4) | **불가 또는 조건부** | 시뮬 MPC는 Isaac 계열 필요(CUDA). DROID 평가는 데이터와 Qwen, SAM 파이프라인이 필요 |
| 20 FPS 실시간 추론 | **확인 불가** | 측정 정보 없음 |

이 맥에서 할 수 있는 확인 중 가장 값진 것은 **D2–D3의 결과를 축소판으로 보는 것**입니다. 특권 라벨로 라우팅하는 경우와 학습 가능한 게이트를 쓰는 경우를 비교하면, 논문의 핵심 주장("운동 이력으로 체제를 고를 수 있다")이 얼마나 필요한지 알 수 있습니다. 이것은 재현 항목이므로 시작 전 사용자에게 확인합니다.
