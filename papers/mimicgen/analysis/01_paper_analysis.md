## 1. 문제와 주장

모방학습은 사람 시연이 많을수록 좋아지지만, 시연 수집은 비쌉니다. 이 논문의 질문은 **이미 가진 적은 사람 시연(10개)을 새 장면에 맞게 바꾸어 대량의 성공 시연을 자동으로 만들 수 있는가**입니다(§1, Abstract).

주장은 네 가지입니다(§1 기여 목록).

1. 객체 중심 세그먼트를 장면 객체의 자세에 맞게 변환하고 이어 붙여 새 시연을 만드는 시스템 MimicGen.
2. 18개 과제(본문 주장), 여러 장면 분포, 객체, 로봇 팔에서 작동한다는 것.
3. 사람 시연 10개로 만든 MimicGen 데이터 200개와 사람 시연 200개의 정책 성능이 비슷하다는 것(§6.2, Fig. 4 오른쪽 아래).
4. 실로봇 두 과제(Stack, Coffee)에서 생성 데이터로 시각 정책을 학습할 수 있다는 것(§6.4). 다만 성공률은 시뮬레이션보다 낮습니다.

## 2. 방법

### 2.1 가정 (§3)

- **가정 1 (델타 자세 행동공간):** 행동은 엔드이펙터 컨트롤러의 델타 자세와 그리퍼 명령입니다. 델타 행동을 목표 자세 열로 바꿔 다룹니다(부록 N.1).
- **가정 2 (객체 중심 하위과제 순서):** 과제는 알려진 하위과제 순서 S₁(o_S1), …, S_M(o_SM)이며, 각 하위과제의 동작은 한 객체의 좌표계 기준입니다. 순서는 사람이 쉽게 지정할 수 있다고 봅니다(부록 K.1).
- **가정 3 (관측 가능한 객체 자세):** 데이터 수집 중 각 하위과제 시작 때 객체 자세를 알 수 있어야 합니다. 정책 배포 때는 필요 없습니다.

### 2.2 원천 데이터 분할 (§4.1, 부록 K.2)

각 원천 시연을 하위과제마다 하나의 세그먼트로 나눕니다. 끝점은 시뮬레이터 상태에서 계산하는 metric(예: 물체를 잡은 순간)으로 찾습니다. 사람이 끝점을 표시하는 방법도 가능하다고 씁니다.

### 2.3 세그먼트 변환 (§4.2, 부록 M)

현재 장면에서 객체 자세가 T_{O'_0}일 때, 원천 세그먼트의 엔드이펙터 목표 C_t를 다음으로 바꿉니다.

> C'_t = O'_0 (O_0)⁻¹ C_t

객체 좌표계에서 본 상대 자세가 시간마다 보존됩니다(부록 M의 유도). 세그먼트 전체를 한 번에 같은 강체 변환으로 옮기는 식입니다.

### 2.4 보간과 실행 (§4.2, 부록 N.2, N.4)

- 변환된 세그먼트 앞에 **보간 세그먼트**를 붙입니다. 현재 엔드이펙터 자세에서 변환된 첫 목표까지 위치는 선형, 회전은 구면 보간(slerp)으로 잇습니다. n_interp 단계를 쓰고, 그 뒤 n_fixed 단계 동안 목표를 고정합니다.
- 기본값은 n_interp = 5, n_fixed = 0입니다(시뮬레이션). 실로봇은 n_interp = 25, n_fixed = 25입니다(부록 N.6).
- 실행 때 목표를 델타 행동으로 바꾸고 가우스 잡음을 더합니다(σ = 0.05, 그리퍼 제외). 실로봇은 σ = 0.02를 씁니다.
- 모든 하위과제를 실행한 뒤 과제 성공 여부를 봅니다. 성공한 시도만 데이터셋에 넣습니다. 성공 비율이 **데이터 생성 성공률(DGR)**입니다.

### 2.5 원천 세그먼트 선택 (부록 N.3)

- **무작위 선택:** 원천 시연 N개 중 하나를 균등하게 고릅니다. 대부분 과제에서 씁니다.
- **최근접 이웃 선택:** 현재 객체 자세와 각 원천 세그먼트 시작 객체 자세의 거리(위치 L2 + 회전 각)를 계산해, 가까운 상위 n_nk = 3개 중 하나를 고릅니다. Square, Nut Assembly, Stack, Stack Three, Pick Place에 씁니다.
- **하위과제마다 선택 여부(per-subtask):** 하위과제마다 원천을 새로 고를지, 한 에피소드에서 같은 원천을 끝까지 쓸지를 정합니다. Stack, Stack Three, Pick Place는 하위과제마다 새로 고릅니다.

### 2.6 학습과 평가 (§5, 부록 O)

- 정책은 robomimic의 BC-RNN입니다. 이미지 입력은 84×84, 실로봇은 120×160입니다. 이미지 정책은 픽셀 이동 무작위화(±10%)를 씁니다.
- 과제 변형마다 1000개의 성공 시연을 모읍니다.
- 시뮬레이션 평가는 체크포인트마다 롤아웃 50회이고, **세 시드에서 최대 성공률을 보고합니다.** 실로봇은 마지막 체크포인트를 50회 평가합니다.
- 표의 "±"가 무엇을 가리키는지 논문은 정의하지 않습니다. 시드 표준편차로 읽는 것이 자연스럽지만 명시되지 않았습니다(03 §1.2에서 다룹니다).
- 학습과 생성은 V100 GPU 한 장과 8 CPU 기계에서 했다고 씁니다(부록 O).

## 3. 실험

### 3.1 과제와 변형 (§5, 부록 L)

과제 군은 기본 쌓기(Stack, Stack Three), 접촉이 많은 과제(Square, Threading, Coffee, Three Piece Assembly, Hammer Cleanup, Mug Cleanup), 긴 과제(Kitchen, Nut Assembly, Pick Place, Coffee Preparation), 이동 조작(Mobile Kitchen), Factory 과제(Nut-and-Bolt, Gear, Frame)입니다. 부록 L에 나온 과제는 16개입니다.

변형은 D0(원천과 같은 기본 분포), D1(넓은 분포), D2(더 넓은 분포)입니다. 로봇 팔(R)과 객체(O)를 바꾼 변형도 있습니다.

원천 시연은 대부분 한 조작자가 D0에서 10개를 모은 것입니다. Mobile Kitchen은 25개, Square는 robomimic Square PH의 10개입니다.

### 3.2 주요 결과 (그림 4, 이미지 기반, D0)

| 과제 | 원천 10개 | MimicGen D0 | D1 | D2 |
|---|---|---|---|---|
| Stack | 26.0 | 100.0 | 99.3 | - |
| Square | 11.3 | 90.7 | 73.3 | 49.3 |
| Threading | 19.3 | 98.0 | 60.7 | 38.0 |
| Three Pc. Assembly | 1.3 | 82.0 | 62.7 | 13.3 |
| Coffee Preparation | 12.7 | 97.3 | 42.0 | - |
| Nut-and-Bolt | 8.7 | 92.7 | 81.3 | 72.7 |
| Gear Assembly | 14.7 | 98.7 | 74.0 | 56.7 |
| Frame Assembly | 10.7 | 82.0 | 68.7 | 36.7 |

(값은 평균, 단위 %. 전체 표는 `analysis/recompute.py`의 `FIG4`에 있습니다. 표 값은 PDF 6쪽 렌더링과 대조했습니다.)

본문이 강조하는 결과:

- 원천 10개로 학습한 정책보다 D0 생성 데이터로 학습한 정책이 모든 과제에서 높습니다(§6.1).
- D1과 D2에서도 정책이 작동합니다. D1 성공률은 42.0%(Coffee Preparation)에서 99.3%(Stack)까지입니다(§6.1, 그림 4).
- 로봇 팔 전이: Square와 Threading의 원천(Panda)에서 Sawyer, IIWA, UR5e용 데이터를 생성해 D0 정책 성공률이 80–91%(Square)와 89–98%(Threading)로 비슷합니다(§6.1, 부록 F).
- 객체 전이: Mug Cleanup 원천의 한 머그(O1)에서 90.7%, 12개 머그(O2)에서 75.3%입니다(부록 G 표 G.1).
- 이동 조작: Mobile Kitchen은 이미지 기반 2.0% → 46.7%입니다(그림 4). 저차원 값은 본문에 2.7% → 76.7%로 씌어 있지만, 표 Q.1은 원천 6.7 ± 3.8로 적고 있습니다(§6.1, 부록 Q, 03 §2에서 다룹니다).
- 시뮬레이터 독립성: Factory(Isaac Gym 기반)의 Nut-and-Bolt, Gear, Frame에서 D0 정책 82–99%입니다(그림 4). 원천은 9–15%입니다.

### 3.3 사람 데모와의 비교 (§6.2)

- 200개 MimicGen(원천 10개에서 생성)과 200개 사람 시연으로 학습한 정책은 대부분 과제에서 비슷하다고 씁니다(그림 4 오른쪽 아래). **이 비교의 수치는 그림 막대로만 있고 표는 없습니다.**
- 기존 연구와 비교: BUDS(Zhu 외, 2022)의 Hammer Cleanup 68.6%와 Kitchen 72.0%를 인용하고, BC-RNN D0 생성 데이터의 100.0%와 비교합니다. 사실 비교 대상이 다릅니다(원천 시연 수와 평가 조건이 다름). 이 점은 논문이 명시하지 않습니다.

### 3.4 분석 (§6.3)

- **원천 수:** 원천 1, 10, 50, 200개를 Square와 TPA에서 비교했습니다. 차이는 2–21% 범위로 "모험적"이라고 씁니다(그림 4 위쪽 오른쪽, 그림만 있음).
- **원천 선택 편중:** Gear Assembly D1은 1000개 중 850개 이상이 3개 원천에서 나왔습니다. Threading D0은 한 원천이 170개를 낸 반면 다른 원천은 10개 미만입니다.
- **생성량 대 성능:** 200 → 1000에서 크게 오르고 1000 → 5000에서는 거의 오르지 않습니다.
- **DGR과 성능의 관계:** "꼭 같지는 않다"고 씁니다. 예로 Object Cleanup D0(DGR 29.5%, 성능 82.0%), TPA D0(35.6%, 74.7%), Coffee D2(27.7%, 76.7%), Gear D1(8.2%, 76.0%)를 듭니다(03 §2에서 확인합니다).

## 4. 한계 (논문 §7, 부록 D)

논문 스스로 든 한계는 다음과 같습니다.

- 과제 하위 순서와 객체 자세 관측을 알아야 합니다(가정 2, 3).
- 필터는 과제 성공뿐이어서 데이터에 편향이나 불필요한 충돌이 들어갈 수 있습니다(부록 R).
- 보간은 직선이라 충돌 회피를 보장하지 않습니다. 실로봇 성능 격차의 원인 가운데 하나로 봅니다(부록 H).
- 준정적 강체 과제만 시험했습니다. 같은 범주 안의 새 객체만 다룹니다(부록 G).
- 이동 조작의 기본 이동 세그먼트는 원천을 그대로 복사합니다(부록 N.5).

## 5. 주장과 근거의 간격 (요약, 자세한 판정은 03 §5)

- "18개 과제, 50K 이상의 시연"은 본문 표 기준으로 확인할 수 없습니다. 표 P.1은 36개 변형이고, 여기에 1000개씩을 곱하면 36,000개입니다. 나머지는 부록 실험의 추가 데이터지만 합계 표가 없습니다.
- "매우 비슷하다"(로봇 팔, 조작자, 원천 다양성) 주장은 과제와 변형에 따라 차이가 있습니다(03 §1).
- 시뮬레이션 성공률은 체크포인트 최댓값입니다. "±"의 정의도 없습니다. 이 두 가지는 보고된 차이를 과장할 수 있습니다(03 §1.2).
- 실로봇 결과는 평가 50회 한 번씩으로 신뢰구간이 넓습니다(03 §1.1).
