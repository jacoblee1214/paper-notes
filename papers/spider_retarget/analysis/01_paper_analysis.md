## 1. 문제와 주장

사람 손-물체 시연(모션캡처, 영상 재구성)을 로봇 궤적으로 바꾸는 **물리 기반 리타게팅**입니다. 운동학만 맞추는 IK는 빠르지만 물리적으로 불가능하고(접촉 관통, 미끄럼), RL은 궤적마다 정책을 학습해 비싸고, 텔레오퍼레이션은 사람이 많이 필요합니다(서론, §1, 2쪽).

SPIDER의 주장은 세 가지입니다.

1. 시연은 **전역 과제 구조와 목표**를 주고, **샘플링 기반 최적화**가 물리 제약을 만족하는 해를 찾습니다. 그래디언트가 필요 없어 RL과 최적화의 중간입니다(§1, §2.3).
2. 접촉 정보(가상 접촉 안내)로 샘플링이 **의도한 접촉 순서**를 유지합니다(§3.3, 부록 C).
3. 같은 파이프라인으로 **물리 기반 데이터 증강**(물체 기하 변경, 외력, 지형)과 **강건화**(최악 경우 목적 함수, 식 4)를 할 수 있습니다. 결과 데이터로 정책을 학습하거나 실로봇에 열린 고리로 실행합니다(§3.3, §4.2–4.3).

## 2. 방법

### 2.1 문제 정의 (식 1, §3.1)

제어열 `u_{0:T-1}`을 골라 기준 상태열 `x^ref_{0:T}`와의 오차(`⊖`는 SE(3)에서 로그 맵 기반 차이)와 제어 노력을 최소화합니다. 제약은 시뮬레이션 전이 식 `x_{t+1} = f(x_t, u_t, t)`입니다. 오프라인 최적화이고 출력은 열린 고리 명령입니다. 식은 시작 상태가 기준과 맞는다는 가정 아래 쓰였습니다(§3.1, 4쪽).

### 2.2 샘플링 해법 (식 2–3, Algorithm 1, §3.2)

- **식 2 (업데이트):** 샘플 `N_W`개의 가우시안 노이즈를 `U^i`에 더해 롤아웃하고, 비용의 지수 가중 평균(softmax, 온도 λ)으로 `U^{i+1}`를 만듭니다. 방식은 MPPI/CEM 계열입니다(§2.3의 참고 문헌).
- **식 3 (어닐링 공분산):** `Σ_h^i = exp(-(N-i)/(β1 N) - (H-h)/(β2 H)) I`. 반복 횟수 `i`에 따라 전역 탐색에서 국소 탐색으로, 호라이즌 `h`에 따라 가까운 시간의 노이즈를 줄입니다. β1과 β2의 값은 본문과 표 5, 6에 없습니다(§3.2, `04` D6).
- **Algorithm 1:** 최대 반복 `N`, 조기 종료 `ε_tol`, 병렬 샘플 `N_W`. 자동 난이도 부스트(부록 A.3): 수렴하지 못한 단계는 반복 수를 2배, 노이즈를 √2배 키운 뒤 재시도합니다.

### 2.3 데이터 증강과 강건화 (§3.3, 4쪽 이후)

- **강건화 (식 4):** `J_rob(U) = max_{d∈D} J(U, d)`. 마찰, 접촉 여유, 질량 같은 파라미터 집합 `D`에 대해 최악 비용을 씁니다. 집합 `D`의 구체적 범위는 본문에 없습니다(`04` D8).
- **기하·물리 증강:** 물체 위치와 크기를 바꾸거나 물체 메쉬를 교체합니다. 무거운 물체를 당길 때 120 N, 240 N의 외력을 주면 기울어 천천히 움직이는 궤적이 나옵니다(그림 4, 5쪽 논문 그림).
- **접촉 안내 (식 5, 부록 C 식 7):** 목표 접촉쌍(예: 손잡이-엄지)의 상대 위치를 가상 제약으로 묶고, 페널티 η를 반복마다 키워 제약을 점차 강하게 합니다. 접촉은 기준 상대 위치가 임계값(ε_contact) 안에 있을 때만 켜집니다. 접촉 필터는 지속 시간이 짧거나 접촉점이 많이 움직이면 해당 제약을 끕니다(부록 C, 32쪽).

### 2.4 시뮬레이션 설정 (부록 A.3, 표 5, 표 6, 표 16–18)

- MuJoCo Warp(대부분), Genesis(ARCTIC, DexMachina 설정), IsaacGym(ManipTrans 설정). 물리 100 Hz, 제어 50 Hz(A.3).
- 표 5(Oakink, GigaHands 기본 및 접촉 안내 설정), 표 6(대규모 생성 공용 설정, 궤적당 중앙 약 220 s).
- 표 16(ManipTrans 비교), 표 18(DexMachina 비교)은 각 비교 대상의 설정에 맞췄습니다.

## 3. 실험 결과 (논문 값)

### 3.1 손 리타게팅 (표 1, 9–10, §4.1.1)

표 1은 Oakink(IsaacGym, ManipTrans 설정, 12-DoF Inspire 손)와 ARCTIC(Genesis, DexMachina 설정, Inspire 양손), 그리고 MuJoCo 운동학 기준선을 비교합니다.

| 비교 | 방법 | ADD-AUC (%) ↑ | FPS ↑ |
|---|---|---|---|
| vs RL, Oakink | ManipTrans | 19.4 ± 27.5 | 0.1 |
| | SPIDER (IsaacGym) | 22.3 ± 28.1 | 2.5 |
| vs RL, ARCTIC | DexMachina | 41.0 ± 25.3 | 0.05 |
| | SPIDER (Genesis) | 43.6 ± 29.8 | 1.5 |
| vs 운동학, Oakink | Kinematic | 11.0 ± 11.1 | 248.9 |
| | SPIDER / SPIDER+C | 48.8 ± 24.9 / 56.9 ± 24.7 | 6.1 / 0.4 |
| vs 운동학, GigaHands | Kinematic | 24.1 ± 22.3 | 244.2 |
| | SPIDER / SPIDER+C | 56.9 ± 20.6 / 57.7 ± 23.9 | 5.9 / 0.5 |

- 본문 주장: RL 대비 "비슷하거나 더 좋은 ADD-AUC", 그리고 "한 자릿수 이상 빠른 생성"입니다. FPS 비율은 25배와 30배로 계산됩니다.
- 운동학 대비 SPIDER는 두 배 이상 AUC를 얻습니다. 접촉 안내(+C)는 더 올립니다.
- 표 9(Oakink, 손별 7개 작업)와 표 10(GigaHands, 3개 궤적)은 손별 평균과 표준편차를 줍니다. 표 1과의 차이는 `03` §2에 있습니다.

### 3.2 휴머노이드 전신 (표 2, §4.1.2)

| 데이터 | 방법 | 관절 ej ↓ | 골반 et ↓ (cm) | er ↓ (도) | FPS |
|---|---|---|---|---|---|
| LAFAN1 | GMR | 1.08 | 2.01 | 2.40 | 35.2 |
| | SPIDER | 0.58 | 0.11 | 0.07 | 23.1 |
| AMASS | GMR | 6.2 | 4.1 | 18.7 | 37.2 |
| | SPIDER | 0.75 | 0.23 | 0.08 | 22.0 |
| OMOMO | GMR | 0.57 | 1.43 | 2.28 | 28.0 |
| | SPIDER | 0.83 | 0.20 | 0.17 | 19.6 |

- 본문은 "모든 지표에서 낮은 오차"라고 씁니다. 그러나 **OMOMO의 관절 오차는 SPIDER가 더 큽니다**(0.83 대 0.57). 물체 오차 열은 OMOMO 하나에만 있습니다.
- 표본은 작습니다. LAFAN1은 춤과 일어서기 2개, AMASS는 8개, OMOMO는 1개 궤적입니다(§4.1.2). 불확실성이 없어 통계 검정은 할 수 없습니다.

### 3.3 정책 학습 (§4.2, 그림 6–7, 부록 A.5–A.6)

- **손 정책 (그림 6, 7 시드, PPO, 4096 환경):** 컵 잡기 과제의 작업 진행도가 SPIDER 기준은 0.99 ± 0.01, 운동학 기준은 0.07 ± 0.11입니다. 이 결과는 가장 강한 주장이고 표본이 가장 작습니다(7 시드).
- **휴머노이드 정책 (그림 7):** 상자 옮기기입니다. 정성적 곡선만 있고 숫자 요약이 없습니다. 운동학 기준 정책은 상자를 잡지 못합니다.
- 손 정책의 보상 가중치는 표 8에 있습니다. 가중치 합은 약 0.53이며 "normalized"라는 설명과 맞지 않습니다(`03` V9).

### 3.4 실로봇과 실제 영상 (§4.3, 그림 8–9)

- **실로봇 (Franka 7-DoF + Allegro, OSC):** 빛전구 돌리기, 작은 숟가락, 기타 연주, 충전기 뽑기 4개 과제를 열린 고리로 재생합니다. 성공률, 시도 수, 오차 수치는 없습니다. 물체 초기 위치가 크게 어긋나면 실패한다고 스스로 씁니다(§4.3).
- **영상 입력 (그림 9):** Trellis(메쉬), HAMER(손), FoundationPose(물체 추적)로 단일 RGB 영상을 재구성해 컵 붓기와 볼트 설치를 재생합니다. 정량 결과가 없습니다.

### 3.5 대규모 생성 (§4.4, 표 3, 표 6–7, 부록 A.4)

- **원천:** DexYCB 499, OakInk-Image 169, HRDexDB 441, HOT3D 2,718 오른손 시연(총 3,827). 손 4종 (Allegro, XHand, Inspire, Sharpa) × 3,827 = 15,308 과제.
- **결과:** 15,302 기록 중 15,041 완료, 161 IK 실패, 100 준비 실패. 완료 15,041 중 437개는 들어 올림이 부족해 제외하고, 14,604 중 최종 **6,520 궤적**을 보존합니다(표 7). 보존 세트의 평균 ADD-AUC는 78.30%입니다.
- 보존 전 완료 롤아웃의 평균 ADD-AUC는 61.48%입니다(§4.4). 손별 평균은 표 3에 있습니다(Allegro 67.86, XHand 66.76, Inspire 66.41, Sharpa 44.46).
- **중요:** 표 7의 78.30%는 **필터를 거친 보존 세트**의 값입니다. 필터를 거치지 않은 생성 성능은 61.48%입니다. 두 값을 같은 뜻으로 쓰면 안 됩니다. 본문도 "higher ADD-AUC describes the selected dataset"이라고 밝힙니다(부록 A.4).
- **규모 주장의 차이:** 초록 6,520, 서론 6,532(`04` D4), 프로젝트 페이지 6,523, 공개 저장소 README의 HF 보존 세트 7,876 궤적(2,885 원천 에피소드, 2026-09-22 공지). 같은 "전체 데이터"가 시점마다 다릅니다.

### 3.6 한계 (§4.5, §5)

논문이 스스로 밝힌 실패 모드는 (1) 인식 오차가 잘못된 접촉 모드로 이끄는 것, (2) 심한 가림으로 생긴 기준의 시간적 공백, (3) 열린 고리라서 초기 상태가 조금만 달라도 오차가 커지는 것, (4) 접촉 모호성입니다. 접촉 안내는 접촉 주석이 필요합니다(§4.5). 향후 과제는 노이즈 강건화와 정책 증류입니다(§5).

## 4. 무엇이 잘 뒷받침되는가

- **잘 뒷받침됨:** 운동학 기준 대비 물리 일관성 향상(표 1, 표 9–10). RL 기준선과 비교한 처리량 차이(표 1 FPS, 시드 없이도 큰 차이). 손 정책 학습의 차이(7 시드 결과, 0.99 대 0.07).
- **약함:** ADD-AUC 차이(SPIDER 22.3 대 ManipTrans 19.4, 표준편차 28 안에서 구분 안 됨). 휴머노이드 비교의 표본(궤적 1–8개). 실로봇 결과(수치 없음). 강건화와 데이터 증강의 정량 효과(없음).
- **재현에 필요한 정보가 빠짐:** β1과 β2, 강건화 집합 D의 범위, 접촉 필터 임계값 `t_c,min`, `d_c,max`의 값, 표 1 집계의 가중치, 시드 수의 일관성(`04` D6–D9).
