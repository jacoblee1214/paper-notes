## 1. 문제 설정

VLA(π0 계열)를 **실물에서** RL로 미세조정하면 장면과 물체가 몇 개뿐이어서 일반화가 떨어집니다. 시뮬레이션은 장면을 많이 만들 수 있지만, 장면을 설계하는 비용이 큽니다(§1, 1문단). 이 논문은 **3D 세계 생성 모델**(EmbodiedGen)과 **언어 기반 장면 설계기**(GPT-4o)로 장면을 자동으로 만들고, 그 위에서 사전학습 VLA를 희소 보상 RL로 미세조정합니다. 질문은 두 가지입니다. 장면 분포를 넓히면 OOD 일반화가 좋아지는가, 그렇게 학습한 정책이 실물에 옮겨지는가.

기여는 네 가지입니다(§1, 기여 1–4).

1. 생성 엔진과 장면 설계기로 VLA RL을 여러 장면에서 수행합니다. 100장면에서 시뮬 성공률 9.7% → 79.8%, 완료 시간 1.25배 빠름.
2. 훈련 장면 수를 늘리면 OOD 일반화가 좋아집니다. 1장면 대 50장면에서 OOD +24.7 pp.
3. 실물 전이: 12장면, 240회 시도에서 21.7% → 75%, 완료 시간 1.13배 빠름.
4. 흐름 매칭 VLA를 단일 단계 가우시안 정책으로 바꿔 PPO로 미세조정합니다(PPOFlow). 추론 지연 2.36배 빠름(부록 B).

## 2. 방법

### 2.1 생성 시뮬레이션 (§3, 그림 2, 부록 C)

- 시뮬레이터는 ManiSkill 3(GPU 병렬)입니다. 생성 백엔드는 EmbodiedGen [42, 43]을 확장했습니다.
- **장면 설계기:** GPT-4o가 과제 문장("put the pen in the pen holder")을 장면 그래프로 바꿉니다. 역할은 배경, 맥락, 방해물, 조작 대상, 로봇이고, 관계는 ON, IN입니다(§3 "Generative simulation").
- **QA 루프:** GPT-4o가 장면의 물리 타당성과 기하 일관성을 검사합니다. 실패한 구성은 버립니다. 자산 단계에서는 Semantic Appearance, Mesh Geometry, Cross-modal Text-to-3D Alignment의 세 검사를 씁니다(부록 C, 표 C.1).
- 물체가 그리퍼(최대 74 mm)보다 크면 메시 경계 상자에 따라 자동으로 줄입니다(부록 C, "Auto-scaling of objects").
- **규모:** 100장면, 고유 물체 자산 516개, 장면당 평균 5.16개, 배경 자산 100개입니다(표 C.1).

### 2.2 MDP와 정책 (§3, 식 1–7)

- **관측:** RGB 영상, 언어 지시, 말단 자세 q ∈ R⁷(xyz, rpy, 그리퍼)입니다. 행동은 말단 델타 자세와 이진 그리퍼로 이루어진 청크 A ∈ R^{C×7}이고, **청크 하나를 하나의 결정 단계로 봅니다**(C = 4).
- **보상:** 희소 규칙 보상입니다. 식 A.1에서 contact(A, B) ∧ ¬contact(A, table) ∧ ¬contact(A, robot)일 때만 성공입니다.
- **사전학습 정책 πpre:** π0(3B)을 BridgeV2로 사전학습한 체크포인트입니다. **Physical Intelligence 공식 가중치가 아니라 제3자 저장소 open-pi-zero의 체크포인트**를 썼습니다(부록 D). 공식 π0도 비슷한 성공률을 보였다고 쓰지만 수치는 없습니다. π0.5는 더 나빴습니다(부록 D).
- **흐름 매칭 손실** (식 1): 속도장 v_θ를 조건부 흐름 매칭으로 학습합니다. 추론은 식 2의 ODE를 적분합니다.

### 2.3 PPOFlow (§3, 식 3–7, 부록 B)

- 흐름의 각 적분 단계에 학습 가능한 노이즈 σ_φ를 넣어 가우시안 샘플로 바꿉니다(식 3–4). 그 단계들의 로그 확률 합으로 중요도 비율을 계산합니다(식 5).
- 중요도 비율에 지수 s ∈ (0, 1]를 씁니다(식 6). 값은 s = 0.2입니다(표 A.1). 부록 A는 이 지수가 없으면 학습이 바로 무너진다고 씁니다.
- PPO 클리핑 목적함수(식 7)에 GAE 이점을 씁니다. 가치 머리 V_ψ와 노이즈 머리 σ_φ는 얕은 MLP입니다.
- **K = 1** (적분 단계 하나)로 두어 πpre를 **단일 단계 가우시안 정책**으로 바꿉니다. 부록 B의 K ∈ {1, 2, 4} 비교에서 성공률 차이는 2.5 pp 안팎입니다. 실행은 1회씩입니다.

### 2.4 VLA 구조와 미세조정 범위 (§3, 그림 3, 부록 A)

- 학습 가능 부분은 VLM 백본(Gemma 2B)을 LoRA(rank 32)로, 행동 전문가와 가치·노이즈 머리를 완전 미세조정합니다(부록 A, 전략 (e)). 부록 A는 VLM을 얼리면 학습 상한이 낮아지고 결국 무너진다고 씁니다.
- 학습률 2e-5, 클리핑 0.2, 기울기 노름 0.5, 환경 192개, 배치 19,200, 미니배치 1,920, 에피소드 길이 25, 제어 5 Hz입니다(표 A.1).
- 노이즈 로그-σ 범위는 [-2.5, -2.0]으로 σ ≈ 0.082–0.135입니다(표 A.1에서 계산).
- 학습 자원은 RTX 6000 Ada 8장으로 5일입니다(§4 "Training details"). 실물 평가는 RTX 4090 한 장입니다(§4 "Experiment design").

### 2.5 도메인 무작위화와 실물 제어 (§4, 표 A.2)

- 물체 x ∈ [0.2, 0.4] m, y ∈ [-0.15, 0.15] m, yaw ∈ [0, 2π]. 로봇 관절 ±0.1 rad, z 0–0.05 m. 카메라 위치 ±0.05 m. 주광 밝기 0.5–1.5. 주변광 RGB 0–0.6입니다.
- 실물 제어는 **PD 제어와 중력 보상**입니다. 저자들은 시스템 식별이 "대부분 필요 없었다"고 씁니다(§4). 이 주장을 뒷받침하는 실험은 없습니다.
- 제어 지연 무작위화는 쓰지 않았습니다. 청크 C = 4 때문에 불필요했다고 씁니다(부록 A).

## 3. 실험 설계

- **평가 세트:** 100장면 W를 세 개의 무작위 부분집합 H_i(50장면)로 나눕니다. 각 H_i에서 N ∈ {1, 3, 10, 25, 50}으로 훈련하고(처음 N장면, 고정 순서), 각 H_i에서 3회 실행합니다. N = 100은 W 전체로 3 시드입니다(§4).
- **ID:** 훈련 장면 N개 (N = 100은 W 전체). **OOD:** W \ H_i (50장면). 평가는 장면당 100 에피소드입니다.
- **외부 OOD:** SimplerEnv 3장면(부록 F), Google Scanned Objects 18장면(부록 G), Hunyuan3D-2.1 생성 자산 25장면(부록 H). 세 세트 모두 학습에 쓰지 않았습니다.
- **고정 연산량:** 배치를 N과 무관하게 고정합니다. 그래서 장면당 샘플이 1/N로 줄어듭니다(§4 "Fixed compute budget"). 저자들은 이것이 큰 N에 불리하게 작용하고, 포화(N = 25–50)가 연산 한계 때문일 수 있다고 씁니다(§5 "Limitations").
- **기준:** πpre(N = 0)와 SimplerEnv 3장면만으로 학습한 정책(N = 3, SE)입니다.
- **실물:** WidowX 250S, 웹캠 한 대(Logitech C922), 장면 12개, 장면당 정책별 10회, 총 240회입니다(§4, 표 2).

- 외부 세트: SimplerEnv는 N = 0 23.7% → N = 100 74.3%. Google Scanned는 12.1% → 60.7%(최고 N = 25의 62.7%). Hunyuan3D-2.1은 10.2% → 62.5%(최고 N = 50의 63.3%)입니다(표 1 블록 2, 3).
- **읽는 법:** 저자들은 ∆G가 ID 성공률이 떨어져도 줄 수 있다고 씁니다(§4). OOD 절대 성공률과 같이 봐야 합니다.
- 평균 완료 시간: 정책 W 기준 10.0 s(N = 0) → 7.9–8.1 s(N = 50–100).

### 4.2 실물 (표 2)

| 지표 | πpre (IL) | RL (N = 100) |
|---|---|---|
| PSR (잡고 들어 올림) | 45.0% | 88.3% |
| SR (과제 성공) | 21.7% | 75.0% |

- 장면 10(드라이버, 학습 분포 밖)에서 0% → 50%, 장면 11(찻잔 쌓기)에서 20% → 50%입니다(본문 §4). 장면 11의 PSR은 100%입니다.
- 실패 분류 정의는 본문에 있습니다. DFR과 SFR은 겹칠 수 있습니다(§4).

### 4.3 K와 추론 지연 (표 B.1)

- 추론 지연(정규, 초): K = 10 0.267 → K = 1 0.098, 2.72배. torch.compile은 0.172 → 0.073, 2.36배입니다.
- 학습 역전파 시간: K = 4 108.8 s, K = 2 87.6 s, K = 1 74.7 s입니다.
- RL 성공률: K = 4 77.29%, K = 2 77.23%, K = 1 79.75%입니다. **각 1회 실행**입니다(부록 B).

### 4.4 생성 파이프라인 (표 C.1)

- 장면당 46.8 ± 5.0분(RTX 4090 한 장, 순차 실행). 자산 라이브러리에서 재사용하면 약 2분입니다.
- 자동 QA 통과율: 의미 83.3%, 메시 75.2%, 텍스트-3D 정렬 91.9%. 자산당 평균 시도 1.37회입니다.
- 최종 장면 수용률(수동 점검): **85%**. 나머지는 "최소한의 수동 조정"으로 고칠 수 있다고 씁니다(부록 C).

## 5. 저자가 밝힌 한계 (§5 "Limitations")

1. 과제는 집어 올려 놓기(pick-and-place)뿐입니다. EmbodiedGen이 안정적으로 만들 수 있는 물체에 묶여 있습니다.
2. 스케일링 추세가 기술, VLA 백본, 로봇, 분포 이동 종류에 대해 일반화된다는 증거는 없습니다. 배경과 물체 자산만 바꿨습니다.
3. 고정 연산량 때문에 큰 N이 불리합니다. 포화가 연산 한계일 수 있습니다.

## 6. 읽으면서 확인한 것 (이 분석의 관점)

- 시뮬 결과는 3 실행(N = 100은 3 시드)이고, 실물은 정책당 120회입니다. 정량 검정은 `analysis/03_analysis.md`에 있습니다.
- 실물 평가는 한 정책(N = 100)의 한 체크포인트입니다. 체크포인트를 어떻게 골랐는지 본문에 없습니다.
- 공식 코드와 학습 세부(예: 에피소드 길이의 단위, 장면 수용 85%의 수동 조정 여부)는 원문에서 확정되지 않습니다.
- 정책 체크포인트, 장면 자산, 학습 코드는 공개되지 않았습니다(`analysis/04_claim_verification.md` §0).
