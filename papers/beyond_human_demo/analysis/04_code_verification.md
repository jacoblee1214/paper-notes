### 확인한 것 중 문제가 없던 것

- 가드 파라미터의 정책 쪽 복사본과 원격조작 쪽 기본값이 접시(재개방 2개 제외)와 마커(37개 모두)에서 같습니다. "같은 G\*를 데이터 수집과 배치에 쓴다"는 설명은 파라미터 수준에서 맞습니다(D3의 활성 플래그 문제는 별개).
- 와인 리타기터 훅(`calibrate`와 `update` 덮어쓰기)과 CRAFT 모터 목표 가드는 서술과 같은 구조입니다(`teleop_craft_glide.py:700–790`).
- 부록 D 와인 1단계의 "도구 좌표 위쪽 축 자동 학습"(`_pose_axis_closest_to_up`)이 코드에 있습니다.

## 4. 구현할 수 있는가 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**전체 재현은 불가능합니다. 가드 필터의 핵심은 CPU에서 구현·시험할 수 있습니다.**

| 정책 평가 (표 2) | 불가 | 실로봇, SpaceMouse |

| 가드 필터 재구현과 시뮬레이션 시험 | 가능 | 접시 필터(EMA + 속도·가속 제한 + 쌍 결합)와 마커 놓기 단계, 와인 기울기 증폭은 numpy로 수백 줄입니다. 가상의 조작자 입력(노이즈, 좌우 높이 차)으로 필터 효과를 시험할 수 있고, 일부는 이미 산술로 확인했습니다(`toy_selection_and_filter.py`) |
| 에이전트 생성 루프(Write, Revise)의 모의 | 조건부 | 코딩 에이전트 호출 비용과 API 사용 승인이 필요. 프롬프트는 논문 부록 C·D에 있어 구조는 재구성할 수 있으나 어떤 에이전트인지, 실패 진단이 얼마나 정확한지는 실로봇 영상 없이 검증할 수 없음 |
| MuJoCo 모의 과제(접시 위 구슬 운반 등)로 가드 효과 측정 | 조건부 | mujoco 4.0, torch 2.15가 설치되어 있고 CPU에서 가능. 접시·구슬 모델링과 가상 조작자 설계가 필요. 논문 수치와는 비교할 수 없음 |

**노력 추정(측정 아님):** 접시·마커 필터의 numpy 재구현과 가상 입력 시험 2–3일, MuJoCo 모의 과제 1–2주, 에이전트 루프 모의 1주(API 승인 후). 실로봇 재현은 하드웨어를 갖추는 문제입니다.
