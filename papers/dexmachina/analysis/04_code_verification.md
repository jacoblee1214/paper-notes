- **대상:** `https://github.com/MandiZhao/dexmachina`, HEAD `adae5bf` (2026-03-22). `repo/`에 얕은 clone으로 두고 정적으로만 읽었습니다. 설치, import, 실행을 하지 않았습니다. 내려받은 내용은 신뢰하지 않는 자료로 취급했습니다.
- **대조 방법:** 논문 본문 식과 알고리즘, 부록(A.2–A.4, B.1–B.4)을 해당 코드(`dexmachina/envs/*.py`, `retargeting/*.py`, `eval/*.py`, `examples/*.sh`, `eval/group_cfgs/dexmachina_main.yaml`)와 나란히 읽었습니다.
- **라벨:** D1–D12는 논문과 코드의 차이, K는 맞은 항목입니다. 03의 V 라벨과 겹치지 않습니다.

## 1. 한눈에 보기

- **맞는 것:** 과제 보상의 곱 형태, 혼합 행동의 식(A.3), 접촉 근사의 임계 γ = 0.01과 N_c = 50, 물체 2부품, 에피소드 길이 T = end − start, 보상의 R/L_max 정규화, 기본 설정의 보상 합, 7개 시연과 5개 물체, 시드 5개 평가(03 V5–V6).
- **다른 것:** 논문 Alg. 1은 단일 지수 감쇠이지만, 공식 메인 설정은 **환경마다 무작위로 뽑는 이득 구간**(uniform 스케줄)을 씁니다. 논문에 없는 **게이트 여러 개**(길이, 기울기, 대기 에폭, 되돌림, 마지막 에폭 강제 종료)가 있습니다. 보상 가중치, 혼합 행동 스케일, β, d_max, 감쇠율은 논문에 값이 없고 코드도 조건마다 다릅니다.
- **재현 판단에 가장 중요한 차이:** D1(커리큘럼 형태)과 D4(가중치 부재)입니다. 논문만 읽고 구현하면 메인 결과를 다시 얻기 어렵습니다.

## 2. 불일치 항목 (D1–D12)

### D1. 커리큘럼 형태: 논문은 단일 지수 감쇠, 메인 설정은 uniform 스케줄
- **논문:** Alg. 1은 모든 환경에 같은 k_p, k_v를 두고, 조건을 만족할 때 k_p ← k_p·φ_p, k_v ← k_v·φ_v로 줄입니다(§4.3).
- **코드:** `envs/curriculum.py`의 `Curriculum`은 `schedule`로 `fixed`, `exp`, `uniform` 중 하나를 고릅니다. `train_rl.sh`, `train_dex3.sh`, `constructors.py` 324행(argparse 기본값)과 `eval/group_cfgs/dexmachina_main.yaml`의 DexMachina 조건 모두 `uniform`입니다.
- **uniform의 의미:** `reset_object_gains()`가 환경마다, 물체 자유도마다 `[lower, upper]` 구간에서 kp, kv, force range를 **무작위로 뽑습니다**(curriculum.py `reset_object_gains`). 상한과 하한이 모두 감쇠합니다(`set_auto_uniform_decay`). 논문에는 이 무작위화와 하한 감쇠가 없습니다.
- **임계값도 다릅니다:** 논문 k_p ≤ 0.01이면 0입니다. 코드의 exp는 k_p < 0.05 또는 힘 범위 < 0.01이면 0, uniform은 하한 k_p < 0.1이면 0입니다(curriculum.py).
- **영향:** 논문 §4.3의 "이득을 점차 줄인다"는 설명은 맞지만, 메인 결과가 나온 설정은 환경별 이득 분포입니다. 다시 구현하려면 이 차이를 명시해야 합니다.

### D2. 논문 Alg. 1에 없는 게이트와 안전장치
`Curriculum.determine_decay()`와 `determine_dialback()`에 다음이 있습니다. 논문은 "최근 정규화 보상 평균이 σ_z를 넘는가"만 씁니다.
1. 대기 에폭(`wait_epochs`): 인자 기본 500, 예제 스크립트 100.
2. 마지막 감쇠 후 40 에폭 미만이면 감쇠하지 않음.
3. 달성 에피소드 길이 평균 ≥ max_len − 2를 요구(평균이 짧으면 감쇠 안 함).
4. 보상 기울기 조건(`grad_threshold`, 기본 0.001, 예제는 `--skip_grad`로 끔).
5. 되돌림(dialback): 달성 길이 평균이 `dialback_ep_len`(인자 기본 30, 예제 80)보다 짧은 상태가 `dialback_min_epochs`(인자 기본 500) 넘게 지속되면, 마지막 이득에 0.98을 곱해 되돌림.
6. `zero_epoch = max_epochs − num_zero_epoch`(인자 기본 1000을 뺌)을 넘으면 이득을 모두 0으로 둠. 최대 에폭이 5000이면 4000 에폭부터입니다.
7. 보상 임계값 인자 기본은 `[0.5, 0, 0, 0]`(task만 0.5, 나머지 0. 커리큘럼 클래스의 기본 0.05와 다름). 예제는 `task=0.6`, 나머지 `0.01`. 논문 σ 값은 없음.
- **영향:** 학습 스케줄은 보상 곡선만으로 정해지지 않습니다. 긴 과제에서 이 게이트가 실제 감쇠 시점을 크게 바꿀 수 있습니다.

### D3. 보상 결합과 추가 항
- **기본 결합:** `rewards.py` 기본값 `multiply_all_rew = False`이면 `rew = task + imi + con + bc` 합입니다. 논문 §4.2 식과 맞습니다(K).
- **곱 옵션:** `-mar`를 주면 `rew += 0.5 · imi · con · bc`가 됩니다(rewards.py 622–634행). 논문에 없고 예제는 쓰지 않습니다.
- **힘 패널티:** 학습 환경은 `observe_contact_force = True`로 고정됩니다(`constructors.py` 107행). 그러면 힘 패널티 `0.1 · mean(max(‖f‖ − 500, 0))`가 활성화됩니다(rewards.py 640–646행, 기본 `force_penalty = 0.1`). 논문 보상식에는 없습니다.
- **행동 패널티:** 예제는 `--action_penalty 0.01`을 씁니다. 논문에 없습니다.

### D4. 가중치와 β 값이 논문에 없습니다
- 논문 §4.2는 "정확한 가중치는 App. A.4"라고 쓰지만 A.4는 접촉 근사만 다룹니다. λ, β_pos, β_rot, β_ang, β_imi, β_bc, β_con 값이 본문과 부록 어디에도 없습니다.
- 코드 값은 다음과 같습니다(기본값, 예제, 메인 조건).
  - 과제 β (pos, rot, arti): 기본 `[10, 1, 5]`, `rewards.py` 기본 `[20, 5, 20]`, 예제 `10 1 5`.
  - 모방 `-imi`: 기본 0, 예제 0.3, 메인 조건 0.2 또는 0.3.
  - 행동 `-bc`: 기본 0, 예제 0.3, 메인 조건 0.2. `bc_beta` 기본 500.
  - 접촉 `-con`: 기본 0, 예제 3, 메인 조건 2. `contact_beta` 예제 10, `rewards.py` 기본 30.
- **영향:** 논문만으로는 이 설정을 복원할 수 없습니다. 메인 결과는 조건(`group yaml`의 `condition_sets`)마다 다른 값을 씁니다.

### D5. 접촉 보상 식과 불일치 처리
- **논문 식 (2):** 부품과 링크 쌍마다 exp(−β_con D)를 구하고 1/(2NK)로 평균합니다. 마스크가 어긋난 쌍은 d_max를 씁니다.
- **코드 (매칭 경로, 예제가 쓰는 `--use_retarget_contact`):** `compute_matched_contact_reward()`는 시연에서 같은 링크의 접촉을 골라 거리를 구합니다. 한쪽만 접촉이면 거리를 `max_distance = 1.0`(고정, 단위 m)으로 두고, 둘 다 없으면 같은 값으로 둡니다. 결과는 `/4.0`으로 나눕니다(rewards.py 438–471행).
- **다른 경로(`compute_hand_contact_reward`):** 부품별 객체 좌표계와 손목 좌표계 보상을 곱합니다(`multiply_frame_contact`). 이는 매칭 경로에서 쓰지 않습니다.
- **논문과 차이:** d_max 값이 논문에 없고, 코드는 1.0을 씁니다. 정규화 계수도 1/(2NK)와 `/4.0`은 다른 식입니다. 학습에 쓰인 경로는 매칭 경로입니다(예제 `--use_retarget_contact`).

### D6. 혼합 행동 스케일과 부가 옵션
- **식 (A.3):** 손목 잔차 `q_t + s·clip(a)`, 손가락 절대 `ℓ + (u − ℓ)(a + 1)/2`. `robot.py` `translate_actions()` 603–621행이 이 식을 구현합니다(K).
- **스케일:** 논문은 s_T, s_R 값을 주지 않습니다. 코드 기본은 `(0.04, 0.5)`(robot.py `hybrid_scales`, 주석은 ObjDex의 ±4 cm, ±0.5 rad). 메인 설정과 예제는 `(0.1, 1.0)`입니다. 단위 표시는 없고, 값 차이는 손목 움직임 범위를 병진 2.5배, 회전 2배 넓힙니다.
- **추가 옵션:** `action_moving_avg`(기본 1.0, 즉 끔)로 목표를 지수 평활할 수 있습니다. 논문에는 없습니다. `res_cap`도 있습니다(기본 끔).

### D7. 가상 물체 제어기의 이득 설정과 "임계 감쇠"
- **논문 §4.3:** 시작 이득은 "임계 감쇠(critical damping)"로 높게 둔다고 씁니다. 그러나 k_v와 k_p의 관계식이나 질량, 관성은 없습니다.
- **코드:** `kp`와 `kv`를 따로 설정합니다. 물체 기본값 kp 1000, kv 100, force range 200. 커리큘럼 기본 kp_init 1000, kv_init 10. 예제는 kp 80, kv 5입니다. 저장소에서 "critical"을 검색해도 감쇠 공식은 나오지 않습니다(grep 확인).
- **무작위화:** `object.py` `reset_idx()`는 물체 이득에 환경마다 `rand_scale ∈ [0.7, 1.0]`을 곱합니다. 주석은 `[0.5, 1.0]`이라 씁니다. 코드 안에서도 주석과 식이 다릅니다.
- **영향:** 임계 감쇠라는 설명은 검증하지 못했습니다. 감쇠비를 계산하려면 물체의 질량과 관성이 필요한데, 이 clone만으로는 찾지 못했습니다.

### D8. 학습 규모와 에폭
- **논문 B.1:** 환경 12,000개(DexRobot 10,000개), L40s 또는 H100 한 장.
- **예제:** `train_rl.sh`는 `-B 4096`, `--max_epochs 5000`입니다. 메인 설정의 에폭 수는 조건 이름(`10k`, `13k`)에서만 짐작할 수 있고 명시되어 있지 않습니다.
- **영향:** 예제로 돌린 결과와 논문 결과는 다른 설정입니다.

### D9. 운동학 리타겟팅 인용
- **논문:** 본문 §4.2는 [3](AnyTeleop)을 인용하고, App. A.1과 A.2는 [26](Open-TeleVision)을 인용합니다.
- **코드:** `retargeting/`은 `dex_retargeting` 패키지(`dexmachina.yaml`에 `dex-retargeting==0.5.0` 고정)를 씁니다. 이 패키지가 어느 논문의 알고리즘인지는 이 저장소에 없고 확인하지 않았습니다.
- **영향:** 인용이 어긋나 있습니다. 본문과 부록 가운데 하나를 고쳐야 합니다.

### D10. 평가 지표 순서와 임계값
- **논문 B.4:** "부품별 ADD를 평균한 뒤 AUC를 계산한다"고 씁니다.
- **코드:** `group_results.py` 71–96행은 부품별로 AUC를 계산한 뒤 두 부품의 AUC를 평균합니다. 두 방식은 일반적으로 같지 않습니다.
- **임계값:** 코드는 0.01–0.09 m 9개입니다. 논문에는 임계값 범위가 없습니다.
- **seed 값:** 한 seed의 값은 20 에피소드의 모든 프레임을 한 번에 평균한 정확도입니다.

### D11. ManipTrans 재구현 범위
- **논문 B.3:** 중력 범위 g ∈ [0, −9.81], 마찰 μ ∈ [4.0, 1.0]이라고 씁니다.
- **코드:** `envs/maniptrans_curr.py` 10–11행은 중력 `[9.81, 0.005]`, 마찰 `[5.0, 1.0]`, 그리고 논문에 없는 허용 오차 범위(손가락, 물체 위치와 회전)를 둡니다.
- **영향:** 논문 수치를 낸 설정이 공개 기본값과 같은지 알 수 없습니다. 저자의 확인이 필요합니다.

### D12. ObjDex 재구현 옵션
- **논문 B.3:** 손목 기준 자세는 운동학 리타겟팅 결과를 쓰고, 과제 β 값은 주지 않습니다.
- **코드:** `--objdex_baseline`을 주면 행동을 `hybrid`로 두고 과제 β를 `[30, 2, 10]`으로 바꿉니다(`constructors.py` 42–45행). 논문에 없는 값입니다.

## 4. 구현 가능성 (이 맥, Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**판정: 전체 재현은 이 맥에서 불가능합니다.** 두 가지 이유가 있습니다.

1. **학습에 GPU가 필요합니다.** 논문 설정은 환경 12,000개와 L40s 또는 H100입니다. 예제도 4,096개입니다. 공식 코드는 `gs.init(backend=gs.gpu)`와 `torch.device('cuda:0')`를 직접 씁니다.
2. **전처리에도 CUDA가 하드코딩되어 있습니다.** `grep`으로 18곳의 `cuda`를 찾았습니다. `retargeting/parallel_retarget.py`(`torch.device("cuda")`), `retargeting/map_contacts.py`와 `eval/compute_add.py`(`gs.gpu`)가 포함됩니다. 즉 ARCTIC 시연을 로봇 손 자료로 바꾸는 단계도 MPS나 CPU로 바로 돌지 않습니다.

| 구성 | 이 맥에서 | 근거 |
|---|---|---|
| 집계 파일 재계산과 검정 | **가능, 완료** | 03, `analysis/recompute.py` |
| 보상과 커리큘럼 로직의 numpy 토이 | 가능 (새 설치 없음) | 만들지 않음 (이유는 아래) |
| 운동학 리타겟팅(dex_retargeting) | 조건부 | 패키지 설치 필요(승인 대상), CUDA 호출 제거 필요 |
| 시연 데이터 처리 (ARCTIC) | 조건부 | 데이터 별도 다운로드, 라이선스 미확인, CUDA 제거 필요 |
| Genesis와 rl-games 포크로 학습 | **불가** (GPU 전제) | `gs.gpu`, `cuda:0`, 12,000 환경 |
| 시각 정책, 실로봇 | **불가** | 논문 §7 |

- **토이를 만들지 않은 이유:** 이 논문의 핵심 주장은 "가상 힘 커리큘럼이 긴 과제에서 학습을 살린다"입니다. 2-DoF 토이는 이 주장을 시험하지 못합니다. 주장과 같은 규모의 검사는 시뮬레이션과 RL이 필요합니다.
