# 03. 재계산, 검정, 일관성 검사

재현 실험은 하지 않았습니다. 논문이 보고한 숫자를 다시 계산하고, 검정과 구간을 붙이고, 표와 본문과 그림이 서로 맞는지 확인했습니다. 계산은 `analysis/recompute.py`(수 초, numpy와 scipy)에 있고 결과는 `analysis/recompute_results.json`입니다. 그림은 `analysis/plot_figures.py`가 그립니다.

논문의 수치는 대부분 그림에만 있습니다(표는 표 1, 2뿐). 그래서 그림 값은 **픽셀 측정(±0.01 안팎)**으로 읽었고, 시도 수는 가장 가까운 정수로 맞췄습니다. 이 점을 모든 표에 적었습니다.

## 1. 실로봇 삽입 (그림 4c)

### 1.1 판독값과 시도 수

과제당 15회입니다(본문). 판독 성공률에 15를 곱해 정수로 맞춘 값을 씁니다.

| 정책 | USB (12핀) | Switch (3핀) | VGA (17핀) | 평균 |
|---|---|---|---|---|
| 촉각 없음 | 0.007 → 0/15 | 0.130 → 2/15 | 0.000 → 0/15 | 0.046 |
| 처음부터 학습 | 0.307 → 5/15 (4/15 가능) | 0.331 → 5/15 | 0.396 → 6/15 | 0.345 |
| T3 | 0.518 → 8/15 | 0.665 → 10/15 | 0.598 → 9/15 | 0.594 |

- **K1. USB 막대는 15회 분수와 맞지 않습니다.** 0.307은 4/15(0.267)나 5/15(0.333)와 떨어져 있습니다(픽셀 오차는 약 ±0.005). 0.518은 8/15(0.533)보다 낮습니다. USB 시도 수가 15가 아니었거나 막대 값이 다른 기준을 쓴 것 같습니다. 원자료 없이는 확정할 수 없습니다.

### 1.2 구간과 검정 (시도 수는 위 근사값)

| 비교 | 결과 |
|---|---|
| T3 Wilson 95%: USB, Switch, VGA | [0.30, 0.75], [0.42, 0.85], [0.36, 0.80] |
| 처음부터 학습 Wilson 95%: USB, Switch, VGA | [0.15, 0.58], [0.15, 0.58], [0.20, 0.64] |
| 과제별 Fisher, T3 대 처음부터 | USB p = 0.46, Switch p = 0.14, VGA p = 0.47 |
| 과제별 Fisher, T3 대 촉각 없음 | USB p = 0.002, Switch p = 0.008, VGA p = 0.0007 |
| 세 과제 합산, T3 27/45 대 처음부터 16/45 | Fisher p = 0.034 (처음부터 15/45이면 p = 0.020) |
| 세 과제 합산, T3 27/45 대 촉각 없음 2/45 | Fisher p < 0.0001 |

- **C1. "T3가 촉각 없음보다 낫다"는 확실합니다.** 세 과제 모두 p < 0.01입니다.
- **C2. "T3가 처음부터 학습한 촉각보다 낫다"는 과제별로는 확인되지 않습니다.** 세 과제 모두 p > 0.1입니다. 합산 p = 0.03은 세 과제를 같은 확률로 보는 가정을 깔고 있어 약합니다. 본문은 "세 부품 모두에서 높다"고 쓰지만 방향만 맞습니다.

### 1.3 "25%"와 "53%"는 %p입니다

- 세 과제 평균 차이: T3 − 처음부터 = **0.249 (약 25 %p)**, T3 − 촉각 없음 = **0.548 (약 55 %p)**.
- 상대 증가: T3 / 처음부터 − 1 = **72%**, T3 / 촉각 없음 = **약 13배** (평균 기준, 촉각 없음 평균 0.046이 작아서 상대 값이 크게 나옴).
- 초록의 "25% higher"는 %p 차이와 맞고, 상대 증가(72%)와는 맞지 않습니다. "53%"는 판독 평균 차이(55 %p)에 가깝습니다(±3 %p 판독 오차 안).

- **K2. 초록의 "%" 단위가 모호합니다.** 독자가 "상대적으로 25% 높다"로 읽기 쉽습니다. 이 분석에서는 %p로 해석하고, 상대 증가는 72%라고 적습니다.

### 1.4 평균 스텝 (성공 에피소드만)

| 정책 | USB | Switch | VGA |
|---|---|---|---|
| 촉각 없음 | (데이터 없음) | 23.5 | (데이터 없음) |
| 처음부터 학습 | 14.4 | 14.3 | 11.4 |
| T3 | 15.5 | 3.6 | 8.7 |
| T3 − 처음부터 | **+1.1** | −10.7 | −2.7 |

- **K3. 캡션의 "가장 낮은 평균 에피소드 길이"는 USB에서 성립하지 않습니다.** T3 15.5 대 처음부터 14.4입니다. 본문 (3)은 "스텝을 줄였다"고 쓰는데, Switch와 VGA에서만 맞습니다.
- 평균은 성공 에피소드만으로 계산했습니다. 성공 수가 2–10개라 평균 스텝의 분산이 큽니다. 시도 단위 검정은 원자료가 없어 할 수 없습니다.

## 2. 모델 크기와 파라미터 수 (표 1, 체크포인트 대조)

논문 표 1은 파라미터 수를 "모든 인코더와 디코더 포함"이라고 적습니다. 공식 저장소의 HF 체크포인트(`models/t3_*`)는 파일별로 나뉘어 있습니다. 파일 크기를 fp32 4바이트로 나누면 파라미터 수를 근사할 수 있습니다(피클 여분 0.1% 안팎).

| 크기 | 논문 (M) | 체크포인트 인코더 8개 + 트렁크 + 포즈 4개 + 분류 7개 + 분산 1개 (fp32 환산, M) | 인코더 4개(가장 작은 4개) + 트렁크 + 포즈 1개 (M) |
|---|---|---|---|
| tiny | 12 | 22.8 | 11.6 |
| small | 45 | 85.3 | 44.4 |
| medium | 174 | 331.2 | 174.2 |
| large | 308 | 735.8 | 308.1 |

- 트렁크 이론값 9 × 12 × D² 은 medium에서 63.7M, 체크포인트 63.8M으로 맞습니다. 인코더 한 개 3층 이론값은 medium에서 21.2M, 체크포인트 22.0M입니다. 블록 크기 가정은 맞습니다.
- **K4. 논문 표 1의 파라미터 수는 "모든 인코더와 디코더"와 맞지 않습니다.** 체크포인트에는 인코더가 8개, 포즈 디코더가 4개 있고, 전부 넣으면 medium은 331M입니다.
- 4개 인코더 + 트렁크 + 포즈 디코더 1개 조합은 네 크기 모두에서 논문 값과 1M 안에 듭니다(가설). 논문이 실제로 이 조합을 셌을 가능성이 있지만 본문으로는 확인할 수 없습니다.
- **K5. large 체크포인트의 인코더 크기가 두 종류입니다.** 네 개는 38.8M이고 네 개는 76.6M입니다. 설정 파일은 인코더 깊이를 하나로 두는데, 두 배 크기 인코더가 어떤 구조인지 릴리스에서 확인할 수 없습니다(`04` D3).
- 프로젝트 페이지의 large 304M은 논문 본문 308M과 다릅니다(`02` §4).

## 3. 데이터셋 합계와 센서 비율 (표 2)

- **K6. 표 2 합계 = 3,083,452.** 본문 값과 같습니다. 구성 행 17개(VisGel-small, TVL, Touch-and-Go, Calandra17, Yuan18, YCB-Sight 실 480 + 시뮬 1,800, ObjectFolder-real, Tippur23 네 행, 새로 모은 다섯 행)를 더했습니다.
- **K10. 새로 모은 데이터의 센서 목록이 본문과 표 2에서 다릅니다.** 본문 3절은 새 데이터 센서로 GelSight Finray, Svelte, Wedge, DenseTact 2.0, GelSight 360을 듭니다. 표 2의 "New data collected in-house" 행에는 Wedge, Finray, Svelte, DenseTact 2.0, GelSight Mini(3,359장)가 있고 GelSight 360 행은 공개 데이터(Tippur23)에만 있습니다. 어느 쪽이 맞는지 본문으로 확인할 수 없습니다.
- **K7. "두 센서가 50% 이상"은 맞지만 묶음 정의가 없습니다.** 가장 큰 GelSight'17 계열(VisGel-small, Touch-and-Go, Calandra17, Yuan18)은 48.9%이고, 둘째인 ObjectFolder의 GelSight var.2는 46.0%입니다. 합 약 95%입니다. 센서를 어떻게 묶었는지 본문에 없습니다.

## 4. 사전학습과 마스킹 (그림 3a, 3b)

- **K8. 중앙값 24%는 %p인지 상대 증가인지 본문에 없습니다.** 그림 3a를 판독한 여덟 쌍(tiny–large, 절반과 전체 데이터, 사전학습 I+II 대 처음부터)으로 계산하면 중앙값 차이는 약 25 %p, 상대 증가는 약 52%입니다. 판독 오차가 3 %p 안팎이라 24와 25는 구별할 수 없지만, 52%는 본문 24%와 다른 단위입니다. 여기서도 %p가 맞습니다.
- **C3. 마스킹 80%가 최선이라는 결론은 확정하기 어렵습니다.** 85%(30%)에서 89%(80%)까지 4 %p입니다. 검증 세트 크기가 없어 구간을 구하려면 n을 가정해야 합니다. 가정 n = 330(전체의 10%)이면 차이 구간은 [−0.01, +0.09], p = 0.13입니다. n = 660이면 p = 0.03, n = 1000이면 p = 0.008입니다. 반복 실험이 없어서 시드 변동을 알 수 없습니다(그림 `own_mask_sens.png`).

## 5. 제로샷과 미세조정 (그림 3c, 3d)

- **K9. "17%"의 정의가 없습니다.** 그림 3c 판독: 분류 정확도 Svelte 무작위 0.17, 제로샷 0.22, 미세조정 0.40, DenseTact 무작위 0.18, 제로샷 0.22, 미세조정 0.37입니다. 미세조정과 제로샷의 차이는 0.15–0.18이고, 무작위와의 차이는 0.19–0.23입니다. "17%"가 어느 것인지 본문이 밝히지 않습니다.
- "5.5 mm"는 그림 3d의 이중 축에서 판독하기 어렵습니다. 본문 값을 그대로 인용하고, 판독은 하지 않았습니다.
- 평가 세트 크기와 반복이 없어 제로샷과 미세조정 차이의 검정은 할 수 없습니다.

## 8. 하지 않은 것

- **토이 실험은 하지 않았습니다.** 논문의 핵심 주장(여러 센서 공유 표현의 제로샷 전이)은 실제 촉각 이미지와 여러 센서 없이는 검증할 수 없습니다. 장난감 모델로 옮기면 주장과 무관한 결과가 나옵니다. 그래서 CPU 검사는 재계산과 체크포인트 대조로 한정했습니다.
- **재현 실험은 하지 않았습니다.** 학습, 추론, 공식 코드 실행, 설치, 데이터와 가중치 다운로드를 하지 않았습니다(`04` §4).
