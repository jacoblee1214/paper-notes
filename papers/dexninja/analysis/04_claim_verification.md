# 04. 주장 검증과 구현 가능성

공식 코드가 없어 논문 ↔ 코드 대조(D 항목) 대신 논문 주장 C1–C19를 표·식·본문 수치로 대조합니다. 근거 수치는 `03`(V, K 항목)에 있습니다.

## 0. 대상과 방법

- 대상: arXiv v1(2026-10-12, 28쪽). 판은 하나뿐입니다.
- 코드: 프로젝트 페이지가 "Code Coming soon"이라고 적고(2026-11-26 확인) GitHub 검색에서 저장소를 찾지 못했습니다. 정책, 시뮬레이터, 평가 코드와 체크포인트는 없습니다. 공개 자원은 시뮬레이션 에셋 목록(Hugging Face, 약 140 GB, 받지 않음)뿐입니다(`02` §2).
- 방법: 본문과 부록의 수치를 표에서 다시 계산하고(`recompute.py`), 서술과 식의 내적 일관성을 점검하고, 몬테카를로 토이로 시행 잡음 크기를 봤습니다. 판정 기준은 다음과 같습니다.
  - **지지:** 보고된 횟수와 표의 수치가 서술을 뒷받침하고 구간·검정이 충분함.
  - **방향만:** 점추정은 서술과 같은 방향이나 시행 수 안에서 구분되지 않음.
  - **범위 조건부:** 서술의 일부 범위(예: 범주 안)에서만 지지됨.
  - **확인 불가:** 필요한 정보가 논문에 없음.

## 2. 코드가 공개되면 확인할 것

코드가 나오면 아래를 먼저 대조합니다(D 항목으로 `04_code_verification.md`를 새로 만듦).

1. 정책: 단계 토큰과 게이트 임계값(ε_app, p_on, p_off, K_lost), H_min·H_max·λ(식 8), 그룹별 정규화와 s_kin/s_tac(식 14–15), 손실 가중 ω(식 17), 청크 길이 64/128/16이 그대로인지.
2. 시뮬레이터: 부록 식 4–11의 손실에 음식 상태가 들어가는지(K9), 식 11의 이진 술어 S의 구현(보상, 정제 루프), 국소-장면 렌치 다리의 좌표·단위 처리, 에피소드 1개 20 GB·10분(H200) 측정 가능 여부.
3. 데이터: 학습 시연 수와 시뮬 에피소드 수, 학습·평가 인스턴스 분리, Sim-only 학습량, N의 단위(`K4`, `K13`).
4. 평가: Progress/Success/Integrity 판정 규칙과 판정자(`K5`), 시행별 로그가 있으면 짝 검정(McNemar)으로 표 1·2를 다시 계산.
5. 에셋: 수락 기준 코드(미터 척도, 기하 유효성, 시뮬 호환, 안정 초기화)와 판정기 모델 이름(`K8`).

## 3. 먼저 확인이 필요한 곳

- 개선 폭의 출처: 표 3(N 증가)과 표 2(절제)가 "표본 수만으로는 설명되지 않는 기여"를 지지한다는 서술(§6.4)은 N과 절제 데이터 양이 표에 없어 확인이 안 됩니다. 같은 데이터 양의 단순 섭동 증강 대조가 있어야 "물리 조밀화"의 몫을 가를 수 있습니다(`K13`).
- 사과: 표 1에서 Sim+Real 사과 성공이 8/25로 가장 낮고, 부록 표 2에서는 기준선이 사과에서 더 높습니다. 부록 5.1이 이를 인정하고 증강 분포 확대를 제안합니다.
- 다른 하드웨어와 범주로의 일반성: 두 번째 하드웨어는 정량이 없고, 정책은 범주별입니다(§8).

## 4. 구현 가능성 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**판정: 논문의 파이프라인과 실험은 이 맥에서 재현할 수 없습니다. 표 재계산(완료)과 소형 축소 구현은 가능합니다.**

| 층 | 판정 | 근거 |
|---|---|---|
| 실로봇 실험(표 1–4, 레몬) | 불가 | DR3/DR5 양팔, LinkerHand L10, 압력식 촉각, 고정 RGB-D, 데이터 수집 장갑, 매 시행 소모되는 음식 25개 x 여러 조건이 필요(부록 3.1, 표 1). 정책 체크포인트·데이터 없음 |
| 공식 파이프라인(시뮬레이터 + 정책) | 불가 (코드 없음) | 공개 코드가 없고 공개 시점도 미정입니다. 시뮬은 에피소드당 GPU 메모리 약 20 GB, H200에서 약 10분(부록 5.2) |
| 공개 에셋 사용 | 조건부 | 목록 기준 약 140 GB(에셋당 약 93 MB). 받으려면 사용자 승인(1 GB 이상)이 필요하고, 일부(예: 수 GB)만 받아 형상 통계를 보는 용도가 현실적입니다. 이번에는 받지 않았습니다 |
| 표 재계산과 검정(`recompute.py`) | 가능, 완료 | 수 초, numpy·scipy |
| 정책 구조의 소형 재구현 | 가능 | 단계 토큰 + 가변 청크(식 8) + 그룹별 정규화(식 14)를 합성 접촉 과제에서 구현하고 고정 청크와 비교. torch CPU 또는 MPS |
| 변형체 절단 시뮬레이터의 소형판 | 조건부 | 2D MPM 또는 끊어지는 스프링 격자 + 칼 SDF 손실(식 4–11)은 직접 짤 수 있습니다. 3D MPM + 장면 시뮬레이터 연결은 Genesis·Warp의 macOS 지원 확인이 필요합니다(미확인) |

**노력 추정(실측 없음).** 정책 구조 소형 재구현 1–2주. 2D 절단 시뮬레이터 + 궤적 정제 + 국소 교정 정책(식 11)의 장난감판 3–4주. 논문 수준의 3D 절단 + 촉각 + 로봇 시뮬레이션 재구성은 GPU와 장비를 전제로 수개월 규모입니다. 이 맥에서 현실적인 범위는 앞의 두 가지입니다.
