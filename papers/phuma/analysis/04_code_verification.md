## 3. 중요 항목 설명

### 3.1 큐레이션 (D1–D8)

- **임계 값은 코드와 논문이 같습니다.** 다만 2차 로봇 공간 필터(D7)가 다운로드 파이프라인에 들어 있습니다. 공개 데이터 G1 폴더가 이 필터를 거친 결과인지는 데이터를 받아야 확인할 수 있습니다. 필터가 더해진 것이라면 논문의 73.0 h는 공개 데이터와 다를 수 있습니다.
- **접지 추정(D2)과 접촉 비율(D3)은 식과 다릅니다.** 논문 식 (11)은 꼭짓점 기반 다수결이지만, 코드는 프레임 기반 대표값입니다. 결과 차이는 장난감으로 가늠하기 어렵고, 같은 입력으로 두 방식을 비교해야 합니다.
- **D8은 실행 오류가 날 것으로 보입니다.** 단일 파일 스크립트만 해당합니다. 폴더 스크립트는 같은 함수를 올바르게 호출합니다. 실행 확인은 하지 않았습니다.

### 3.2 리타게팅과 평가 (D9–D17)

- **저장 시 클리핑(D11)이 가장 중요합니다.** 저장된 로봇 모션은 위치 기준으로 항상 한계 안에 있습니다. 표 1에서 PhySINK의 관절 feasibility 100%가 최적화 결과인지 클리핑 결과인지 구분되지 않습니다. 이 클리핑은 논문에 언급이 없습니다.
- **미끄럼 손실(D13)은 식과 다릅니다.** 제곱 대신 노름을 쓰므로 작은 미끄럼에 대한 벌점 기울기가 다릅니다. 가중치 0.002와 함께 읽어야 합니다. 논문이 제곱 식을 썼다면 수치 결과도 달라질 수 있습니다.
- **학습 가능한 링크 스케일(D9, D15)은 논문 본문에 없습니다.** 뼈 길이를 12개 계수로 스케일해 사람 뼈와 맞추므로 자유도가 늘어납니다. 부록 B.1은 β만 말합니다.
- **지표와 손실이 같은 양입니다(D11, D12, D13 대 D14).** 표 1의 지표는 손실과 같은 접지·미끄럼·관절 기준이어서 독립 평가가 아닙니다.
- **표 1 지표 코드(D14)는 없고, 실행 출력 정의도 다릅니다.** 출력의 접촉 마스크(전체 최댓값과 같은 프레임)와 미끄럼 임계(2.5 mm)는 논문 정의(1 cm, 10 cm/s)와 다릅니다.

### 3.3 정책과 데이터 (D18–D21)

- 정책 학습과 성공률 계산은 저장소에 없습니다. 논문 결과를 코드로 확인할 수 없습니다.
- 학습·테스트 원본 사람 포즈와 Unseen Video SMPL은 접근할 수 없거나 아직 공개되지 않았습니다. 큐레이션을 처음부터 재현하려면 SMPL-X 등록과 원천 데이터가 필요합니다.
- Humanoid-X 시간 값이 네 개 다르고 출처 설명이 불명확합니다(D21). 논문 주장의 기준선(Humanoid-X 231.4 h)을 정확히 재현하려면 원천 필터 기준을 저자에게 물어야 합니다.

| **PhySINK 손실 재구현** (torch, 짧은 클립) | **부분 가능 (맥 MPS 미검증)** | 손실 식은 D9–D13 기준으로 쓸 수 있음. 입력(사람 SMPL-X)이 없으면 실제 클립 검증 불가. MPS에서 `pytorch_kinematics` 배치 FK가 동작하는지 확인 필요 |
| **정책 학습 재현** (MaskedMimic 또는 BeyondMimic) | **불가** | CUDA와 Isaac 계열 시뮬이 필요. 코드 미공개 (D18). MuJoCo로 대체하면 논문과 다른 실험 |
| **실물 G1 재현** | **불가** | 하드웨어 없음. GPU 학습 필요 |

### 4.2 이 맥(Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음)에서의 조건

- **torch:** 저장소 요구 사항은 `torch==2.6.0`, `mujoco==3.3.0`, `numpy==1.26.4`, Python 3.9입니다. 이 분석의 실행 환경은 torch 2.15.0, mujoco 4.0.0입니다. 저장소 요구 버전은 설치하지 않았습니다. 2026-11-12 공개 데이터 재계산은 기존 환경(mujoco 4.0.0)과 직접 짠 스크립트로 했습니다.
- **장치:** 리타게팅 기본값은 CUDA입니다. MPS는 `--device mps`로 바꿔야 하며, `pytorch_kinematics` 배치 FK와 `torch.diff` 계열 연산의 MPS 지원은 확인하지 않았습니다.
- **처리 시간 추정(미측정):** RTX 3090에서 PhySINK 0.92 fps(표 10). 4초 클립 한 개는 약 130초입니다. 맥에서 2–5배 느리다고 가정하면 클립 하나에 4–11분이고, 100개 부분 집합은 수 시간이 걸릴 것으로 보입니다. 전체 76K 클립은 현실적이지 않습니다.
- **메모리:** 3001 반복의 역전파 기록은 클립당 수백 MB 수준으로 추정됩니다(미측정). 24 GiB는 한두 클립을 병렬로 돌리는 데 충분할 것으로 보입니다.
- **작업량 추정(구현만):** 지표 재계산 1–2일, 큐레이션 numpy 재구현 2–3일, PhySINK 손실 재구현 1–2주(검증 입력 확보 포함). 정책 학습 재현은 GPU 환경이 없으면 시작할 수 없습니다.

### 4.3 결론

이 맥에서 **공식 파이프라인을 그대로 돌려 논문 표를 재현하는 것은 불가능합니다.** 실제로 할 수 있는 것은 (1) 공개 로봇 모션의 물리 지표를 CPU로 재계산하는 것, (2) 큐레이션 식과 PhySINK 손실을 numpy·torch로 옮겨 장난감 입력에서 검증하는 것입니다. 둘 다 데이터 다운로드(3.42 GB) 승인이 필요하고, 두 번째 작업은 SMPL-X 등록 없이는 실제 사람 데이터로 검증할 수 없습니다.
