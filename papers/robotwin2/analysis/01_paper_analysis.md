# 01. 논문 분석: RoboTwin 2.0

*RoboTwin 2.0: A Scalable Data Generator and Benchmark with Strong Domain Randomization for Robust Bimanual Robotic Manipulation* (Tianxing Chen 외 25명; 교신 Ping Luo, Yao Mu). 분석 대상은 **arXiv v2 (2025-08-27, 24쪽)** 하나입니다. v1(2025-06-22, 22쪽)과의 차이는 §6에 있습니다. 이 논문은 방법 논문이라기보다 **데이터 생성기 + 벤치마크 + 데이터셋**의 기술 보고서 성격이 강합니다. 그래서 이 문서는 벤치마크 설계, 보고된 통계, 평가 프로토콜에 무게를 둡니다.

## 1. 문제 설정과 기여

논문은 양팔 조작 데이터의 세 가지 결함을 짚습니다. (1) 새 과제를 자동으로 만드는 방법 부족, (2) 단순한 시뮬레이션 장면, (3) 로봇 간 차이 무시 (§1, 저자 표현). 기여는 네 가지입니다 (§1, contributions 목록).

1. MLLM 코드 생성과 시뮬레이션 피드백으로 전문가 코드를 자동 생성 (§2.1, 그림 3).
2. 다섯 축 도메인 랜덤화 (clutter, 배경 질감, 조명, 탁상 높이, 언어) (§2.2).
3. 객체별 파지 후보와 로봇별 적응 (§2.3, §3.1).
4. RoboTwin-OD, 10만 궤적 데이터셋, 생성기, 벤치마크를 공개 (§3, §3.2).

**평가 관점에서 중요한 점:** 실험은 네 축을 본다. 코드 생성 성공률 (§4.1, 표 1), 임베딩별 파지 효과 (§4.2, 표 2), 사전학습 효과 (§4.3, 표 3), 실세계 (§4.4, 표 4), 벤치마크 Easy/Hard (§4.5, 표 5 와 부록 K). 아래에서 각 축을 보고된 숫자와 함께 적습니다.

## 2. 방법 (요약)

### 2.1 MLLM 전문가 코드 생성 (§2.1, 그림 3, 부록 G)

- 코드 생성 에이전트 (DeepSeek-V3, 부록 G)와 VLM 관찰자 (moonshot-v1-32k-vision-preview, 부록 G)가 루프를 돈다.
- 한 반복에서 프로그램을 **10회** 실행한다. VLM이 10회 실행을 프레임 단위로 검토해 실패 단계를 찾는다 (§2.1).
- 반복은 "한 반복의 10회 성공률이 설정값에 도달하거나, **5회 연속 개선** 뒤에도 실패할 때" 끝난다 (§2.1, v2 문장). 부록 G.1의 CR-Iter 정의는 "50% 초과 또는 반복 예산 소진"이다.
- 지표: ASR (10개 과제 평균), Top5-ASR, CR-Iter, Token (부록 G.1).

### 2.2 도메인 랜덤화 (§2.2, 부록 C)

다섯 축. 부록 C는 "탁상 높이 최대 3 cm 변화"라고 수치를 준다. 본문은 높이를 "plausible range에서 균등 분포"라고만 쓴다.

- **clutter:** RoboTwin-OD에서 무관한 물체를 놓는다. 비슷한 물체는 제외한다고 적는다.
- **배경 질감:** 질감 11,000개. 표면 설명 1,000개 (LLM + 웹 크롤링) → Stable Diffusion v2로 설명당 20장 생성 (20,000장) → 사람 검수 (§2.2). 
- **조명:** 색 온도, 광원 종류, 개수, 위치 무작위화.
- **탁상 높이:** 균등 분포 무작위화.
- **언어:** 과제 템플릿과 객체 설명을 MLLM으로 생성해 조합. 부록 H에 예시. 설명 프롬프트 (부록 I)은 템플릿 60개 (train 50 / eval 10), 객체 설명 15개 (train 12 / eval 3)를 만든다.

### 2.3 embodiment 적응 (§2.3, 그림 6)

객체마다 여러 파지 축과 접근 방향의 후보 자세를 주석으로 단다. 도달성이 높은 방향으로 각도 섭동을 준다. 그 뒤 병렬 모션 플래닝을 시도한다. 근거는 낮은 DoF 로봇 (Piper, ARX-X5, AgileX)에서 파지 방식이 달라진다는 관찰이다.

## 3. 데이터, 벤치마크, 데이터셋

- **RoboTwin-OD (§3.1):** 731개 객체, 147 범주. 생성 534개 (111 범주, Rodin 3D 재구성, 볼록 분해), Objaverse 153개 (27 범주), PartNet-Mobility 관절 객체 44개 (9 범주). 객체당 설명 15개, 파지점·기능점·축 주석.
- **과제 (§3.2, 그림 8):** 50개 양팔 과제. 다섯 로봇 (Aloha-AgileX, ARX-X5, Piper, Franka, UR5, 그림 5). 사전 수집 10만+ 궤적 (HF `TianxingChen/RoboTwin2.0`).
- **데이터 생성 규칙 (코드, `02`·`04`에서 확인):** 성공한 에피소드만 저장한다 (`collect_data.py`). 즉 데이터셋은 **성공 필터링된 전문가 궤적**이다. 논문에 이 문장은 없다.

## 4. 실험과 보고된 통계

### 4.1 코드 생성 (표 1, 표 8, 표 9, 그림 9)

| 구성 | ASR | Top5-ASR | CR-Iter | Token |
|---|---|---|---|---|
| R1.0 Vanilla | 47.4% | 57.6% | 1.00 | 1236.6 |
| R1.0 + FB | 60.4% | 71.4% | 2.46 | 1190.4 |
| R1.0 + MM FB | 63.9% | 74.2% | 2.42 | 1465.0 |
| R2.0 Vanilla | 62.1% | 68.0% | 1.00 | 569.4 |
| R2.0 + FB | 66.7% | 73.6% | 1.89 | 581.6 |
| R2.0 + MM FB | 71.3% | 78.6% | 1.76 | 839.7 |

- 표 1은 **10개 과제 부분집합** (RoboTwin 1.0과 2.0이 둘 다 지원하는 과제)이다. 표 8의 10개 과제 값으로 표 1의 ASR을 재계산하면 6개 구성 모두 일치한다 (`03` §1).
- **그런데 50개 과제 평균은 43.34%** (표 9, R2.0 + MM FB). 나머지 40개 과제 평균은 약 36.4%로 계산된다 (`03` §1). 즉 표 1의 71.3%는 전체가 아니라 비교 가능한 10개 과제에서 나온 수치다. 본문 §4.1은 "10 tasks"라고 쓰지만 초록은 "a 10.9% gain in code generation success rate"만 쓴다.
- **초록의 10.9%는 같은 구성끼리 비교한 값이 아니다.** R2.0 + MM FB (71.3%) − R1.0 + FB (60.4%) = 10.9%p로 맞아떨어진다. 같은 구성끼리는 MM FB 기준 7.4%p, Vanilla 기준 14.7%p다 (`03` §1).
- **FB → MM FB 효과는 과제마다 엇갈린다.** R2.0에서 handover_block은 FB 50% → MM FB 27%로 떨어진다. R1.0 pick_diverse_bottles와 stack_blocks_two도 소폭 떨어진다 (표 8). 본문의 "consistent gains"는 과장이다.
- **선택 편향 가능성 (코드로 확인, `04` D10):** 생성 루프의 최고 코드 선택과 보고 ASR이 같은 10회 실행을 쓰는지 논문은 밝히지 않는다. 코드 경로에서는 같은 `run()` 결과로 최고 코드를 고른다.
- **VLM 관찰자 성능 (부록 G.4):** 130개 시퀀스 (실패 101, 성공 29). 혼동행렬 TP 16, FP 61, TN 40, FN 13. 정확도 0.431, 정밀도 0.208, 재현율 0.552, F1 0.302. 실패 원인 위치 추정 정확도 12/40 = 30%. 오류 탐지는 과다 판정 쪽으로 치우쳐 있다. 이 130개 데이터는 공개되지 않았다.

### 4.2 embodiment별 파지 (표 2, 부록 L 표 11)

- 표 2 평균: RoboTwin 1.0 52.2% → 2.0 60.5% (+8.3%p). Aloha 65.1 → 78.8 (+13.7), Piper 2.4 → 25.1 (+22.7), Franka 67.3 → 67.2, UR5 57.6 → 57.1, ARX 68.6 → 74.2 (+5.6).
- 본문은 Aloha 이득을 "13.5%"라고 쓴다. 표 2는 13.7, 부록 표 11의 평균 행에서는 13.5다 (표 2와 표 11의 1.0 행 값이 서로 다르다, `03` §2).
- 50과제 평균을 표 11 원자료로 다시 계산하면 Piper 2.3→25.1 같은 값은 거의 맞지만 1.0 쪽 행 평균이 0.1–0.3 정도 다르다. 큰 문제는 아니다.

### 4.3 사전학습 효과 (표 3)

- 사전학습 9,600 궤적 (32과제 × 300). 평가는 8개 과제 (표 3). 본문은 "five unseen tasks"라고 쓰는데 표에는 8개 과제가 있다.
- 평균 (재계산 일치): RDT 18.8 → RDT+Clean 14.6 → RDT+Rand 24.8. Pi0 22.5 → Pi0+Clean 24.9 → Pi0+Rand 29.1.
- 상대 향상 31.9% (RDT), 29.3% (Pi0)는 재계산과 일치한다.
- **문장 대 표:** 본문은 clean 사전학습이 "negligible improvements"라고 쓰지만 RDT는 18.8 → 14.6 (−22%)로 **떨어진다**. Pi0만 +2.4 올라간다.
- ACT 평균은 표 값 2.0이지만 8개 행을 합치면 1.5다 (사소한 불일치).

### 4.4 실세계 (표 4, 그림 10)

- COBOT-Magic 양팔 플랫폼, RDT 백본, 과제 4개 (Stack Bowls, Handover Block, Pick Bottle, Click Bell). 설정 4개 (seen/unseen 배경 × 비정돈/정돈).
- 셀 값이 2%의 배수이므로 셀당 **시행 50회**로 추정된다 (논문은 시행 수를 밝히지 않음, `03` §4).
- 평균 행 (Unseen + 정돈, 가장 어려운 셀): 10 clean real 9.0% → 10 real + 1k synthetic 42.0% → 합성만 29.5%.
- **초록의 "367%"와 "228%"는 이 한 셀에서 나온다.** 42.0/9.0 − 1 = 366.7%, 29.5/9.0 − 1 = 227.8%. v1 초록은 "42.0% vs. 9.0%"라고 적어 근거를 밝혔지만 v2는 빠뜨렸다 (§6).
- 전체 8개 셀의 평균으로 보면 17.0% → 41.4%로 **약 143%** 상대 향상이다 (`03` §4).
- 본문의 "24.4%"는 절대 %p 평균 (13.5, 27.5, 23.5, 33.0의 평균)이다. 상대 향상과 섞여 쓰였다.
- 과제 4개, 셀당 시행 50회. 과제 단위 군집 부트스트랩의 95% 구간은 **+217% ~ +1,267%** (1k 대 10 real), **+32% ~ +833%** (합성만 대 10 real)로 매우 넓다 (`03` §4). 이 주장은 과제 4개 위에 서 있다.

### 4.5 벤치마크 (표 5, 부록 K 표 10)

- 설정: 과제당 **clean 50 데모**로 단일 과제 학습, 평가는 과제당 **100회** (Easy = clean, Hard = clutter·조명·질감·높이 랜덤화). 본문은 "Easy와 Hard는 평가 조건만 다르다"고 쓴다 (부록 K).
- 50과제 평균 (재계산, 표 10 원자료): RDT 34.5 / 13.7, Pi0 46.4 / 16.3, ACT 29.7 / 1.7, DP 28.0 / 0.6, DP3 55.2 / 5.0 (Easy/Hard). 보고값과 소수점 한 자리 안에서 일치한다.
- 낙폭: RDT −20.8%p, Pi0 −30.1%p. 본문 수치와 일치한다. 표 5의 "Average" 행은 12개 행만 보여 주면서도 같은 평균 값을 쓴다. 평균은 50과제에서 나온 것이다.
- 과제 단위 쌍체 Wilcoxon 검정 (n = 50): 모든 정책에서 p < 10⁻⁷ (ACT가 1.1×10⁻⁸로 가장 큰 값, 나머지는 더 작음). 낙폭은 과제별 샘플링 잡음보다 훨씬 크다. 단 시드는 하나다 (`03` §3).
- DP3: 쉬운 설정에서 가장 높다 (55.2). 본문은 "완벽한 점군과 깨끗한 배경 분할에서 나온 것"이라고 단서를 단다.

## 5. 한계와 논문이 말하지 않는 것

- **초록 수치의 근거가 한 셀이다.** 367%, 228%는 과제 4개의 한 셀에서 나온다. 셀 시행 수는 논문에 없다 (`03` §4).
- **평가 프로토콜의 선택 편향.** 공식 평가 스크립트 기본값은 전문가 검사 (`expert_check`)를 켜고, 전문가가 실패하거나 불안정한 시드는 건너뛴다 (`04` D7). 보고된 성공률의 분모는 건너뛰지 않은 시드다. 건너뛴 시드 수는 논문에 없다. Hard 설정에서 건너뛰는 비율이 더 높으면 Easy와 Hard의 비교가 같은 장면 집합에서 이뤄지지 않는다. 이 효과는 **측정되지 않았다**.
- **Easy/Hard는 저장소 설정상 평가 언어 분할도 다르다.** `demo_clean.yml`은 `eval_instruction: seen`, `demo_randomized.yml`은 `unseen`이다 (`04` D6). 논문의 "평가 조건만 다르다"와 맞지 않는다.
- **시드가 하나다.** 벤치마크, 코드 생성, 사전학습, 실세계 모두 시드 분산이 없다.
- **실세계 결과는 과제 4개, 셀당 시행 50회 가정.** 실세계 코드와 데이터는 공개되지 않았다.
- **질감 11,000개와 객체 731개의 수치는 자산 zip 없이는 확인할 수 없다** (`04` D4, D16).
- **시뮬레이터 실행 요구사항.** 저장소는 CUDA 기반 cuRobo v0.7.8과 SAPIEN 3.0.0b1을 요구한다. 맥에서 설치와 실행은 확인하지 못했다.
- **VLM 관찰자 정확도가 낮다** (정밀도 0.21). 그런데 코드 생성 성능 향상의 주장은 이 관찰자의 피드백에 기댄다 (§4.1). 

## 6. v1과 v2의 차이 (텍스트 대조, 2026-11-22)

v1 (2025-06-22, 22쪽)과 v2 (2025-08-27, 24쪽)를 같은 방식으로 맞춰 비교했다. 비교는 `.scratch/paper_v1.txt`와 `paper_v2.txt`의 문장 단위 차이로 했다 (70개 변경 조각).

| 항목 | v1 | v2 |
|---|---|---|
| 초록의 367% | "42.0% vs. 9.0%"로 근거를 명시 | 근거 없이 "367% relative improvement over the 10-demo baseline" |
| 사전학습 표 (표 4 → 표 3) | 5과제, RDT 14.8 → 25.4 (+71.6%), Pi0 21.0 → 29.8 (+41.9%) | 8과제, RDT 18.8 → 24.8 (+31.9%), Pi0 22.5 → 29.1 (+29.3%) |
| 열 이름 | R1.0 / R2.0 | Clean / Rand. |
| 같은 과제의 수치 | 예: Stack Bowls Two RDT 사전학습 28% | 같은 과제 30%. 열 대응이 명시되지 않아 세부 대응은 확정할 수 없다 |
| 벤치마크 | 13과제 부분집합 (그림 6) | 50과제 전체 (부록 K 표 10). 평균 행의 값도 다르다 |
| 표 2 (파지) | 표 3으로 번호 매김 | 표 2 |
| 실세계 표 | 표 5 | 표 4 (값 동일) |
| 코드 생성 표 1 | Top5-ASR R1.0 Vanilla 47.4% (오기) | 57.6% (수정) |

**해석:** v2는 사전학습 효과를 크게 낮춰 쓴다. 그 과정에서 초록의 근거를 빼고 수치 표를 다시 짰다. 최신 주장은 v2 기준으로 읽어야 한다. 학회 판본 (PMLR)은 이 분석에 포함하지 않았다.

## 7. 읽는 순서 메모
