## 1. 문제 설정과 핵심 주장

**문제.** VLA 모델에 촉각을 넣어도 성공률 이득이 일관되지 않고, 일부 visuo-tactile VLA는 촉각 입력을 거의 쓰지 않습니다 (§1, §4.4). 저자들은 이유를 촉각 신호의 성질에서 찾습니다. 촉각 센서는 로봇이 자기 행동에 대해 접촉이 어떻게 반응하는지를 재므로, 그 변화의 많은 부분(예: 그리퍼가 닫히면서 생기는 젤 변형)이 이미 관측된 영상과 실행한 행동으로 예측됩니다 (§1, Fig. 1a).

**주장.** 촉각 변화 ΔX는 두 부분의 합입니다 (식 2):

- 영상 관측과 실행 행동으로 예측되는 부분 E[ΔX | X_t, o_{t:t+5k}, a_{t+1:t+5k}]
- 두 조건으로 설명되지 않는 잔차 ν (= "tactile innovation", 촉각 혁신)

예측되는 부분을 학습 목표에 넣으면 손실이 그 부분에 지배되므로, 잔차 ν만 학습 신호로 씁니다. 잔차는 16비트 이산 코드로 압축하고, 정책(TacInno-VLA)은 현재 관측에서 이 코드를 예측하는 보조 손실만 받습니다. 코드는 배포 때 쓰이지 않습니다 (§1, §3.3, §3.3 말미).

**기여.** (1) 촉각 가리기 검사(tactile-off test)로 기존 정책의 촉각 의존성이 낮음을 보임, (2) 조건부 다중 프레임 토크나이저, (3) 보조 코드 예측이 있는 TacInno-VLA. 결과는 시뮬레이션 6과제 87.5%, 실로봇 4과제 70.5%이고, 가장 강한 visuo-tactile 기준선보다 각각 10.7 pp, 9.0 pp 높습니다 (Abstract, §4.2, §4.6).

## 2. 방법

### 2.1 문제 정식화와 촉각 혁신 (§3.1)

- 정책 입력: 영상 o_t, 언어 ℓ, 고유감각 q_t, 촉각 X_t(압입 깊이 맵과 마커 변위장). 출력: 행동 청크 a_{t+1:t+H} (§3.1; 청크 길이 H는 §3.1에 없고 구현 설정은 04 D9 참조).
- 촉각은 t, t+5, t+10, t+15 네 시점에서만 샘플링하고, 행동은 매 제어 단계마다 기록합니다 (§3.1).
- 식 (1): ΔX_{t:t+5k} = X_{t+5k} − X_t, k ∈ {1,2,3}.
- 식 (2): 위의 분해. 혁신 ν_{t:t+5k}는 "두 조건이 설명하지 못하는 잔차"입니다. 저자들은 정보 이론의 innovation 개념 [17, 18]을 가져왔다고 씁니다 (§2).

### 2.2 TacInno 토크나이저 (§3.2, Fig. 2)

- 인코더 E: 역동역학 모델. 입력은 X_{t:t+15}와 o_{t:t+15}, a_{t+1:t+15}. 출력 z_t의 네 벡터 (식 3).
- VQ: 네 슬롯 각각 16개 엔트리 코드북 → 4 × log2(16) = **16비트**. 코드 c_t ∈ {0..15}^4.
- 디코더 D: 순방향 동역학 모델. X_t와 c_t, 그리고 조건 o, a로 세 미래 시점의 촉각 변화를 한 번에 예측합니다. 조건은 세미콜론 뒤에 있으며 시간 주의(temporal attention)는 인과적입니다 (식 3 아래).
- 핵심 설계: 인코더와 디코더가 **둘 다** 영상과 행동을 조건으로 받습니다. 디코더가 조건을 직접 받으므로 코드에는 조건으로 설명되지 않는 정보만 남습니다 (§3.2 "Visual and action conditioning").
- 구현: 공간·시간 Transformer, 프레임마다 촉각·영상(동결 DINOv2 특징)·행동 토큰. 인코더에는 프레임마다 학습 가능한 쿼리 네 개를 붙입니다 (§3.2).
- 학습 목표: 재구성 손실 L_rec(접촉 가중 L1), 코드북 손실, 커밋 손실 (§3.2, 세부 가중치는 논문에 없음).

### 2.3 TacInno-VLA (§3.3, Fig. 3)

- 베이스: π0.5 [3] (PaliGemma 2B prefix + Gemma 300M action expert, flow matching).
- 조건 토큰 세 묶음을 행동 토큰 앞에 넣습니다 (§3.3): 촉각 토큰 60개(촉각 프레임 세 개 t−8, t−4, t × 젤 2개 × 토큰 10개), 학습 가능한 코드 쿼리 4개, 고유감각 토큰.
- 주의 마스크: 코드 쿼리는 prefix·고유감각·촉각 토큰을 볼 수 있지만, 다른 어떤 토큰(행동 토큰 포함)도 코드 쿼리를 보지 못합니다 (§3.3 "block-wise attention mask"). 그래서 코드 손실의 그래디언트는 공유 파라미터를 통해서만 행동 표현에 닿습니다.
- 손실 (식 4, 5): L_code = −(1/4) Σ_s log p_s(c_t^(s) | h_s) (네 슬롯의 분류기), L_contact는 촉각 인코더에 붙인 접촉 상태 헤드, L = L_flow + λ_contact L_contact + λ_code L_code. λ는 학습 시작 시 각 보조 손실이 L_flow의 15%가 되도록 정한다고 씁니다 (§3.3).
- 배포: 토크나이저와 두 보조 헤드를 제거하고, 촉각 토큰 60개만 남긴 모델을 씁니다 (§3.3 "Training and deployment").

### 2.4 설계의 근거 (논문이 직접 든 것)

- 구조 가설 세 개: 조건부(§3.2), 동적(두 프레임 대신 다중 프레임, §3.2, Table 2 "two-frame code"), 미래에 있음(코드를 입력이 아닌 타깃으로, §3.3, Table 2 "w/o attention mask", "w/o code loss").
- 가중치 방식(촉각 변화 크기로 가중)은 도움이 되지 않는다고 주장하며 Fig. 4의 시각 자료를 씁니다 (§1, "Weighting the loss by the magnitude ... does not help").

### 4.5 촉각 혁신의 성질 (§4.5, Fig. 4)

- 데이터셋 수준: 코드 없이 문맥(과제, 영상, 고유감각, 미래 행동)만으로 예측할 때, 촉각 기록이 더해 주는 정보는 0.020 nats입니다. 혁신 코드에서는 0.073 nats로 3.6배입니다 (§4.5). 전체 미래 촉각 변화는 문맥만으로 거의 예측된다는 주장입니다.
- 6과제에서 혁신은 평균 37%입니다 (§4.5). Lift Can에서 영상과 행동이 설명하는 비율은 +5 / +10 / +15 단계에서 65 / 78 / 87%이고, 코드가 추가로 25 / 16 / 7%를 설명합니다 (§4.5).
- 시간 분포(Fig. 4): 혁신 코드의 설명 비율은 접촉 직전과 미끄러짐 직전에 높고, 캔의 움직임이 영상에 보이면 0으로 떨어집니다.
- 코드 손실의 효과(§4.5): 코드 손실이 있을 때 행동 전문가의 촉각 토큰이 혁신 코드를 top-1 49.0%로 맞히고, 없을 때는 38.6%입니다. 주의 가중치와 촉각 입력의 상관은 촉각을 끄면 90%가 사라지고, 코드 손실이 없으면 13%만 사라집니다.

### 4.6 결과 전체 평가

- 주장 (1)은 표 1, 4로 뒷받침됩니다. 다만 실로봇은 시도가 적어 차이가 확실하지 않습니다 (03 §4).
- 주장 (2)는 표 3이 가장 강한 증거입니다. 촉각을 끄면 TacInno만 크게 떨어집니다.
- 주장 (3)은 표 2에서 대부분 방향이 맞지만, 시도 수가 없어 통계 검정이 근사에 머뭅니다 (03 §2).

## 5. 한계와 빠진 내용

- 논문에 별도의 한계 절이 없습니다. 결론은 "혁신 개념은 촉각에만 있는 것이 아니며 다른 모달리티로 확장은 후속 연구"라고만 씁니다 (§5).
- 학습 세부(VLA 학습 단계 수, 학습률, 배치 크기, EMA, 토크나이저 학습 단계 수, λ 값, 코드북 리셋, 커밋 가중치)가 없습니다. 공식 코드에 있습니다 (04 D2–D5).
- 실로봇 4과제가 하나의 모델인지 과제별 모델인지 명확하지 않습니다. 공식 체크포인트는 하나가 4과제를 처리합니다 (04 D10).
- 시뮬레이터의 행동 한계(공식 코드는 기본값의 2배), 유효하지 않은 에피소드 처리, 실행 구간 길이가 빠져 있습니다 (04 D8, D9).
- Put Bottle은 머리 카메라만 쓰고, 그림 3의 "head + wrist" 구성과 다릅니다 (04 D11).
- 실로봇 시도 수가 과제당 50회여서 차이 검정력이 낮습니다 (03 §4).
