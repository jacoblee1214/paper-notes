# 04. 주장 검증 (공식 코드 없음)

분석일 2026-11-22. 공식 코드가 공개되지 않아(프로젝트 페이지 "Code (Coming Soon)", GitHub에 저자의 OTQL 코드 저장소 없음, `02` §4) 코드 대조(D 항목)는 하지 못했습니다. 대신 논문의 주장을 표·그림·부록의 수치로 확인했습니다. 수치 번호 V, 일관성 번호 K는 `03`, 장난감 번호 T는 `03` §4입니다.

## 1. 확인 범위

- **한 것:** 논문 PDF(v1)와 프로젝트 페이지의 표·벡터 그림 재계산, 기준선 값의 출처 대조(QAM 논문 표와 72칸), 선행 코드 저장소의 메타데이터 확인.
- **못 한 것:** 손실·하이퍼파라미터·평가 프로토콜의 코드 대조, 시드 수와 신뢰구간(논문에 없음), Fig. 6의 수치(래스터 이미지).
- 판정 표기: **지지** = 보고 수치로 확인됨, **부분** = 방향은 맞으나 크기·범위가 다르거나 가정 의존, **미확인** = 보고된 근거로 확인 불가, **불일치** = 재계산이 논문 서술과 다름.

## 4. 구현 가능성 판정 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**논문 수치의 재현은 불가능합니다. 알고리즘을 작은 상태 기반 과제에서 구현해 보는 것은 가능합니다(공식 코드 없이 논문만으로 약 1–2주, 추정, 측정 전).**

| 항목 | 이 맥에서 | 필요한 것 | 비고 |
|---|---|---|---|
| 실로봇 단일 과제(Fig. 5) | **불가** | KUKA iiwa 14, 그리퍼, 카메라 2대, SpaceMouse, 과제 환경 | 로봇 없음 |
| 실로봇 SmolVLA 적응(표 2) | **불가** | 위 장비 + GPU(VLM과 행동 헤드 학습) | 코드·데이터 미공개 |
| OGBench 오프라인 전체(표 1, 40과제 × 시드) | **사실상 불가** | GPU 또는 장시간 CPU | 1M 스텝, 크리틱 앙상블 10, MLP 512×4. 한 과제 한 시드가 이 맥에서 수 시간으로 추정(측정 전) |
| OGBench 한두 과제의 축소 학습(예: 10만 스텝) | **가능(조건부)** | `ogbench` 패키지 설치(현재 미설치, 설치 승인 필요), torch로 알고리즘 구현 | MuJoCo는 이미 설치됨. 논문 수치와 직접 비교는 어려움 |
| MuJoCo 두 과제(Fig. 3) | **불가(데이터 없음)** | 환경 정의와 시연 | 저자가 게임패드로 수집, 미공개 |
| 알고리즘 구조 구현(wCOT-CFM, 크리틱, 거절 샘플링) | **가능** | torch(설치됨), Sinkhorn 직접 구현 | 장난감 T1이 핵심 부분을 구현해 둠. 2D에서 수 분 |
| 가중 OT 결합의 통계 검사(유효 표본, 클램프) | **가능, 완료** | numpy | T2 |

- **노력 추정(측정 전):** 공식 코드가 없어 (1) 상태 기반 OTQL 알고리즘(크리틱 앙상블, flow 정책, Sinkhorn OT 결합, 거절 샘플링) torch 구현 3–5일, (2) 간단한 상태 기반 과제 하나에서 가중 질량의 효과를 분리하는 절제(가중 OT 대 비가중 OT + 가중 손실, 클램프, α) 1주. 후자가 논문이 분리하지 못한 질문에 직접 답합니다.
- **공식 코드가 공개되면:** 정적 대조(D 항목)를 새로 해야 합니다. 특히 U1–U3.
