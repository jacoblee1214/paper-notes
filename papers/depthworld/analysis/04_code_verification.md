- **라이선스 (데이터):** DROID-3D 보정 자세는 CC BY 4.0, `pseudolabels/`는 CC BY-NC 4.0(VGGT-Ω 출력 기반). 접근은 수동 승인이고 약관 문서에 동의해야 합니다. 깊이 데이터는 요청 양식으로만 받을 수 있습니다.

### 2.1 논문 주장의 코드 쪽 확인

- **보정 결과의 사용은 확인됩니다.** `dataset/dataset_droid_pointmap.py`는 보정 자세와 손-눈 변환을 읽어 로봇 기준 점지도를 만듭니다. 누락된 자세는 0 점지도와 `valid=0`으로 처리합니다(같은 파일 주석).
- **보정 자체는 확인되지 않습니다.** D20입니다. 논문의 가장 큰 기여 중 하나가 공개 코드에서 검증되지 않습니다.

## 4. 구현 가능성 (이 맥)

이 맥은 Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음입니다. 아래 노력 추정은 모두 측정하지 않은 추정입니다.

| 항목 | 판정 | 근거 |
|---|---|---|
| 세계 모델 학습 (90k 스텝, 전역 배치 64) | **불가** | 논문 C.6: H200 두 노드 약 2일. 저장소 설정도 FSDP와 CUDA 전제 |
| 공개 체크포인트로 한 청크 추론 (CPU 또는 MPS) | **조건부** | 체크포인트 6.1 GB (horiz) 또는 6.2 GB (점지도) 다운로드 승인 필요. SVD 기반 파이프라인 설치(`diffusers` 고정 버전)도 승인 필요. 장치 선택 코드가 cuda 또는 cpu뿐이라 MPS 포팅이 필요합니다. 속도는 측정 전 |
| 표 2 재현 (256 궤적 자기회귀 롤아웃, 깊이 참조) | **불가** | GPU 시간과 DROID-3D 깊이 데이터(요청 양식으로만 제공) 필요 |
| 보정 파이프라인 재현 (요인 그래프, 대응 매칭, S²M²) | **불가 (구현 필요)** | 공개 코드에 최적화기가 없음 (D20). S²M²와 RoMa·LoMa 가중치 필요. 원본 DROID 스테레오 녹화 용량은 확인 안 함 |
| 점지도 손실 식의 CPU 수치 검사 (합성 입력) | 가능 | numpy 또는 torch CPU로 수 분. 다만 본문 주장과 직접 연결이 약해 이번 분석에서는 하지 않았습니다 |
| 정적 코드 대조 (이 문서) | 완료 | D1–D22 |

- **노력 추정 (추정):** 공개 체크포인트 한 청크의 MPS 포팅과 추론 확인 2–4일. 보정 파이프라인을 새로 짜는 일은 최적화기, 대응 매칭, S²M² 연결까지 4–8주. 학습 축소판은 GPU가 필요해서 이 맥 기준으로는 세지 않습니다.
- **종합:** 세계 모델의 **구조**(공간 타일링, 점지도 헤드)는 MIT 코드로 구현할 수 있습니다. 그러나 논문 수치를 이 맥에서 재현하는 것은 불가능합니다. 핵심 기여인 **보정 최적화기가 공개되지 않아** 보정 부분은 처음부터 다시 짜야 합니다.
