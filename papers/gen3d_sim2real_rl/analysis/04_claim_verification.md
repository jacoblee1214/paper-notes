## 2. 원문 내부의 불일치와 모호함

1. **헤드라인 79.8%** (C1). 표 1의 평균과 다르고, 어떤 체크포인트가 실물에 쓰였는지도 본문에서 확정되지 않습니다.
2. **TF 평균 정의** (C8). 표 1은 성공 에피소드만 평균한다고 쓰지만, 표 2에는 그런 문구가 없습니다.
3. **에피소드 길이 단위** (표 A.1). 값 25가 청크인지 환경 스텝인지 밝히지 않았습니다.
4. **학습 장면 수용과 수동 조정** (표 C.1). 85% 수용과 나머지 15% 수동 조정이 학습 세트에 어떻게 들어갔는지 불명입니다.
5. **ID 기준의 정의** (표 1). N = 100의 ∆G가 W 평균을 기준으로 하고, SimplerEnv 행은 96.7(SE 정책의 자기 장면 성공률)을 씁니다. 이 정의는 표 주석에 없습니다.
6. **DFR에서 "−"의 처리** (표 2). 0으로 보는 것이 맞지만 본문에 명시되지 않았습니다.
7. **표 1 SD의 정의.** 3 실행의 표준편차인지 표본인지 모릅니다.

## 3. 대조하지 못한 것

- 학습 로그, 체크포인트, 장면 자산 목록(부록 E–H는 목록과 그림만 있음).
- 실물 영상의 시도별 결과 (프로젝트 페이지에 영상이 있으나 분석하지 않음).
- 공식 π0 비교 수치.

## 4. 구현 가능성 판정 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**판정: 논문 수치의 재현은 이 맥에서 불가능합니다. 재계산과 통계 검사는 완료했습니다. PPOFlow(단일 가우시안 + PPO) 알고리즘의 축소판은 CPU 토이로 조건부 구현이 가능하지만, 논문의 VLA 주장은 검증하지 못합니다.**

| 단계 | 필요 자원 | 이 맥 | 판정 | 노력 추정 |
|---|---|---|---|---|
| 표 재계산, 검정, 그래프 | CPU | 가능 | **완료** | 1일 미만 (완료) |
| πpre (π0 3B) 추론 | open-pi-zero (torch 2.5.0 고정, Python 3.10), BridgeV2 체크포인트 다운로드 | MPS에서 조건부. 속도 미측정 | **조건부** (설치와 다운로드 승인 필요) | 반나절 (측정 전) |
| 생성 장면 (EmbodiedGen) | 3D 생성 모델, RTX 4090 기준 장면당 46.8분 | 확인하지 못함. CUDA 전제로 보임 | **불가** (추정, 확인 필요) | 해당 없음 |
| GPU 병렬 시뮬 (ManiSkill 3) | Linux와 Vulkan이 주 지원 | macOS 지원 제한 (README) | **불가** (추정) | 해당 없음 |
| PPOFlow 학습 (N = 1–100 장면) | 8 × RTX 6000 Ada, 5일 | 불가 | **불가** | 해당 없음 |
| 실물 WidowX 250S 평가 | 로봇, 카메라, 정책 체크포인트 (미공개) | 불가 | **불가** | 해당 없음 |
| PPOFlow 축소판 (CPU 토이, 작은 흐름 정책, 도달 과제) | numpy 또는 torch CPU | 가능 | **조건부** (재현 승인 후) | 1–2주 (추정, 측정 전) |

- **구현할 수 있는 것:** 단일 단계 가우시안 정책으로 바꾸는 PPOFlow 식 3–7, 중요도 비율 지수 s, 희소 성공 보상 식 A.1. 이 셋은 CPU 토이로 구현할 수 있습니다.
- **구현할 수 없는 것:** 장면 생성 규모, 학습 규모, 실물 평가. 논문의 핵심 수치(79.8%, 75%)는 이 맥에서 재현되지 않습니다.
- **공식 코드가 없어** 구현은 논문 설명(식과 표 A.1)에 의존합니다. 기울기 클리핑, 노이즈 머리 구조, 에피소드 길이 단위 등 재현 세부가 빠져 있어 같은 결과를 기대하기 어렵습니다.
