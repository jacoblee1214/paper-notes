## 4. 구현할 수 있는지

### 4.1 공식 코드로 실물 재현 (하드웨어)

필요한 것: 6축 로봇 팔(코드는 xArm6와 FR3 설정을 함께 가진다), Allegro 16-DoF와 Inspire 6-DoF 손(장착 인터페이스 포함), 하드웨어 동기 RGB 카메라 20–24대와 ChArUco 보드, 조명 셀, Linux와 CUDA GPU 여러 대 또는 여러 환경(D20), 비공개 `paradex` 라이브러리(D19), 작성자 환경의 경로와 네트워크 공유(D19).
**판정: 불가능하다(연구실 워크셀과 비공개 라이브러리 없이는 실행되지 않는다).** 하드웨어 규모는 "로봇 팔 1 + 다지 손 1 + 카메라 20 이상 + 동기 장치"다. 설치와 캘리브레이션, 코드 정리까지 포함하면 수 주에서 수 개월이다(추정).

### 4.2 이 맥 (Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음, torch 미설치)

- **실물 재현: 불가능.** 로봇, 손, 카메라가 없다.
- **공식 소프트웨어 재현: 불가능.** SAM 3, FoundationPose, BODex, cuRobo가 CUDA를 쓴다(D20). `paradex`가 없다(D19). 서브모듈 GoTrack도 비어 있다(D15).
- **이 맥에서 할 수 있는 것(CPU):** 표 재계산과 통계(완료, `table_check.py`), 라벨 오차 토이(완료), 처리량과 선택 편향 모형(완료). charuco 판독 로직은 OpenCV ArUco로 다시 쓸 수 있으나(`paradex` 래퍼 없이), 검증용 영상이 없다.
- MPS는 작은 학습 토이(예: 라벨 노이즈 아래 분류기)에 쓸 수 있다. 이 폴더의 토이는 numpy로 충분했다.

| 잔차 토크 감지 | 중간 | MLP는 쉽고, 학습 데이터(자유 공간 궤적)가 필요 | 학습 데이터가 있어야 함 |
| 리셋 파지 생성 | 큼 | BODex와 cuRobo 충돌 계획 | 어렵다(CUDA 의존) |
| 검색 실행(DB 조회 + 팔 계획 + 충돌 확인) | 쉬움 | DB 조회와 계획 호출 | 가능 |

추정: 아이디어 수준의 재구현(루프 + 라벨 규칙 + 검색, 시뮬 기반)은 **2–4주**(1인, 하드웨어 없음). 실물 루프 재구현은 하드웨어 포함 **수 개월**. 이 값은 추정이다.
