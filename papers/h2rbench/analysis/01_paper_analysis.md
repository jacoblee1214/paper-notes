## 1. 문제와 주장

사람 영상으로 로봇 정책을 학습하는 H2R(human-to-robot) 방법들이 서로 다른 과제, 장면, 물체, 로봇 데이터 양으로 평가되어 비교가 어렵다는 것이 출발점입니다(§1). 논문의 세 가지 기여(§1)는 다음입니다.

1. 실제 장면을 재구성한 시뮬레이션 과제 네 개와, 과제별 사람 데모(실제 영상)와 로봇 데모(시뮬)를 갖춘 벤치마크.
2. 사람 데모 양에 따른 방법별 확장 곡선과 실패 유형 분류.
3. 시뮬 성능이 실로봇 성능을 대략 예측한다는 검증(Pearson r = 0.89, Spearman ρ = 0.85, MMRV 0.06, 초록과 Table 4).

핵심 설계 두 가지는 (i) 사람 쪽은 시뮬 손이 아니라 **실제 사람 영상**을 그대로 쓰는 것(§1), (ii) 로봇 데모 수는 고정하고 사람 데모 수만 바꾸는 것(§3.1)입니다.

## 2. 벤치마크 설계

### 2.1 파이프라인 (§3.3, Fig. 2)

3단계입니다. (1) 실제 작업대를 **PolaRiS**(Isaac Lab 위의 real-to-sim)로 재구성하되 원래 파이프라인 대신 **Marble**로 메시와 가우시안 스플랫을 만들고, 상호작용 물체는 **TRELLIS**로 다시점 이미지에서 만들어 실제 크기로 맞춥니다. (2) 사람 데모는 고정 카메라 3인칭 RGB 영상(여러 작업자), 로봇 데모는 시뮬에서 **cuRobo** 모션 플래너로 생성하고 실세계에서는 Franka Panda를 GELLO로 원격 조작해 모읍니다. (3) 시뮬에서 학습과 평가를 합니다. 관측은 다시점 RGB-D, 로봇 자세, 언어이고 행동은 로봇 베이스 좌표계의 3D 이동 + 6D 회전 + 이진 그리퍼입니다(§3.1).

### 2.2 과제 (Table 2, Table 6)

| 과제 | 지평 | 정밀도 | 로봇 데모 | 최대 사람 데모 | 단계 수 (Table 6) |
|---|---|---|---|---|---|
| 집기-놓기 (머그 → 접시) | 짧음 | 거침 | 40 | 100 | 3 (닿기, 들기, 놓기) |
| 쌓기 (그릇 → 그릇) | 짧음 | 보통 | 100 | 300 | 4 |
| 끼우기 (도넛 → 말뚝) | 짧음 | 정밀 | 100 | 300 | 4 |
| 순차 조작 (블록 → 상자) | 김 | 보통 | 100 | 300 | 3 (물체 셋을 상자에 넣기) |

과제 이름이 Table 2에서는 "Blocks → Box", Table 6에서는 "blue toy, orange toy, yellow toy into the pink box"이고 공식 코드의 환경 이름은 `PickPlaceToys`입니다. 같은 과제의 표기가 일관되지 않습니다(V1).

### 2.3 평가 지표 (§3.4, §5.1)

- **진행도(Prog.)**: 과제를 누적 단계로 나눈 평균 단계 달성률. **최종 단계 성공률(SR)**: 마지막 단계 달성률.
- **로그 오즈 이득** Δlogit = log(p_{R+H}/(1−p_{R+H})) − log(p_R/(1−p_R)) (§5.1): 로봇 전용(R) 대비 로봇 + 사람(R+H)의 효과를 포화 근처에서 공정하게 재려는 지표.
- **Sim-vs-Real**: 방법–과제 쌍 N = 16에 대해 풀링한 Pearson r, Spearman ρ(식 1, 2)와 과제별 MMRV(식 3, SIMPLER 방식)의 과제 평균(부록 D.4).

## 3. 평가한 방법 (§4, 부록 A.3)

| 방법 | 격차를 메우는 방식 | 사용 시점 (Table 5) | 비고 |
|---|---|---|---|
| Phantom [13] | 사람 팔을 지우고 로봇 팔을 덧그리는 시각 정렬 | 정면 | 로봇 팔 렌더가 다시점에서 일관되지 않아 정면만 사용 |
| Point Policy [12] | 공유 3D 키포인트(DIFT + CoTracker) | 정면 + 좌측 | 과제당 1개 데모의 첫 프레임 키포인트를 수동 지정(A.3.2) |
| AMPLIFY [14] | 잠재 동역학(모션 토큰) 분리 | 정면 + 좌측 | 손목 영상 사용 불가 |
| GHOST [15] | 고수준 하위 목표 계획(사람 + 로봇) + 저수준 제어(로봇만) | 정면 + 좌측 + 손목 | 하위 목표는 엄지–검지 거리 기준(사람)과 그리퍼 개폐(로봇)로 뽑음, 임계값은 과제별 수동 선택 |

부록 B.5의 XSkill은 표현이 붕괴하거나(단순 과제) 프롬프트를 무시해(복잡 과제) 점수가 낮아 본문에서 뺐습니다(Table 10).

## 4. 실험 결과

### 4.1 Q1 능력과 사람 데모 효과 (§5.1, Table 3, Fig. 3)

3개 시드 평균 ± SD, 최대 사람 데모, 시드당 30회 롤아웃(90회)입니다. Table 3과 Table 9는 같은 표입니다(`03` K1).

|---|---|---|---|---|
| Phantom | 77.0 ± 1.4 / 56.7 ± 2.7 | 75.6 ± 2.7 / 25.6 ± 6.8 | 39.2 ± 3.6 / 7.8 ± 4.2 | 37.8 ± 2.4 / 13.3 ± 4.7 |
| AMPLIFY | 74.4 ± 2.7 / 58.9 ± 4.2 | 85.3 ± 3.7 / 61.1 ± 9.6 | 35.0 ± 6.2 / 2.2 ± 1.6 | 8.1 ± 3.4 / 0.0 ± 0.0 |
| Point Policy | 82.6 ± 7.4 / 62.2 ± 11.7 | 79.7 ± 7.7 / 61.1 ± 17.1 | 37.8 ± 6.5 / 6.7 ± 11.5 | 17.4 ± 5.6 / 0.0 ± 0.0 |
| GHOST | 91.1 ± 4.9 / 82.2 ± 6.9 | 88.9 ± 5.9 / 76.7 ± 8.8 | 64.7 ± 1.3 / 34.5 ± 6.9 | 63.3 ± 8.4 / 38.9 ± 15.0 |

본문 결론: GHOST가 가장 강하고 일관되며, 계층 분해나 명시적 하위 목표 표현이 유리합니다. 사람 데모는 집기-놓기와 쌓기에서 도움이 되고(고수준 공간 의도 전달), 끼우기에서는 자주 해가 되며, 순차 조작에서는 제한적입니다(§5.1, Fig. 3).

### 4.2 Q2 사람 데모 수에 따른 확장 (§5.2, Fig. 4, Table 7)

단순 과제는 대체로 단조 개선, 쌓기는 방법별로 갈리고, 끼우기는 이득이 작거나 불안정하며, 순차 조작은 수익 체감입니다. Table 7은 최대 설정(Prog.@MaxH)과 확장 곡선 위의 최고 진행도(Best Prog.)와 그때의 사람 데모 수를 줍니다. 최고값이 최대 설정과 다른 칸이 16개 중 7개이고 평균 격차는 1.6 퍼센트포인트, 최대 5.9입니다(`03` K6).

### 4.3 Q3 Sim-vs-Real (§5.3, Table 4, 부록 D)

| 조건 | Pearson r | Spearman ρ | MMRV |
|---|---|---|---|
| 로봇 전용 | 0.971 | 0.940 | 0.014 |
| 로봇 + 최대 사람 | 0.894 | 0.851 | 0.060 |

과제별 MMRV(Table 13): 집기-놓기 0.000/0.000, 쌓기 0.042/0.171, 끼우기 0.000/0.037, 순차 0.015/0.033 (로봇 전용/최대 사람). AMPLIFY를 빼면 최대 사람 조건의 MMRV가 0.060 → 0.007, 쌓기를 빼면 0.060 → 0.023입니다(Table 14). 논문은 AMPLIFY의 시뮬–실세계 차이를 "계획기 궤적은 매끈하고 원격 조작 데모는 변동이 크기 때문"이라고 설명합니다(D.2).

**실세계 수치는 어떤 표에도 없고 산점도(Fig. 5, 15, 16)에만 있습니다.** 실세계 평가 시도 수도 적혀 있지 않습니다(`03` V3). 이 분석은 산점도의 점 좌표를 읽어 되살렸고, 읽은 값으로 Table 4, 12, 13, 14가 소수 셋째 자리까지(과제별 MMRV는 ±0.001 이내) 다시 나옵니다(`03` K7).

### 4.4 부가 실험

- **분포 밖 배치 (B.3, Table 8):** 쌓기, 로봇 데모는 오른쪽에서만, 평가는 왼쪽. Prog. Point Policy 78.3, GHOST 58.3, Phantom 48.3, AMPLIFY 41.7. Point Policy의 강건성을 "인간과 로봇의 통합 행동 공간" 덕으로 해석합니다.
- **XSkill과 Diffusion Policy (B.5, Table 10):** 로봇 100회로 학습한 Diffusion Policy가 쌓기 Prog 95.0 / SR 80.0, 끼우기 41.7 / 0.0, 순차 82.2 / 63.3입니다. 같은 과제에서 사람 데모를 쓴 H2R 방법의 최고값은 88.9 / 76.7, 64.7 / 34.5, 63.3 / 38.9입니다(`03` K17).
- **AMPLIFY 잠재 정렬 (C.1.2, Table 11):** 쌓기는 사람 데모를 늘릴수록 W2 거리가 줄고(10.91 → 9.05), 끼우기는 늘며(6.08 → 10.97), 이를 사람 데모의 이득과 연결합니다.

## 6. 읽으면서 남은 의문 (분석 문서 03, 04로 이어짐)

1. 산점도의 "Success Rate" 축은 실제로 진행도이고, 시뮬 값은 3 시드 평균(Table 3)이 아니라 Table 7의 값입니다(`03` K6, V2).
2. 로그 오즈 이득(Fig. 3B)은 본문 정의("success rates")와 달리 진행도로 계산되어 있습니다(`03` K5).
3. 사람 데모의 효과를 시뮬이 예측하는가는 검증되지 않았습니다. 검증된 것은 방법·과제의 절대 수준 순서입니다(`03` K9).
4. 쌓기와 순차 조작에서 로봇 전용 Diffusion Policy가 모든 H2R 방법과 같거나 높습니다(`03` K17).
5. 평가 규칙(단계 임계값, 성공의 "한 번이라도" 의미, 에피소드 길이)이 논문에 없고 코드에만 있습니다(`04` D1–D6).
