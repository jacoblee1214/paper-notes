## 2. RoboTwin: 기준선이 공식 리더보드보다 낮다

RoboTwin 2.0 공식 리더보드(`paper/site/robotwin_leaderboard.json`, 2026-10-25 갱신)의 조건은 다음과 같습니다.

- 학습 데이터: 50과제 × clean 시연 50개(2,500개)
- 평가: 과제당 100회, clean과 random

AW-0의 학습 데이터 조건과 같습니다. 이 리더보드에 **RoboTwin 팀이 직접 학습한 π0.5(co-train, 50과제를 정책 하나로 학습)**가 2026-08-10부터 올라와 있습니다.

| | Clean | Random | 평균 |
|---|---|---|---|
| π0.5, 논문 재현 (Table 1) | 54.9 | 27.7 | 41.3 |
| π0.5, RoboTwin 리더보드 | **70.66** | **46.0** | **58.3** |
| AW-0 | 80.8 | 20.6 | 50.7 |
| AW-0 hybrid | 63.1 | 29.2 | 46.2 |

- **과제별 비교:** 논문 값이 리더보드보다 낮은 과제는 clean 36/50, random 42/50입니다(Wilcoxon p = 5 × 10⁻⁶, 3 × 10⁻⁹). 과제별 상관은 clean 0.48, random 0.74입니다. 같은 모델을 제대로 재현했다면 과제별 상관이 더 높아야 합니다.
- **리더보드 π0.5를 기준으로 하면** AW-0는 clean에서 10.1점 높지만, random에서 25.4점, 평균에서 7.6점 낮습니다. 하이브리드 모드의 random 29.2도 46.0보다 16.8점 낮습니다.
- **리더보드 순위:** 논문 공개일(2026-10-21) 이전에 등록된 27개 항목 사이에 넣으면 다음과 같습니다.
  - AW-0의 평균은 13위, clean은 9위입니다. clean에서 AW-0보다 높은 항목은 PatchWAM 91.6, ME-Dex-1.0 89.6, CloudRobo-WM 88.9 등 8개입니다.
  - 하이브리드의 random은 13위입니다.
- **차이의 원인:** 논문의 π0.5 설정(부록 C)은 action horizon 50, FSDP, 배치 256, 학습률 5e-5입니다. 리더보드의 설정은 이 저장소에서 확인할 수 없습니다. 시행 수(50 vs 100)는 평균에 편향을 만들지 않습니다.

**판단:** 리더보드 값이 같은 학습 데이터와 평가 장면에서 나온 것이라면, Table 1의 "평균이 가장 높다"와 "하이브리드가 random에서 π0.5를 포함한 모든 기준선보다 높다"는 **논문이 직접 재현한 기준선 안에서만** 성립합니다. 평가 장면의 seed가 같은지는 논문에 적혀 있지 않습니다.

## 3. 코드 전문가의 효과 분해

Fig. 5, Fig. 7, Table 3–4는 같은 실제 로봇 8과제를 같은 프로토콜로 평가했습니다. 그래서 평균을 한 줄로 세울 수 있습니다(`report/figures/ablation_ladder.png`).

| 변형 | 평균 | 무엇이 빠졌나 |
|---|---|---|
| V → A (w/o code) | 32.9 | 코드 전문가 전체 **+ Qwen3-VL ViT 시각 경로** |
| V → C → A | 48.3 | 코드가 video를 이끌지 못함 |
| AR 코드 | 54.5 | joint denoising |
| VAE 특징으로 코드 계획 | 55.6 | 코드 전문가의 ViT 입력 |
| 주석 없는 코드 | 62.8 | 코드 안의 자연어 |
| 스킬 없는 코드 | 63.3 | 스킬 추상화 |
| 자연어 subgoal | 63.6 | 코드 형식 전체 (자연어 계획은 유지) |
| AW-0 | 71.1 | |

- **코드 형식이 아니라 계획 스트림의 효과가 큽니다.** 전체 이득 38.3점(32.9 → 71.1) 가운데 30.8점은 자연어 subgoal만으로도 얻습니다. "코드 대 자연어"의 몫은 7.5점(20%)입니다. 자연어 subgoal 변형(63.6)도 가장 강한 기준선 DreamZero(46.0)보다 17.6점 높습니다.
- **w/o code 변형은 의미 수준 시각 입력까지 잃습니다.** 공식 코드(`build.py`)에서 Qwen3-VL ViT prefix는 `use_code_expert`가 켜졌을 때만 붙습니다. w/o code 변형의 video와 action 전문가가 보는 관측은 Wan2.2 VAE 잠재뿐입니다. Table 3에서 코드 전문가의 입력만 ViT에서 VAE로 바꿔도 15.6점이 떨어지므로, 32.9 → 71.1의 차이 가운데 상당 부분이 ViT의 몫일 수 있습니다. "코드는 있고 ViT가 없는" 변형과 "코드는 없고 ViT가 있는" 변형이 없어서, 두 효과를 나눌 수 없습니다.
- **w/o code 변형이 기준선 WAM보다 약합니다.** w/o code(32.9)는 구조가 가까운 DreamZero(46.0)보다 13점 낮습니다. 저자들의 WAM 바탕 자체가 실제 로봇 100개 시연 조건에서 강하지 않다는 뜻입니다. 그래서 "코드가 WAM을 강하게 만든다"는 결론은 이 바탕 위에서 얻은 것입니다.
- **스킬과 주석의 효과는 비슷한 크기입니다(각 약 8점).** 주석을 빼거나 스킬을 빼거나 자연어로 바꾸면 모두 62.8–63.6으로 수렴합니다. "전체 프로그램"이 더하는 몫은 세 요소가 함께 있을 때만 나타납니다.

## 5. Noise 재표본화와 "미리 보는 영상"의 실제 상태 (`noise_toy.py`)

- **N1.** 사전학습 video 분포(u = 0.999·Beta(7,1), shift 5)에서는 σ > 0.9가 95.5%이고, 중앙값은 σ = 0.979입니다. 공식 코드 주석의 "~95%"와 일치합니다. 이 분포만 쓰면 action 손실은 거의 잡음뿐인 video만 보고 학습됩니다. Eq. 5–6이 이 문제를 고칩니다.
- **N2.** α = 0.5이므로 가중치의 상한은 1/α = 1/(1 − α) = 2입니다. 실제 최댓값은 w_v 1.75, w_g 2.0입니다. Table 6의 importance clip 4.0은 **한 번도 작동하지 않습니다**. 공식 코드 주석도 같은 상한을 적어 둡니다.
- **N3.** 정규화하지 않은 가중 손실은 목표 분포의 기댓값을 정확히 재현합니다. 공식 설정처럼 GPU당 배치 6(3 + 3 층화)에서 "배치 평균 1로 정규화"하면 작은 편향이 생깁니다. 예를 들어 action 손실이 σ < 0.7 구간을 보는 비율은 31.8%가 아니라 30.0%가 됩니다. 실효 표본 수는 배치의 약 70%입니다. 영향은 작습니다.
- **N4.** 추론에서 video와 action은 같은 단계 수로 함께 denoise합니다. 공식 코드에서 action은 각 단계 시작 시점의 video를 읽습니다. 그래서 action이 마지막으로 읽는 video의 σ는 단계 수에 따라 다음과 같습니다(`report/figures/noise_sigma.png`).

  | joint 단계 | action이 읽는 video σ | 마지막 σ |
  |---|---|---|
  | 4 (논문 Table 6) | 1.0, 0.94, 0.83, 0.63 | **0.625** |
  | 10 (실물 서버 기본값) | 1.0 … 0.36 | 0.357 |
  | 20 (RoboTwin 공개 설정) | 1.0 … 0.21 | 0.208 |
  | 40 (RoboTwin 하이브리드) | 1.0 … 0.11 | 0.114 |

  논문 설정(4단계)에서 action이 보는 "미래 영상"은 잡음이 62.5% 이상 섞인 상태입니다. 논문이 말하는 predictive guidance는 선명한 미래 영상이 아니라, 덜 denoise된 video 전문가의 내부 특징입니다. 지연 0.23 s(Fig. 6)는 4단계일 때의 값으로 보입니다. RoboTwin 결과를 낸 공개 설정(20단계)의 지연은 이보다 클 것입니다.
- **N5.** 4단계 추론이 쓰는 σ 범위(0.625–1)는 균등 목표에서 학습 표본의 75%를 차지합니다. 나머지 25%(σ < 0.625)에서 학습한 action은 4단계 추론에서는 쓰이지 않습니다.

## 6. 코드가 행동에 영향을 주는 경로 (코드 읽기에서의 해석)

- **코드는 attention 섬입니다.** 코드 스트림은 [ViT prefix][지시문][canvas]만 보고, video와 action을 읽지 않습니다(`_build_mot_attention_mask`). 그래서 계획은 관측 이미지(ViT)와 지시문만으로 정해지고, 예측된 미래 영상으로 수정되지 않습니다. 저자들이 V → C → A보다 C → V → A가 낫다고 한 결과(48.3 vs 71.1)도 같은 방향입니다. 코드는 영상을 보지 않는 편이 낫습니다.
- **action은 완성된 프로그램을 보지 않습니다.** 코드 토큰은 각 joint step의 forward 다음에 확정됩니다. 그래서 4단계 디코딩에서 action은 canvas가 0%, 25%, 50%, 75% 공개된 상태를 차례로 봅니다. 다만 action은 토큰이 아니라 층마다 코드 전문가의 hidden state를 읽습니다. 그래서 마스크된 위치에도 계획 정보가 들어 있을 수 있습니다. "로그에 남는 코드"와 "action이 조건으로 쓴 것"이 같지 않다는 점은 해석할 때 주의해야 합니다.
- **기본 모드에서 코드는 실행되지 않습니다.** 따라서 기본 모드의 성능 향상은 "코드를 실행해서"가 아니라 "코드를 맞히도록 학습한 표현을 action이 읽어서"입니다. 자연어 subgoal과의 차이가 7.5점에 그친다는 점(§3)도 이 해석과 맞습니다.
