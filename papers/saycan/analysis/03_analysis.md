# 03. 수치 재계산과 일관성 검사

*SayCan* (arXiv:2204.01691 v2). 이 문서는 **논문 표의 수치를 다시 계산한 것**입니다. LLM 호출, 로봇 실행, 노트북 실행은 하지 않았습니다. 재계산 스크립트는 `analysis/recompute.py`, 결과는 `analysis/recompute_results.json`(수 초, numpy·scipy)입니다. 분석일 2026-11-22.

## 0. 방법과 한계

- **입력:** 본문과 부록의 표 값(표 2, 3, 5, 6, 7, 8)과 본문 문장의 수치. 지시문별 성공 여부(표 5의 101행)는 논문에 **없습니다**.
- **정수화:** 퍼센트에서 분모 n과 정수 k를 역산합니다(round(100k/n) = 보고값을 만족하는 k). 15개짜리 가족과 11개짜리 가족은 k가 하나로 정해집니다. 101개 전체 합은 행 합으로 검사합니다.
- **검정:** 같은 101개 지시문을 두 시스템이 풀었으므로 쌍체 구조입니다. 그러나 지시문별 결과가 없어서 **비쌍체 Fisher 정확 검정**만 했습니다. 쌍체 상관이 양이면 실제 검정력은 이보다 높습니다. 따라서 여기서 "비유의"는 보수적 판정입니다.
- **구간:** Wilson 95%.
- **검출력(정규 근사, 양측 0.05, 검정력 0.8, 두 독립 집단 n = 101 각각):** 차이가 약 **14–17%p**보다 작으면 검출하기 어렵습니다.
- **토이와 속도 측정은 하지 않았습니다.** 근거: 본문 주장의 핵심은 PaLM 540B 점수와 로봇 실행입니다. 토이로 같은 결과를 재현하면 설계상 당연한 결과만 나옵니다. 공식 노트북 실행은 GPU와 유료 API가 필요해 하지 않았습니다(`04` §4).

**K1이 중요한 이유:** 실제 주방 열의 헤드라인(계획 81%, 실행 60%)은 행별 값으로는 79%, 58%입니다. 본문의 "계획 −3%p, 실행 −14%p"도 이 총계에서 나왔습니다. 행 기준으로는 **계획 −5%p, 실행 −16%p**입니다. 방향은 같지만 크기가 조금 달라집니다. 원인은 논문에 적혀 있지 않습니다(표 편집 오류일 수 있음). 이 분석은 저자에게 확인이 필요하다고 봅니다.

| 명사 대 동사 (계획, 모의) | 10/15 대 15/15 | 0.042 | 유의 (가족 내) |

| 영어 대 비영어 (계획, 표 8) | 3/3 대 8/9 | 1.00 | 표본이 작아 검정 무의미 |

- **구간(모의 계획 84%):** [75.8, 90.0]. **가치함수 없음 67%:** [57.7, 75.7]. **생성 결과 74%:** [65.0, 81.8].
- **가치함수 효과의 크기:** 계획에서 17%p(p = 0.008)는 본문 "거의 두 배"와 맞지 않습니다. 계획에서 상대 배율은 1.25(대 No VF)이고 1.13(대 Gen)입니다.
- **가족 표본:** 15개짜리 가족 하나의 1개 차이는 6.7%p입니다. 가족별 차이는 대부분 검출되지 않습니다. 명사 대 동사만 유의합니다. 가족별 결론은 방향으로만 씁니다.

## 4. 주장 판정 (C항목)

판정 기준: **맞음**(수치와 설명이 일치), **부분**(방향은 맞지만 크기·조건이 다름), **과장**(수치가 주장보다 작음), **근거 없음**(정량 자료가 없음).

| 번호 | 주장 | 근거 | 판정 |
|---|---|---|---|
| C1 | 101개 지시를 실제 로봇에서 "zero-shot" 수행 | 계획 84%, 실행 74% (모의 주방) | **부분**. 헤드라인은 기술이 학습된 장면에서 나옴. "zero-shot"은 LLM과 기술을 과제에 맞춰 다시 학습하지 않는다는 뜻 |
| C2 | 실제 주방에서도 잘 일반화 (v2 §5.1) | 실행 74 → 60, 행 합 기준 58 | **부분**. 실행 −14 ~ −16%p, p = 0.03–0.05 (경계). 계획 차이는 작음 |
| C3 | 가치함수 grounding이 기준선 성능을 거의 두 배로 높임 (초록) | 계획 84 대 67(No VF), 74(Gen). 실행 74 대 9(BC USE) | **과장** (계획 1.13–1.25배). 두 배는 BC USE 실행에서만 |
| C4 | LLM이 좋아지면 로봇 성능도 좋아짐 (§5.1) | PaLM 84/74, FLAN 70/61, 생성 결과 8B 38, 62B 72, 540B 74 | **부분**. 두 LLM 비교와 생성 결과 곡선. 같은 조건에서 LLM만 바뀐 것인지 본문에 없음. 계획 차이는 p = 0.03 |
| C5 | 사고 연쇄로 부정·추론 처리 개선 (§5.2) | 롤아웃 3개(Table 4), 프롬프트 공개 | **근거 없음** (정량 평가 없음) |
| C6 | 다국어 질의에서 계획 저하 거의 없음 (§5.2) | 8/9 대 3/3 | **근거 약함** (표본 12). 방향만 |
| C7 | 드로어 스킬을 프롬프트 예시와 가치함수로 추가하기 쉬움 (§5.2) | 계획 100%, 실행 33% (18회 가정) | **부분**. 계획 쪽은 맞음. 실행은 어려움 (기계 실패가 원인) |
| C8 | 프롬프트 예시 수가 계획 성능을 좌우 (§D.3) | 0개 52%, 1개 74, 4개 84, 17개 88 (언어 시뮬, n = 50, 무종료 요건) | **맞음 (방향)**. 4개와 17개 차이 4%p는 n = 50에서 불확실. 0개 수치는 K4 불일치 |
| C9 | 계획 오류가 FLAN 대비 절반으로 줄었다 (§5.1) | 계획 오류 16 대 30(−47%), 실행 오류 26 대 39(−33%) | **부분**. 계획은 맞고 실행은 절반이 아님 |
| C10 | 실패의 65%가 LLM, 35%가 affordance (§5.1) | 계획 실패 16건, 실행 실패 26건 | **근거 불충분** (분모 불명). 실행 실패 26건 기준 17 + 9이면 맞음 (K7) |
| C11 | 실제 주방은 모의 주방과 비슷하다 (v1의 "no significant loss", v2 §5.1) | v2 81/60 대 84/74, 행 합 79/58 | **부분**. 계획은 비슷함, 실행은 14–16%p 낮음 |
