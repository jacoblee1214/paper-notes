## 2. v1 ↔ v3 대조

| 항목 | v1 (2026-06-17, 21쪽, 부록 포함) | v3 (2026-10-20, 9쪽) |
|---|---|---|
| 다시점 올리기 | 삼각측량 합의 + **reference-view ray voting**(합의가 τ_tri = 0.5M 미만이면 대체) | 삼각측량 합의만. ray voting 언급 없음. 합의 실패 시 동작 미기재 |
| 로봇 | xArm + Inspire | Franka(zero-shot 비교) + xArm(VLA 비교) |
| zero-shot 기준선 | 단일 시점 RGB-D 역투영 1개 | MOKA, ReKep |
| 성공률 시행 수 | 과제별 n = 5 (Ours 5/5, 4/5, 4/5 vs RGB-D 4/5, 4/5, 2/5) | 조건별 n = 10, 합 n = 20 |
| VLA 미세조정 | 과제당 30개 시연. GR00T·Being-H0 모두 0/5 (두 과제) | 100개 시연. GR00T 6/20, Being-H0 0/20 (한 과제) |
| 그라운딩 지표 | 정확도: L_grasp RGB-D 16.43 cm vs Ours 4.58 cm. 침투 오차 9.91 vs 9.81 (거의 같음) | 반복성 σ, δ_max. 침투 P_max, P_avg, Coll% (Coll% 100 vs 17) |
| 시점 수 | 4–6대, 2·3·5 시점 ablation (차이 작음) | "모든 실험 4시점", ablation 없음 |
| long-horizon | retry 예산 4. Organize 4/6, Cooking 1/3 | retry 1회. 8/10, 9/10 (없으면 6/10, 6/10) |
| 모션 생성기 | 기성 팔-손 모션 생성기 [54] | cuRobo v2 [52] + Natural functional gradients [53] (고려대 공저자 추가) |
| 하이퍼파라미터·프롬프트 | 부록 D: ε_tri = 20 px(640×480), τ = 0.65, 보정 격자 ±4 cm / 2 cm, 파지 가중치, VLM 프롬프트 원문 | 본문에 없음. "프롬프트는 보충 영상에" |
| 프로젝트 페이지 | 초록이 ray voting 설명 (현재까지 유지) | — |

**해석:** 실험이 더 강한 기준선과 더 많은 시행으로 다시 만들어졌다는 점은 긍정적입니다. 다만 (1) 핵심 기여였던 ray voting이 빠졌는데 그 이유와 영향이 설명되지 않았고, (2) v1에서는 침투 오차 개선이 없었는데 v3에서는 크게 개선된 것으로 나와 지표 변경의 영향을 분리할 수 없으며, (3) VLA 비교의 시연 수가 30 → 100개로 바뀌었습니다. v3만 읽은 독자는 이 이력을 알 수 없습니다.

## 4. 구현 가능성 판단

### 4.1 공식 코드를 그대로 돌리는 경우
**현재 불가능합니다.** 코드가 공개되지 않았습니다. 공개되더라도 다음이 필요합니다.

| 항목 | 요구 사항 |
|---|---|
| 로봇 | Franka 또는 xArm 팔 + Inspire dexterous hand |
| 센서 | 보정된 RGB 카메라 4대(스테레오 쌍 포함) |
| GPU | NVIDIA CUDA GPU (FoundationStereo, FoundationPose, BODex, cuRobo, 파지 물리 시뮬레이션) |
| VLM | Gemini Robotics-ER 1.6 API 키, 하위 과제당 약 20회 호출 |
| 물체 | 조작 대상마다 메쉬(스캔 또는 CAD) |
| 라이브러리 | 기술 범주별 물체 중심 6D 궤적(시연 기록 또는 VLMPose) |

### 4.2 이 맥(Apple M4 Pro, CUDA 없음)에서 할 수 있는 것

| 구성 요소 | 가능 여부 | 근거 |
|---|---|---|
| 다시점 합의, 정렬, 어포던스 투표, 끝점 보정의 수학 | ✅ 완료 | numpy toy (`grounding_toy.py`, `alignment_toy.py`) |
| VLM 2D 그라운딩 (Gemini API) | ✅ 가능 | API 호출이라 기기와 무관합니다. 다만 이미지를 외부 서비스(Google)로 보내야 하고 API 키·비용이 필요합니다. v1 부록 프롬프트로 시작할 수 있습니다 |
| 실제 다시점 3D 그라운딩 | ⚠️ 장비가 있으면 가능 | 카메라 2–4대(스마트폰 가능)와 체커보드 보정만 있으면 삼각측량까지는 이 맥에서 돌릴 수 있습니다 |
| FoundationStereo / FoundationPose | ❌ (미확인) | CUDA 전용 연산을 쓰는 것으로 알고 있어 MPS로 돌리기 어렵다고 판단합니다. 확인하지는 않았습니다 |
| BODex 파지 생성, cuRobo 모션 계획 | ❌ | CUDA 커널 기반입니다 |
| 실제 로봇 실행 | ❌ | 하드웨어가 필요합니다 |

### 4.3 아이디어를 재구현하는 경우

| 계층 | 난이도 | 메모 |
|---|---|---|
| 그라운딩 (VLM 질의 + 다시점 합의) | 낮음–중간 | 핵심은 수십 줄이지만 ε_tri를 VLM 픽셀 오차에 맞춰야 하고, 동률·합의 실패 처리를 정해야 합니다(`03` §2). inlier 재적합을 권장합니다 |
| 도구 궤적 정렬 (Eq. 7) | 낮음 | 닫힌 해가 있습니다(`03` §3). 앵커 간격 불일치가 그대로 끝점 오차가 된다는 점을 점검해야 합니다 |
| 어포던스 영역 (Eq. 9) | 낮음 | 메쉬 꼭짓점 투영 투표. 메쉬와 자세 추정이 있어야 합니다 |
| 파지 생성 + 안정성 시뮬레이션 | 중간–높음 | BODex·Dexonomy를 손 모델에 맞춰 설정해야 하고 NVIDIA GPU가 필요합니다 |
| 팔-손 모션 계획 | 중간 | cuRobo로 대체할 수 있습니다. [53]은 코드 공개 여부를 확인하지 못했습니다 |
| long-horizon 검증 루프 | 낮음 | VLM 프롬프트 설계 문제입니다. v1 부록의 planner 프롬프트가 출발점입니다 |

**요약:** 지금은 공식 코드가 없어서 "그대로 재현"은 할 수 없습니다. 아이디어의 핵심인 그라운딩 계층(VLM + 다시점 합의)은 이 맥에서 Gemini API로 바로 시작할 수 있습니다. 반면 실행 계층(깊이·자세 추정, 파지, 모션)은 NVIDIA GPU와 로봇 하드웨어가 있어야 하고, 물체 메쉬도 준비해야 합니다. 논문 성능을 비교하려면 장면 목록과 성공 기준이 공개되어야 하는데, 지금은 없습니다.
