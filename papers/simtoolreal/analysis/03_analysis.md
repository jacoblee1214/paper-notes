# SimToolReal 수치 재계산과 일관성 검사

재계산: `recompute.py` → `recompute_results.json` (numpy, scipy, 1초 미만). 토이: `toy_gap_power.py` → `toy_gap_power_results.json`. 그래프: `plot_figures.py` → `report/figures/own_*.png`. 입력은 표 II(v3)의 24 과제 x 5 rollout 값이고, 논문 본문과 그림 5의 캡션 값을 함께 씁니다.

## 1. 표 II 재계산

- **과제 평균 일치:** 24개 과제 모두 보고된 Avg가 다섯 rollout 평균과 맞습니다(최대 차이 0.04 pp, 반올림 오차). 표 II 자체에는 계산 오류가 없습니다.
- **범주 평균(rollout 20개씩):**

| 범주 | 평균 (%) | 본문 주장과의 관계 |
|---|---|---|
| Eraser | 100.0 | "가장 높은 Task Progress" (IV-A) 일치 |
| Hammer | 89.4 | |
| Marker | 78.6 | 얇은 도구 신뢰도 낮음, 본문과 일치 |
| Spatula | 76.0 | |
| Brush | 73.8 | |
| Screwdriver | 57.7 | "가장 어려운 범주" (IV-A) 일치 |

- **도구별 주장 확인:** 주걱은 두께 3 cm 숟가락(평균 90.3)이 1 cm 평평한 주걱(61.8)보다 높습니다(본문과 일치). 망치는 36 g 클로(두 과제 평균 97.8)가 331 g 메일릿(두 과제 평균 81.0)보다 높습니다(일치). 솔은 빨간 솔의 Sweep Fwd(82.7)가 Sweep Right(61.4)보다, 파란 솔은 반대입니다(본문과 일치).

## 2. 전체 평균과 구간

- 120 rollout 평균: **79.26%** (표준편차 30.5). t 기반 95% 구간 **73.7–84.8**.
- 과제 단위 bootstrap(과제를 리샘플링, 20,000회) 95% 구간: **71.7–86.4**. 과제 사이 변동이 커서 과제 단위 구간이 넓습니다.
- 24 과제 평균의 평균: 79.25%. 제3자 요약(The Moonlight)이 제시한 79.2%와 일치합니다.
- 본문 어디에도 이 전체 평균(79.3%)은 적혀 있지 않습니다. 독자가 얻을 수 있는 숫자는 표 II에서 직접 계산해야 합니다.

## 3. "37%" 와 그림 5 (검정력 토이 포함)

- 그림 5 Variation #1: SimToolReal 98.0, 고정 파지 61.0, 키네마틱 리타게팅 8.1 (%).
  - 고정 파지와의 차이 **37.0 %p**, 리타게팅과의 차이 89.9 %p.
- Variation #2: SimToolReal 82.7, 고정 파지 10.8, 리타게팅 0.0.
  - 고정 파지와의 차이 71.9 %p, 리타게팅과의 차이 82.7 %p. 두 변형 고정 파지 차이의 평균은 54.5 %p입니다.
- 결론: 초록의 "37%"는 두 조건 가운데 **가장 작은 고정 파지 차이**입니다. 어느 변형인지, 어떤 지표(%p인지 상대 개선인지)인지 초록은 밝히지 않습니다. 상대 개선으로 읽으면 98.0/61.0 = 1.61배, 즉 61%이므로 37과 맞지 않습니다. %p로 읽어야 37이 됩니다.
- 82.7은 표 II의 Red Sweep Fwd 평균과 같습니다. 따라서 Variation #2의 SimToolReal은 표 II와 같은 rollout입니다. Variation #1의 98.0은 표 II에 없는 별도 실험입니다.

**검정력 토이 (`toy_gap_power.py`).** 논문은 Variation #1의 rollout 값을 보고하지 않습니다. 가정: rollout은 평균 m, 표준편차 s인 정규분포를 [0, 100]으로 자른 값, 조건당 5회, Welch t, 20,000회 반복입니다.

| SD 가정 s (pp) | p < 0.05 비율 | 기대 차이 (pp) |
|---|---|---|
| 5 | 1.000 | 35.8 |
| 10 | 0.998 | 33.9 |
| 15 | 0.904 | 32.0 |
| 20 | 0.664 | 30.2 |
| 25 | 0.461 | 28.5 |
| 30 | 0.323 | 27.1 |

해석: 표준편차가 15 pp를 넘으면 5회 반복으로 37 pp 차이를 유의하게 보기 어렵습니다. 실제 SD는 표 II 전체의 30.5에 가깝습니다(과제마다 0–100 사이로 흩어짐). 따라서 "37%가 유의하다"는 근거가 없습니다. 방향(SimToolReal이 더 높다)은 그럴듯하지만, 크기는 불확실합니다. 이 토이는 정규 가정과 클리핑에 의존하므로 실제 p값이 아닙니다.

## 4. 실패 원인 비율

본문 IV-A: 자세 추적 손실 43.7%, 물체 낙하 34.5%, 불완전 재배치 18.2%, 파지 실패 3.6%(합 100.0%).

- 표 II에서 100% 미만 rollout은 **120개 중 50개**입니다.
- 이 네 비율을 정수 실패 수 N(10–200)으로 만들 수 있는 N은 **없습니다**(`recompute_results.json`의 `failure_pct_consistent_denominators_10_200`이 빈 목록). 예: N = 87이면 43.7, 34.5는 맞지만 18.2는 18.4가 됩니다.
- 결론: 분모(실패 수, 또는 세부 분류 기준)가 본문에 없어 이 비율은 **검증 불가**입니다(미확인). 세부 실패 집계표가 부록 G에 있는지 원문에서 찾지 못했습니다.

## 5. 기타 일관성 검사

1. **성공 허용오차.** 표 I의 성공 허용오차 1 cm, 본문 IV의 평가 ε = 2 cm입니다. 코드는 학습 0.075 m에서 시작해 목표 0.01 m까지 줄이고(curriculum), 평가 기본값은 `evalSuccessTolerance`(null이면 기본값)입니다(`04` D1). 두 값이 같은 조건인지 논문은 말하지 않습니다.
2. **외력과 외토크.** 표 I: 5 N, 0.5 Nm. 코드: 물체 질량에 비례(`forceScale` 20, `torqueScale` 2) (`04` D4).
3. **리프트 기준.** 표 I: z_lifted = 0.73 m(절대), 부록 E: 10 cm 리프트 기준. 코드: 초기 높이 대비 0.15 m (`04` D5).
4. **환경 수와 블록.** 24,576 환경, 블록 4096, 블록 6개(README와 일치). 코드 기본값은 8,192(`04` D6).
5. **지연.** 표 I: 물체 포즈 지연 최대 10스텝, 행동·관측 지연 3스텝. 코드 `objectStateDelayMax 10`, `obsDelayMax 3`, `actionDelayMax 3` 일치.
6. **보상 계수.** 표 I의 λ_arm 0.03, λ_hand 0.003, λ_approach 50, λ_lift 20, B_lift 300, λ_goal 200, B_succ 1000. 코드 `kukaActionsPenaltyScale 0.03`, `handActionsPenaltyScale 0.003`, `distanceDeltaRewScale 50`, `liftingRewScale 20`, `liftingBonus 300`, `keypointRewScale 200` 일치. B_succ은 설정 파일에서 찾지 못했습니다(미확인).
7. **시드와 통계.** 그림 8(RL 구성요소)은 5개 시드 평균이라고 쓰지만, 시드별 값과 분산이 없습니다. 그림 7의 "강한 상관"은 상관계수가 없습니다.
8. **버전 간 본문.** v1, v2, v3 본문은 같습니다(감사의 글 한 곳만 다름, `01` §0).
9. **계산 자원.** 학습 시간, GPU 수, 환경 한 스텝 시간은 없습니다. 재현 가능성 판단에 필요한데 빠져 있습니다.

## 6. 자원과 속도

이 맥에서 실제 시뮬레이션 처리량은 측정하지 않았습니다. 공식 파이프라인은 IsaacGym(NVIDIA CUDA)과 PhysX GPU를 쓰므로 맥에서 측정할 수 없습니다. 맥에서 측정 가능한 것은 프리미티브 생성, 키포인트 보상, Task Progress 계산 같은 **NumPy 부품**뿐입니다. 이것은 처리량 측정이 아니라 구현 확인입니다.
