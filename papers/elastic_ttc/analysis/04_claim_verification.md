## 2. 항목별 상세

### 2.1 C7: 종료 가치와 최적성

- §4.2는 Ng 외 [27]을 인용해 "보상 변환이 정책 최적성을 보존한다"고 씁니다. Ng 외의 결과는 **포텐셜 기반 보상 성형**에 대한 것입니다. 여기서의 Qtask는 포텐셜이 아니라 메타 MDP의 종료 보상입니다.
- 부록 §7.5.1은 Qtask를 "기준 연속 정책"(기본 확산 정책 10 DDIM 스텝)의 롤아웃에서 얻은 return-to-go로 회귀합니다. 따라서 Qtask(x,u)는 **ELASTIC 자신이 이후에 따를 연속 정책의 값이 아니라 기준 정책의 값**입니다. 이 경우 각 시점의 메타 최적화는 "기준 정책을 이어 따른다고 가정한 한 단계 개선"이고, 전체 에피소드 최적성은 보장되지 않습니다. 반복해서 Q를 다시 학습하지 않는 한 정책 반복의 한 번에 해당합니다.
- 부록이 인정하듯 메타 정책이 Qϕ를 악용하는 경우가 있습니다. Qϕ가 보상이면서(식 1) 행동 선택자(Alg. 1 줄 24)이기도 하므로 검증기 오차가 두 번 반영됩니다. 이득이 검증기의 오차 방향으로 부풀 수 있습니다.
- 이 분석은 이론 결함을 증명한 것이 아니고, 논문 문장이 가정을 명시하지 않았다는 지적입니다.

### 2.2 C3와 C8: 인과 귀속

- Fixed는 상태와 무관하게 (L,P)를 무작위로 섞는 것이고, ELASTIC은 상태 정보, 검증기 점수(가지치기 결정이 후보 상태를 봄), 학습된 다단계 의사결정을 모두 씁니다. "상태 의존 할당만의 효과"라는 문장은 가지치기가 검증기 정보를 쓰는 부분을 분리하지 못합니다.
- 절제가 하나도 없어(어텐션 대 연결, 중앙 대 분산, FiLM 유무, 오프라인 사전학습 유무, 반사실 증강 유무) §4.3의 설계 결정은 "설명"이지 "검증"이 아닙니다.

### 2.3 C9: 기준선의 범위

- 비교한 것: 기본 정책, BoN(N=4 또는 8, 10 스텝), 같은 계산량의 Sequential, Fixed, Learned Fixed.
- 비교하지 않은 것: 순차 적응 선행([11–13]), 병렬 조기 중단(FASTER [23]), 병렬 서빙 최적화(RoboMonkey [18]). 이들이 코드가 있는지는 `02`에 정리했습니다. 논문이 "FASTER가 실제로는 가지치기를 하지 않는다"고 평가한 것(§2)은 직접 실험이 아니라 서술입니다.

### 2.4 C10과 C11: 정성 해석과 학습 비용

- Fig. 3의 Can Paired 타임라인은 한 시드의 한 궤적이거나 평균인지 적혀 있지 않습니다. Square MH가 PH보다 더 많은 계산을 받는 것(Fig. 9)은 "정책 성능에 적응"의 근거로 제시되지만, 두 체크포인트의 검증기가 같은지도 불분명합니다(§5.2는 "같은 검증기", §7.5.1은 기본 체크포인트의 롤아웃으로 검증기를 학습한다고 씀).
- 학습 비용: 메타 정책은 과제마다 따로 학습되고(§6), 확산 정책 실험은 6과제 × 3 비용 체제 = 18개 메타 정책, LIBERO는 10개, 실로봇은 3개입니다. 각각의 환경 스텝 수와 학습 시간은 없습니다. UTD 30, 배치 512(Table 2)로 볼 때 CPU만으로는 부담이 클 것으로 추정합니다(미측정).

## 4. 구현 가능성 판정 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**결론: 논문 수치(Fig. 2, 5, 11)의 재현은 이 맥에서 불가능합니다. 알고리즘 구조를 줄인 토이는 구현할 수 있습니다.**

| 층 | 판정 | 필요한 것 | 노력 (추정, 미측정) |
|---|---|---|---|
| 메타 MDP와 식 1을 푸는 2차원 토이 (해석적 속도장의 혼합 가우시안 GCP, 잡음 있는 검증기, 샘플별 stride와 가지치기, 어텐션 SAC) | **가능** | torch CPU 또는 MPS. 데이터와 설치 추가 없음 | 구현 3–5일. 학습은 분 단위로 예상 |
| Fixed, Learned Fixed 대비 상태 의존의 이득을 토이에서 분리 | **가능** | 위 토이 확장 | 1주 |
| 확산 정책 PushT 상태 기반 과제 (원 DP 체크포인트, 저차원) | **조건부** | DP 저장소와 체크포인트 다운로드(크기는 확인 전), 환경 의존성 설치, 승인 필요. 메타 정책 SAC(UTD 30)가 CPU에서 몇 시간에서 며칠인지는 측정 전 | 2–4주 |
| Robomimic Square/Can | **조건부** | 데이터, 체크포인트, robosuite와 mujoco 의존성. Can Paired, Can Reverse 변형 데이터는 공개되지 않아 직접 만들어야 함 | 3–6주 |
| LIBERO-10와 π0.5 | **불가** | 시뮬레이터, 대형 VLA 체크포인트와 지연 측정 GPU(논문은 RTX 4090), V-GPS 학습 | 이 맥에서 해당 없음 |
| 실로봇 (Franka, π0.5-DROID, RTX 6000) | **불가** | 로봇, 실험실, GPU | 해당 없음 |

- 공개된 외부 구성 요소(openpi, diffusion_policy, V-GPS, robomimic, LIBERO)는 모두 있지만(`02` §2) **메타 정책 학습 코드와 Can Paired, Can Reverse 변형, 과제별 검증기는 없습니다**. 따라서 확산 정책 6과제 재현도 상당 부분을 새로 짜야 합니다.
- 이 폴더의 작업은 새 설치, 실행, 다운로드 없이 읽은 값 재계산까지만 했습니다.
- 가장 낮은 비용으로 논문의 핵심(상태 의존 할당이 상태 무관 할당보다 얼마나 나은가)을 직접 검증하려면 토이 층이 맞고, 그 결과는 "알고리즘이 의도대로 작동하는가"를 보일 뿐 논문 수치를 재현하지는 않습니다.
