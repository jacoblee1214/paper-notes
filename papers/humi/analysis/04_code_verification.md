### 2.1 논문과 일치한 항목 (정적 확인)

- 저수준 보상 구조: 전신 위치 σ = 0.3, 회전 0.4, 선속도 1.0, 각속도 π(가중치 1.0), 적응형 EE 가중치 0→0.5, 행동 변화율 −5e-2, 관절 한계 −10, 접촉 −0.1(임계 1 N). 적응형 σ는 `speed_range = (0.05, 0.10)`에서 위치 0.01–0.1 m, 회전 5°–20°로 보간, 기준 골반 속도 0.02 m/s 게이트(`root_vel_threshold`). 오차는 "제곱합의 평균"(식 §3.2의 평균 제곱 오차)로 구현됨.
- DR 값: 정마찰 0.3–1.6, 동마찰 0.3–1.2, 토르소 질량중심 ±0.025/±0.05/±0.05, 그리퍼 질량 0.75–1.25배(스케일), 밀기 4–6 s 간격 ±0.5 m/s, 요 ±0.78. 리셋 섭동의 위치·자세·관절 범위(±0.05, z 0–0.05, 롤·피치 ±0.1, 요 ±0.2, 관절 ±0.1, 시간 ±0.05 s)와 각속도 범위(±0.52, ±0.78).
- 학생 구조: 이력 25스텝, 명령 10웨이포인트(`future_samples=10`, `future_length_s=2`), 맹점 키포인트는 첫 샘플 기준 상대 변환(`reference_blind_keypoints_delta`), 기본은 골반 하나. 교사는 `future_samples=1`. 제어 50 Hz(시뮬 dt 0.005 × 디시메이션 4), 속도 계수 [0.25, 1.25], 평균 1.0.
- 하드웨어·제어: 배포 PD 이득이 시뮬의 `NATURAL_FREQ = 10 Hz`, 감쇠비 2에서 계산된 값(예: 엉덩이 요 40.18)과 같고, 허리 롤·피치와 손목 요는 고정됨(`Fixed_Joints`). 그리퍼는 손목 요 모터로 구동(`ActionScale` 마지막 항 1, 논문 부록 B.1과 일치).
- 데이터 수집 IK: 골반 높이만 에피소드별로 척도 조정(`_root_z_scale_factor = 서 있는 높이 / 시작 골반 높이`), 나머지는 비척도 SE(3)(부록 A.2와 일치). 5키포인트 정책 설정(`umi_g1_5_keypoints.yaml`)과 서버의 5로봇 추론 경로가 있음(5키포인트 실험과 일치).
- 데이터 수집 절차: 서 있는 기본 자세 카운트다운 3초 뒤 발과 골반 포즈로 전역 변환과 높이 척도를 추정(README), 부록 A.4와 같은 흐름.

## 4. 구현 가능성 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**판정: 논문 결과(실로봇 성공률, 수집 효율)의 재현은 불가능합니다. 공식 코드의 학습·배포 경로도 이 맥에서는 불가능합니다. 데이터 수집 후처리(IK)와 핵심 메커니즘의 소형 구현은 가능합니다.**

| 수준 | 가능성 | 근거 |
|---|---|---|
| 실로봇 성공률(표 §4.1–4.2), 수집 효율(§4.3) | **불가** | Unitree G1, Vive 추적기, GoPro, 커스텀 그리퍼, 조작자 시간이 필요. 시도 20회 × 과제 5개 |
| 저수준 제어기 학습(교사 PPO 50,000 반복 × 4096 환경, 학생 증류) | **불가** | Isaac Lab + CUDA + cuRobo 전제. 환경 스텝 4.9e9. 이 맥에서 실행 경로 없음 |
| 고수준 정책 학습(UNet 흐름 정합 + DINOv2 ViT-B, 224², 200 에폭, bf16 + DDP) | **사실상 불가** | `train.sh`가 `nvidia-smi`·`accelerate` DDP·bf16을 쓰고 시연 100–350개 × 20 Hz. MPS에서 ViT-B 학습 속도는 측정하지 않음. 소형 백본(ResNet18 등)으로 바꾼 축소판은 가능할 수 있으나 논문 구성이 아님 |
| 공개 데이터 읽기·오프라인 IK 재계산(`offline-ik`, Mink + MuJoCo) | **가능(승인 후)** | 의존성이 CPU(MuJoCo, daqp)이고 README가 Linux/macOS를 지원. 필요한 것: `uv`로 환경 구성(설치 승인), 데이터 다운로드(가장 작은 LeRobot Toss 126 MB, 원시 150 GB·Zarr 32 GB는 비현실적) |
| 시연 데이터 구조 점검(LeRobot 파케이) | **가능(승인 후)** | 126–3,465 MB. 원시 시연은 쓰지 않음 |
| 핵심 메커니즘의 소형 재구현: MuJoCo(또는 단순 모델) 위의 속도 의존 EE 허용 오차 보상 + 가변 속도 증강 + 덩어리 기준 선택 | **가능(토이 규모)** | mujoco 4.0 + torch 2.15가 이미 설치됨. 24 GiB, MPS로 소형 정책은 충분. 단 G1 + 접촉 + 4096 환경 규모는 불가 |
| 정적 대조(이 문서) | **완료** | 위 D1–D13 |

**노력 추정(추정, 측정 전):** 오프라인 IK 파이프라인을 공개 소형 데이터로 돌려 시연 궤적과 IK 해를 점검하는 데 1–2일(설치와 다운로드 승인 포함). 메커니즘 토이(2D 팔 + 몸통, 속도 의존 보상, 가변 속도, 덩어리 기준) 구현과 절제 비교에 1–2주. G1 MuJoCo 모델에서 전신 추종 RL을 소규모(CPU/MPS, 수천 환경 아님)로 돌려 적응형 보상 효과를 확인하는 데 4–8주. 논문 규모(4096 환경 PPO + 실로봇)는 GPU 서버와 G1이 없으면 진행할 수 없습니다. 막히는 것은 노력이 아니라 자원입니다.
