# 04. 공식 코드 대조 (논문 ↔ 코드, 차이 D1–Dn)

공식 저장소 `robocasa/robocasa`를 **정적으로만** 읽었습니다. 설치, import, 실행을 하지 않았고 데이터셋과 에셋(약 10 GB, 공식 README 기준)은 받지 않았습니다. 대조 대상은 세 스냅샷입니다.

| 약칭 | 커밋 | 날짜 | 의미 |
|---|---|---|---|
| **S0** | `be5d99c` | 2024-05-29 (`public release`) | arXiv v1 (2024-06-04) 직전의 공개 코드. 논문 실험에 가장 가까운 시점 |
| **S1** | `a6c2dc6` | 2024-10-31 (`robocasa v0.2 release`) | 2024년 마지막 릴리스. MimicGen 데이터 항목 포함 |
| **S2** | `7bfc60c` (HEAD) | 2026-11-18 | 현재 main. RoboCasa365(v1.0.1) 코드 |

S0과 S1은 `git archive`로 `repo/robocasa-2024-05/`, `repo/robocasa-2024-10/`에 풀었습니다(gitignore). 현재 HEAD는 `repo/robocasa/`, 태그 v0.2는 `repo/robocasa-v0.2/`입니다.

**주의.** 태그 `v0.2`는 현재 `756598a`(2025-12-18 커밋)를 가리킵니다. 2024-10-31 릴리스 커밋 `a6c2dc6`과 다릅니다. 2024년 코드를 비교할 때는 태그가 아니라 커밋 해시를 써야 합니다(D13).

## 3. 차이 목록 (D1–D17)

**D1. 사람 시연 범위 (본문 내부 불일치와 공개 데이터).** 서론과 IV는 "100개 과제 전체에 사람 시연을 제공한다"고 쓰지만, IV-A는 원자 과제 50개씩만 말하고 공개 데이터는 30개 과제(원자 25 + 복합 5)입니다. 나머지 70개 복합 과제에는 공개 사람 시연이 없습니다. 실험 V-B의 복합 과제 5개가 바로 이 5개입니다.

**D2. MimicGen 연동 시점.** 논문 실험에 쓰인 생성 데이터는 S0 이후 `c3e89f7`에서 추가된 레지스트리 항목과 맞습니다. 즉 논문 시점의 공개 코드에는 생성 데이터 경로가 없었습니다. 생성기는 외부 `mimicgen` 패키지에 있습니다.

**D3. AI 생성 객체 궤적 28K.** 본문 주석 1의 "추가 28K 궤적"은 레지스트리에서 찾지 못했습니다. 공개 데이터 범위에서 빠져 있는지 확인이 필요합니다.

**D4. 복합 과제 수.** 논문 75개와 코드 클래스 수를 바로 맞출 수 없습니다. 기반 클래스와 보조 클래스를 제외한 목록이 필요합니다.

**D5. 과제 수와 데이터 개수.** D1–D4와 같은 맥락입니다. 본문 "100개 과제"의 공개 데이터는 30개 과제뿐입니다(D1).

**D6. 장면 구성.** 10개 배치, 12개 스타일이 코드 구조와 맞습니다(§2). 장면마다 텍스처를 바꾸는 방식(`texture_swap.py`)도 있습니다.

**D7. 로봇 이름.** 논문은 "Franka + Omron 이동 기반"이라고 쓰고, S0은 `PandaMobile`, S1 이후는 `PandaOmron`이라고 씁니다. 같은 기구인지는 robosuite 모델 정의를 봐야 확정할 수 있어 확인하지 않았습니다.

**D8. 원자 과제 실패 방식.** 논문 V-A는 "성공 궤적"을 저장한다고 하지만, 코드 성공 조건(물체 위치 + 그리퍼 이탈)은 부드러움이나 충돌을 보지 않습니다. 논문 결론도 이 문제를 한계로 적었습니다. 코드와 논문이 같은 방향이라 불일치는 아닙니다.

**D9. 평가 프로토콜 (코드에 없음).** "과제당 50회, 장면 5개, 두 장면은 미본 스타일"은 저장소에 근거가 없습니다. 50회가 과제 전체인지 장면당인지도 본문에서 확정되지 않습니다(§3 재계산 참조).

**D10. 정책 학습 (코드에 없음).** 학습 설정은 robomimic 외부에 있습니다. 논문이 말하는 500k 스텝을 네 데이터 설정에 같이 적용했는지도 본문에 없습니다.

**D11. 성공 판정 정의.** 논문에는 과제별 성공 조건이 없습니다. 코드에서 PnP 과제는 "물체가 목표 안 + 그리퍼가 멀어짐"입니다. 평가 결과의 기준이므로 본문에 적었어야 합니다.

**D12. 호라이즌.** 논문은 최대 스텝 수를 쓰지 않습니다. 코드 기본값은 1000이고, 과제별 호라이즌은 레지스트리에서 300–1000입니다(S0 500–700). 평가 호라이즌은 논문 재현에 필요한 값입니다.

**D13. 버전 이동.** 태그 v0.2가 2024년 릴리스 커밋이 아니라 2025-12 커밋을 가리킵니다. 현재 HEAD는 RoboCasa365 기준이고 README에 "호라이즌 1.5배 증가(v1.0.1)"가 있습니다. 논문 수치를 재현하려면 S0 또는 S1 커밋을 고정해야 합니다.

**D14–D15. 텍스처 100개와 객체 2,509개.** 에셋을 받아야 확인됩니다. 에셋은 약 10 GB입니다(공식 README).

**D16. 데이터셋 크기.** 공개 데이터(사람 시연, 생성 72K)의 실제 용량은 받지 않아 측정하지 않았습니다.

**D17. 실로봇.** DROID 인프라와 실험 코드는 이 저장소에 없습니다.

## 4. 구현 가능성 (이 맥)

맥 사양은 Apple M4 Pro, 약 24 GiB, MPS 사용 가능, CUDA 없음입니다. 판정은 이 분석 묶음의 README 맨 위 요약과 같습니다.

| 작업 | 판정 | 이유와 추정 |
|---|---|---|
| 설치(robosuite master, robocasa, 의존성) | **조건부** | 설치는 승인 후에만 합니다(`CLAUDE.md`). 공식 README는 Python 3.11 conda 환경을 권장합니다. 추정 반나절 |
| 에셋 다운로드(약 10 GB) | **조건부** | 1 GB 이상이므로 승인과 보고가 필요합니다(`reproduction-approval-scope`). 디스크와 시간은 미측정 |
| 원자 과제 1개(예: PnP Counter→Cab)의 MimicGen 생성 성공률 측정 | **조건부** | 맥 CPU에서 MuJoCo 실행은 가능하나 오프스크린 렌더링(mjpython, 84×84 등)을 확인해야 합니다. 시도 횟수는 논문이 보고하지 않아 시간을 추정할 수 없습니다 |
| 24개 과제 BC-Transformer 학습 (4 설정) | **불가** | 500k 스텝 × 4 설정, 약 20M 파라미터. MPS 학습 시간을 측정하지 않았고, CLAUDE.md는 GPU 재현을 하지 않습니다 |
| 실로봇 실험 | **불가** | 실로봇과 DROID 환경이 필요합니다 |
| 공식 코드 실행 | **보류** | 승인 전까지 실행하지 않습니다 |

노력 추정(측정 없음): 설치와 렌더링 확인 1–2일, 과제 하나의 생성 성공률 측정 1일 안팎. 24과제 학습은 이 맥에서 현실적이지 않습니다.
