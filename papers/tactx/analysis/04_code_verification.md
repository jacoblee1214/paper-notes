추가 확인 (논문과 일치):

- **정규화와 입력.** Daimon `(3, 240, 320)` 채널 [깊이, 전단 x, 전단 y]를 224×224로 리사이즈, eFlesh 15차원, FlexiTac 12×16 (표 4와 일치). 통계는 설정에 고정(`datasets_config.yaml`).
- **하이퍼파라미터.** d = 16, 배치 64(쌍마다), lr 1e-4, τ = 0.01, λ_recon = 1, β_max 0.1, KL 워밍업 30 에폭, 시드 42 (표 5와 일치). 인코더는 `pretrained=False`로 처음부터 학습.
- **손실 구조.** 쌍당 L1 재구성 네 항(자기 둘, 교차 둘)과 KL 두 항, 세 쌍 합산(식 1, 2와 일치).
- **추론 잠재.** 잠재 변환 스크립트의 `--latent_type mu`(사후분포 평균).
- **인코더·헤드.** 투영 헤드 512 → 512 → 2d Linear–ReLU–Linear(bias 없음), 센서별 디코더 (부록 B와 일치).
- **Daimon 입력 서술.** 부록 D.2는 "Daimon 잠재는 촉각 RGB 합성 영상에서 계산"이라고 쓰지만 정책 README는 변환이 원시 깊이·전단 채널을 쓴다고 씁니다(표 4와 부록 B는 깊이+전단). 부록 D.2의 서술이 어느 쪽을 가리키는지 확인이 필요합니다.

## 3. 테스트와 검증 상태

- `tests/`는 합성 데이터로 전처리, 학습, 평가, HDF5 변환, ACT 학습 재개를 확인합니다. `maintenance/validation.json`: Python 3.11 CPU, 30개 통과. 이 분석은 테스트를 실행하지 않았습니다.
- 논문의 성능 수치(표 1, 2, 8, 그림 3–5)는 테스트 범위 밖이고 저장소도 "공개 로봇 성공률을 재현하지 않는다"고 적습니다.

## 4. 구현 가능성 판정 ("구현할 수 있는지")

이 맥 기준: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음. 확인한 한도 안의 판정입니다.

**전체 재현은 불가능합니다. 부분 재구현은 가능합니다. 쌍 데이터가 공개되지 않아 표현 학습도 데이터를 새로 모으지 않고는 못 합니다.**

| 범위 | 판정 | 이유 |
|---|---|---|
| 실로봇 정책 평가 (표 1, 2, 8, 6방향 × 5과제) | 불가 | Franka, GELLO, 세 촉각 센서 하드웨어 필요. 배치 코드 없음 (D16) |
