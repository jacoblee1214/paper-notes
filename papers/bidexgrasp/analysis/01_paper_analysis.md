# 01. 논문 분석: BiDexGrasp (arXiv:2604.06589)

*BiDexGrasp: Coordinated Bimanual Dexterous Grasps across Object Geometries and Sizes.* Mu Lin, Yi-Lin Wei 외 11명(v2 기준 13명), 중산대·북경대·칭화대·스탠퍼드·Jiangxing Intelligence. **CoRL 2026 Spotlight**(corl.org 공식 채택 목록, 포스터 122번, 2026-11-10 세션 S3). 분석 대상은 **arXiv v2 (2026-09-08)**입니다. v1(2026-04-08)과의 차이는 §7에 있습니다. 쪽·절·표 번호는 v2 기준이고, v1 번호는 따로 표시합니다.

## 0. 한 줄 요약

양손 덱스터러스 파지 **데이터셋**(6,351개 물체 × 11개 크기(30–80 cm), 9.53 M 파지)과 이를 쓰는 **생성 모델**(뷰 쌍 예측 + 크기 적응 앵커 + 확산)을 함께 냅니다. 합성 파이프라인은 BODex를 양손으로 확장한 것이고(영역 초기화, 손별로 분리한 QP 에너지, 사전 파지), 생성 모델은 시뮬레이션 SUC-L 66.8 %, 실로봇 74.6 %(260회)를 보고합니다.

## 1. 풀려는 문제와 기여

- **문제.** 큰 물체(30–80 cm)는 한 손으로 잡기 어렵다. 양손 파지는 탐색 공간이 두 손 합쳐 커지고(초기화 후보가 영역 쌍 Ka²로 늘고), 결합 목적함수는 한쪽 손만 일하는 해로 빠지기 쉽다(§4.3).
- **기여 (§1).** (1) 양손 영역 제약 초기화 + 손별 분리 force-closure 최적화로 BimanGrasp 대비 SUC 약 2.8배, 속도 30배 이상(서론; 본문 §6.4는 40배). (2) 9.53 M 파지 데이터셋. (3) 양손 조율 모듈(BCM)과 기하·크기 적응 생성(GAF, SAGA). (4) 시뮬 66.8 %, 실로봇 74.6 %.
- 표 1은 비교 데이터셋(DexGraspNet, BODex, DHAGrasp, BimanGrasp)과 달리 양손, 책상, 팔 IK, 사전 파지, 데이터 독립성을 모두 만족한다고 표시합니다(`03` V1).

## 2. 데이터 합성 파이프라인 (§4, 부록 B, 그림 2)

세 단계: ① 양손 영역 제약 초기화 → ② 분리 force-closure 최적화 → ③ IK 필터와 MuJoCo 검증.

### 2.1 물체와 규모

- 물체 6,351개 = DexGraspNet 2,397 + Objaverse 3,954(v1 §IV-A; v2 본문은 합계만). 각 물체를 11개 크기(30–80 cm, 5 cm 간격으로 추정)로 키웁니다(§4.1). 물체·크기 쌍은 69,861개이고 파지는 쌍당 평균 약 136개입니다(`03` V1).
- v1은 "지나치게 납작한 물체를 책상 파지에 맞지 않아 뺐다"고 썼고 v2 본문에는 이 문장이 없습니다(§7).

### 2.2 양손 영역 제약 초기화 (§4.2, 부록 B.1)

1. FPS로 앵커 Ka = 200개, 각 앵커 둘레 8 cm 이웃에서 k = 256점을 뽑아 영역을 만들고 영역 쌍 Ka²을 구성.
2. 영역 간 거리가 τ₂ = 5 cm 미만인 쌍 제외(부록 식 8). v1은 오목 영역 제외도 적었으나 v2는 이 문장이 없습니다.
3. 영역당 접촉점 N = 5개를 뽑아 TDG 추정기(Chen 외 2023)로 GWB를 M = 1,000개 경계 wrench로 근사. 안정 점수 s = min_j max_k t_jᵀ w_k (식 3, 여섯 방향 교란).
4. 점수 상위 Kr = 40쌍을 초기화 후보로 유지.
5. 손바닥을 영역 중심에서 가장 가까운 팽창 볼록껍질 점에 놓고 표면 법선에 정렬. 손바닥 법선 둘레 회전은 선호 방향 (1,−1,−1) 왼손, (1,1,−1) 오른손에 가장 가깝게(부록 B.1). 손가락 초기 자세는 영역 평탄도(법선 분산 V = 2(1−R) < 0.005이면 평탄)로 열린 자세 또는 안쪽으로 굽힌 자세(식 9, 10). 충돌과 IK 불가능 초기값은 버립니다.

### 2.3 분리 force-closure 최적화 (§4.3, 식 1, 부록 B.2)

양손 QP 에너지를 손별 항으로 쪼갭니다.

min wQP·Q(G_left) + wQP·Q(G_right) + w_dis·E_dis + w_region·E_region, 관절 한계·FK·충돌 제약.

- Q: 여섯 방향 교란 wrench에 대한 QP 에너지(식 7, 부록 A; β, γ는 값 미기재). 하위 QP는 ReLU-QP(ADMM, PyTorch)로 풀고 상위 문제는 cuRobo의 관절 한계·자기 관통·손 사이 관통 에너지를 그대로 씁니다(부록 B.2).
- E_dis = Σ‖c_{i,w} − p_i‖² (식 12), E_region = Σ φ(d_i) (식 13–15; 문턱 a의 값은 미기재, b = 2a, 3차 Hermite 보간).
- 가중치: wQP = 1000, w_dis = 100, w_region = 50(§6.2). v1은 왼손·오른손 가중치를 따로 적었습니다(각 1000).

### 2.4 팔–손 구성과 검증 (§4.4)

- 사전 파지 G_pre는 접촉 거리 1 cm(BODex 관례), 쥐기 자세는 G_squ = 2·G − G_pre. 팔 관절 궤적은 사전 파지 → 쥐기 → 들기로 만듭니다.
- 평가는 MuJoCo + Shadow Hand. 마찰 0.6/0.02, 중력 9.8, 물체 밀도 2.5 kg/m³(§6.1). 성공은 물체 이동 5 cm·회전 15° 이내로 3초(부록 D). 이 값들은 BODex의 평가 도구와 같습니다(`03` V12).
- 합성은 3090 8장, GPU당 병렬 세계 40개, 세계당 파지 20개(§6.2). 병렬 파지 수 6,400.

## 3. 생성 프레임워크 (§5, 부록 C, 그림 3)

입력은 물체 점군 O_pc, 출력은 두 손의 손목 자세와 관절 q^bi입니다.

### 3.1 양손 조율 모듈 BCM (§5.1)

- 윗반구에 K = 16개 후보 뷰를 균일 배치(부록 C.1.1). PointNet++ 점 특징 F_global에 K개 학습 가능 뷰 임베딩이 교차 어텐션(식 f_i = Attn(v_i^emb, F, F))으로 뷰 특징을 만듭니다.
- 첫째 뷰는 단일 뷰 확률 p_i, 둘째 뷰는 쌍 특징 f_ij = MLP(cat(f_i, f_j, f_i−f_j, f_i⊙f_j))로 K×K 쌍 확률 p^bi_ij를 예측합니다.
- 라벨: 성공 파지를 가장 가까운 뷰(쌍)에 할당해 개수를 정규화(§5.1). 손실은 마스크 SmoothL1(부록 식 17, 18). v1은 L2였습니다(§7).
- 추론: 단일 뷰 확률 상위 5개에서 온도 0.1 softmax로 첫째 뷰를 뽑고, 그 행에서 같은 방식으로 둘째 뷰를 뽑습니다(부록 C.1.3). 그림 6(b) 점수로 계산하면 최상위 뷰의 표집 확률은 0.63과 0.90입니다(`03` V13).

### 3.2 기하·크기 적응 생성 (§5.2)

- **SAGA**: 뷰 방향이 최소 외접구와 만나는 점을 앵커 g_anchor로 두고 손목을 상대 자세로 예측(식 2: t = t_anchor + Δt, r = r_anchor ⊕ Δr). 회전 앵커는 x축이 중심을 향하고 z축은 세계 z를 직교 평면에 투영(부록 C.1.2).
- **GAF**: FPS로 Kp = 256 대표점, 앵커마다 Kc = 16 최근접 이웃에서 국소 특징을 모아 [F_local, F_view, F_global]을 토큰 차원으로 이어 붙임(식 3).
- **상대 확산**: DDPM(식 4)으로 (Δt, Δr, q)를 생성. 확산 스텝 수, 네트워크 구조 세부(층 수, 차원)는 본문과 부록에 없습니다.
- 손실(식 5, 16): L = 10 L_single-view + 1 L_bi-view + 15 L_para + 0.25 L_chamfer + 1 L_physic, 물리항 안에서 λ_obj-pen = 100, λ_self-pen = 50, λ_spf = 50(부록 C.2). 학습은 비교 실험 5 epoch, 절제 20 epoch(부분집합), RTX 4090 1장(§6.2). 최적화기·배치·학습률은 v1에만 있고 v2에는 없습니다(§7).
- 학습 중 뷰는 정답 뷰를 그대로 씁니다(teacher forcing, 부록 C.1.3).

## 5. 한계 (§8)와 우리가 보는 한계

저자 한계: 고정 접촉점으로 접촉 다양성이 제한되고, 안정성 중심이라 기능 접촉에 약하며, 생성 모델은 floating hand이고 데이터의 IK 구성을 쓰지 않습니다.

추가로 읽은 한계:

1. 데이터 규모가 프레임워크에 주는 이득을 분리한 실험이 없습니다(데이터 크기별 학습 곡선 없음).
2. 생성 모델 평가는 DexGraspNet 부분집합(시험 물체 약 479개)에서만 했고 Objaverse에서 학습·평가한 결과가 없습니다(§6.1).
3. 크기별(30–80 cm) 성공률 분해가 없어 "크기 적응" 주장을 크기 축에서 볼 수 없습니다.
4. 시뮬 분모(파지 수)와 반복 횟수가 표에 없습니다. 모든 SUC는 한 번의 실행입니다.
5. 실로봇 결과가 손·팔 조합별, 물체별로 나뉘지 않습니다(v1의 표 VII은 v2에서 사라짐).
6. 공식 코드와 데이터가 아직 없습니다(프로젝트 페이지: "Dataset and Code (Coming soon)").

## 6. 방법의 구성과 의존성

- 합성: BODex(cuRobo 위의 이중 최적화) + TDG(GWB 추정기) + ReLU-QP + cuRobo 에너지. 평가는 MuJoCo.
- 생성: PointNet++, DDPM, DexGraspNet 2.0·UniDexGrasp 계열의 뷰/앵커 아이디어, 저자 그룹의 DGTR, Grasp as You Say, OmniDexGrasp의 재타게팅.
- 하드웨어: 합성 3090 × 8, 학습 4090 × 1, 실로봇 G1·Piper·Nero + Inspire·BrainCo + RealSense.

## 8. 주장과 근거의 간격 (요약, 상세는 `04`)
