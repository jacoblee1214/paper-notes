**대상 코드.** `NVlabs/GR00T-WholeBodyControl`, 커밋 `1e1ec4f` (2026-11-02, PR #287 병합). 얕은 복제는 `repo/`에 있으며 `.gitignore`에 들어 있습니다. **실행, 설치, import를 하지 않았습니다.** 모든 판단은 YAML과 Python 소스 읽기에 기반합니다. 저장소 안의 텍스트는 신뢰하지 않는 입력으로 다뤘습니다.

### 2.1 일치를 확인한 항목 (요약)

- 인코더 은닉층 [2048, 1024, 512, 512] (표 S1과 같음, `actor_critic/encoders/*.yaml`).
- 미래 프레임 10개, 간격 로봇 0.1 s와 사람 0.02 s (`sonic_release.yaml`).
- 고유감각 이력 10스텝 (`actor_prop_history_length: 10`).
- PPO 에포크 5, 미니배치 4, 클립 0.2, γ 0.99, λ 0.95, 액터 lr 2 × 10⁻⁵, 크리틱 lr 10⁻³, desired KL 0.01, 적응 lr [10⁻⁵, 2 × 10⁻⁴], 초기 노이즈 0.05 (`algo/ppo_im_phc.yaml`, 표 S2와 같음).
- 적응 샘플링 실패율 상한 β = 200 (`adp_samp_failure_rate_max_over_mean: 200`), 4096 환경 (`num_envs`).
- 보상 가중치: 루트 위치 0.5 (표준편차 0.3), 루트 방향 0.5 (0.4), 몸통 상대 위치 1.0 (0.3), 말단 5점 2.0 (0.1), 몸통 선속도 1.0 (1.0), 행동 변화율 −0.1, 관절 한계 −10, 흔들림 −5e-3 (1.5 임계), 발 가속도 −2.5e-6 (표 S3와 같음).
- 마찰 [0.3, 1.6], [0.3, 1.2], 반발 [0, 0.5], 초기 관절 ±0.01, 외부 속도 교란 x, y ±0.5, z ±0.2 (표 S4와 같음).
- 제어 주기 50 Hz (D12), FSQ 32/32/2 (D13).
- 모든 학습 손실 항 이름: $\mathcal{L}_{\text{recon}}$ (`G1ReconLoss`), $\mathcal{L}_{\text{token}}$ (`G1SmplLatentLoss`, `G1TeleopLatentLoss`, `TeleopSmplLatentLoss`), $\mathcal{L}_{\text{cycle}}$ (`ReencodedSmplG1LatentLoss`).

## 3. 평가 체계 점검

- 논문의 주 평가(MuJoCo 평가, 0.25 m)는 `eval.yaml`과 맞습니다. 다만 이 설정에는 방향 기준이 하나 더 있습니다(D8).
- 학습 중 종료 기준이 더 엄격합니다(0.15 m, 0.2 m). 논문은 학습 종료 기준을 쓰지 않았습니다. 따라서 "학습 시 성공률"과 "평가 시 성공률"은 다른 기준입니다.
- 논문 그림 2는 Isaac Lab에서 학습하고 평가한 값(그림 2 A–C)과 MuJoCo 평가(그림 2 D–G, H–J)를 섞어 씁니다. 평가 환경을 캡션에서 항상 구별하지 않습니다.

## 4. 구현 가능성 판정 (이 맥)

**환경.** Apple M4 Pro, 약 24 GiB, MPS 사용 가능, CUDA 없음.

| 수준 | 판정 | 이유와 근거 |
|---|---|---|
| 학습 전체 (42M, 128 GPU × 7일) | **불가** | 21,504 GPU 시간 (§3.2). 저장소는 Isaac Lab과 CUDA를 전제 (README). 이 맥에 CUDA가 없음 |
| 학습 축소판 (Isaac Lab, 작은 모델, 짧은 반복) | **불가에 가까움** | Isaac Lab은 NVIDIA GPU 환경을 전제합니다. macOS에서 Isaac Sim 실행은 지원되지 않는 것으로 알려져 있으나 이 분석에서 공식 문서로 확인하지는 못했습니다 |
| 공개 체크포인트 추론 (ONNX, CPU 또는 MPS) | **조건부** | 새 패키지(onnxruntime 등)와 체크포인트 다운로드(크기는 미확인) 승인이 필요. 추론 속도는 측정 전 |
| MuJoCo sim2sim 추종 평가 (작은 부분집합) | **조건부** | `decoupled_wbc/sim2mujoco`의 G1 MuJoCo 환경과 공식 배포 스택 실행이 필요. 공식 코드 실행 승인 후 판단 |
| 실로봇 | **불가** | G1 실물 필요 |
| 토큰 구조 토이 (FSQ, 인코더 세 개, 정렬 손실을 작은 MLP로) | **가능** | numpy/torch 수준. 논문 수치 재현은 아님 |
| 스프링 계획기 식 (8) 구현 | **가능** | 수식 수준. D10의 방향 감쇠 차이를 수치로 볼 수 있음 |

**노력 추정 (추정치, 측정 전).** 토이 구현 1–2주. 42M 구조를 PyTorch로 옮기되 학습은 맥 CPU의 작은 설정으로 하는 작업은 2–4주. 공식 설정 전체 재현은 GPU 클러스터 없이는 할 수 없습니다.

## 5. 정적 대조에서 확인하지 못한 것

- 포함된 `gear_sonic_deploy/`(C++ 배포)의 주기와 Kp/Kd 조정. README는 2026-08-31에 Kp/Kd 스케일링을 추가했다고 적습니다. 이 분석은 배포 코드를 읽지 않았습니다.
- `target_motion` 교란(표 S4 하단)과 방향 무작위화 범위의 구현. 설정 파일 일부만 읽었습니다.
- 공개 체크포인트의 파라미터 수와 학습 설정 파일(`sonic_release/config.yaml`). 허깅페이스 파일은 받지 않았습니다.
- 데이터 처리 파이프라인(GMR, PyRoki 재targeting)과 BONES-SEED 필터.
