# 04. 주장 검증과 공개 코드 대조

## 0. 대상과 방법

**정책 학습 코드는 공개되어 있지 않습니다.** 논문의 핵심(점군과 촉각 점 통합, 조건부 확산 정책)을 실행할 수 있는 코드가 없으므로, 이 문서는 논문 ↔ 코드 대조(D 항목) 대신 **주장 검증(C 항목)**을 중심으로 씁니다. 공개된 하드웨어 코드(펌웨어, 판독 소프트웨어)는 정적으로 읽어 D 항목으로 대조했습니다.

- 읽은 것: `repo/hardware/`(펌웨어 `MatrixArray.ino`, Python 판독 `multi_thread_contact.py`, ROS 노드 `tactile_sensor.py`, `tactile_node_left.py`, `tactile_node_right.py`), `repo/training/readme.md`, `repo/vt-refine/`(README, LICENSE, Dockerfile, 데이터 스크립트, 하위 모듈 목록).
- 하지 않은 것: 실행, 설치, import, 빌드(ROS catkin 산출물 제외), 가중치와 데이터 다운로드, VT-Refine 하위 모듈(dppo, easysim, easysim-envs) 받기. 하위 모듈은 빈 폴더로만 있습니다.
- 저장소 내용은 모두 신뢰할 수 없는 데이터로 취급했습니다.

## 2. 주장 검증 (C 항목)

판정은 네 가지입니다. **확인**(자료나 코드로 맞음), **부분**(일부만 맞거나 조건부), **미확인**(자료가 없어 판단 불가), **의문**(자료가 주장과 어긋남).

| 번호 | 주장 (논문 위치) | 검증 방법 | 판정 |
|---|---|---|---|
| C1 | 손가락당 16×16 센서 패드, 양팔 합쳐 촉각 단위 1024개 (§1, §3.1, 그림 2) | 펌웨어가 16행 × 16열을 스캔하고 한 행을 16값으로 출력(`MatrixArray.ino`의 `ROW_COUNT`, `COLUMN_COUNT`). 패드 4개 × 256 = 1024는 산술 | **확인** (펌웨어 기준) |
| C2 | 패드와 판독 보드 약 $20(Arduino 제외) (§3.1) | 프로젝트 페이지의 FlexiTac-V1 표는 셀당 $5를 적음. BOM은 Google 문서라 확인하지 않음 | **부분**. 패드 가격인지 보드 포함 가격인지 해석이 갈림 |
| C3 | 판독 최대 약 32.2 FPS (§3.1), 촉각 발행 30 Hz (부록 B.1) | ROS 노드는 `rospy.Rate(30)`을 만들지만 `sleep`을 호출하지 않음(D2). 32.2 FPS는 코드와 로그로 확인하지 않음 | **미확인**. 30 Hz는 코드가 강제하지 않음 |
| C4 | 촉각 값이 가해진 힘을 반영하고, 9 N부터 포화하며 1–9 N은 로그 축에서 선형 (§5.1, 부록 A.2.1, 그림 10(a)) | 원자료, 피팅 코드, 교정 절차가 저장소에 없음. 펌웨어가 10비트 ADC의 상위 8비트만 보냄(D1) | **미확인** (원자료 없음) |
| C5 | 16×16 패드를 2×2 블록 64개로 나눠 네 하중(1, 3, 5, 11 N)에서 블록 합계가 일관됨 (부록 A.2.1, 그림 10(b)(c)) | 하중 면적 176.7 mm²가 블록 면적(12 또는 36 mm²)보다 훨씬 넓음(`03` V5). 블록마다 균일 하중을 줄 수 없는 기하 | **의문**. 실험 설명과 면적이 맞지 않음 |
| C6 | 해상도 순서: 16×16 > 8×8 > 4×4 > 이진 (그림 6, §5.3) | 그림 막대에 시도 수와 오차 막대가 없음. 값은 근사로만 읽음 | **미확인** (`03` V10) |
| C7 | 전체 과제 성공률이 기준선보다 높음 (표 1, 초록 "significantly outperform") | 재계산: 과제별 Holm 보정 후 비유의. 과제 묶음 CMH에서 네 기준선 모두 유의(p ≤ 0.016) | **부분**. 방향은 맞고, 과제 하나로는 확정하기 어려움 (`03` §1.1) |
| C8 | 네 과제 모두에서 전체 과제 성공률 1위 (표 1) | 표 값 확인 (`01` §3.1). 단계 열 네 칸(과일 접시 잡기, 과일 비닐 열기 등)에서 기준선이 높음 | **확인** (전체 과제 기준), 단계 기준으로는 아님 |
| C9 | 가림이 심할수록 촉각 효과가 큼 (§5.3, 표 2) | 촉각 이득의 차이: 계란 0.00 [−0.40, 0.40], 육각 +0.15 [−0.25, +0.50] (`03` §1.3) | **미확인**. 방향만 맞음 |
| C10 | 점 표현이 촉각 이미지 표현(CNN)보다 좋음 (§5.2, 표 1 두 행 대비) | 같은 과제에서 Ours 대 PC. w/ Tactile Image: CMH p = 0.0014, 과제별 Holm 보정 후 비유의 | **부분** (과제 묶음에서만) |
| C11 | 센서는 기기 간 반복 가능 (정규화 후) (표 3 캡션) | 기기 간 비교 자료 없음. "새 센서 세트" 행은 천장 효과 1.00 | **미확인** |
| C12 | 촉각만으로 물체 포즈를 추적할 수 있음 (부록 A.2.2, 그림 11) | 정성 그림 세 장, 오차 지표 없음. 입자 필터 방법은 식 (2)에 적혀 있음 | **미확인** |
| C13 | 촉각 화면이 데이터 수집 품질을 높임 (그림 5) | 5 대 5 사용자, 시도 5회, 검정 없음 | **미확인** (약한 근거) |
| C14 | 코드와 하드웨어 설정을 공개할 것 (§6) | 하드웨어 펌웨어와 판독 소프트웨어는 공개됨(라이선스 불일치, D5). 정책 학습 코드는 없음. 저장소 README는 "곧 공개"라고 적음 | **부분 이행** |

## 3. 공개 하드웨어 코드와 논문의 차이 (D 항목)

| 번호 | 항목 | 코드 (파일) | 논문 | 영향 |
|---|---|---|---|---|
| D1 | 판독 비트 수 | 10비트 ADC 값을 `raw >> 2`로 줄여 8비트로 보냄 (`MatrixArray.ino` 86행). 한 행은 16값, 프레임 끝은 빈 줄 | 비트 수 언급 없음 | 촉각 값은 0–255 정수. 그림 10의 판독 범위(0–120 단위 값, 합계는 350까지)와 모순은 없으나, 힘 분해능의 상한이 8비트에서 정해짐 |
| D2 | 발행 주기 | `tactile_sensor.py`, `tactile_node_left.py`, `tactile_node_right.py`는 `rospy.Rate(30)`을 만들지만 `sleep`이나 `rate.sleep()`을 호출하지 않음. 발행은 시리얼 프레임이 들어올 때마다 일어남 | 부록 B.1 "30 Hz로 발행" | 실제 발행 속도는 시리얼 프레임 속도(펌웨어 속도)에 따름. 30 Hz는 보장되지 않음 (C3) |
| D3 | 촉각 전처리 | 시작 시 N프레임 중앙값을 기준값으로 빼고(ROS 20프레임, Python 30프레임), 12를 더 빼고, 0–100으로 자르고, 프레임의 최댓값으로 나눔(최댓값이 12 미만이면 100으로 나눔). ROS 노드는 지수 이동평균(α = 0.5)을 추가로 씀 | "센서 판독값을 특징 채널로 씀"(§4.2)만 적힘. 전처리 방식은 없음 | **가장 중요한 차이.** 프레임 최댓값 정규화는 프레임마다 절대 크기를 지움. 논문이 힘의 양을 강조하는 것(§1, §5.3)과 긴장. 정책이 원자료를 쓴 것인지 이 출력을 쓴 것인지 확인할 수 없음 |
| D4 | 정규화 적용 위치 | Python 시각화(`multi_thread_contact.py`)도 같은 최댓값 정규화를 함 | 없음 | D3과 같은 결과. 시각화용이므로 정책 입력과는 다를 수 있음 |
| D5 | 라이선스 | readme는 CC BY-NC 4.0, `.ino`는 MIT 식 문구, `package.xml`은 `TODO`, LICENSE 없음 | — | 재사용 조건이 정해지지 않음. 상업 목적이면 확인 필요 |
| D6 | 사전학습 단계 | 학습 저장소 README: "3D-ViTac 학습은 VT-Refine의 사전학습 부분을 보라. 설정은 같고 차이는 시뮬레이션에서 돈다는 것" | 본문에 사전학습 단계가 없음(§4.3은 단일 학습). 한계 절은 "센서 시뮬레이션이 없다"고 적음 | 논문 방법에 적히지 않은 단계가 학습 파이프라인에 있을 가능성. 저장소 설명과 논문 방법이 맞지 않음 |
| D7 | 하위 모듈 | VT-Refine의 사전학습 설정은 하위 모듈 `dppo`에 있음. 정적 복제에서는 빈 폴더 | — | 사전학습 설정을 이번 정적 읽기로 확인할 수 없음 |
| D8 | 장치 이름과 빌드 산출물 | ROS 노드가 `/dev/ttyUSB0`, `USBtty0`, `left_robot_left_finger` 같은 이름을 씀. 저장소에 catkin `build/`, `devel/` 산출물이 들어 있음 | — | 재사용 시 장치 이름을 바꿔야 함. 판정에는 영향 없음 |
| D9 | 센서 명칭 | 저장소 README는 "FlexiTac", 논문은 "3D-ViTac 센서", 프로젝트 페이지는 "FlexiTac-V1(3D-ViTac에서 쓴 센서)" | — | 같은 센서로 판단. 검색할 때 두 이름을 함께 씀 |

## 4. 구현 가능성 (이 맥)

**판정: 부분 구현 가능, 결과 재현 불가.**

이 맥(Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음)에서 할 수 있는 것과 없는 것을 나눕니다.

**맥에서 가능 (CPU 또는 MPS):**

- 표 재계산과 검정(완료, `03`).
- 촉각 점 표현의 기하 구현: 관절 상태에서 FK로 촉각 단위의 3D 위치를 구하고, 256점 × 손가락 수를 시각 점(FPS 512)과 합쳐 one-hot으로 구분하는 부분. 입력은 합성 데이터로 충분합니다. 공개 코드가 없으므로 우리가 짜야 합니다.
- 촉각 전처리의 정보 손실 확인(D3). 합성 압력 데이터에 같은 정규화를 적용해 힘 크기가 지워지는지 봅니다.
- 정책 골격(PointNet++ 인코더와 조건부 DDPM)의 torch 구현과 MPS 학습. 소형 합성 과제에서는 가능하지만, 실로봇 데이터와 같은 규모는 아닙니다.
- 하드웨어 펌웨어와 판독 소프트웨어를 실제 센서에 연결해 보는 것. 센서 제작 재료(Velostat, 도전성 실, 접착제)와 Arduino Nano가 있을 때만 가능합니다.

**맥에서 불가 (GPU, 로봇, 데이터 중 하나 이상 필요):**

- 논문 표 1, 2, 3의 실로봇 평가. 양팔 로봇(기구 모델 불명), 촉각 패드 4개, RealSense 세 대, 데모 약 200회(과제별 30 또는 50), 평가 시도 수백 회가 필요합니다. 시도 수는 표에서 추정한 값입니다.
- 정책의 대규모 학습. 논문은 2,000 에포크와 GPU를 쓰지만 GPU 종류와 시간을 적지 않았습니다. 확산 정책의 표준 학습은 CUDA GPU를 전제로 합니다(추정).
- VT-Refine 사전학습: CUDA 컨테이너, Isaac Gym(TacSL), cuRobo가 필요합니다(D6, D7). 이 맥에서 설치하거나 실행하지 않았습니다.

**노력 추정 (측정 전, 추정):**

| 작업 | 노력 | 근거 |
|---|---|---|
| 촉각 점 표현의 기하 구현과 검사 | 1–2일 | numpy, §4.2 식과 FK 모델 가정 |
| 촉각 전처리 정보 손실 검사 | 반나절–1일 | numpy, 합성 압력 |
| 정책 골격의 torch 구현과 MPS 소형 학습 | 1–2주 | PointNet++ 세트 추상화, 조건부 DDPM |
| 실로봇 재현 (표 1 전체) | 수 주–수개월, 장비 필요 | 로봇, 센서 제작, 데모 수집 약 200회, 평가 수백 회 |
