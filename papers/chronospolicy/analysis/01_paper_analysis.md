## 1. Abstract (한 줄 요약과 주장)

**한 줄 요약:** 모방학습 정책이 관측과 행동을 "고정 주기 시퀀스의 몇 번째"로만 보던 것을, **관측을 찍은 시각과 행동을 실행할 시각(물리 시간)**으로 보게 바꿨습니다. 방법은 diffusion transformer의 위치 인코딩을 인덱스 대신 물리 시각으로 돌리는 **time-aware RoPE**와, 학습 때 관측 주기·지연·행동 시작 시각을 흔드는 **시간 무작위화**입니다.

정책은 다음과 같이 정의됩니다(Eq. 1, 3).

> A_{t_a} ∼ π_θ(· | O_{t_o}, t_o, t_a)

t_o는 각 관측의 캡처 시각, t_a는 요청한 행동 실행 시각입니다. 둘의 간격에 관측 주기, 측정 나이, 추론 지연, 실행 주기가 모두 담깁니다.

논문이 내세우는 기여는 세 가지입니다(§1).

1. 로봇 정책 학습을 물리 시간 위에서 정식화했습니다.
2. 비동기·다중 주기 관측을 고정 격자에 맞추지 않고 그대로 학습하는 time-aware RoPE diffusion transformer를 제안했습니다.
3. 현실적인 시간 변동을 넣은 벤치마크를 만들고, 동적 과제(관측-행동 시간)와 다중 감각 과제(관측-관측 시간)에서 개선을, 준정적 과제에서 성능 유지를 보였습니다.

## 2. Method

### 2.1 시간 변동의 종류 (Fig. 1)

논문은 실제 로봇의 시간 변동을 여섯 가지로 나눕니다: 센서 샘플링 주기, 관측 지연, 누락(dropout), 추론 지연, 제어 주기, 실행 지연. 과제 유형마다 중요한 시간 관계가 다릅니다.

| 과제 유형 | 중요한 시간 관계 | 예 |
|---|---|---|
| 동적 | 관측 시각 ↔ 행동이 효과를 내는 시각 | 움직이는 컨베이어, 회전하는 받침접시 |
| 다중 감각 | 서로 다른 관측의 캡처 시각 | 영상 20 Hz, 자세 20 Hz, 힘/토크 90–100 Hz |
| 준정적 | 학습 때와 배포 때 시간 조건의 차이 | DexMimicGen 6과제 |

### 2.2 물리 시간 정식화 (§3.1, Eq. 2–3)

요청 시각 t에서 H개 행동 chunk의 실행 시각을 다음처럼 둡니다.

> t_{a,j} = t + d_t + j·Δt_a,  j = 0, …, H−1

d_t는 첫 행동까지의 지연, Δt_a는 행동 간격(20 Hz → 50 ms)입니다. 다중 감각 입력은 모달리티마다 자기 캡처 시각을 그대로 유지합니다.

### 2.3 time-aware RoPE (§3.2, Eq. 4–6)

모든 토큰에 요청 시각 기준 상대 시각 t̃_i = t_i − t를 붙입니다(Eq. 4). 이미지 패치는 프레임 캡처 시각을, 자세·힘 토큰은 측정 시각을, 행동 토큰은 요청 실행 시각 d_t + jΔt_a를 받습니다. 이 값을 RoPE의 회전 좌표로 씁니다.

> q̃_i = R(t̃_i) q_i,  k̃_j = R(t̃_j) k_j  →  q̃_iᵀ k̃_j = q_iᵀ R(t_j − t_i) k_j

따라서 attention은 **경과 시간 t_j − t_i에만** 의존하고, 시계 원점을 옮겨도 변하지 않습니다. 토큰 내용(embedding)은 건드리지 않고 시간은 attention의 위치 관계로만 들어갑니다. 저자들은 이 "내용과 시간의 분리"를 시간 임베딩을 토큰에 더하는 방식(AddTime)보다 강건한 이유로 듭니다.

구현 세부(부록 A.2): 주기 0.1–2 s 사이 로그 간격의 **16개 query-key 좌표쌍**을 회전합니다. 폭 512, head 8개라 head 차원은 64(32쌍)이므로, **head마다 절반만 시간으로 회전하고 나머지 절반은 시간과 무관한 채널**로 남는 것으로 보입니다(본문에 명시되지는 않았고, 숫자에서 추론한 것입니다. `03` §1).

### 2.4 시간 무작위화 (§3.3, 부록 B.2)

학습 때 시연마다 다음을 무작위로 바꿉니다.

- **관측:** 스트림마다 주기 12.5–33.33 Hz와 전달 지연 0–50 ms를 따로 뽑습니다. 원본 데이터는 100 Hz입니다. Pivoting의 힘/토크는 1–100 Hz, 지연 0–100 ms입니다.
- **행동 시작 지연:** chunk의 절반은 지연 0, 나머지는 0–100 ms에서 뽑습니다.

뽑힌 측정은 원래 캡처 시각을 유지합니다. 그래서 같은 토큰 위치가 서로 다른 물리 간격에 대응해도 정책이 시각을 보고 해석할 수 있습니다. 부수 효과로, 고정 주기로 다운샘플링하면 버려질 측정까지 학습에 쓰게 되어 **데이터 증강**이 됩니다.

학습 목표는 표준 diffusion 손실입니다(Eq. 7–8). clean-action 예측과 ℓ1 손실을 씁니다.

### 2.5 배포 (§3.4)

- chunk를 비동기로 실행합니다. 다음 chunk를 추론하는 동안 이전 chunk를 계속 실행합니다.
- 시뮬레이션에서는 주입한 추론 지연으로 d_t를 정합니다. 실제 로봇에서는 이전 요청들의 완료 시간으로 d_t를 추정합니다.
- 새 예측이 도착하면, 실행 시각이 이미 지난 행동은 버리고 나머지를 t_a에 맞춰 실행합니다.

### 2.6 구조와 학습 설정 (부록 A, Fig. 6)

| 항목 | 값 |
|---|---|
| 백본 | 16층 diffusion transformer, 폭 512, head 8 (DP와 Chronos 공통) |
| 영상 | SigLIP2 base, 256×256, 768차원 패치 특징 → 투영. 비영상 토큰끼리 self-attention, 영상 패치에는 cross-attention |
| 관측 이력 | Conveyor·표준 과제: 카메라당 영상 2장 + 자세 2개. Pivoting: 영상 2, 자세 3, 6차원 힘/토크 32개 |
| 행동 | 16개 @ 20 Hz. Pivoting은 19차원 adaptive-compliance 행동(Hou et al., 2025) |
| 학습 | AdamW 3e-4, 인코더 0.1배, BF16, 50 epoch, DDIM 24/8 step(시뮬레이션), 50/16 step(실제) |
| 실행 길이 | 표준 12, Conveyor·Pivoting 8 |

## 3. Experiments

### 3.1 설정 (§4.1, 부록 B)

- **시뮬레이션:** Conveyor(동적, 벨트 속도 무작위), Pivoting(다중 감각, 접촉), DexMimicGen 6과제(준정적: Threading, Assembly, Transport, Coffee, Drawer Cleanup, Pouring).
- **평가 조건 6개(Table 2, 3):**

| 조건 | 영상·자세 주기 | 힘/토크 | 관측 지연 | 추론 지연 |
|---|---|---|---|---|
| Nominal | 20 Hz | 100 Hz | 0 | 0 |
| Small obs. | 12.5–33.33 Hz | 75–100 Hz | 0–50 ms | 0 |
| Wide sensors (= Table 2의 "Large") | 1–50 Hz | 1–100 Hz | 0–100 ms | 0 |
| Delay 0–100 / 0–200 ms | 20 Hz | 100 Hz | 0 | 0–100 / 0–200 ms |
| Combined | Large | Large | 0–100 ms | 0–200 ms |

- **통계:** 학습 시드 3개. Conveyor·Pivoting은 시드마다 평가 시드 3 × 50 에피소드(조건당 방법당 450 에피소드), 표준 과제는 시드마다 50 에피소드입니다. 체크포인트는 nominal 검증 성공률로 고릅니다(부록 B.1).
- **실제 로봇(부록 C):** Dynamic Cup(시연 252), Peg Insertion(220), Pivoting(322). 조건마다 10회(Pivoting 20회). 완전 성공 1점, 부분 성공 0.5점입니다.

### 3.2 동적 과제: Conveyor (§4.2, Table 3)

| 조건 | DP | Chronos |
|---|---|---|
| Nominal | 73.1 | 82.0 |
| Small obs. | 15.6 | 77.6 |
| Wide sensors | 0.0 | 45.6 |
| Delay 0–100 ms | 14.2 | 83.1 |
| Delay 0–200 ms | 1.8 | 76.4 |
| Combined | 0.0 | 32.7 |

시간 정보가 없는 DP는 관측 간격이나 추론 지연이 바뀌면 거의 실패합니다. 같은 영상 변위가 20 ms 간격이면 빠른 물체, 200 ms 간격이면 느린 물체이기 때문입니다.

### 3.3 다중 감각 과제: Pivoting (§4.2)

작은 시간 변화에서는 비슷하고(64.0 vs 64.9), 큰 변화에서 차이가 벌어집니다: Delay 0–200 ms 51.3 → 60.2, Combined 19.6 → 38.4. 다만 시드 간 편차가 커서 이 차이는 시드 단위 검정에서 유의하지 않습니다(`03` §5).

### 3.4 무엇이 정책을 시간 인식형으로 만드는가 (§4.3, Fig. 3, Table 3)

| 변형 | Conveyor 교란 평균 | Pivoting 교란 평균 |
|---|---|---|
| DP | 6.3 | 48.4 |
| DP + 시간 무작위화 | 26.9 | 21.6 |
| RoPE, 무작위화 없음 | 48.8 | 33.3 |
| AddTime (시간 임베딩 더하기) | 51.5 | 33.5 |
| **Chronos (RoPE + 무작위화)** | **63.1** | **55.3** |

- 시간 무작위화만 하면 Conveyor에서는 도움이 되지만, Pivoting에서는 모든 조건에서 오히려 나빠집니다(nominal 61.6 → 29.8). 시각을 모르는 채로 주기를 섞으면 같은 토큰 위치가 서로 다른 모달리티 간 시간차를 뜻하게 되어 모호해진다는 해석입니다.
- 시각을 주면 무작위화가 일관되게 도움이 됩니다.
- AddTime은 Conveyor nominal에서만 RoPE보다 낫고(85.8 vs 82.0), 나머지 모든 조건에서 RoPE가 낫습니다.

### 3.5 준정적 과제: DexMimicGen 6과제 (§4.4, Table 4)

nominal 평균은 76.4(DP) vs 77.1(Chronos)로 비슷하고, 교란 5조건 평균은 59.7 → 73.4입니다. 이득은 Assembly, Coffee, Pouring에 몰려 있습니다. 이 세 과제에서 DP가 Wide·Combined 조건에서 0–15%로 무너지기 때문입니다(`03` §5.3).

## 4. Limitations

### 4.1 저자가 밝힌 한계 (§5)

- 행동 주기는 고정(20 Hz)입니다. 가변 제어 주기와 시간 배율 조절(시연보다 빠르게나 느리게 실행)은 향후 과제로 남겼습니다.

### 4.2 분석하면서 추가로 발견한 한계와 의문점

1. **"Small obs." 조건은 Chronos의 학습 무작위화 범위와 정확히 같습니다**(12.5–33.33 Hz, 0–50 ms). Chronos에게는 학습 분포 안이고, 무작위화 없이 학습한 DP에게만 분포 밖입니다. 공정한 비교 상대는 DP + 무작위화입니다(Conveyor 60.9 vs 77.6, Pivoting 30.0 vs 64.9). 프로젝트 페이지 데이터도 이 조건을 `sensor_id`, Wide를 `sensor_ood`라고 부릅니다(`03` §3).
2. **표준 과제와 실제 로봇에는 "DP + 무작위화" 기준선이 없습니다.** Conveyor에서는 무작위화만으로도 교란 평균이 6.3 → 26.9로 올랐습니다. 그래서 표준 과제의 59.7 → 73.4, 실제 로봇의 차이 중 얼마가 시각 정보 덕이고 얼마가 데이터 증강 덕인지 나눌 수 없습니다.
3. **Pivoting과 RoPE-vs-AddTime 결론은 시드 3개로는 통계적으로 약합니다.** Pivoting의 Chronos-DP 차이는 6개 조건 모두에서 시드 단위 p > 0.2입니다. AddTime은 시드 하나만 잘 되고 둘은 무너진 패턴입니다(nominal 시드별 110, 61, 56/150). 이는 표현 방식의 차이라기보다 학습 불안정일 수 있습니다(`03` §5).
4. **실제 로봇은 조건당 10–20회입니다.** 12개 조건에서 모두 최고라는 서술은 맞지만, 조건별 차이 24개 중 permutation p < 0.05는 1개뿐입니다. 4개 조건을 합치면 과제별로 유의합니다(Peg vs DP만 p = 0.09).
5. **실제 로봇 학습의 무작위화 범위가 적혀 있지 않습니다.** 부록 B.2의 범위는 시뮬레이션 절에 있습니다. 실제 평가의 자세 주기 하한(8.33 Hz)과 힘/토크 범위(37.5–150 Hz)가 학습 범위 안인지 판단할 수 없습니다.
6. **이력 처리 방식이 불분명합니다.** 학습 때 힘/토크를 1–100 Hz로 뽑고 32개를 쓰면, 1 Hz에서는 이력이 31초에 이릅니다. 에피소드 시작 부분이나 오래된 측정을 어떻게 처리했는지 적혀 있지 않습니다.
7. **기준선 세부가 부족합니다.** DP가 어떤 인덱스 위치 인코딩을 쓰는지, 실제 로봇에서 d_t를 어떻게 추정하는지(이동 평균인지, 최댓값인지)가 없습니다.
8. **용어가 섞여 있습니다.** 같은 조건을 "Large"(Table 2), "Wide sensors"(Table 3), "large"(Fig. 3), `sensor_ood`(웹 데이터)로 부릅니다. Pivoting은 웹 데이터에서 `flipup`입니다. Table 3의 "Delay" 열은 관측 지연이 아니라 추론 지연입니다.
9. **코드가 공개되지 않았습니다.** 그래서 이 분석의 검증은 수치 정합성과 toy 수준입니다.
