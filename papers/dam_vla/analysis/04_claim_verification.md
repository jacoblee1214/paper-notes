# 04. 주장 검증과 구현 가능성

공식 코드가 없어(프로젝트 페이지 "Code (soon)", 2026-11-26 확인, `02` §2) 코드 대조 대신 논문의 주장 C1–C16을 표·그림 수치와 대조했습니다. 근거는 `03`의 재계산 결과입니다. 시행 수는 논문이 적은 과제당 15회입니다.

## 1. 주장 판정

판정 범주: **지지**(수치와 검정이 뒷받침), **부분**(일부만), **방향만**(방향은 맞으나 구별되지 않음), **미검증**(논문에 확인할 실험이나 값이 없음).

| 번호 | 주장 (위치) | 확인한 것 | 판정 |
|---|---|---|---|
| C1 | 평균 성공률 95.2% 대 40.95%로 두 배 이상 (초록, §6, 표 2) | 100/105 대 43/105, Fisher p = 2e-18, 과제 층화 p = 6e-21. 과제별로는 Button·Handwash·Lego·Socket에서 Holm 후에도 유의, Scarf·Whiteboard·Sweep은 구분 안 됨 (`03` V5, V6) | **지지** (네 과제에서) |
| C2 | "평균 성공률이 54.25% 향상" (§1) | 반올림 값의 차이이며 단위는 %p, 계산 값 54.29 %p (`03` V3, K11) | 지지 (단위 표기) |
| C3 | 동기식을 100 Hz로 올리면 오히려 나빠진다: 40.95 → 21.9% (RQ1) | 43/105 대 23/105, p = 0.005. Whiteboard 13/15 대 2/15가 가장 큼 | **지지** |
| C4 | 비동기만으로 100 Hz 손실을 회복: 비동기만 40.0%가 X-VLA25와 "거의 같고" X-VLA100보다 높다 (RQ2) | 42/105 대 43/105 p = 1.0 (X-VLA25와 구분 안 됨), 대 X-VLA100 23/105 p = 0.007 | **지지** (X-VLA100 대비 회복, X-VLA25를 넘지는 못함) |
| C5 | 메모리와 힘이 "각각 독립적으로 기여" (RQ3) | 가산 예측 84.8% 대 실제 95.2%, 상호작용 +10.5 %p (구간 −1.9 ~ +21.9), Lego +80, Socket +66.7 %p에 몰림. 기억만(61/105)과 힘만(70/105)의 차이는 p = 0.25 (`03` V8, §1.2) | **부분** (두 요소가 함께 있어야 풀리는 과제가 있는 것으로 읽힘) |
| C6 | GCA가 이어 붙이기보다 낫다: 95.2% 대 54.3% (RQ4) | 100/105 대 57/105, p = 2e-12. Lego 14/15 대 0/15, Button 14/15 대 2/15, Socket 12/15 대 1/15 | **지지** (성능 차). 파라미터 수가 같은지는 확인 못 함 |
| C7 | 이유: 새 토큰이 사전학습 self-attention을 흐트러뜨린다 (RQ4) | 표현 보존을 재는 실험 없음. 토이 1에서 초기 출력 변화는 이어 붙이기 8.8% 대 GCA(b = −5) 0.16%이나 무작위 가중치이고 식 2의 게이트는 0이 아닌 값에서 시작 (`03` §3.1) | **미검증** |
| C8 | X-VLA100의 실패 원인은 "같은 영상에 다른 액션 라벨"의 모순 (RQ1) | 원인을 가르는 실험 없음. 고유감각이 매 스텝 달라 같은 영상이라도 입력이 완전히 같지는 않다는 점이 논문에 논의되지 않음 | **미검증** |
| C9 | 100 Hz에서 가장 부드러운 명령: SPARC 8.1이 최소 (부록 D, 그림 6, Sweep) | 점추정은 최소이나 오차 막대(그림 판독)가 AFM 10.47(±2.9), /M 10.6(±3.0)과 겹침. 비동기만(16.83)은 AFM보다 높음 (`03` §1.5) | **방향만** |
| C10 | 추종 지연 최소 0.116 s (부록 D, 그림 7) | 그림 7은 0.118 s. 100 Hz 구성들과 6–21 ms 차이, 오차 막대와 겹침. 토이 2에서 지연 추정이 명령 구성에 수십 ms 민감 (`03` §3.2, K1) | **방향만** |
| C11 | "100 Hz에서 부드럽고 반응적으로 동작" (초록) | 제어기는 100 Hz이고 재계획은 약 5.5 Hz(§4.1). 힘은 청크 안에서 교정에 쓰이지 않는다고 저자가 §5에서 밝힘 (`03` §1.6, K3) | **부분** (제어기 주기 기준) |
| C12 | 추론 지연 감소 (기여 3) | ms 단위 지연 표는 없고 재계획 주파수만 있음(X-VLA25 약 1, X-VLA100 약 3.5, DAM-VLA 약 5.5 Hz). 구성별 s와 청크 길이 차이가 같이 있음 | **미검증** (주파수는 보고, 지연은 미보고) |
| C13 | 힘은 접촉 종료 시점을, 기억은 반복 방지를 준다 (RQ3, 그림 5) | 힘 없는 구성에서 Lego(/F 0/15 대 14/15)와 Socket에서 큰 차이. Handwash 반복 누름 서술은 그림 5의 한 에피소드 힘 곡선과 /M의 partial 7/15(46.67%)에 의존. 힘 신호를 가리거나 섞는 대조는 없음 | **부분** |
| C14 | 에피소드 시간이 데모 대비 "결정적" (부록 E) | 판독 값으로 DAM-VLA는 데모 시간의 1.1–1.9배(평균 1.55배). 세 구성만 그림에 있음 (`03` §1.5) | **부분** |
| C15 | 200 Hz 제어기에서도 반응적 (부록 F, 표 4) | Handwash와 Whiteboard 두 과제만, 시행 수 미기재, 성공률 100% | **방향만** (시행 수 필요) |
| C16 | 구조는 센서 집합에 한정되지 않는다 (§1) | 힘 한 종류만 실험. 촉각 등 다른 고주파 모달리티 실험 없음 | **미검증** |

- **성공 정의:** 표 2는 clean과 partial의 합입니다. clean만의 평균은 분해가 없는 세 과제를 전부 clean으로 가정한 상한이 87.6%(DAM-VLA)와 38.1%(X-VLA25)입니다(`03` V9). 판정 C1은 합 기준입니다.
- **초기 조건과 반복:** 구성 사이 초기 조건이 짝지어졌는지, 학습 시드가 몇 개인지는 논문에 없습니다. 모든 검정은 이 가정 위에 있습니다.

## 2. 프로젝트 페이지와의 대조

프로젝트 페이지의 표(평균 막대와 히트맵)는 표 2와 같은 수치이고, 그림 4의 clean/partial 막대 폭이 논문 그림과 일치합니다. 페이지는 "15 trials per task"를 적고, "Accepted to CoRL 2026"과 "Code (soon)"을 표기합니다. 논문 본문에 없는 새 수치는 없었습니다.

## 3. 공식 코드

2026-11-26 기준으로 공식 코드를 찾지 못했습니다. 그래서 하이퍼파라미터, 손실, 평가 절차의 코드 대조(D 항목)는 하지 않았습니다. 논문에서 코드 없이는 정할 수 없는 값은 다음과 같습니다.

- 시각 기억 버퍼 길이 K, 압축 토큰 수 N_mem, GRU 크기, 힘 레지스터 수
- 힘 게이트 초기화 b (식 2의 "거의 닫힘"), 교차어텐션 헤드 수
- 지수이동평균 계수, 힘 토큰화
- 실행 지평 s의 정의, 지연 인지 실행에서의 청크 접합
- 부분 성공의 판정 기준, 시행 종료 조건(시간 제한)

## 4. 구현 가능성 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**판정: 논문 수치의 재현은 불가능합니다. 구조(비동기 버퍼, GCA, 힘 인코더)의 축소판은 이 맥에서 구현할 수 있고, 수치 재계산과 구조 토이 두 개는 끝냈습니다.**

| 항목 | 판정 | 근거 |
|---|---|---|
| 실로봇 표 2 재현 (Franka Panda, 손목·3인칭 카메라, 100 Hz 제어, 과제 7개) | 불가 | 로봇, 데이터(과제당 시연 50–60개, 미공개), 과제 장치가 필요 |
| X-VLA 미세조정 (GH200, 20,000 스텝, 배치 192) | 불가 | 대형 VLA 학습. CUDA 전제의 큰 자원 (논문 부록 B) |
| 공식 코드로 추론 | 불가 | 코드 없음 |
| 추론 지연 측정(RTX 4060 Ti 기준) | 불가 | 이 맥에서 MPS로 재면 다른 하드웨어 값이 됨. 모델과 코드 없음 |
| 구조 재구현: 모달리티별 버퍼, GRU 기억, GCA(식 1–3)를 작은 정책에 붙이기 | 가능 | 수백만 파라미터 규모 토이는 CPU나 MPS에서 가능 (아래 노력 추정) |
| 합성 과제에서 "한 시계 대 센서 주기" 비교 (MuJoCo, 접촉 있는 단순 과제) | 가능 | mujoco 4.0과 torch 2.15가 설치되어 있음 (새 설치 없음) |
| 표·그림 수치 재계산, 통계 검정 | 가능, 완료 | `analysis/recompute.py` |
| 구조 토이 (초기화 변화, 지연 지표 민감도) | 가능, 완료 | `analysis/toy_gca_init.py`, `analysis/toy_zoh_lag_sparc.py` |

**노력 추정(측정 전, 추정):** 작은 비동기 버퍼 + GCA 정책을 MuJoCo 접촉 과제에서 동기식과 비교하는 데는 1–2주입니다. X-VLA 가중치로 같은 구성을 재구현하려면 GPU와 가중치 다운로드(수 GB), 로봇 데이터가 필요해 이 맥에서는 의미 있는 규모가 안 됩니다. 실로봇 재현은 Franka와 과제 장치가 있어야 하며, 코드가 공개될 때까지 대조할 기준도 없습니다.
