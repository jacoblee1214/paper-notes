공식 저장소를 얕게 클론했습니다(`repo/`, gitignore). HEAD는 `a3699b5`(2026-10-10 "Align MC-TAC vertical slip proxy and calibration")이고, 그 앞 커밋은 `30f336d`(2026-10-10 "Initial release of TactileReflex reproduction code")입니다. 저장소에 커밋은 두 개뿐입니다. 라이선스 파일이 없습니다.

## 3. 저장소 두 커밋의 차이 (`30f336d` → `a3699b5`)

`git diff`로 확인했습니다. 변경은 4개 파일, +67/−28줄입니다. 논문 식과 맞추려고 바뀐 부분입니다.

1. **Sy 정의:** `median(flow_mag)` → `median(abs(fy))` (D1, D1a).
2. **CoP:** EMA 값 → 원시 가중 중심 (D15).
3. **Closing 판정:** `Fn_min`(EMA) → `Fn_raw_min`(D17).
4. **보정 후보:** 슬립 상한이 `(P95 + 최소 슬립)/2`에서 `(P99.9 + 최소 슬립)/2`로 바뀜 (D9). 조건도 `slip_weakest > static_sy_p999`로 바뀜.

**해석.** 논문 수치가 초판 코드로 얻어졌다면 CoP와 Closing과 Sy 정의가 모두 달랐을 것입니다. 저장소 README는 "논문과 임계값이 다를 수 있다"고 씁니다. 따라서 **논문의 Table III, IV, V 수치를 이 저장소로 다시 얻을 수 있는지는 현재로서 알 수 없습니다.**

## 4. 구현할 수 있는지

### 4.1 공식 재현 (두 MC-Tac 센서와 Piper 그리퍼)

- **필요한 것:** MC-Tac 센서 두 개(3D 프린트 부품, 미니 카메라, LED 링, 실리콘 젤, 아크릴; 설계는 `Tacxels/MC-Tac`, BSD-3), 손가락에 맞는 어댑터, Piper 팔과 그리퍼, CAN 어댑터, 리눅스 PC, 컵과 물.
- **코드 의존성:** `piper_sdk`(MIT, `agilexrobotics/piper_sdk`)와 CAN 설정(`can0`), OpenCV(Apache-2.0)가 필요합니다. 카메라 자동 탐지는 `/sys/class/video4linux`를 읽으므로 **리눅스 전용**입니다(v1 88–116).
- **보정:** 연한 컵과 강성 컵에 대해 E1–E3 순서로 CSV를 모은 뒤 `calibrate_thresholds.py`를 실행합니다(README §3). 이 단계가 노이즈 유도 임계값의 실제 구현입니다.
- **판정: 기술적으로 가능, 조건부.** 코드는 읽을 수 있는 수준이고 공개되어 있지만, 논문 수치를 그대로 재현하는 것은 D1, D4, D5, D9, D10 때문에 보장되지 않습니다. 재현 목표를 "논문 Table V가 같은 결과를 내는가"에서 "Sy 정의와 보정 절차를 고정한 뒤 어떤 결과가 나오는가"로 낮추는 것이 현실적입니다.

### 4.2 이 맥 (Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음, torch 미설치)

| 작업 | 가능 여부 | 이유 |
|---|---|---|
| 논문 표 재계산, 검정, toy | **가능** (완료) | numpy, scipy로 충분 |
| `calibrate_thresholds.py`를 기록된 CSV에 실행 | **가능** (설치 없이 numpy는 있음) | CPU 작업. 단 저장소 코드 실행은 재현 승인 후 |
| 실시간 제어 루프 | **불가** | 카메라 자동 탐지와 CAN(`can0`)이 리눅스 전용. Piper는 CAN 필요 |
| 센서 영상 재처리 (녹화 영상이 있을 때) | **조건부** | OpenCV 설치 필요 (설치 승인 전이므로 보류). 영상 파일 자체가 없음 |
| 학습 기반 방법 | 해당 없음 | 이 논문은 학습이 없음. 정책과 결합 실험은 별도 |

### 4.3 아이디어 재구현 노력

- **제어 로직 (상태 기계 + 세 채널):** 약 150–200줄. 식 (7)–(13)과 Alg. 1은 명확합니다. 증분 값은 D11의 코드 값을 쓰면 됩니다.
- **촉각 처리 (ΔI, 마스크, Fn, CoP, Sy):** 약 100–150줄. 광흐름 매개변수 D2는 OpenCV 기본과 같은지 확인해야 합니다.
- **보정:** 약 200줄(저장소 스크립트 재사용 가능, 라이선스는 D-항목 §5 참고).
- **하드웨어 어댑터와 안전 루틴:** 가장 큰 비용입니다. 센서 동기화(D5), 그리퍼 CAN 명령, 긴급 정지.
- **총평:** 제어와 처리는 쉽습니다. 실물 튜닝, 보정 반복, 센서 동기화가 실제 노력입니다. 첫 동작 버전까지 하드웨어가 있다면 1–2주 정도로 추정합니다(추정, 확인 안 함).

### 4.4 판정 (한 줄)

**구현할 수 있는가: 예, 단 하드웨어(MC-Tac 두 개, Piper, 리눅스 PC)가 있을 때만.** 이 맥에서는 실물 제어를 돌릴 수 없고, 분석과 toy와 기록 데이터 재처리까지만 가능합니다. 논문 수치의 재현은 D1·D4·D5를 먼저 고정하지 않으면 확인할 수 없습니다.

- 이 폴더는 코드를 옮기지 않았습니다. 인용은 파일과 줄 번호(`file:line`)로만 했고, 식별자는 몇 개만 짧게 썼습니다.
- 공개본에도 코드 본문은 없습니다. 토이와 재계산 스크립트는 우리가 쓴 것이며 논문 식만 따릅니다.
- 재현을 하게 되면, 저장소 코드를 **참고용으로만** 쓰고 우리 구현을 따로 짜는 것이 안전합니다. 코드를 가져다 쓰려면 저자에게 라이선스를 문의해야 합니다(사용자 판단).
- 의존 저장소 `piper_sdk`(MIT)와 OpenCV(Apache-2.0)는 허용 라이선스입니다.

## 6. 재현에 필요한데 논문에 없는 정보

1. Sy의 정확한 정의(D1)와 광흐름 매개변수(D2), 프레임 간격.
2. 오른쪽 영상 반전 여부와 좌표계(D4).
3. 두 센서의 동기화 방식(D5).
4. 임계값 후보 계산식: θs(중점 대 상한), θc, Flim의 여유(D6–D10).
5. Fstop의 유도 (D8).
6. 제어 증분 Δe, Δp의 값(D11)과 주기 측정(D19).
7. N_min, 모폴로지 커널(D20).
8. 시험 순서, 시험 간 간격, 판정 기준(붓기의 변형 판정).
