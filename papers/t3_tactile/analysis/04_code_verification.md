### 2.1 일치하는 부분

- 디코더: MAE 재구성은 512차원, 8층, 16헤드 (`pretrain1_mae.yaml`), 분류 MLP는 256-128-64에 드롭아웃 0.1 (`pretrain2.yaml`), 포즈 디코더는 ResNet 기본 블록 두 개 뒤 MLP 256-64 (`CNNFCDecoder`, `decoder.py:111`). 모두 A.5와 맞습니다.
- 분류는 토큰(cls)만 디코더에 넘깁니다. 본문과 같습니다.
- 갠트리 분류 `cls_cnc`의 출력은 6입니다(`finetune_exp_cls.yaml:57–60`). 6개 프로브 질감이고, §5.1의 "객체 분류 6개 범주"와 맞습니다. 따라서 §5.1 실험은 갠트리 데이터를 씁니다.
- 인코더 MLP 비율 4, 임베딩 768, 헤드 12 (`pretrain2.yaml`)는 표 1 medium과 맞습니다.

### 2.2 차이가 결과에 미칠 영향

- D1: 기본 마스킹 0.4는 본문 최적 0.8과 다릅니다. 공개 체크포인트가 어떤 값으로 학습됐는지 모르면 사전학습 결과를 재현할 때 어느 쪽을 써야 할지 정할 수 없습니다.
- D5: 갠트리 데이터가 사전학습에 들어갔다면 §5.1–5.2의 평가(갠트리 분류, 3D 포즈)가 누설될 수 있습니다. 확인할 수 없습니다. 조합 파일이 없기 때문입니다.
- D2와 D3: 표 1의 크기 비교(§5.1 scaling 주장)는 실제 파라미터 수가 아니라 설정 이름에 기댑니다. 체크포인트로 보면 medium 331M이라 "174M"과 다릅니다.

## 3. 재현 가능한 설정 (설정 파일 기준)

- 사전학습 I: `pretrain1_mae.yaml` + 공개 데이터 목록 (`single_tower_mae.yaml`). `activate: true`인 데이터셋 10개(목록: tippur23 두 종, TVL, VisGel, Calandra17, Touch-and-Go, Yuan18, YCB-Sight 시뮬, ObjectFolder-real, YCB-Sight 실제는 eval_only), 배치 64, 100,000 스텝 (`config.yaml`).
- 사전학습 II: `pretrain2.yaml` + `finetune_exp_*`. 조합 파일이 없어 어떤 데이터셋을 켤지 직접 정해야 합니다(D5).
- 평가: `eval_ds_cls_*.yaml`, `eval_ds_pose_*.yaml`이 갠트리와 새 센서 평가를 정의합니다. 체크포인트 로드는 `T3.load_components`(`t3/models/t3.py:114`)가 맡고, 추론은 `T3Pretrain.predict`(`pretrain.py:453`)가 합니다. 두 함수를 읽었지만 실행하지 않았습니다.

## 4. 구현 가능성 (이 맥: Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음)

**판정: 논문 전체 재현은 이 맥에서 불가능합니다. 공식 체크포인트로 특징을 뽑는 평가 파이프라인은 승인을 받으면 가능합니다. 학습 재현과 제로샷 주장 재현은 GPU와 데이터 규모 때문에 불가능합니다.**

| 작업 | 자원 | 이 맥 | 근거 |
|---|---|---|---|
| 체크포인트 추론 (tiny, small) | 91 MB, 341 MB 다운로드, torch·timm·hydra 설치 | 조건부 (다운로드와 설치 승인) | HF 목록 (`02` §4) |
| 체크포인트 추론 (medium, large) | 1.3 GB, 2.9 GB 다운로드 | 조건부 (다운로드 승인, 1 GB 이상) | 같음 |
| 동결 특징 + 소형 헤드로 분류 | 데이터 일부 (분류 데이터셋 크기는 개별로 확인 못함) | 보류 | 데이터 392.5 GB, 분할 zip 파트 약 16 GB (`02` §4) |
| FoTa 사전학습 (MAE, 사전학습 II) | 392.5 GB 데이터, 10만 스텝 | 불가 | GPU 전제 (`04` D9, D14) |
| 삽입 실로봇 재현 | Franka, 그리퍼, 촉각 센서, PCB | 불가 | 실로봇 |
| 갠트리 평가 재현 | CNC 장치 (데이터는 HF 안에 있을 가능성) | 불가 (데이터 접근 어려움, 구조는 CPU로 가능) | - |
| 구조 축소 재구현 (ViT 인코더 + 공유 트렁크, 작은 차원) | numpy 또는 torch | 가능 | 노력 2–3주 추정 (측정 전) |

- **노력 추정 (측정 전):** 체크포인트 추론과 몇 장의 특징 비교는 1–2일(설치와 승인 포함). 구조 축소 재구현은 2–3주(추정). 두 방법 모두 측정하지 않은 추정입니다.
- **하지 않은 것:** 설치, 실행, import, 가중치와 데이터 다운로드(크기만 확인), 토이 실험.

## 5. 검토 범위와 한계

- 정적 읽기만 했습니다. 데이터 로더, 학습 루프, 평가 코드가 설정과 맞게 동작하는지는 실행하지 않아 확인하지 못했습니다.
- `T3Pretrain`의 배치 구성(한 배치가 한 쌍에서 오는지)은 읽지 않았습니다. 논문 §4 첫 문단의 주장은 확인 못함으로 둡니다.
- 체크포인트 크기로 파라미터 수를 추정했습니다(fp32 가정). 실제 텐서 형태를 로드하지 않았습니다.
