# 04. 논문 ↔ 공식 코드 대조

대상은 공식 저장소 `UMass-Embodied-AGI/TesserAct`의 커밋 `d2fe4b1`(2025-08-03, 얕은 clone, `repo/`)입니다. 코드는 **읽기만** 했습니다. 실행, import, 설치, 가중치 다운로드는 하지 않았습니다. 저장소의 Python 파일과 셸 스크립트를 `grep`과 직접 읽기로 확인했고, 검색 결과는 본문에 적었습니다. 대조 기준은 arXiv v1(`01`)입니다. 학회판과 본문 차이는 `01` §6에 있습니다.

## 2. 일치하는 부분

- **생성 모델 구조.** `TesserActDepthNormal`은 RGB 출력 뒤에 깊이와 법선을 합칩니다. `dn_out_proj`(Conv3DNet)가 `[RGB 출력; 깊이 입력; 법선 입력]`을 받고, 그 결과를 `dn_out`으로 깊이와 법선 출력에 결합합니다. 논문 §4.2의 Conv3D 결합과 대응합니다.
- **0 초기화.** `embeddings.py`의 `depth_proj`, `normal_proj`는 `nn.init.zeros_`로 초기화합니다(53, 152행). 논문의 "나머지 모듈 0 초기화"와 맞습니다.
- **VAE와 텍스트 인코더 고정, 트랜스포머만 학습.** `i2v_depth_normal_sft.py` 431–433행의 `requires_grad_` 설정이 논문 §4.2의 "VAE를 고정하고 DiT 학습"과 맞습니다.
- **라벨링 도구.** `video_depth.py`는 RollingDepth(anyeZHY 포크), `video_normal.py`는 `prs-eth/marigold-normals-lcm-v0-1`을 씁니다. 논문 §4.1의 RollingDepth와 Temporal Marigold-LCM과 맞습니다.
- **프레임 수와 해상도.** 추론 스크립트는 `num_frames=49`, 480×640을 씁니다. 논문 §5.1.2의 49 프레임과 맞습니다.
- **로봇 이름 조건.** `doc/usage.md`와 추론 예시의 `google robot`, `Franka Emika Panda`, `Trossen WidowX 250`은 논문의 `[지시] + [로봇 이름]` 형식과 맞습니다.
- **학습 반복 수.** `doc/usage.md`는 `tesseract_v01e_rgbdn_sft`를 "trained for 40000 steps"로 적었습니다. 논문 부록 1.1의 40,000 반복과 맞습니다(단, 설정 세부는 D9).

## 3. 불일치와 빈칸 (D1–D14)

**구성 요소가 빠진 것 (D1–D5)**

- **D1. 4D 재구성 최적화가 없습니다 (논문 §4.3, 식 3–7).** 법선 적분 기반 깊이 최적화(식 3), RAFT 흐름 마스크와 일관성 손실(식 5), 정규화 손실(식 6), 총손실 최적화 루프를 구현한 파일이 없습니다. `optical`, `flow`, `raft`, `consistency`, `regular`는 저장소 전체에서 0건입니다. 공개된 `scripts/rendering_points.py`는 깊이·점군을 Blender로 그리는 스크립트이지 최적화가 아닙니다. 따라서 **표 2의 실세계·합성 점군 Chamfer를 재현할 수 없습니다.** 그림 3의 일관성·정규화 손실 효과도 재현할 수 없습니다.
- **D2. 역동역학 행동 예측이 없습니다 (§4.4, 표 3).** PointNet 점군 인코더, 4층 MLP, 8192점 샘플링, 20% 잡음 증강 코드가 없습니다. `inverse`라는 단어는 `robodataset.py`에서 데이터 가중치 주석으로 한 번 나올 뿐입니다.
- **D3. RLBench 학습 경로가 주석 처리되어 있습니다.** `robodataset.py` 589–592행에서 `_load_rlbench_dataset_from_local_path()` 호출과 `samples` 추가가 모두 주석입니다. 그런데 `doc/usage.md`는 `tesseract_v01e_rgbdn_sft`를 "RT1, Bridge, RLBench"로 학습했다고 적습니다. 공개 저장소로는 RLBench 데이터를 읽을 수 없고, 표 3에 쓰인 RLBench 전용 모델(13 프레임, 부록 1.3)도 공개되지 않았습니다.
- **D4. 베이스라인 코드가 없습니다.** Image-BC, UniPi*, 4D Point-E, OpenSora·CogVideoX LoRA, SoM, Shape of Motion의 구현이나 설정이 없습니다. 감사의 글은 "baseline code"에 기여한 사람을 언급하지만(`01` §6) 그 코드는 공개되지 않았습니다.
- **D5. 평가 지표 코드가 없습니다.** FVD, SSIM, PSNR, AbsRel, δ1·δ2, 법선 평균·중앙·11.25°, Chamfer L1, CLIP 점수·미학 점수의 계산 스크립트가 없습니다. 특히 AbsRel과 δ의 **깊이 정렬 방식**(스케일·이동 정렬 여부)과 Chamfer의 **스케일 처리**는 논문에 적혀 있지 않아서, 코드 없이는 표 2를 재현할 수 없습니다.

**설정과 세부 값의 차이 (D6–D10)**

- **D6. 라벨링 도구는 일치하지만, 저장소가 한계를 인정합니다.** `README.md` 178행: "RT1 and Bridge normal data is generated by Temporal Marigold ... sometimes normal outputs are not perfect. We are working on improving the data using NormalCrafter". 논문 §4.1에는 이 한계가 없습니다. 실세계 라벨 품질 문제가 저자 스스로 확인된 셈입니다.
- **D7. 샘플러가 다릅니다.** 논문 부록 1.1은 "DDPM scheduler across 50 steps"라고 씁니다. 저장소 추론(`inference_rgbdn_sft.py` 81행, `_lora.py` 104행)은 `CogVideoXDPMScheduler`를 씁니다. DDPM과 DPM 계열은 같은 샘플링 식이 아니어서 생성 품질이 달라질 수 있습니다.
- **D8. 가이던스 설정이 더 많습니다.** 논문은 CFG 7.5만 씁니다. 저장소 `__main__`은 `guidance_scale=7.5`에 `image_guidance_scale=1.5`를 함께 씁니다. 함수 기본값은 6.0입니다. 논문은 이미지 가이던스를 언급하지 않습니다.
- **D9. 학습 설정이 논문과 다르고, EMA 코드가 없습니다.**
  - 논문 부록 1.1: 40,000 반복, 전역 배치 16, 학습률 1e-4, Adam(ε = 1e-15), 워밍업 1,000, EMA 0.99.
  - 저장소 `train_i2v_depth_normal_sft.sh`: 학습률 5e-5(목록형 실험 설정), AdamW, 워밍업 200, `MAX_TRAIN_STEPS=200000`, `train_batch_size 1`(GPU 수 곱), gradient checkpointing. 스크립트에는 "Experiment with as many hyperparameters as you want!"라는 주석이 있어서 **공개 체크포인트의 실제 설정이 아닙니다.**
  - EMA: `tesseract/*.py`에서 EMA 관련 코드가 없습니다(`scripts/video_normal.py`의 `ema`는 무관한 단어 일치).
  - 따라서 공개 체크포인트가 논문 표 2·3의 모델과 같은지 확인할 수 없습니다(D12).
- **D10. 프레임 수는 일치합니다.** 논문 49 프레임(학습·추론), 13 프레임(RLBench 계획)은 저장소의 `num_frames=49`와 맞습니다. RLBench 13 프레임 설정은 D3 때문에 확인할 수 없습니다.

**데이터, 가중치, 라이선스 (D11–D14)**

- **D11. 4D 데이터셋이 공개되지 않았습니다.** README는 "We don't have a clear plan for releasing the whole dataset yet"라고 씁니다. 공개된 것은 Bridge 전처리 스크립트(`scripts/preprocess_bridge.py`)와 `DATA.md`입니다. 논문의 약 205k 실세계 + 80k 합성 데이터는 없습니다.
- **D12. 공개 체크포인트의 버전이 실험과 맞는지 확인할 수 없습니다.** HF 저장소에 올라간 것은 `tesseract_v01e_*`(실험 버전, `e`는 experimental)입니다. 업로드 날짜는 2025-05-01로, 학회판 수치를 낸 최종 체크포인트인지 적혀 있지 않습니다.
- **D13. 라이선스 조건이 여러 개입니다.** 저장소 코드와 HF 가중치 카드는 MIT입니다. 반면 기반 모델 CogVideoX-5B는 `license:other`(CogVideoX 라이선스)이고, `i2v_depth_normal_*.py` 108행이 "Please adhere to the licensing terms" 링크를 적습니다. 파생 가중치에 CogVideoX 조건이 붙는지는 이 분석에서 판단하지 않습니다(법적 판단이 아닙니다). 상업 이용 전에 확인이 필요합니다.
- **D14. 생성 조건 방식이 논문에 명시되지 않았습니다.** 저장소의 학습 스크립트는 `THUDM/CogVideoX-5b-I2V`를 씁니다(`MODEL_PATH`). 논문은 "CogVideoX"라고만 씁니다. 이미지 조건 생성(I2V)을 쓴다는 점이 논문 본문에 없습니다.

## 4. 구현 가능성 (이 맥 기준)

기기는 Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음입니다.

| 작업 | 자원 요구 | 이 맥 판정 | 근거 |
|---|---|---|---|
| 논문 표 2 재현 (4D 생성, 실세계 400·합성 200, 샘플당 10회) | CogVideoX-5B 추론, 저장소 체크포인트는 **25–29 GB** (HF 사용법 표), 데이터 수백 GB | **불가에 가까움.** 통합 메모리 24 GiB에서 25–29 GB는 맞지 않음. 오프로딩은 가능할 수 있으나 미검증 | `doc/usage.md` 표 |
| 4D 재구성 최적화 (식 3–7) | 공개 코드 없음 (D1). 직접 구현하면 RAFT 가중치 필요 | 조건부. 저해상도 축소판은 MPS에서 가능 (미측정) | `04` D1 |
| 논문 표 3 재현 (RLBench 9 과제) | RLBench와 CoppeliaSim 설치, 시뮬레이션 실행, CogVideoX 학습 | **불가** (데이터·모델 미공개, D3, D4) | `04` D3 |
| 저장소 체크포인트 추론 (데모 수준) | 25–29 GB | 불가~빠듯함 (추정). 메모리 측정 안 함 | 위 표 |
| 전체 학습 (40k 반복, 205k 샘플) | 다중 GPU | **불가** | 논문 부록 1.1, D9 |

**구현 노력 추정 (이 맥이 아닌 GPU 기기 기준, 추정치)**

- 공식 추론 파이프라인 실행: 설치와 체크포인트 준비 반나절~하루, 추론 한 번에 수 분 (GPU 필요).
- 4D 재구성 최적화를 직접 구현해 재현: 1–2주 (RAFT 포함, 공개 코드 없음).
- 표 3 행동 계획 재현: 데이터 준비와 RLBench 설치, 학습까지 2–4주 (GPU 필요, 추정).
- 전체 학습 재현: GPU 여러 장으로 수일~수주 (추정).
