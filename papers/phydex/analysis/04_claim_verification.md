# 04. 주장 검증 (공식 코드 없음)

PhyDEX에는 공식 코드와 데이터가 공개되어 있지 않습니다(`analysis/02_prior_work.md` §4). 그래서 코드 대조 대신 **논문 표·그림·본문 주장이 서로 맞는지**와 **주장의 근거가 충분한지**를 검증했습니다. 수치 계산은 `analysis/03_analysis.md`와 `analysis/recompute.py`에 있습니다.

## 1. 수치 정합성 요약

| 항목 | 결과 |
|---|---|
| Table 1 평균 ↔ 셀 (9칸 × 50회 개수) | ✅ 일치 (0.9 / 0.2 / 2.4%) |
| Table 2 평균 ↔ 셀 | ✅ 일치 (α 세 값 × 세 정책) |
| Table 3, Table 4 평균 | ✅ 일치 (6.0 / 0.7 / 8.7%, 10.7 / 0 / 51.3%) |
| Fig. 4 값 ↔ Table 1 균일·단일 셀 | ✅ 일치 (GR00T 6, ForceVLA 10, DynamicVLA 0) |
| Fig. 4 사후 값 ↔ n = 50 | ❌ GR00T 12.5%는 50회에서 불가능 (n 미보고) |
| Fig. 7 파이 ↔ 정책별 값 | ✅ 무가중 평균과 일치 (38.5 / 22.0 / 10.6 / 28.8) |
| 본문 21.24%(파지 성공 또는 던지기 도달) ↔ Fig. 7 + Table 1 | ❌ 재구성 11.6% |
| 본문 "5.6% 던지기 성공" ↔ 1.2% | 21.24%에서 유도. 재구성 시 10.2% |
| 본문 "Fig. 4에서 12.5%와 24%만큼 올림" ↔ 그림 | ❌ 그림 값은 사후 값. 증가는 6.5와 14 |
| 본문 "DynamicVLA 4% 미만" ↔ Table 2 α = 0 | ❌ 정확히 4.0% |
| 데이터 규모 35,357 ↔ 143.2 h ↔ 10 Hz | ✅ 에피소드당 14.6 s |

**결론:** 표 안의 숫자는 서로 맞습니다. 틀린 곳은 본문 서술 몇 군데(Fig. 4 증가, 21.24%, "below 4%")와 시행 수가 보고되지 않은 Fig. 4입니다.

## 2. 주장과 근거 사이의 간극

| # | 주장 (위치) | 근거 | 판정 |
|---|---|---|---|
| C1 | 세 VLA 모두 전체 성공률 3% 미만 (초록, Fig. 1) | Table 1 평균 0.9, 0.2, 2.4% | ✅ 지지됨. 단 시드 수 미보고(단일 학습으로 보임), 과제당 50회 |
| C2 | 물리량을 주면 성공률이 "대략 두 배" (초록, §4.4, §5) | Fig. 4: 6 → 12.5, 10 → 24 (균일·단일 셀) | ⚠️ 점 추정만 두 배. ForceVLA p = 0.11, GR00T 검정 불가. "대략 두 배"는 한 셀에 한정. 전체 성공률 얘기가 아님 |
| C3 | 무작위화가 강할수록 성공률이 낮다 (§4.4) | Table 2: ForceVLA 3.3 → 11.3 → 35.3%, GR00T 2 → 4.7 → 9.3% | ✅ 강하게 지지됨 (p ≈ 10⁻¹³) |
| C4 | α = 0에서도 어떤 셀도 44%를 넘지 않음 → "무작위화 탓만은 아님" (§4.4) | Table 2 최댓값 44% | ✅ 지지됨. 이는 "무작위화가 전부는 아니다"의 근거이지 "물리 추정이 병목"의 근거는 아님 |
| C5 | 실패의 약 89%는 던지기 전 (§4.4, Fig. 7) | Fig. 7 파이, 합 89.3% | ✅ 지지됨 |
| C6 | 던지기 전 실패의 원인은 "정책의 강건성 부족" (§4.4) | Fig. 7 정책별 파지 오류 38.5%; 무작위화 설정과 강건성의 인과는 실험하지 않음 | ⚠️ 해석. 원인을 분리하는 실험이 없음 |
| C7 | 물리 정보가 없는 것이 "physical blindness"의 원인 (초록, §4.4) | GT 입력 실험 한 개(p = 0.11). DynamicVLA는 변화 없음 | ⚠️ 가설로서 타당하나 근거가 약함. DynamicVLA의 0%는 강건성 문제일 수 있어 구분되지 않음 |
| C8 | 휴머노이드에서 "같은 실패 패턴" (§4.3, §5) | Table 3 성공률만 있음. 실패 모드 분해 없음 | ❌ 미검증 (정성적) |
| C9 | 실물에서도 같은 패턴, ForceVLA의 우위는 F/T 입력 때문 (§4.3) | Table 4: ForceVLA 51.3%, GR00T 10.7%. 같은 F/T 입력은 시뮬에서 차이를 만들지 못함 (p = 0.72). 실물은 고정 셋업, 큐브당 시연 300회 | ⚠️ 과장. 교란 있음 (환경·데이터 규모·물체 설계). 실물 성공률은 시뮬보다 5–16배 높아서(GR00T 2.0 → 10.7%, ForceVLA 3.3 → 51.3%) "같은 조건"이 아님 |

| C13 | PhyDEX는 질량·CoM·마찰 추정을 요구한다 (§1, §2.3) | 식 (2)에는 질량이 없음. 질량은 추종 오차와 슬립으로만 들어감. 마찰 무작위화는 ±20% (§3.2.2) | ⚠️ 주장의 범위가 넓음. "추종 오차 보정"으로 다시 쓰는 편이 정확 |
| C14 | 기존 벤치마크는 무작위화가 약해 비제로 결과를 숨긴다 (§4.4) | LIBERO, RoboSPA를 인용하지만, 같은 정책을 그 벤치마크에서 돌린 결과를 보이지 않음 | ⚠️ 비교가 간접적 |
| C15 | 21.24% 던지기 도달과 5.6% 던지기 성공 (§4.3) | Fig. 7과 Table 1 재구성 11.6%, 10.2% | ❌ 재구성되지 않음 |

## 3. 재현 가능성

- **공개된 것:** 논문 PDF(v1, 12쪽, CC BY 4.0). 프로젝트 페이지는 404입니다.
- **공개되지 않은 것:** 데이터셋, 생성 코드, 정책 체크포인트, 평가 스크립트, 롤아웃별 결과, 시드 수, 과제별 시연 수, 던지기 계획기 파라미터, 성공 판정 기준.
- **필요한 자원:** Isaac Sim (RTX급 NVIDIA GPU), GraspGen-X와 cuRobo (CUDA), 데이터 생성은 RTX A6000 8장으로 보고됨(§4.2), 미세조정은 A100 40 GB 16장(§4.2), 실물은 UR10e와 Robotiq 2F-85, 손목 F/T 센서, RealSense 두 대.
- **라이선스:** arXiv abs의 라이선스 링크는 `creativecommons.org/licenses/by/4.0/`(CC BY 4.0)이고, PDF XMP의 dc:rights도 같습니다. PDF 전문에 ©, All rights reserved, 회사 고지가 없습니다(`pdftotext` 전수 검색). **논문은 CC BY 4.0입니다.** 다만 그림 중 장면 렌더와 로고가 있어서 공개본에는 논문 그림을 넣지 않았습니다(`README.md`).

## 4. 구현 가능성 판정

**판정: 논문을 그대로 재현하는 것은 이 맥에서 불가능합니다. 축소판 구성 요소는 CPU로 만들 수 있습니다.**

| 구성 요소 | 이 맥(M4 Pro, 24 GiB, MPS, CUDA 없음)에서 | 필요 자원 | 노력 (추정, 측정 없음) |
|---|---|---|---|
| 데이터 생성 (Isaac Sim, GraspGen-X, cuRobo) | **불가** | RTX GPU, CUDA, Isaac Sim | — |
| VLA 미세조정 (GR00T N1.7, DynamicVLA, ForceVLA) | **불가** | A100급 여러 장 (논문 16장) | — |
| 시뮬 평가 (추론 + 시뮬) | **불가** | Isaac Sim과 데이터셋 | — |
| 실물 (UR10e, F/T, 큐브) | **불가** | 하드웨어 | — |
| 통계 재계산 (표·그림) | **가능, 완료** | numpy, scipy | 완료 |
| 던지기 계획식 점검 (식 1–2, 질량 의존성) | **가능, 대수로 완료** | 없음 | 완료 |
| 축소 던지기 계획기 (CPU, numpy, 운동학 + 탄도 + SLSQP) | 가능 (조건부) | numpy, scipy (설치 승인 필요) | 1–2주 (추정). 논문과 비교할 기준이 없음 |
| 자체 벤치마크 재구현 (MuJoCo 기반, 질량·마찰 무작위화) | 조건부 (MuJoCo CPU 가능, 학습은 GPU 필요) | MuJoCo, UR5e 모델, 던지기 계획기 | 3–6주 (추정) |

- **구현 노력의 핵심:** 벤치마크의 가치는 데이터 파이프라인과 평가 프로토콜에 있습니다. 둘 다 공개되지 않아서, 재구현하면 그 자체가 새 벤치마크가 됩니다. 저자 수치와 맞춘다는 것은 불가능합니다.
- **CPU 가능 여부 근거:** 식 (1)과 (2)의 계산, SLSQP 최적화, 탄도 비행은 CPU에서 충분합니다. 장면 렌더링과 GPU 물리가 필요한 부분은 CPU로 옮길 수 없습니다.
- **판정 근거:** 공식 데이터 생성에 필요한 Isaac Sim과 CUDA 패키지는 이 맥에서 실행되지 않습니다. 실물 과제는 하드웨어 없이 재현할 수 없습니다.

## 5. 검증되지 않은 것

- 롤아웃별 결과와 시드 수가 없어서 셀 평균의 불확실성을 정확히 알 수 없습니다.
- 정책 체크포인트 버전(GR00T N1.7 대 N1)과 하이퍼파라미터 차이.
- 시뮬 미세조정 데이터량(과제당 에피소드 수).
- 던지기 계획기의 수율과 시도 횟수.
- 성공 판정 기준(목적지 개구부 크기, 허용 오차).
- 휴머노이드와 실물의 실패 모드 분해.
