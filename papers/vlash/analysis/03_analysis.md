# 03. 수치 재계산과 해석: VLASH (v2)

원본 코드: `analysis/recompute.py`(→ `recompute_results.json`), `analysis/digitize_bars.py`(그림 막대 읽기, 결과 `fig_digitized.json`), `analysis/toy_attempts.py`, `analysis/toy_state_proxy.py`, `analysis/plot_figures.py`. 모두 CPU, numpy/scipy/matplotlib만 씁니다(각 1초 미만). 새로 설치한 것은 없습니다. 라벨 V1–V9는 이 문서의 검사, 토이는 토이 1·2입니다. 논문 수치는 v2 기준이고 표 번호는 논문의 로마자(표 I–V)를 씁니다.

## 1. 표 I (LIBERO): 평균, 정수 가능성, 유의성 (V1, V2)

**V1. 네 스위트 평균.** 표시된 네 값의 단순 평균과 표의 평균 열을 비교하면, π0.5 지연 1은 97.275(표 97.2), 지연 2는 97.150(표 97.1)로 **반올림하면 한 칸씩 다릅니다**. 나머지 6행은 일치합니다. 아래 정수 분석으로 이 불일치가 반올림 때문임이 설명됩니다.

**V2. 정수 가능성.** 스위트마다 N 에피소드이면 표시 값(소수 한 자리, 사사오입)은 100k/N이어야 합니다. 32개 값(표 I의 스위트별 값 전부)에 대해:

| N (스위트당) | 맞지 않는 값 개수 / 32 | 비고 |
|---|---|---|
| 50 | 31 | LIBERO의 과제당 초기 상태 50개를 스위트 하나로 오해한 경우 |
| 100 | 30 | |
| **480** | **0** | 가능한 N 중 가장 작음 (480, 520, 840, 857, ...) |
| 500 | **17** | 97.3, 96.7, 93.5, 97.5, 93.3, 91.9, 81.3, 92.9, 82.3 등. 500은 0.2% 단위라서 불가능 |
| 1000 | 0 | 0.1% 단위라 자명 |

N = 480이면 표시된 정수 개수로 계산한 평균이 표의 평균 열과 모든 8행에서 일치합니다(예: π0.5 지연 1은 (474+476+464+453)/1920 = 97.24 → 97.2). 즉 **표 I은 스위트당 500이 아니라 480(= 8 GPU × GPU당 과제당 6 에피소드 × 10 과제) 에피소드의 결과와 일치**합니다. 공식 평가 스크립트의 에피소드 분배가 정확히 480을 만듭니다(V9, `04` D10). 480은 "에피소드를 500으로 지정해도 실제로는 480"이라는 정적 해석과 맞는 우연이 아닌 증거로 읽습니다(단, 논문 본문이 에피소드 수를 쓰지 않아서 논문과 코드 사이의 직접 대조는 불가능합니다).

**유의성 (독립, 4 스위트 합산 N = 1,920, Fisher 정확 검정).**

| 비교 | p |
|---|---|
| π0.5 Sync 96.8 대 VLASH 지연 3 94.6 (−2.2 %p) | 0.0008 |
| π0.5 Sync 96.8 대 VLASH 지연 1 97.2 (+0.4 %p) | 0.57 |
| SmolVLA Sync 79.0 대 VLASH 지연 3 79.1 (+0.1 %p) | 0.97 |

따라서 본문의 "지연 1, 2에서 동기와 비슷하거나 더 좋음"은 +0.4, +0.3 %p가 잡음 안이라는 뜻이고, **지연 3의 −2.2 %p는 통계적으로 유의한 저하**입니다("약간 줄지만 경쟁력 있음", §V-A 2). 한 시드, 같은 평가 초기 상태 28개/과제(V9) 때문에 독립 가정이 낙관적입니다.

## 2. 표 II (반응 속도): 산술과 기준 의존 (V3)

모든 칸이 식으로 재현됩니다. Sync = 500 + 2L, RTC = 2L_RTC, VLASH = 2L, 속도 향상 11.78/9.50/8.74(대 Sync), 2.09/1.69/1.68(대 RTC), 표의 11.8/9.5/8.7/2.1/1.7/1.7과 일치(`matches_reported = true`).

**기준 의존.** 속도 향상 = (D + 2L)/(2L)이고 D = K/50 s입니다. RTX 5090(L = 29.4 ms)에서 동기 쪽 K를 바꾸면 5 → 2.7배, 10 → 4.4배, 25 → 9.5배, 50 → 18.0배(`own_latency_k.png`). 논문은 K = 25를 π0.5 설정에서 가져왔다고 하지만(§V-B 2 a), LIBERO(K = 5)와 실로봇(K = 24, 30 Hz)은 다른 K를 씁니다. 표 II의 "최대 11.8배"는 K = 25, H100, 영상 1장, 추론이 연속(back-to-back)이고 관측 촬영과 제어 루프 지연이 0이라는 가정의 값입니다. 또 L은 제어 스텝(20 ms)으로 1.2–1.6스텝(H100 1.16, 5090 1.47, 4090 1.61)입니다.

**L의 일관성.** 실로봇 실험은 "추론 지연 2스텝, 30 Hz"(§V-B 1)이고 부록 II는 노트북 RTX 5090에서 추론 주파수 15 Hz라고 합니다. 15 Hz는 L ≈ 66.7 ms = 30 Hz에서 2.0스텝으로 서로 맞지만, 표 II의 RTX 5090 L = 29.4 ms(영상 1장, 아마 데스크톱)와는 2.3배 다릅니다. 영상 수와 기기 차이로 설명 가능하나 논문은 이 차이를 말하지 않습니다.

## 3. 표 III (동적 과제) (V4)

- 핑퐁 VLASH 11/20 = 55%, Wilson 95% 구간 [34.2%, 74.2%]. 기준선 세 개는 모두 0/20(구간 상한 16.1%). Fisher 정확 검정 11/20 대 0/20: p = 1.5 × 10⁻⁴. **이 비교는 통계적으로 확실합니다.** 다만 서브마다 공 궤적이 다르고 q = 2 한 설정, 한 설치, 한 사람이라는 조건입니다.
- 두더지 평균 점수 3.2 / 8.6 / 11.0 / 28.8은 5라운드 평균이라 총합 16 / 43 / 55 / 144로 정수와 맞습니다. 라운드별 분산은 없습니다(n = 5). 3번 놓치면 종료이므로 점수는 생존 시간과 섞입니다.
- 기준선들은 q = 2로 고정(표 III 캡션, "모든 기준선에 가장 좋은 값"). 기준선마다 q를 튜닝했는지는 불명입니다.

## 4. 표 IV (파인튜닝 효율) (V5)

- 3.26배는 420.99/129.29 = 3.256으로 맞습니다.
- **토큰 수비와의 일치.** 기준선: 물리 배치 16 × 650토큰(영상·언어 약 600 + 행동 약 50) = 10,400. VLASH: 물리 배치 4 × (600 + 4분기 × 50) = 3,200. 비 = 3.25로 보고된 3.26배와 거의 같습니다. 즉 속도 향상은 **스텝당 처리하는 토큰이 3.25배 적은 것**의 반영입니다.
- **스텝당 고유 관측.** 4 GPU 합계로 기준선은 64개, VLASH는 16개입니다. 그래서 같은 스텝 수에서 VLASH가 더 늦게 수렴합니다(10K: 87.1 대 94.1).
- **시간 대비 정확도.** 시간은 스텝 × 스텝당 시간으로 계산: 기준선 10K 4,210 s(94.1), 20K 8,420 s(97.1), 30K 12,630 s(96.8). VLASH 10K 1,293 s(87.1), 20K 2,586 s(94.4), 30K 3,879 s(96.6). VLASH 30K는 기준선 20K보다 2.17배 빠르게 비슷한 정확도(96.6 대 97.1)에 도달하고, 같은 스텝 30K 대비는 3.26배입니다. "3.26배"는 스텝당이고 실질적 수렴 시간 이득은 약 2.2배입니다.
- 이 정확도는 LIBERO 한 시드이고 평균 점수 차 0.2–0.5 %p는 N = 1,920에서 잡음입니다.
- **설정 불일치.** 표 V와 §V-A 2는 배치 32, 표 IV는 전체 64입니다. 표 IV의 30K 결과는 표 I(배치 32)의 모델이 아닙니다.

## 5. 그림 7·8 (실로봇): 막대를 읽은 결과와 시도 수 (V6, 토이 1)

그림 7과 8은 수치 표가 없어서 래스터 이미지를 픽셀 단위로 읽었습니다(`analysis/digitize_bars.py`). 눈금 행(100%, 0%)을 격자선에서 읽고 막대 윗면과 오차 막대 끝(캡)을 잡았습니다. 해상도 1 px ≈ 0.12 %p, 막대 가장자리 두께 보정 후 오차는 약 ±0.3 %p입니다. 오차 막대는 이항 표준오차 SE = √(p(1−p)/N)이므로 **N = p(1−p)/SE²** 로 분모를 역산했습니다.

**읽는 법.** 본문의 서술 중 다음은 막대와 맞습니다. VLASH q = 2가 Sync q = 1 이상(Pick&Place 80.0 대 79.1, Sorting 53.1 대 46.9), Stacking VLASH q = 1.5가 Sync q = 1과 비슷(46.9 대 45.7). "VLASH가 모든 과제·q에서 가장 높다"는 π0.5 9개 설정에서 맞습니다(9/9, 부호 검정 p = 0.0039). 그러나:

1. **분모가 22–56으로 막대마다 다릅니다.** 성공 수를 S, 전체 시도 수를 N이라 하면 20 롤아웃·최대 3회 시도에서 N은 60 − 2S 이상 60 − S 이하여야 하는데, 36개 막대가 모두 이 범위에 들어갑니다(`own_fig7_denominators.png`). 예: VLASH Pick&Place q = 1은 20/24(83.3%)가 유일한 후보이고, Sync는 19/24(79.2%), Naive는 17/33 근처입니다. 즉 이 지표는 **실패가 많은 설정이 시도를 더 많이 가져 분모가 커지는** 시도 가중 비율입니다.
2. **통계 검정.** 시도 단위 두 비율 z 검정(군집 무시)에서 VLASH 대 Sync는 Stacking q = 1.5가 z = 2.45(p = 0.014)이고 나머지 8개는 |z| ≤ 1.32입니다. 최대 경쟁 기준선과의 비교는 9개 모두 |z| ≤ 1.5입니다(`V6_pi05_vlash_vs_best_baseline`). 같은 롤아웃의 시도들은 독립이 아니라서 실제 p는 이보다 큽니다. 9개 설정 방향 일치(부호 검정)는 설정 간 독립을 가정합니다(과제와 q는 같은 롤아웃 집합을 공유하지 않지만 같은 정책·학습을 공유합니다).
3. **그림 8 (GR00T N1.6, q = 1).** Pick&Place 44.9 / 39.9 / 50.0 / 54.9, Sorting 27.5 / 15.0 / 22.4 / 27.5, Stacking 11.9 / 11.9 / 11.9 / 16.6 (Sync / Naive / RTC / VLASH, SE 4–8 %p). **Sorting에서 VLASH는 Sync와 같고**(27.5 = 27.5), 본문 "모든 과제에서 가장 높다"(§V-B 1 b)는 동률을 포함해야 맞는 서술입니다. Stacking의 세 기준선은 막대 높이가 같습니다.
4. **같은 시행이 아니라는 점.** 방법마다 20 롤아웃이 독립으로 새로 수행되는지(초기 위치 공유 여부) 본문에 없습니다. 그림 7의 RTC는 Pick&Place q = 1과 q = 1.5에서 값이 같고(76.0 ± 8.6) Sync Sorting q = 1과 q = 1.5도 같습니다(46.9 ± 8.6). 20 롤아웃의 정수 개수 근처라 우연일 수 있으나, 같은 롤아웃 결과를 재사용했을 가능성도 배제하지 못합니다.

**토이 1 (시도 가중 지표의 성질).** 20 롤아웃, 최대 3회, 성공하면 종료하는 프로토콜을 롤아웃별 성공 확률이 Beta 분포(평균 q̄, 농도 1/4/1000)를 따르는 가정에서 2만 번 반복했습니다(`toy_attempts.py`, `own_toy_attempts.png`).

## 6. 상태 대용 오차 (토이 2, V6 보조)

공식 코드와 논문(§IV-A)은 절대 행동에서 **마지막 행동 a를 미래 상태 s로 대용**합니다. 로봇이 명령을 1차 지연(이득 α)으로 따라가는 가정에서 지연 4스텝 뒤 실제 상태와의 오차를 3가지로 비교했습니다(`toy_state_proxy.py`, `own_state_proxy.png`): 오래된 현재 상태, 마지막 명령(VLASH 코드), 명령열을 모델로 굴린 값.

| α (추종 이득) | 오래된 상태 오차 | 마지막 명령 오차 | 대용이 줄이는 오차 |
|---|---|---|---|
| 1.0 (즉시 추종) | 0.30 | 0.00 | 100% |
| 0.5 | 0.31 | 0.08 | 75% |
| 0.2 | 0.26 | 0.27 | −1% |
| 0.1 | 0.23 | 0.51 | −126% |

(오차는 궤적 표준편차로 정규화, 속도 배율 1배. 속도를 키우면 절대 오차는 커지지만 줄이는 비율은 거의 같음.) 추종 시간 상수(약 1/α)가 지연 Δ와 비슷해지면 마지막 명령이 오래된 상태보다 나쁩니다. 단, 학습도 같은 대용(행동을 상태로)을 쓰므로 정책이 이 불일치를 일부 흡수할 수 있습니다. 토이는 "추종 오차가 큰 팔에서 이 가정이 위험할 수 있다"는 경고로만 읽어야 하고, 실제 SO-101과 R1 Lite의 추종 특성은 측정하지 않았습니다. 논문은 이 오차를 보고하지 않습니다.

81.7 − 51.2 = 30.5 **퍼센트포인트**로 맞습니다. 상대 개선율은 59.6%이고 서론의 "up to 30.5% accuracy improvement"는 퍼센트포인트입니다. 그림 6은 점 값이 없어 곡선에서 읽을 때 지연 4의 VLASH ≈ 0.82, Naive ≈ 0.51로 본문과 일치합니다(눈 대중).

## 9. 공식 평가 스크립트의 에피소드 수 (V9, 정적 계산)

`sim/libero`의 `libero-eval-scripts/run.sh`는 `N_EPISODES=500`, `NUM_GPUS=8`입니다. `eval_libero.py`의 다중 GPU 분배는 `gpu_n_episodes // 과제 수(10)`를 과제당 에피소드로 씁니다(`04` D10). 500/8 = 62(+4 나머지)이므로 GPU당 62 또는 63 → 과제당 6 에피소드, 8 GPU 합 **스위트당 480**입니다. 초기 상태 인덱스는 GPU별로 (시작 % 50)부터 6개 연속이라 과제당 서로 다른 초기 상태가 28개(GPU 4개일 때 24개)입니다. 코드는 실행하지 않았고 위 산술만 같은 식으로 계산했습니다(`recompute.py` V9). 이 480이 표 I의 정수 분석(V2)이 가리키는 N과 일치합니다.
