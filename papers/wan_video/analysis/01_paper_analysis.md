# Wan: Open and Advanced Large-Scale Video Generative Models (arXiv:2503.20314) 논문 분석

*Wan: Open and Advanced Large-Scale Video Generative Models* (Wan Team, Alibaba Group; 기여자 명단 약 60명). arXiv cs.CV, 60쪽, 그림 33개. 분석 대상은 **arXiv v2 (2025-04-19 제출)** 하나입니다. v1(2025-03-26)과의 차이는 §6에 있습니다. 분석일 2026-11-22.

이 논문은 **학회 논문이 아니라 기술 보고서**입니다. 공개 저장소의 코드는 `04_code_verification.md`에서 대조했습니다.

## 0. 한눈에 보기

- **무엇:** 영상 생성 기반 모델 Wan 시리즈. 1.3B과 14B 두 크기의 T2V와 I2V가 핵심입니다. 그 위에 영상 편집(VACE 계열), 얼굴 개인화, 카메라 궤적 제어, 스트리밍 실시간 생성, 4단계 일관성 증류, 영상→오디오(V2A)를 얹었습니다.
- **구조:** 3D 인과적 VAE(Wan-VAE, 시간·공간 4×8×8 압축, 16채널, 보고 크기 127M) → 확산 트랜스포머(DiT, 패치 (1,2,2), 텍스트는 교차 어텐션, 시공간 전체 어텐션) → 텍스트 인코더 umT5. 학습 목표는 rectified flow의 속도 예측 MSE입니다.
- **데이터:** 사전학습은 수십억 장의 이미지와 영상을 4단계 정제와 클러스터 기반 점수화로 걸렀습니다(전체의 약 절반 제거). 후처리는 미적·움직임 품질로 고른 소량의 고품질 데이터입니다. 캡션 모델은 Qwen LLM을 쓰는 LLaVA형입니다.
- **핵심 수치:** VBench 총점 14B 86.22, 1.3B 83.96. 사람 평가 T2V 승률 우위(표 3)와 I2V 우위(표 7). 1.3B 모델은 VRAM 8.19 GB(본문과 저장소 README 모두).
- **공개 범위:** 추론 코드와 가중치(Apache-2.0). 학습 코드, 데이터 파이프라인, Wan-Bench 평가 코드는 저장소에 없습니다(`04`).

## 1. 문제 설정

비디오 생성에서 오픈 모델과 상용 모델(Sora, Kling, Hailuo, Runway, Veo 2 등)의 격차를 세 가지로 짚습니다. 성능 격차, 기본 T2V 중심의 제한된 기능, 계산 자원이 적은 팀에게 높은 비용입니다(§1). 논문은 DiT와 flow matching을 기반으로 이 셋을 함께 겨냥합니다. 스케일링(데이터·모델), 기능 확장(I2V, 편집, 개인화), 소형 모델(1.3B)의 효율을 내세웁니다.

## 2. 방법

### 2.1 Wan-VAE (§4.1)

- 3D 인과적 구조. 입력 영상 (1+T)×H×W×3을 (1+T/4)×H/8×W/8×16 잠재로 압축합니다. 첫 프레임은 시간 압축 없이 공간만 압축합니다(MagViT-v2 방식, §4.1.1).
- GroupNorm을 RMSNorm으로 바꿔 인과성을 유지하고, 특징 캐시를 쓸 수 있게 했습니다. 공간 업샘플 층의 입력 채널을 절반으로 줄여 추론 메모리를 33% 줄였다고 씁니다(§4.1.1).
- 크기는 127M(보고). 3단계 학습: 2D 영상 VAE를 학습 → 3D로 부풀림 → 고해상도 미세조정(L1, KL, LPIPS, 3D 판별기 GAN 손실, §4.1.2).
- 특징 캐시: 청크당 최대 4프레임, 커널 3의 인과 합성곱은 이전 두 프레임을 캐시에 둡니다(§4.1.3, 그림 6). 임의 길이 영상을 청크 단위로 인코딩·디코딩합니다.
- 재구성 평가: 720×720, 25프레임, 200개 영상의 PSNR 대 처리량(그림 7). Wan-VAE가 HunYuan Video보다 2.5배 빠르다고 씁니다(§4.1.4).

### 2.2 DiT와 텍스트 조건 (§4.2)

- 패치화: 3D 합성곱 커널 (1,2,2)로 토큰화하여 L = (1+T/4)×H/16×W/16 (§4.2.1).
- 블록: 자기 어텐션(시공간 전체) → 교차 어텐션(텍스트) → FFN. 시간 임베딩의 MLP(SiLU와 선형)는 모든 블록이 공유하고, 블록마다 6개 변조 파라미터의 편향을 따로 둡니다. 파라미터 약 25% 절감을 주장합니다(§4.2.1). 절감 수치의 근거는 제시되지 않습니다(§4.7.2 ablation은 손실 곡선만 보여 줌).
- 텍스트: umT5. 다국어 이해, 조합성, 수렴 속도에서 우위라고 씁니다. 512토큰(§4.2.1, 식 (3)). 소거 실험에서 Qwen2.5-7B, GLM-4-9B, Qwen-VL을 비교했습니다(§4.7.2, 표 6).

### 2.3 학습 목표와 단계 (§4.2.2–4.2.3)

- Rectified flow: x_t = t·x1 + (1−t)·x0, 목표 속도 v = x1 − x0, 손실 ‖u(x_t, c, t) − v‖². 시간 t는 logit-normal 분포에서 뽑는다고 씁니다(식 (1)–(3)).
- 단계: (i) 256px 텍스트→이미지 사전학습(14B 초기화). (ii) 이미지 256px와 5초 영상(192px, 16fps)의 공동학습. (iii) 480px로 해상도 확대. (iv) 720px로 확대. 사후학습은 480·720px에서 고품질 데이터로 같은 구조와 옵티마이저(AdamW, 가중치 감쇠 1e-3, 학습률 1e-4, FID와 CLIP 점수 정체 시 감소)로 진행합니다.
- 81프레임 1280×720은 5초(16fps)에 해당합니다(81 = 5×16+1). 따라서 시간 길이는 5초로 맞췄습니다.

### 2.4 대규모 학습과 추론 공학 (§4.3–4.4)

- 병렬화: DiT는 FSDP와 2D 컨텍스트 병렬(바깥은 Ring Attention, 안쪽은 Ulysses)을 씁니다. 예시는 GPU 128개, CP 16(Ulysses 8, Ring 2), FSDP 32, DP 4입니다(그림 11). 256K 토큰 16 GPU에서 통신 비용이 Ulysses의 10% 초과에서 1% 미만으로 줄었다고 씁니다(§4.3.2).
- 메모리: 100만 토큰 배치 1에서 활성 메모리가 8 TB를 넘는다고 씁니다. 활성 오프로딩을 주로 쓰고 그라디언트 체크포인트를 보조로 씁니다(§4.3.1, §4.3.3).
- 추론 가속(보고된 값, 각각 따로): 확산 캐시 1.62배(14B, "무손실" 주장), FP8 GEMM으로 DiT 모듈 1.13배, 8비트 FlashAttention으로 추가 1.27배(H20에서 MFU 95%). 저장소에는 캐시·FP8·8비트 어텐션 코드가 없습니다(`04`).

### 2.5 프롬프트 정렬과 벤치마크 (§4.5–4.6)

- 학습 캡션은 길이(짧음·중간·긴)와 문체(격식·구어·시적)가 다양하게 붙습니다. 추론 프롬프트는 LLM(Qwen2.5-Plus)으로 다시 씁니다(§4.5, 표 1).
- Wan-Bench: 3개 축(동적 품질, 이미지 품질, 지시 이행)과 14개 지표. 지표는 전통 검출기(RAFT 광흐름, YOLOv3 기반 아티팩트 탐지기, DINO 일관성)와 MLLM(Qwen2-VL)으로 측정합니다. 가중치는 5000개 넘는 쌍대 비교에서 나온 사람 선호와의 피어슨 상관으로 정한다고 씁니다(§4.6).

### 3.1 주장의 강도

- **강한 주장:** 오픈 모델 가운데 VBench 최상위권(14B 86.22). 이 값은 공개 리더보드 수치로 재계산이 가능합니다(`03` V1).
- **중간 주장:** 사람 평가 우위. 측정 단위와 표본 크기가 불명확합니다. 표 3과 7은 값이 음수가 될 수 있어 "승률"이 아니라 승-패 차이로 읽어야 합니다(`03` §2).
- **약한 주장:** 확산 캐시 "무손실", 2.5배 VAE 속도, 2D CP의 통신 비율, 25% 파라미터 절감, 시간 샘플링 효과. 근거 표가 없거나 그림에만 있습니다.
- **정성적 주장:** 대규모 움직임, 중국어·영어 글자, 영상 편집, 오디오. 예시 그림 위주이고 V2A는 정량 평가가 없습니다(§5.7.2).

## 4. 한계와 논문이 말하지 않는 것

- 본문 한계(§6): 큰 움직임에서 세부 보존이 약함, 14B 추론 약 30분(단일 GPU, 최적화 없음), 교육·의학 같은 전문 영역 부족.
- 논문이 말하지 않는 것: 사용한 샘플링 시프트(공식 저장소는 720p 5.0, 480p 3.0을 기본으로 씀), CFG 척도(저장소 기본 5.0, 1.3B는 6 권장), 평가에 쓴 샘플 수와 시드, 사람 평가자 간 일치도, 베이스라인 실제 이름(CN-TopA 등 익명), 학습 비용(GPU 시간), 사용한 데이터 규모(수치는 "수십억" 같은 개략 표현)입니다.
- 베이스라인이 익명이라 표 3, 7, 8의 상대 비교는 외부에서 재현할 수 없습니다. 상용 모델 점수는 표 4 VBench 리더보드 값으로 보입니다(날짜 기록 없음).

## 5. 주장과 증거의 틈 (요약)

1. **사람 평가의 측정 단위.** 표 3과 7에는 음수가 있어(표 7 Matching 대 CN-TopA −4.2%) 값은 승률이 아니라 승-패 차이입니다. 본문 캡션은 "비율"이라고 씁니다. 그리고 표 3 "All Rounds"는 5,710, 5,785 같은 합계인데 "700개 이상의 평가 과제"와 비교하면 과제당 몇 개인지 알 수 없습니다.
2. **일부 우위는 신뢰구간에서 0을 포함합니다.** 표 7의 Matching 대 CN-TopA는 신뢰구간이 0을 포함합니다(`03` §2). 본문 "모든 차원에서 우수"와 어긋납니다.
3. **Wan-Bench의 순위는 가중치에 달렸습니다.** 가중치 자체는 공개되지 않았습니다. 단순 평균으로 보면 Sora가 1위입니다(`03` §1).
4. **표 5의 스텝 표기.** 본문은 100k와 150k 스텝, 표는 10k와 15k 스텝입니다.
5. **그림 31 캡션과 본문의 FPS 불일치.** 한 장의 RTX 4090에서 본문은 8 FPS, 그림 캡션은 20 FPS(int8과 TensorRT)라고 씁니다.
6. **오디오(V2A) 평가는 정성적입니다.** MMAudio와의 비교 그림 몇 쌍뿐입니다.
7. **14B 메모리 주장.** §4.3.2는 텍스트 인코더가 20GB 넘는 GPU 메모리를 쓴다고 하지만, 저장소 설정은 umT5를 bf16으로 올립니다(약 10 GB 추정, `03` §4). 두 값이 맞으려면 FP32 로드가 필요합니다. 본문은 로드 정밀도를 밝히지 않았습니다.
