## 1. 주장 검증 (C1–C10)

판정 기준: **지지** = 그림·본문과 일치, **부분 지지** = 방향은 맞으나 크기나 정의가 다름, **확인 불가** = 원자료 없이는 판단 못함.

| 번호 | 주장 (위치) | 검증 근거 | 판정 |
|---|---|---|---|
| C1 | 가장 어려운 구간 속도 최대 3배 (초록, §I, §VII) | 그림 9 중앙값 비 228/66 = 3.45. 그림 4 이더넷 처리량 비 2.7. 다른 과제의 처리량 비 4–7은 성공률 증가가 섞여 속도 비가 아님 | **부분 지지**. 중앙값 기준 속도 3배는 맞고, 처리량 6배는 속도가 아님 |
| C2 | 나사 임계 구간 성공률 20%→65% (§I) | 그림 5 읽은 값 20%, 65%(±1%p). n=50 가정 Fisher p ≈ 1.5×10⁻⁵ | **지지**(n 가정) |
| C3 | 전체 과제 성공률 나사 +40%p, 지퍼 타이 +60%p (§VI-C Q1) | 그림 5 읽은 값 나사 약 7→47(+40), 지퍼 타이 약 27→87(+60) | **지지**. 전체 과제의 에피소드 수는 미보고 |
| C4 | 이더넷에서 평균 완료 스텝 2배 감소 (§VI-C Q2) | 그림 9 중앙값은 228→66 (3.45배). 평균은 그림에서 직접 확인 불가 | **확인 불가**. 본문의 "2배"와 그림 9 중앙값 비 3.45의 정의 차이 |
| C5 | RL 정책이 사람 원격조작보다 빠름 (초록, §VI-C Q4) | 그림 9: 원격조작 중앙값 146, RL 66. RL 에피소드 대부분이 원격조작 분포 아래 | **지지**(이더넷 한 과제). 원격조작 데이터의 정의(임계 구간 한정 여부)는 본문에 없음 |
| C6 | 제거 실험: 모든 구성 요소가 기여 (§VI-C Q3) | 그림 7 15분: RL 약 400, w/o Pass-Through 약 397, w/o RL token 약 157, w/o Chunk 약 128, w/o BC 0 | **지지**(BC, 청크, RL token). **부분 지지**(Pass-Through는 최종 성능에서 차이 없음, 학습 속도만 차이) |
| C7 | RL token 제거 시 처리량 50% 감소 (§VI-C Q3) | 그림 7: 5분 71%, 10분 60%, 15분 61% 감소. 50%라는 시점은 없음 | **부분 불일치**. 본문 50%는 그림의 어떤 시점과도 맞지 않음(읽기 오차 ±5%p 안에서 불일치) |
| C8 | 5분 데이터 후 기준 정책을 앞섬 (그림 7 캡션) | 그림 7: 5분 RL 약 262, 기준 약 148 | **지지** |
| C9 | 청크 행동이 Q-학습 지평을 줄임 (§IV-B, Q3) | 청크 C=10, 단일 스텝 기준선은 학습 실패(그림 7 w/o Chunk는 128로 정체). 원인은 본문 주장 | **지지**(경험적). 크레딧 할당 기전은 이 논문에서 직접 측정하지 않음 |
| C10 | 기준 행동 드롭아웃이 베끼기를 막음 (§IV-B) | 드롭아웃 단독 ablation 없음. "w/o Pass-Through"는 입력 제거로 다른 실험이며 드롭아웃 제거가 아님 | **확인 불가**. 드롭아웃 효과는 따로 검증되지 않음 |

## 3. 재현에 필요한데 본문·부록에 없는 값 (M1–M9)

| 번호 | 빠진 것 | 영향 |
|---|---|---|
| M1 | β(식 (5)) 값 | 묶음 강도. 제거 실험의 β=0만 명시. 가장 큰 영향 |
| M2 | 행동 가우시안 σ 값("small fixed") | 탐색 폭. 사람 개입 없이 RL이 되는 정도 |
| M3 | 워밍업 스텝 N_warm과 업데이트 비율 G의 정확한 정의 | 초기 개선 속도 |
| M4 | RL token 적응 스텝 과제별 값(부록 B는 2,000–10,000만 씀)과 VLA 미세조정 여부 α | 표현 품질 |
| M5 | 기준 VLA 미세조정 데이터 양과 스텝(과제별 1–10시간 시연) | 기준 정책 수준 |
| M6 | 독립 실행 수(시드), 오차막대 정의, 전체 과제의 에피소드 수 | 통계 검정 가능성 |
| M7 | 보상 판정 기준(사람 라벨)의 신뢰도와 평가자 수 | 성공률 해석 |
| M8 | 학습 컴퓨트(GPU 종류와 시간) | 비용 비교 |
| M9 | 행동 상자(action bound), 그리퍼 제어, 인식 입력 해상도 | 재현 세부 |

## 4. 구현 가능성 판정

**판정 (이 맥: Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음)**

- **알고리즘 구현: 가능 (조건부).** RL token 인코더-디코더(식 (1)–(2)), 청크 actor-critic(식 (3)–(5)), 기준 행동 드롭아웃, 워밍업과 혼합 버퍼는 PyTorch로 **약 350–500줄**, **3–5일(추정)**으로 옮길 수 있습니다. 세 부분은 맥에서 돌아갑니다. (a) 작은 트랜스포머 인코더-디코더는 MPS에서 학습 가능, (b) MLP actor-critic은 CPU로 충분, (c) 청크 버퍼와 손실은 CPU로 충분합니다.
- **조건부 1 (VLA):** 기반 VLA가 필요합니다. π0.6 가중치의 공개 여부는 확인하지 못했습니다(미확인). 공개 가중치가 없으면 다른 공개 VLA나 작은 임의 트랜스포머로 바꿔야 하며, 이는 논문의 방법이 아니라 대체 실험입니다.
- **조건부 2 (로봇):** 실로봇 RL 없이는 논문 결과(성공률, 처리량, 사람 대비 속도)를 재현할 수 없습니다. 이 맥에서 할 수 있는 것은 시뮬레이션 또는 toy 수준의 검증뿐입니다.
- **불가:** 실로봇 4과제 재현, 원 VLA(π0.6) 미세조정, 14차원 양팔 로봇에서 실험, GPU 학습 시간 수 시간 이상의 재현. 이유는 실로봇 하드웨어, 가중치 접근, CUDA 부재입니다.
- **판정 요약:** 방법을 **구현하는 것은 가능**하고, 결과를 **재현하는 것은 불가**합니다. 방법의 핵심 주장(묶음과 저차원 readout의 효과)은 toy로 검증할 수 있습니다(`03` §5).

**노력 추정 (추정, 근거 없는 감)**
| 작업 | 시간 |
|---|---|
| 손실과 인코더-디코더 구현 | 1–1.5일 |
| actor-critic, 버퍼, 묶음 손실, 드롭아웃 | 1–1.5일 |
| toy 환경에서 학습 확인과 디버깅 | 1일 |
| 작은 공개 VLA 또는 대체 트랜스포머에 연결 | 1–2일 |
