# 04. 주장 검증과 구현 가능성 (공식 코드 없음)

## 1. 대조 범위

공식 코드, 프로젝트 페이지, 체크포인트를 찾지 못했습니다(2026-11-24 확인: arXiv 초록 페이지, Hugging Face 논문 페이지에 연결된 모델·데이터 없음, GitHub 저장소 검색 "Mem-World"와 "W-VMem" 결과 없음, 웹 검색 두 번). 그래서 논문 ↔ 코드 대조 대신 **주장 C1–C10**을 표·그림 수치의 재계산(`03`)과 대조해 판정합니다. 보충으로, W-VMem의 출발점인 VMem의 공개 코드(MIT)를 **정적으로만** 읽어 "새로 한 것"의 범위를 가렸습니다(§3, U1–U7). 이 코드는 실행, 설치, 가져오기를 하지 않았고 게시본에도 넣지 않습니다.

판정 기준: **지지**(수치 재계산과 일관되고 설계가 주장을 뒷받침), **부분 지지**(방향은 맞으나 크기나 범위에 조건), **근거 부족**(주장을 가를 실험이 본문에 없음), **확인 불가**(보충 자료나 코드가 필요).

## 3. VMem 공개 코드와의 정적 대조 (U1–U7)

대상: https://github.com/runjiali-rl/vmem (MIT, 커밋 `39291e4`, 2025-07-25, 별 452). `modeling/pipeline.py`와 `configs/inference/inference.yaml`을 읽었습니다. 목적은 Mem-World가 VMem에 더한 것과 이미 있는 것을 가르는 것입니다(Mem-World 코드가 없으므로 논문 서술과 비교).

| 번호 | VMem 공개 코드 | Mem-World 논문 서술 | 판단 |
|---|---|---|---|
| U1 | 서펠마다 타임스텝 목록(`surfel_to_timestep`)을 유지하고, 렌더링된 서펠이 가리키는 타임스텝에 `cos / (1 + depth)`를 더해 타임스텝 가중치를 구함 | 식 2의 기하항 ⟨n_s, v̄_w⟩/(1 + d_s)와 서펠 시간 집합 t_k | 구조가 같음. "VMem은 시간 정보가 없다"기보다 VMem도 타임스텝 투표를 함. 새로운 것은 타임스텝별 따로 렌더링과 감쇠 |
| U2 | 렌더링은 `render_surfels_to_image`가 z-버퍼로 **전체 서펠을 한꺼번에** 그림. 한 서펠이 다른 타임스텝 서펠에 가리면 투표를 못 받음 | 타임스텝별로 따로 렌더링해 가림과 시간 신호를 분리 (§3.2) | 논문의 차이점이 코드에서 확인되는 지점. 효과 절제는 없음 |
| U3 | 목표 카메라 자세들의 평균(`average_camera_pose`)에서 한 번 렌더링 | 평균 미래 손목 자세 c̄_w | 같은 아이디어 |
| U4 | 서펠 병합: 반경 기반 위치 임계, 법선 내적 임계(코드 기본 0.7, 설정 파일 0.6)로 기존 서펠에 현재 타임스텝을 추가 | "merged timestep"과 갱신 | 같은 구조. Mem-World의 임계값은 미기재 |
| U5 | NMS 있음(`use_non_maximum_suppression: true`). 기준은 카메라 자세 간 측지 거리이고 임계값은 기존 프레임 쌍 거리의 중앙값에서 시작해 1.2배씩 완화 | NMS를 쓴다고만 서술 | 기준 미기재 (K6) |
| U6 | 최종 선택: 서펠 투표로 후보를 만든 뒤 **목표 자세와의 측지 거리 순**으로 정렬해 NMS | 점수 기반 상위 K 타임스텝 + NMS (알고리즘 1 줄 6) | 선택 단계가 다름. VMem은 자세 거리를 최종 정렬에 쓰고 Mem-World는 점수를 씀 |
| U7 | 조작 물체 표지, 시간 감쇠, 손목 전용 갱신, 순기구학 기반 자세, 세계모델 학습 없음 (카메라 자세는 점 지도 추정기가 같이 추정) | 모두 Mem-World의 새 요소 | 새로움은 이 다섯 가지에 있고, 논문은 이들의 개별 절제를 보이지 않음 (C4) |

추가로 VMem은 점 지도 추정기에서 카메라 자세까지 같이 얻는데, Mem-World는 순기구학 자세를 쓰고 점 지도는 DA3로 만들므로 **두 좌표계의 스케일 맞춤**이 필요합니다. 논문은 "보정된 제3자 카메라를 기준 프레임으로 점군을 추정한다"고만 쓰고 DA3의 깊이 스케일(상대 대 미터)과 생성된 손목 프레임의 스케일 일관성을 어떻게 다루는지 말하지 않습니다.

## 4. 구현 가능성 판정 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**논문 수치의 재현은 불가능합니다. W-VMem 검색 모듈 단독 구현과 작은 장면에서의 검증은 가능하고, 검색 토이는 이미 끝냈습니다.**

| 작업 | 판정 | 필요 자원과 이유 |
|---|---|---|
| 표 1·2 재현 (영상 지표) | 불가 | 코드, 34개 궤적 목록, 체크포인트가 없음. 학습은 8 H100 약 2일(약 384 H100 시간), 기반 Ctrl-World는 SVD 약 1.5B와 DROID가 필요 |
| 그림 4 재현 (정책 평가) | 불가 | Franka + 2자유도 그리퍼 실로봇, 과제당 50 에피소드 수집(250개), π0·π0.5 후학습(4 H100), 실로봇 평가 |
| 그림 5 재현 (정책 개선) | 불가 | 위 + 과제당 200개 롤아웃 생성, 사람 성공 판정, π0.5 미세 조정, 실로봇 재평가 |
| Ctrl-World 추론 시연에 W-VMem 연결 | 불가 | W-VMem 문맥으로 학습한 시간 어텐션 가중치가 공개되지 않음. 기성 Ctrl-World 가중치는 이 문맥으로 학습되지 않아 연결해도 효과를 볼 수 없음 |
| **W-VMem 검색 모듈 단독 구현** (점군 + 손목 자세 열 → 타임스텝 점수 → NMS 상위 K) | **가능** | numpy 또는 torch(MPS). 점 지도는 사전 계산한 깊이 지도나 합성 장면으로 대체. 공개 VMem(MIT)의 렌더링·병합·투표 구조를 참고하면 신규 코드는 타임스텝별 렌더링, 식 2 점수, 감쇠, 표지 정도. 추정 3–5일 (측정 전) |
| DA3로 점 지도를 뽑아 모듈에 연결 | 조건부 | DA3 가중치 다운로드와 설치 승인이 필요하고 MPS 속도는 미측정. |
| 작은 영상 세계모델에 기억을 붙여 학습·평가 | 조건부 | 소규모(저해상도, 합성·소형 데이터) 축소판은 MPS에서 가능. 논문 수치와 직접 비교는 불가. 추정 2–4주 (측정 전) |
| 검색 규칙 토이 (구현·완료) | 완료 | `analysis/toy_retrieval.py`, numpy, 수 초 |

**노력 추정 (모두 측정 전 추정).** 모듈 단독 3–5일, 합성 장면 평가 harness 포함 약 1–2주, 소형 세계모델 축소판 2–4주. 논문 규모의 재현은 GPU와 로봇이 필요해 이 맥에서는 추정하지 않습니다.

**재구현을 막는 누락된 설정.** 본문만으로는 다음 값을 알 수 없습니다: K(상위 개수), NMS의 기준과 임계값, 타임스텝 점수의 합산 방식, 렌더링 해상도·서펠 반경·병합 임계, DA3 변형과 입력 해상도, 깊이 스케일 정렬, 손목 손실 가중치, 학습률과 총 스텝, 행동 청크 길이와 프레임율, VLM 프롬프트, 34개 평가 궤적 목록, 정책 평가의 시행 수. 보충 자료(PDF에 없음)나 공개 코드가 필요합니다.

## 5. 실행하지 않은 것과 이유

- VMem 저장소: 얕은 clone을 정적으로 읽기만 했고 실행, 설치, 가져오기를 하지 않았습니다.
- 가중치, DROID, Ctrl-World 체크포인트: 받지 않았습니다(크기와 필요성만 확인).
- API 호출, 패키지 설치, 새 가상환경: 하지 않았습니다. 재계산과 토이는 이미 있는 numpy, scipy, matplotlib만 썼습니다.
