# 01. 논문 분석: Render the Robot, Generate the World (Doppel)

- 논문: *Render the Robot, Generate the World: One Video World Model Across Embodiments*
- arXiv: 2611.24925 (cs.RO), 제출 2026-11-18, **v1만 있음**(arXiv abs 기준)
- 저자: Yash Jangir (JHU), Karan Mirakhor, Renos Zabounidis, Yonatan Bisk (CMU), Muhammad Zubair Irshad, Sergey Zakharov (TRI), Homanga Bharadhwaj (JHU)
- 방법명: **Doppel**. 프로젝트 페이지 https://doppelwm.github.io/ , 코드 https://github.com/DoppelWM/Doppel
- 분석 기준: `paper/paper.pdf`(v1, 45쪽, 39.6 MB)의 텍스트. 인용은 논문의 절·표·식 번호로 한다.

## 1. 한 문단 요약

로봇 영상 world model은 보통 행동 벡터(관절 목표)만 입력받아 로봇이 화면에서 어떻게 움직이는지까지 함께 학습한다. Doppel은 **미래 관절 궤적으로 로봇을 카메라 시점에서 미리 렌더링한 영상**을 같은 입력에 더해 준다(§4). 그러면 모델은 로봇 몸의 움직임을 배우는 부담을 덜고 물체가 어떻게 반응하는지에 집중할 수 있다고 주장한다. 기반은 Wan 2.1 I2V 14B(§3, §4)이고, 렌더 조건은 토큰마다 flow timestep 임베딩에 더해지는 방식(식 7)으로 들어간다. 카메라 외부 파라미터가 없는 데이터셋은 미분 가능 렌더러로 카메라 포즈를 복원한다(§4.1). 로봇 팔 3종(DROID, RoboMind, Bridge)에 학습한 Doppel-3와, 양팔 로봇·휴머노이드·사람 손/몸을 더한 8개 데이터셋 Doppel-8을 비교한다(§5–6).

## 2. 문제 설정 (§3)

- 입력: 첫 프레임 o0, 계획된 구성 궤적 a^e_{1:T-1}, 로봇 URDF U_e (식 1). 모델은 세 입력을 받아 미래 영상을 예측한다. 파라미터 θ는 임베디먼트 간에 공유된다.
- 학습 목표: 잠재 공간 rectified flow(식 2–3). 목표 속도 ε − z를 쓰고, 첫 잠재 프레임은 손실에서 뺀다(M0 = 0). 텍스트는 항상 빈 문자열이다.
- 로봇 렌더링: Dr. Robot(Liu et al., CoRL 2024, [49])의 3D Gaussian 로봇 모델. 순기구학으로 관절 변환을 구하고, 자세 조건 외형 모델을 거쳐 카메라 내·외부 파라미터로 래스터화한다(식 4–5).

## 3. 방법 (§4)

### 3.1 카메라 보정 전처리 (§4.1, 부록 A.9)

- 렌더러는 고정하고, 6-자유도 카메라-로봇 변환만 최적화한다. 손실은 RGB, 광류(RAFT로 교체), DINOv2 특징을 쓴다. 여러 초기 포즈를 병렬로 최적화하고 coarse 탐색으로 시작점을 고른다.
- 카메라 하나당 한 번 보정하고, 그 카메라의 모든 데모에 재사용한다.
- 부록 A.9 수치: 45,345 데모(Bridge 14,824 / RoboMind 17,588 / ABC 12,933). ABC는 13,518개 영상 중 12,933개(95.7%)가 정합 검사를 통과했다. Bridge는 56개, RoboMind는 49개 세션 포즈를 얻었다. 12,933/13,518 = 95.7%로 맞다.

### 3.2 렌더 액션 표현 (§4.2, 부록 A.4)

- 렌더 영상을 같은 고정 causal VAE로 잠재 공간에 넣고, 채널별 시공간 평균을 뺀다(식 9). 평균 뺀 뒤 3층 Conv3D 인코더, 2층 자기 주의 블록, 학습된 3D 위치 임베딩을 거친다. 그 결과가 DiT 토큰 격자에 맞는 2025개 토큰이다(부록 A.4).
- 행동은 프레임마다 159차원으로 0 패딩한 뒤 공유 MLP로 인코딩하고 시간 위치 임베딩을 더한다(식 11). 임베디먼트마다 데이터셋별 통계로 정규화한다.
- 렌더 토큰을 질의로, 행동 토큰을 키/값으로 하는 교차 주의 2층으로 융합한다(식 12–13). 결과는 Wan 은닉 차원 5120으로 투영된다.
- 토큰별 시간 변조: 토큰 j의 조건 벡터 g_j를 flow timestep 임베딩 e(s)에 더한다(식 7). 같은 임베딩이 40개 블록 전체와 출력 정규화에서 shift, scale, gate를 만든다. 백본의 attention과 FFN 구조는 바꾸지 않는다.
- 어댑터 파라미터는 약 30.5M(부록 A.4), 행동 전용 어댑터(EgoWM 방식)는 4.2M(부록 A.5). 학습 시 조건 드롭아웃은 확률 0.1이다.

### 3.3 다중 임베디먼트 공유

- 어댑터와 백본의 모든 학습 파라미터를 공유하고, 임베디먼트 토큰이나 로봇별 헤드는 두지 않는다(§4.2 마지막 문단).
- 저자들은 "모델은 어떤 몸을 보는지 알려받지 않는다"고 쓴다. 그러나 렌더링 자체가 몸 종류를 드러내므로, 완전히 라벨이 없다고 보기는 어렵다. 이 점은 §6 해석에서 다시 본다.

## 4. 실험 설정 (§5, 표 1, 부록 A.3, A.6–A.8)

- 학습 데이터(표 1, 표 4): Droid(Franka) 83,511 클립, Bridge(WidowX) 61,935, RoboMind(UR5e + 2F-85) 74,005 — 3개 로봇 합계 219,451 클립(43,914 에피소드). 8개 데이터셋 합계 803,602 클립, 593.1 h.
- 추가 5개: ABC(양팔 YAM), T-Rex(Vega-1 + Sharpa 손), Ego-Exo4D(사람 몸, SMPL-H), GigaHands(사람 손, MANO), OakInk2(사람 상체, SMPL-X).
- 평가 분할: 검증은 같은 환경의 보지 않은 궤적, 테스트는 환경 이동(Droid는 새 실험실, Bridge는 새 주방, RoboMind는 새 물체·과제). 데이터셋마다 200 클립(연속 창 100 + 전체 구간 100).
- 지표: 전체 프레임 PSNR, SSIM, LPIPS, SCS(SAM 2 마스크 IoU). 영역별 PSNR(로봇 팔, 움직이는 물체)과 움직임 기준 0.25(부록 A.8).
- 학습 규모(§5, 부록 표 7–9): Doppel-3는 배치 256, 49.5k 스텝, 32 GPU(4노드). Doppel-8은 배치 256, 189k 스텝. 단일 데이터셋 전문가와 배치 64 비교 모델은 8 GPU.
- 기준선: 행동 전용(EgoWM 방식, 같은 Wan 2.1 백본, 어댑터 4.2M), OSCAR(골격 조건, 데이터셋마다 미세조정, 백본과 학습 방식이 달라 시스템 수준 비교로만 본다).

- Droid 검증 +0.52 ± 0.03, 테스트 +0.21 ± 0.03. RoboMind 검증 +0.24 ± 0.04, 테스트 +0.22 ± 0.04. Bridge 검증 −0.01 ± 0.06, 테스트 −0.24 ± 0.05.
- 본문의 "네 개 세트에서 개선"(§6)은 표 2와 맞다.

### 5.4 학습 효율 (§6, 표 16–17, 그림 9)
- 배치 64 공유 행동 전용 모델 3.356M 드로우 대 Doppel-3(배치 64) 1.216M 드로우: 63.8% 적은 드로우. 6개 세트 PSNR·SCS 평균에서 Doppel이 앞선다.
- 단일 데이터셋 전문가 대비 같은 드로우 수에서도 Doppel-3가 높다(그림 7, 표 14–15).

### 5.5 물체 움직임 (§6, 그림 6, 표 13)
- Bridge 테스트에서 움직이는 물체 PSNR: 행동 전용 21.50 → Doppel-8 24.85 dB. SCS_obj: 0.778 → 0.831.
- 같은 세트에서 Doppel-3(0.843)와 단일 Doppel(0.838)의 SCS_obj는 Doppel-8보다 높다. 주장은 행동 전용 기준으로만 맞다.

### 5.6 장기 롤아웃 (§6, 그림 8)
- 3.2 s 창을 25.6 s까지 연결한다(창 8개). 실제 프레임은 첫 프레임뿐이다. 코드 `doppel/rollout.py`의 1 + 16n 프레임 구조와 맞다(04 §3).

## 6. 해석과 한계 (저자 주장과 독립 판단)

1. **초록의 1.00/1.20 dB는 비교 조건이 다르다.** Doppel-8은 8개 데이터셋으로 학습했고, 기준선은 단일 데이터셋 전문가다. 데이터 양과 렌더 입력이 섞여 있어, "렌더 입력의 효과"로 읽으면 과대평가된다. 같은 데이터끼리 비교한 효과(단일 Doppel 대 행동 전용)는 평균 0.81 dB(검증)와 0.85 dB(테스트)다(03 §1).
2. **"임베디먼트 라벨 없음"의 의미.** 렌더링이 몸의 모양과 위치를 이미 담고 있으므로, 모델은 몸 종류를 입력으로부터 알 수 있다. 공유의 장점은 "라벨 없음"보다 "렌더 공간의 공통성"에서 나온다.
3. **다중 임베디먼트 이득의 크기.** Doppel-8의 추가 이득은 Droid 검증에서 크고(+0.52), Bridge 검증에서는 0이다. Bridge 테스트는 −0.24 dB로 떨어진다. 저자들은 Bridge 과적합을 의심하고, Bridge 테스트 PSNR이 약 10 pass에서 최고였다고 보고한다(§6). 이 해석은 학습 곡선(표 11)과 맞지만, 원인을 확인하는 실험은 없다.
4. **단일 실행.** 본문과 표는 학습 실행을 여러 시드로 반복했다는 말이 없다. 표 16–17의 Bridge 검증 여유는 +0.03 dB, +0.002 SCS다. 이 차이는 시드 차이보다 작을 수 있다.
5. **평가 세트의 크기.** 데이터셋당 200 클립, 같은 데이터셋의 클립은 같은 에피소드에서 나온다(§A.3). 신뢰구간이 클립 단위인지 에피소드 단위인지 밝히지 않았다(부록 A.10.3은 에피소드 단위 부트스트랩을 말하지만 표에는 SE만 있다).
6. **저자 한계 진술(§7).** URDF와 카메라 정확도가 필요하다. 카메라가 자주 바뀌는 경우는 제한이다. 보는 카메라는 궤적마다 하나다. 본 적 없는 임베디먼트와 다중 시점 예측은 다루지 않았다. 구성 궤적을 조건으로 쓰므로 저수준 제어 명령의 불확실성은 다루지 않았다.
7. **재현 세부 누락.** 본문은 Doppel 추론 샘플러(스텝 수, 가이던스)를 쓰지 않았다. 부록 표 5는 OSCAR에만 샘플러를 적었다. 코드의 기본값(50 Euler, 가이던스 1.0)은 04 D1에서 다룬다.
