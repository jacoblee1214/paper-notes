## 1. 문제와 기여

**문제.** 휴머노이드가 물체를 옮기고 올라타고 밀며 걷는 긴 동작은 접촉 모드 순서가 조합적으로 늘어납니다. 대부분의 최신 방법은 사람 동작을 리타게팅하거나 원격조종 데이터를 쓰기 때문에, 데이터가 없는 상황이나 로봇 고유 능력을 쓰는 동작에는 한계가 있다는 것이 서론의 동기입니다(§1, 2.1).

**제안.** 접촉 계획(contact plan)을 짧은 파이썬 프로그램으로 쓰게 하고, LLM(Claude Opus 4.7, §3.2)이 그 프로그램을 변이시키는 진화 트리 탐색을 돌립니다. 각 후보는 (i) 순차 기구학 실현 가능성 검사(sequential IK), (ii) 통과하면 접촉 명시적 궤적 최적화(TO)로 평가합니다. 평가 결과가 점수와 텍스트 피드백으로 LLM에 돌아갑니다(그림 2, 식 5–6). 찾은 궤적을 RL 추종 정책으로 학습해 실제 휴머노이드에 영 샷으로 올립니다(§4.3).

**기여(서론).** (1) LLM 진화 탐색 + 수치와 구조화된 언어 피드백을 주는 TO 결합, (2) 비반복 방식(단일 호출)보다 낫다는 분석과 한 번의 탐색에서 다양한 해를 얻는다는 주장, (3) 리타게팅과 원격조종 없이 긴 loco-manipulation을 실로봇에 올린 "첫 사례"라는 주장.

## 2. 방법

### 2.1 접촉 명시적 모션 계획 (§3.1)

- 접촉 인터페이스 집합 I(말단장치, 발바닥, 움직이는 물체). 접촉 상태는 쌍 (a, b), b는 단방향 접촉 대상 또는 ∅. 접촉 모드 c는 모든 a에 대한 할당이고 대칭 조건 (a,b) ∈ c ⇒ (b,a) ∈ c를 둡니다(식 1).
- 모드 c의 실현 가능 다양체 M(c) = {(x, ẋ, u) | 동역학 = 0, 접촉 ≤ 0, 충돌 ≤ 0, 한계 ≤ 0}(식 2). 추가 충돌은 "의도하지 않은 접촉"이므로 접촉 모드 이탈이라고 봅니다.
- 고정된 모드열 C = (c₀..c_{K−1})에 대해 상태, 제어, 모드 지속 시간 T̄ₖ를 푸는 연속 최적화(식 3): 최소화 ∫φ + φ_T + w_T·T, 제약 x(0) = x_init, x(T) ∈ X_goal, T̄_min ≤ T̄ₖ ≤ T̄_max, 각 모드에서 M(cₖ).
- 순차 기구학 최적화(KSO)와 TO 모두 직접 다중 사격(direct multiple shooting)으로 이산화하고, 시간 구조를 활용하는 솔버(acados [26], HIPPO [27])로 풉니다. KSO는 동역학을 무시하는 빠른 기하 필터입니다(§3.1).

### 2.2 LLM 진화 탐색 (§3.2, 부록 A)

- **장면 S와 목표 G.** S는 물체의 이름, 위치, 크기를 적은 텍스트입니다. G는 이산 성분(원하는 접촉)과 연속 성분(목표 자세)을 가집니다(§3.2).
- **트리 노드.** 노드 n = (프로그램 pₙ, 점수 Fₙ, 텍스트 피드백 τₙ, 자손 수 oₙ). 루트는 초기 접촉 상태입니다(§3.2.1).
- **확장.** ShinkaEvolve [22]의 섬(island) 모형을 씁니다(§3.2.2, 부록 A.2): 섬을 균등 추출하고, 섬 안에서 wᵢ = σ(λ(Fᵢ − αₖ)/mₖ)·1/(1+oᵢ)로 부모를 추출(αₖ는 중앙값, mₖ는 MAD와 ε 중 큰 값). 영감 노드(상위 + 무작위), 코사인 유사도 η 초과 시 LLM 새로움 판정으로 기각, 변이 유형은 diff 0.6, full 0.3, crossover 0.1.
- **변이.** 프롬프트에는 장면, 목표, 부모 프로그램·점수·피드백, 유효 인터페이스 목록, 예시 접촉 패턴이 들어갑니다(§3.2.3, 부록 A.1). LLM은 이산 접촉 계획만 바꾸고 접촉 사이의 연속 운동은 KSO와 TO가 복원합니다(식 4).
- **점수와 피드백(§3.2.4).** KSO를 먼저 돌립니다. 실현 가능하면 TO를 풀고 비용 J = Σᵢ‖r(xᵢ, uᵢ, c_{s(i)})‖₁ + w_j Σᵢ‖q⃛ᵢ‖²(식 5)를 계산합니다. 텍스트 피드백은 KSO 가능 여부와 잔차·저크 비용입니다. KSO가 실패하면 TO를 돌리지 않고 **점수 0**을 주며, 가장 긴 실현 가능한 접두부 K̂를 찾아(식 6) 처음으로 실패한 모드(또는 전이)를 텍스트로 돌려줍니다.

**논문이 정의하지 않은 것.** 비용 J에서 점수 Fₙ으로 가는 변환, λ, w_j, ε, η, 섬 수, 이주 설정, 탐색 예산(노드 수), 실행 횟수(시드), LLM 온도, TO 반복 한도와 수렴 기준. 공식 코드와 맞춘 값은 `04`에 있습니다.

## 3. 실험

### 3.1 평가 설정 (§4)

여덟 과제(부록 B.1, 그림 4): (1) Banana, (2) Box Stacking, (3) Climb Table w/ Box, (4) Long-Dist. Pick & Place, (5) Move Through Clutter, (6) Parkour Pick & Place 1, (7) Parkour Pick & Place 2, (8) Under-Table Pick & Place. 세 조건을 비교합니다: SC(단일 LLM 호출), MD w/o TF(텍스트 피드백 없는 MotionDisco), MD(전체). 텍스트 피드백(TF)은 "어느 노드에서 기구학적으로 실현 불가능해지는가"를 알리는 것입니다(§4.1, 식 6).

### 3.3 다양성(§4.2, 그림 3)과 실로봇(§4.3, 부록 B.2)

- 그림 3은 Parkour Pick & Place 2에서 MD가 찾은 모든 유효 계획의 손과 발 xyz 궤적을 겹쳐 그리고, 서로 다른 두 해의 스냅샷을 보입니다. 다양성의 정량 지표(서로 다른 전략의 수, 거리 등)는 없습니다.
- 실로봇: DeepMimic식 보상 + 도메인 무작위화로 추종 정책을 학습해 영 샷으로 실행합니다. "모든 시도한 과제에서 여러 번 연속 성공"이라고 쓰지만 시행 수, 성공률, 정책 학습 설정(환경 수, 보상 항, 학습 시간), 로봇 기종은 본문에 없습니다. 부록 B.2의 그림 5–9는 다섯 과제(Under-Table, Move Through Clutter, Parkour 2, Long-Distance, Climb Table w/ Box)의 스냅샷입니다. Banana, Box Stacking, Parkour 1은 실로봇 그림이 없습니다. 로봇이 Unitree G1이라는 정보는 부록 A.1의 프롬프트 문구("one G1 step covers ~0.4 m")에만 있습니다.

## 4. 저자가 쓴 한계 (§6)

접촉 모델이 직사각형 패치의 단방향 고착 접촉뿐이고 물체는 상자 모양의 강체입니다. 장면은 알려져 있다고 가정하고 인지는 없습니다. 시뮬레이션 준비된 장면 생성(SimRecon 등 [29–31])과의 결합을 향후 과제로 둡니다.

## 5. 주장과 근거의 간격 (요약, 세부는 `03`)

1. **"첫 사례"** 주장(초록, 기여 3)은 비교 대상 범위를 본문이 정의하지 않습니다. 관련 연구 절(§2)은 리타게팅과 LLM 계획 연구를 소개하지만 "탐색으로 찾은 접촉 계획을 실로봇에 올린" 선행 사례의 부재를 조사한 서술은 없습니다. 이 분석에서는 검증하지 않았습니다.
2. **비교는 과제당 한 번의 결과**로 보이고(표에 시드, 구간 없음), 상자 쌓기를 뺀 일곱 과제에서 MD의 비용 이득은 w/o TF 대비 2.4–5.5%입니다(`03` V2).
3. **Valid %의 분모와 탐색 예산이 본문에 없습니다.** 공식 저장소의 과제별 노드 예산(11–40)을 분모로 놓으면 표의 16칸 중 13칸이 정수 비율로 재현됩니다(`03` V1).
4. **실로봇 결과는 정성적**입니다. 성공률, 시행 수, 정책 설정이 없고 세 과제는 실로봇 그림이 없습니다.
5. **Parkour Pick & Place 2의 목표 서술이 세 곳에서 다릅니다**(B.1은 바닥에 내려놓기, 그림 7 캡션은 먼 테이블에 놓기, A.1 프롬프트는 높은 테이블에 놓기). 그림 3의 장면은 두 단 단상 위입니다. `03` V7.
