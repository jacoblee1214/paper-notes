# 04. 주장 검증 (C1–C18)과 구현 가능성

공식 코드 저장소를 찾지 못해(2026-11-26, `02` §2) 논문과 코드의 대조(D 항목) 대신 표, 그림, 본문의 주장을 재계산으로 점검합니다. 근거 번호 V와 K는 `03`의 검사입니다. 판정 말: 지지(재계산과 맞음) / 방향만(방향은 맞지만 차이를 구분할 수 없음) / 부분(일부만 맞음) / 확인 불가(근거 자료가 없음) / 저자 확인 필요(서로 맞지 않는 값이 있음).

## 1. 확인한 공개 자료

- **코드.** 논문, arXiv 주석, 프로젝트 페이지에 코드 링크가 없어 공식 코드를 확인하지 못했습니다(2026-11-26 기준). 프로젝트 페이지 저장소는 정적 HTML입니다.
- **데이터.** Hugging Face 조직 AtomBench에 시연 데이터셋 두 개(Franka, Cobot Magic)가 있고 카드의 라이선스는 Apache-2.0입니다. 목록 메타데이터로 과제 15개 × 에피소드 100개 × 플랫폼 2 = 3,000 에피소드를 확인했습니다(parquet 합계 약 86 MB와 152 MB, 영상 mp4 약 5.5 GB와 8.4 GB). 데이터는 받지 않았습니다.
- **평가 롤아웃.** 초록은 "evaluation rollout data"도 공개한다고 쓰는데 이 위치는 확인하지 못했습니다(2026-11-26). 프로젝트 페이지에는 성공, 실패 롤아웃 영상 목록이 있습니다.

## 3. 가장 중요한 세 가지

1. **조합 결과를 읽을 때 AS와 SR을 직접 빼면 안 됩니다.** AS는 부분 점수의 평균이고 SR은 이진 값입니다. 독립 곱 기준선을 두면 Pi0.5의 간격은 65 %p에서 약 11 %p로 줄고, 다른 모델은 간격이 거의 사라집니다(C7).
2. **그림 3과 표 1이 모델 세 개에서 맞지 않습니다.** 원자별 막대는 이 논문의 핵심 진단 그림인데 모델 다섯 중 두 개만 표 1과 맞고(C18), 본문의 교차 평균 숫자도 그림 라벨과 다릅니다(C4). 시드별 결과가 공개되면 닫힐 수 있습니다.
3. **조합 과제에 새 값이 섞여 있습니다.** 합성 실패와 값 일반화 실패를 가르는 통제(원자 값을 훈련에서 모두 본 조합만 평가)가 있으면 논문의 주장이 더 직접적으로 시험됩니다(C14).

## 4. 구현 가능성 판정 (이 맥: Apple M4 Pro 24 GiB, MPS, CUDA 없음)

**논문의 실험(5개 정책의 미세조정과 2,700회 실로봇 평가)은 이 맥에서 구현할 수 없습니다. 지표 계산과 통계 재분석은 구현하고 끝냈고, "원자와 조합" 구조를 재는 작은 시뮬레이션은 이 맥에서 구현할 수 있습니다. 공식 코드가 없어서 논문 구현 대조는 하지 못했습니다.**

| 표 재계산, Wilson, Fisher, CFS 대입, 곱 기준선, TG 부호 검정 | 구현 가능, 완료 | `analysis/recompute.py` (수 초) |
