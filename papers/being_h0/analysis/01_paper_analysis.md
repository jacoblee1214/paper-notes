## 1. 한 문단 요약

Being-H0는 사람 손 영상에서 만든 **3D 손 모션(MANO)** 을 언어 모델이 읽는 토큰으로 바꿔, 비전-언어-행동(VLA) 모델을 사전학습한 뒤 로봇 손 과제에 붙이는 방법입니다. 핵심은 세 단계입니다. (1) InternVL3 백본에 손 모션 토큰(부분별 그룹 잔차 양자화, 1초에 128 토큰)을 넣어 사람 영상으로 사전학습합니다. (2) 여러 카메라의 영상을 약한 원근(weak-perspective) 좌표계로 맞추고, 시점 분포를 균형 맞춥니다. (3) 로봇 과제에서는 학습 가능한 쿼리와 MLP로 관절 행동을 회귀합니다(L1). 학습 데이터 UniHand는 11개 출처(모캡, VR, 의사 주석)에서 444.1K 궤적, 1,155 h, 표 1 기준 166.5M 명령 샘플입니다. 실로봇(Franka Research 3 + Inspire 손, 과제 7개, 과제당 20회)에서 Being-H0의 합계 성공률은 104/140, 기준선 InternVL3는 67/140, GR00T N1.5는 89/140입니다.

## 2. 문제 설정과 방법

### 2.1 문제 설정과 세 단계 (§1, §3.1)

- 목표는 사람 영상으로 손 동작을 명시적으로 배우는 VLA를 만들고, 이를 로봇 손에 옮기는 것입니다(§1, p.3). 기존 암묵 학습(대비 학습 [21], 마스크 오토인코더 [22], 잠재 행동 [23])과 달리 **손 모션을 직접 예측 대상으로 씁니다**(§1, p.3).
- 세 단계 "물리 명령 튜닝(physical instruction tuning)"은 (1) 사람 영상 사전학습, (2) 물리 공간 정렬, (3) 후학습입니다(§3.1, p.5).
- 학습 목적은 다음 토큰 예측입니다. 식 (1)은 입력 X_Q(영상, 명령)에서 목표 토큰 X_A(텍스트와 모션)의 로그우도 합입니다(p.5).

### 2.2 손 모션 토큰화 (§4.1.2, 식 2–6, p.7–9)

- 입력은 MANO 파라미터 m = {θ, r_rot, τ, β}입니다. 다섯 가지 표현(MANO-D51, D99, D109, D114, D162)을 비교하고 **MANO-D162**(6D 회전, 관절 위치 보조 포함)를 택합니다(p.8, 표 5, 표 6). 손목은 축각, 손가락은 6D 회전이 더 낫다는 관찰이 있습니다(p.8).
- 양자화는 **부분별 그룹 잔차 양자화(GRQ-VAE)** 입니다. 채널을 n = 2 그룹으로 나누고, 각 그룹에 L = 8층 잔차 양자화를 씁니다. 코드북은 부분마다 K = 4096, d = 512입니다. 손목과 손가락은 **별도 토크나이저**입니다(p.9).
- 손목 손실 L_wrist는 부분 토크나이저에서 뺍니다(p.9). 재구성 손실은 L = L_recon + λ1 L_commit + λ2 L_wrist, λ1 = 0.02, λ2 = 1.0입니다(식 6, p.9).
- 시간 해상도: 15 FPS에서 1초 창, 다운샘플 α = 4 → 1초에 ⌈15/4⌉ = 4 단계, 2 부분 × 2 그룹 × 8층 × 4 = **128 토큰**(p.10, §6.1.1 p.17).

### 2.3 멀티모달 통합과 학습 (§4.1.3–4.1.4, 식 7–10, p.10–11)

- 시각 토큰은 InternViT-300M과 2층 MLP 투영, 동적 타일링(448×448 기준, 썸네일 포함, 픽셀 셔플 0.5)입니다(p.7, p.10).
- 모션 토큰 어휘를 K개 추가하고 <MOT>, </MOT> 경계 토큰으로 블록을 만듭니다(p.7).
- 사전학습에서 **어휘 수준 로짓 마스크**(모션 라벨 위치에서 비모션 로짓을 확률 P로 −∞, 식 8, P = 50%)와 **토큰 수준 손실 필터**(손실 백분위 [15%, 95%] 밖 제외, 식 9–10)를 씁니다(p.11, §6.1.1).
- 학습 기준 좌표: 1초 창을 첫 프레임 좌표로 바꾸고, 학습 때는 10초 창에서 기준 프레임을 무작위로 고릅니다(p.10).
- 모델 크기 1B, 8B, 14B (InternVL3 기반). 학습은 UniHand-2.5M 부분집합, A800 80GB 32장, AdamW lr 1e-5, 배치 128, ViT 어댑터와 LLM 함께 미세조정(§6.1.1, p.17).

### 2.4 디코딩 모드 (§4.1.5, p.11)

- **자유 형식**: 제약 없음. 모션 블록이 깨질 수 있습니다.
- **블록 형식**: <MOT> 사이에서 모션 토큰만 뽑습니다. 표 3과 표 6이 쓰는 모드입니다.
- **소프트 형식**: 각 블록을 생성한 뒤 예측과 **정답(GT)** MANO의 평균을 내고 다시 양자화합니다. 표 4(장기 생성)가 쓰는 모드입니다. 정답을 매 블록에 섞으므로 자유 롤아웃 오차가 아닙니다(§4.1.5, `04` §2의 D7).

### 2.5 물리 공간 정렬 (§4.2, 식 11–14, p.11–13)

- **약한 원근 정렬**(§4.2.1): 원본 내부 파라미터 K에서 목표 K′로 스케일 s = f′/f와 평행 이동 Δ = c′ − s·c를 써서 픽셀을 옮깁니다(식 11–12). 어안은 FoV 90°로 정규화합니다(p.12).
- **시점 분포 균형**(§4.2.2): **깊이 스케일** τ′_z = λ_s τ_z와 영상 1/λ_s 재조정(식 13), **광축 회전** R_z(φ)(식 14). 손 자세 분포를 넓히되 카메라 시점은 바꾸지 않는다고 주장합니다(p.12–13).
- 분석 메모: 깊이 스케일 λ와 영상 1/λ 조정을 함께 쓰면 손목 위치와 손의 겉보기 크기가 같은 비율로 줄어 2D–3D 대응이 유지됩니다(핀홀 모델, 주점 고정). 그래서 식 13의 주장은 수식상 맞습니다. 다만 **물체는 함께 바뀌지 않으므로** 접촉 관계는 보존되지 않습니다(`03` §4 C17).
- §4.2.3은 깊이 센서, 촉각, 음향을 향후 과제로만 씁니다(p.13).

### 2.6 UniHand 데이터 (§5, 표 1, p.14–16)

- 11개 출처를 세 종류로 나눕니다. 모캡(ARCTIC, FPHA, H2O, HOI4D, HOT3D, OakInk2, TACO, DexYCB), VR 기록(EgoDex, Apple Vision Pro), 의사 주석(Taste-Rob, 손 자세 추정 기반)입니다(§5.1, p.14).
- 손 자세 표준화(§5.2.1): MANO 직접 추출, 3D 관절에서 최적화, 없으면 HaMeR로 추정. 좌우 뒤바뀜을 불연속으로 찾아 보정합니다(p.15).
- 주석(§5.2.2): 10초 이하 구간 단위와 1초 겹침 창 단위, Gemini-2.5-Flash-Lite로 지시문과 캡션을 만듭니다(p.15).
- 명령 생성(§5.2.3): 세 과제(명령에 따른 생성, 모션 번역, 문맥 모션 예측), 과제마다 약 20 템플릿, Gemini-2.5-Pro로 변형, 규칙으로 채움(p.16).
- 표 1의 합계(검산은 `03` §1.5): 명령 166.5M, 궤적 444.1K, 1,155 h, 프레임 **130M(표 기재)**. 본문은 "over 150M"(서론 p.3), "over 165 million"(§5.2.3 p.16), "over 1,100 hours"(§5.1 p.14), "over 1,000 hours"(§3.2 p.6)로 씁니다.

### 2.7 로봇 전이 (§4.3, 식 15, p.13)

- 기반: 제안 백본을 인코더로 쓰고, 고유감각 p_t를 MLP f_p로 임베딩합니다. 행동 쿼리 {q_i}를 붙이고 MLP 헤드 f_r이 행동 청크를 냅니다. 목적은 L1 손실(식 15)입니다.
- 행동 차원과 청크 길이는 본문에 없습니다. 공식 코드는 행동 차원 13, 청크 16을 씁니다(`04` D12, D15).

### 3.3 절제 (§6.4, 표 5–6, 그림 8–9, p.21–23)

- 토크나이저(표 5): MANO-D162 + Part-Level은 재구성 MPJPE 0.573 cm, PA-MPJPE 0.129 cm입니다. MPJPE만 보면 MANO-D114 + Part-Level(0.523 cm)이 더 낫습니다. 본문도 "약간 높다"고 씁니다.
- 생성(표 6, 8B 기준): 토크나이저 변형, 데이터 절제(번역, 문맥, 균형). 가장 큰 하락은 **균형 제거**입니다(tail MPJPE 9.02 → 12.13, FID 13.4 → 16.3). 번역 제거는 PA-MPJPE, M2T, FID를 떨어뜨리고, 문맥 제거는 대부분을 떨어뜨립니다(§6.4.2).
- 그림 9: 학습 샘플 수 0.5M–2.5M에 따른 정규화 성능. 8B만 있고 수치 표가 없습니다.
- 단일 학습 실행이고 씨앗 반복과 신뢰구간이 없습니다. 표 6의 차이가 학습 잡음보다 큰지 판단할 수 없습니다(`03` §2).

## 5. 재현에 필요한 정보와 빠진 정보

- **학습 세부는 많이 빠져 있습니다.** 학습 스텝 수, 에폭, 워밍업, 체크포인트 선택, 토크나이저 학습 반복 수가 없습니다. 로봇 과제의 행동 청크 길이, 정규화, 손 행동 차원 매핑도 없습니다(§4.3).
- **데이터 접근.** UniHand 전체 공개 여부는 본문에 없습니다. 공식 저장소는 후학습 데이터 하나(h0_post_train_db_2508, 1.17 GB)만 제공합니다. 나머지 원천(EgoDex, TACO 등)은 각자 받아야 하고, 저장소는 테스트 세트 배포를 하지 않는다고 적습니다.
- **평가 코드.** 표 2–6을 재생산하는 스크립트와 TMR 모델이 없습니다(`04` §3).
- **인용 문제.** §5.1의 "pseudo-annotated … off-the-shelf hand motion predictors [152]"는 참고문헌 [152]가 HD-EPIC 데이터셋이라 맞지 않습니다(p.14). §6.4.2는 "Section 4.1.5"를 가리키지만 데이터 균형은 §4.2.2입니다(p.22).
- **한계 절이 없습니다.** 독립된 한계 절은 없고 §4.2.3과 결론의 향후 과제가 그 역할을 합니다. 객체 모델링(6D 포즈) 미포함을 §2에서 밝힙니다(p.4).

## 6. 이 논문 읽기에서 남는 질문

1. 손 모션 토큰이 로봇 행동을 실제로 돕는지, 아니면 같은 백본의 사전학습 효과인지 나눌 실험이 없습니다. 기준선 InternVL3는 같은 백본이지만 로봇 데이터 전처리가 다를 수 있습니다.
2. 소프트 모드(표 4)는 정답 블록을 섞으므로 장기 생성 능력의 상한을 보여 줄 뿐입니다. 자유 롤아웃의 장기 오차는 나오지 않습니다.
3. 데이터 균형은 손 자세만 바꾸고 물체를 옮기지 않아, 접촉이 있는 장면에서 손과 물체의 관계가 학습 분포와 다를 수 있습니다.
4. 같은 저자들의 후속 연구(Being-H0.5, Being-H0.7)가 README 인용에 있습니다. 이 분석 범위에 넣지 않았습니다(`02` §2).
