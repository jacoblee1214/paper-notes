# 03. 수치 재계산, 일관성 검사, 주장 판정

## 0. 재계산 방법과 한계

- 입력은 논문 본문·부록 표(표 1, 2, 3, 5)를 옮긴 값입니다. **그림 4(실로봇)와 그림 5(절제)는 수치 표가 없어서** PDF의 래스터 막대 끝을 눈금선 기준으로 읽었습니다(픽셀 측정, 오차 약 ±0.5 %p). 실로봇 막대는 5 %p 단위(20회 시행)에 정확히 떨어졌고 절제 막대는 1 %p 단위로 읽었습니다.
- 시행 수는 본문 §4.1 기준입니다: 동적 과제 과제당 40회, 실로봇 과제당 20회, LIBERO 과제당 20회. LIBERO 스위트의 과제 수는 본문에 없어 스위트당 10개(공개 벤치마크 구성)로 가정해 N = 200으로 둡니다. 표 1의 모든 값이 0.5 %p 단위라는 점이 이 가정과 맞습니다(N = 100이면 .5가 불가능).
- 두 방법의 시행은 같은 시드·같은 초기 상태로 짝지어졌다고 쓰여 있지만 쌍별 결과가 없어, 검정은 **비쌍체 Fisher 정확 검정**(양측)과 **Wilson 95% 구간**을 씁니다. 다중 비교는 Holm 보정을 표시했습니다.
- 스크립트: `analysis/recompute.py`(numpy, scipy, 수 초) → `recompute_results.json`, 장난감 `analysis/toy_feedback_param.py` → `toy_feedback_param_results.json`, 그래프 `analysis/plot_figures.py`.
- 검사 번호: **V**는 재계산, **K**는 논문 내부 일관성, **C**는 주장 판정입니다. 코드 차이는 `04`의 D입니다.

## 1. 표 1 (시뮬레이션)

### V1. 정수 실현 가능성
N = 200(LIBERO), 40(동적)에서 표 1의 36개 값이 모두 정수 성공 수로 나타납니다. 불일치는 없습니다.

### V2. 평균 재계산
동적 세 과제 평균: GR00T (47.5 + 20 + 15)/3 = **27.5**, VLA-Feedback (80 + 75 + 100)/3 = **85.0**으로 초록과 일치합니다. 미학습 네 과제 평균은 GR00T 15.6, VLA-Feedback 68.1입니다. LIBERO 두 스위트 평균은 GR00T 94.75, VLA-Feedback 93.75이고, 그림 5a의 정적 막대 94와 맞습니다.

Pick 2D에서 최강 기준선은 FiS-VLA(67.5, 27/40)이고 VLA-Feedback 75(30/40)와 **p = 0.62로 구분되지 않습니다.** Drop Ball은 FiS-VLA 80 대 100(p = 0.0053), Ball Color는 FiS-VLA 60 대 97.5(p = 5e-5)로 확실합니다. 나머지는 최강 기준선이 GR00T 또는 OpenVLA이고, 1D·Ball Speed에서는 모든 기준선이 0%입니다. 즉 "모든 기준선보다 낫다"는 8열 중 2D 이동 과제에서만 FiS-VLA와 구분되지 않습니다.

## 2. 실로봇 (그림 4)

### V5. 막대 읽기와 평균 불일치
막대를 눈금 기준으로 읽은 값입니다.

| 과제 | GR00T | VLA-Feedback | Fisher p (20회) |
|---|---|---|---|
| Pick bread (정적) | 80 (16/20) | 90 (18/20) | 0.66 |
| Drop lemon | 45 (9/20) | 65 (13/20) | 0.34 |
| Catch can | 35 (7/20) | 65 (13/20) | 0.11 |
| 평균 막대 / 보고 평균 | **51.0** | 73.0 | — |
| 세 값의 산술 평균 | **53.3** | 73.3 | — |

- VLA-Feedback의 평균 73은 세 값의 평균 73.3과 맞습니다. **GR00T의 51은 세 값의 평균 53.3과 맞지 않습니다**(차 −2.3 %p). 20회 시행의 과제 성공률은 5 %p 단위라서 세 과제 평균은 (합)/3이고, 평균 51이 되려면 합이 153이어야 하는데 5의 배수 합은 150(→ 50.0) 또는 155(→ 51.7)뿐입니다. 평균 51은 이 시행 설계로는 나올 수 없는 값입니다(`K2`).
- 개선폭은 보고된 51 → 73(+22 %p)이 아니라 막대 값 기준 **53.3 → 73.3(+20.0 %p)** 입니다.
- 과제별로는 어느 하나도 p < 0.05가 아닙니다(최소 Catch can p = 0.11). 동적 두 과제 합산 16/40 대 26/40은 p = 0.043, 세 과제 합산 32/60 대 44/60은 p = 0.037이지만 **보정하지 않은 검정**이고 과제 간 짝지음이 없습니다. 정적 Pick bread의 +10 %p(p = 0.66)도 같은 방향이지만 구분되지 않습니다. 결론: 방향은 일관(3/3)하나 과제당 20회로는 개별 확정이 어렵습니다. 20회 시행의 최소 검출 차이는 p = 0.5 근방에서 약 44 %p, 40회는 약 31 %p입니다(양측 α = 0.05, 검정력 0.8, 정규 근사, `V11`).

## 3. 표 3 (속도 강건성)

### V6. 값과 표 1 대조
Drop Ball 속도별 GR00T / VLA-Feedback (n = 40): 원래 6/40 → 40/40, +10% 2/40 → 37/40, +20% 2/40 → 34/40, +30% 0/40 → 23/40, +40% 0/40 → 2/40. 모든 값이 정수로 가능합니다. +40%에서는 두 방법이 구분되지 않습니다(0/40 대 2/40, p = 0.49). 성능은 +10% 92.5, +20% 85, +30% 57.5, +40% 5로 **+30%와 +40% 사이에서 급락**합니다. "중간 정도의 속도 증가에는 강건"이라는 서술(부록 A.1)은 +20%까지는 맞고, +30%부터는 절반으로 떨어집니다.

- **K3. 표 1과 표 3의 같은 값.** 표 1 `Drop Ball Speed*`는 0.066 m/s(= +32%, 부록 A.1)이고 값은 GR00T 0, VLA-Feedback 57.5입니다. 표 3 `+30%`(= 0.065 m/s)도 0 / 57.5입니다. 속도가 0.001 m/s 다른 두 설정이 같은 시행 결과를 가진다는 뜻이므로, 같은 평가를 다르게 표기했을 가능성이 있습니다(확정할 수 없음). 표 3 `원래` 줄(15 / 100)은 표 1 `Drop Ball`과 같은 값으로 의도된 대응입니다.

## 4. 반응 지연 (표 2, 표 5)

### V7. 표 2와 표 5 재계산
- `T̄_react = T_update + (R/2)Δt`를 Δt = 100 ms(10 Hz)로 계산하면 OpenVLA 210 ms, GR00T 880 ms, FiS-VLA 90 ms, **VLA-Feedback 52 ms**입니다. 표의 기호식과 일치합니다. VLA-Feedback는 GR00T의 약 1/17, FiS-VLA의 약 1/1.7, OpenVLA의 약 1/4입니다.
- 표 5의 합계: 시뮬레이션 0.03 + 0.06 + 1.95 = 2.04 ms, 하드웨어 62.00 + 4.00 + 0.06 + 1.95 + 2.00 + 1.00 = 71.01 ms로 모두 보고값과 같습니다. 계획기 주파수 1/(16 × 0.1 s) = 0.625 Hz도 맞습니다.
- **식 (9)에는 감지·통신 지연이 들어 있지 않습니다.** 표 5의 하드웨어 합에서 피드백 추론을 뺀 69 ms(카메라 노출·전달 62, IPC 4 등)가 방법과 무관하게 모든 방법에 더해진다고 가정하면 VLA-Feedback의 실제 기대 반응 지연은 약 52 + 69 = **121 ms**이고 식 (9)의 52 ms와 2.3배 다릅니다. 방법 간 순위는 바뀌지 않지만 "2 ms 피드백"이 주는 인상과 달리 지연의 대부분은 대기 시간 50 ms와 감지 69 ms입니다. FiS-VLA와의 차이(90 대 52 ms)는 모듈 시간 차 38 ms에서 오며, 하드웨어 감지를 더하면 비율이 1.7배에서 약 1.3배로 줄어듭니다.

### V8. 낡은 정도(변위)로 환산
목표 속도 × 기대 반응 지연으로 청크가 낡아서 생기는 평균 어긋남을 계산합니다(식 (9)의 값, 감지 지연 제외).

| 과제 (속도) | OpenVLA | GR00T | FiS-VLA | VLA-Feedback | GR00T 청크 끝 |
|---|---|---|---|---|---|
| Pick 1D (0.04 m/s) | 0.84 cm | 3.52 cm | 0.36 cm | 0.21 cm | 6.72 cm |
| Drop Ball (0.05 m/s) | 1.05 cm | 4.40 cm | 0.45 cm | 0.26 cm | 8.40 cm |

공식 평가 코드의 공 넣기 성공 판정은 컵 중심에서 x, y 각각 3 cm 이내입니다(`04` D9). GR00T의 평균 낡음 4.4 cm와 청크 끝 8.4 cm는 이 허용치보다 크고, 피드백의 0.26 cm는 훨씬 작아서 Drop Ball의 15% 대 100%(표 1)가 크기 면에서 그럴듯합니다. 반면 Pick 1D의 평균 낡음 3.5 cm는 들어올리기 위한 파지 허용 범위와의 관계를 알 수 없어 47.5%의 설명은 약합니다.

## 5. 절제 (그림 5, 막대 읽기)

### V9. 절제 값
그림 5a(동적 / 정적): Δa 63 / 92, No Obs 53 / 91, Transformer→MLP 77 / 91, VLA-Feedback 85 / 94. 그림 5b: 1:2 62 / 90, 1:4 67 / 90, 1:8 67 / 92, 1:16 85 / 94. 풀 모델의 동적 85와 정적 94는 표 1 평균(85.0, 93.75)과 일치하고 그림 5a와 5b의 풀 모델 막대도 같습니다.

- **No Obs는 GR00T(27.5)보다 25.5 %p 높습니다**(풀 모델 이득 57.5 %p의 44%). 실시간 관측의 순수 기여는 No Obs 대비 32 %p입니다. 본문은 "관측을 빼면 크게 떨어진다 → 개선이 실시간 시각 피드백에 달렸다"고 쓰지만, 관측 없는 학습 보정기도 GR00T보다 크게 높다는 점이 같이 보고되어야 합니다. 원인 후보: 추가 학습(피드백 모듈 50,000 스텝, `04` D7), 계획기의 체계적 편향 보정, 계획기 노이즈 제거 효과(최종 행동 회귀는 평균으로 수렴). 장난감에서 관측 없는 보정기도 오차를 줄이는 것이 확인됩니다(§8).
- 피드백 비율 1:2는 62로 GR00T 대비 +34.5 %p(풀 이득의 60%)입니다. 1:2, 1:4, 1:8이 62–67로 평평하다가 1:16에서 85로 뜁니다. 비율 표기 "1:2"가 "계획기 1회당 피드백 2회"인지 "2행동마다 계획기 재실행"인지 본문에 정의가 없어 해석이 둘로 갈립니다(`K9`).
- 그림 5의 시행 수와 오차 막대가 없어 Δa 63 대 85, MLP 77 대 85의 차이가 유의한지는 알 수 없습니다(동적 세 과제를 120회로 풀링해 짐작하면 Δa 63 대 85는 p ≈ 0.0002, MLP 77 대 85는 p ≈ 0.14이고, 막대를 읽은 값이라 참고용입니다).

## 6. 구조 수치

### V10. 학습 가능 파라미터
부록 A.2의 구성(d = 256, 선형 투영 두 개, 사전 정규화 디코더 한 층 헤드 4·FFN 512, 256 → 7 머리, 스칼라 게이트)으로 직접 세면, 입력 차원 1024에서 **1,186,312개(1.19M)** 로 보고값 1.19M과 일치합니다. 입력 차원이 1536이면 1.317M이라 맞지 않으므로, 피드백 모듈에 들어가는 계획기 특징은 1024차원(GR00T 행동 머리의 `hidden_size`)임이 확인됩니다. 동결 ResNet-18(fc 제외 11.18M)을 더하면 12.36M으로 "약 12.4M"과 일치합니다. 시각 토큰 "64개"는 ResNet-18의 224×224 출력 7×7 = 49개 위치를 8×8로 평균 풀링해 만든 값입니다(`04` D5).

### V11. 시행 수와 검출력
양측 α = 0.05, 검정력 0.8의 정규 근사로 p ≈ 0.5 근방의 최소 검출 차이는 시행 20회 약 44 %p, 40회 약 31 %p, 200회 약 14 %p입니다. 실로봇 Catch can의 35 → 65 %p를 80% 검정력으로 확정하려면 팔당 약 43회, Drop lemon 45 → 65는 약 96회가 필요합니다. 정적 Pick bread 80 → 90은 약 199회입니다.

## 8. 장난감: 속도 갱신은 행동 잔차와 같은 함수인가 (`toy_feedback_param.py`)

식 (6)의 `a^k = a^{k-1} + Δk·v̂`와 식 (8)의 최종 행동 L2 손실에서 머리가 선형이면, `v̂ = Fw`로 쓴 최적해가 `Δk`에 의존하지 않습니다(`Δk·F·w`의 `w`를 `1/Δk`배로 바꾸면 같은 함수). 1차원 낡은 청크 설정(목표가 8스텝 뒤 속도 `{0, −0.04}`로 전환, 계획기는 청크 시작 위치를 청크 전체의 목표로 냄, 피드백은 현재 위치 관측 사용)에서 CPU 수 초로 확인했습니다.

| 조건 | 시험 MSE |
|---|---|
| 계획기만(낡은 청크) | 610 × 10⁻⁶ |
| 피드백, 관측 사용, 닫힌형 (Δk = 0.25, 0.5, 1.0 모두) | **3.95 × 10⁻⁶** (세 값 동일) |
| 피드백, 관측 없음, 닫힌형 (Δk 무관) | 233 × 10⁻⁶ |
| 피드백, 관측 사용, Adam 300 스텝 | Δk = 0.25: 59.7, Δk = 0.5: 25.8, Δk = 1.0: 19.0 (× 10⁻⁶, 시드 5 평균) |

- **최적해는 Δk와 무관**합니다. 따라서 그림 5a의 "속도 갱신(85) 대 Δa(63)" 차이는 파라미터화 자체가 아니라 **입력 특징, 머리의 비선형성, 학습 설정**(Δa 변형이 계획기 특징 대신 행동만 받았는지 등, 논문에 기술 없음)에서 와야 합니다.
- 같은 Adam 설정에서는 Δk가 작을수록 오히려 **느립니다**(가중치가 `1/Δk`배 커야 같은 함수). 속도 갱신이 잔차보다 최적화가 쉽다는 설명은 이 장난감에서는 반대입니다.
- 관측 없는 보정기도 계획기 오차의 62%를 줄입니다(체계적 표류를 학습). 그래서 그림 5a의 No Obs 이득(+25.5 %p)은 이상한 값이 아닙니다. 다만 그 이득은 실시간 관측의 효과가 아니라 **보정기가 학습된다는 효과**입니다.
- 한계: 이 장난감은 VLA를 재현하지 않으며 식 (6), (8)의 대수적 성질과 관측 유무의 효과 분리만 확인합니다. 실제 계획기의 편향과 비선형 머리에서의 차이는 시험하지 않았습니다.
