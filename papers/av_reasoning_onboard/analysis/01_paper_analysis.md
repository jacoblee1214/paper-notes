# 01. 블로그 분석: Running AV Reasoning Models Within Onboard Compute and Latency Limits

## 1. Abstract에 해당하는 주장

블로그 상단 요약과 서론이 말하는 내용은 다음과 같습니다.

1. Alpamayo 2 Edge는 **2B 파라미터**의 적응형 추론 VLA입니다. 백본은 Cosmos 3 Edge의 Nemotron 계열 2B 추론 백본이고, 궤적은 확산 행동 전문가(diffusion action expert)가 만듭니다.
2. 추론(Chain-of-Causation, CoC)은 **필요할 때만** 생성합니다(적응형 추론, 블로그 표현으로 "NOMINAL" 토큰).
3. **폐루프 강화학습**을 AlpaGym에서 해서 폐루프 주행 성능이 "최고 체크포인트 대비 48.9%" 좋아졌다고 주장합니다.
4. AlpaJudge는 사람이 보정했다고 하는 추론 평가·보상 모델입니다. RB(참조 기반)와 RF(참조 없음) 두 체크포인트가 있습니다.
5. 배포 레시피(TensorRT, TensorRT-Edge-LLM, DFlash2 추측 디코딩)로 **Thor에서 160–190 ms**를 얻는다고 합니다.

## 2. Method: 블로그가 설명하는 구성

### 2.1 모델 구조와 크기
- 백본: Cosmos 3 Edge 기반 Nemotron 계열 2B 추론 백본. 공개 config로 세면 텍스트 1.963B(임베딩·LM head 포함), 비전 0.411B(SigLIP2형), projector 약 0.08B, 액션 expert 0.198B. 합계 **2.65B**이고 모델 카드의 "백본 2.45B + expert 0.2B"와 맞습니다(`03` §1, `config_check.py`).
- 입력: 6대 카메라, 22장 프레임. 전방 광각·망원(카메라 1, 6)은 5장(−2, −1, −0.5, −0.1, 0초), 나머지 4대는 3장(−1, −0.1, 0초). 카메라마다 픽셀 예산이 다름(전방 163,840–196,608, 나머지 81,920–98,304). 20개 과거 자세(−1.9–0초, 0.1초 간격)와 내비게이션 문장.
- 출력: CoC 텍스트(기본 최대 256 토큰)와 64 웨이포인트(0.1–6.4초, 0.1초 간격). 행동은 unicycle 가속도·곡률(accel, curvature) 공간.

### 2.2 학습 방법
- **오프라인 증류**: Alpamayo 2 Super가 만든 CoC 자동 라벨로 학습(블로그 주장, 데이터·코드 공개 여부 불명).
- **폐루프 RL**: AlpaGym, 수치 "+48.9%"(블로그 주장).
- **다해상도 입력**: 카메라별 픽셀 예산(위 2.1, 공개 config로 확인됨).

### 2.3 추론 최적화
- **추측 디코딩 DFlash2**: 블록 16 초안 모델로 토큰을 미리 제안하고 큰 모델이 한 번에 검증. 블로그는 "품질을 떨어뜨리지 않고 가속"이라고 함.
- **양자화**: TensorRT Edge-LLM의 FP8 보정(calibration). 레시피는 FP8 가중치, 활성값, KV 캐시를 쓰고 비전 앞 층은 FP16으로 둠.
- **엔진 구성**: 행동 expert는 TensorRT 그래프로 내보내고, Euler 적분 5단계를 씀. 공개 PyTorch 예제는 10단계(차이는 `04` D8).

## 3. Experiments: 블로그 수치

### 3.1 다른 모델과 비교 (블로그 Figure 2, 막대 값 판독)
Figure 2의 Edge 값은 모델 카드 수치와 맞습니다(Ego3D, VLADBench, SURDS, WaymoQA, nuReasoning, LingoQA, KITScenes). Qwen-Drive-1.0(4B) 값은 확인할 공개 자료가 없습니다.

| 항목 | Alpamayo 2 Edge (2B) | Qwen-Drive-1.0 (4B, 블로그 값) | 비고 |
|---|---|---|---|
| 폐루프: 중대 사고 간 거리 (km) | 15.15 | 0.25 | 약 60배 (15.15/0.25 = 60.6) |
| Ego3D 정확도 | 84.9 | 61.0 | 모델 카드 84.94 |
| VLADBench | 69.9 | 66.5 | 모델 카드 69.94 |
| SURDS | 86.5 | 66.1 | 모델 카드 86.50 |
| WaymoQA (all) | 75.8 | 74.5 | 모델 카드 75.77 |
| nuReasoning (choice) | 78.6 | 58.4 | 모델 카드 78.58 |
| LingoQA (LingoJudge) | **75.2** | **79.4** | Edge가 낮음 |
| KITScenes (motion) | 70.0 | 52.5 | 모델 카드 70.00 |

블로그 제목 "Outperforms Across Major AV Tasks"와 달리 **LingoQA에서는 Qwen-Drive가 더 높습니다.**

### 3.2 폐루프 주행 (모델 카드)
- 875개 시나리오, 시나리오당 3회 롤아웃. 중대 사고 사이 주행 거리 **15.15 ± 0.04 km**(평균 ± 표준편차, 3세트). AlpaSim 기반.
- 개방 루프: 1,392 샘플, minADE₆@5초 **0.52 m**(모델 카드).
- 블로그의 "+48.9% (RL)"에 해당하는 표·수치는 공개 자료에서 찾지 못했습니다.

### 3.3 RL 보상의 효과 (블로그 Figure 5, 판독)
| 보상 | 자체 판정기 기준 향상 | 사람 평가 기준 향상 |
|---|---|---|
| AlpaJudge 보상 | +10.2% | +11.4% |
| 기준선 보상 | +13.4% | +1.8% |

이 그림은 "자체 판정기로 잰 향상"과 "사람이 잰 향상"을 나란히 보여 줍니다. 기준선 보상에서 자체 평가는 13.4%인데 사람 평가는 1.8%라 차이가 큽니다. 이것은 판정기 자체가 보상에 맞춰지는 문제(reward hacking)가 있을 수 있음을 보여 주는 증거이기도 합니다. 다만 블로그는 이 해석을 쓰지 않았고, 사람 평가 절차와 표본 수도 공개하지 않았습니다.

### 3.4 데이터 선별 (블로그 Figure 4, 판독)
판정 점수 분포를 세 구간으로 나눕니다. 낮음(0–0.26)은 라벨 오류나 어려운 사례, 중간(0.26–0.66)은 학습 가치가 큰 사례, 높음(0.66–1.0)은 이미 해결된 사례라고 봅니다. 원자료에서 각각 16%, 27%, 57%이고, 중간 구간을 표본 추출하면 81%가 됩니다. 이 임계값은 그림에 적힌 값이지만 선택 근거는 쓰이지 않았습니다.

### 3.5 지연 (블로그 본문)
- "픽셀에서 궤적까지 **160–190 ms**"(추론량에 따라 다름). 측정 장치: DRIVE AGX Thor-X, DRIVE OS 7.2.7.0, CUDA 13.4, TensorRT 11.3.1.9.
- 측정 방법(몇 번 반복, 예열 여부, 롤링 또는 콜드 스타트, 샘플 수)은 블로그에 없습니다. 레시피 README에서 측정 조건을 찾았습니다(`04` §2).
- 파트너 인용: Embedl은 "AGX Thor에서 10 Hz 계획", PORT는 Alpamayo 1.5 서버보다 "약 2배 빠른 계획", Niulinx는 minADE 13.6% 감소·횡방향 오차 46.1% 감소. 모두 파트너의 자체 보고이고 검증하지 못했습니다.

## 4. Limitations: 블로그가 말하지 않은 것

블로그에는 한계 절이 없습니다. 다음은 공개 자료로 확인한 빈칸입니다.
1. **측정 조건**: 지연의 반복 횟수, 샘플 수, 롤링 또는 콜드 스타트, 소프트웨어 버전(레시피 README는 "지표용이 아닌 대략적 타이머"라고 씀).
2. **양자화 품질**: 블로그는 "품질 보존"을 말하지만 BF16 PyTorch 기준과의 비교 수치가 없습니다. 레시피는 FP16 엔진과 비교한 minADE₆만 줍니다(1.547 m 대 1.570 m, 내부 10 클립).
3. **RL 효과**: "+48.9%"의 기준선, 시나리오 수, 반복 횟수가 없습니다.
4. **AlpaJudge 보정**: "사람이 보정했다"고 하지만 보정 데이터, 일치도, 신뢰구간이 공개 저장소에 없습니다.
5. **NOMINAL 토큰**: 학습 데이터 준비 스크립트에는 `<NOMINAL>` 라벨이 있지만, 추론 때 이 토큰이 얼마나 자주 나오는지는 공개 자료로 확인하지 못했습니다(`04` C14).
6. **추측 디코딩 초안 모델(DFlash2)**: 블록 16 초안 모델은 "모델 릴리스의 일부가 아니다"라고 레시피가 명시합니다.

## 5. 이 저장소의 관심사와 연결

블로그는 AV 추론 모델을 온보드 예산에 맞추는 **배포 공학** 글입니다. 로봇 VLA·월드 모델 관점에서 얻을 것은 다음과 같습니다.
- 지연을 **단계별로 쪼개고 측정 조건을 함께 적는** 방식(롤링 대 콜드 스타트의 차이가 53 ms 정도로 추정됨, `03` §3).
- 추측 디코딩의 손익분기 수락률(약 0.42, `03` §5). 행동 토큰에서 이 값을 넘는지는 미지수입니다.
- 판정기 점수로 **데이터를 고르고** RL 보상을 만드는 흐름. 다만 블로그의 보상 향상 수치는 자체 판정과 사람 평가가 크게 엇갈립니다(§3.3).
- 적응형 추론(필요할 때만 추론): 평균 지연을 줄이는 효과를 모델로 계산할 수 있습니다(`03` §5). 블로그는 NOMINAL 비율을 보고하지 않았습니다.
