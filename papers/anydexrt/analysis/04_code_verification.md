### 2.1 논문과 같은 부분 (확인함)

- 부분(한 방향) Chamfer: 매핑된 샘플에서 로봇 샘플 전체까지 최근접 거리 평균(`losses.py:19–23`).
- 정렬 손실: 앵커 쌍에서 위치의 L2 오차 평균(`losses.py:72–74`). 앵커는 손가락마다 가능한 쌍에서 32개를 복원 추출.
- 손실 가중치 모두 1(`losses.py:86`), 그림 2의 구조(손가락마다 독립 f_m, 엄지-손가락 쌍마다 f_c, F−1개의 분류기).
- 정규화: 손가락마다 최대 축 범위로 [−1, 1](`dataset/normalization.py`).
- 앵커 종류와 배치: 굽힘 다섯 손가락, 옆 회전 엄지만, 모든 손이 같은 사람 앵커 공유(`collection/pipeline.py`의 `collect_anchor_recordings`).

## 3. 대조에서 찾은 것의 정리

1. 공개 코드는 논문 손실의 다섯 번째 항(지도 대조)과 여러 후처리(One Euro, 범위 밖 입력 대체, 소프트 접촉 융합)를 포함합니다(D1, D6, D7). 논문의 서술보다 구현이 두꺼운 구조이고, 각각이 지표에 얼마나 기여하는지는 논문에 없습니다.
2. 접촉 보정의 설정이 논문 v2와 다릅니다(임계값 0.9 대 0.5, 융합 방식). v1은 0.5로 코드의 기본값과 같습니다.
3. 앵커의 숨은 조정값이 손별 JSON에 있습니다(D9). v1 → v2에서 λ 하나를 바로잡아 표 1이 크게 바뀐 이유와 연결되는 지점이지만(`03` V2), 코드로 그 인과를 확인한 것은 아닙니다.
4. 평가 코드와 데이터가 없어 논문 표는 이 저장소로 재현할 수 없습니다(D13, D14).

## 4. 구현 가능성 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**판정: 논문의 방법(f_m 학습 + 접촉 분류기 + NNS 추론)은 이 맥에서 구현하고 작게 학습할 수 있습니다. 논문 수치(표 1–4)와 실로봇 결과의 재현은 불가능합니다. 공식 코드를 그대로 돌리는 것은 코드 수정과 설치가 필요한 조건부입니다.**

| 항목 | 이 맥에서 | 이유·필요한 것 |
|---|---|---|
| f_m 학습 (MLP 5개, 입력 3차원) | **가능 (CPU, 수십 분 추정)** | 모델이 아주 작고 데이터가 30,000점입니다. 스텝당 연산은 로봇 샘플 10,000점과의 거리 행렬(2,048 × 10,000)과 쌍별 거리(2,048²)입니다. 약 7,320 스텝이라 CPU로 수십 분(측정 전 추정). MPS 사용은 미검증 |
| 접촉 분류기 학습 | **가능 (CPU, 수십 분 추정)** | 분류기 4개, 에폭당 100만 샘플을 `__getitem__`에서 numpy로 합성하므로 데이터 생성이 병목(워커 수에 따라) |
| 로봇 샘플 생성 (URDF 순기구학 1만 개 × 손가락) | **가능 (설치 후)** | `kinpy`, `open3d`가 필요합니다. `HandVisualizer`가 import 시점에 open3d를 불러오므로 Mac용 설치 확인이 필요 |
| 공식 코드 그대로 학습 | **조건부** | `prepare_training`이 CUDA가 없으면 오류(`arguments.py:27`), 학습 함수의 `device="cuda"` 기본값. 장치 인자 수정이 필요하고 코드 수정은 사용자 승인 사항 |
| 글러브 데이터 수집 | **불가** | MANUS 글러브와 MANUS Core SDK가 필요. 대안은 사람 손 운동학 모델로 만든 합성 지문 데이터로, 논문의 사람 데이터와는 다름 |
| 앵커 수집 | **부분 가능** | 사람 쪽 앵커는 글러브가 필요. 합성 앵커(손가락 시너지 관계로 만든 굽힘 곡선)로 대체 가능 |
| GMC, LMC 평가 | **구현 가능, 논문과 비교 불가** | 정의식이 논문에 없고 GeoRT를 가리킴. GeoRT 평가 코드는 비상업 라이선스(CC BY-NC) 저장소에 있음 |
| 기준선(GeoRT, 최적화) | **조건부** | GeoRT 학습 코드의 CUDA 요구는 이 분석에서 읽지 않아 미확인. 최적화 기준선은 dex-retargeting (MIT)이 공개되어 있음 |
| 실로봇 (Flexiv Rizon 4 + Wuji 손 + Manus 글러브 + Vive Tracker) | **불가** | 하드웨어 없음. 작업자 8명 평가도 해당 |

**노력 추정 (측정 전, 분석자 추정)**
- 공식 코드를 내려받아 장치 인자만 고쳐 합성 데이터로 학습·시각화: **1–2일** (설치 승인 필요).
- 핵심 방법 재구현(합성 사람 지문 데이터 + 로봇 FK 샘플 + 네 손실 + NNS)과 본 문서의 토이를 키운 형태: **3–5일**.
- 글러브 데이터와 7개 손 비교까지 논문 수준의 재현: 글러브 장비와 작업자가 필요해 이 맥만으로는 **불가능**.
- 논문 수치(GMC, LMC)와의 비교는 지표 정의와 평가 입력이 같지 않으면 의미가 없습니다(`03` K9).

## 5. 이 저장소에서 한 확인과 하지 않은 것

- 한 것: 모든 `.py`와 설정 파일 정독, 논문과 1:1 대조, 줄 번호 기록.
- 하지 않은 것: 코드 실행·import·설치, 체크포인트·데이터 다운로드, MANUS SDK 저장소 읽기(이름만 확인), 손별 URDF·메시 검증.
