# 01. 논문 분석: Do As I Can, Not As I Say (SayCan)

*Do As I Can, Not As I Say: Grounding Language in Robotic Affordances* (Ahn 외 44명, Google Research·Everyday Robots). arXiv:2204.01691, **CoRL 2022**(PMLR 205, 2023 발행). 분석 대상은 **arXiv v2 (2022-08-16)**이며 CoRL 2022 camera-ready입니다(PDF 메타데이터 Subject: "Proceedings of the 6th Conference on Robot Learning (CoRL 2022)"). 분석일 2026-11-22.

## 0. 버전 기록과 차이

| 판본 | 날짜 | 주요 내용 | 헤드라인 수치 |
|---|---|---|---|
| v1 | 2022-04-04 | LLM은 **FLAN(137B)**. 모의 주방 101개 지시에서 계획·실행 평가 | 계획 70%, 실행 61% (Table 2) |
| v2 (분석 대상) | 2022-08-16 | LLM을 **PaLM 540B**로 교체. 모의 주방 재평가, 실제 주방 101개 전체 평가, 드로어·사고 연쇄·다국어·오픈소스 환경(§6) 추가 | 계획 84%, 실행 74% (Table 2) |

- **v2의 Table 3에 있는 FLAN-SayCan 행(계획 70%, 실행 61%)은 v1 Table 2의 수치와 같습니다.** 열 하나하나(NL 단일 67/67, 명사 60/53, 동사 80/67, 구조화 100/87, 구현체 64/55, 크라우드 73/67, 장기 47/33)가 일치합니다. 즉 v1의 헤드라인 숫자는 v2에서 FLAN 기준선으로 강등되었고, PaLM-SayCan이 새 헤드라인이 되었습니다.
- v1 Table 3의 실제 주방 비교는 46개 지시의 부분집합이었습니다. v2는 101개 전체로 바꿨습니다.
- v1 본문은 "실제 주방에서 큰 성능 손실이 없다"였고, v2는 계획 −3%p, 실행 −14%p를 적었습니다(§5.1).
- v2에는 "LLM 크기 ablation"(Table 6, 8B/62B/540B/FLAN)이 새로 있습니다. 그런데 이 표는 가치함수 없이 생성 결과만 본 것이라 로봇 성능 근거가 아닙니다(§3 K3).
- 논문 제목은 두 판본 모두 같습니다. 본문 문장 대부분은 편집만 바뀌었습니다(difflib 문장 단위 비교로 확인, 85개 블록 변경).

**결론:** 이 분석의 숫자와 주장은 v2 기준입니다. v1을 인용하는 2차 자료는 FLAN 결과를 SayCan 결과로 읽을 수 있으니 주의가 필요합니다.

## 1. 문제 설정

- 목표: 사용자의 긴 자연어 지시(예: "I spilled my coke, can you help?")를 로봇 기술(skill) 순서로 바꾸되, LLM이 **실행 불가능하거나 장면에 맞지 않는** 계획을 내지 않게 하기 (§1).
- 정식화(§3): 각 기술 π는 짧은 언어 설명 ℓ_π, 가치함수 p(c_π | s, ℓ_π)(성공 확률), 그리고 LLM이 주는 p(ℓ_π | i)(지시 i에 대한 유용성)를 갖습니다. 논문은 "성공한 기술만 지시 진행에 기여한다"는 가정으로
  **p(c_i | i, s, ℓ_π) ∝ p(c_π | s, ℓ_π) · p(ℓ_π | i)** 를 씁니다. 앞 항이 *world-grounding*, 뒤 항이 *task-grounding*입니다.
- 선택 규칙(Algorithm 1): 매 스텝 π_n = argmax_π p_LLM(ℓ_π | i, ℓ_{π_{n-1}}, …) · p_aff(π | s_n), 종료 토큰 "done"이 나올 때까지 반복.

**점검 (C-항목은 03 §4에서 판정):** 곱 규칙은 두 확률이 **독립**이고 가치함수가 **보정된 확률**일 때만 확률 해석이 맞습니다. 논문은 보정을 경험적 상수로 했다고만 적었습니다(D.2). 또 p(ℓ|i)가 옵션 집합 안에서 정규화된 확률인지, 문자열 길이를 보정했는지는 본문에 없습니다.

## 2. 방법

### 2.1 가치함수 = 기술의 가용성 (affordance)
- 기술 정책은 두 종류입니다. 피킹은 BC-Z 방식 다중 과제 BC 정책(68,000 시연 + 자율 수집 276,000 에피소드 중 성공 12,000 추가, C.2)과 MT-Opt 방식 RL 가치함수를 씁니다. 가치함수는 **희소 보상 0/1 Q-함수**이고, 이를 affordance로 씁니다(§2).
- 언어 조건은 고정된 문장 임베딩(USE)으로 주며, 정책과 가치함수는 텍스트 임베딩을 입력으로 받습니다(§4).
- 보정(D.2): 피킹은 clamp((v − v_min)/(v_max − v_min), 0, 1), v_min = 0.2, v_max = 0.5. 이동은 거리 d(0–100 m)에서 clamp((d_max − d)/(d_max − d_min), 0, 1). 배치는 1.0 고정, 종료는 0.1. 이미 완료된 기술은 상한을 둡니다(완료 상태 반영, 하지만 구체적 방법은 한 문장뿐).

### 2.2 LLM 점수화 (Say)
- 프롬프트: 17개 예시(Listing 1)의 대화형 "How would you … / I would: 1. …, 2. done" 구조. 점수는 "I would: 1. " 뒤에 붙는 기술 설명 문장의 로그확률입니다(§3, D.3).
- 예시 수 ablation(Table 5, 언어 시뮬레이터 50문장): 예시 0개 52%(무종료 요건)/10%(종료 요건), 1개 74/64, 2개 76/68, 4개 84/82, 8개 80/80, 17개 88/88.

### 2.3 구현 세부
- 로봇: Everyday Robots 모바일 매니퓰레이터, 7자유도 팔, 2지 그리퍼. 기술 551개 중 평가에 쓴 것은 "가장 유용하고 성능이 높은" 부분집합(§4). 객체 15개, 위치 5개(두 카운터, 탁자, 쓰레기통, 사용자).
- 평가 장면: 실제 사무실 주방과 그 주방을 본뜬 **모의 주방**(기술을 학습한 바로 그 장면). 헤드라인 수치는 모의 주방에서 나옵니다.
- 측정: 계획 성공 = 사람 3명 중 2명이 "계획이 지시를 달성 가능"이라고 판정. 실행 성공 = 3명 중 2명이 로봇 영상을 보고 "과제 달성"이라고 판정(§5).

## 4. 재계산 가능한 것과 불가능한 것

- 표 2·3·6의 행별 백분율은 분모 n(15 또는 11)에서 정수 계수 하나로만 맞아떨어집니다. 이 계수로 합계를 다시 맞춰 보았고, **실제 주방 열의 행 합은 보고된 총계와 맞지 않습니다**(03 K1).
- 지시문별 성공 여부(Table 5의 101행)는 **본문에 없습니다**. 그래서 같은 지시문을 쓴 비교(쌍체)를 하지 못하고, 모든 검정은 비쌍체 Fisher로 했습니다(03 §2).
- 학습 곡선, 기술별 정책 성공률, 보정 상수 값의 민감도, 기술 수 증가 효과는 논문에서 다시 계산할 수 없습니다.

## 6. 한계 (논문이 적은 것 + 이 분석이 본 것)

- 기술 집합이 병목입니다(§8). 기술이 없으면 계획이 맞아도 실행이 안 됩니다.
- 실패 복구가 없습니다. 기술이 높은 가치를 보고해도 실패하면 시스템은 다시 계획하지 않습니다(§8). 폐루프 확장은 Inner Monologue(Huang 외, 2022)가 다룹니다(본문 §5.2, 인용만 함).
- 본문 §6 "오픈소스 환경"은 PaLM 대신 GPT-3를 쓰고, 가치함수 대신 객체 탐지기를 씁니다(`04_code_verification.md`). 논문의 헤드라인과 공개 코드는 다른 시스템입니다.
- 평가에 쓴 101개 지시문과 사람 평가 원자료는 공개되지 않았습니다.
- 시뮬레이션 정책 학습에 TPU 16개와 CPU 6,000개를 썼습니다(C.2). 재현 비용은 이 맥으로 감당할 수 없습니다.

## 7. 용어와 표기

- 본문은 "value function"과 "affordance function"을 같은 뜻으로 씁니다(§2, D.2). 이 분석도 같은 뜻으로 씁니다.
- "zero-shot"은 LLM과 기술을 이 과제에 맞춰 다시 학습하지 않는다는 뜻입니다. 기술 정책은 이 장면에서 학습되었고, 프롬프트에는 예시 17개가 들어 있습니다.
