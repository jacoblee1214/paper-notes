# 04. 논문 ↔ 공식 코드 대조: ManipTrans

대상: `repo/` (https://github.com/ManipTrans/ManipTrans, GPL-3.0), 얕은 clone HEAD `a3d08cf` (2025-06-18). **정적으로만 읽었습니다.** 설치, import, 실행을 하지 않았습니다. clone 내용은 신뢰하지 않는 데이터로 취급했습니다. 파일 경로는 `repo/` 기준입니다.

## 1. 한눈에 보기

- 코드는 논문의 두 단계 구조(손 모방 `DexHandImitator` → 잔차 `ResDexHand`)를 **그대로 갖추고 있습니다**. 주요 PPO 값(horizon 32, minibatch 1024, γ 0.99, Adam), 4096 환경, dt 1/60, 밀도 200, 거울 데이터, 중력·마찰 완화, 임계 완화 방식 모두 논문과 맞습니다.
- 그러나 **보상 식과 임계 값은 논문과 다른 곳이 여럿** 있습니다. 논문 식 (1)은 제곱 노름과 관절별 가중치를 쓰는데, 코드는 노름(제곱 없음)과 그룹별 가중치를 씁니다. 잔차 보상도 논문의 세 항보다 훨씬 많은 항을 씁니다(D5, D6, D7).
- **성공 판정도 논문과 다릅니다.** 논문은 3 cm, 30°, 8 cm, 6 cm를 쓰지만, 코드의 성공은 학습 중 완화 계수에 따라 바뀌는 실패 임계로 판정합니다(D15).
- 논문 표의 재현에 필요한 **평가 스크립트, 실로봇 코드, 기준선(Retarget + Residual, RL-Only) 구현은 저장소에 없습니다.**

## 3. 불일치와 빈칸 (D1–D19)

### 3.1 학습 설정

- **D1. 학습률.** 논문 §4.2는 5e-4입니다. 코드 기본값도 5e-4입니다(`main/cfg/config.yaml:26`, `ResDexHandPPO.yaml:138`). 그러나 README의 **모든 학습 명령**은 `learning_rate=2e-4`를 씁니다. 표 1을 어느 설정으로 얻었는지 불명확합니다.
- **D13. 환경 수 기본값.** 논문과 README는 4096입니다. 기본값 8192(`ResDexHand.yaml:9`)와 다릅니다. 실행 명령으로 덮어쓰면 문제는 없습니다.
- **D12. 에피소드 길이.** 논문에 없습니다. 코드는 손 모방 2000 스텝(`DexHandImitator.yaml:12`), 잔차 1200 스텝(`ResDexHand.yaml:12`)입니다.

### 3.2 보상 식 (1) 손가락 추적

논문 식 (1): $\sum_f w_f \exp(-\lambda_f \|j^d_f - j^h_f\|_2^2)$, 손가락별·마디별 가중치 표 5 (5 손가락 × 4 마디).

- **D5. 식의 형태와 가중치 구조.** 코드(`dexhandimitator.py:1100–1137`):
  - 거리는 `torch.norm`으로 **제곱 없이** 씁니다. 논문은 제곱입니다.
  - 가중치는 **손가락 공통 3그룹**(손끝, 1단계 관절, 2단계 관절)입니다. 표 5의 손가락별 값이 아닙니다.
  - 손끝 그룹(w 0.9, 0.8, 0.75, 0.6, 0.6, λ 100, 90, 80, 60, 60)은 표 5의 **tip 열과 값이 같습니다**(엄지, 검지, 중지, 약지, 새끼 순). 1단계(w 0.5, λ 50)와 2단계(w 0.3, λ 40)도 표 5 엄지의 근위·중위 값과 같습니다.
  - 그래서 말단(distal) 마디의 값이 코드에 어떻게 들어가는지는 확인하지 못했습니다.
  - 코드는 엄지·검지·중지의 상대 가중을 표 5 그대로 쓰지만, 마디별 차이는 그룹으로 뭉쳐졌습니다.

### 3.3 임계 완화 (커리큘럼)

논문 §4.2: $\epsilon_{finger}$ 6 → 4 cm, $\epsilon_{object}$ 90° and 6 cm → 30° and 2 cm.

- **D2. 손가락 임계.** 코드는 **관절 그룹마다 다른 값**을 씁니다(`dexhandimitator.py:1147–1153`, `dexhandmanip_bih.py` failed_execute). 완화 계수 $s$에서 엄지 손끝은 $0.04/0.7 \cdot s$, 2단계 관절은 $0.08/0.7 \cdot s$입니다. 처음($s=1$)은 엄지 5.7 cm, 2단계 11.4 cm이고, 끝($s=0.7$)은 4.0 cm, 8.0 cm입니다. 논문의 "6 cm"는 하나의 값이라서 시작 값이 맞지 않습니다.
- **D3. 물체 임계.** 코드는 $0.02/0.343 \cdot s^3$과 $30/0.343 \cdot s^3$입니다(`dexhandmanip_bih.py` failed_execute). $s = 1$에서 5.8 cm, 87.5°이고, $s = 0.7$에서 2 cm, 30°입니다. 끝 값은 논문과 맞고, 감소 함수가 $s^3$이라는 점은 논문에 없습니다.
- **D4. 완화 스케줄.** 코드는 `exp_decay`, 계수 0.7입니다. 스텝 수는 잔차 3200 프레임(`ResDexHand.yaml:40–42`), 손 모방 128000 프레임(`DexHandImitator.yaml:37–39`)입니다. 논문은 스텝 수를 쓰지 않았습니다.

### 3.4 접촉 보상과 종료 조건

- **D6. 접촉 보상.** 논문 식 (2)는 $w_c \exp(-\lambda_c / \sum_f C \cdot \mathbb{1}(D < \xi_c))$입니다. 부록 D.2는 $w_c = \lambda_c = 1$로 둡니다. 코드(`dexhandmanip_bih.py:1940–1948`)는 **지시 함수가 아니라 2–3 cm 사이 선형 가중치**를 쓰고, 값은 $\exp(-1/(\|\sum F \cdot w\| + 10^{-5}))$입니다. $\xi_c$ 값은 논문에 없습니다.
- **D18의 일부.** 접촉 종료 조건 $\xi_t$는 논문에 없습니다. 코드는 **손끝과 물체 거리가 5 mm 미만인데 접촉이 없으면** 종료합니다(`dexhandmanip_bih.py:1970`). 단 8 스텝 이후부터입니다(`running_progress_buf >= 8`, :1972).

### 3.5 잔차 보상 구성

논문 §3.3: $r^R = r^I + w_{object} r_{object} + w_{contact} r_{contact}$. 가중치 $w_{object}$는 논문에 없습니다.

- **D7. 보상 항 수.** 코드(`dexhandmanip_bih.py` `reward_execute`, 약 1997–2016행)는 **19개 항**을 씁니다. 항목은 손목·손끝 위치(0.1–0.9), 손목 회전(0.6), 1·2단계 관절(0.5, 0.3), 물체 위치(**5.0**), 물체 회전(**1.0**), 손목 속도(0.1), 각속도(0.05), 관절 속도(0.1), 물체 속도·각속도(0.1), 손끝 힘(**1.0**), 관절 일률(0.5), 손목 일률(0.5)입니다. 논문은 이 가중치와 항들을 쓰지 않았습니다.
- 논문의 "부드러움" 보상은 관절 일률 페널티입니다(§3.2). 코드의 `reward_power`(exp(−10·일률))가 이것에 대응합니다. 그러나 여기서도 가중치가 논문에 없습니다.
- 확인 범위: `dexhandmanip_bih.py`(양손)만 읽었습니다. `dexhandmanip_sh.py`(한 손)의 가중치는 확인하지 않았습니다.

### 3.6 정책 초기화와 행동 처리

- **D10. 잔차 초기화.** 논문은 "0 평균 가우스 분포로 초기화"라고 씁니다(§3.3). 코드(`ResDexHandPPO.yaml`)는 `mu_init: glorot_normal_initializer, gain 0.01`과 `sigma_init: const −1, fixed_sigma: True`입니다. 평균이 작은 가중치로 초기화되지만 "0 평균 가우스"는 아닙니다. 효과는 비슷하지만 같은 것은 아닙니다.
- **D9. 저역통과 필터.** 논문 부록 E는 롤아웃에 $\alpha = 0.4$ 필터를 씁니다. 코드의 `actionsMovingAverage` 기본값은 **1.0**입니다(`main/cfg/config.yaml:27`). 1.0이면 필터가 없습니다. 식 `curr * target + (1 - curr) * prev`(`dexhandimitator.py:924`)는 논문의 저역통과와 같은 구조입니다. 따라서 α = 0.4로 설정했는지 확인해야 합니다. 저장소에는 그 설정이 없습니다.
- **D11. 손목 제어 모드.** 기본 힘 모드(논문과 일치)입니다. README는 손마다 **PID 모드 체크포인트**를 따로 줍니다(`imitator_pid_*`). 논문에는 PID 모드가 없습니다. 논문 표는 어떤 모드인지 밝히지 않았습니다.
- **D14. 기타 PPO 항.** GAE 람다 τ = 0.95(`ResDexHandPPO.yaml:137`)는 논문에 없습니다. `max_epochs` 10000이 기본값입니다.

### 3.7 평가와 데이터

- **D15. 성공 판정.** 논문 §4.1은 $E_r < 30°$, $E_t < 3$ cm, $E_j < 8$ cm, $E_{ft} < 6$ cm를 씁니다. 코드의 성공은 `success_buf`(`dexhandmanip_bih.py` `compute_imitation_reward`)이고, 실패 임계와 같은 식을 씁니다. 완화 계수 $s$가 평가 모드(`training = False`)에서 1.0이면 물체 5.8 cm, 87.5°, 손끝 5.7–11.4 cm입니다. 학습 중에는 $s$가 0.7–1.0 사이로 움직입니다. 논문 수치와 같은 임계를 쓴 평가 스크립트는 찾지 못했습니다.
- **D16. 잡음 강건성.** 논문 부록 B는 손 관절 목표에 $N(0, \sigma^2)$을 넣습니다. 저장소에서 찾은 잡음은 리셋 때 초기 자세에 넣는 값(`dexhandimitator.py:763–792`)과 주석 처리된 `dexhand_rDofNoise`뿐입니다. 표 4의 실험 설정은 확인할 수 없습니다.
- **D17. 물체 질량.** 논문은 일부 물체를 실측하고 나머지는 밀도 200으로 계산한다고 씁니다(부록 D.3). 코드에서는 밀도 설정만 찾았고, 실측 질량을 읽는 코드는 찾지 못했습니다.
- **D19. 실로봇.** 저장소에 실로봇 제어 코드가 없습니다.
- **D18. 기준선.** Retarget + Residual과 RL-Only는 저장소에 없습니다. 논문은 두 기준선을 직접 재구현했다고 씁니다(§4.3).
- **외부 참고.** 논문 각주 1은 QuasiSim 공식 저장소(MIT, 80 star, 마지막 push 2024-08-10)를 가리킵니다. 논문 본문은 같은 저장소의 "전체 파이프라인은 아직 공개되지 않았다"고 씁니다(§4.3). 이 저장소는 열지 않았습니다. 두 주장이 맞는지는 확인하지 못했습니다.

## 5. 저자에게 물을 것

1. **표 1 분모.** 단일과 양손 SR의 분모와 집계 방식(평균인지 풀링인지)은 무엇입니까? 네 행을 동시에 만드는 정수 분모가 없습니다(`03` §1).
2. **표 1 학습률.** 논문 결과는 5e-4입니까, README의 2e-4입니까(D1)?
3. **표 2 분모.** 320인지 420인지, 시험 시퀀스는 몇 개입니까(`03` §3)?
4. **표 4.** 양손 SR 열의 의미는 무엇입니까? 노이즈 0 기준 행은 있습니까? 1.5 cm에서 양손 SR이 오른 이유는 무엇입니까?
5. **손가락 임계.** 논문의 "6 cm"는 관절 그룹별 값(D2)의 대표값입니까?
