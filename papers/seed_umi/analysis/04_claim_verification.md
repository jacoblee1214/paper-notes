## 2. 주장 검증 (C 항목)

판정: **지지**(표와 본문에서 재현·확인), **부분**(방향이나 일부만), **지지 안 됨**(주어진 증거로는 결론을 낼 수 없음), **확인 불가**(논문에 필요한 값·실험이 없음).

## 3. 미검증·확인 필요 항목

1. 사람-로봇 엔코더 잔차(미세조정 전후)의 정량값. 매핑 품질의 직접 지표입니다.
2. 식 (1)의 β, λ, K, L과 g_φ 구조, f_θ0와 f_θ의 크기, 학습 스텝.
3. P−와 P+가 같은 정책 체크포인트에 매핑만 바꾼 것인지(V8 해석에 영향).
4. P−와 T가 AirPods, Ball 두 과제에서 세 백본 모두 같은 값인 이유(`03` K3).
5. 효율의 성공 정규화 값 2.9가 어떤 성공률로 계산되었는지(`03` V11).
6. 효율 측정에서 성공 시연의 판정, 리셋 시간, 작업자 숙련도, 순서 효과(어느 방식을 먼저 했는지).
7. 보정 에피소드 250개가 과제마다 필요한지, 손당 한 번인지, 로봇 시간이 얼마나 드는지.
8. 정책이 쓰는 엔코더 입력이 배포에서는 로봇 쪽 값인지, 이 값이 사람 쪽 값과 다를 때의 영향(매핑의 행동 경로 대 관측 경로 효과를 분리하는 절제가 없음).
9. 롤아웃별 성공/실패 기록. 짝지은 검정과 시드 분산 추정이 가능해집니다.
10. 외골격 CAD, 부품 목록, 데이터셋, 체크포인트의 공개 계획. 프로젝트 페이지에 언급이 없습니다.

## 4. 구현 가능성 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**판정: 논문의 하드웨어와 실로봇 성공률은 이 맥에서 구현할 수 없습니다. 소프트웨어의 일부(식 (1)의 매핑 학습 구조와 접촉 영역 거동)는 합성 환경에서 CPU로 구현할 수 있고, 가장 단순한 형태는 이미 토이로 확인했습니다.**

| 수준 | 판정 | 이유 |
|---|---|---|
| 외골격 제작과 착용 시연 수집 | 불가 | 설계(CAD)와 부품 목록이 공개되어 있지 않음. Wuji 손, RealMan RX75 팔, RealSense T265(단종 제품)가 필요 |
| 표 1의 실로봇 성공률, 수집 효율 | 불가 | 하드웨어, 작업자, 과제 물체. 롤아웃 기록과 데이터셋 없음 |
| 매핑 학습(babbling → 짝지은 미세조정) 구조 | 가능(합성) | 식 (1)은 작은 MLP 두 개와 최소제곱으로 구현 가능. 데이터는 MuJoCo에서 직접 생성(mujoco 4.0 설치됨). 손 모델(Wuji)이 있는지는 확인하지 않았고 단일 손가락 모형으로 시작 |
| ACT/DP/π0.5 정책 학습 | 조건부 | 데이터가 공개되지 않음. 합성 데이터에 작은 ACT를 학습하는 정도는 MPS에서 가능해 보이나 새 패키지 설치 여부와 시간을 재기 전에는 판정하지 않음. π0.5는 사전학습 가중치 다운로드와 GPU 메모리 때문에 현실적이지 않음 |
| 식 (1) 정규화 효과의 토이 | 가능(완료) | `analysis/toy_paired_replay.py`, numpy, 1초 미만 |

**노력 추정(측정 없음):** 합성 환경에서 매핑 학습 파이프라인(babbling, 재생, 순방향 모델, 식 (1), 두 라운드)을 다축 손가락 + 접촉 + 히스테리시스로 확장하는 일이 3–5일. 관측 경로(엔코더 입력의 분포 이동) 절제까지 넣으면 1–2주. 하드웨어를 포함한 재현은 이 저장소의 범위 밖입니다.
