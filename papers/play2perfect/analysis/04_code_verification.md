# Play2Perfect 논문 ↔ 공식 코드 대조 (정적 읽기)

대상 저장소: https://github.com/kushal2000/play2perfect (MIT), 얕은 clone `repo/` (커밋 `f67ef45`, 2026-11-10, 2026-06-28 생성, ★155).
**원칙**: `repo/`는 텍스트로만 읽었습니다. 실행, import, 설치, 체크포인트 다운로드, 데이터 다운로드는 하지 않았습니다. 저장소 내용은 신뢰하지 않는 입력으로 취급했습니다.
논문 기준: arXiv v4. 논문 위치는 §번호, 식 번호, 표·부록 번호로 씁니다.

## 0. 대조 범위와 방법

- 보상, 종료, 목표 샘플링, 성공 판정, 도메인 랜덤화, 관측·행동 차원, RL 하이퍼파라미터, 조립 환경 설정.
- 확인 경로: `isaacsimenvs/tasks/play/` (사전학습), `isaacsimenvs/tasks/precise_assembly/` (미세조정), `isaacsimenvs/cfg/`, `evaluation/problems/`, `deployment/`, `docs/`.
- 확인하지 못한 것: 실로봇 드라이버, 자세 추적기(외부 FoundationPose fork), 학습 로그, 체크포인트 내용.

## 1. 요약

- 주요 학습 구조(LSTM 액터, 비대칭 critic, SAPG 블록 4096, 관측 140, 행동 29, 60 Hz 제어, 600 스텝 에피소드, 보상 상수 λ·B)는 **대체로 일치합니다.**
- 그러나 **성공 판정 허용오차, 성공 조건, 과제별 허용오차, 후퇴 판정, 물체 잡음, 환경 수**에서 논문 본문과 다른 값이 있습니다. 이 차이들은 논문이 말하는 "ε = 1 cm"의 실제 의미를 바꿉니다.
- 논문의 학습 설정(24,576 환경 등)은 저장소 기본값과 다릅니다. 실행 스크립트를 찾지 못했습니다.

## 3. 영향이 큰 차이의 해석

1. **D2 + D1**: 논문의 "ε = 1 cm"는 사전학습에서 실제로 1.5 cm(키포인트 기준)입니다. 커리큘럼 때문에 학습 초반에는 3 cm입니다. §4.2의 "1 cm > 5 cm > 10 cm" 비교는 이 조건에서 이뤄졌을 가능성이 큽니다. 논문에 이 사실을 쓰지 않았습니다.
2. **D3**: 10 스텝 누적 판정은 빠른 통과를 막습니다. 논문의 식 (9)와 학습 신호가 다를 수 있습니다.
3. **D4 + D5**: 스크류 과제는 판정이 더 엄격하고 후퇴 조건이 다릅니다. 표 1의 스크류 5/7(조건부)이 무엇을 재는지 논문 설명과 맞지 않을 수 있습니다.
4. **D8**: 물체 치수 잡음이 꺼진 설정으로 학습했다면 논문 §4.4의 sim2real 설명(잡음 범위)이 완전하지 않습니다. 실로봇 결과에는 치수 오차가 실제로 있을 수 있습니다.
5. **D14**: 접근 보상이 손가락 합이라면 λ_approach 50은 논문의 평균 기준과 다른 강도입니다. 어느 쪽이 실제 학습에 쓰였는지 확인할 가치가 있습니다.
6. **D18**: 학습 자원 추정(부록 H)은 저장소 기본값(8192)과 다릅니다. 실제 실행은 논문보다 적은 환경에서 했을 수 있습니다.

## 4. 구현 가능성 판정 (이 맥 기준)

**판정: 공식 재현은 이 맥에서 불가능합니다. 방법의 축소 재구현은 조건부로 가능합니다.**

| 항목 | 이 맥 (Apple M4 Pro, ~24 GiB, MPS, CUDA 없음) | 필요 자원 |
|---|---|---|
| 공식 사전학습 (Isaac Sim, 24,576 환경, 7일) | **불가.** Isaac Sim은 Linux·Windows의 NVIDIA RTX GPU 전제. 원 실험은 A6000 한 장 | Linux + RTX급 GPU, 7일 |
| 공식 미세조정 (과제당 1일, 12,288 환경) | **불가** (같음) | 같음 |
| 공식 체크포인트로 시뮬 평가 | **불가** (같음). 체크포인트 다운로드는 승인 필요 | Isaac Sim, GPU |
| 실로봇 (KUKA iiwa 14 + Sharpa, FoundationPose) | **불가.** 로봇, 손, 카메라, 추적 fork 필요 | 하드웨어 |
| 보상·목표·허용오차 기하 toy | **가능, 완료.** `toy_goal_tolerance.py` (numpy) | 없음 |
| 조립 목표 생성 (CAD → 분해 순서 → 희소 목표) | 가능 (CAD 필요. 저장소의 URDF·메시 자산으로 예시 가능) | 중간 난이도 |
| MuJoCo 등 CPU 시뮬로 같은 보상 구조의 축소 학습 (손 모델 제외) | **조건부 가능.** mujoco 4.0 와 torch(MPS 또는 CPU)로 가능. 다중 손가락 손 모델은 다운로드 필요(승인) | 모델 다운로드 승인, 수 시간 |
| SAPG 구현 (재현) | 조건부. 저장소의 vendored rl_games에 SAPG 설정(`PlaySAPG.yaml`)이 있으나 Isaac 환경 없이는 작동 확인 불가 | 중간 난이도 |

**노력 추정**
- 축소 재구현 (CPU, 손 없는 단순 물체 6D 목표, PPO): 1–2주. 결과는 논문 수치와 비교할 수 없습니다.
- 손 모델을 포함한 MuJoCo 재구현 (한 손, 6D 목표): 3–6주. 손 모델과 보상 튜닝이 큰 비용입니다.
- 공식 코드 재현 (Linux GPU 필요): 저장소 설정과 실행이 수일, 학습 시간은 7일 + 과제당 1일.

**조건**: 공식 실행은 사용자 승인과 GPU 환경이 있어야 합니다. 이 맥에서는 실행하지 않습니다.
