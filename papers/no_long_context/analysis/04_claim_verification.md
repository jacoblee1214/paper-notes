### 1.1 계산해 본 보조 수치

- 표 3–8, 11–17의 명목 비용 합계(단일 실행, SAC와 오픈 모델 제외): 약 **$17,500**(장기 Opus $5,738, GPT $3,319; 긴 입력 Opus $5,014, GPT $3,422).
- LOONG과 Counting-Stars는 두 모델의 기준선 입력 토큰 합계가 같습니다(272.0M, 9.5M). LongBench v2 기준선은 Opus가 캐시 입력 263.4M, GPT가 47.0M으로 5.6배 차이가 납니다. 둘 다 이유가 적혀 있지 않습니다.

## 3. 확인하지 못한 것

1. 처리량 측정(Fig. 4)의 동시 요청 수, GPU 사용률, vLLM 설정(`max_num_seqs` 등). 16K에서 무엇이 처리량을 막았는지 알 수 없습니다.
2. GLM 5.2의 구조. 그래서 C10의 상한 비교에서 비워 두었습니다. Kimi K2.6과 Qwen 3 Coder Next의 구조도 공개 config를 이 저장소에서 다시 확인하지 않고 Kimi K2·Qwen3-Next와 같다고 가정했습니다.
3. 요청별 문맥 길이 분포. C15의 같은 규칙 추정은 표의 평균·중앙값·최댓값만으로 만든 근사입니다.
4. 긴 입력 기준선이 창을 넘는 입력을 어떻게 처리했는지(C11). RULER의 표본 수.
5. 과제별 결과. 대응 검정을 할 수 없습니다.
6. SAC의 토큰 사용량과 비용.
7. 압축 프롬프트 자리표시자의 내용(부록 G).

## 4. 구현 가능성 판단

### 4.1 방법 자체

**쉽습니다.** 하네스에 수십–수백 줄을 더하는 일입니다: 문맥 크기를 세고, 임계값에서 압축 프롬프트를 한 번 보내고, 시스템 프롬프트 + 과제 + 요약으로 대화를 다시 시작합니다. 긴 입력은 문서를 파일로 두고 bash 도구를 주면 됩니다. 학습이 필요 없습니다.

- 공식 코드는 없습니다. mini-swe-agent(MIT) 위에 얹거나, 비공식 구현(MIT, Anthropic API 전용)을 참고하면 됩니다.
- 압축 프롬프트 자리표시자는 직접 채워야 합니다(U4).

### 4.2 이 맥에서 작은 로컬 모델로

이 맥은 Apple M4 Pro, 통합 메모리 24 GiB, CUDA 없음입니다.

- **하네스:** CPU면 충분합니다.
- **모델:** llama.cpp, Ollama, LM Studio, MLX 중 하나를 설치하고 모델을 받아야 합니다. 이번에는 설치·다운로드를 하지 않았으므로 아래는 계산이고 미확인입니다.
  - 4비트 8–14B(약 5–9 GB)는 여유가 있습니다.
  - 27–32B 4비트(약 16–19 GB)는 GPU 기본 한도(RAM의 약 2/3, 약 17 GB로 가정) 근처라 빠듯합니다.
  - 순수 어텐션 8B(예: 32층, KV 헤드 8, 헤드 차원 128)는 FP16 KV가 토큰당 128 KiB입니다. 128K 문맥이면 KV만 16 GiB라서, 이 맥에서는 짧은 문맥이 실제로 필요합니다. 반대로 DeltaNet·Mamba 하이브리드는 KV가 작아 이 압박이 덜합니다(`03` §1.4).
- **어디까지 확인할 수 있나:** 긴 입력 과제(NIAH, Counting-Stars, BABILong 일부)의 "파일 + grep" 선택 읽기는 작은 모델로도 해 볼 만합니다. SWE-bench급 장기 과제는 작은 모델의 기본 성능이 낮고, 논문 부록 D처럼 장황한 모델은 16K/12K에서 무너질 수 있습니다. SWE-bench 평가 이미지는 x86 Docker라 Apple Silicon에서 되는지도 확인이 필요합니다.
