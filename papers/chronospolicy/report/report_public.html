핵심 요약

  1. 무엇을 하는가: 정책이 관측과 행동을 "시퀀스의 몇 번째"가 아니라 관측 캡처 시각과 행동 실행 시각으로 보게 했다. 위치 인코딩을 물리 시각으로 돌리는 time-aware RoPE와, 학습 때 관측 주기·지연·행동 시작 시각을 흔드는 시간 무작위화를 쓴다.
  2. 숫자는 정확하다: 논문 Table 3·4의 132칸이 프로젝트 페이지의 반올림 전 값과 모두 일치하고, 본문 수치 23개도 재계산과 맞는다. 시드별 성공 횟수도 132칸 모두 역산된다.
  3. 동적 과제의 개선은 확실하다: Conveyor에서 교란 5조건 모두 시드 단위 p < 0.02. 같은 무작위화로 학습한 DP와 비교해도 교란 평균 26.9 → 63.1이다.
  4. "Small" 조건은 Chronos의 학습 분포 그 자체다: 주기·지연 범위가 학습 무작위화와 같다. DP 15.6 vs Chronos 77.6의 대부분은 학습 분포 차이이고, 시각 정보의 순수 효과는 DP + 무작위화 대비 +16.7%p(Conveyor), +34.9%p(Pivoting)다.
  5. 약한 결론도 있다: Pivoting의 Chronos-DP 차이와 RoPE-AddTime 차이는 시드 3개로는 유의하지 않다(p 0.13–0.92). 표준 6과제의 59.7 → 73.4는 세 과제에 몰려 있고, 나머지 세 과제는 81.2 vs 80.7이다. 표준 과제와 실제 로봇에는 DP + 무작위화 기준선이 없다.
  6. 실제 로봇: 12개 조건 모두 최고 점수지만 조건별 차이는 잡음 범위다. 과제별로 합치면 6개 비교 중 5개가 유의하다.

우리 분석: Table 3을 시드 SD와 함께 다시 그림. Small 조건은 시간 무작위화 변형들에게 학습 분포 안이고, 회색 배경 조건은 모든 방법에게 분포 밖이다.

1. Abstract (한 줄 요약과 주장)

한 줄 요약: 모방학습 정책이 관측과 행동을 "고정 주기 시퀀스의 몇 번째"로만 보던 것을, **관측을 찍은 시각과 행동을 실행할 시각(물리 시간)**으로 보게 바꿨습니다. 방법은 diffusion transformer의 위치 인코딩을 인덱스 대신 물리 시각으로 돌리는 time-aware RoPE와, 학습 때 관측 주기·지연·행동 시작 시각을 흔드는 시간 무작위화입니다.

정책은 다음과 같이 정의됩니다(Eq. 1, 3).

A_{t_a} ∼ π_θ(· | O_{t_o}, t_o, t_a)

t_o는 각 관측의 캡처 시각, t_a는 요청한 행동 실행 시각입니다. 둘의 간격에 관측 주기, 측정 나이, 추론 지연, 실행 주기가 모두 담깁니다.

논문이 내세우는 기여는 세 가지입니다(§1).

  1. 로봇 정책 학습을 물리 시간 위에서 정식화했습니다.
  2. 비동기·다중 주기 관측을 고정 격자에 맞추지 않고 그대로 학습하는 time-aware RoPE diffusion transformer를 제안했습니다.
  3. 현실적인 시간 변동을 넣은 벤치마크를 만들고, 동적 과제(관측-행동 시간)와 다중 감각 과제(관측-관측 시간)에서 개선을, 준정적 과제에서 성능 유지를 보였습니다.

2. Method

2.1 시간 변동의 종류 (Fig. 1)

논문은 실제 로봇의 시간 변동을 여섯 가지로 나눕니다: 센서 샘플링 주기, 관측 지연, 누락(dropout), 추론 지연, 제어 주기, 실행 지연. 과제 유형마다 중요한 시간 관계가 다릅니다.

과제 유형 중요한 시간 관계 예
동적 관측 시각 ↔ 행동이 효과를 내는 시각 움직이는 컨베이어, 회전하는 받침접시
다중 감각 서로 다른 관측의 캡처 시각 영상 20 Hz, 자세 20 Hz, 힘/토크 90–100 Hz
준정적 학습 때와 배포 때 시간 조건의 차이 DexMimicGen 6과제

2.2 물리 시간 정식화 (§3.1, Eq. 2–3)

요청 시각 t에서 H개 행동 chunk의 실행 시각을 다음처럼 둡니다.

t_{a,j} = t + d_t + j·Δt_a, j = 0, …, H−1

d_t는 첫 행동까지의 지연, Δt_a는 행동 간격(20 Hz → 50 ms)입니다. 다중 감각 입력은 모달리티마다 자기 캡처 시각을 그대로 유지합니다.

2.3 time-aware RoPE (§3.2, Eq. 4–6)

모든 토큰에 요청 시각 기준 상대 시각 t̃_i = t_i − t를 붙입니다(Eq. 4). 이미지 패치는 프레임 캡처 시각을, 자세·힘 토큰은 측정 시각을, 행동 토큰은 요청 실행 시각 d_t + jΔt_a를 받습니다. 이 값을 RoPE의 회전 좌표로 씁니다.

q̃_i = R(t̃_i) q_i, k̃_j = R(t̃_j) k_j → q̃_iᵀ k̃_j = q_iᵀ R(t_j − t_i) k_j

따라서 attention은 경과 시간 t_j − t_i에만 의존하고, 시계 원점을 옮겨도 변하지 않습니다. 토큰 내용(embedding)은 건드리지 않고 시간은 attention의 위치 관계로만 들어갑니다. 저자들은 이 "내용과 시간의 분리"를 시간 임베딩을 토큰에 더하는 방식(AddTime)보다 강건한 이유로 듭니다.

구현 세부(부록 A.2): 주기 0.1–2 s 사이 로그 간격의 16개 query-key 좌표쌍을 회전합니다. 폭 512, head 8개라 head 차원은 64(32쌍)이므로, head마다 절반만 시간으로 회전하고 나머지 절반은 시간과 무관한 채널로 남는 것으로 보입니다(본문에 명시되지는 않았고, 숫자에서 추론한 것입니다. 03 §1).

논문 Fig. 2: 비동기·불규칙 토큰 → 물리 시각으로 회전하는 time-aware RoPE → 공유 물리 시간 축.

2.4 시간 무작위화 (§3.3, 부록 B.2)

학습 때 시연마다 다음을 무작위로 바꿉니다.

  • 관측: 스트림마다 주기 12.5–33.33 Hz와 전달 지연 0–50 ms를 따로 뽑습니다. 원본 데이터는 100 Hz입니다. Pivoting의 힘/토크는 1–100 Hz, 지연 0–100 ms입니다.
  • 행동 시작 지연: chunk의 절반은 지연 0, 나머지는 0–100 ms에서 뽑습니다.

뽑힌 측정은 원래 캡처 시각을 유지합니다. 그래서 같은 토큰 위치가 서로 다른 물리 간격에 대응해도 정책이 시각을 보고 해석할 수 있습니다. 부수 효과로, 고정 주기로 다운샘플링하면 버려질 측정까지 학습에 쓰게 되어 데이터 증강이 됩니다.

학습 목표는 표준 diffusion 손실입니다(Eq. 7–8). clean-action 예측과 ℓ1 손실을 씁니다.

2.5 배포 (§3.4)

  • chunk를 비동기로 실행합니다. 다음 chunk를 추론하는 동안 이전 chunk를 계속 실행합니다.
  • 시뮬레이션에서는 주입한 추론 지연으로 d_t를 정합니다. 실제 로봇에서는 이전 요청들의 완료 시간으로 d_t를 추정합니다.
  • 새 예측이 도착하면, 실행 시각이 이미 지난 행동은 버리고 나머지를 t_a에 맞춰 실행합니다.

4. Limitations

4.1 저자가 밝힌 한계 (§5)

  • 행동 주기는 고정(20 Hz)입니다. 가변 제어 주기와 시간 배율 조절(시연보다 빠르게나 느리게 실행)은 향후 과제로 남겼습니다.

4.2 분석하면서 추가로 발견한 한계와 의문점

  1. "Small obs." 조건은 Chronos의 학습 무작위화 범위와 정확히 같습니다(12.5–33.33 Hz, 0–50 ms). Chronos에게는 학습 분포 안이고, 무작위화 없이 학습한 DP에게만 분포 밖입니다. 공정한 비교 상대는 DP + 무작위화입니다(Conveyor 60.9 vs 77.6, Pivoting 30.0 vs 64.9). 프로젝트 페이지 데이터도 이 조건을 sensor_id, Wide를 sensor_ood라고 부릅니다(03 §3).
  2. 표준 과제와 실제 로봇에는 "DP + 무작위화" 기준선이 없습니다. Conveyor에서는 무작위화만으로도 교란 평균이 6.3 → 26.9로 올랐습니다. 그래서 표준 과제의 59.7 → 73.4, 실제 로봇의 차이 중 얼마가 시각 정보 덕이고 얼마가 데이터 증강 덕인지 나눌 수 없습니다.
  3. Pivoting과 RoPE-vs-AddTime 결론은 시드 3개로는 통계적으로 약합니다. Pivoting의 Chronos-DP 차이는 6개 조건 모두에서 시드 단위 p > 0.2입니다. AddTime은 시드 하나만 잘 되고 둘은 무너진 패턴입니다(nominal 시드별 110, 61, 56/150). 이는 표현 방식의 차이라기보다 학습 불안정일 수 있습니다(03 §5).
  4. 실제 로봇은 조건당 10–20회입니다. 12개 조건에서 모두 최고라는 서술은 맞지만, 조건별 차이 24개 중 permutation p < 0.05는 1개뿐입니다. 4개 조건을 합치면 과제별로 유의합니다(Peg vs DP만 p = 0.09).
  5. 실제 로봇 학습의 무작위화 범위가 적혀 있지 않습니다. 부록 B.2의 범위는 시뮬레이션 절에 있습니다. 실제 평가의 자세 주기 하한(8.33 Hz)과 힘/토크 범위(37.5–150 Hz)가 학습 범위 안인지 판단할 수 없습니다.
  6. 이력 처리 방식이 불분명합니다. 학습 때 힘/토크를 1–100 Hz로 뽑고 32개를 쓰면, 1 Hz에서는 이력이 31초에 이릅니다. 에피소드 시작 부분이나 오래된 측정을 어떻게 처리했는지 적혀 있지 않습니다.
  7. 기준선 세부가 부족합니다. DP가 어떤 인덱스 위치 인코딩을 쓰는지, 실제 로봇에서 d_t를 어떻게 추정하는지(이동 평균인지, 최댓값인지)가 없습니다.
  8. 용어가 섞여 있습니다. 같은 조건을 "Large"(Table 2), "Wide sensors"(Table 3), "large"(Fig. 3), sensor_ood(웹 데이터)로 부릅니다. Pivoting은 웹 데이터에서 flipup입니다. Table 3의 "Delay" 열은 관측 지연이 아니라 추론 지연입니다.
  9. 코드가 공개되지 않았습니다. 그래서 이 분석의 검증은 수치 정합성과 toy 수준입니다.

1. time-aware RoPE가 계산하는 것 (V1)

RoPE는 2차원 좌표쌍마다 각도 ω_k·t만큼 회전합니다. 회전행렬은 R(a)ᵀR(b) = R(b − a)를 만족하므로 다음이 성립합니다.

(R(t_i) q)ᵀ (R(t_j) k) = qᵀ R(t_j − t_i) k

  • 확인: 무작위 q, k(32차원 = 16쌍)와 시각 1,000쌍으로 계산하면 두 식의 최대 오차는 7.8×10⁻¹⁴입니다. 모든 시각을 ±100 s 옮겨도 내적은 최대 7.4×10⁻¹²만큼만 변합니다. 즉 Eq. 6과 "시계 원점에 불변"이라는 서술은 정확합니다.
  • 부분 회전으로 보입니다. 부록 A.2는 "16개 query-key 좌표쌍을 회전한다"고 씁니다. 폭 512, head 8개면 head 차원은 64 = 32쌍입니다. 따라서 head마다 절반은 시간으로 회전하고 절반은 회전하지 않는 구성으로 보입니다(GPT-NeoX의 부분 rotary와 같은 형태). 회전하지 않는 절반은 시간과 무관하게 내용만으로 attention 점수를 만듭니다.
  • AddTime과의 차이에 대한 해석(가설): AddTime은 시간 특징을 MLP에 통과시켜 토큰 자체에 더합니다. 그래서 학습 때 보지 못한 시간 차이에서는 토큰 내용이 예측할 수 없게 바뀝니다. RoPE는 내적의 시간 의존 부분만 바뀌고, 회전하지 않는 절반은 그대로입니다. 저자들의 "내용과 시간의 분리"가 구조적으로는 이 절반 채널로 구현된 것으로 보입니다. 다만 AddTime 결과 자체가 불안정해서(§5.3) 이 비교의 근거는 약합니다.

2. 시간 커널: 해상도와 되풀이 (V2)

16개 주기(0.1–2 s, 로그 간격)가 만드는 시간 유사도 s(Δt) = mean_k cos(ω_k Δt)를 계산했습니다(timing_coverage.png (b)).

항목 값 의미
s가 0.5로 떨어지는 Δt 45 ms 행동 간격(50 ms)과 비슷합니다. 인접 행동 토큰이 attention에서 구별됩니다
|Δt| ≥ 0.5 s에서 |s| 최대 0.34 멀리 떨어진 시각이 가까운 시각처럼 보이는 강한 되풀이는 없습니다
가장 느린 성분이 한 바퀴 도는 Δt 2 s 토큰 쌍 간격이 2 s를 넘으면 이 성분은 되풀이됩니다
간격이 2 s를 넘는 샘플 비율 Wide 0.5%, Combined 0.8% 되풀이는 성능 저하의 주원인이 아닙니다

처음에는 "Wide 조건에서 오래된 관측이 2 s 주기를 넘어 RoPE가 되풀이되기 때문에 성능이 떨어진다"는 가설을 세웠습니다. 계산해 보니 그런 샘플이 1% 미만이라 이 가설은 기각합니다. 주기 범위 선택은 이 실험의 시간 범위에 맞게 되어 있습니다.

3. 학습 때와 평가 때의 시간 범위 (V3)

부록 B.2(학습)와 Table 2(평가)의 설정을 시뮬레이션했습니다. 스트림마다 위상이 무작위인 균일 샘플링, 요청 시각까지 도착한 측정 중 최신 n개를 쓴다고 가정했습니다. 이 가정은 논문에 명시되지 않은 부분입니다.

여기서 세 가지가 나옵니다.

  1. Small obs.는 Chronos에게 학습 분포 그 자체입니다. 주기 12.5–33.33 Hz와 지연 0–50 ms가 학습 무작위화 범위와 같습니다. 웹 데이터도 이 조건을 sensor_id라고 부릅니다. 그러므로 "Small에서 DP 15.6 vs Chronos 77.6"(Conveyor)은 같은 분포로 학습했는지의 차이가 대부분입니다. 시각 정보의 기여는 같은 무작위화로 학습한 DP와 비교해야 합니다: Conveyor 60.9 → 77.6(+16.7), Pivoting 30.0 → 64.9(+34.9).
  2. Wide와 Combined는 모든 방법에게 분포 밖입니다. 샘플의 23.6%는 학습 때 보지 못한 관측 간격(최대 약 1 s)을 갖고, 관측 나이는 학습 최대의 10배까지 늘어납니다. 이 조건에서 Chronos도 크게 떨어지는 것(Conveyor 77.6 → 45.6)은 ① 1 Hz 영상이 정보 자체를 잃는 것과 ② RoPE가 학습 범위 밖 시간차로 외삽하는 것이 겹친 결과로 보입니다. 둘을 나누려면 학습 무작위화를 1–50 Hz로 넓힌 실험이 필요합니다.
  3. Delay 0–200 ms도 절반은 분포 밖입니다. 학습 때 행동 시작 지연은 최대 100 ms였으므로, U(0, 200 ms)에서 뽑힌 지연의 절반이 학습 범위를 넘습니다. 그래도 Conveyor에서 83.1 → 76.4로 비교적 덜 떨어집니다. 행동 토큰 시각의 외삽은 0.85 s → 0.95 s 정도로 작기 때문입니다.

힘/토크 이력: 학습 때 힘/토크를 1–100 Hz로 뽑고 32개를 쓰면, 이력 길이의 중앙값은 0.61 s이고 p99는 15.6 s입니다(1 Hz에서는 31 s). 에피소드 길이보다 길 수 있으므로 실제로는 잘라 내거나 채우는 처리가 있었을 텐데, 논문에 적혀 있지 않습니다.

4. 시간 정보가 없는 정책은 무엇을 틀리나 (V4)

Conveyor 직관을 수치로 옮겼습니다.

  • 속도 추정 배율: 학습 때 이미지 간격이 항상 50 ms였던 정책이, 실제 간격 g로 찍힌 두 영상을 보면 물체 속도를 (g / 50 ms)로 나눈 값만큼 틀리게 해석합니다. 그 배율의 p1–p99 범위는 Small에서 0.60–1.57배, Wide에서 0.40–13배입니다. 속도를 ±40–60% 잘못 보면 벨트 위 물체를 놓치기 쉽습니다. 이것이 DP의 Small 성능 붕괴(73.1 → 15.6)와 맞습니다.
  • 추론 지연: 지연 d_t를 모르면 목표 위치가 v·d_t만큼 어긋납니다. 벨트 속도는 논문에 없으므로 0.1 m/s를 예로 들면, 0–200 ms 지연에서 평균 1 cm, 최대 2 cm입니다. 컵 받침이나 컨베이어 위 물체를 잡는 데는 충분히 큰 오차입니다.

5.3 Pivoting: 방향은 같지만 유의하지 않음 (S3)

  • Chronos vs DP: 6개 조건 모두 시드 단위 p = 0.24–0.92입니다. Combined 38.4 vs 19.6도 p = 0.24입니다.
  • Chronos vs AddTime: 6개 조건 모두 p = 0.13–0.31입니다. AddTime은 nominal에서 시드 하나만 73%이고 둘은 37–41%입니다. 이 패턴은 표현 방식의 차이보다 학습 불안정에 가깝습니다.
  • Chronos vs RoPE 무작위화 없음: Wide에서만 p = 0.03입니다.
  • 반면 DP + 무작위화가 Pivoting을 해친다는 결과(nominal 61.6 → 29.8)는 효과가 커서 방향이 분명합니다.

따라서 "다중 감각 과제에서 시간 정보가 강건성을 높인다"(§4.2)와 "RoPE가 AddTime보다 낫다"(Pivoting 부분)는 시드를 늘려 확인해야 할 주장입니다.

4. 구현 가능성 판단

4.1 공식 코드로 재현하는 경우

  • 코드가 공개되지 않았습니다. Conveyor와 Pivoting은 저자들이 만든 벤치마크라 코드 없이는 재현할 수 없습니다.
  • DexMimicGen 6과제는 공개 벤치마크라 기준선(DP)은 재현할 수 있습니다. 16층 DiT + SigLIP2, 시드 3개 × 6과제 × 2방법이면 GPU 수십–수백 시간이 필요할 것으로 추정합니다(논문에 계산량 미기재).

4.2 핵심 아이디어를 다시 구현하는 경우 (코드 없이 가능)

  • time-aware RoPE는 기존 transformer 정책에서 위치 인덱스를 상대 시각(초)으로 바꾸고, 주기 0.1–2 s 로그 간격 16쌍만 회전하면 됩니다. 수십 줄 수준의 변경입니다.
  • 시간 무작위화는 데이터 로더에서 스트림별 주기·지연을 뽑아 측정을 고르는 일입니다. 원본 데이터에 스트림별 캡처 타임스탬프가 있어야 합니다.
  • 작은 1차원 toy(움직이는 표적, 불규칙 관측)는 CPU로 학습할 수 있습니다. 이 기기에는 torch가 없어 설치가 필요합니다.

3. 이 저장소의 다른 논문과의 관계

  • do_as_i_do: Do as I Do의 SAM 3D guided blending은 마지막 스텝에서 EMA 필터와 같았고(do_as_i_do/analysis/03_derivations.md), 그 05의 A1은 "flow action head에 적응형 guided blending을 넣되 RTC를 확인한 뒤 신규성을 판단"이었습니다. Chronos는 RTC를 기준선으로 직접 비교하고 "비동기 실행과 시간 인식은 상보적"이라고 결론냅니다. 따라서 chunk 연속성 아이디어를 평가할 때는 RTC와 Chronos식 타임스탬프를 둘 다 비교 대상으로 두어야 합니다.
  • dexscrew: DexScrew의 BC는 촉각과 관측 이력을 20 Hz 제어 스텝 단위로 넣고, 분석 결과 촉각보다 이력의 효과가 더 뚜렷했습니다(dexscrew/analysis/01_paper_analysis.md). 촉각은 보통 제어 주기보다 빠르게 들어오므로, Chronos의 Pivoting 설정처럼 "제어 격자에 맞추지 않고 캡처 시각과 함께 넣는" 대안을 시험해 볼 수 있습니다. 다만 Chronos에서도 다중 감각 쪽 개선은 시드 단위로 유의하지 않았습니다(03 §5).
  • gpt6_astra_tactile: 그 분석의 D2 가설은 느린 LLM 계층(약 0.05 Hz)이 전략을 정하고 빠른 정책(20 Hz 이상)이 촉각에 반응하는 구조이고, ablation에 느린 계층 지연 주입(0/5/20 s)이 있습니다. 느린 계층의 출력은 큰 지연을 두고 도착하므로, 그 출력에 "언제 만든 계획인지" 타임스탬프를 붙여 빠른 정책에 주는 것이 Chronos식 해법입니다.
  • hydra0: Hydra-0은 이미지 평면 점 궤적(action flow)을 조건으로 영상을 생성합니다. Chronos가 가장 가깝다고 꼽은 BulletTime도 영상 생성에서 연속 시각을 RoPE로 넣습니다. world model과 정책이 같은 "물리 시각 좌표"를 공유하면, 서로 다른 프레임레이트의 데이터를 섞을 때 유리합니다.
  • flashdexretarget: FlashDexRetarget은 K = 10개 미래 레퍼런스 프레임을 조건으로 씁니다. 사람 시연 데이터셋(TACO, OakInk2, HOT3D)은 프레임레이트가 서로 다릅니다. 레퍼런스 프레임을 인덱스가 아니라 물리 시각으로 주면 데이터셋 간 주기 차이를 흡수할 수 있습니다.
