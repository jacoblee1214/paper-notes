# 04. 주장 검증 (공식 코드 없음)

이 논문의 공식 코드를 찾지 못했습니다(`02` §4). 그래서 논문 ↔ 코드 대조(D1–Dn) 대신 **주장 검증(C1–Cn)**을 합니다. 검증 방법은 세 가지입니다. (a) 식과 표의 산술을 다시 계산(`03`), (b) 주장을 뒷받침하는 증거가 본문과 표에 있는지 확인, (c) 기반 코드(LeWM 공식, 커밋 `8edfeb3`, MIT)의 CEM과 PushT 설정이 논문 설정과 맞는지 정적으로 대조. 기반 코드는 실행하지 않았습니다. 게이트 코드는 기반 코드에 없습니다.

## 2. 주장별 증거의 강도 (요약)

- **확실한 것:** 계산량 감소(C4), 산술 일관성(C2, C3, C7의 계산), Cube에서 깊이 효과가 없다는 점(C9), PushT 개발에서 깊이 5 → 15의 이득(C10).
- **방향은 맞지만 통계는 약한 것:** 시간 절약(C5), 같은 작업량 이득(C6). 구간이 0을 포함하고 부호가 시드마다 다릅니다.
- **검정되지 않은 것:** 성공 손실(C8). 이 논문의 결론에서 "성공을 덜 잃는다"는 주장은 하지 않지만, 초록의 "observed success rate was 5.36 percentage points above" 문장이 독자에게 이득으로 읽힐 수 있습니다.
- **재현에 필요한 정보가 없는 것:** 게이트 계수, 임계값 결정, 레이블 정의(C13).

## 3. 기반 코드(LeWM 공식)와 논문 설정 대조

기반 코드 `repo/config/eval/`(정적 읽기):

| 항목 | 논문 | 기반 코드 기본값 | 판정 |
|---|---|---|---|
| 계획 길이 H, 실행 상한 K, 행동 묶음 b | 5, 5, 5 (표 1) | horizon 5, receding_horizon 5, action_block 5 (`pusht.yaml`) | 일치 |
| 명령 상한 T | 50 | eval_budget 50 | 일치 |
| 목표 시점 오프셋 | 25 | goal_offset_steps 25 | 일치 |
| CEM 후보 수 M | 300 | num_samples 300 (`cem.yaml`) | 일치 |
| 엘리트 수 L | 30 | topk 30 | 일치 |
| CEM 반복 수 | 주 실험 J = 15 (고정), 개발 5·15·30 | n_steps 30 (기본) | 기본값은 30. 논문이 15와 5를 고른 것은 실험 설계 선택 |
| 장면 수 | 주 실험 16 장면 x 시드 2 | num_eval 50 | 같은 환경 설정에서 다른 표본 크기 |
| 장치 | RTX PRO 4000 (시간 측정) | `device: "cuda"`, `eval.py`에 `.to("cuda")` 하드코딩 | 맥에서는 수정 필요 (`04` §4) |

- 설정은 대부분 맞습니다. 특히 CEM 300·30과 b·H·K = 5 설정은 같습니다. 따라서 논문의 "고정 깊이"를 기반 코드로 재현하는 것은 설정 측면에서는 가능합니다.
- 기반 코드는 게이트 관련 코드가 없습니다. 게이트, 패딩, 종점 혼합 계산은 기반 코드 밖입니다.

## 4. 구현 가능성 판정

**판정: 조건부 구현 가능. 논문의 수치 재현은 이 맥에서 불완전합니다.**

이 맥은 Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음입니다.

| 구성 요소 | 이 맥 | 필요 자원 | 판단 |
|---|---|---|---|
| 게이트 식 (d5, g5, s5, 로지스틱, 임계값) | 가능 | 엘리트 비용과 제안 평균을 저장하는 코드. CPU로 충분 | **구현 가능** (수 시간, 추정) |
| 종점 혼합과 통계 재계산 | 가능 | 표 값만. 이미 완료 (`03`) | **완료** |
| LeWM PushT 체크포인트 로드와 CEM 평가 | 조건부 | 체크포인트 다운로드(HF `quentinll/lewm-pusht`, 크기 미확인), stable-worldmodel 설치(승인 필요), `device` 수정 | **조건부 (승인과 설치 후)**. MPS 동작은 미확인 |
| 표 4의 다섯 제어기 32 궤적 재현 | 조건부 | 위와 같음. 한 궤적에 CEM을 여러 번 호출. 시간은 측정 전 | **조건부**. 처리량 미측정. 시간 수치는 RTX와 같을 수 없음 |
| OGBench-Cube 전이 | 조건부 | Cube 환경과 체크포인트 | **조건부** |
| 학습 재현 (LeWM 자체) | 불가 | GPU와 대규모 데이터 (기반 코드 README는 학습 설정을 제공하지만 이 논문의 학습은 아님) | **불가 (이 논문에 필요하지 않음)** |
| 저자 게이트 계수 재현 | 불가 | 계수가 공개되지 않음 | **재학습으로 대체해야 함** |

- **노력 추정 (판단, 측정 아님):** 게이트를 개발 장면에서 다시 학습하고 PushT 축소 비교를 맥에서 돌리는 데 1–2주. 저자의 계수와 값을 맞추는 데는 충분하지 않을 가능성이 큽니다.
- **가장 큰 장애:** 계수와 τ의 정의가 없고, 장면별 결과가 없습니다. 맞춰 볼 기준이 없어서 "재현했다"를 판정할 수 없습니다.

## 5. 저자에게 물을 질문 (메모, 발송하지 않음)

1. 게이트 계수 w, β0와 임계값 τ = 0.3966의 결정 절차와 개발 세트 크기.
2. 게이트 레이블 정의(고정 깊이 전체 결과 중 무엇을 썼는지)와 시드별 작업량 W.
3. 장면별 짝지은 결과(32 궤적)와 시간 원자료(배치 4개의 개별 값).
4. 종점 혼합 기준선의 시간 측정이 몇 회 반복으로 얻어졌는지.
