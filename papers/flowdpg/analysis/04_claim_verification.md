# 04. 주장 검증과 구현 가능성

공식 코드가 없어서(2026-11-22, `02` §4) 코드 대조(D 항목) 대신 **논문의 주장 C1–C12를 표, 그림, 식과 비교**했습니다. 계산은 `03`, 토이는 `analysis/toy_dpg.py`입니다. 판정은 **확인**(수치와 논리가 맞음), **부분 확인**(점 추정은 맞지만 증거가 약하거나 한 조건에서만), **근거 부족**(검정되지 않았거나 논문 안에서 검증 불가), **불일치**(논문 안에서 서로 어긋남)입니다.

## 1. 대조 범위

- 대상: v2 본문 §3–§5, 표 1–3, 그림 4–6, 부록 A–D. 하이퍼파라미터는 v1 부록 표 3에서 가져왔고 v2에는 없습니다(`01` §6).
- 제3자 구현(LeRobot 패치, `02` §4)은 참고했지만 clone하지 않았고 이 문서의 판정에 쓰지 않았습니다.
- 실행, 설치, 가중치와 데이터 다운로드는 하지 않았습니다.

## 3. 비교에서 빠진 것 (저자에게 확인할 것)

1. **BPTT 기준선:** 같은 백본에서 ODE 전체 역전파 DPG나 EDP식 한 단계 기울기(직접 역전파)와의 비교. 논문의 핵심 동기인데 비교가 없습니다.
2. **FQL류 한 단계 정책:** §2에서 "청크 배포 시 불가"라고만 쓰고 비교하지 않았습니다.
3. **시드:** 방법마다 학습 한 번. 그림 4 오차막대의 의미.
4. **단계별 분모와 분자:** 표 1의 단계별 비율이 어떻게 계산됐는지, 기준선 셀의 분모.
5. **표 1과 그림 4의 −2점:** 롤아웃 공유 여부.
6. **보상 척도:** β_stage, 종료 보너스, γ, 반환 정규화, Q 값 33.6과 54.2의 단위.
7. **L_cons와 BC 가중:** 일관성 정규화를 빼면서 BC 가중을 같게 맞춘 절제.
8. **λ_max, α, 워밍업 스텝**(v1 값이 v2에서도 같은지).
9. **계란 과제의 성공률과 단계별 점수.**
10. **QAM 구현:** 어떤 코드와 하이퍼파라미터를 썼는지(`02` §4의 공식 QAM 저장소를 썼는지).

## 4. 구현 가능성 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**논문 결과의 재현은 불가능합니다. 알고리즘은 구현할 수 있고, 작은 과제에서의 축소 검증은 이 맥에서 가능합니다.** 공식 코드, 데이터, 가중치가 모두 없습니다.

| 대상 | 이 맥에서 | 근거 |
|---|---|---|
| FlowDPG 정책 추출(식 4–9)과 IQL 크리틱 | **구현 가능** | 흐름 정합 정책 위에 손실 몇 개를 얹는 일이라 PyTorch로 300–500줄, 3–5일(추정). 이 분석의 `toy_dpg.py`가 같은 식을 이미 돌렸고 약 1분(CPU)입니다 |
| 작은 시뮬레이션 과제에서의 축소 검증(저차원 상태 정책, MuJoCo 도달·조작, 해석 크리틱과 학습 크리틱 비교) | **가능**(시작 가능) | mujoco 4.0과 torch 2.15가 이미 있어 새 설치 없음. 노력 1–2주(추정, 처리량 미측정) |
| LIBERO 단일 과제 오프라인(제3자 구현 방식) | 조건부 | 제3자 구현은 LeRobot, LIBERO, RTX 4090, 50 에피소드 평가를 씀. LeRobot과 LIBERO 설치(승인 필요)와 이미지 데이터 다운로드가 필요하고 맥 처리량은 미확인 |
| 행동 머리 단독(DiT 14층, 1024차원, 176 M 파라미터) 학습 | **느림** | 이 맥 MPS에서 한 스텝 0.67 s(배치 64, 비전 백본과 크리틱 제외, 다른 작업과 동시 실행) → 배치 256, 10,000 스텝이면 하한 약 7.5시간(`analysis/bench_dit_step.py`). 온라인 6,000 스텝은 별도 |
| 비전 백본 합동 학습(DINOv2 ViT-B/14, 카메라 4대, 640×480) | **불가** | 배치당 이미지 토큰이 수천 개여서 24 GiB 통합 메모리에서 배치 256은 현실적이지 않음(측정하지 않은 추정). 온라인 단계는 백본이 얼려 있어 다르지만 오프라인은 합동 학습 |
| 에어팟·계란 실로봇 재현 | **불가** | Franka 두 대 또는 YAM 두 대, GELLO 원격 조종 시연, 카메라, 25 케이스 평가, 온라인 롤아웃 수집(시간당 약 25 케이스, 프로젝트 페이지) |
| SARM 보상 모델 | 조건부 | SARM [26]의 공개 여부와 가중치는 확인하지 않음. 단계 주석 데이터가 필요 |
| 논문 수치 재현 | **불가** | 시연, 가중치, 코드 모두 비공개. 하이퍼파라미터는 v1에만 있음 |

**노력 추정:** 알고리즘 이식 3–5일, 작은 시뮬레이션 축소 검증 1–2주, 공개 데이터와 코드를 쓰는 중간 규모(LIBERO)는 GPU 기기에서 며칠 더(모두 추정, 측정 전).

**구현할 때 가장 위험한 부분:** (1) 보상 척도와 γ, 반환 정규화(Q 값이 보상 상한을 넘는 원인 불명, `03` V5), (2) L_cons와 BC 가중의 얽힘(`03` K3), (3) 크리틱 기울기의 잡음 민감도(`03` K4), (4) 흐름 시각 샘플링 분포(논문은 균등, LeRobot 기본은 작은 t 치우침, `02` §4).
