# 04. 공식 코드 대조와 구현 가능성

대상: `Bottle101/ForceBand` (Apache-2.0), 커밋 `4e02176289acb3b70121ead16f3d1272a0b0d67d` (2026-10-28 "updated BOM."), 얕은 복제를 `repo/`에 두고 **정적으로만** 읽었습니다(실행, import, 설치, 체크포인트·데이터 내려받기 없음). `repo/`는 `git clone --depth 1 https://github.com/Bottle101/ForceBand repo` 로 받은 상태입니다. 체크포인트와 `data/` 파일은 Git LFS 포인터만 있어 내용은 읽지 못했고 크기만 확인했습니다. 번호 D는 논문과 코드의 차이 항목입니다.

## 1. 저장소 범위와 라이선스

- 포함: EMG2Force 모델(`emg2force/`: `encoder.py`, `model.py`, `lightning.py`, `data.py`, `eval.py`), 평가·보정·학습 스크립트(`scripts/`), 설정 한 개(`configs/models.json`), 체크포인트(116,115,839 byte, LFS), 검증 구간 7개와 데모 94개(LFS 포인터), 참고 지표 CSV.
- 없음: 정책 학습(흐름 매칭), 사람 영상에서 로봇 관측으로의 변환(Aria, SAM2 등), 로봇 힘 제어(PD, Paxini), 기준선(FEEL, VISOR-HOS), 전극 배치 비교 자료와 코드, 표 2 평가 기록. 논문 §4, 표 2, 표 1 오른쪽은 이 저장소로 다룰 수 없습니다.
- 라이선스: `LICENSE`는 Apache-2.0이고 `pyproject.toml`이 이를 가리킵니다. 사용한 백본은 DINOv2(Apache-2.0)이며, 코드 주석은 DINOv3가 "custom (non-Apache) license"라서 출하하지 않았다고 적습니다.
- 열린 이슈 4건: 사용자 ID·기록-사용자 대응표(#6), 전체 데이터 공개 시점(#3), 카메라-EMG 동기화와 DIY 매뉴얼(#2), BOM(#1).

## 3. README 수치와 논문 수치의 관계

- 릴리스 체크포인트의 검증 MAE는 센서 단위 17.63(약 0.98 N), RMSE 39.85(약 2.21 N), r2 0.453, Pearson 0.698입니다. 손가락별 r2는 엄지 0.68, 검지 0.65, 중지 0.50, 약지 0.19, 소지 0.25이고, README도 "약지와 소지는 힘이 작고 노이즈가 많다"고 적습니다.
- 논문 그림 5D의 손가락별 MAE와 비교하면 약지·소지·중지는 같은 범위(0.26–0.86 N)이고, 엄지·검지는 저장소 값이 큽니다(2.03/1.34 대 1.45/1.06 N). 검증 자료가 다르다는 점을 감안해야 합니다(`03` V10).
- 보정 전 제로샷의 r이 0.59인데 r2가 −4.94인 것은 예측의 크기 불일치로 설명할 수 있습니다(`03` V13). 논문의 "짧은 사용자별 보정이 필요하다"는 서술은 저장소 수치와 방향이 같습니다.

## 4. 구현 가능성 판정 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**판정: 논문 전체(밴드 제작, 데이터 수집, 정책 학습, UR-5 실험)는 이 맥에서 구현·재현할 수 없습니다. EMG2Force 한 부분(체크포인트 평가와 보정)은 설치와 내려받기 승인 뒤 이 맥에서 할 수 있을 가능성이 크고, 그 축소판은 직접 구현할 수 있습니다.**

| 구성 요소 | 이 맥에서 | 필요한 것 |
|---|---|---|
| 표·그림 수치 재계산 | **완료** (`03`) | 없음 |
| 합성 신호 토이 | **완료** (`toy_calibration.py`, 수 초) | 없음 |
| 릴리스 체크포인트 평가 (검증 약 14분 분량, 약 84개 10 s 창 추정) | 가능성 큼, **미시도** | 패키지 설치(timm, pytorch-lightning, h5py 등), 체크포인트 116 MB와 검증 약 84 MB 내려받기 승인. 평가 코드(`eval.py`)는 CUDA가 없으면 CPU를 고르므로 수정 없이 돌 가능성이 있고, 보정·학습 스크립트(`finetune.py`, `train.py`)는 `accelerator="gpu"`로 고정이라 MPS 또는 CPU로 고쳐야 합니다. 창 하나의 순전파는 ViT-S가 약 1,400 토큰을 처리하므로 수 초 이내로 추정(측정 전) |
| 사용자 보정 미세조정 (데모 36개) | 가능성 있음, **미시도** | 위와 같고 `finetune.py`의 장치 고정 수정, 데모 24 MB. 시간은 측정 전 |
| 전체 사전학습 (8.6 h, 300 epoch) | **사실상 불가** | HF 시계열 약 0.56 GB(영상 7.7 GB는 불필요), 창마다 ViT 순전파 약 1,400 토큰 × 보폭 1/4 중첩 × 300 epoch. 1 epoch당 수십 분, 전체 100 h 이상으로 추정(측정 전) → GPU 필요 |
| EMG2Force 축소판 (DINO 없이 1-D 합성곱 + 작은 변환기) | **가능** | HF 시계열 0.56 GB 내려받기 승인, torch(설치됨) + h5py. 논문이 말한 스펙트로그램 분기의 효과를 작은 모델로 점검하는 용도 |
| 힘 포함 정책 (흐름 매칭, 사람 영상 변환) | 불가 | 저장소에 코드 없음. Grounding DINO, SAM2, CoTracker, Orient-Anything, LaMa, Aria MPS가 필요하고 GPU 위주. UR-5, Robotiq, Paxini 센서 4개, ZED 2i 필요 |
| 밴드 제작과 자료 수집 | 불가 (하드웨어) | OpenBCI Cyton 계열 보드, 전극, FSR과 골무, 3D 프린터. BOM은 공개됨(Google Sheets, 열어 보지 않음) |
| 표 2 실로봇 평가 | 불가 | 위 로봇 + 정책 체크포인트(미공개) |

**노력 추정(측정 전 추정):**

- 체크포인트 평가와 보정을 이 맥에서 돌리는 것: 설치와 GPU 고정 수정 포함 1–2일.
- EMG2Force 축소판 구현과 공개 시계열 자료로 비교: 1–2주.
- 힘 포함 정책의 구현(변환 파이프라인 포함)과 로봇 평가까지: 저장소가 없어 수 개월 규모이고 로봇과 GPU가 필요합니다.

## 5. 이 대조의 한계

- 체크포인트와 데이터 내용을 읽지 않았으므로 `proj8to3`의 학습 여부, 릴리스 모델의 실제 입력 통계, 검증 구간의 사용자 구성은 확인하지 못했습니다.
- 코드를 실행하지 않았습니다. README의 수치는 저장소가 적은 값이며 재현하지 않았습니다.
- 정책, 로봇, 기준선 코드가 저장소에 없어 표 2와 그림 5(기준선)의 재현 가능성은 판단할 수 없습니다.
