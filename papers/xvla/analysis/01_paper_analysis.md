## 1. 한 문단 요약

이 논문은 여러 로봇 데이터셋을 섞어 VLA를 사전학습할 때 생기는 **이질성**(하드웨어, 카메라 배치, 과제 분포)을 **데이터 원천마다 하나씩 두는 학습 가능한 soft prompt**로 흡수한다고 주장합니다 (§3, 식 없음). 백본은 Florence-Large 기반 VLM 인코더에 24층, 은닉 1024의 표준 self-attention Transformer를 얹은 flow-matching 정책이며, 이 0.9B 모델을 290K 에피소드(7개 원천, 5종 팔)로 사전학습하고, 두 단계(prompt warm-up 후 공동 미세조정)로 새 로봇에 적응시킵니다 (§4). 평가는 6개 벤치마크(Simpler, LIBERO, VLABench, RoboTwin-2.0, CALVIN, NAVSIM)와 실로봇 3종, 그리고 LoRA 9M 파라미터 PEFT로 이뤄집니다 (§5). 주장의 핵심은 "soft prompt가 HPT식 투영, 언어 프롬프트, 이종 어댑터, MoE보다 안정적으로 학습되고, 스케일링(모델·데이터 다양성·데이터량)에서 포화가 없다"입니다.

## 3. 방법

### 3.1 소프트 프롬프트 (§3, 식 없음)

- 원천 i마다 학습 가능한 벡터 p_i ∈ R^k를 둡니다. 저자 표현으로는 p_i ≈ Φ(h_i)이고 Φ는 명시적 규칙이 아닌 end-to-end 학습입니다.
- 비교한 네 방식은 (a) 도메인별 action 투영, (b) HPT식 관측 투영, (c) 언어 설명 프롬프트, (d) soft prompt (그림 2)입니다. 그림 4는 학습 곡선이라 수치는 추출하지 못했습니다.
- 대조 실험 설정 (그림 3, 부록 I): Florence-Base + DiT-Base (12층, 768), 8 A100, 배치 256, 200K 스텝. 같은 설정으로 비교합니다.
- 부록 E는 실패한 두 방식을 보고합니다. 이종 LoRA 어댑터는 백본 최적화와 충돌했고, 이종 MoE는 라우터가 몇 전문가로 붕괴했습니다.

### 3.2 X-VLA 구조 (§4.1, 그림 10)

- **고차원 관측 흐름:** 고정 시점과 언어는 Florence-Large의 VLM 인코더 전체를 통과하고, 손목 시점 등 보조 시점은 공유 시각 백본(ViT 인코더만)을 통과합니다 (§4.1-1, 부록 C). VLM에는 주 시점만 넣는 것이 특징입니다.
- **저차원 proprio–action 흐름:** 고유 자세(proprio) R_t, 잡음이 섞인 action A_t, flow 시간 T를 이어 붙여 선형층 하나로 사상합니다 (§4.1-2). 이 선형층 두 개(입력·출력)가 원천별 파라미터이며, 그림 10의 설명에 따르면 전체의 0.04%입니다.
- 공유 Transformer 블록 24개(은닉 1024, 16 head), 그 앞에 soft prompt를 붙입니다 (부록 C). 코드 기본값은 소프트 프롬프트 길이 32입니다 (`04` D1).
- **출력:** 30개 anchor 자세 (4초 분량 압축, §4.2.2 "intention abstraction").
- **손실:** 위치와 6D 회전은 MSE, 그리퍼는 BCE (§4.2.2). 그러나 공개 코드에서 AGIBOT 행동 공간은 그리퍼에도 MSE를 씁니다 (`04` D4).

### 3.3 학습 레시피 (§4.2)

- **사전학습** (§4.2.1, 부록 G): 64 A100, 전역 배치 1024, 200K 스텝, 약 4일. AdamW (β = 0.9, 0.95), lr 1e-4, weight decay 0.01, bf16, 224×224, ColorJitter.
- **두 단계 적응:** 새 원천의 프롬프트만 먼저 학습 (백본 동결), 다음에 백본과 프롬프트를 함께 학습 (§4.2.1, 부록 H는 동결 1000 + warm-up 1000).
- **원천별 학습률 축소** ("custom LR"): 프롬프트와 VLM 모듈의 학습률을 줄입니다 (§4.2.1). 축소 배율은 본문에 없습니다. 표 1에서 이 단계가 +35.5점으로 가장 큽니다.
- **균형 샘플링** (§4.2.2): 원천 사이와 궤적 사이를 섞는 방식. 기존 round-robin과 대비됩니다. 가중치는 부록 G 표 8에 있습니다.
- **데이터 구성** (그림 3, 표 8): AGIBOT-beta 141K (가중치 0.4), Droid 좌·우 각 45K (0.15), RoboMind Franka 19K (0.1), Dual-Franka 2K (0.03), UR 25K (0.1), Agilex 11K (0.07). 합 288K (본문은 290K). 원천 개수는 7개입니다.

### 3.4 적응과 PEFT

- 표 9: 벤치마크별 control 방식과 학습 스텝 (CALVIN, LIBERO, RoboTwin, VLABench, BridgeData, Simpler-Google, SoftFold 400K, PEFT 40K).
- PEFT는 LoRA를 씁니다. 본문은 rank를 적지 않았습니다. 공개 코드는 r = 8, α = 16, `all-linear`입니다 (`04` D12).

## 4. 실험과 결과

### 4.1 스케일링 (§5.1, 표 1, 그림 5)

- 표 1 (Simpler-WidowX 적응 성공률과 PT 검증 오차). 단계별 차분은 모두 맞습니다 (`03` §4). 최종 행은 Acc 95.8, PT 오차 0.032.
- 그림 5 "Scaling Behavior Across Model Size"는 R² = −0.925를 적어 두었습니다. 본문은 "포화 없음"이라고 쓰지만, 그림의 적합도 수치는 그 주장을 받쳐주지 못합니다.
- 검증 오차는 AGIBOT-beta에서 빼낸 189과제, 과제당 3궤적으로 만듭니다 (부록 G). 오류 지표는 ℓ1입니다. 그런데 §5.1은 "ℓ1 error between predicted actions"라고 쓰고, 표 1과 표 4는 Val Error로 씁니다. 같은 값인지는 확인되지 않았습니다.

### 4.2 벤치마크 (§5.2, 표 2–5, 표 11–16)

- **표 2 (주요 결과).** 5개 벤치마크의 평균 열에서 X-VLA는 "최고 기존 SOTA" 행을 이깁니다. LIBERO 평균 98.1 (기존 최고 97.1), NAVSIM PDMS 87.3 (81.7), VLABench 51.1 (39.7), RoboTwin Easy 70.0 / Hard 39.0 (46.4 / 16.4 기존 최고와 비교), Simpler 세 열 (80.4, 75.7, 95.8).
- 두 가지 한계: (a) "최고 기존 SOTA" 행은 열마다 다른 모델에서 뽑은 최댓값이고, (b) LIBERO 세부 스위트 (Spatial 98.2 < 98.4, Object 98.6 < 98.8, Goal 97.8 < 97.9)와 CALVIN (4.43 < 4.53, FLOWER)에서는 X-VLA가 최고가 아닙니다. 본문은 세부 스위트 우위를 주장하지 않지만, 초록 "SOTA on most suites"는 이 점을 감춥니다.
- **표 5 (단일 대 다과제 미세조정, 부록 D.2).** 단일 미세조정 행은 LIBERO-Long 97.6, Simpler-WidowX 96.0, CALVIN 4.42입니다. 표 2의 같은 값 (97.6, 95.8, 4.43)과 Simpler와 CALVIN이 조금 다릅니다 (`03` §3).
- 다과제 공동 미세조정 행은 LIBERO-Long 98.1, Simpler-WidowX 93.8, CALVIN 4.32입니다. 다과제가 단일보다 "때로 더 좋다"고 씁니다. 시드 수가 적혀 있지 않아 차이가 잡음인지 구분되지 않습니다.
- **표 6 (데이터 효율, LIBERO-Goal 및 PEFT).** 50 데모 (Full & Default)는 96.6 / 95.4 / 95.0 / 84.2 로 적혀 있는데, 표 3의 같은 설정 (95.4 / 96.6 / 96.0 / 84.2)과 Spatial·Object가 바뀌었고 Goal이 1.0점 다릅니다 (`03` §2).
- **표 11 (NAVSIM).** 열 NC, DAC, EP, TTC, C와 PDMS. 표 값에서 NAVSIM 표준 식으로 다시 계산하면 X-VLA 84.3, Transfuser 80.1로, 적힌 PDMS (87.3, 84.0)와 차이가 3–5점입니다 (`03` §6). 정의나 열 이름이 다를 수 있습니다.
- **표 12–16 (세부).** Simpler 과제별 평균은 맞습니다. RoboTwin 50과제 평균은 Easy 70.1, Hard 38.2로, 본문 Hard 39.0과 0.8점 차이입니다 (`03` §4).

### 4.3 PEFT (§5.2, 표 3, 표 7, 그림 9)

- 표 3: Libero-Spatial 95.4, Object 96.6, Goal 96.0, Long 84.2 (평균 93.05), Simpler-WidowX 54.2. π0 대비 "비슷하다"고 씁니다.
- π0 LIBERO 평균은 표 2에 94.1, 본문에 94.2입니다. 표 3 열의 평균은 94.15입니다 (`03` §1).
- 표 7 (PEFT 세부)과 AIRBOT 과제 (200 데모, 옷감 집기)는 본 분석에서 수치를 얻지 못했습니다 (이미지 또는 표 본문 누락).

### 4.4 실로봇 (§5.2, 그림 7, 부록 J)

- WidowX (BridgeData), AgileX (Soft-Fold), AIRBOT (PEFT, 옷감 집기)의 세 플랫폼입니다. 과제당 10회 (부록 J).
- 그림 7 수치는 이미지에만 있어 재계산하지 못했습니다. 성공 수가 과제당 10회의 정수인지 확인하려면 그림을 읽어야 합니다.

### 4.5 Soft-Fold 데이터와 PEFT 데모 효율 (부록 F, 그림 11–12)

- 1,200 궤적, 2M 샘플, "24H Time Cost" (그림 11 글자), 1 에피소드 약 1.5분, 시간당 20–25 에피소드 (부록 F 본문).
- 1,200을 시간당 20–25 에피소드로 모으면 48–60시간이 걸리는데, 그림 11은 24시간이라고 씁니다 (`03` §5).
- HF 데이터셋 카드 (`Facebear/XVLA-Soft-Fold`)는 **1,500 에피소드**, MIT 라이선스, 475.6 GB, 1,724개 파일이라고 씁니다 (`04` D9).
- DAgger식 수집 (ACT를 100 에피소드마다 학습하고 실패 모드 보충)을 설명합니다 (부록 F).

### 4.6 Limitations (부록 N)

- 저자가 쓴 한계는 세 가지입니다. 규모가 작다 (0.9B), 액션 라벨만으로 감독 신호가 부족하다, 새 로봇에 배치하려면 여전히 소량 데모 적응이 필요하다.
- 이 분석이 추가로 본 한계: 소프트 프롬프트 길이, 원천 수 7의 선택 근거, 시드 수 (표마다 한 번 실행), 평가 시도 수 (LIBERO, Simpler 등 표준 프로토콜이라 가정), 실로봇 과제당 10회의 통계력.

## 5. 주장과 증거의 틈 (정리)

1. **표 평균의 SOTA 주장은 맞지만 세부 스위트에서는 아닙니다.** (T4) LIBERO 세부 3개와 CALVIN에서 X-VLA는 최고가 아닙니다.
2. **같은 PEFT 설정의 표 3과 표 6이 서로 다릅니다.** (T6) 평균은 맞지만 스위트별 값이 엇갈립니다.
3. **RoboTwin Hard 평균과 CALVIN 평균이 본문 값과 맞지 않습니다.** (T4, §5.2) 0.8점, 0.02점 차이입니다.
4. **NAVSIM PDMS가 적힌 열로 재현되지 않습니다.** 모든 기준선에서 같은 방향으로 3–5점 차이라서 열 이름이나 정의 차이로 보입니다. 적힌 값 자체의 순위는 유지됩니다.
5. **Soft-Fold 규모 세 가지가 서로 다릅니다.** 논문 1,200, HF 카드 1,500, 그림 11 시간 24시간 대 수집 속도 48–60시간.
6. **스케일링 주장은 음의 R²로 받쳐져 있습니다.** (T3)
7. **원천 매핑에서 Droid-Left가 두 번 나옵니다.** 표 8의 두 번째 행은 Droid-Right일 가능성이 큽니다 (표 8 합계 288K, 본문 290K).
