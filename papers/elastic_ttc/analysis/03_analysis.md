이 논문에는 결과 표가 없고 수치가 그림(Fig. 2, 5, 11, 13, 14)에 있습니다. 그래서 **그림의 래스터 이미지에서 마커 중심과 막대 높이를 읽어** 재계산했습니다. 코드는 `analysis/recompute.py`(수 초), 결과는 `analysis/recompute_results.json`, 그래프는 `analysis/plot_figures.py`입니다. 검사 번호는 재계산 V1–V11, 일관성 K1–K12입니다. 공식 코드가 없어 학습이나 실행 재현은 하지 않았습니다.

## 0. 읽은 값의 정확도

- 읽는 방법: PDF에서 그림 이미지를 추출하고, 축 눈금 막대의 픽셀 위치로 축을 보정한 뒤 색으로 마커를 분리해 중심을 구했습니다. 성공률 오차는 약 ±0.3 %p, 지연 오차는 ±0.7 ms로 잡습니다.
- 내부 검증 (V9): 그림 2와 13의 읽은 값 48개가 모두 200회 이항에서 가능한 0.5 %p 격자에서 0.2 %p 이내이고(평균 0.07), 그림 2와 그림 13에서 같은 ELASTIC 점의 값이 0.1 %p 이내로 일치합니다. 그림 11의 과제별 막대 값(5 %p 단위, 20회)에서 구한 평균이 논문 라벨 5개와 모두 같습니다(V1).
- 한계: ELASTIC 마커 아래에 가려진 Fixed 마커 4곳(PushT 2비교는 한 점 공유, PushT Obstacle 1, Square PH 1)은 값을 가정했습니다(V7 표 비고). 마커 크기에서 P를 읽는 것은 정확하지 않아 쓰지 않았습니다.
- PushT의 "성공률" 정의는 논문에 없습니다. 원 Diffusion Policy 벤치마크의 PushT 점수는 목표 영역 덮임 비율 기반인 것으로 알려져 있으나 이 논문이 어느 정의를 썼는지는 확인하지 못했습니다. 읽은 PushT 값도 0.5 %p 격자에 맞아 이항 성공률과 모순되지는 않습니다.

### 1.4 계산량 정합 (V3)

식 1의 α=0.13, β=0.1로 계산하면 다음과 같습니다.

| 방법 (L,P) | α·L + β·(P−1) | α·L + β·P |
|---|---|---|
| ELASTIC (2.6, 6.9) | 0.93 | 1.03 |

L=7.1의 Sequential은 그림에 없어서 어떤 성능인지 알 수 없습니다.
- Fixed (3,7)은 (2.6, 6.9)의 반올림이고 §7.2.1은 floor/ceil 무작위 섞기를 쓴다고 하므로 실제 실행값과 라벨이 다를 수 있습니다.

## 3. 확산 정책 6과제 (과제당 200회, Fig. 2, 13)

### 3.1 ELASTIC 대 Fixed (V7)

같은 평균 (L,P)에서 18개 비교(6과제 × 3 비용 체제)를 읽었습니다. 막대는 `own_dp_gain.png`입니다.

| 과제 | 비교 수 | 평균 이득 (%p) | 비고 |
|---|---|---|---|
| PushT | 3 | +4.4 | 모두 p > 0.14 |
| PushT Obstacle | 3 | +1.8 | 한 점은 Fixed와 같은 값(가정) |
| Square PH | 3 | +3.1 | 한 점은 ELASTIC이 −1.1 (가정), L=7.6에서만 p = 0.028 |
| Square MH | 3 | +6.2 | 모두 p > 0.11 |
| Can Paired | 3 | +21.0 | 두 점에서 p < 0.001 |
| Can Reverse | 3 | +14.2 | 두 점에서 p ≤ 0.04 |

- ELASTIC이 높은 비교 16개, 같은 것 1개, 낮은 것 1개입니다(전체 평균 +8.5 %p, 중앙값 +5.8). **Fisher p < 0.05(비보정)인 것은 18개 중 5개**이고 모두 Can Paired, Can Reverse, Square PH의 한 점입니다.
- 그래서 "모든 과제와 비용 체제에서 Pareto 우위"(초록)는 점추정 방향으로는 대체로 맞지만, 6과제 중 4과제에서는 개별 비교가 유의하지 않습니다. 이득이 큰 두 과제(Can Paired, Can Reverse)는 저자들이 모드 문제를 보이려고 만든 과제입니다(§5.1). PushT Obstacle과 Can Reverse도 저자의 변형입니다.
- 같은 200개 초기 조건에서 평가했다면 쌍체 검정이 더 강할 수 있으나 짝 정보가 없어 비쌍체 Fisher만 계산했습니다.

| 과제 | BoN | DP | ELASTIC 최고 (L) | 학습된 Fixed 최고 (L) | 대 BoN (p) | 대 DP (p) | 대 학습된 Fixed (p) |

- **학습된 Fixed(Fig. 13)는 본문에서 수치로 논의되지 않았지만 가장 중요한 대조입니다.** Can Reverse에서는 ELASTIC과 같고(61.5 대 61.1) Can Paired를 뺀 나머지 과제에서도 이득이 +1.5–3.9 %p이며 어느 것도 유의하지 않습니다. 다만 학습된 Fixed는 L이 더 큽니다(예: Square MH 14.2 대 7.9). 이 대조는 "상태 의존이 필요한가"보다 "학습 가능한 고정 할당이 이미 대부분을 얻는가"를 묻습니다.
- Can Reverse에서 ELASTIC 최고(61.5)는 BoN(67.9)보다 6.4 %p 낮습니다. "BoN 성공률에 가까운 성능을 훨씬 적은 계산으로"라는 서술에서 Can Reverse는 예외입니다.

### 3.3 Sequential 기준선의 L 상한 (V11)

App. 7.2.1 식 L = L̄ + (β/α)(P̄−1)에서 P̄ ≤ N이므로 Sequential의 L에는 상한이 있습니다. 가장 큰 읽은 Sequential L과 비교하면 다음과 같습니다.

| 과제 | 읽은 최대 L | 식의 상한 (N=4, Can Reverse는 8, β/α=3.33) |
|---|---|---|
| PushT | 9.7 | 16.0 |
| PushT Obstacle | 16.7 | 18.0 |
| Square PH | 15.3 | 17.6 |
| Square MH | 17.6 | 17.9 |
| **Can Paired** | **17.1** | **14.1** |
| Can Reverse | 16.8 | 27.0 |

Can Paired의 Sequential L ≈ 17.1은 식으로 도달할 수 없습니다(ELASTIC 점의 L̄ 최대가 4.1). 식 적용 방식이 다르거나(예: 측정 지연으로 환산) 읽은 라벨이 다를 수 있어서 **오류로 단정하지 않고 미확인으로 둡니다**(K5).

## 4. 지연 모델 점검 (V6)

그림 14는 RTX 6000에서 P=1…10, L=1, 5, 10의 지연을 보여 줍니다(`own_latency.png`). 읽은 값으로 다음을 얻었습니다.

- 스텝당 약 2.4 ms (P=1에서 L=1→10: 63.0 → 84.8 ms). 샘플당 비용은 L=1에서 0.52 ms, L=10에서 2.0 ms입니다. 그러므로 스텝 대 샘플의 비용비는 L=1에서 4.6, L=10에서 1.2로 L에 따라 변합니다. 논문의 α/β = 1.3 (α=0.13, β=0.1)은 L=10 근처의 비율과 맞고, 작은 L(ELASTIC이 실제로 쓰는 2–4)에서는 샘플이 상대적으로 더 싸므로 β를 크게 잡은 셈입니다.
- **같은 RTX 6000 측정이라는 그림 5의 점이 그림 14보다 7–16 ms 낮습니다**(K6).

| 구성 | 그림 5 | 그림 14 보간 | 차이 |
|---|---|---|---|
| π0.5 (10,1) | 69.1 | 84.8 | −15.7 |
| BoN (10,10) | 95.5 | 102.8 | −7.3 |
| ELASTIC (2.6,5.6) | 62.5 | 71.5 | −9.0 |
| ELASTIC (3.6,2.9) | 64.6 | 72.4 | −7.8 |
| ELASTIC (1.9,3.5) | 58.0 | 68.0 | −10.0 |

- 그림 14의 모델을 그대로 쓰면 BoN 대비 감소율은 30.5% / 29.6% / 33.8%입니다. 그림 5의 34.6% / 32.4% / 39.3%보다 약 3–6 %p 작습니다. 효과의 크기는 같지만 헤드라인 34%는 그림 5의 지연에 의존합니다.
- 그림 5(RTX 6000)와 그림 11(RTX 4090)의 π0.5 지연이 거의 같습니다(69.1 대 68.7 ms, BoN 95.5 대 94.0 ms). GPU가 다르면 같은 값이 나오기 어렵지만 클라이언트-서버 왕복 시간이 지배한다면 가능합니다. 이 점은 확인하지 못했습니다(K7).
- §7.4는 그림 5의 지연이 메타 정책과 검증기를 포함한 클라이언트 왕복 시간이라고 쓰지만, 그림 14가 무엇을 포함하는지는 적혀 있지 않습니다. 포함 범위가 다르다고 해도 메타 정책 비용은 양수이므로 그림 5가 더 낮게 나온 것은 설명되지 않습니다.

## 6. 해석

1. **가장 강한 근거는 확산 정책의 Can 두 과제와 헤드라인 지연 이동**입니다. 그 밖의 비교는 점추정 방향이 일관적이어도 200회 또는 20회로는 개별 유의성이 약합니다.
2. **지연 절감의 상당 부분은 "스텝을 줄여도 된다"에서 옵니다.** π0.5에서 L=10이 과다하다는 관찰이며 Fixed (2,10)과 같은 지연입니다. 적응형 할당만의 기여는 성공률 80 대 70(p = 0.72)이라 이 데이터로 분리되지 않습니다.
3. **통계 정보가 없는 것이 가장 큰 간극**입니다. 시드, 반복, 오차 막대, 학습 비용이 모두 빠져 있어서 이 문서의 모든 p 값은 단일 실행의 이항 분산만 반영합니다. 메타 정책 학습 분산은 포함되지 않았습니다.
