# 04. 논문과 공식 코드 대조: MimicGen

## 0. 요약과 판정

- 대조 대상: `NVlabs/mimicgen` 로컬 얕은 복제, 커밋 `c0fbff22ba40060f05a917a80817f3f5c20731e7`(2026-10-21). 논문 시점(2023)이 아니라 2024년 릴리스 이후 코드입니다.
- **방법:** 정적으로만 읽었습니다. 저장소 코드는 실행, import, 설치하지 않았습니다. 대조한 파일은 `mimicgen/datagen/data_generator.py`, `selection_strategy.py`, `waypoint.py`, `mimicgen/utils/pose_utils.py`, `mimicgen/configs/config.py`, `configs/robosuite.py`, `scripts/generate_core_configs.py`, `scripts/generate_dataset.py`, `env_interfaces/robosuite.py`입니다.
- **핵심 결과:** 변환 식, 선택 전략, 하이퍼파라미터(N.6)의 큰 틀은 논문과 일치합니다. 다음 차이가 논문 본문에 없고 결과에 영향을 줄 수 있습니다. (a) 보간 시작점의 기본값, (b) 하위과제 경계의 무작위 오프셋, (c) 성공 판정 시점. 학습과 평가 코드, 실로봇 코드, Factory 과제와 이동 조작 과제는 저장소에 없습니다.
- **구현 가능성(이 맥):** 저장소의 로봇 시뮬레이션 과제(12개)에서 데이터 생성 파이프라인을 CPU로 돌려 보는 것은 가능성이 높습니다(설치 후 확인 필요). 논문의 표 전체 재현은 불가능합니다(§4).

## 3. 차이 목록 (D1–D11)

**D1. 보간 시작점의 기본값 (결과에 영향 가능).**
논문 §4.2는 보간을 "현재 엔드이펙터 자세"에서 시작한다고 씁니다. 코드의 기본값은 직전 목표 자세입니다(`experiment.generation.interpolate_from_last_target_pose = True`). 설정 주석도 이 기본값이 "가끔 품질을 높인다"고 씁니다. 논문 실험이 어느 쪽을 썼는지 본문은 말하지 않습니다. 영향: 세그먼트 사이 연결 위치가 달라져 생성률과 궤적 모양이 달라집니다. 확인 질문으로 남깁니다(§5).

**D2. 작은 회전 보간 생략 (영향 작음 추정).** 회전 차이가 0.05 rad(약 2.9°)보다 작으면 보간 없이 목표 회전을 바로 씁니다. 위치는 여전히 보간됩니다. 논문 N.2는 회전 보간을 명시하므로 엄밀히는 다릅니다. 영향은 작을 것으로 보지만 측정하지 않았습니다.

**D3. 행동 자르기 (논문에 없음).** 잡음을 더한 뒤 행동을 [−1, 1]로 자릅니다(`waypoint.py`). 큰 델타 자세나 잡음이 클 때 실제 행동이 목표와 달라집니다. 논문 N.4에는 자르기가 없습니다.

**D4. 보간 구간의 잡음 (해석 필요).** 기본값은 보간 구간에 잡음을 넣지 않습니다. 논문 N.4는 "변환된 세그먼트를 실행할 때" 잡음을 넣는다고 쓰므로 기본값과 맞습니다. 다만 보간 구간의 잡음이 실험에 쓰였는지는 본문에서 알 수 없습니다.

**D5. 하위과제 경계의 무작위 오프셋 (논문에 없음, 재현에 중요).** 시도마다 각 하위과제 끝을 metric 시점에서 5–10 또는 10–20 스텝 뒤로 밉니다(`randomize_subtask_boundaries`, `configs/robosuite.py`의 `subtask_term_offset_range`). 논문 K.2와 N.6은 이 오프셋을 말하지 않습니다. 영향: 세그먼트 경계가 달라져 생성 데이터의 다양성과 생성률이 달라집니다. 이 설정 없이는 논문 생성률을 재현하기 어렵습니다.

**D6. 성공 판정 시점 (데이터 품질에 영향 가능).** 실행 중 매 스텝 `env.is_success()`를 OR로 누적합니다(`waypoint.py`의 `execute`). 한 번이라도 성공 상태가 되면 궤적은 성공으로 저장됩니다. 논문 §4.2는 모든 세그먼트 실행 후 성공을 확인한다고 씁니다. 두 방식은 "일시적으로 성공한 뒤 실패한 궤적"에서 다릅니다. 논문 부록 R은 성공 판정만으로 생기는 편향을 한계로 듭니다. 이 코드의 판정은 그 편향을 키울 수 있습니다.

**D7. 실패 궤적의 별도 저장 (영향 없음).** 메인 데이터셋은 성공만 담습니다. 실패는 최대 50개를 별도 파일로 저장하는 기본값이 있습니다(`max_num_failures = 50`). 논문에는 없습니다. 학습 데이터에는 들어가지 않습니다.

**D8. 실로봇 설정 (재현 불가).** 실로봇 파이프라인, 자세 추정, 실로봇 설정(σ = 0.02, 보간 25/25)은 저장소에 없습니다. 논문 §6.4와 부록 H의 실로봇 수치는 이 코드로 재현할 수 없습니다.

**D9. 과제 범위 (논문 표와 저장소의 차이).** 논문 본문의 "18개"는 표로 확인되지 않습니다(표 16개). 저장소는 12개 로봇 과제 설정입니다. Mobile Kitchen과 Factory 3개(Nut-and-Bolt, Gear, Frame)는 저장소에 없습니다. 이 과제들의 공개 코드는 확인되지 않았습니다. Factory 과제는 Isaac Gym 기반(논문 [51], [52])이라 CUDA가 필요합니다.

**D10. 학습과 평가 코드 (외부 의존).** 학습(BC-RNN), 하이퍼파라미터(저차원 학습률 1e-3), 체크포인트 평가, 최댓값 보고 방식은 robomimic 쪽에 있습니다. 이 저장소로는 확인할 수 없습니다.

**D11. 논문에 없는 선택 전략 (영향 없음).** 로봇 거리 기준 최근접 이웃 전략이 정의되어 있으나 설정에서 쓰이지 않습니다.

## 4. 구현 가능성 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

| 경로 | 판정 | 근거와 노력 |
|---|---|---|
| 로봇 과제(12개) 데이터 생성 파이프라인 CPU 실행 | **조건부 가능** | 생성 자체는 시뮬레이션 CPU 실행입니다. `setup.py`는 numpy, h5py, imageio 등을 요구하고, 코드는 robomimic과 robosuite를 import합니다. 설치와 이미지 렌더링(84×84 오프스크린)은 이 맥에서 미확인입니다. 노력: 설치와 검증 1–2일(추정). 설치는 사용자 승인 후 |
| Square D0 DGR 재측정 (73.7%) | **조건부** | 1000개 목표를 채우려면 약 1,400회 시도가 필요합니다(1000/0.737). 시도 한 번의 시간은 측정하지 않았습니다 |
| 36개 변형 전체 생성 (1000개씩) | **시간 미정** | 시도 수는 약 112,600회입니다(`03` §4). 시간은 측정 후에만 추정 가능 |
| BC-RNN 학습 (이미지 1000개) | **GPU 권장, 미측정** | 논문은 V100을 썼습니다. MPS에서 가능성은 있으나 측정하지 않았습니다 |
| 표 3 전체(시드 3, 36변형) 재현 | **불가** | 학습이 GPU 수십~수백 시간 규모로 추정됩니다(추정, 미측정). 학습 코드는 외부 |
| Factory 과제, Mobile Kitchen | **불가** | 공개 코드 없음(D9). Factory는 Isaac Gym(CUDA) |
| 실로봇 | **불가** | 로봇, 카메라, 자세 추정 코드 없음(D8) |

**판정:** 이 맥에서 할 수 있는 것은 **로봇 시뮬레이션 과제 한두 개의 생성 파이프라인 확인과 DGR 측정**입니다. 논문 결과 전체 재현은 불가능합니다. 노력 추정은 설치·검증 1–2일과 측정 후 결정입니다. 설치와 공식 코드 실행은 사용자 승인이 필요합니다.

3. 성공 판정은 전체 궤적 중 한 번이라도인가, 마지막 스텝인가(D6)?

5. 본문의 "18개 과제"와 "50K 이상"의 목록과 합계는 무엇인가(`03` §2.3)?
6. 표 Q.1의 Mobile Kitchen 원천 값은 6.7인가, 본문 2.7인가(`03` §2.1)?
