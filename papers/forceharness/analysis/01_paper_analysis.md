## 1. 한 줄 요약

가중치가 고정된 API 전용 프런티어 모델에 **손(또는 관절)에서 추정한 힘**을 쓰게 하는 harness입니다. 모델은 도구 호출 한 번씩만 하고, 힘 제어는 모델 아래에서 **자기 종료 힘 프리미티브**가 맡으며, 결과는 **물리량과 불확실도**로 되돌립니다. 학습과 데모 없이 실로봇(센서 없는 Franka FR3), ForceBench(Isaac Lab), 자체 MuJoCo 벤치마크 HiddenPhys에서 평가했습니다.

## 2. 문제 설정

- 저자들은 두 질문을 세웁니다(서론, 2쪽). 첫째, 접촉은 API 모델이 판단하는 주기보다 빨리 변하므로 힘 루프를 모델 아래에서 닫아야 합니다. 둘째, 모델은 원시 힘 숫자를 잘 해석하지 못하므로 힘을 추론 가능한 형태로 돌려줘야 합니다.
- 기존 접근의 한계로 두 갈래를 듭니다. 학습 기반 힘 정책(FoAR, ForceVLA2, FORGE 등)은 시연과 가중치 갱신이 필요합니다. 기존 frozen-model harness는 원시 wrench·촉각 값을 그대로 주거나(refs [7], [29]) 힘 제어 코드를 생성하게 합니다(refs [4], [28]).

## 3. 방법

세 층입니다(그림 2, 3쪽).

**(a) 힘 감지와 보정 (3.2절, 식 1).** 손목 F/T 센서가 없으면 관절 토크 추정 외력 τ_ext에서 최소제곱으로 플랜지 wrench를 구하고, 영점 b를 빼고 부호를 뒤집습니다.

  w = (Jᵀ)⁺ τ_ext,  F = −(w_F − b)

영점이 자세에 따라 흘러서, 저자들은 필터 대신 **읽는 시점**을 조절합니다. 프리미티브 전에 빈손 상태에서 영점을 잡고(tare), 정착(settle) 후 짧은 정지 구간을 평균하며, 같은 에피소드의 기준값(빈손이나 잡은 순간)에 대한 **변화량**을 보고합니다.

**(b) 자기 종료 힘 프리미티브 (3.3절, 식 2–3, 표 1).** 프리미티브 하나는 모델이 몇 개 인자(방향, 목표 힘 등)를 주고 호출하는 도구입니다. 내부에서는 목표 자세 p*를 매 틱 갱신합니다.

  −F ≈ K (p* − p),  ‖p* − p‖ ≤ L   (식 2: 임피던스 제어기가 스프링처럼 힘을 만들고, 리드 L이 힘 상한을 정함)
  v = clip(k_f (F_d − F_u), ±v_max),  Δp* = u v Δt   (식 3: 목표 힘을 맞추는 admittance 법칙)

프리미티브는 접촉 사건(접촉, 정체, 저항 감소, 힘 상한)이나 자체 목표가 충족될 때 멈추고, 모델은 그 뒤에 결과를 읽습니다. 표 1은 12개 프리미티브를 다섯 묶음으로 나눕니다. 도구는 프리미티브 12개와 이동·파지·인식 등 10개를 합쳐 20–21개입니다(5.1절). 기본 예는 `search`(구멍 찾기)이며, 목표 힘으로 누르면서 아르키메데스 나선을 그리다가 부품이 구멍에 떨어지면 멈춥니다(3.4절, 그림 2).

**(c) 물리 변환층 (3.5절, 식 4–5).** 프리미티브의 힘 궤적을 물리량과 불확실도, 플래그로 바꿉니다. 저자들은 추정기를 평균과 최소제곱, 오차 전파로만 만들고 작업별 임계값은 넣지 않았다고 씁니다. 대표 식은 다음과 같습니다.

  m = |F̄_z| / g,  σ_m = √(s_z²/n + σ_b²) / g   (식 4: 정지 파지에서 질량)
  μ = |F̄_t| / F̄_n,  (σ_μ/μ)² = (σ_t/|F_t|)² + (σ_n/F̄_n)²   (식 5: 마찰 계수)

이 외에 접촉 높이(탐지기 지연 보정), 강성(침투량에 대한 기울기), 삽입 전진량(플래그 포함) 등이 있습니다(표는 부록 B.2). 결과는 값, σ, 측정 창, 플래그와 함께 도구 결과로 돌아갑니다.

**모델 루프 (3.6절).** 모델은 매 턴 지시문, 도구 목록, 호출 이력, 최근 관측을 받고 도구 호출 하나를 냅니다(에피소드당 최대 40턴, 80 호출, 300 s). 지시문은 과제마다 손으로 쓰며 숨은 변수 값은 말하지 않습니다. 안전 가드는 모델이 바꿀 수 없습니다(힘 상한 25 N, 속도, 작업 공간).

## 4. 실험 설정

기준선은 HiddenPhys에서 손으로 짠 전문가 상태 기계, 힘 없는 위치 제어기, Diffusion Policy(과제별), π0.5(다중 과제 1개), ForceVLA(다중 과제 1개)입니다. 학습 기준선은 모두 **학습 시드 1개**로 학습했고, 마지막 체크포인트로 평가합니다(부록 C.5, G).

## 5. 주요 결과

**표 3 실로봇 (10회씩).** Astra는 무힘 2/60에서 ForceHarness 54/60으로 올랐고, Sol은 47/60입니다. 여섯 과제 모두 무힘 대 ForceHarness가 Fisher 검정으로 p < 0.01입니다(`03` §1에서 재계산, 확인). 병 무게 정렬과 부드러움 구분은 RGB-D 영상에 단서가 없어서 무힘 제어가 0/10입니다.

**표 4 ForceBench (10회씩, 개발 시드).** GPT-6 Astra는 70.0%에서 87.5%로, GPT-6.1 Sol은 65.0%에서 87.5%로 올랐습니다. Claude Fable 5.2는 ForceHarness만 75.0%로 보고되고, 무힘 대조가 없습니다. 학습 기준선 중 최고는 π0.5 + Prompt Fusion의 35.31%입니다. 이 값들은 ForceBench 논문(arXiv:2610.19604)의 Table I과 같습니다(`03` §2). 개선의 대부분은 Drawer Pull 한 과제에서 0/10에서 10/10으로 나왔습니다.

**표 5 HiddenPhys (과제당 20회, 합 140).** GPT-6 Astra는 무힘 87/140에서 ForceHarness 135/140으로, Fable은 96/140에서 135/140으로 올랐습니다. 손으로 짠 전문가는 136/140입니다. 학습 기준선은 65–83/140이고 손상(damage)이 자주 발생합니다. ForceHarness의 손상은 0입니다. 분포 이동(네 과제의 숨은 범위를 바꿈)에서 Astra는 75 → 69, Fable은 75 → 71입니다.

**표 6 형식 비교와 Fig. 4 (HiddenPhys 절제).** 힘을 이벤트 단어로만 주면 Sol의 성공률은 0.63 → 0.77, 소형 모델은 0.18 → 0.54입니다. 힘 그래프, 원시 수치, 유도 신호, L1, L2 물리량을 비교하면 소형 모델의 결정 정확도는 원시 수치 0.69에서 L2 0.85로 올라갑니다. 저자들은 L2와 원시 수치 비교가 McNemar p = 0.023이라고 보고합니다. 원래 분모는 표에 없습니다.

## 7. 본문 주장과 증거의 차이

본문 주장은 대부분 표 값과 맞습니다(`03` 참조). 다만 읽는 사람이 주의해야 할 점이 있습니다.

1. **ForceBench 수치는 튜닝에 쓴 시드입니다.** 본문은 "eight of the ten seeds"로 튜닝을 말하지만, 저장소 문서는 Stove Press의 측정 창을 **시드 300–309의 기록 56회를 재생해서** 골랐다고 씁니다(`04` D4). 같은 시드로 보고하면 낙관적으로 치우칠 수 있습니다. 저자들이 따로 한 **보류 시드 320–329** 결과(Astra 50/80 → 66/80)는 저장소 문서와 프로젝트 페이지에만 있고 논문 본문에는 없습니다.
2. **학습 기준선과의 비교는 서로 다른 평가입니다.** 학습 기준선은 ForceBench 논문이 200회씩 평가한 값이고, 이 논문은 그 값을 재실행하지 않고 인용합니다. "학습 정책보다 낫다"는 주장은 방향은 맞지만, 평가 시드와 횟수가 다르므로 차이의 크기를 그대로 읽으면 안 됩니다.
3. **학습 기준선은 시드 하나입니다.** Diffusion Policy, π0.5, ForceVLA는 학습 시드 1개씩이라서, 기준선의 분산은 보고되지 않았습니다.
4. **통계 검정 절차가 공개되지 않았습니다.** Fisher 검정, 짝 McNemar 검정은 본문과 부록에 방법만 적혀 있고, 코드(저장소에는 Wilson 구간만 있음)와 에피소드별 결과는 공개되지 않았습니다(`04` D3).
5. **Astra의 Stove Press 행은 현재 코드로 재현되지 않습니다.** 저장소 설정 파일 주석과 문서에 따르면 이 행은 이전 버전의 도구 결과(두 번째 절반 평균 토크, 읽기 주석 없음)를 씁니다(`04` D5).
6. **"약 45% 비용 절감"은 측정이 아니라 추정입니다.** 저장소 설정 파일 주석의 목록가 추정(에피소드당 $0.28 대 $0.50)에서 나온 값입니다(`03` §5).
