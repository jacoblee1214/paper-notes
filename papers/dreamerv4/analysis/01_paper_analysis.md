## 1. 한 문단 요약

Dreamer 4는 두 단계 world model 위에서 **오프라인 데이터만으로** 행동을 학습하는 에이전트입니다. (a) 인과적 토크나이저(마스크 오토인코딩으로 학습)와 (b) 인터리브된 행동·잡음 수준·스텝 크기·표현을 받는 dynamics 트랜스포머(shortcut forcing으로 학습)를 **같은 2D 블록 인과 트랜스포머 구조**로 만듭니다. 이 world model에 task 토큰과 policy·reward 헤드를 붙여 behavior cloning으로 미세조정한 뒤, 모델 안에서 상상한 궤적으로 PMPO 기반 강화학습을 합니다. Minecraft VPT 계약자 데이터(2541시간, 20 FPS) 하나로 학습한 뒤, 환경 상호작용 없이 60분 에피소드에서 다이아몬드를 얻은 성공률 0.7%를 보고합니다(Table 7). 2B 파라미터 모델은 단일 H100에서 21 FPS(9.6초 문맥)로 상호작용 추론을 합니다(Table 1).

## 2. 문제 설정과 주장 구조

- **문제**: 기존 world model(Genie 3, Oasis, Lucid, MineWorld 등)은 실시간성이나 물체 상호작용 정확도 중 하나가 부족하고, 상상 학습에 쓸 만큼 정확하지 않습니다(§1, §5).
- **목표**: 정확한 상호작용, 실시간 추론, 오프라인 상상 학습을 한 모델로 얻는 것(§1 기여 목록).
- **핵심 주장(원문 기준)**:
  1. Minecraft 다이아몬드를 오프라인 데이터만으로 얻은 첫 에이전트(§1, §4.1, Fig. 3).
  2. VPT 대비 "100배 적은 데이터"(§1, Table 3).
  3. 단일 GPU 실시간 추론(§3.2, Table 1, Table 2).
  4. 행동 라벨이 적은 영상에서도 행동 조건화를 배움(§4.3, Fig. 7).
  5. shortcut forcing과 효율 구조 각각이 성능에 기여(§4.4, Table 2, Fig. 8).

## 3. 방법

### 3.1 인과적 토크나이저 (§3.1, 식 (5))
- 패치 토큰과 학습 가능한 잠재 토큰을 쓰는 인과 인코더·디코더. 잠재는 선형 투영 후 tanh를 거쳐 저차원 표현이 됩니다.
- 손실: `L = L_MSE + 0.2 L_LPIPS` (식 5). 입력 패치를 확률 p ~ U(0, 0.9)로 마스킹(MAE).
- MAE를 넣으면 생성 영상의 공간 일관성이 좋아졌다고 보고합니다(§3.1, 정량 근거는 본문에 없음).

### 3.2 상호작용 dynamics와 shortcut forcing (§3.2, 식 (6)–(8))
- 입력: 표현 `z̃ = (1−τ) z0 + τ z1`, 잡음 수준 τ, 스텝 크기 d, 행동 a. 이산 τ와 d는 임베딩 룩업, 행동은 구성요소별 토큰으로 인코딩합니다(키보드 23 이진, 마우스 121 범주, §4.1).
- **x-prediction**: 네트워크가 깨끗한 표현 `ẑ1`을 직접 예측합니다. v-prediction은 고주파 출력을 만들어 긴 자기회귀 롤아웃에서 오류가 쌓인다고 주장합니다(§3.2). 이 주장을 뒷받침하는 수치는 Table 2의 "+X-Prediction"과 "+X-Loss" 행입니다.
- **shortcut 손실**: 식 (7). 가장 작은 스텝(d_min)에서는 흐름 정합 손실, 큰 스텝에서는 두 작은 스텝을 이은 부트스트랩 목표(sg 연산자)를 씁니다.
- **ramp 가중치** `w(τ) = 0.9τ + 0.1` (식 8). 낮은 τ에서 흐름 손실이 데이터 평균 예측으로 퇴화하는 문제를 줄인다고 설명합니다.
- **추론**: 프레임마다 K = 4 스텝, d = 1/4. 과거 입력은 τ_ctx = 0.1로 살짝 손상시킵니다.

### 3.3 상상 학습 (§3.3, 식 (9)–(11))
- **행동 복제와 보상 모델** (식 9): 에이전트 토큰을 인터리브해 정책·보상 MLP 헤드를 붙입니다. MTP 길이 L = 8. 보상 헤드는 symexp twohot 출력(Dreamer 3 계승).
- 에이전트 토큰은 다른 모달리티를 보지 못하게 마스킹합니다(인과 혼동 방지, §3.3).
- **강화학습** (식 10–11): 트랜스포머는 동결하고 정책·가치 헤드만 갱신합니다(부록 주 †에서 전체 미세조정은 작은 추가 이득만 주고 비용이 크다고 함). 가치 헤드는 λ-return TD 학습(γ = 0.997). 정책은 PMPO로 **이득의 부호만** 씁니다. α = 0.5, 행동 사전분포 KL 가중 β = 0.3, KL 방향을 원 PMPO와 반대로 씁니다(§3.3).
- 상상 롤아웃은 데이터셋 문맥마다 **한 번씩만** 시작합니다(메모리와 다양성, §3.3).

### 3.4 효율 트랜스포머 (§3.4, Table 2)
- 공간 전용 어텐션 층과 시간 전용 어텐션 층을 분리하고, 시간 어텐션은 4층마다 하나만 둡니다.
- pre-RMSNorm, RoPE, SwiGLU, QK-Norm, 어텐션 로짓 soft cap, 동적 모델에 GQA, 등록 토큰(register tokens).
- 배치 길이: 짧은 배치와 긴 배치를 번갈아 씁니다. 긴 문맥은 **시간 전용 어텐션**으로 처리합니다.

## 4. 실험 (수치는 원문 표 기준, 재계산은 `03`)

### 4.1 오프라인 다이아몬드 (Fig. 3, Fig. 4, Table 7, Table 8)
- 설정: 60분 에피소드, 빈 인벤토리, 무작위 세계, **1000 에피소드**(Fig. 3 캡션, Table 7 캡션). 원시 픽셀과 저수준 마우스·키보드 행동. 환경 상호작용 없음.
- 주요 성공률(Table 7, Dreamer 4 대 대표 기준선):
  - 돌 곡괭이: Dreamer 4 90.1% / WM+BC 89.4% / VLA 76.7% / BC 53.8%
  - 철 곡괭이: Dreamer 4 **29.0%** / WM+BC 16.9% / VLA 11.2% / BC 0.6%
  - 다이아몬드: Dreamer 4 **0.7%** (7/1000) / 나머지 전부 0.0%
- 본문 주장 "돌 곡괭이까지 90% 이상"(§4.1)은 90.1%로 맞지만 경계선입니다.
- 행동 시간(Table 8): 다이아몬드까지 평균 20.7분인데, 이 값은 **성공 7회**의 평균입니다(표가 0.5% 이상이면 포함하는 기준을 따름).
- 데이터: VPT 계약자 데이터만 사용(2.5K 시간). 작업 20개, 희소 이진 보상을 VPT 이벤트 주석에서 만듦(Table 4). 데이터는 행동 조건화·보상 모델·RL에 50% 균일 시퀀스와 50% 관련 시퀀스로 섞음(§4.1). 행동 복제 손실은 관련 부분에만 적용하고, dynamics 손실은 균일 부분에만 적용합니다(오해 방지).

### 4.2 상호작용 생성 품질 (Fig. 5, Table 1, 부록 Figs. 12–14)
- 사람 플레이어가 16개 과제를 world model 안에서 수행. Dreamer 4 14/16, Oasis(large) 5/16, Lucid-v1 0/16, Oasis(small) 0/16(Table 1).
- **평가 절차가 본문에 없습니다**(누가 판정했는지, 성공 기준, 반복 횟수). 정량 근거가 아니라 시연 수준입니다.
- 추론 속도(Table 1, 단일 H100): Dreamer 4 21 FPS, 9.6초 문맥. Lucid 44 FPS, 1.0초. Oasis(small) 20 FPS, 1.6초. **Oasis(large) 약 5 FPS는 측정이 아니라 공개 정보로 추정한 값**입니다(Table 1 캡션, §4.2).
- 로봇 확장(Fig. 6): SOAR 데이터(180시간, 256×256, 5 FPS)로 학습한 정성 결과입니다. 정량 평가는 없습니다.

### 4.3 행동 일반화 (Fig. 7)
- 행동 데이터 양: 2541시간 영상 중 0, 10, 100, 1000, 2541시간에만 행동 라벨을 줌. 16스텝 생성, 문맥 320 프레임, PSNR·SSIM 비교.
- 본문 수치: 10시간에서 PSNR 53%·SSIM 75%, 100시간에서 PSNR 85%·SSIM 100%(모두 전체 행동 학습 대비). 캡션은 "80% 이상"이라고 씀(`03` §5).
- 행동 외삽: Overworld 행동만으로 학습해 Nether·End에서 평가. PSNR 76%, SSIM 80%(§4.3).
- 행동 라벨 선택 방식: "처음 순서대로" 골랐다고 씀(세계 수와 플레이어 수가 무작위보다 적음). 이는 편향 가능성이 있습니다.

### 4.4 설계 절제 (Table 2, Fig. 8)
- 기준: 48시간 학습 후 384프레임 영상 1024개를 생성, FVD를 16프레임 청크로 계산.
- FVD 흐름: 확산 포싱 306 → 4스텝 875 → shortcut 329 → x-pred 326 → x-loss 151 → ramp 102 → 교차 배치 80 → 4층마다 긴 문맥 70 → GQA 71 → 시간 전용 91 → 등록 토큰 91 → 공간 토큰 128 66 → 256 57.
- FPS 흐름: 0.8 → 9.1 → 18.9 → 23.2 → 30.1 → 28.9 → 25.7 → 21.4. 최종 모델은 21.4 FPS.
- **본문과 표가 다릅니다**: 본문은 "v-space 예측과 손실을 쓴 완전한 구조의 FVD는 124"라고 쓰지만, Table 2에는 124 행이 없습니다(`03` §4).
- Fig. 8은 샘플링 스텝 1–64에서 shortcut과 확산 포싱을 비교합니다. "16배 빠르다"는 스텝 수 비율(64/4)이며 실제 속도 비율이 아닙니다.

### 4.5 학습 설정 (§4, 부록 A)
- 모델: 2B 파라미터 = 토크나이저 400M + dynamics 1.6B. 256–1024 TPU-v5p, 장치당 배치 1, FSDP(§4).
- 해상도와 토큰: Minecraft 360×640을 384×640로 패딩, 16×16 패치 → 960 토큰, 토크나이저 병목 512×16을 256×32로 재배열. 문맥 192프레임(9.6초), 배치 길이 64와 256 (부록 A).
- 로봇 SOAR: 256×256, 5 FPS, 512 공간 토큰, 문맥 96, 배치 32와 128. Epic Kitchens 100: 256×256, 10 FPS, 같은 설정.
- 최적화기, 학습률, 스텝 수, 배치 크기 전역값, 시드 수는 **본문과 부록에 없습니다**. 재현에 필요한 핵심 정보가 빠져 있습니다.

## 5. 한계 (논문이 스스로 밝힌 것, 그리고 빈 곳)

- 논문이 밝힌 한계(§4.2, §6): 문맥 9.6초, 인벤토리 텍스트 불명확, 완전한 게임 복제가 아님, 장기 기억 부족.
- 논문에 없는 것(우리가 본 것):
  1. 다이아몬드 성공은 7/1000이고 신뢰구간이 0.34–1.44%입니다. "첫 에이전트"라는 주장은 맞지만 효과 크기는 작습니다.
  2. 시드 반복, 신뢰구간, 검정이 본문에 없습니다. Table 7, Fig. 7, Table 2는 모두 단일 실행으로 보입니다.
  3. Table 1의 16과제 평가 절차가 불명확합니다.
  4. 공식 코드와 체크포인트가 공개되지 않았습니다(`04_claim_verification.md`).
  5. 부록의 학습률·옵티마이저·스텝 수가 없습니다.
  6. 계약자 데이터 기반이라 다른 게임이나 로봇으로의 일반화는 논문이 주장하지 않습니다(§6은 미래 과제로 둠).
