# 03. 수치 재계산, 일관성, 검정, 버전 차이

재현 실험은 하지 않았습니다. 논문 표 값을 옮겨 `analysis/recompute.py`로 다시 계산했습니다(numpy, scipy). 결과는 `analysis/recompute_results.json`에 있고, 각 절의 키 이름을 적었습니다. 그림은 `analysis/plot_figures.py`로 그렸습니다.

## 0. 원자료가 없다는 전제

- 논문에는 에피소드 단위 결과, 시드, 시행 수, 신뢰구간이 없습니다.
- 공식 README는 LIBERO 평가를 "50 trials/task"로 적으므로 한 군집(10과제)은 **500회**로 가정했습니다(K1, `assumption_K1_trials_per_suite`). 이 가정은 §2에서만 씁니다.
- 검정은 셀마다 독립이라고 가정합니다. 같은 정책을 같은 초기 조건으로 돌렸다면 실제 불확실성은 더 작을 수도, 더 클 수도 있습니다.

## 1. 표 재계산

### 1.1 Table 3 (LIBERO, §5.1)

- **논문 표 대 공식 README 표(V1):** README의 Table 3 복사본 9개 행, 144개 값이 논문 표와 **모두 같습니다**(`V1_table3_paper_vs_readme_mismatches` = 0). 같은 저자의 두 자료가 같은 값을 보여 줍니다. 다만 README 값도 논문과 같은 원자료에서 나왔는지는 알 수 없습니다.
- **Avg 행:** 16개 평균(4개 군집 × 4개 열) 모두 ∆ = 1..9의 산술 평균과 맞습니다(`T3_avg_row_check`).
- **본문 차이 값(`T3_claims`):**

| 주장 | 본문 값 | 재계산 (+Sched 열) | 재계산 (Ours 열) |
|---|---|---|---|
| 네 군집·∆ 평균, VLASH 대비 | 14.8 %p | 14.82 %p | 14.41 %p |
| 네 군집·∆ 평균, RTC 대비 | 3.9 %p | 3.91 %p | 3.51 %p |
| ∆ = 9, VLASH 대비 | 45.6 %p | 45.62 %p | 45.42 %p |
| ∆ = 9, RTC 대비 | 7.0 %p | 7.05 %p | 6.85 %p |

  본문 값은 +Sched 열 기준입니다. 본문에는 어느 열인지 적혀 있지 않습니다. 또 이 값은 **%p**이므로 초록의 "14.8%"는 상대 증가율이 아닙니다.
- **셀 단위:** 36칸 중 6칸에서 VLASH가 +Sched와 같거나 높습니다(Spatial ∆=1 98.8 대 98.6, Object ∆=1 99.2 대 98.8, Object ∆=3 98.8 대 98.4, LIBERO-10 ∆=1 94.4 대 93.1, ∆=2 94.6 대 92.9, ∆=3 91.9 대 91.9). 긴 ∆(≥ 5)에서만 차이가 크므로 평균 14.8 %p는 주로 ∆가 큰 칸이 만듭니다.
- **+Sched 대 Ours:** ∆별 평균 차이는 0.15–0.77 %p입니다(`T3_Sched_minus_Ours_by_delta`). 스케줄링의 정확도 효과는 작습니다.
- **+Sched 대 Sync(`T3_Sched_minus_Sync_by_suite`):** Spatial +0.10, Object −1.02, Goal +0.14, LIBERO-10 −0.99 %p입니다. "거의 손실 없음"은 Object와 LIBERO-10에서 약 1 %p 낮다는 뜻입니다.

### 1.2 Table 4 (지연과 제어 주기, §5.2)

- **Hz와 반응 시간의 대응(`T4_v7_rows`):** 제어 주기 = 1000 / 반응 시간 ms가 모든 행에서 맞습니다(Thor 스케줄 행만 4.087을 4.08로 적었음). 다만 Naive 행에서 반응 시간 = 총 지연으로 둔 것은 논문 정의와 맞지만, 다른 행의 반응 시간은 **계산 방법이 없습니다**.
- **배율(`T4_speedups_v7`, v7 값):**

| 본문 배율 | 본문 | 재계산 (ms) | 재계산 (반올림 Hz) |
|---|---|---|---|
| Orin, +Schedule | 2.11× | 2.105 | - |
| Thor, +Schedule | 1.87× | 1.871 | - |
| Orin, +Graph reuse | 3.67× | 3.668 | - |
| Thor, +Graph reuse | 1.82× | 1.818 | - |
| Orin, +Buffer & Unroll | 1.89× | 1.895 | - |
| Thor, +Buffer & Unroll | 2.20× | 2.203 | - |
| Orin, 전체 제어 주기 | 14.71× | **14.63×** | 14.71× |
| Thor, 전체 제어 주기 | 7.51× | **7.49×** | 7.51× |
| Orin, vla.cpp 대비 (893.0 ms) | 9.20× | 9.20× (893.0 / 97.1) | - |

  결론: 본문 배율 여섯 개는 모두 맞습니다. 헤드라인 14.71×은 반올림된 Hz(0.70, 10.30)로 계산한 값이고, 반응 시간으로 계산하면 14.63×입니다. 차이는 0.6%로 작지만, 표 값과 본문 계산 방식이 맞지 않는다는 기록으로 남깁니다.
- **v6 본문과 v6 표의 불일치(H1):** v6 본문은 버퍼·unroll 배율을 1.33×(Orin), 1.46×(Thor)로 썼지만 v6 표로는 184.0/144.3 = 1.275, 134.6/97.6 = 1.379입니다. v7은 1.89, 2.20으로 고쳐 씁니다(`H1_version_headlines.v6.text_1_33_1_46`).
- **가정 기반 역산(`T4_sched_implied_VLM_fraction_ASSUMED_MODEL`):** 반응 시간 = 행동 전문가 + f × (ViT + LLM)이라고 가정하면 f는 Orin 0.18, Thor 0.14입니다. 이 모델은 논문에 없으므로 값의 크기만 참고하세요. 실제 VLM 호출 비율은 논문이 보고하지 않습니다.

### 1.3 Table 1 합 검사와 Table 4의 목록 합

- Table 1에서 **Orin 50 W 행만** 목록 합과 총합이 다릅니다. π0은 100.0 ms, π0.5는 100.7 ms입니다(`T1_sum_check`). 나머지 여덟 행은 0.1 ms 이내입니다. 다만 A6000과 RTX 4090 행에서도 1.8–3.0 ms 차이가 있어 반올림으로는 설명되지 않습니다.
- 같은 100.7 ms는 공식 EagleVLA-Edge README의 Naive PI0.5 Orin 행에도 있습니다(같은 값, README는 "rounded medians need not add up exactly"라고 적음). 그래프 재사용 행에서는 차이가 0.2 ms로 사라집니다(412.9 대 412.7). 이 차이가 호스트 쪽 오버헤드였다면 그래프 재사용 배율의 일부는 커널 가속이 아니라 오버헤드 제거일 수 있습니다. 논문도 저장소도 설명하지 않으므로 가능성으로만 둡니다.

### 1.4 Table 2 (균형 강도)와 대역폭 제약 점검

- **계수:** 균형 강도 열은 floor(2000 × TOPS / 대역폭) 규칙과 맞습니다(RTX A6000, Orin 32/64 GB, Thor, `T2_balance_factor`). 그런데 RTX 4090 행은 2 × 309 / 1024 × 1000 = 603이 나와야 하는데 표는 618입니다(618은 대역폭을 1000 GB/s로 놓았을 때 값). 계수 2의 근거도 본문에 없습니다.

| 장치 | VLM 계산 판정 | 표 2 라벨 | 행동 전문가 판정 | 표 2 라벨 |
|---|---|---|---|---|
| RTX 4090 | 계산 (0.022 ms 대 0.011 ms) | 계산 바운드 | 대역폭 | 대역폭 |

## 2. 통계 검정 (K1 가정, 근사)

- **격자 검사(`K1_values_not_on_n500_grid`):** 500회 단일 집계라면 성공률은 0.2 %p의 배수여야 합니다. Table 3의 148개 값(네 군집의 Sync 4개 포함) 중 **85개가 맞지 않습니다**. 예를 들어 Spatial Sync 97.3(486.5/500), Goal Sync 96.7, LIBERO-10 Sync 93.5가 그렇습니다. 따라서 Table 3 값은 500회 단일 집계가 아니거나, 여러 시드의 평균이거나, 다른 분모를 썼을 가능성이 큽니다. 논문에는 이 사실이 적혀 있지 않습니다. 이 항목은 저자에게 물을 질문으로 둡니다(`04` §3).
- **Sched 대 VLASH(Fisher 정확 검정, 셀 36칸, `K1_fisher_Sched_vs_VLASH_cells`):** 25칸에서 +Sched가 유의하게 높고(p < 0.05), 11칸은 차이가 없습니다. 11칸은 Spatial ∆=1–2, Object ∆=1–3, Goal ∆=1–2, LIBERO-10 ∆=1–4입니다. 낮은 쪽으로 유의한 칸은 없습니다.
- **Sched 대 Ours(`K1_fisher_Sched_vs_Ours_cells`):** 36칸 모두 유의하지 않습니다. 보정 모듈만 쓴 방법과 스케줄을 더한 방법은 칸별로 구분할 수 없습니다.
- **네 군집 평균 차이의 근사 95% 구간(셀 독립 가정, `T3_claims`):** +Sched − VLASH = 14.82 %p [14.24, 15.40], +Sched − RTC = 3.91 %p [3.44, 4.38]. 셀이 독립이 아니면 구간은 좁게 나옵니다. 이 구간은 "시행 수 500과 독립 가정이 맞을 때의 근사"로만 읽으세요.

## 3. 실로봇 (§5.3, Fig. 7)

| 시스템 | 과제별 (Picking, Folding, Placing, 각 10회) | 합계 | Wilson 95% |
|---|---|---|---|
| RTX 4090 (기준) | 10, 7, 10 | 27/30 (0.90) | [0.744, 0.965] |
| Jetson Orin 나이브 비동기 | 6, 0, 5 | 11/30 (0.37) | [0.219, 0.545] |
| EagleVLA | 10, 8, 9 | 27/30 (0.90) | [0.744, 0.965] |

- Fisher 검정: EagleVLA 대 나이브 p = 3.3 × 10⁻⁵, EagleVLA 대 4090 p = 1.0, 나이브 대 4090 p = 3.3 × 10⁻⁵(`F7_real_world`).
- **해석:** 나이브 대비 향상은 뚜렷합니다. "4090과 거의 같다"는 p = 1.0이라는 **차이가 없다는 증거가 아닙니다**. 과제당 10회, 합계 30회에서는 각 비율의 95% 구간이 0.74–0.97로 넓고, 두 비율 차이의 구간은 0을 충분히 포함하므로 동등성을 주장할 수 없습니다.
- **과제 구성:** Folding 8/10은 4090 7/10보다 높지만 10회로는 구분할 수 없습니다.
- **모델과 주기 불일치:** 실로봇은 XR-1 모델이고 행동을 15 Hz로 실행합니다. Table 4의 10.30 Hz(π0.5, LIBERO)와 같은 설정이 아니므로, 실로봇 결과를 지연 표와 직접 연결할 수 없습니다.

## 4. 지연 산술: 어떤 값이 어디서 나오는가

- 전체 제어 주기 이득 = 스케줄 × 그래프 재사용 × 버퍼·unroll 배율의 곱(Orin: 2.105 × 3.668 × 1.895 = 14.63, Thor: 1.871 × 1.818 × 2.203 = 7.49)입니다. 셋 중 어느 것도 독립 측정이 아니며, 구간별 반응 시간은 측정 방법이 없습니다.
- 버퍼·unroll 단계의 값(Orin 66.6/137.0/67.6, Thor 29.0/54.9/48.9)은 공식 엔진 README의 "+ time cache, and GEMM tuning (PR #6)" 행과 같습니다. 이 행은 버퍼·unroll 단계가 아니라 **GEMM 튜닝, 시간 변조 캐시, FP16 캐스트, 새 FP16 모델·프로젝터가 포함된 구성**입니다(`04` D12). 따라서 §5.2의 "버퍼·unroll이 1.89×, 2.20×"는 이 구성 전체의 효과이며 단계별 귀속이 아닙니다.
- Edge README는 같은 날짜(2026-10-23)에 "이 구성은 같은 체크포인트에서 통제된 절제 실험이 아니다"라고 명시합니다. 그래서 단계 배율은 분리해서 읽으면 안 됩니다.
- **Thor 정확도 단서:** 같은 Thor 행은 저장소에서 "정확도 게이트(cosine > 0.9994) 미통과, 최소 0.999075"라고 적혀 있습니다. 이 값을 쓴 Thor 헤드라인 7.51×은 정확도 승인 전 값입니다(`04` D13).

## 7. 결론 (재계산 기준)

1. **재현된 것:** Table 3의 평균과 본문 차이(%p, +Sched 기준), Table 4의 배율 여섯 개와 제어 주기 대 반응 시간, Table 2의 대역폭 제약 라벨, 실로봇 합계와 Fisher 검정.
2. **재현되지 않거나 불일치한 것:** 헤드라인 14.71×의 계산 방식(반올림 Hz, 반응 시간으로는 14.63×), v6 본문 배율(1.33×, 1.46×), Table 1의 Orin 50 W 행 합(100.7 ms), Table 2 RTX 4090 행 계수, Table 3 값의 500회 격자 불일치(148개 중 85개).
3. **판단을 바꾸는 것:** 최종 행이 버전마다 바뀌었고, 바뀐 이유가 논문에 없습니다. 최종 행은 저장소의 최적화 구성이며, Thor 구성은 정확도 게이트를 통과하지 못했습니다. 그래서 헤드라인 배율은 "최적화 구성 전체의 측정값"으로 읽어야 하고, 방법의 효과로 귀속하면 안 됩니다.
