# 04. 주장 검증과 구현 가능성 (공식 코드 없음)

공식 저장소 `github.com/shenbiachao/HumanoidNDM`은 2026-09-27에 만들어진 **빈 저장소**입니다(커밋 0개, 2026-11-24 확인). 논문과 코드를 대조할 수 없어 `04_code_verification.md` 대신 표와 본문 수치의 재계산으로 주장 C1–C18을 점검합니다. 재계산 근거는 `03`의 V, K 항목입니다. 코드가 공개되면 D 항목으로 다시 대조해야 하는 값은 §3에 모았습니다.

## 1. 판정 기준

- **재현:** 논문 표 값에서 같은 수가 나옴.
- **부분 지지:** 방향은 맞으나 서술의 범위가 값보다 넓음.
- **구분 불가:** 보고된 평균과 SD, 시행 수로는 차이가 있다고도 없다고도 말할 수 없음.
- **재계산 불가:** 수치 표가 없고 그림에만 있거나 정의가 없음(그림 판독은 하지 않음).
- 시행 수는 표 2·3·7은 5회, 표 4는 3회, 표 5는 3회로 가정했습니다(`03` §0).

## 4. 구현 가능성 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**전체 재현은 이 맥에서 불가능합니다. 공식 코드가 없어 논문을 그대로 구현하려면 처음부터 짜야 하고, 시뮬 축소판(MuJoCo CPU + PyTorch)은 구현할 수 있습니다. 모델과 정책 갱신 루프의 계산은 이 맥에서 같은 자릿수로 돕니다.**

| 구분 | 판정 | 이유 |
|---|---|---|
| 실로봇 실험(표 4, 5, Unitree G1) | 불가 | G1과 부하, 탄성 밴드, 손상 모터, 안전장치가 필요. 데이터와 체크포인트도 공개되지 않음 |
| 공식 코드 실행과 대조 | 불가 | 저장소가 비어 있음 |
| 시뮬 표 2 전체(5동작 × 3교란 × 5방법 × 5시행) | 사실상 불가 | 기본 정책(PPO, MJX, G1 5동작)과 PPO w/ Disturb., ASAP·RWM 이식본을 모두 새로 만들어야 하고 JAX(MJX) 환경을 새로 설치해야 함. 기본 정책 학습의 시간은 측정하지 않았음 |
| 방법의 축소판(저자유도 MuJoCo 모델, 소형 정책) | **가능** | 아래 노력 추정 참조. 새 패키지 설치는 필요 없음(torch 2.15, mujoco 4.0이 이미 있음) |
| NDM 학습과 모델 기울기 정책 갱신 루프의 계산 | **가능** | 토이 T2에서 514,080 파라미터 NDM의 반복 추정이 CPU 7.1 s, MPS 1.8 s(`03` §3.2). 논문은 4090에서 약 3 s |
| FENCE 섭동과 안정성 비교 | 가능(토이로 확인) | 토이 T1에서 순서(`03` §3.1) |
| 이 맥에서 하지 않은 것 | | 새 환경 설치, 모델 다운로드(예: G1 MuJoCo 모델 파일), 정책 학습 |

**노력 추정(모두 추정, 측정 전).**
- 1–2일: MuJoCo 저자유도 모델에서 FENCE 섭동 + 기준 추종 PD 정책 + 데이터 수집 루프(토이 T1을 MuJoCo로 옮김).
- 1–2주: 이력 트랜스포머 NDM + 앙상블 머리 + 구성·유클리드 이중 손실(미분 가능 FK는 MuJoCo의 `mj_kinematics`를 torch로 다시 쓰거나 직접 구현) + 자기회귀 롤아웃 학습.
- 1–2주: 모델 기울기 정책 미세조정(Lπ = 128 롤아웃 역전파)과 교란(질량·Kp·마찰) 시뮬 평가, 직접 전이와 모델 없는 기준선 한두 개와 비교.
- 위를 합치면 시뮬 축소판 약 3–5주. G1 모델과 기본 정책을 쓰는 설정은 기본 정책 학습 시간이 미정이라 따로 추정하지 않았습니다.
- 실로봇 확장은 G1과 안전 체계가 있어야 하므로 추정하지 않았습니다.
