# 04. 주장 검증과 구현 가능성

- **대상:** Mana arXiv:2606.13677v1. Mana 자체 코드는 공개되지 않아, 주장은 표·그림·부록 수치로 검증했습니다(§1). 공개된 구성 요소인 Lightning Grasp `zhaohengyin/lightning-grasp` @ `af43818`(2026-06-12)는 Mana 서술과 대조했습니다(§2).
- **범위:** GPU 실행 없이 CPU 재계산(`table_check.py`), 물리 toy(`physics_toy.py`), 코드 읽기만 했습니다.

## 2. 공개 구성 요소 대조: Lightning Grasp (`af43818`)

Mana는 LG 위에 LG+를 만들었다고 씁니다(Sec. 3.1, 부록 A.1). 공개 LG 저장소(파일 42개, CUDA는 바이너리로만 배포)를 읽고 Mana의 서술과 맞춰 보았습니다.

| # | 내용 | Mana 서술과의 관계 |
|---|---|---|
| D1 | 파이프라인은 다음 순서입니다(`demo.py`). 접촉 영역에서 접촉점 탐색(0차 최적화, wrench 점수) → 접촉 ID 샘플링 → 거친 IK(`batch_ik`, 접촉 위치·법선 정합, 재시도 10회, `err_thresh` 0.02로 필터) → 반복 투영 + IK 미세조정(`batch_contact_adjustment`, 기본값 4회 × 3스텝, 3스텝마다 재투영, 허용 오차 4 mm) → 자유 손가락 배치 + 충돌 필터. | Sec. 3.1의 "contact field 질의 → 접촉 영역 → 손끝 위치와 관절 최적화"와 일치합니다. |
| D2 | **IK에 침투 해소 항이 없습니다.** 충돌은 마지막 단계에서 결과를 버리는 필터로만 씁니다(`collision.py`, `batch_assign_free_finger_and_filter`). | Mana가 지적한 LG의 한계("kinematic optimization is not collision-aware", A.1)를 코드로 확인했습니다. 따라서 LG+의 핵심(Algorithm 1의 p → p + d 목표)은 공개 코드에 없습니다. |
| D3 | 지면·탁자 같은 **환경 장애물 개념이 없습니다.** 물체 자세는 손 기준 표준 공간에서 샘플링하고, 손–물체·손–손 충돌만 검사합니다(`object_placement.py`). | Sec. 3.1의 "in the presence of environmental obstacles"와 탁자 위 파지(Fig. 9)는 공개 LG만으로는 재현할 수 없습니다. |
| D4 | README가 "hand–object 침투를 줄이는 position iteration을 운동학 미세조정에 넣은 판"을 다음 릴리스로 예고합니다(2026-05-24 작성). 10월 말 기준 main에는 반영되지 않았습니다. | LG+와 같은 기능으로 보입니다(추정). |

## 4. 구현 가능성 판단

### 4.1 공식 코드로 재현
**불가능합니다.** Mana 코드(데이터 생성기, LG+, RL 환경, 도구 모델, 정책)가 공개되지 않았습니다. 공개된 것은 LG뿐이고, 그것도 지면 장애물과 침투 해소가 없는 판입니다(D2, D3).

### 4.2 공개 구성 요소로 다시 조립
| 구성 요소 | 공개 여부 | 필요한 것 |
|---|---|---|
| 파지 keyframe (LG) | ✅ (바이너리, 비상업) | Ubuntu + NVIDIA GPU + CUDA 12 |
| LG+ (탁자 위 얇은 물체) | ❌ | Algorithm 1을 직접 구현. LG CUDA 소스가 없어 Python 쪽에 IK 목표를 추가해야 함 |
| MP (GPU RRT-Connect) | 일반 기법 | cuRobo 같은 공개 플래너로 대체 가능(추정) |
| RL 전이 (IsaacLab PPO) | 틀은 공개 | 도구별 URDF·스프링 식별, 보상·랜덤화는 부록 A.2–A.3대로 |
| 점군 diffusion 정책 | 구조만 공개 | 구현은 표준(Perceiver + DDPM head) |
| 배포 지각 (SAM 3 + Fast-FoundationStereo) | ✅ | NVIDIA GPU(논문은 RTX 4090 2장) |
| 하드웨어 | — | xArm7 + Allegro + D435, 실리콘 손끝 성형 |

### 4.3 이 맥(Apple M4 Pro GPU, CUDA 없음)에서
- **완료한 것:** 표·그림 재계산, 손가락 힘 용량·적분기·랜덤화 toy, LG 코드 읽기(모두 CPU, 설치 없음).
- **할 수 있어 보이는 것:**
  - Algorithm 1(침투 해소 IK)을 numpy로 평면 toy에 구현해, 얇은 물체 지면 파지에서 효과를 보는 것(설치 없음).
  - MuJoCo(CPU, 설치 필요)로 스프링 도구 관절의 적분기 비교를 실제 접촉 솔버에서 확인하는 것.
- **불가능한 것:** LG 실행(CUDA 바이너리), IsaacLab RL, SAM 3·스테레오 실시간 지각, 실물 실험.

### 4.4 아이디어만 재구현
- **쉬운 부분:** keyframe 그래프 + 구간별 MP/RL 분해, 보상 식, 점군 diffusion 정책은 수백 줄 수준입니다.
- **어려운 부분:**
  - 도구마다 관절 모델과 스프링 힘을 실측해 시뮬레이션에 맞추는 일.
  - 지면 근처 얇은 물체의 파지 합성(LG+).
  - 접촉이 강한 소형 물체의 시뮬레이션 안정성(암시적 액추에이터, 작은 dt, 많은 solver 반복).
  - 실물 손끝 제작.
- **결론:** 이 연구의 가치는 "데이터 생성 공학"에 있어서, 공개 코드 없이 같은 성능을 내기는 비용이 큽니다. LG+가 포함된 Lightning Grasp 다음 릴리스나 Mana 코드 공개를 기다리는 편이 현실적입니다.
