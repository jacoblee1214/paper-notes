요약

  1. 무엇을 했나: WAM(미래 영상 + 행동을 함께 생성하는 정책)에 코드 전문가를 붙여, 스킬 호출 프로그램·미래 영상·행동을 한 루프에서 함께 denoise한다. 프로그램 라벨은 Gemini 3.1 Pro와 Claude Code가 자동으로 만들고 스킬 50개로 정리했다.
  2. 숫자는 정확하다: Table 11(600칸) → Table 1 평균 12개, 본문·그림 수치 36개, Table 12의 성공·실패 가중 합이 모두 맞는다. 실제 로봇 AW-0 점수는 모두 루브릭 점수 격자(48회) 위에 있다.
  3. RoboTwin 기준선이 약하다: 같은 학습 데이터의 RoboTwin 공식 리더보드 π0.5는 clean 70.66 / random 46.0인데, 논문 재현 π0.5는 54.9 / 27.7이다. 리더보드 값과 비교하면 AW-0는 random에서 25.4점, 평균에서 7.6점 낮고, 하이브리드도 random에서 16.8점 낮다. "평균 최고", "하이브리드가 모든 기준선보다 강건"은 논문이 재현한 기준선 안에서만 성립한다.
  4. 코드 효과의 대부분은 "계획 스트림 + ViT"의 효과다: 코드 전문가 없음 32.9 → 자연어 subgoal 63.6 → 코드 71.1. "코드 대 자연어" 몫은 7.5점(20%)이다. 공식 코드에서 "코드 없음" 변형은 Qwen3-VL ViT 시각 입력까지 함께 빠진다.
  5. 확실한 것과 약한 것: 실제 로봇에서 기준선보다 25점 높다는 결과와 RoboTwin clean의 우위는 견고하다. Fig. 7 변형 간 차이(약 8점)는 과제별로 표본 오차 상한 안이고, 하이브리드의 random 이득은 5개 과제에 몰려 있으며 학습 데이터·step·디코딩이 모두 달라 실행 방식의 효과로 분리되지 않는다.
  6. 논문과 공개 코드의 차이: 학습형 메모리 슬롯은 공개 설정에서 꺼져 있고, joint 단계(논문 4 vs 공개 10–40), 코드 canvas, RoboTwin 학습 설정이 다르며, 하이브리드에는 규칙 기반 repair가 있다. 4단계 추론에서 action이 읽는 "미래 영상"은 σ ≥ 0.625인 흐린 상태다.
  7. 재현: 하지 않았다. 학습·평가 모두 GPU가 필요하다. 표·그림 재계산, noise 재표본화 toy, 코드 정적 대조만 CPU로 했다.

1. Abstract

World Action Model(WAM)은 미래 영상과 행동을 함께 예측하지만, 기술을 재사용하거나 조합하는 명시적 구조가 없습니다. 반대로 코드 기반 agentic 로봇 시스템(Code-as-Policies 계열)은 기술을 프로그램으로 조합하지만, 물리 동역학을 예측하지 않습니다. AW-0는 둘을 합칩니다. Mixture-of-Transformers(MoT) 안에 코드 전문가, video 전문가, action 전문가를 두고 세 스트림을 한 번에 denoise합니다. 코드는 두 역할을 합니다.

  1. 모델 안에서 영상과 행동 생성의 계획 조건(plan)이 됩니다.
  2. 따로 실행할 수 있는 기술 프로그램이 됩니다.

학습용 프로그램 라벨은 VLM(Gemini 3.1 Pro)과 coding agent(Claude Code, Opus 4.8)로 자동 생성하고, 반복되는 루틴을 스킬 라이브러리(50개)로 모읍니다. 저자들은 다음 결과를 보고합니다.

  • RoboTwin 2.0에서 두 설정의 평균 50.7%로 기준선 4개(π0.5, DreamZero, EgoScale, WLA)보다 높습니다.
  • 실제 로봇 8과제의 평균 루브릭 점수는 71.1로, 가장 강한 기준선(DreamZero 46.0)보다 25.1점 높습니다.

2. Method

2.1 문제 설정 (§2, Eq. 1–2)

조건 C_t = {O_t(다시점 관측), L(지시문), S_t(로봇 상태), M_t(이전 프로그램 조각의 메모리)}에서 p_θ(C₀, Z₀, A₀ | C_t)를 학습합니다.

  • C₀: 코드 토큰열
  • Z₀: 미래 영상의 VAE 잠재
  • A₀: H=32 step의 행동 chunk

하나의 네트워크 F_θ가 masked code C̃_r, noisy video Z_σv, noisy action A_σa를 받아 코드 logit과 두 속도장을 동시에 냅니다(Eq. 2).

2.3 Joint denoising (§2.2, Eq. 3–6)

  • video와 action: flow matching을 씁니다. X_σ = (1−σ)X₀ + σε이고, σ = γu/(1+(γ−1)u), γ = 5입니다.
    • video의 사전학습 분포는 u = 0.999·Beta(7,1)입니다.
    • action은 u ~ U(0,1)입니다.
  • 코드: 흡수 마스크 확산을 씁니다. r ~ U(0,1)로 각 토큰을 [MASK]로 바꾸고, 마스크 위치의 cross-entropy를 학습합니다.
  • Noise 재표본화(Eq. 5–6): video의 u를 혼합 분포 q = 0.5·p_pre + 0.5·U(0,1)에서 뽑고, 손실별로 중요도 가중치를 다르게 줍니다.
    • video 손실에는 w_v = p_pre/q를 줍니다. 원래 video 목표를 유지하기 위해서입니다.
    • action과 code 손실에는 w_g = U/q를 줍니다. action과 code가 "덜 흐린 미래 영상"을 보는 경우를 늘리기 위해서입니다.
    • 가중치는 clip 4.0 후 배치 평균 1로 정규화하고, 손실 가중치는 (v, c, a) = (1, 0.5, 1)입니다(Table 6).
  • 추론: 128 토큰짜리 마스크 canvas를 놓고, T번의 joint step마다 가장 확신하는 G/T개 위치를 확정합니다. 기본 T = 4입니다(Table 6).

2.4 코드 라벨 자동 생성 (§2.3, 부록 K)

  1. 과제마다 에피소드 하나를 뽑습니다. Gemini 3.1 Pro가 선언만 있는 primitive API(Fig. 38)로 subtask 단위 프로그램을 씁니다. Claude Code(Opus 4.8) coordinator는 반복 패턴을 스킬로 증류합니다.
    • 스킬 채택 조건: 일반적이어야 하고, 2개 이상 과제에서 반복되어야 하며, 동작 수준이어야 하고, 기존 스킬과 중복되지 않아야 합니다.
  2. 스킬 라이브러리를 동결합니다. YAM용 23개, 사람 1인칭 영상용 27개입니다(Table 8–9).
  3. 나머지 데이터는 캐시된 프로그램을 재사용합니다. 재사용 조건은 YAM에서는 그리퍼 개폐 사건이 일치하는 것이고, 사람 영상에서는 손 운동 프로파일이 가까운 것입니다. 재사용 조건을 만족하지 못하면 새로 생성합니다.

논문 Fig. 3: 자동 라벨 파이프라인. 스킬 발견(coding agent + coordinator) → 라이브러리 동결 → 캐시 재사용 라벨링.

2.5 메모리와 하이브리드 실행 (§2.3, 부록 I)

  • 메모리: 지금까지 생성한 코드 조각을 학습 가능한 K개 슬롯으로 압축해 코드 스트림 앞에 붙입니다. 학습 때는 확률 p로 모델 자신의 예측을 넣습니다. p와 K는 본문에 적혀 있지 않습니다.

  • 기본 모드: 코드는 실행하지 않습니다. 코드는 계획 조건일 뿐이고, 로봇은 action chunk가 움직입니다.

  • 하이브리드 모드(Algorithm 1–2): 생성된 코드 조각을 Code-as-Policies 방식으로 실행할 수 있습니다. 실행하려면 다음 게이트를 모두 통과해야 합니다.

    • stage 게이트: 아직 완료되지 않은 단계이고, 실패 횟수가 R 미만이어야 합니다.
    • 의존성 게이트: 쓰는 변수가 모두 정의되어 있어야 합니다.
    • 문법·whitelist·공문 게이트: 컴파일되고, 허용된 함수만 부르며, 실행할 문장이 있어야 합니다.

    게이트를 통과하지 못하면 같은 forward의 action chunk를 씁니다. 저자들은 "생성 코드를 수리하지 않고 검사한다"고 씁니다.

2.6 학습 (§2.4, 부록 A–B)

  • 사전학습: YAM 원격조작 1,919시간(73,101 에피소드, 279 과제)과 사람 1인칭 994시간(175,541 에피소드, 327 과제), 합계 2,913시간입니다.
    • 학습 자원: H100 48장, 유효 배치 2,592, 1 epoch.
    • 배치의 15%에서는 지시문과 프로그램을 마스크로 바꿉니다.
  • 사후학습: 과제마다 시연 100개로 20 epoch 학습합니다. RoboTwin은 과제당 clean 시연 50개(총 2,500개)로 100k step 학습합니다.

4. Limitations

4.1 저자가 밝힌 한계 (부록 L)

  • 코드 품질: 코드 품질은 자동 라벨의 정확도와 스킬 범위에 달려 있습니다. 스킬은 맞게 골라도 인자가 틀릴 수 있습니다(부록 F.1: 사전학습 모델의 parse rate 87.5%, primitive F1 0.365).
  • 분포 이동: 시각 분포 이동에 여전히 약합니다. 하이브리드 실행은 random에서 낫지만 clean에서는 성능을 깎습니다. arbiter는 유효성만 보고, 코드가 action보다 나을지는 예측하지 않습니다.
  • 실제 로봇 하이브리드 평가: YAM 과제 하나뿐입니다. 손에 쓸 CaP 시스템이 없기 때문입니다. 온라인 학습도 하지 않습니다.

4.2 추가로 확인한 한계 (03, 04에서 근거)

  1. π0.5 기준선이 공식 리더보드보다 크게 낮습니다.
    • RoboTwin 공식 리더보드에는 RoboTwin 팀이 같은 학습 데이터(50과제 × clean 50개)로 낸 π0.5 co-train 결과가 2026-08-10부터 올라와 있습니다. 값은 clean 70.66, random 46.0입니다.
    • 논문이 재현한 π0.5는 54.9와 27.7입니다. 리더보드 값과 비교하면 AW-0는 random에서 25.4점, 평균에서 7.6점 낮습니다.
    • "평균이 가장 높다"는 주장은 논문이 직접 재현한 기준선 안에서만 성립합니다(03 §2).
  2. "코드 전문가 없음" ablation은 Qwen3-VL ViT 시각 경로도 함께 뺍니다.
    • 공식 코드에서 ViT prefix는 코드 전문가에만 붙습니다. 따라서 32.9 → 71.1의 차이에는 의미 수준 시각 입력의 효과가 섞여 있습니다.
    • 같은 구조에서 코드 대신 자연어 subgoal을 쓰면 63.6입니다. "코드 대 자연어"의 몫은 7.5점(전체 이득의 20%)이고, 나머지 30.8점은 계획 스트림과 ViT가 있는지에서 나옵니다(03 §3).
  3. 하이브리드 비교에는 학습 데이터 외에도 차이가 있습니다. 공개 설정에서 하이브리드 모델은 15k step, 기본 모델은 200k step을 학습했습니다. 추론 단계와 코드 디코딩 규칙도 다릅니다(04 D6).
  4. 실제 로봇 결과의 불확실성이 보고되지 않았습니다. 시드별 값과 표준편차가 없습니다. 8과제 평균의 차이(AW-0 대 기준선)는 크지만, Fig. 7 변형 간 과제별 차이는 표본 오차 상한 안에 있습니다(03 §4).
  5. 논문의 설정과 공개 설정이 다릅니다. 학습형 memory slot, 추론 단계 수(4), 코드 canvas(128), RoboTwin 학습률·step 수가 공개 설정과 다르고, 하이브리드 모드에는 규칙 기반 repair가 들어 있습니다(04 §2).
  6. "미리 보는 영상"은 꽤 흐린 상태입니다. 4단계 joint denoising에서 action이 읽는 video는 σ ≥ 0.625입니다. 논문이 말하는 "predictive guidance"는 덜 denoise된 video 특징입니다(03 §5).

5. Noise 재표본화와 "미리 보는 영상"의 실제 상태 (noise_toy.py)

  • N1. 사전학습 video 분포(u = 0.999·Beta(7,1), shift 5)에서는 σ > 0.9가 95.5%이고, 중앙값은 σ = 0.979입니다. 공식 코드 주석의 "~95%"와 일치합니다. 이 분포만 쓰면 action 손실은 거의 잡음뿐인 video만 보고 학습됩니다. Eq. 5–6이 이 문제를 고칩니다.

  • N2. α = 0.5이므로 가중치의 상한은 1/α = 1/(1 − α) = 2입니다. 실제 최댓값은 w_v 1.75, w_g 2.0입니다. Table 6의 importance clip 4.0은 한 번도 작동하지 않습니다. 공식 코드 주석도 같은 상한을 적어 둡니다.

  • N3. 정규화하지 않은 가중 손실은 목표 분포의 기댓값을 정확히 재현합니다. 공식 설정처럼 GPU당 배치 6(3 + 3 층화)에서 "배치 평균 1로 정규화"하면 작은 편향이 생깁니다. 예를 들어 action 손실이 σ < 0.7 구간을 보는 비율은 31.8%가 아니라 30.0%가 됩니다. 실효 표본 수는 배치의 약 70%입니다. 영향은 작습니다.

  • N4. 추론에서 video와 action은 같은 단계 수로 함께 denoise합니다. 공식 코드에서 action은 각 단계 시작 시점의 video를 읽습니다. 그래서 action이 마지막으로 읽는 video의 σ는 단계 수에 따라 다음과 같습니다(report/figures/noise_sigma.png).

    joint 단계 action이 읽는 video σ 마지막 σ
    4 (논문 Table 6) 1.0, 0.94, 0.83, 0.63 0.625
    10 (실물 서버 기본값) 1.0 … 0.36 0.357
    20 (RoboTwin 공개 설정) 1.0 … 0.21 0.208

    논문 설정(4단계)에서 action이 보는 "미래 영상"은 잡음이 62.5% 이상 섞인 상태입니다. 논문이 말하는 predictive guidance는 선명한 미래 영상이 아니라, 덜 denoise된 video 전문가의 내부 특징입니다. 지연 0.23 s(Fig. 6)는 4단계일 때의 값으로 보입니다. RoboTwin 결과를 낸 공개 설정(20단계)의 지연은 이보다 클 것입니다.

  • N5. 4단계 추론이 쓰는 σ 범위(0.625–1)는 균등 목표에서 학습 표본의 75%를 차지합니다. 나머지 25%(σ < 0.625)에서 학습한 action은 4단계 추론에서는 쓰이지 않습니다.

6. 코드가 행동에 영향을 주는 경로 (코드 읽기에서의 해석)

  • 코드는 attention 섬입니다. 코드 스트림은 [ViT prefix][지시문][canvas]만 보고, video와 action을 읽지 않습니다(_build_mot_attention_mask). 그래서 계획은 관측 이미지(ViT)와 지시문만으로 정해지고, 예측된 미래 영상으로 수정되지 않습니다. 저자들이 V → C → A보다 C → V → A가 낫다고 한 결과(48.3 vs 71.1)도 같은 방향입니다. 코드는 영상을 보지 않는 편이 낫습니다.
  • action은 완성된 프로그램을 보지 않습니다. 코드 토큰은 각 joint step의 forward 다음에 확정됩니다. 그래서 4단계 디코딩에서 action은 canvas가 0%, 25%, 50%, 75% 공개된 상태를 차례로 봅니다. 다만 action은 토큰이 아니라 층마다 코드 전문가의 hidden state를 읽습니다. 그래서 마스크된 위치에도 계획 정보가 들어 있을 수 있습니다. "로그에 남는 코드"와 "action이 조건으로 쓴 것"이 같지 않다는 점은 해석할 때 주의해야 합니다.
  • 기본 모드에서 코드는 실행되지 않습니다. 따라서 기본 모드의 성능 향상은 "코드를 실행해서"가 아니라 "코드를 맞히도록 학습한 표현을 action이 읽어서"입니다. 자연어 subgoal과의 차이가 7.5점에 그친다는 점(§3)도 이 해석과 맞습니다.

1. 두 갈래의 계보

AW-0는 두 갈래를 하나의 생성 모델로 묶습니다. 하나는 "미래를 예측하며 행동하는 정책"(World Action Model)이고, 다른 하나는 "코드로 계획하고 기술을 조합하는 에이전트"(agentic robotics)입니다.

  • agentic robotics의 문제: 코드는 정책 바깥에서 로봇을 조종하고, 부를 수 있는 primitive의 성능에 묶입니다. 물리 동역학을 예측하지도 않습니다.

4. 이 논문이 주장하는 새로움과 실제로 새로운 것

  • 새롭다고 볼 만한 것:
    • 코드(이산 마스크 확산), 영상, 행동(연속 flow)을 같은 denoising 루프에서 함께 만드는 구조입니다.
    • 자동 라벨 파이프라인으로 3,000시간 규모의 데이터에 프로그램을 붙인 것도 새롭습니다. 50개 스킬 라이브러리와, 사건 일치 기반 캐시 재사용이 여기에 들어갑니다.
  • 조합에 가까운 것:
    • 각 구성 요소(MoT, LLaDA식 디코딩, Cosmos 백본, CaP primitive)는 모두 기존 것입니다.
    • 하이브리드 arbitration은 규칙 기반 게이트입니다. 학습된 선택기가 아닙니다.
  • ablation이 실제로 보여 주는 것: 계획 스트림(자연어든 코드든)과 의미 수준 시각 입력(ViT)이 있으면 성능이 크게 오릅니다(32.9 → 63.6). 코드라는 형식이 더하는 몫은 그보다 작습니다(+7.5, 03 §3).

5. 이 저장소의 다른 논문과의 관계

논문 관계
Hydra-0 (hydra0/) 둘 다 NVIDIA 계열 video world model(Cosmos 계열)을 정책에 쓰는 WAM입니다. Hydra-0는 행동을 이미지 평면의 점 궤적(action flow)으로 표현하고, AW-0는 64차원 말단 자세·관절 행동을 쓰면서 코드 계획을 더합니다. 두 논문 모두 "영상 예측이 행동을 돕는다"는 주장을 같은 구조의 대조군 없이 내세운다는 점에서 비슷합니다.
ZeroDex (zerodex/) 학습된 정책 없이 VLM과 고정 primitive로 손을 움직이는 agentic 쪽 극단입니다. AW-0의 하이브리드 모드가 실패하는 이유(primitive의 실패를 그대로 물려받음, 부록 J.2)는 ZeroDex의 단계별 실패 귀속 분석과 같은 문제입니다.
GPT-as-Tactile-Policy (gpt6_astra_tactile/) 대형 언어 모델이 느린 계획을 맡고 빠른 정책이 실행하는 구조입니다. AW-0는 계획과 실행을 한 forward에 넣어 지연을 0.04 s로 줄였다고 주장합니다. 반면 AR 코드 생성은 0.55 s가 걸립니다(Fig. 6).
Chronos Policy (chronospolicy/) AW-0는 32 step chunk 중 24 step마다 다시 계획합니다(공개 서버 기본값). 추론 지연 0.23 s 동안의 관측 지연은 다루지 않습니다. Chronos의 시간 조건화가 보완할 수 있는 부분입니다.
FlashDexRetarget (flashdexretarget/) 같은 Sharpa Wave 손을 씁니다. AW-0는 사람 1인칭 영상의 손 운동을 22-DoF 관절 목표로 리타겟해서 사전학습에 넣습니다(부록 B.1). 리타겟 품질 평가는 논문에 없습니다.
DexScrew, Contact-Grounded Policy 접촉이 많은 다지 손 과제입니다. AW-0의 실패 사례(카드 미끄러짐, 손끝 접촉 상실, 부록 H)는 촉각 없이 시각만 쓰는 정책의 한계와 같습니다. AW-0는 촉각 입력을 쓰지 않습니다.

6. 논문에 없는 관련 연구 (비교해 볼 만한 것)

  • RoboTwin 리더보드의 WAM 계열: UniWAM, PatchWAM, 4D-WAM, PrismWAM 등이 같은 프로토콜에서 clean과 random 모두 AW-0보다 높거나 비슷합니다(03 §2). 이 중 상당수는 AW-0 공개(2026-10-21) 전에 등록되었습니다.
  • Motus (Bi et al. 2025): AW-0가 "전문가 기반 WAM"으로 인용하는, 구조가 가장 가까운 선행연구입니다. 하지만 Table 1이나 Table 2의 비교 대상에는 없습니다.
  • 기준선 저자의 중복: 기준선 EgoScale(Zheng et al. 2026)의 저자 일부(Ruijie Zheng, Dantong Niu, Jing Wang, Linxi Fan)가 AW-0 저자이기도 합니다. EgoScale을 RoboTwin random에서 2.9%로 보고한 것이 그 모델의 최선 설정인지는 논문만으로 판단할 수 없습니다.
