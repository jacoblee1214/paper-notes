## 1. 문제 설정과 주장

- 잠재 세계 모델(latent world model)로 행동열 후보를 비교할 때, 재귀 롤아웃(recursive rollout)은 후보마다 H번의 예측이 필요해 온라인 비용이 큽니다 [§1, §3.5].
- 논문의 주장은 **후보 생성은 중간 예측을 쓰고, 후보 평가는 종점 예측만 쓰면** 성공률을 유지하면서 지연을 줄일 수 있다는 것입니다 [§1, Fig. 2].
- 목표 함수는 시각 목표 기준 종점 거리입니다. `J(A) = ||Q(z_t, A, H) − z_g||²` (식 4 부근, §3.4). 최적 계획은 `A* = argmin_{A∈S} J(A)`입니다.

## 2. 방법

### 2.1 공유 순방향 모델과 앵커 질의 (§3.2, 식 2)

- 같은 순방향 모델 `W_ψ`를 쓰며, 질의는 항상 **관측 표현 `z_t`에서 출발**합니다: `Q_ψ(z_t, A, k) = W_ψ(z_t, A_{:k})`. 예측된 상태를 다음 입력의 앵커로 쓰지 않습니다 [§3.2].
- 저자들은 `k`가 추가 입력이 아니라 "요청하는 예측 시점"이라고 명시합니다 [§3.2].

### 2.2 목표 지향 제안 생성 (§3.3, 식 3)

- 순차 구성: `ā_k = G_φ(ẑ_k, z_g, ā_{k−1})`, `ẑ_{k+1} = Q_ψ(z_t, Ā_{:k+1}, k+1)`. 시작은 `ẑ_0 = z_t`입니다 [식 3–4].
- 중간 예측 질의는 H−1번이고, 행동 생성기 호출은 H번입니다 [§3.3, 계산 분석 §3.5].
- 부록 A의 제안은 조건부 평균(`G_φ`의 평균)을 씁니다.

### 2.3 제안 중심 CEM과 종점 채점 (§3.4, 식 5–6)

- 탐색 분포 초기값은 제안 `Ā`를 중심으로 하며, 분산은 `σ_0² · 1`입니다(식 5).
- 한 라운드에서 `N`개 슬롯 중 2개는 `Ā`와 지금까지의 최고 계획으로 고정하고, 나머지 `N−2`개를 샘플합니다. 엘리트 `K`개로 평균과 분산을 갱신합니다(식 6).
- 마지막에 평균 후보를 한 번 더 채점하고, 평가한 계획 중 비용이 가장 낮은 것을 씁니다. 제안이 항상 후보에 남으므로 **예측 비용 기준으로는 제안보다 나빠지지 않습니다**. 실제 제어 성공이 좋아진다는 보장은 아닙니다 [§3.4 마지막 문단, 부록 A].

### 2.4 학습 목표 (§3.5, 식 7–11)

- 세계 모델 손실: 같은 관측 앵커 `z_0`에서 여러 시점 `k`를 예측하는 MSE, 차원 평균 (식 7).
- 행동 모델: 다음 상태 조건 `r = next`와 구간 끝 조건 `r = end`를 같은 조건부 가우시안으로 학습 (식 8–9). 종점 목표는 stop-gradient입니다.
- 전체 손실 `L = L_wm + λ_reg L_SiGReg + L_act`, `(λ_reg, λ_next, λ_end) = (0.02, 0.10, 0.05)` (식 11–12, 부록 A). SiGReg는 LeJEPA [4]에서 가져온 정규화입니다.

### 2.5 계산량 (§3.5, 식 10)

- 제안: `HG + (H−1)W`. 탐색과 종점 채점: `(NI+1)W`. 합계 `C_Fast-JEPA = HG + (H+NI)W` (식 10).
- 롤아웃 기준 CEM: `C_CEM-rollout = (NI+1)HW`.
- 점근적으로 `O(NIHW) → O((H+NI)W)`로 줄어듭니다. 단, `G = O(W)`와 "배치 효과 무시"를 가정합니다 [§3.5].
- 설정 H=5, N=64, I=2에서 세계 모델 호출 수는 롤아웃 645회 대 Fast-JEPA 133회입니다(`03` S10). 실제 지연은 배치와 CEM 오버헤드에 좌우되므로 측정값으로 확인해야 합니다.

## 3. 실험 설정

- 과제: PushT (Diffusion Policy 평가 세트 [7]), Reacher (DMC [33]), Cube (OGBench [28]), TwoRoom (LeWM 설정 [24]). MuJoCo 기반 [34] (부록 B.1).
- 인코더: ViT-Tiny [9] + MLP 프로젝터(BatchNorm), 192차원. ℓ2 정규화 없음 (부록 A).
- 학습: 과제당 **1 에폭**, 배치 256, AdamW 5e-4, weight decay 1e-3, BF16 (부록 A). 시드 0, 42, 3072.
- 평가: 과제당 100 에피소드 × 3 학습 모델 (본문 §5). 지연은 RTX PRO 6000 Blackwell에서 워밍업 후 배치 1 기준 완전 계획 시간 (§5, 부록 B.1).
- 설정: N=64, I=2, K=8 (부록 A). 실행 구간 L=25, H=5, B=5 (부록 A).
- DynaGoal: 원래 과제 모델을 재학습하지 않고 쓰는 세 가지 프로토콜 (§4, 부록 B.2, E).
  - Shift: PushT 목표가 방향을 바꾸고, Reacher/Cube는 목표를 바꾸며, TwoRoom은 문이 움직입니다 (100 스텝).
  - Deadline: PushT 2.50 s, Reacher 1.20 s, Cube 1.25 s, TwoRoom 2.50 s의 마감. 계획 시간과 실행 시간을 함께 셉니다.
  - Delay: Shift 과제에 0, 300, 500, 800 ms의 응답 지연을 줍니다 (그림 4만 있고 표 값은 없습니다).

## 5. 한계와 저자의 진술

- 저자는 "Fast-JEPA는 실제 실행 성공이 좋아진다고 보장하지 않는다"고 씁니다 [§3.4].
- 저자는 평균 지연 예산이 "모든 호출의 하드 마감을 보장하지 않는다"고 씁니다 [부록 D.1].
- 저자는 "Oracle-state" 제안은 시뮬레이터 롤아웃을 쓰므로 지연 비교가 공정하지 않다는 점을 암묵적으로 둡니다(Table 5 781 ms).

## 6. 분석자의 관찰 (근거 번호 포함)

1. **성공률 차이가 작습니다.** 4과제 평균 차이는 INTACT Guarded A와 0.17 pp입니다(Table 1). 시드 3개 기준 Welch 검정 p = 0.72입니다(`03` V2). INTACT와의 차이 0.92 pp도 p = 0.15입니다(`03` V1).
2. **같은 컨트롤러의 수치가 표마다 다릅니다.** Table 1은 96.50% / 10.88 ms, Table 4·5는 96.33% / 10.78 ms입니다. PushT도 90.00(Table 1)과 89.00(Table 4)이고, TwoRoom은 99.67과 100.00입니다(`03` K1).
3. **그림 4(지연 0 ms)가 표 2(Shift)와 맞지 않습니다.** 그림에서 읽은 값과 표 값의 차이는 최대 81 pp입니다(`03` K3). 그림 값은 ±3 pt 정도의 읽기 오차가 있어 큰 차이만 신뢰합니다.
4. **지연 비교의 기준이 다릅니다.** 2.41배는 INTACT(26.19 ms)에 대한 값입니다. 성공률이 더 높은 INTACT Guarded A(127.09 ms)와 비교하면 11.7배입니다. 두 값 모두 맞지만, 초록은 더 약한 기준을 씁니다(`03` S7).
5. **구현 관련 주장이 저장소와 다릅니다.** 초록의 "code is available"과 저장소의 "coming soon"이 모순됩니다(`04_claim_verification.md`, C3).
6. **"1 에폭" 학습 설정과 5.95 GPU-h의 관계가 불명확합니다.** 부록 A의 1 에폭과 표 6의 비용이 어떻게 맞는지 설명이 없습니다(`04` C12).
7. **지연 측정 조건.** 주 지연은 "배치 1, 고정 합성 입력, 워밍업 후"입니다 [부록 B.1]. 실제 제어 루프의 지연 분포와는 다를 수 있습니다.
