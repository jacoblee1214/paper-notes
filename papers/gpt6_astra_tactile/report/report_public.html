핵심 요약

  1. 무엇을 하는가: 파라미터가 고정된 GPT-6-Astra를 단독 정책으로 쓴다. 데모 40개를 같은 모델이 요약해 텍스트 Task Skill과 촉각 reference를 만들고, 폐루프에서 RGB·양손가락 촉각·자세를 받아 EEF 목표를 직접 낸다.
  2. 제목 주장은 데이터와 맞지 않는다: 5-task 평균 93.8 대 N0-VTLA 96.2(−2.4%p)로 "Outperform"과 반대 방향이다. "comparable"은 ±5%p 마진에서만 방어된다. baseline 값은 출처 논문 표에서 옮겨 온 것이다.
  3. 촉각 ablation 99 대 31은 교란되어 있다: 촉각 관측, 촉각 reference, Task Skill이 함께 바뀌었고 태스크도 하나다.
  4. 우리 0단계 probe(Claude Opus 5.5, 실제 UniVTAC 데모): reference가 있으면 100%지만 1-NN도 96%다. reference가 없으면 62%이고, 센서 좌표 정보만 주면 92%다. reference 라벨을 뒤집으면 좌표 정보가 있어도 48/48 뒤집힌 라벨을 따른다.
  5. 우리 폐루프 2×2(카메라 없음, 조건당 20 ep): 촉각+Skill 17/20, Skill만 7/20, 촉각만 12/20, 둘 다 없음 9/20. 촉각 효과는 Skill이 있을 때만 유의하다(+50%p, McNemar p = 0.0063). 숨은 결정(−x seed)은 촉각+Skill만 풀었다(6/7).
  6. 반사실 촉각: 촉각 프레임만 거울 반전하면 첫 이동 20/20이 반대쪽, 성공 1/20. "촉각을 이해한다"는 "증류된 촉각 규칙을 따른다"로 좁혀 써야 하고, 규칙이 틀렸을 때 폐루프에서 고치지 못했다.
  7. 구현 가능성: 아이디어는 이미 이 저장소에서 재구현해 돌렸다(테스트 123개, UniVTAC 폐루프). 원문 수치 재현은 GPT-6-Astra와 원문 프롬프트가 없어 불가능하다. 결정당 약 30초(0.03 Hz)라 실시간 제어와는 거리가 멀다.

우리 실험: UniVTAC Insert Hole 폐루프 2×2(Task Skill × 촉각), 조건당 20 episode. code/results/univtac51_2x2/.

1. Abstract (요약과 핵심 주장)

이 논문은 "범용 멀티모달 모델이 물리 상호작용을 이해하고 그 이해를 행동 결정에 활용할 수 있는가"라는 질문을, contact-rich manipulation과 촉각 이해라는 구체적인 사례로 검증하려 합니다 [Abstract, §1]. 제안 시스템인 GPT-as-Tactile-Policy는 파라미터가 고정된 GPT-6-Astra를 단독 action policy로 사용하며, 다음 두 단계로 구성됩니다.

  1. Offline: 같은 GPT-6-Astra가 expert demonstration(태스크당 40개)을 분석하여 텍스트 형태의 Task Skill K_τ와 대표 촉각 reference 집합 E_τ^tac을 만듭니다 [§3.2, §4.1].
  2. Online: scene/wrist RGB, 양손가락 촉각(이미지, 압입 깊이 통계, 마커 변위), proprioception, 에피소드 내 history를 입력으로 받아 EEF 목표 pose, gripper 목표값, 1–5 step의 실행 horizon을 출력하고, 일반 IK 제어기가 이를 실행합니다 [§3.1, §3.4].

저자가 내세우는 핵심 수치는 다음과 같습니다.

  • UniVTAC 5개 태스크에서 평균 성공률 93.8%를 달성했습니다. 비교 대상인 N0-VTLA는 96.2%, N0-TWAM은 84.6%입니다 [Tab.2].
  • Insert Hole에서 촉각을 제거하면 성공률이 99%에서 31%로 떨어집니다 [Tab.3].
  • 추가 robotics-specific pretraining과 태스크별 파라미터 업데이트가 없습니다 [Tab.1].

제목은 "Outperform VTLA Models"라고 주장하지만, 평균 기준으로는 N0-VTLA(96.2%)보다 낮습니다. 따라서 제목의 주장은 본문 결과보다 강하게 표현되어 있습니다(§4.2 참조).

2. Method

2.1 상위 패러다임: GPT-as-Policy

이 논문은 같은 연구 계열의 선행 연구인 GPT-as-Policy("Systematically exploring the capabilities of GPT-6 Astra as embodied policies", Team et al., arXiv:2609.38537)의 direct-control 정식화를 그대로 계승합니다 [§2.1, §3.1]. 해당 정식화에서 GPT는 수치형 EEF/gripper 목표를 직접 생성하고, generic IK 제어기가 이를 관절 명령으로 바꾸며, 실행 후 새로운 관측이 다시 모델로 돌아갑니다. 이 논문의 기여는 그 루프에 (i) 양손가락 촉각 관측과 (ii) 데모로부터 증류한 고정 컨텍스트 C_τ를 추가한 것입니다. 액션 포맷, 프롬프트 구조, 출력 파싱 방식 등 세부 구현은 상위 논문에 있을 것으로 보이지만, 이 문서에서는 arXiv:2609.38537 본문을 확인하지 못했으므로 미확인입니다.

2.2 식 (1): 조건부 액션 생성

a_t ~ π_θ(· | ℓ, C_τ, o_t, H_t),   o_t = (V_t, s_t, T_t)            (1)
  • ℓ: 자연어 태스크 지시입니다.
  • C_τ: 태스크 τ에 대해 고정된 컨텍스트(식 2)입니다. 평가 전에 고정되며 같은 태스크의 모든 테스트 에피소드에서 공유됩니다 [§4.1].
  • o_t: V_t(scene RGB와 wrist RGB), s_t(proprioception), T_t(양손가락 촉각, 식 3)로 구성됩니다.
  • H_t: 에피소드 내의 이전 관측, 액션, "execution feedback"입니다. 에피소드마다 독립된 모델 세션을 시작하므로 에피소드 사이에 history가 리셋됩니다 [§4.1].
  • a_t: 목표 EEF pose, gripper position, 짧은 실행 horizon(1–5 control step)으로 이루어집니다 [§3.1, §3.4].
  • θ: offline 요약과 online 실행 모두에서 고정됩니다.

해설하면 식 (1)은 학습 대상 정책을 정의하는 식이 아니라, in-context conditioning 구조를 선언하는 식입니다. π_θ는 확률적 정책으로 표기되어 있지만, 샘플링 온도나 seed 같은 디코딩 설정은 보고되지 않았습니다(미확인). reasoning effort가 xhigh로 고정되었다는 사실만 명시되어 있습니다 [§4.1]. 결국 식 (1)이 의미하는 바는 "정책 개선이 파라미터 공간이 아니라 컨텍스트 공간(C_τ, H_t)에서 일어난다"는 것이며, 이것이 논문이 주장하는 "no parameter updates"의 실체입니다.

2.3 식 (2): 고정 태스크 컨텍스트

C_τ = { K_τ, E_τ^tac }                                               (2)
  • K_τ(Task Skill)은 텍스트입니다. 원문에 따르면 Task Skill은 (a) task objectives, (b) manipulation principles, (c) stage transition의 근거(evidence), (d) 장애물 상황에서의 corrective strategies로 구성되며, "어떤 관측을 살펴보고 그것이 이후 행동에 어떻게 반영되어야 하는지"를 명시합니다 [§3.2]. 원문이 제시한 유일한 구체 예시는 "삽입 중 deformation은 증가하는데 물체가 전진하지 않으면 후퇴하여 접촉을 해소하고, 이어서 위치 또는 각도를 조정한 뒤 후속 피드백으로 그 효과를 평가한다"입니다 [§3.2].
  • E_τ^tac은 데모에서 GPT-6-Astra가 직접 골라낸 대표 촉각 관측이며, "양손가락 접촉 분포와 국소 변형 패턴을 보존한다"고만 설명되어 있습니다 [§3.2, §4.1]. 몇 장을 고르는지, 어떤 기준으로 고르는지, 이미지 형태인지 descriptor 형태인지는 보고되지 않았습니다(미확인).

해설하면 K_τ는 촉각 신호에 **조작적 의미(operational meaning)**를 부여하는 규칙집 역할을 하고, E_τ^tac은 그 규칙을 지각적으로 grounding하는 few-shot exemplar 역할을 합니다. 구조적으로 보면 이 설계는 REFLECT(Liu et al., arXiv:2306.15724)처럼 경험을 언어로 요약하는 접근과, VLM에 few-shot 시각 예시를 주는 in-context imitation을 결합한 형태입니다.

2.4 식 (3): 촉각 관측 표현

T_t = { I_t^f, D_t^f, M_t^f }_{f ∈ {L, R}}                          (3)
  • I_t^f: 손가락 f의 촉각 이미지입니다. [Fig.1A]와 [Fig.3]으로 보면 GelSight 계열의 마커 격자가 있는 RGB 이미지이며, 육안으로 대략 10×8 규모의 마커 격자가 보입니다(정확한 개수는 미확인).
  • D_t^f: gel 압입(indentation) 맵을 공간적으로 pooling한 뒤 계산한 통계입니다. 원문에 명시된 항목은 mean indentation, peak indentation, contact region, centroid입니다 [§3.3].
  • M_t^f: reference 위치 대비 마커의 2D 변위입니다 [§3.3]. [Fig.4]에서는 흰 배경 위의 quiver 형태로 시각화되어 있으며, [Fig.1A]에는 "Indentation" 히트맵과 "Marker motion" quiver가 별도의 패널로 그려져 있습니다. 따라서 모델이 마커 변위를 수치로 받는지, 렌더링된 quiver 이미지로 받는지, 혹은 둘 다 받는지는 확정할 수 없습니다(미확인이며, 리버스 엔지니어링 (d)에서 추정합니다).
  • 두 손가락의 정보는 분리된 채로 유지되어, 모델이 좌우 접촉 차이와 그 변화를 비교할 수 있도록 합니다 [§3.3].

해설하면, 이미지(I)는 국소 디테일을 보존하고 descriptor(D, M)는 시점 간 정량 비교를 쉽게 만드는 이중 표현입니다. LLM은 이미지 두 장 사이의 미세한 차이를 수치적으로 비교하는 데 약하므로, 이 이중 표현은 합리적인 설계입니다. 다만 D는 시뮬레이터가 제공하는 정답 압입 깊이에 의존할 가능성이 높습니다. 실제 GelSight 센서에서는 photometric stereo 등으로 depth를 복원해야 하므로 sim-to-real 간극이 생깁니다(Limitations L5 참조).

또한 저자는 "연속된 관측 사이의 indentation 분포와 마커 변위를 같은 구간의 EEF/gripper 실측 이동량과 함께 비교한다"고 서술합니다 [§3.3]. 즉 모델 입력에는 액션 전후의 차분 정보가 포함되어야 합니다. 이 차분을 시스템이 미리 계산해서 주는지, 모델이 history에서 직접 비교하는지는 미확인입니다.

2.5 Offline 지식 구성 데이터 흐름

UniVTAC expert demos (태스크당 50개)
  ├─ 40개: knowledge construction
  │     └─ GPT-6-Astra(θ 고정)가 "액션 전후의 접촉 변화 + 물체 이동 + 태스크 진행"을 함께 분석
  │           ├─ K_τ : Task Skill 텍스트 (objectives / principles / stage evidence / corrective strategies)
  │           └─ E_τ^tac : 대표 촉각 reference
  └─ 10개: "offline validation" (용도는 서술되지 않음)
→ C_τ = {K_τ, E_τ^tac} 를 평가 전에 고정하고, 해당 태스크의 100개 테스트 에피소드 전체에서 재사용

근거는 [§3.2]와 [§4.1]입니다. 40개 데모 전체를 한 번의 컨텍스트에 넣었는지, 데모별로 분석한 뒤 집계(map-reduce)했는지, 사람이 결과를 검수하거나 수정했는지는 보고되지 않았습니다(미확인). 10개 validation 데모가 Task Skill을 반복적으로 수정하는 데 쓰였다면, 이는 사실상 사람이 수행하는 prompt optimization에 해당합니다(L1 참조).

2.6 Online 폐루프 데이터 흐름

for t = 0, 1, ...:
  o_t ← (scene RGB, wrist RGB, s_t, {I, D, M}_{L,R})
  a_t ← GPT-6-Astra(xhigh)(ℓ, C_τ, o_t, H_t)          # 목표 EEF pose, gripper, horizon h ∈ {1..5}
  bound/format 검사 → 통과하면 IK 제어기가 h control step 동안 실행
  o_{t+1} 획득, H_{t+1} ← H_t ∪ {o_t, a_t, feedback}
  (다음 호출에서) o_t와 o_{t+1}을 비교하여 진행 여부 판단 → 전진 / probing / 교정 선택
종료: 환경의 native success 조건을 만족하거나, 실행 예산을 소진하면 종료합니다(후자는 실패로 처리).

근거는 [§3.4]와 [§4.1]입니다. 원문은 액션을 "최신 측정 로봇 상태로부터 구성한다"고 서술합니다 [§3.4]. 이는 모델이 현재 실측 pose를 기준으로 목표를 계산한다는 뜻이며, 액션이 절대 목표 pose이더라도 그 값이 사실상 "현재 pose + 증분"으로 만들어진다는 점을 시사합니다. 불확실한 상황에서는 작은 병진, 자세 조정, gripper 개도 변경 같은 탐색 액션을 수행하고, 그 결과가 H_t에 누적됩니다 [§3.4]. [Fig.4]는 같은 에피소드 안에서 near-vertical(step 30→35→40), leftward(119→124→127), rightward(191→194→199) 방향의 probing을 차례로 시도하는 모습을 보여줍니다.

# 한계 근거 위치 영향
L1 "Training-free" 표기와 실제 데이터 사용의 괴리. [Fig.1C] 범례는 "Ours (Training-free)"라고 표기하지만, 태스크당 40개 데모를 in-context로 증류하고 10개를 "offline validation"에 사용합니다. validation이 Task Skill을 반복 수정하는 데 쓰였다면, 이는 사람 또는 모델이 수행하는 prompt-level optimization입니다. 데이터 사용량(50 demo)은 ACT+UniVTAC(50 demo)와 같은 수준입니다. Fig.1C, §4.1, Tab.1 주장 과장. "parameter-free adaptation"이 더 정확한 표현입니다.
L2 비대칭적인 비용 비교. [Tab.1]은 baseline의 사전학습 비용(128×H800 등)을 나열하지만, GPT-6-Astra의 사전학습 비용과 데이터(로보틱스나 촉각 데이터 포함 여부)는 공개되지 않았습니다. "No additional robotics-specific pretraining"은 검증할 수 없는 주장입니다. UniVTAC 유사 데이터가 사전학습에 섞였을 가능성(contamination)도 배제할 수 없습니다(미확인). Tab.1, Abstract 비교의 공정성
L3 추론 비용과 지연시간을 보고하지 않음. reasoning effort가 xhigh이고, 1–5 step마다 한 번씩 호출하며, 에피소드는 약 191–300 step입니다. 에피소드당 수십에서 백 회 이상의 호출이 필요할 것으로 추정되지만(리버스 엔지니어링 (g) 참조), 토큰 수, API 비용, 호출당 지연, 에피소드 wall-clock 시간이 모두 빠져 있습니다. §4.1, §3.4, Fig.2 실시간 제어 가능성과 실용성을 평가할 수 없습니다.
L4 시뮬레이션 전용 평가. 5개 태스크 모두 UniVTAC 시뮬레이션에서만 평가했습니다. 시뮬레이션은 LLM 호출 동안 시간을 멈출 수 있지만, 실제 로봇에서는 수십 초 단위의 지연 동안 접촉 상태가 유지된다는 보장이 없습니다. §4.1 실세계 일반화 미검증
L5 촉각 descriptor가 시뮬레이터의 특권 정보에 의존할 가능성. D_t는 "gel indentation map"에서 계산합니다. 시뮬레이터에서는 정답 depth를 쉽게 얻지만, 실제 GelSight에서는 photometric stereo로 복원해야 하며 노이즈가 큽니다. 마커 변위 역시 실제 센서에서는 마커 추적 오차가 생깁니다. §3.3 sim-to-real 간극
L6 단일 run이며 신뢰구간이 없음. 각 설정을 100 에피소드로 한 번만 실행했고, CI, seed 분산, 반복 실행 결과가 없습니다. 3.3절의 계산에 따르면 저자가 강조한 우위는 유의하지 않고, 열세(Pull-out Key, Lift Bottle)는 유의합니다. closed model은 같은 입력에도 출력이 달라질 수 있어 run 간 분산을 보고하는 것이 특히 중요합니다. Tab.2, Tab.3, §4.1 결론의 통계적 강도 부족
L7 촉각 ablation의 confound. w/o tactile 조건은 촉각 관측만 제거한 것이 아니라 Task Skill 자체를 촉각 없이 다시 증류했습니다("fixed Task Skill matched to its available observations"). 따라서 99→31의 차이에는 (i) online 촉각 관측의 효과, (ii) offline 증류 단계에서 촉각을 본 효과, (iii) 촉각 reference의 효과가 섞여 있습니다. 이를 분리하려면 2×2(또는 2×2×2) 설계가 필요합니다. 예를 들어 촉각 기반 Task Skill을 유지한 채 online 촉각만 제거하는 조건이 필요합니다. §4.3 인과 귀속 불가
L8 구성요소 ablation 부재. Task Skill 유무(zero-shot), 촉각 reference 유무, descriptor(D,M)와 이미지(I)의 상대 기여, history 길이와 truncation, horizon 상한(1–5) 고정 대비 가변, reasoning effort(xhigh 대비 low/medium), 데모 수(40 대비 5/10/20)에 대한 ablation이 하나도 없습니다. 특히 "모델이 촉각을 이해한다"는 제목의 주장을 검증하려면 Task Skill 없는 조건이 핵심인데 이 조건이 빠져 있습니다. §4.3 (ablation 1종) 메커니즘 주장 근거 부족
L9 ablation이 Insert Hole 하나뿐임. 나머지 4개 태스크에서 촉각의 기여는 측정되지 않았습니다. Grasp Classify는 "tactile classification"을 포함한다고 설명되지만 [§4.1] 촉각 제거 결과가 없습니다. §4.1, §4.3 일반화 불가
L10 closed model 재현성. GPT-6-Astra의 버전이나 스냅샷, 날짜, 디코딩 설정(temperature 등), 프롬프트 원문, Task Skill 원문, reference 선택 결과가 공개되지 않았습니다(프로젝트 페이지 내용은 미확인). 모델이 업데이트되면 결과를 재현할 수 없습니다. §4.1 재현성
L11 "이해(understands)"라는 주장의 범위. 관찰된 행동([Fig.4]: 변위가 크면 후퇴하고 작으면 전진)은 [§3.2]에 명시된 Task Skill 규칙과 동형입니다. 규칙 추종과 물리 이해를 구분하는 실험(규칙에 없는 새로운 접촉 상황, 반사실적 촉각 입력, Task Skill 없는 조건)이 없습니다. Title, §3.2, §4.4 제목 과장

비용 공식

Cost ≈ N_calls × ( T_in,uncached·p_in + T_in,cached·p_cache + T_out·p_out )

예시로 가상 단가 p_in=$5/M, p_cache=$0.5/M, p_out=$30/M(실제 GPT-6-Astra 가격 아님, 미확인)를 적용하고, 호출당 입력 20k(그중 15k cached), 출력 10k를 가정하면 다음과 같습니다.

  • 호출당 비용 ≈ 5k×5e-6 + 15k×0.5e-6 + 10k×30e-6 ≈ $0.33
  • 4만 회 기준 약 $13k이고, 가정 범위 전체로는 $2k–$60k입니다. 비용은 출력(reasoning) 토큰이 지배합니다.

지연 (확실도: 낮음) xhigh reasoning의 호출당 지연을 10–90초로 가정하면, 에피소드당 50–100회 호출에 약 8분–2.5시간이 걸립니다. 600 에피소드를 순차 실행하면 수백에서 천 시간 이상이 필요하므로 대규모 병렬화가 필수였을 것입니다. 이 지연 수준에서는 실제 로봇의 폐루프 제어가 사실상 불가능하므로, L3과 L4를 정량적으로 뒷받침합니다.

(h) 재구현 시 대체 전략 (참고)

이 환경에는 torch와 LLM SDK가 없고 GPT-6-Astra에 접근할 수 없습니다. 따라서 재구현은 (1) 정책 인터페이스(ℓ, C_τ, o_t, H_t → a_t)를 추상화하고, (2) mock/규칙 기반 정책으로 루프, descriptor, 스키마, 검증기를 먼저 검증한 뒤, (3) 실제 VLM 백엔드(사용 가능한 closed/open 모델)를 교체해 넣는 순서가 현실적입니다. 아래 ablation을 기본 실험 계획에 포함할 것을 권장합니다. 대상은 L7과 L8에서 지적한 2×2 촉각 ablation(offline 증류 시 촉각 사용 여부 × online 촉각 사용 여부), Task Skill 제거, reference 제거, history 길이, horizon 상한, reasoning effort입니다.

6. 미해결 이슈 (원문만으로 확인할 수 없는 것)

  1. GPT-6-Astra의 정확한 버전과 스냅샷, 디코딩 설정, 이미지 토큰화 방식, 가격을 확인할 수 없습니다.
  2. 상위 논문 GPT-as-Policy(arXiv:2609.38537)의 액션 포맷과 프롬프트 세부 사항을 확인하지 못했습니다.
  3. 프로젝트 페이지에 프롬프트, Task Skill 원문, 코드가 공개되어 있는지 확인하지 못했습니다.
  4. UniVTAC(arXiv:2602.10093)의 센서 모델(depth/marker 제공 방식), control 주기, 태스크별 step 예산, success 조건을 확인하지 못했습니다.
  5. baseline 수치가 재실행 결과인지 인용인지, seed가 일치하는지 알 수 없습니다. E0 결과가 누락된 이유도 알 수 없습니다.
  6. 10개 "offline validation" 데모의 실제 용도를 알 수 없습니다.
  7. 데모의 초기 설정과 테스트 seed가 분리되어 있는지 알 수 없습니다.

1. 0단계: 단일 판단 probe (시뮬레이터 없음)

1.1 설정

  • 데이터: UniVTAC 공개 데모(HF byml/UniVTAC, isaac45/insert_hole, 에피소드 0–49).
  • 과제: Insert Hole expert는 (1) 약 30 mm 내려가 구멍 입구에 막히고, (2) x로 ±40 mm 이동하며 peg를 약 26° 기울인 뒤, (3) 기울어진 축으로 넣습니다. 숨은 결정은 (2)의 부호 하나입니다(slot yaw 0°/180°가 정함).
  • 질의: 각 데모를 (1)의 마지막 프레임(첫 막힘 접촉)에서 멈추고 +x/−x를 묻습니다. 에피소드 2–49의 48개이고, +x 30개, −x 18개라 다수 클래스가 62.5%입니다. reference를 쓰는 조건은 에피소드 0(+x)과 1(−x)을 라벨과 함께 보여 줍니다. 원문 E_τ^tac에 해당합니다.
  • 조건: V = head·wrist RGB, T = 양손가락 marker overlay 이미지 + descriptor(압입 D, marker 변위 M), Ti = 이미지만, Td = descriptor만, VT = V+T. 모든 조건에 EEF pose를 넣습니다.
  • 추가 조건: 0b는 reference 없이 센서 장착 정보(이미지 u/v ↔ 로봇 축)를 시스템 프롬프트에 넣습니다. 0c는 reference 두 개의 라벨을 뒤집어 보여 줍니다.
  • 센서 좌표 보정: 정답 라벨을 쓰지 않았습니다. peg가 손 안에서 미끄러지기 전(정지 마찰) 구간에서 peg–센서 실제 상대 이동과 marker 평균 이동의 부호를 대조했습니다. u = +local X가 50/50, v = +local Y가 47/50(왼쪽)·44/50(오른쪽)이었습니다. 결과는 왼쪽 +u = −z, 오른쪽 +u = +z, 양쪽 +v = −x입니다. zero-shot에서 모델이 흔히 가정한 "v = 위쪽"은 틀린 가정이었습니다.
  • 기준선과 통계: 비LLM 기준선은 같은 reference 두 개에 대한 1-NN(marker 평균 변위 + 접촉 중심)입니다. 통계는 Wilson 95% CI, 예측 × 정답 Fisher 양측 검정, balanced accuracy입니다.

1.3 해석

  3. reference가 있으면 모델은 자기 해석보다 reference를 따릅니다. 라벨을 뒤집은 0c에서 48/48이 뒤집힌 라벨을 따랐고, 좌표 정보를 함께 줘도 0%였습니다. 근거 문장에서 "+x 방향 전단"이라고 맞게 읽고도 "reference 1(−x)과 일치"를 이유로 −x를 답했습니다.
  4. 원문에 주는 함의: 원문 Tab.3의 99 vs 31은 (i) 텍스트로 촉각을 물리적으로 해석하는 경로와 (ii) reference를 대조하는 경로 가운데 어느 쪽에서 나왔는지 원문 실험만으로는 구분할 수 없습니다. 두 경로가 충돌하면 (ii)가 이깁니다.

한계: 태스크 1개, 이진 판단 1회, 프레임 1개, 질의 48개입니다. reference는 에피소드 0·1로 고정했고, 조건당 1회만 호출했습니다. 압입 descriptor는 사후에 오류를 발견했습니다. depth는 젤까지의 거리라 정적 형상이 섞여 있습니다. 판단 근거가 된 marker 전단과 좌표 보정에는 영향이 없습니다.

2. 본실험: UniVTAC 폐루프 2×2 (Task Skill × 촉각)

2.1 설정

  • 시뮬레이터: UniVTAC Insert Hole, Isaac Sim 5.1(물리 120 Hz, 평가 60 Hz), GelSight Mini 양손가락. 시뮬레이터는 NVIDIA GPU 서버에서 env server로 띄우고, 정책 프로세스와 네트워크로 연결했습니다.
  • 모델과 행동: Claude Opus 5.5, effort xhigh, JSON schema로 행동 형식을 강제했습니다. 행동은 EEF 목표 변위(축당 최대 20 mm, 회전 10°), gripper, horizon입니다.
  • 관측: 카메라는 쓰지 않았습니다. 0단계에서 RGB가 판단에 기여한 근거가 없었고, 촉각 효과를 분리하기 위해서입니다. 자세(P)는 모든 조건에 줍니다. 촉각 조건(T)에는 marker overlay 이미지, 압입·전단 descriptor, 이전 결정 대비 변화, 데이터로 보정한 센서 장착 정보를 줍니다.
  • Task Skill: 조건마다 같은 모델이 데모 40개로 증류하고 10개로 검증했습니다. 촉각 Skill은 촉각 reference 7개를 함께 만듭니다. "noskill" 조건은 지시문과 공통 규약만 받습니다.
  • 평가: 조건당 20 episode, 네 조건 모두 같은 seed 1000000–1000019입니다. 성공 기준은 구멍 축 기준 xy 1 cm 이내, 4 cm 이상 삽입, 축 정렬 cos > 0.99입니다. 실패는 전부 early_stop(시험관이 손 안에서 4 cm 넘게 밀림)이었습니다.
  • 통계: 같은 seed끼리 짝지은 McNemar 정확검정을 썼습니다. 상호작용은 seed별 diff-in-diff에 seed bootstrap 10,000회로 계산했습니다.

2.4 해석

  1. 촉각 효과는 Skill이 있을 때만 나타납니다. 촉각만 있고 Skill이 없으면 모델은 측방 이동을 한 번도 시도하지 않았습니다. 촉각 신호는 받았지만, "구멍이 기울어 있고 전단 방향이 기울기를 알려 준다"는 지식이 없었습니다.
  2. 방향 결정은 증류된 규칙을 촉각에 적용한 결과입니다.
    • 근거 문장이 Skill 규칙을 그대로 인용합니다. 예: "Shear y is positive on both pads …, which per the skill means the hole inclines toward −x."
    • 규칙은 증류 단계에서 같은 모델이 데모 촉각 데이터로 찾아냈습니다(Skill 원문: "Both y negative → move +x. This held in 26/26").
  3. 촉각 없는 Skill은 다수 방향으로 찍고 사후에 합리화했습니다. 막힘이 없자 "방향이 맞았다"고 결론 내렸지만, 시뮬레이터에서는 반대로 가도 자세에 막힘 신호가 나타나지 않습니다. CoT 근거가 실제 결정 요인과 다른 unfaithful explanation의 사례입니다(Turpin et al., arXiv:2305.04388).
  4. 전체 성공률에는 과제 수준의 지름길이 섞여 있습니다. 수직으로 밀기만 해도 +x seed는 9/13, 12/13이 성공했지만, −x seed는 0/7입니다. 촉각 효과는 숨은 변수별로 층화해야 보입니다.
  5. 비용: P+T skill은 결정당 약 30초(약 0.03 Hz), episode당 출력 토큰 약 46k입니다. 실시간 제어와는 거리가 멉니다. 원문은 비용과 지연을 보고하지 않았습니다.

원문 형태의 비교(P+T skill vs P skill)는 85% 대 35%로, 원문 99% 대 31%와 방향과 크기가 비슷합니다. 그러나 2×2로 나눠 보면 이 차이는 "촉각 관측" 하나의 효과가 아닙니다. 촉각과 증류된 Skill의 상호작용(+35%p)에, Skill 없이도 되는 수직 삽입 지름길이 더해진 것입니다.

3. 반사실 촉각: 정말 규칙대로 움직이는가

§2.4의 해석은 "근거 문장이 규칙을 인용하고 행동이 규칙과 맞았다"는 상관에 기대고 있습니다. 원인인지 확인하려면 입력에 개입해야 합니다. 같은 Task Skill과 seed로 촉각 프레임만 v축으로 거울 반전했습니다. 그러면 전단 y와 curl의 부호, 접촉 중심 v, 이미지 상하가 바뀌고, 나머지 물리와 자세는 그대로입니다. 전단 y 숫자만 뒤집으면 다른 촉각 특징과 모순되지만, 거울 반전은 "구멍이 반대쪽으로 기운 세계"에서 나올 법한 일관된 관측을 만듭니다. 예측은 실행 전에 등록했습니다.

  • 방향 결정의 원인은 전단 y 부호입니다. +x seed와 −x seed에서 똑같이 뒤집혔으므로, 데모 다수 방향으로 치우친 결과가 아닙니다.
  • 틀린 방향을 알려 주는 신호도 규칙의 틀 안에서 읽었습니다. 옆으로 움직이면 방향과 관계없이 축 방향 하중이 풀리는데, 모델은 이를 반대 방향에서도 "구멍 축 위에 있다"는 진행 증거로 읽었습니다. 방향 자체를 의심한 근거 문장은 없었습니다(키워드 검색 + 일부 직접 판독).
  • 유일한 성공은 우연입니다. 시험관을 놓친 뒤 빈 손으로 탐색하던 중 성공 판정이 났습니다.
  • 뜻하는 바: 데모에서 규칙을 스스로 찾아낸 것은 모델의 능력입니다. 그러나 폐루프에서 그 규칙이 틀렸을 때 물리 피드백으로 가설을 고치지는 못했습니다. 0단계 0c("reference를 뒤집으면 따른다", 48/48)가 폐루프에서도 재현된 것입니다. 다만 거울 반전 관측은 물리적으로 일관되므로, 물리를 이해하는 정책이라도 첫 이동은 틀릴 수 있습니다. 둘을 가르는 것은 그 뒤에 고치는지이고, 이번 결과는 "고치지 못했다"입니다.

4. 이 실험들의 한계

  • 모델이 원문과 다릅니다(Opus 5.5 vs GPT-6-Astra). 카메라를 뺐으므로 원문 V+P+T 조건 자체의 재현이 아니고, 나머지 4개 태스크는 돌리지 않았습니다.
  • 과제 1개, 조건당 20 episode, seed당 1회 실행입니다. 파일럿에서 같은 seed의 결과가 바뀐 사례가 있습니다.
  • 센서 장착 정보는 촉각 조건에만 들어가므로, 여기서 "촉각" 요인은 촉각 관측과 그 해석 정보를 함께 뜻합니다.
  • P skill의 Skill 텍스트가 실행 조건에 없는 카메라 단서를 참조했습니다. 증류 프롬프트의 결함일 수 있습니다.
  • 구멍 방향 복원은 UniVTAC의 난수 소비 순서에 의존하며, P+T skill 성공 17건과의 일치로만 검증했습니다.
  • 같은 seed라도 reset 직후의 파지 상태가 실행마다 조금 다를 수 있습니다. 성공률 비교에는 이 변동이 섞이지만, 반사실 실험의 주 지표(첫 이동 방향)에는 영향이 없습니다.

0. 결론 요약

  1. 수치 산술은 모두 맞다. Tab.2의 5개 행 평균을 다시 계산해도 같다. Fig.1C의 30개 막대 라벨도 Tab.2와 모두 같다. Tab.3의 +68pp와 Tab.2/Tab.3의 Insert Hole 99%도 일치한다. baseline 20개 task 셀은 출처 논문 표와 같다. N0-VTLA와 N0-TWAM 행은 이번에 직접 대조했다.
  2. 제목의 "Outperform VTLA Models"는 데이터와 모순된다. 비교 대상 가운데 VTLA는 N0-VTLA 하나다. 5-task 평균은 N0-VTLA가 96.2, Ours가 93.8로 Ours가 낮다. 차이는 −2.4pp, SE는 1.34pp이고 양측 p=0.073이다. 방향을 정하면 오히려 "Ours가 낮다"는 쪽의 단측 p가 0.037이고, Jeffreys 사후확률로 계산한 P(Ours > N0-VTLA)는 0.042다. Pull-out Key에서는 Ours가 15pp 낮고, 이 차이는 Holm 보정 후에도 유의하다(p=0.0008).
  3. "comparable to SOTA"는 조건부로만 지지된다. task를 고정하고 에피소드 수준에서 보면 ±5pp 동등성 TOST가 p=0.026으로 성립한다. ±3pp 기준(p=0.33)이나 ±2pp 기준에서는 성립하지 않는다. task를 표본으로 보는 수준에서는 df=4라 95% CI가 [−13.2, +8.4]pp로 넓어 동등성이든 우열이든 판정할 수 없다.
  4. 저자가 내세운 우위는 모두 통계적으로 유의하지 않다. Insert Hole에서 N0-VTLA를 앞선다는 주장은 Fisher p=0.21이다. Lift Can 최고치는 N0-TWAM 93 대비 p=0.77이다. 게다가 n=100에서는 기준 성공률이 95%일 때 Ours가 100%를 찍어도 검출력 80%에 도달하지 못한다. 실험 설계 단계에서 이미 우위를 입증할 수 없는 구조다.
  5. N0-TWAM 대비 평균 우위(+9.2pp)는 Lift Bottle 한 task에서 거의 다 나온다. Lift Bottle은 93 vs 58로 +35pp다. Lift Bottle을 빼면 평균 차이는 +2.75pp이고, 나머지 4개 task는 하나도 유의하지 않다. task 수준 paired t는 p=0.23이다.

4. 계산 코드 (핵심부 인라인)

전체 코드는 analysis/stats_check.py에 있다. 아래는 판정에 직접 쓰인 함수만 옮긴 것이다.

import math, numpy as np
N = 100
def norm_cdf(x): return 0.5 * math.erfc(-x / math.sqrt(2))

def wilson(k, n=N, z=1.959964):
    p = k / n; den = 1 + z*z/n
    c = (p + z*z/(2*n)) / den
    h = z * math.sqrt(p*(1-p)/n + z*z/(4*n*n)) / den
    return max(0, c-h), min(1, c+h)

def newcombe_diff_ci(k1, k2, n1=N, n2=N):           # Newcombe (1998) method 10
    p1, p2 = k1/n1, k2/n2; (l1, u1), (l2, u2) = wilson(k1, n1), wilson(k2, n2)
    d = p1 - p2
    return d - math.hypot(p1-l1, u2-p2), d + math.hypot(u1-p1, p2-l2)

def _lchoose(n, k): return math.lgamma(n+1) - math.lgamma(k+1) - math.lgamma(n-k+1)
def fisher_two_sided(k1, k2, n1=N, n2=N):          # sum of P(table) <= P(observed)
    K, M = k1+k2, n1+n2
    lp = {x: _lchoose(n1, x) + _lchoose(n2, K-x) - _lchoose(M, K)
          for x in range(max(0, K-n2), min(K, n1)+1)}
    return min(1.0, sum(math.exp(v) for v in lp.values() if v <= lp[k1] + 1e-9))

def stratified_mean_diff(ours, base, n=N):         # equal-weight task mean, tasks fixed
    d = np.mean(ours) - np.mean(base)
    var = sum(a/n*(1-a/n)/n + c/n*(1-c/n)/n for a, c in zip(ours, base)) / len(ours)**2
    se = math.sqrt(var) * 100; z = d / se
    return d, se, z, 2*(1-norm_cdf(abs(z))), norm_cdf(z)   # diff, SE, z, p_two, p(ours<base)

def tost(d, se, m): return max(1-norm_cdf((d+m)/se), norm_cdf((d-m)/se))

def cmh(ours, base, n=N):                          # Cochran–Mantel–Haenszel, cc=0.5
    dev = var = 0.0
    for a, c in zip(ours, base):
        b, d = n-a, n-c; t = a+b+c+d
        dev += a - (a+b)*(a+c)/t
        var += (a+b)*(c+d)*(a+c)*(b+d) / (t*t*(t-1))
    chi2 = (abs(dev)-0.5)**2 / var
    return chi2, math.erfc(math.sqrt(chi2/2))

ours = [99, 95, 98, 93, 84]; vtla = [95, 88, 100, 99, 99]; twam = [99, 93, 94, 58, 79]
print(stratified_mean_diff(ours, vtla))   # (-2.4, 1.34, -1.79, 0.073, 0.037)
print(fisher_two_sided(93, 99))           # 0.0649  (Lift Bottle; z-test gives 0.030)
print(cmh(ours, twam))                    # (22.9, 1.7e-06)

3.3 해석: 차이는 있지만 mock 구조가 만든 차이다

결과는 "100% 대 0%"처럼 극단으로 갈리지 않았다. 그러나 다음 세 가지 이유로 차이의 크기를 의미 있게 해석할 수 없다.

  1. V+P+T는 천장에 닿아 있다. step 수가 26–35로 좁게 몰려 있고 실패가 하나도 없다. mock 환경은 숨은 4자유도 오차(측방 2D, 축 각도 2D)를 촉각 단서 4개에 일대일로, 거의 선형으로 대응시킨다(A의 설계 메모). mock 정책은 이 대응을 데모에서 ridge 회귀로 학습한다(R² 약 0.93–0.95). 그러므로 V+P+T 조건은 사실상 "역함수를 학습한 뒤 한두 번 보정하는" 문제이며, LLM이 촉각을 해석하는 능력과는 관계가 없다.

  2. V+P의 21%는 휴리스틱의 탐색 범위가 상한을 정한다. V+P mock 정책은 측방 {0, 0.5, 1.0}×lateral_range_mm(2.67 mm)와 기울기 {0, 0.5, 1.0}×angle_range_deg(5.27°)를 8방향으로 조합한 288개 후보를 seed별 무작위 순서로 시도한다(backends.py::_search_candidate). 진입 조건은 |e|<1 mm 그리고 θ<3°다. 따라서 각도 오차가 약 8.3°를 넘으면 원리상 맞출 수 없다. 실측에서도 그렇게 나왔다. 숨은 오차 크기별 V+P 성공은 다음과 같다(같은 100 seed, default_rng(seed)에서 다시 샘플링).

  3. calibration 목표가 미리 정해져 있었다. SPEC §5.5(MockHeuristicBackend 항목)는 mock에서 "V+P+T ≥ 0.9, V+P ≤ 0.6"이 나오도록 설계하라고 명시한다. 이번 결과는 그 목표를 만족한다는 확인일 뿐이다.

이번 E2E가 실제로 보여 주는 것은 다음과 같다. (a) 증류, 고정 context, 폐루프 평가, 집계, ablation이 끊김 없이 이어진다. (b) V+P 조건에서 촉각 정보가 정책에 실제로 차단된다. 차단되지 않았다면 두 조건의 결과가 같았을 것이다. (c) 같은 seed와 같은 context에서 결과가 결정적으로 재현된다. 논문의 핵심 주장, 즉 범용 멀티모달 모델이 촉각 표현을 보고 접촉 상태를 추론한다는 주장은 이 실험으로 검증되지 않았다.

5. 발견한 문제

5.1 수정함: V+P 조건의 K_τ에 촉각 용어가 남음

  • 위치: code/tactile_gpt_policy/policy/mock_skill.py, "Corrective strategies for obstructions" 줄.
  • 증상: V+P 조건으로 증류한 skill.md에 "Condition: blocked or deformation increases without advancement"라는 문장이 들어 있었다. V+P 정책은 변형(deformation)을 관측할 수 없다. SPEC §6.1("V+P이면 촉각 플래그를 쓰지 않는다")과 §6.2(V+P에서는 Contact interpretation 제외)의 의도에도 어긋난다.
  • 영향: mock 정책은 K_τ의 mock_calibration 블록만 읽기 때문에 수치에는 영향이 없다(수정 전과 후 모두 V+P 21/100). 그러나 실제 LLM으로 V+P ablation을 할 때 mock 증류 결과를 K_τ 템플릿으로 재사용하면, 정책이 볼 수 없는 신호를 기준으로 쓰라는 지시가 들어가 V+P 성능이 왜곡될 수 있다.
  • 수정(최소 변경): has_tac가 False일 때는 "blocked (commanded advance not achieved)"를 쓰도록 바꿨다. V+P+T의 skill.md는 수정 전후 바이트 단위로 같음을 diff로 확인했다. 수정 뒤 두 context를 다시 증류하고 eval과 ablation을 다시 실행했으며, 수치는 같았다. pytest도 113개 모두 통과했다.

5.2 수정하지 않음: 관찰과 권고

  1. context_dir가 cwd 기준 상대경로다. task yaml에 있는 outputs/contexts/${task}_mock/${condition}은 --out과 관계없이 cwd 아래에 캐시된다. 프롬프트나 증류 코드를 바꿔도 이전 캐시가 조용히 재사용될 수 있어 위험하다. 이번 검증에서는 결과 전용 yaml을 따로 두고, distill_if_missing: false로 고정 context만 쓰도록 했다. 기존 code/outputs/contexts/insert_hole_mock/(A와 B의 이전 실행에서 생긴 것)는 지우지 않고 그대로 두었다. 권고: 상대경로는 out_dir을 기준으로 해석하고, context에 코드나 프롬프트 해시를 기록해 불일치하면 경고하도록 한다.
  2. 증류 검증 지표가 실제로는 아무것도 측정하지 않는다(§3.1). mock validate_act는 관측과 상관없이 같은 답을 낸다. 실제 LLM을 붙이기 전에 최소한 "막힘 직후에는 retract나 adjust를 기대한다" 같은 규칙 기반 baseline과 비교하는 기준이 필요하다.
  3. K_τ의 "Events per demo" 수치가 n_events와 맞지 않는다. V+P+T 텍스트에는 blocked 1.7, retract 1.0이 적혀 있지만, n_events로 계산하면 blocked 75/40=1.9, retract 75/40=1.9다. V+P 텍스트에는 1.9, 1.9로 적혀 있다. 구간 병합 기준이 조건마다 다른 것으로 보이지만 원인은 추적하지 않았다(미확인). mock 동작에는 영향이 없다.
  4. V+P 정책의 탐색 범위를 데모 보정량의 분포에서 가져온다(§3.3). 숨은 오차의 분포 범위(각도 4–10°)보다 좁아서 큰 오차는 원리상 해결할 수 없다. "V+P 성능"이라기보다 "이 휴리스틱의 성능"이다. 숫자를 인용할 때는 반드시 이 점을 같이 적어야 한다.
  5. SPEC과 지시서의 파일명 차이(테스트, 프롬프트). 구현은 SPEC을 따랐고 기능 범위는 SPEC §11과 같다.

6. 남은 한계 (검증하지 못한 것)

  1. 실제 UniVTAC(arXiv:2602.10093)에서는 실행하지 않았다. Isaac Sim과 isaaclab이 없다.   3. 평가 프로토콜 차이: UniVTAC의 eval_policy.py는 예외가 난 에피소드를 집계에서 빼고 seeds.json으로 seed를 건너뛴다. 이 runner는 논문 §4.1에 따라 모든 종료를 실패로 센다. seed_base도 100000으로, UniVTAC의 1e6과 다르다. 논문 수치와 비교하려면 이 둘을 맞춰야 한다.
  4. mock은 UniVTAC Insert Hole의 ±30° 구멍 기울기를 운동학에 반영하지 않는다(A의 open issue). 그래서 논문 Fig. 2에 나오는 "~30° 축 탐색" 현상은 재현되지 않고, 4–10° 범위의 숨은 보정만 재현된다.
  5. 비용과 지연 시간: 실제 API 기준 비용(cost_usd)은 단가를 알 수 없어 null이다. 논문은 호출당 지연 시간과 에피소드 wall-clock을 보고하지 않는다(미확인). 실제 LLM으로 V+P를 실행하면 실패 에피소드마다 약 100회 호출이 필요하므로, 파일럿은 --n-episodes 5–10부터 시작하기를 권한다.
  6. 나머지 4개 태스크(lift_can, grasp_classify, lift_bottle, pull_out_key)는 yaml만 있고 mock 환경이 없다. 이 태스크들의 파이프라인은 E2E로 실행해 보지 않았다.

1. 한 줄 요약

논문의 정책은 파라미터를 고정한 범용 멀티모달 LLM 하나다. 이 LLM이 (1) 오프라인에서 전문가 데모 40개를 분석해 텍스트 Task Skill K_τ와 촉각 레퍼런스 E_τ^tac를 만들고 [논문 §3.2, §4.1], (2) 온라인에서는 ℓ, C_τ, o_t, H_t를 받아 EEF 목표 pose, 그리퍼, 1–5 step horizon을 직접 출력하는 폐루프 정책 역할을 한다 [논문 식(1), §3.4]. 학습되는 파라미터가 없으므로, 재구현의 핵심은 모델이 아니라 관측 표현(식 3), 컨텍스트 증류, 프롬프트와 액션 계약, 평가 하네스다. 아래 구조는 이 네 가지를 모듈로 나누고, 실제 LLM이나 시뮬레이터 없이도 끝까지 검증할 수 있도록 mock 경로를 함께 둔다.

설계 포인트

  • 이벤트 요약 기반 입력 [가정]. 논문은 GPT-6-Astra가 데모를 "jointly analyzes … relating contact changes and object motion before and after actions"라고만 쓴다 [논문 §3.2]. 40개 데모의 원시 프레임을 모두 넣으면 토큰 비용이 감당되지 않는다. 그래서 REFLECT(Summarizing robot experiences for failure explanation and correction, arXiv:2306.15724)의 계층적 경험 요약처럼, 촉각과 운동 변화를 이벤트로 압축한 표를 LLM 입력으로 쓴다. 원시 이미지를 포함한 변형은 비교 실험 대상으로 남긴다.
  • K_τ 섹션 고정. 논문이 열거한 구성 요소 "task objectives, manipulation principles, evidence for stage transitions, corrective strategies for obstructions"[§3.2]를 Markdown 헤더로 강제한다. 여기에 촉각 해석과 액션 크기 섹션을 더했다.
  • E_tac 선택. 논문은 "bilateral contact distributions and local deformation patterns를 보존하는 대표 촉각"이라고만 쓴다 [§3.2]. 재구현은 좌우 finger를 분리한 26차원 descriptor 공간에서 이벤트별 k-medoids로 고른다. medoid는 실제 관측 프레임이므로 이미지 레퍼런스로 그대로 쓸 수 있다.
  • ablation용 별도 컨텍스트. "Each configuration uses a fixed Task Skill matched to its available observations"[§4.3]에 따라, V+P 조건은 촉각 플래그 없이 이벤트를 검출하고 K_τ를 따로 증류하며 E_tac은 비운다.

설계 포인트

  • 상대 명령 JSON을 절대 목표로 변환 [가정]. 논문은 "a_t specifies the target end-effector pose, gripper position, and a short execution horizon"[§3.1]과 "constructs action a_t from the latest measured robot state"[§3.4]를 모두 쓴다. 모델은 base frame의 dpos_mm와 drot_deg(rotation vector)를 내고, parser가 최신 측정 상태를 기준으로 절대 목표(m, quat wxyz)로 바꾼다. LLM이 쿼터니언을 직접 다루지 않게 하려는 선택이다. 대가로 "상대 vs 절대" 자체가 재현 오차의 원인이 될 수 있다(미확인 항목 3).
  • Bounds와 format 체크 [논문 §3.4]. format 위반은 재질의(최대 2회) 후 hold로 처리하고, bounds 위반은 clip한 뒤 warning을 다음 prompt에 피드백한다. 논문은 위반 시 처리를 밝히지 않았다.
  • stateless 재직렬화 [가정]. "independent model session per episode, H_t updated within the episode"[§4.1]를 만족하면서 비용을 통제하기 위해, H_t는 텍스트(최근 20개는 상세, 이전은 압축, 막힘과 접촉 이벤트는 보존)로 넣고 이미지는 현재 시점과 직전 결정 시점의 촉각 패널만 넣는다. part 순서를 고정해 앞쪽(ℓ, K_τ, E_tac)이 에피소드 내내 바이트 동일하게 유지되므로 prompt caching이 가능하다.
  • delta 플래그는 Task Skill의 어휘다. deform_up_no_advance는 논문 §3.2의 예시("increasing deformation without object advancement during insertion prompts retraction")를 그대로 관측 플래그로 만든 것이다. 같은 flag 어휘가 오프라인 이벤트 검출, K_τ 텍스트, 온라인 관측 JSON에 공통으로 쓰여서 증류된 지식과 현재 관측이 같은 언어로 연결된다.
  • privileged 차단. 시뮬레이터 정답 상태는 Observation.privileged에만 두고, prompt와 mock 정책에 들어가지 않음을 테스트로 강제한다. mock 결과가 정답 누출로 부풀려지는 것을 막기 위해서다.

02. 선행연구 조사 및 인용 검증 — GPT-6-Astra Understands Touch (arXiv:2610.28457v1)

  • 작성 역할: 선행연구 조사 에이전트
  • 작성일: 2026-10-23
  • 대상: Wang et al., "GPT-6-Astra Understands Touch and Outperform Vision–Tactile–Language–Action Models", arXiv:2610.28457v1 (2026-10-20), SYSU / X-Era AI Lab / PolyU. 프로젝트 페이지 https://gpt-as-tactile-policy.github.io/ ("Code Coming soon", 2026-10-23 기준 코드·프롬프트·Task Skill 원문 미공개)
  • 검증 방법: arXiv abs/HTML 페이지, GitHub README/소스, 프로젝트 페이지를 WebFetch로 직접 열람. arXiv API는 HTTP 429로 막혀 abs 페이지를 하나씩 확인함. 아래 "확인됨"은 제목과 1저자(가능한 범위에서 저자 목록 전체)가 원 출처와 일치한다는 뜻임. "지식 기반"은 웹으로 다시 확인하지 않고 모델 지식으로만 확인한 항목.

0. 요약 (핵심 결론)

  1. References 22건 중 19건은 제목·저자·ID가 일치함. 불일치는 3건: E0(제목이 다르고 NeurIPS 2026 채택을 확인하지 못함, 저자 표기 오류), VLA-Touch(저자 "M. S. Zheng"는 실제로 "Mike Zheng Shou"), VITaL Pretraining(arXiv 프리프린트 제목은 다르고 ICRA 2025 판 제목은 일치함, IEEE Xplore 원문은 직접 확인하지 못함). 존재하지 않는 인용은 없었음.
  2. Table 2의 baseline 수치는 모두 다른 논문에서 가져온 것이고, 저자들이 다시 돌린 결과가 아님. ACT+UniVTAC는 UniVTAC 원 논문(arXiv:2602.10093) 표, π0.5와 N0-VTLA는 N0-VTLA 논문(arXiv:2607.23782) 표, N0-TWAM은 N0-TWAM 논문(arXiv:2607.23783) Table 2의 값과 숫자 단위로 같음. 본문에는 "previously evaluated on UniVTAC"라고만 적혀 있고 "가져왔다"는 명시가 없으며, seed와 episode가 같은지도 밝히지 않음.
  3. UniVTAC는 8개 task인데 논문은 5개만 보고함. Insert HDMI, Insert Tube, Put Bottle in Shelf가 빠졌고 제외한 이유는 적혀 있지 않음. 다만 이 3개를 넣으면 N0-VTLA 평균이 96.2에서 83.1로 떨어지므로, 5-task 부분집합은 오히려 N0-VTLA에 유리함. 제외된 3개 task에서 본 방법이 얼마나 나오는지는 미확인임. 그래서 체리피킹 여부는 판정할 수 없지만 선정 기준이 공개되지 않은 것은 문제임.
  4. 제목의 "Outperform"은 결과와 맞지 않음. 5-task 평균 93.8은 N0-VTLA의 96.2보다 낮음(각 task 100 episode를 가정하면 차이 −2.4pp, SE 약 1.3pp). N0-TWAM의 84.6보다는 높음(+9.2pp, SE 약 1.8pp). 결국 "N0-TWAM과 일부 task에서 앞선다"가 정확한 표현임.
  5. E0는 Baselines 절에 이름이 나오지만 Table 2와 Fig. 1C에는 없음. 본문은 "four methods"라고 쓰면서 다섯 개를 나열함. E0는 교신저자 Guangrun Wang과 Liang Lin이 공저자인 자기 인용이고, 우리가 확인한 UniVTAC·N0 계열 표에는 E0의 UniVTAC 결과가 없음.
  6. 계보상 본 논문은 GPT-as-Policy(Galbot, arXiv:2609.38537)의 direct-control 정식화를 그대로 쓰고 tactile을 확장한 것임. "IK 컨트롤러로 1–5 control step 실행", "xhigh reasoning"까지 같음. 2026년 9–10월에 GPT-6 Astra를 정책으로 평가한 논문이 최소 4편 더 확인됨(아래 4절). 그러나 촉각을 넣은 것은 본 논문이 처음으로 보이며, 이는 우리가 찾은 범위 안에서의 판단임.
  7. 재구현에 중요한 발견. UniVTAC 소스(envs/insert_hole.py)를 보면 Insert Hole 구멍의 기울기는 ±30°(π/6) 두 가지 중 하나로만 정해짐(rotate ∈ {0, π}). 그러니 "probing으로 방향을 찾는" 문제는 사실상 이진 선택에 가깝고, Fig. 2의 "~30° Success"도 여기서 나옴. episode 상한은 step_lim = 300으로, Fig. 2의 "step 300 Failed"와 맞음.

2.1 GPT-as-Policy (Galbot Team, arXiv:2609.38537)

  • 내용. GPT-6 Astra를 6개 domain(gripper, dexterous in-hand, mobile manipulation, navigation, locomotion, humanoid WBC)에서 direct 정책과 hybrid 정책으로 평가함. 보고 수치는 RoboDojo gripper hybrid 약 48%, dexterous hybrid 50%, RoboCasa365 mobile 38.7%, RxR 92%, HM3D 82%임. locomotion은 5번 모두 실패했고 HumanoidBench에서는 30개 중 13개 task에서 baseline보다 나았음.
  • 본 논문이 그대로 가져온 것. Appendix H의 내용이 같음. gpt-6-astra를 xhigh reasoning으로 Responses API를 통해 호출하고, schema로 검증되는 tool call로 action vector와 1–5 repeat count를 받으며, episode마다 model thread 하나를 유지함. 본 논문 3.4절의 "IK controller executes the target for one to five control steps"와 4.1절의 "reasoning effort fixed to xhigh", "independent model session per episode"는 이 프로토콜을 그대로 옮긴 것임.
  • 지연 시간. locomotion 30초 롤아웃에 250번 호출, 호출당 평균 39.86초였고 그동안 physics를 멈춤. RoboDojo 50 instance에서 Direct 방식은 총 1,132.3M token을 썼음. 본 논문은 latency, token, 비용을 하나도 보고하지 않음. 시뮬레이션을 멈추는 방식이라고 가정하면 "실시간 촉각 반응"이라는 주장은 RDP 같은 고주파 촉각 제어와 같은 선에서 비교할 수 없음.
  • 촉각은 다루지 않음. in-hand task 입력이 "images and state"뿐이었음. 그러므로 촉각 확장이 본 논문의 실질적인 새 기여임.
  • GPT-6 Astra 자체: GPT-as-Policy의 ref [32]는 OpenAI, "GPT-6 Astra: A new generation of intelligence"(openai.com/index/gpt-6-astra/, 2026)임. 해당 페이지는 HTTP 403이라 원문 미확인.

5. 차별점 및 공정 비교 평가

5.1 연구별 차별점

비교 대상 본 논문의 차별점 그 차별점의 실제 무게

REFLECT 실패 설명을 사후 재계획이 아니라 사전 Task Skill로 만들어 두고, 온라인 단계마다 반영 개념상 REFLECT의 경험 요약을 offline으로 옮긴 것에 가까움

RDP 반응 제어를 LLM 재질의로 대체 실시간성 비교는 불가능함
촉각 WAM 계열 명시적인 미래 촉각 예측 모델 없이 H_t와 LLM 추론으로 결과를 비교 예측 모델이 없으므로 "anticipating contact"는 주장하지 않음(정확한 위치 설정)

5.3 Insert Hole 결과 해석에 대한 주의

  • 소스상 hole 기울기는 ±30° 두 가지로만 정해짐. 따라서 "probing 방향 탐색"은 사실상 좌우 이진 탐색에 가깝고, Fig. 4의 near-vertical, leftward, rightward 3방향 탐색과 rightward 성공은 이 구조와 잘 맞음.
  • w/o tactile의 31%는 무작위로 한 방향을 고를 때 기대되는 약 50%보다 낮음. 시각만으로는 방향을 고른 뒤에도 정렬과 삽입을 완료하기 어렵다는 해석이 가능하지만 이것은 추정임.
  • Task Skill이 "구멍은 ±30° 중 하나"라는 사실을 demo에서 뽑아 담았을 가능성이 높음. 그렇다면 99%는 일반적인 촉각 추론이라기보다 task 구조를 사전 지식으로 쓴 결과일 수 있음. Task Skill 원문이 공개되지 않아 확인할 수 없음.

6. 재구현 및 검증 에이전트에 넘길 사항

  1. UniVTAC repo의 envs/{insert_hole,lift_can,grasp_classify,lift_bottle,pull_out_key}.py에 있는 check_success, check_early_stop와 _base_task.py의 step_lim=300, take_action(action_type='ee')를 그대로 따를 것. Isaac Sim 4.5와 RTX급 GPU가 필요하므로 현재 환경(torch 없음, 설치 금지)에서는 실제 실행이 불가능함. mock env로 프로토콜만 재현하는 것을 권장함.
  2. 촉각 descriptor D와 M은 left_tactile/right_tactile의 depth와 marker_motion에서 mean, peak, contact area, centroid, 변위장 통계로 계산할 것. 정확한 pooling 크기와 임계치는 논문에 없으므로 미확인.
  3. LLM 호출 프로토콜은 GPT-as-Policy Appendix H를 기준으로 할 것: Responses API, xhigh, schema tool call(action, repeat 1–5, rationale), episode마다 thread 하나.
  4. 검증 에이전트는 Table 2의 baseline 셀을 2.2와 2.3의 출처 표와 대조하고, n=100 binomial CI와 8-task로 외삽한 시나리오를 다시 계산할 것.
