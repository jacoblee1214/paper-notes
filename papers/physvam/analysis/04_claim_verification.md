# 04. 주장 검증 (공식 코드가 없어 논문 주장을 직접 대조)

## 1. 대조 기준과 범위

- 공식 코드와 학습된 가중치가 공개되지 않았습니다(`02` §2). 그래서 코드 대조(D1–Dn)를 하지 않았습니다. 대신 논문의 주장 C1–C20을 표, 부록, 본문 값과 대조했습니다.
- 판정 기호: **확인** (재계산이나 식으로 맞음), **부분** (방향이나 일부만 맞음), **미확인** (논문에 없는 정보가 필요함), **불확실** (맞을 수 있지만 현재 증거로는 판단할 수 없음).
- 통계 근거는 `03_analysis.md`, 식 근거는 `analysis/toy_value_target.py` 결과(V1–V3)입니다.

## 3. 구조적 발견 (주장 밖의 점)

1. **실패 궤적의 출처가 기준선이라 데이터 분포가 기준선에 묶입니다.** 실패 샘플이 PUMA와 DynamicVLA의 실패 패턴을 따른다면 가치 모델은 이 실패들을 학습하게 됩니다. 기준선 대비 이득이 "가치 예측"에서 왔는지 "추가 데이터"에서 왔는지 분리하지 못합니다. 실험 설계상 같은 궤적 수를 쓰는 대조가 없습니다.
2. **가치 재가중은 가치 모델을 학습 데이터 자체에 씁니다.** 학습 샘플에서 ΔV를 계산하므로 과적합 가능성이 있습니다. 재가중 효과(+2.67)가 작으므로 이 점이 결론을 바꿀 정도인지 판단하기 어렵습니다.
3. **시간 지표 정의.** 시간은 낙하 종료를 포함하므로 "빠른 완료"가 "효율"을 뜻하지 않을 수 있습니다.
4. **시드 3개.** 모든 ±와 Welch 검정이 시드 3개에 기댑니다. 3개 시드에서 SD 추정치는 매우 불안정합니다. ±가 모집단 SD로 계산되었다는 점(`03` §1.4)도 검정 결과를 과장할 수 있습니다.
5. **실로봇 n = 20.** 과제당 시행이 적어 장면별 차이 중 하나(굴림)는 유의하지 않습니다.

## 4. 구현 가능성 판정

**판정: 논문 재현은 이 맥에서 불가능합니다. 축소 구현은 조건부로 가능합니다.**

| 구성 요소 | 필요 자원 | 이 맥(M4 Pro, 24 GiB, MPS, CUDA 없음) | 판정 |
|---|---|---|---|
| 공식 코드 | 공개되지 않음 | 해당 없음 | **불가** (코드 없음) |
| 시뮬레이션 환경 (DOM 기반 10 물체 장면) | 환경과 데이터가 공개되었는지 미확인 | 미확인 | **미확인** |
| 학습 (ActionDiT 1B + ValueDiT 512 차원, 24K 스텝, 배치 128) | RTX 5090 4장, 48 GPU 시간 (부록 A.2) | CUDA 없음. MPS는 훨씬 느릴 것으로 추정 (측정 전) | **불가** (GPU 필요) |
| 추론 (10 + 4 디노이징 스텝, 1B) | RTX 5090에서 0.322 s/청크 | MPS에서 측정 전 | **미확인** (측정 필요) |
| 실로봇 (AgileX PiPER, 턴테이블, 컨베이어, 3 카메라, FoundationPose) | 실물 장비 | 없음 | **불가** |
| 가치 목표 식과 통계 재계산 | CPU | 가능 | **완료** (`03`, 검사 V1–V3) |
| 축소 구현 (1-D 또는 2-D 동적 도달/잡기 토이, ValueDiT와 게이트 교차 주의 구조) | numpy 또는 torch CPU/MPS, 승인 없는 패키지 확인 필요 | 가능 (소형) | **조건부**: 노력 1–2주 (추정). 논문 수치와 비교할 수 없음 |

- **노력 추정.** 축소 구현은 1–2주(추정, 측정 전)입니다. 시뮬 재구현은 DOM 환경 공개 여부에 따라 달라집니다. 공개된다면 4–8주(추정)이고, 그래도 학습은 GPU가 필요합니다.
- **실제로 확인할 수 있는 것.** 가치 목표의 성질(V1–V3), 통계 재계산(`03`), 표 간 일치(`03` §2)입니다. 학습된 모델의 성능은 이 맥에서 확인할 수 없습니다.
