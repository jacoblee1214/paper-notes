# 03. 수치 재계산과 일관성 검사: Beyond Semantic Classes (arXiv:2611.10107 v1)

이 문서의 숫자는 모두 `analysis/recompute.py`가 `analysis/recompute_results.json`에 쓴 값입니다(numpy, scipy, 1초 미만). 논문 원자료(주행 로그, 궤적, 충돌 시도)가 없어서 **본문과 표·그림 주석에 있는 값만** 다시 계산했습니다. 학습과 시뮬레이션은 돌리지 않았습니다.

## 1. 재계산

### 1.1 9회 주행 시간 통계 (§4.3, p.8)

입력: 주행 시간 9.304 ± 0.316 s(사전분포만, 기준선), 8.135 ± 0.007 s(이력 사용), 구간 200–300 m, 각 9회. **± 의 의미(SD 또는 SE)와 두 조건의 짝 여부는 논문에 없습니다.** 두 해석을 모두 계산했습니다.

| 항목 | ±를 SD로 읽음 | ±를 SE로 읽음 |
|---|---|---|
| Welch t (df) | 11.1 (8.0) | 3.7 (8.0) |
| 양측 p | 3.9 × 10⁻⁶ | 0.006 |
| 95% 구간, 기준선 | [9.061, 9.547] s | [8.575, 10.033] s |
| 95% 구간, 이력 사용 | [8.130, 8.140] s | [8.119, 8.151] s |

- 주행 시간 감소율은 (9.304 − 8.135)/9.304 = **12.56%**입니다. 본문 12.6%와 맞습니다.
- 평균 속도는 10.51 → 11.78 m/s로 **12.08%** 증가합니다.
- 표준편차 비는 0.316/0.007 = 45.1, 분산 비는 약 2,040입니다. 이 정도로 작은 분산은 드물어서 원자료 확인이 필요합니다. 짝을 가정하지 않은 Welch 검정이므로, 짝 검정을 하려면 시행별 값이 필요합니다.
- **결론.** 두 해석 모두에서 차이는 통계적으로 유의합니다. 그러나 ±의 정의에 따라 기준선의 신뢰구간 폭이 약 세 배 달라지고, "16배 낮은 속도 프로파일 분산"(본문 p.8)은 이 값으로 확인할 수 없습니다.

### 1.2 평균 속도와 L/T (§4.3, p.8)

구간 길이 L = 100 m(s = 200–300 m)를 쓰면 L/T는 기준선 10.748 m/s, 이력 사용 12.293 m/s입니다. 보고된 평균 속도는 10.51과 11.78이라 각각 **2.2%, 4.2% 작습니다.**

- 시간에 대한 평균 속도는 정확히 L/T입니다. 거리에 대한 평균 속도는 산술-조화 부등식에 따라 L/T보다 **크거나 같아야** 합니다.
- 두 정의 모두 보고값과 맞지 않습니다. 시간 평균으로 맞추려면 구간 길이가 97.8 m(기준선)와 95.8 m(이력 사용)여야 합니다.
- **결론.** 구간 길이, 시간 창, 평균 정의 중 하나가 본문 설명과 다릅니다. 세 가지를 저자에게 확인해야 합니다.

### 1.4 표 1 질의 지연의 규모 (§4.2, p.7)

| N | CPU (S=1000, ms) | GPU (S=1000, ms) |
|---|---|---|
| 10⁴ | 0.81 | 0.74 |
| 10⁵ | 4.01 | 2.07 |
| 10⁶ | 49.84 | 15.22 |

- 10배마다 증가율: CPU 4.95, 12.43. GPU 2.80, 7.35. 10⁵→10⁶ 구간의 로그-로그 기울기는 CPU 1.09, GPU 0.87입니다. **N에 대략 선형**입니다.
- 항목당 비용은 CPU 50 ns, GPU 15 ns입니다.
- S의 효과는 N = 10⁶에서 −3.4%(S = 10 → 1000)입니다. 샘플 수가 비용을 거의 바꾸지 않는다는 본문 주장과 맞습니다.
- **메모리.** 임베딩이 768차원(DINOv3 ViT-B/16 특징 차원이라고 가정. 논문은 차원을 적지 않음)이면 10⁶ 항목의 fp32 저장량은 2.86 GiB, fp16은 1.43 GiB입니다.
- **해석.** CPU 시간 49.8 ms는 3.07 GB를 한 번 훑을 때 약 62 GB/s입니다. 이는 메모리 대역폭에 묶인 선형 스캔과 맞는 크기입니다(M4 Pro의 대역폭은 공개 사양으로 약 273 GB/s이나 이 세션에서 확인하지 않음). 즉 이 맥에서도 같은 종류의 스캔이 될 것으로 예상하며, 실제 측정은 하지 않았습니다.
- **범위.** 표 1은 질의 시간만 잽니다. 인코더와 정제 지연은 포함하지 않습니다.

## 3. 부록 E: 충돌률의 불확실성

본문은 쌍봉 믿음에서 "more than 40%"가 충돌하고 가우시안에서는 "fewer than 1%"라고 씁니다. 롤아웃 수 N이 없으므로, N에 따른 Wilson 95% 구간을 계산했습니다.

| N | 40% (k = 0.4N) 의 Wilson 95% | 0건 (k = 0)의 Wilson 95% 상한 |
|---|---|---|
| 20 | [21.9%, 61.3%] | 16.1% |
| 50 | [27.6%, 53.8%] | 7.1% |
| 100 | [30.9%, 49.8%] | 3.7% |
| 500 | [35.8%, 44.4%] | 0.8% |

- "40% 이상"은 관측 비율이 40%를 넘었다는 뜻입니다. N = 100이면 관측 비율 0.40의 95% 구간이 31–50%라서, 이 문장은 N이 없으면 확정되지 않습니다.
- 1% 미만 주장은 0건이 나왔다고 가정할 때 **N ≈ 380 이상**이어야 95% 상한이 1% 아래로 내려갑니다. 롤아웃 수가 이보다 적으면 "1% 미만"은 통계적으로 확인되지 않습니다.
- **결론.** 충돌률 대비는 방향은 분명하지만, 수치는 롤아웃 수가 있어야 평가할 수 있습니다.

## 4. 그림 10 주석의 역산 (부록 C.6, p.20)

ρ = M/(M+κ)이므로 M = κρ/(1−ρ)입니다. 주석 ρ를 두 자리로 반올림한 값으로 보고 ±0.005 구간을 씁니다. 열(t)마다 다섯 행(κ = 0.1, 1, 5, 10, 100)의 M 구간을 교차시켰습니다.

| t | 행별 구간이 겹치는 M | M/t |
|---|---|---|
| 5 | [4.71, 4.81] | 0.95 |
| 10 | [8.52, 8.69] | 0.86 |
| 25 | [17.22, 17.40] | 0.69 |
| 50 | [30.82, 32.04] | 0.63 |
| 100 | [55.04, 57.48] | 0.56 |
| 315 | [159.7, 166.7] | 0.52 |

- **다섯 행 모두 열마다 같은 M과 맞습니다.** 그림 10의 주석은 ρ = M/(M+κ)와 하나의 M(t)로 만든 것입니다. 내부 모순은 없습니다.
- M(t)은 t^0.85 정도로 자랍니다(t = 5에서 315까지 멱지수 0.853). 상호작용이 쌓일수록 새 접촉 하나가 더하는 지지 질량이 줄어듭니다. 이웃 임베딩이 겹치기 때문으로 보이나, 논문이 이를 설명하지는 않습니다.
- **주의.** 그림 10의 γ와 c가 적혀 있지 않습니다. 레이싱 실험의 γ = 100, c = 0.9를 쓴 것인지 알 수 없습니다. 따라서 M(t)를 레이싱에 그대로 옮길 수는 없습니다.
- 그림 10의 κ 스윕(0.1–100)에는 레이싱 실험의 κ = 0.01이 없습니다.

## 5. 커널 민감도: 이웃 하나의 기여

K = exp(γ(cos − 1)), 바닥 c 미만은 0으로 두고, 이웃이 하나일 때 ρ = K/(K+κ)를 계산했습니다(`recompute_results.json`의 `kernel_single_neighbor`).

| 설정 | cos 0.90 | cos 0.95 | cos 0.99 | cos 1.00 |
|---|---|---|---|---|
| 실험 1 (γ = 400, κ = 5e-3) | ρ ≈ 0 | 4 × 10⁻⁷ | 0.79 | 0.995 |
| 실험 2 (γ = 40, κ = 5e-3) | 0.79 | 0.96 | 0.99 | 0.995 |
| 레이싱 (γ = 100, κ = 0.01, c = 0.9) | 0.005 | 0.40 | 0.97 | 0.99 |
| 실차 (γ = 10, κ = 2, c = 0.9) | 0.16 | 0.23 | 0.31 | 0.33 |

- **레이싱.** 이웃 하나로 ρ = 0.5가 되려면 cos ≥ **0.954**입니다. 바닥 c = 0.9 바로 위의 이웃은 기여가 거의 없습니다. 레이싱의 지지 전환은 사실상 거의 같은 임베딩에 의해 결정됩니다.
- **실차.** κ = 2이므로 ρ = 0.5에 필요한 이웃 수는 cos 0.90에서 5.4개, cos 0.99에서 2.2개입니다. 18회 측정에서 이 조건을 만족하는 이웃이 얼마나 되는지는 보고되지 않았습니다.
- **실험 1.** 같은 0.99 유사도라도 γ = 400이면 ρ = 0.79입니다. 그 아래 유사도는 사실상 무시됩니다. 실험 1의 "정확한 분리"는 γ가 크다는 설정에서 나옵니다.

## 6. 해석

1. **헤드라인 수치는 본문과 맞습니다.** 주행 시간 12.6%, 실차 ADE·FDE 14.8%·16.5%가 그렇습니다. 표 1의 확장성도 선형 스캔과 맞습니다.
2. **레이싱 통계의 정의가 빠져 있습니다.** ±의 의미, 짝 여부, 평균 속도 정의가 확인되지 않습니다. 결론(유의한 차이)은 어느 해석에서도 유지되지만, 크기와 "16배" 같은 세부 주장은 원자료 없이 확인되지 않습니다.
3. **그림 10은 내부적으로 맞습니다.** 다만 M(t)은 γ와 c가 빠져 있어 특정 설정에서만 맞고, 레이싱의 κ = 0.01은 스윕에 없습니다.
4. **커널이 매우 날카롭습니다.** 레이싱과 실험 1에서는 사실상 최근접 이웃 검색입니다. 이는 "다중 모드 보존"과는 다른 메커니즘이며, 이웃이 드물면 사전분포로 돌아가는 동작이 주로 κ와 γ 조합에 달려 있습니다.
5. **재계산하지 못한 것.** 시행별 주행 로그, 실차 궤적의 시행 분산, 부록 E의 롤아웃 수, 사전분포 편향의 민감도, 역모형 오차가 포함된 시뮬레이션, 표 2의 β. 이 항목들은 저자에게 요청하거나 재현 단계에서 측정해야 합니다.
