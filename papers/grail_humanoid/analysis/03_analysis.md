# 03. 수치 재계산과 일관성 검사: GRAIL (arXiv:2606.05160 v2)

재계산 스크립트는 `analysis/recompute.py`, 결과는 `analysis/recompute_results.json`입니다(CPU, 수 초). 그래프는 `analysis/plot_figures.py`가 `report/figures/own_*.png`로 만듭니다. 이 문서의 모든 수치는 두 파일에서 나옵니다. 논문 재현은 하지 않았습니다. 재계산과 검정만 했습니다.

표기: **V** 항목은 재계산 결과, **K** 항목은 본문 내부 일관성 검사입니다. 번호는 `01_paper_analysis.md`에서 가리킵니다.

## 1. 실물 pick-up (Table 3)

### V1. 평균, 구간, 두 집단 비교

| 항목 | 재계산 | 본문 |
|---|---|---|
| 학습 객체 5개의 객체별 평균 | 84.0% | 84% |
| 미학습 객체 5개의 객체별 평균 | 80.0% | 80% |
| 학습 객체 합계 | 42/50 = 84.0%, Clopper-Pearson 95% 70.9–92.8% (Wilson 71.5–91.7%) | 구간 없음 |
| 미학습 객체 합계 | 40/50 = 80.0%, Clopper-Pearson 95% 66.3–90.0% (Wilson 67.0–88.8%) | 구간 없음 |
| 학습 대 미학습 차이 | 4.0점, Fisher 정확 검정 p = 0.80 | "effectively transfers" |

- 객체별 구간은 10회 시험이라 매우 넓습니다. 예: Apple 6/10은 26–88%, Lint Roller 5/10은 19–81%입니다(`recompute_results.json`의 `per_object_CP95_pct`).
- **해석:** 미학습 객체 80%와 학습 객체 84%는 통계적으로 구분되지 않습니다. "미학습 객체에도 전이된다"는 결론은 지지되지만, "학습 객체와 같은 수준"이라고 쓰기에는 시험 수가 부족합니다. 두 집단 모두 하한이 60%대 이하입니다.
- 그림: `report/figures/own_s2r_ci.png`.

### V2. 계단 90% (시도 수 미기재)

본문은 계단 성공률 90%만 적고 시도 수를 쓰지 않았습니다. 가정에 따른 민감도는 다음과 같습니다.

| 가정한 시도 수 | 성공 수 | Clopper-Pearson 95% |
|---|---|---|
| 10 | 9 | 55.5–99.7% |
| 20 | 18 | 68.3–98.8% |
| 30 | 27 | 73.5–97.9% |

시도 10회라면 하한이 55%입니다. 이 값으로는 "90%"의 신뢰 폭을 판단할 수 없습니다(K4와 함께 `01` §5).

## 2. 과제 일반 추적 (Table 2)

### V3. 기준선과의 차이 (분모 124 가정)

본문은 "124 motions across 43 objects" 벤치마크라고 적었습니다(§4.2). 성공률을 에피소드 1회의 정수 비율로 보면 다음과 같습니다(가정: 모션당 에피소드 1개, 분모 124).

| 비교 | 차이 (점) | Newcombe 95% | Fisher 정확 p |
|---|---|---|---|
| Ours (Full) 81.4% vs HDMI 48.5% | +33.1 | 21.4–43.5 | 6.8×10⁻⁸ |
| Ours (Full) vs ResMimic 49.2% | +32.3 | 20.6–42.7 | 1.3×10⁻⁷ |
| Ours (Full) vs Ours w/o π_φ 39.7% | +41.9 | 30.2–52.0 | 1.5×10⁻¹¹ |

- **해석:** 분모가 124든 다르든, 차이가 20점 이상이라는 결론은 흔들리지 않을 가능성이 큽니다. 다만 이 검정은 같은 모션 집합에서 짝지은 정보를 쓰지 않았고, 기준선과 GRAIL의 학습 데이터 양과 손가락 자유도가 다르므로 **효과 크기를 방법 우위로 읽기는 어렵습니다**(`01` §3, 논문 §4.2 3문단이 직접 인정).
- 그림: `report/figures/own_sr_ci.png` (보고값과 Wilson 구간, 분모 124 가정).

### K1. 분모 검사: 여섯 행을 하나의 정수 분모로 설명할 수 있는가

| 확인 | 결과 |
|---|---|
| 분모 124에서 각 행이 보고값(소수 첫째 자리)과 맞는가 | ResMimic 49.2%(61/124)만 맞습니다. HDMI 48.5%, Ours w/o SONIC 45.0%, w/o π_φ 39.7%, w/o Rel. Obs. 57.9%, Ours 81.4%는 124의 정수 비율로 나오지 않습니다. 가장 가까운 값은 HDMI 60/124 = 48.4%, Ours 101/124 = 81.5%입니다. |
| N ≤ 500에서 여섯 행을 모두 맞추는 공통 분모 | N = 478 하나뿐입니다. 소수 첫째 자리 반올림으로는 우연히 맞을 수 있는 수준이라 의미가 없습니다. |

**결론:** Table 2의 성공률은 "124 모션을 1회씩 평가한 정수 비율"이 아닙니다. 시드 평균, 모션당 여러 에피소드, 또는 행마다 다른 분모일 가능성이 큽니다. 논문은 어느 것인지 적지 않았고 분산도 보고하지 않았습니다. 이것이 이 논문 수치 검토에서 가장 중요한 빈칸입니다(`01` §5의 1번).

### K1-b. 같은 검사를 다른 표에 적용

- **Table 1 SR 88.9%(20 물체):** 소수 첫째 자리 반올림으로 맞는 공통 분모는 171 또는 342입니다. 분모가 표에 없어 판단할 수 없습니다.
- **Table 8 SR 81.4%, 53.3%, 41.6%, 42.6%(124 모션 벤치마크):** 124로는 맞지 않습니다. 네 행 공통 분모는 291, 317, 392입니다. 역시 124가 아닙니다.
- **Table 2의 Ours (Full) 81.4%와 Table 8의 Ours (Full) 81.4%는 같습니다.** 두 표가 같은 실행 결과를 쓴 것으로 보입니다.

## 3. HOI 생성 비교 (Table 1)

### V4. 순위와 사용자 연구

- 8개 지표 중 우리 방법이 1위인 것은 **7개**입니다(접촉, 침투, 상호작용 점수, 객체 평활도, SR, 몸 편차, 객체 편차). 인간 평활도는 DAViD(0.0024)가 가장 좋고 우리 방법(0.0033)이 2위입니다. 본문의 "nearly all metrics"는 맞습니다(`recompute_results.json`의 `T1_ours_rank`).
- Table 1의 SR 88.9%는 분모가 없어서 구간을 낼 수 없습니다(K1-b).
- Table 7 사용자 연구: 3택 1 무작위 노출이므로 한 방법이 보일 때 선택될 상한은 75%입니다. 우리 방법은 Aff. 74.7%, Phys. 70.9%입니다. 상한 대비로는 99.6%와 94.5%입니다. 천장 효과에 가까워서 차이를 세기에는 불리합니다. 응답 수와 구간이 없어 검정은 할 수 없습니다. 열 합계는 100.1%와 100.0%로 반올림 범위 안입니다.

## 4. 시간과 비용

### V7. 생성 시간 분해 (Table 4)

- 영상 1분 + 사람 2분 + 물체 1분 + 전처리 2분 + 조인트 최적화 8분 = **14분** (본문 14분과 일치).
- 영상 생성과 초기 추정 합계 4분 (본문 "about 4 minutes"와 일치).

### V5. 추적기 학습 비용 (B.3)

- 정책 1회: 30시간 × 64장 = **1,920 GPU-h**.
- 본문 정의대로 벽시계 시간을 모션 수로 나누면 2,000–4,000 모션에서 **0.45–0.9분/모션**입니다. 본문은 "0.5–0.9"라고 적었습니다(반올림 차이).
- 워밍스타트 6,000 iteration은 30시간의 1/5, 약 6시간으로 맞습니다.

### K2. 비용 단위의 함정

위 0.45–0.9분은 **벽시계 시간**입니다. GPU 자원 기준으로 바꾸면 모션당 **28.8–57.6 GPU분**입니다(64배). 논문 본문은 "far below the per-sequence cost"라고 비교하지만, 그 비교 대상인 "모션 하나마다 따로 맞추는 비용"도 벽시계 기준인지 GPU 기준인지 적지 않았습니다. 두 값을 같은 단위로 맞춰야 "amortized" 주장을 평가할 수 있습니다(`01` §3, B.3).

## 5. 데이터셋 규모

### V6. 공개 데이터 카드 합계

HF 데이터 카드의 표(8개 범주)를 더하면 **36,097 모션**입니다. 범주별 계산은 다음과 같습니다. pickup_table 2,991 / pickup_ground 1,736 / sitting 1,748 / slope 1,880 / curb 1,769 / stair(p1–p4) 24,700 / manip_ground 600 / manip_table 673. 프레임 수 검산: pickup_table은 2,991 × 10 s × 25 Hz = 747,750으로 카드와 일치합니다. 5초 모션은 126프레임(끝점 포함)으로 적으면 manip_ground 75,600과 manip_table 84,798이 맞습니다.

### K6. 규모 수치의 불일치

- 논문 v1·v2 초록과 본문: "over 20,000 sequences".
- 프로젝트 페이지: "over 35,000 physically validated motions".
- 공개 데이터 카드: 36,097 모션 (2026-11-18 갱신 기록 포함).

세 수치는 시점과 범위가 다릅니다. 논문 제출 시점의 학습 풀 규모와 공개본 규모를 같은 것으로 보면 안 됩니다. 논문은 "20,000 이상"이 어느 범주까지 포함하는지 적지 않았습니다.

## 7. 재계산하지 못한 것

- Table 1의 접촉, 침투, 평활도, 물리 추적 편차: 원시 시퀀스가 없어 재계산할 수 없습니다. 공식 데이터셋은 물체와 로봇 궤적을 담고 있지만(카드 기준), 이 분석에서는 내려받지 않았습니다(`README.md`의 제약).
- Table 2, 8의 기준선과 ablation: 에피소드별 결과가 없어 쌍체 검정을 할 수 없습니다.
- Table 7 사용자 연구: 응답 원시 데이터가 없습니다.

## 8. 요약

1. **실물 pick-up 84%는 42/50이고 95% 구간은 71–93%입니다.** 미학습 80%는 40/50으로 구간 67–89%입니다. 두 집단의 차이는 유의하지 않습니다.
2. **계단 90%는 시도 수가 없어 판단할 수 없습니다.** 10회라면 구간이 56–100%입니다.
3. **Table 2의 기준선 차이(20점 이상)는 분모 124 가정에서 유의합니다.** 다만 분모 자체가 124와 맞지 않아서, 분모를 확인하기 전에는 정량 결론을 확정할 수 없습니다.
4. **학습 비용은 벽시계 기준이며 GPU 기준으로는 64배입니다.**
5. **데이터셋 규모는 시점에 따라 20,000, 35,000, 36,097로 달라집니다.**
