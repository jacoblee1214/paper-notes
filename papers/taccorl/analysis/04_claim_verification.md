## 2. 판정에 쓴 근거의 한계

- **시드와 변동:** RL 학습 시드 수가 논문에 없습니다. 표 1·2와 그림 6·7은 한 번의 학습으로 읽습니다. 시뮬 z 검정은 평가 잡음만 반영합니다.
- **체크포인트 선택:** §4.5가 "best simulator success"를 쓰므로 선택에 시뮬 성공이 쓰였을 수 있습니다. 실로봇 평가 전에 시뮬에서 고른 체크포인트를 쓴다면 시뮬 측 선택이 실 평가와 독립이라는 점은 장점이지만, 선택 규칙이 논문에 없습니다.
- **평가 프로토콜:** 20회 시행의 초기 자세, 성공 판정, 정책별로 같은 자세를 쓰는지(짝지은 평가)가 없습니다. 짝지은 평가라면 McNemar 검정으로 효율이 올라갑니다.
- **공개 정보:** 프로젝트 페이지는 영상과 같은 표만 담고 있어 추가 정보(시행별 결과, 설정 파일)는 없습니다.

## 3. 저자에게 물어볼 만한 항목

1. 표 1과 그림 7의 "success"가 최종, 최고, 이동 평균 중 무엇인지와 분모(`03` K2–K4).
2. Table 4의 앵커 에피소드 200개와 실 시연 50개의 관계(`03` K1).
3. 학습 시드 수와 시드 간 변동.
4. 촉각 게이트를 없앤 변형과 이력 길이 L의 영향.
5. Do Puzzle에서 시뮬과 실로봇의 차이(`03` V8)에 대한 원인 분석.

## 4. 구현할 수 있는지 (판정)

**전체 재현은 이 맥(Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)에서 불가능합니다. 구성 요소 일부의 축소판은 구현할 수 있고, 논문의 수치 재현이 아니라 방법의 동작을 보는 용도입니다.** 공식 코드, 데이터, 체크포인트가 모두 공개되지 않았습니다(2026-11-23).

| 구성 요소 | 이 맥에서 | 필요한 것 | 노력(추정, 측정 전) |
|---|---|---|---|
| 표 재계산과 검정 | 가능, 완료 | numpy, scipy | 완료 |
| 접촉 게이트(식 4) + 촉각 토큰 인코더 + 교차 주의(식 3–5) | 가능 (torch, CPU 또는 MPS, 작은 모델) | 합성 촉각 데이터 | 2–3일 |
| 컨트롤러 SysID(식 9, SPSA, 부록 B.1) | 가능 (1자유도 임피던스 모델, 이미 설치된 mujoco 또는 numpy) | 실 스윕 데이터는 없음, 합성으로 대체 | 1–2일 |
| 공동학습 + PPO + 실데이터 앵커(식 7–8)의 축소판 | 가능 (2D 접촉 과제, 작은 정책) | 합성 "실"/"시뮬" 도메인 차이를 직접 설계 | 1–2주 |
| 스프링-댐퍼 촉각 시뮬(식 10) | 가능 (2D 또는 단순 3D) | SDF 거리 질의 | 3–5일 |
| π0.5에 촉각 토큰을 붙인 공동학습(표 3) | 불가 | openpi는 JAX, LoRA 기준 22.5 GB 이상 GPU(공개 문서 기준, 확인 안 함), 공동학습 1000–3000스텝 × 배치 192 | GPU 필요 |
| RLinf Flow-SDE PPO로 π0.5 후학습(표 4) | 불가 | CUDA, 병렬 환경 128개 | GPU 필요 |
| 시뮬 트윈 구축(PiPER 두 대, 촉각, 카메라 정렬) | 불가에 가까움 | 사용한 시뮬 엔진이 논문에 명시되지 않음, 과제별 자산 | 수 주 이상 |
| 실로봇 4과제(표 2) | 불가 | AgileX PiPER 두 대, FlexiTac-V2 패드 4개(오픈 하드웨어 [58]), RealSense 3대, 과제별 실 시연 50개 | 장비 구성에 수 주, 과제당 평가 80회 이상 권장 |

**한 줄 판정:** 논문이 보인 효과(72.5% 대 50%)를 재현하려면 GPU와 PiPER 양손 로봇 + 촉각 패드가 필요해 이 저장소의 범위 밖입니다. 이 맥에서는 "접촉 게이트 + 촉각 토큰", "SysID", "앵커 있는 RL"의 원리를 작은 환경에서 확인하는 정도가 현실적입니다.

**공개되면 달라지는 것:** 코드와 체크포인트가 공개되면 정적 대조(D 항목)와 추론 단계 확인이 가능해집니다. 현재는 저자 프로젝트 페이지 저장소가 웹사이트뿐이라 공개 시점도 알 수 없습니다.
