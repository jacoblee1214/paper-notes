# 04. 주장 검증과 구현 가능성 (TaF-Foundation, arXiv:2611.20718)

## 0. 대상과 방법

- **공식 코드가 없어** 논문 ↔ 코드 대조(D 항목) 대신 **주장 대조(C 항목)**를 했습니다(절차: `paper-deep-dive` 2절).
- 대상: arXiv v1 (`paper/paper.pdf`, 17쪽, 2026-11-16), 프로젝트 페이지(`mrjiangjm.github.io/TaF-Foundation`), 프로젝트 저장소(`mrJiangjm/TaF-Foundation`, GitHub Pages 전용).
- 수치는 `analysis/recompute.py`와 `03_analysis.md`에서 확인했습니다. 여기서는 주장마다 판정만 적습니다.
- 판정 기호: **확인** (수치와 문장이 일치), **방향만** (방향은 맞지만 통계로 확정 못 함), **약함** (근거 부족), **미검증** (데이터·코드 없이 확인 불가), **설계 주의** (지표나 설계가 주장을 과대 설명할 수 있음).

## 4. 구현 가능성 (이 맥: Apple M4 Pro, 약 24 GiB 통합 메모리, MPS, CUDA 없음)

**판정: 원 논문 규모의 재현은 불가능합니다. 방법의 소형 재구현(합성 데이터)은 가능하고, 노력은 1–2주로 추정합니다(측정 전).**

| 단계 | 필요 자원 | 이 맥에서 | 판정 |
|---|---|---|---|
| 데이터 수집 (1억 프레임, 24개 센서) | 동기화 장치, 6축 기준 센서, 센서 24종 | 불가 | 불가 |
| 공개 데이터 내려받기 | 공개 시점 미정 (V7). 광학 프레임 약 4,811만 개(표 S1). 원시 영상 해상도 240×320×3 또는 380×380×3이면 프레임당 0.23–0.43 MB, 합계 수 TB 규모로 추정 (해상도 가정, 압축 미확인) | 미정 | 공개 후 조건부 |
| 인코더 사전학습 (ViT-B/14, 10만 스텝, 배치 256, 입력 238×322, 391 토큰) | GPU 여러 장 수일 추정 (맥 MPS에서 한 스텝 수 초로 가정하면 수 일~수 주, 측정 전) | 조건부 (최소 규모만) | 불가 (본 규모) |
| 동결 인코더 위 헤드 학습 (표 2, 10,000 스텝 × 3) | 인코더 특징 또는 체크포인트 | 특징이 있으면 CPU 가능 (MLP 헤드) | 공개 후 조건부 |
| 미지 센서 적응 (표 S4–S5) | 체크포인트와 센서 데이터 | 헤드 적응은 CPU 가능 | 공개 후 조건부 |
| TaF-Policy 시뮬 (UniVTAC 3과제, 50 시연) | UniVTAC와 Isaac 계열 시뮬레이터 (NVIDIA GPU 전제) | 불가 | 불가 |
| TaF-Policy 실로봇 (Franka, 4과제) | 실로봇, 센서 4종 | 불가 | 불가 |
| 방법 소형 재구현 (입력 어댑터, 세 손실, EMA 정렬, 합성 센서 3–4개) | torch 설치 (승인 필요) | MPS 또는 CPU로 소규모 가능 | 조건부 (승인 후 시작 가능) |
| 통계 재검정 (표 2–5, S4–S6) | 숫자만 필요 | 가능 (완료) | 완료 (03 참조) |

- **노력 추정:** 방법 소형 재구현은 1–2주 (추정, 측정 전). 원 규모 재현은 데이터 공개 전에는 평가할 수 없고, 공개 후에도 GPU 장비가 필요합니다.
- **사용자 승인 대상:** 데이터, 가중치, 설치 모두 재현 전에 사용자에게 묻습니다(`CLAUDE.md`). 이 분석에서는 아무것도 설치하거나 실행하지 않았습니다.
