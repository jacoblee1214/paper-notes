논문의 주장은 한 줄로 이렇습니다. 조작 데이터로 사전학습한 π0를 쿼드로터 위의 그리퍼 비행체에 미세조정하면 시각 표현은 옮겨 가고(전이), 비행 동역학 때문에 생기는 실패는 추론 시점의 가이던스(Payload-Aware Guidance)와 3D 가우시안 스플랫 합성 데이터로 줄일 수 있습니다.

## 1. 문제 설정과 기여 (§I)

- 질문: 고정 베이스 조작기로만 사전학습한 VLA가 **저작동(underactuated) 6자유도 비행체**로 전이되는가. 저자들은 이를 크로스 임바디먼트 학습의 극단적 시험으로 둡니다(§I).
- 비행 쪽 어려움 세 가지(§I): (1) 추력과 자세가 결합되어 행동 오차가 큰 자세 편차로 번짐, (2) 온보드 카메라의 큰 자기 운동·모션 블러, (3) 접촉으로 인한 페이로드 변화와 공력 외란.
- 기여(§I 마지막):
  1. 사전학습 VLA를 항공 조작 플랫폼에 미세조정한 첫 시연(논문 주장).
  2. 교시(teleop) 시연 **270개**(조작 120, 항법 150) 수집, 공개 예정.
  3. 3DGS로 합성한 교정형 항법 예시 **50개**. 논문은 "교시만 쓸 때보다 항법 성공 20% 증가"라고 씁니다(검증은 `03` V5).
  4. 실시간 청킹(RTC) 안에서 파지 물체의 질량에 맞춰 적응하는 물리 기반 가이던스. "집기·놓기 성공 10–40% 향상"(검증은 `03` V6).

## 2. 방법 (§III)

### 2.1 시스템과 하드웨어 (§III-A, III-B)

- 기체: ModalAI Starling 2 Max, 컴패니언 컴퓨터 VOXL 2(Qualcomm QRB5165). UMI 그리퍼에서 가져온 손가락과 3D 프린트 프레임, 서보 두 개로 만든 경량 그리퍼를 기체 아래에 답니다(§III-B1, Fig. 2).
- 카메라 세 대: 외부 1, 온보드 2(전방, 하방), RGB 256×256, **5 Hz**(§III-B). 자세는 **모션 캡처**로 얻습니다(§III-B2, §V). 온보드 VIO나 SLAM은 쓰지 않았습니다.
- 행동 공간: 위치와 yaw의 **4자유도 상대 자세**와 그리퍼 명령. 생성은 **10 Hz**, 실행은 PX4 비행 제어기의 위치 설정값(position setpoint)입니다(§III-B2).
- 정책 추론이 어디서 도는지(온보드인지 외부 GPU인지), 지연, GPU 종류는 본문과 부록에 없습니다(`04` C9).

### 2.2 정책: π0 + RTC (§III-C)

- 기반: 공개 π0 베이스 체크포인트에서 시작해 드론 데이터로 미세조정합니다(부록 VII.A1). 흐름 매칭이 속도장 v_θ(x_τ, o, τ)로 행동 청크 x_τ ∈ ℝ^(H × D)를 만듭니다. 논문은 x_0 ~ N(0, I)에서 시작해 ODE (식 1) dx_τ/dτ = v_θ를 적분해 A = x_1을 얻는다고 씁니다.
- RTC(Black 등, arXiv:2506.07339): 다음 청크의 앞부분(prefix)을 이미 실행 중인 행동으로 고정하고 나머지를 인페인팅합니다. 비동기 추론 중에도 청크 경계의 불연속을 줄입니다(§III-C).

### 2.3 물리 기반 가이던스 (§III-D)

핵심 아이디어는 RTC의 "샘플링 중에 속도장을 고쳐 쓰는" 구조를 일반화하는 것입니다.

- 손실 Φ(A; o)를 행동 청크에 걸고 사후 분포 p_guid(A | o) ∝ p_θ(A | o)·exp(−Φ(A; o)) (식 2)를 목표로 둡니다.
- 구현: 시각 τ에서 종단 행동의 추정치 Â_θ(x_τ, o, τ)를 구하고, ξ = (∇_x_τÂ_θ)^ᵀ ∇_A Φ(Â_θ  o) (벡터-야코비안 곱)를 계산해 v_guid = v_θ - s(τ) ξ (식 3)로 샘플링합니다. s(τ)는 "스칼라 가이던스 스케줄"인데 **값과 형태가 보고되지 않았습니다**(`04` C6, `03` TB).
- 일반 추종 손실 (식 4, 5): Φ_track = 1/2 Σ_t Σ_d λ_d w_t (A_t,d - A^(des)_t,d)^2. 시간 가중 w_t는 RTC의 소프트 마스크(prefix 1, 중간 지수 감쇠, 새 구간 0)라고 설명합니다(§III-D1).
- **페이로드 인식 수직 가이던스** (식 6, 7): 고도 차원 z에만 건다.
  - Φ_payload = (λ_z/2)·α(o, A_{t−1}) Σ_t w_t (z_t(A) - z_des(o))^2, z_des = z_curr + Δ z, Δ z > 0 (부하가 걸리면 조금 높게 목표).
  - 가중 α ∈ [0, 1] (식 8, 9)는 직전 청크 마지막 K개 그리퍼 명령(닫기 의도)과 측정 조리개(닫힘 점수)를 곱한 휴리스틱입니다. 물체를 쥐었을 가능성의 대리 변수입니다.
  - α ≈ 0이면 RTC와 같아지고, α ≈ 1이면 청크의 수직 성분이 z_des 쪽으로 기웁니다. 저자들은 이를 "모드 의존 피드포워드(이득 스케줄링, 중력 보상)를 생성 정책의 샘플링 안에 주입한 것"으로 해석합니다.
- 부록 VII.A3 하이퍼파라미터: λ_z = 0.5, Δ z = 0.15 m, w_t = (t/(H-1))^γ (γ = 1, 뒤쪽 시간 단계에 집중), K = 4. 본문 §III-D1이 말한 RTC 소프트 마스크와 이 w_t는 **다른 가중입니다**(`04` C7).

### 2.4 가우시안 스플랫 데이터 파이프라인 (§III-E)

FiGS/Sous Vide(Low 등, RA-L 2025) 방식을 따릅니다.

1. **장면 복원:** 기체 전방 카메라의 짧은 걸어다니기 영상에서 미터 스케일 포즈를 얻고 Nerfstudio/gsplat로 3DGS를 학습합니다.
2. **그리퍼 분리와 합성:** 하방 카메라에는 그리퍼가 항상 보입니다. 이를 그대로 합성 이미지에 쓰면 편향이 생기므로, 그리퍼가 안 보이는 전방 시점으로 3DGS를 학습하고, SAM으로 고정 박스 프롬프트의 그리퍼 마스크를 따서 패치 라이브러리 {G_a}를 만듭니다. 합성 시점에 I^(synth)_down = (1 - M)⊙ GS(p,q) + M ⊙ G_a(t) (식 11)로 얹습니다.
3. **동역학:** 반운동학 상태 (p, v, q)와 추력·각속도 제어의 질점 모델 (식 12–14), ACADOS로 적분.
4. **도메인 무작위화:** 초기 상태 섭동, 목표 정지 높이 h ~ U(1.0, 1.5) m (식 15), 게이트 통과 후 경유점을 반경 0.125 m 공에서 샘플 (식 16), 게이트의 상하좌우 네 가장자리 중 하나를 지나게 하는 경유점 (식 17)로 **회복 궤적**을 만듭니다. 파라미터 N_s, Δ x, 버퍼 b의 값은 쓰여 있지 않습니다.

합성 데이터는 **항법 과제 전용**이고, 실제로 학습에 쓴 것은 50개입니다(항법 교시 150개 + 합성 50개 = 200개, 부록 VII.A2).

## 3. 실험 (§IV, 부록 VII)

### 3.1 과제와 지표

| 과제 | 프롬프트 | 단계 |
|---|---|---|
| Penguin Grasp | "pick up the stuffed animal and put it in the blue bin" | Pick → Place |
| Gate Navigation | "fly through the gate and hover over the stuffed animal" | Gate → Hover (왼쪽, 오른쪽 게이트 두 곳) |
| Compositional | 위 둘을 이어 붙인 프롬프트 (학습에 없음) | Gate → Hover → Pick → Place |

- 주 지표는 이진 성공이고 보고 비율은 **조건부**입니다. "Place 성공률은 Pick에 성공한 시도 수에 대한 비율"(§IV-D).
- 시도 수: 방법×과제당 **20회**, "누적 460회"(§IV-D). 재계산은 `03` V1.
- 비교 방법: π0 naive(청크 끝까지 열린 고리로 실행), π0 + RTC, π0 + RTC + payload-aware guidance(ours), ACT, Diffusion Policy. 두 기준선은 LeRobot 기본 설정으로 학습했습니다(부록 VII.A).
- 항법 단독에서 가이던스는 "RTC와 동일하므로" 평가하지 않았습니다(§IV-D).

### 3.3 학습·추론 설정 (부록 VII.A)

- 미세조정: 30,000 gradient step, AdamW, 코사인 스케줄(1,000 step 워밍업, 최대 2.5×10⁻⁵, 최종 2.5×10⁻⁶), 전역 배치 32, 행동 청크 H = 50. 4자유도 + 그리퍼를 모델 차원까지 0으로 패딩하고, 추론에서 앞 7차원을 꺼냅니다("그리퍼가 7번째 차원"). 데이터 120–150개 "(약 10시간)".
- 추론: 바닐라는 10 Hz로 실행하고 50개 실행마다 한 번 추론(0.2 Hz, 청크 5초 열린 고리). RTC는 청크 H = 25, prefix-attention 지평 25, 지수 prefix-attention 스케줄, 노이즈 제거 10 step.
- 이미지: 세 시점(외부 1, 몸체 2) + 고유감각.

### 3.4 논문이 내리는 결론 (§IV-E, §V)

- "순진한 미세조정은 pick-and-place 전체 성공 0%. RTC로 최대 23.5%, 가이던스로 최대 50%."
- "RTC는 항법에 필수. 게이트 통과 50→80%(교시만), 45→95%(합성 포함)."
- "합성 증강은 RTC와 함께일 때 가장 효과적". 정성적으로 정책이 "합성 모드"(GS 생성 궤적을 재생하는 모드)로 돌아가 게이트를 통과한다고 관찰했습니다.
- "조합 과제에서 제로샷 62% 전체 조건부 성공."
- OOD: 샌드위치 57%(표 III 조건부), 오른쪽 게이트 40%. 다른 영역은 0%. 저자들은 "부분 전이와 작은 데이터 구간의 심한 과적합"으로 해석합니다(부록 VII.B).
- 한계(§V): 모션 캡처 의존, 데이터 부족(약 270개), 다중 방 항법 불가.

## 4. 비판적 읽기 요약

세부는 `03`, `04`에 있습니다.

1. **초록의 숫자는 조건부 비율을 섞어 씁니다.** "23→50%"의 23은 4/17(조건부), 종단은 4/20. "62%"는 10/16(Pick 성공 중 Place)이고 종단은 10/20 = 50%. "100% 대 81%"는 게이트 통과 후 Hover 19/19 대 13/16이며 종단은 19/20 대 13/20(`03` V2–V4).
2. **가이던스 효과는 시도 20회로 확정하기 어렵습니다.** 종단 4/20 대 10/20의 Fisher p = 0.096, 조건부 4/17 대 10/20은 p = 0.17입니다. 세 설정을 합치면 9/60 대 25/60으로 p = 0.002이지만 설정 간 시도를 풀링한 것입니다(`03` V2).
3. **식 2가 약속한 사후 분포와 식 3의 구현은 다릅니다.** 효과적인 세기는 s(τ)와 정책 분산이 정하고 둘 다 보고되지 않았습니다(`03` TB).
4. **α는 "물체를 쥠"이 아니라 "그리퍼가 닫힘"의 대리 변수입니다.** 빈 손으로 완전히 닫으면 α = 1이 됩니다(`03` TA).
5. **"naive" 기준선은 청크 길이와 재계획 주기가 RTC와 다릅니다**(5초 열린 고리 대 H = 25). 개선이 RTC 알고리즘 때문인지 재계획 빈도 때문인지 분리되어 있지 않습니다(`04` C4).
6. **본문 표 II 한 칸(교시만, naive의 Pick 42.9%)은 앞 단계 성공 수로는 만들 수 없는 값입니다**(`03` V1).
7. **재현 자료가 없습니다.** 코드와 데이터는 "공개 예정"이고 모션 캡처 환경과 실기체가 필요합니다(`04` §4).
