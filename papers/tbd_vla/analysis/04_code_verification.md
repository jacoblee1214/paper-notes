# 04. 공식 코드 대조와 구현 가능성

대상은 `TBD-VLA/lerobot`(LeRobot 포크)의 `src/lerobot/policies/tbdvla/`입니다. 대조 기준은 main의 커밋 `41c746ed487520cf6cc49eb767d090837691e2b2`(2026-10-16)이고 `git clone --depth 1 https://github.com/TBD-VLA/lerobot repo`로 받은 얕은 복제를 정적으로만 읽었습니다(실행, import, 설치 없음). 논문 게시(2026-06-05)에 가까운 판은 커밋 `cf589001`(2026-06-09)이며 GitHub API로 `tbdvla/` 세 파일만 `data/`에 따로 받아 비교했습니다. 파일 규모: `modeling_tbdvla.py` 1,570줄, `configuration_tbdvla.py` 126줄, `cuda_graphs.py` 352줄, 테스트 두 개.

## 1. 일치하는 부분

| 항목 | 논문 | 코드 | 판정 |
|---|---|---|---|
| 백본 | Qwen3-VL 2B(§4.1) | `Qwen/Qwen3-VL-2B-Instruct`, 레이어 전부 | 일치 |
| 토큰 | 512 bin, 상태와 행동 같은 사전(§4.1, 표 8) | `<ACT_BIN_i>` 512개 + `<STATE_SLOT>`, `<MASK_ACT>`, `<ACT_SLOT>` | 일치 |
| 프롬프트 | "State: …, Task: …, Actions: …"(§4.1) | `State: {state}, Task: {task}, Actions: ` | 일치 (과제 문장은 소문자화, `_` 치환, 64 토큰 상한: 논문에 없음) |
| 이산화 | MinMax 정규화(표 8) | [−1, 1] 균등 512 bin, 상태·행동 모두 클램프 | 일치 |
| 손실 | 마스크 위치 평균 교차 엔트로피(식 1 아래) | `(token_loss * mask).sum() / mask.sum()` (배치 전체 평균) | 일치 |
| 토큰 이동·앵커 | 첫 블록은 전부 마스크인 앵커에서 예측, 이후 블록은 앞 깨끗한 블록에서 예측(식 1) | 예측 위치 = [앵커, clean_0, …, clean_{B−2}] | 일치 |
| 이중 배치, 위치 공유 | 깨끗한 열과 오염 열이 RoPE 위치 공유(§4.2) | clean 블록 b의 위치를 noisy 블록 b에 맞춤(별칭) | 일치 |
| 옵티마이저 | AdamW lr 1e-4, wd 0.01, 워밍업 500, 코사인(표 8) | 같은 값 | 일치 |
| 정밀도 | bf16 | `precision="bfloat16"` | 일치 |
| 블록 크기 등 | H_p 16, m 4, n_d 2 | `chunk_size` 16, `block_temporal_size` 4, `n_diffusion_steps` 2 | 일치 |
| 필요한 블록만 디코딩 | ⌈H_a/m⌉ 블록(§4.3) | `n_blocks_needed = ceil((n_action_steps + latency)/m)` | 일치(RTC 때 한 블록이 더 필요, D8) |
| 접두 KV 캐시 | 영상·프롬프트와 이전 블록 캐시 | 접두 캐시 + 확정 블록의 clean 쪽 K/V만 유지 | 일치 |

## 2. 차이 D1–D13

| 번호 | 항목 | 논문 | 코드 (main 41c746ed) | 영향 |
|---|---|---|---|---|
| D1 | 학습 어텐션 마스크의 앵커 항 | 그림 2(B): 깨끗한 블록 행이 앵커 열을 봄 | 깨끗한 블록은 앵커를 보지 않음(2026-10-15 커밋 194707f4가 `clean→앵커` 항을 제거). 6월 코드(cf589001)에는 `is_cln_i & is_sen_j` 항이 있음 | 그림은 6월 코드와 같고 현재 main과 다름. 공개 LIBERO 체크포인트(모델 파일 2026-06-07)가 어느 마스크로 학습됐는지는 확인 못함. 토이에서 무작위 가중치 기준 출력 변화 0.10–0.14 |
| D2 | 마스크 비율 샘플링 | 식 1: 토큰마다 t_{k,i} ~ U(0,1) | 블록마다 하나의 t ~ U(0,1)을 뽑고 토큰은 독립 Bernoulli(t)(`mask_ratio = rand(B, n_blocks, 1)`, 6월 코드도 같음) | 마스크 수가 균일(0–28)해져 전부 마스크된 상태 3.4%, 문자 그대로면 3.7e-9(`03` V11). 서술이 코드와 다름 |
| D3 | 해제 순서와 일정 | "logit이 높은 토큰 먼저"(§4.3), 일정 미기재 | 신뢰도 = 최대 softmax 확률. 마스크 수 / 남은 단계를 내림해 뒤쪽에 몰리는 일정(28 토큰, n_d = 2 → 14, 14) | 논문에 없는 세부. 신뢰도 정의가 logit이 아니라 확률 |
| D4 | 기대값 디코딩 | 식: 분포 전체의 기대값을 연속값으로(§4.3) | 기대 bin 번호를 반올림한 정수 토큰을 확정하고 bin 중심값으로 변환(연속 기대값 아님). `gripper_dims`(기본 마지막 차원)는 argmax 사용 | 양자화 폭은 2/512라 작음. 확정 토큰은 다음 블록의 조건이 됨. 그리퍼 argmax는 논문에 없음 |
| D5 | 추론 마스크 이력 | 학습과 추론 같은 구조라고 서술 | 2026-08-10 커밋 4f92f86d가 "추론 마스크가 학습 마스크와 세 경우에서 달랐다"고 수정(열린 루프 청크 MAE 0.07237 → 0.06927, 2,000 샘플). 10-15에 추론 구조를 학습 배치 그대로 재작성 | 논문 수치가 어느 판으로 나왔는지 기록이 없음. 공개 체크포인트는 수정 전에 올라옴 |
| D6 | 학습 설정 기본값 | 표 9: LIBERO 80K 스텝, 배치 72, 사전학습 80K 스텝 | README 예시: 150,000 스텝, 배치 4 또는 16, 데이터 `sean1295/libero_all`. 체크포인트 config는 사전학습 80,000 스텝 지점에서 시작함을 가리킴. AdamW betas (0.95, 0.999)와 grad clip 1.0은 표 8에 없음 | 논문 재현 설정과 README 설정이 다름 |
| D7 | RTC 학습 | 마스크 완성 학습이 RTC에 맞다고 서술(서론, §4.3) | 기본 학습은 지연 고정 없음(`latency_timestep = 0`). 값을 주면 앞 `latency_timestep` 스텝을 마스크하지 않고 손실에서도 제외 | 실로봇 RTC 체크포인트를 어떤 설정으로 학습했는지 논문·코드에 없음 |
| D8 | RTC 디코딩 비용 | ⌈H_a/m⌉ · n_d(§4.3) | RTC에서는 실행 H_a + 꼬리 d 스텝을 디코딩: H_a 12, d 2이면 4블록(첫 블록 일부 고정으로 1단계) → 7회, RTC 없이 6회 | RTC 지연 측정(0.119 s)에는 이 추가가 들어 있을 수 있으나 논문이 분해하지 않음 |
| D9 | 지연 시뮬레이션 | 표 11과 그림 4: 관측 지연 시뮬레이션 | 모델 카드가 `libero_10_with_obs_delay_t4` 환경을 쓰라고 하지만 저장소 `src/lerobot/envs/`에 지연 관련 코드가 없고, `_deploy_latency`는 읽기만 하고 어디서도 설정되지 않음(`getattr(self, "_deploy_latency", 0)`) | 표 11, 그림 4를 이 저장소만으로 재현할 경로가 없음 |
| D10 | 공개 범위 | 사전학습, 실로봇 평가 | 사전학습 체크포인트와 혼합 데이터 스크립트, 실로봇 배포 코드, 지연 환경, SimplerEnv·LIBERO-Plus 학습 설정은 저장소에 없음(LIBERO-Plus 환경 설정 클래스는 LeRobot 본체에 있음) | 표 3–5, 7, 13은 코드로 확인 불가 |
| D11 | 속도 최적화 | 표 6: 필요한 블록만, KV 캐시, torch 컴파일(0.086 s) | 이후 CUDA 그래프(`cuda_graphs.py`), 확정 블록의 clean 쪽만 캐시 등이 추가됨. 모델 카드 지연은 H_a 12 → 0.095 s, 8 → 0.070 s | 표 1과 6의 수치는 v1 시점의 구현 값 |

`tests/policies/tbdvla/`에 마스크 테스트(가중치 없이 CPU 가능)와 추론 일정 테스트가 있습니다. 실행하지 않았습니다. 별 7개, 이슈와 PR 활동은 확인하지 않았습니다.

## 4. 구현 가능성 (이 맥: Apple M4 Pro, 약 24 GiB, MPS, CUDA 없음)

**논문 수치의 재현은 불가능합니다. 방법의 구조(블록 확산 마스크, 디코딩 일정)는 작은 규모로 구현할 수 있고 마스크 부분은 이미 끝냈습니다.**

| 작업 | 판정 | 근거 |
|---|---|---|
| 표·그림 수치 재계산 | 완료 | `03` |
| 이중 배치 마스크 누수·동등성 검사 | 완료 | `analysis/toy_block_mask.py` |
| 사전학습(160K 에피소드, 약 1,600 A100 시간) | 불가 | 데이터와 GPU 규모, 스크립트 미공개 |
| LIBERO 미세조정(약 120 GPU 시간, 배치 72) | 불가 | CUDA 전제, 맥에서 현실적이지 않음 |
| 공개 체크포인트 추론(약 4.3 GB BF16, 2.13B 파라미터) | 조건부 | LeRobot 설치, 체크포인트 다운로드 승인, 공식 코드 실행 승인이 필요. 코드의 `device`, CUDA 그래프, flex attention은 CUDA 가정이 있어 MPS 동작과 속도는 미확인 |
| LIBERO 시뮬 평가 | 조건부, 어려움 | 시뮬(MuJoCo, robosuite) 설치와 렌더링 설정 필요. 이 맥에서 미확인 |
| 지연 시뮬레이션(표 11) | 불가(현재) | 환경이 저장소에 없음. 직접 구현해야 함 |
| 실로봇(Franka Research 3, UMI 그리퍼, VR 원격조작 50 데모/과제) | 불가 | 장비 |
| 작은 행동 모델로 블록 확산 재구현(토이 데이터, PyTorch) | 가능 | 마스크, 앵커, 손실, 디코딩 일정을 100–200줄로. 노력 3–5일(추정, 측정 전) |
| 마스크 비율 샘플링(D2) 영향 토이 | 가능 | 작은 트랜스포머로 첫 단계 전체 마스크 상태의 오류 비교. 1–2일(추정) |

전체 구현(사전학습 포함)은 데이터와 GPU 클러스터가 필요해 맥에서는 범위 밖입니다. 공식 코드 실행이 필요한 일은 승인이 먼저입니다.
