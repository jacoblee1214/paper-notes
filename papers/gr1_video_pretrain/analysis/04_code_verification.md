# 04. 논문과 공식 코드의 대조 (정적 읽기)

- 대상: `bytedance/GR-1`, 커밋 `4a2e956bb497586d82489eb4c98b27fb82b5ff47` (2024-04-22), 얕은 clone을 `repo/`에 두고 **정적으로만** 읽었습니다.
- 실행, 설치, import, 가중치 다운로드는 하지 않았습니다. 체크포인트는 HEAD 요청으로 크기만 확인했습니다(ABCD·ABC 각 약 197 MB, MAE ViT-B 약 343 MB).
- 저장소 파일: `evaluate_calvin.py`, `evaluate_calvin.sh`, `evaluation/calvin_evaluation.py`, `evaluation/calvin_env_wrapper_raw.py`, `models/gr1.py`, `models/trajectory_gpt2.py`, `models/vision_transformer.py`, `models/transformer_utils.py`, `utils/calvin_utils.py`, `logs/configs.json`, `install.sh`, `README.md`, `LICENSE.txt`. 총 Python 2,144줄.

**한 줄 결론.** 공개된 것은 CALVIN 평가 코드와 모델 구조입니다. 사전학습, 파인튜닝 손실, 학습 루프, 실로봇 코드가 없으므로 논문의 학습 쪽 주장은 코드로 검증할 수 없습니다. 모델 구조와 평가 프로토콜은 논문 설명과 대체로 맞습니다.

## 2. 논문과 맞는 모델 구조 (근거)

`models/gr1.py`의 `forward`를 읽으면 논문 §3.2의 구성이 확인됩니다.
- 토큰 순서: 언어, 상태, 정적 패치(Perceiver 9잠재), 정적 CLS, 손목 패치, 손목 CLS, [ACT], [OBS 정적], [OBS 손목]. 논문 §3.2.1의 순서와 같은 개념입니다.
- 언어 토큰은 시점마다 반복하고, 모든 모달리티가 시점 임베딩을 공유합니다.
- [ACT] 출력이 2층 MLP를 거쳐 팔 행동(6차원)과 그리퍼 로짓(1차원)을 냅니다.
- [OBS] 출력과 마스크 토큰이 2층 디코더를 거쳐 패치를 복원합니다(논문 MSE와 같은 구조).

**추론 경로.** 평가 때는 `training_target=['act_pred']`로 생성하므로 영상 예측 헤드를 계산하지 않습니다(D12의 정보성 항목). 논문 §4.3의 영상 예측 그림은 학습된 모델에서 나온 것이지만, 이 코드로는 재현할 수 없습니다.

## 3. 평가 경로의 세부

- 관측 버퍼: 최근 10 스텝을 쓰고, 부족하면 앞쪽을 0으로 채운 뒤 어텐션 마스크로 가립니다.
- 행동: 마지막 시점의 팔 행동 한 개와 그리퍼 로짓 한 개를 씁니다. 그리퍼 로짓은 시그모이드 후 0.5에서 ±1로 바꿉니다.
- 상태 입력: 팔 6차원과 그리퍼 상태를 원-핫으로 씁니다. 평가 중 손목 카메라 입력도 씁니다.
- 텍스트: CLIP 토크나이저로 지시문을 토큰화합니다. 지시문은 `calvin_agent`의 검증 주석(`new_playtable_validation.yaml`)에서 옵니다.

이 세부 중 시간 앙상블과 샘플링 방식은 논문에 없습니다. 같은 가중치라도 다른 추론 규칙을 쓰면 성공률이 달라질 수 있습니다. 재현할 때는 이 규칙을 그대로 따라야 합니다(D13).

## 4. 구현 가능성

이 항목은 세 부분으로 나눠 봅니다. 맥(Apple M4 Pro, 24 GiB, CUDA 없음, MPS 있음) 기준입니다.

**(a) 학습 (사전학습과 파인튜닝): 맥에서 불가능합니다.** 코드가 없습니다(D1–D5). 또 Ego4D 3,500시간 이상과 CALVIN 학습 데이터가 필요하고, 논문 설정(배치 1024, 50 epoch)은 여러 GPU를 요구하는 규모입니다. 학습 시간과 GPU 수는 논문에 없습니다.

**(b) CALVIN 평가: 맥에서 어렵습니다.**
- 코드가 CUDA를 가정합니다(D16). MPS로 바꾸려면 `.cuda()`와 `torch.device('cuda')`를 고쳐야 합니다.
- 의존성이 2022년 무렵 버전입니다(torch 1.12.1, transformers 4.5.1, D21). 현재 맥의 PyTorch와 맞지 않을 가능성이 큽니다. MPS에서 torch 1.12의 연산 지원은 확인하지 않았습니다.
- CALVIN 롤아웃은 시뮬레이터 렌더링이 필요합니다. `install.sh`는 EGL과 OSMesa 같은 Linux 렌더링 패키지를 설치합니다. 맥에서 이 경로를 어떻게 대체할지 확인되지 않았습니다.
- 체크포인트 두 개(각 약 197 MB)와 MAE(약 343 MB)를 받아야 합니다. 모두 1 GB 미만입니다.
- 따라서 CALVIN 1000 chain 평가를 맥에서 돌리는 것은 현실적으로 어렵습니다. Linux 기기(또는 CUDA GPU)에서 하는 것이 맞습니다.

**(c) 모델 구조 포팅: 가능합니다.** `gr1.py`(356줄)와 GPT 블록(`trajectory_gpt2.py`, 대부분 transformers의 GPT-2 복사본)은 PyTorch 현행 버전으로 옮길 수 있습니다. 약 300줄 수준이며, 파라미터 수 검증과 추론 일치 확인까지 포함하면 노력 추정은 2–4일입니다(추정).

**결론.** 논문 결과를 재현하는 것은 이 맥에서 불가능합니다. 모델 구조를 옮겨 짜고 작은 입력으로 확인하는 것은 가능합니다. 재현 여부는 CUDA 기기를 쓸 수 있는지에 달려 있습니다.

## 5. 저자에게 물을 것

1. 사전학습과 파인튜닝 코드, 또는 두 체크포인트의 학습 설정을 공개할 계획이 있는지.
2. 실로봇 결과의 시도 횟수와 시드, 그리고 실로봇 코드 공개 여부.
3. 추론 규칙(마지막 행동, 그리퍼 임계값, 앙상블 없음)이 논문 결과와 같은지.
4. 표 1 ABCD→D의 HULC 평균 길이 3.06과 합(3.067), ABC→D의 MCIL 평균 길이 0.31과 합(0.319)이 다른 이유.
5. 표 7 작업별 평균(GR-1 92.1%)과 헤드라인 94.9%의 가중치 차이.
6. 표 7의 "rotate blue block right" GR-1 값(94.9%)이 표 1 헤드라인과 같은 이유.
7. 파라미터 수 195M과 46M의 기준(인코더 크기 포함 여부).
8. 1% 언어 주석 데이터의 구성(궤적 수 22,966과 "1%"의 관계).
9. 사전학습 계산 비용(GPU 시간).
10. `GR1-Manipulation/GR-1` 저장소와 저자 조직의 관계.
