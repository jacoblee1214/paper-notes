핵심 요약

  1. 무엇을 하는가: VLA가 텔레옵 시연의 느린 속도를 물려받는 문제를, 이웃 행동을 합치는 시간 양자화(q = 2)를 국면에 따라 켜고 끄는 방식으로 푼다. GR00T N1.5의 공유 action expert에 모드별 decoder 4개를 달고, LVLM이 단 quantizability 점수로 학습한 judge와 라우터가 매 추론마다 모드를 고른다.
  2. 표 내부는 정확히 맞는다: ES를 SR·TPR·t_max만으로 다시 계산하면 36칸이 ±0.005 안에서 재현되고, Table 5의 24개 평균은 PnP 8 + Others 16 가중 평균과 같다. 실물 수치 주장, Fig. 1(b)의 다섯 점(6개 과제 단순 평균)도 모두 맞는다.
  3. 우위는 "덜 실패하면서 충분히 빠르다"에서 나온다: t_max = 1500이면 ES의 대부분이 성공률로 정해진다(실패 몫이 기준 T의 55–78%). 성공 시행만 보면 PnP에서 고정 양자화·DemoSpeedUp·SAIL이 모두 더 빠르고, TPR 1위인 칸은 8칸 중 2칸이다. 다만 실패를 14–115 step만 쳐도 ES 1위는 PaceVLA다.
  4. 기준 대비 성공률 차이는 표본 오차 안이다: 과제당 50회로 역산하면 p = 0.48–0.87이다. "유지"는 맞고 "향상"은 아니다.
  5. 재현 정보가 빠져 있다: judge 임계값 δ, 체크 가중치, 과제별 제어 이득을 고른 절차가 없다. 판정 기준은 평가 과제에서 고정 양자화를 돌려 본 결과를 단서로 Claude가 다듬었다. toy에서는 제어 이득만으로 고정 양자화의 성패가 갈렸다.
  6. 구현 가능성: 코드·라벨·체크포인트가 없어 그대로는 재현할 수 없다. 골격(모드별 decoder + 라우터 + judge)은 짧지만, 라벨 파이프라인(과제별 사전 실행 + LVLM 전체 라벨링)과 GR00T 미세조정(CUDA GPU 40 GB 이상 권장)이 장벽이다. 이 맥에서는 toy와 재계산까지 했고, 작은 정책 실험은 torch(MPS) 설치가 필요하다.

1. Abstract (한 줄 요약과 주장)

한 줄 요약: 텔레옵 시연을 그대로 따라 하는 VLA는 사람이 조심스럽게 움직인 속도까지 물려받습니다. PaceVLA는 이웃한 행동을 합쳐 명령 수를 줄이는 **시간 양자화(temporal action quantization)**를, 정밀한 구간에서는 끄고 여유 있는 구간에서만 켭니다. 이를 위해 GR00T N1.5의 action expert에 모드별 출력 decoder 네 개를 달고, LVLM이 단 "양자화해도 되는가" 점수로 학습한 판정기(judge)와 라우터가 매 추론 step마다 모드를 고릅니다.

논문이 내세우는 기여는 세 가지입니다(Sec. 1).

  1. 텔레옵 시연에서 물려받은 세밀한 실행 패턴을 VLA 비효율의 주요 원인으로 짚었습니다.
  2. 모드별 decoder, quantization judge, context 조건 라우터로 된 가벼운 구조를 제안했습니다.
  3. 시뮬레이션 벤치마크 3종과 실물 과제 6개에서, 기준 VLA와 고정 양자화보다 성공률과 효율의 균형이 낫다고 보고합니다. 기준 대비 최대 1.8배 빠르고, ALLEX 컨베이어 과제에서는 처리량이 1.75배입니다.

2. Method

2.1 전체 구조 (Fig. 2)

관측(카메라, 언어, 고유수용 상태) → VLM(고정) → 조건 특징 Φ_t
        │
        ├─ 평균 풀링 → quantization judge J_ψ → 점수 ≥ δ 이면 "양자화 그룹", 아니면 "세밀 그룹"
        │                router (MLP)        → 그룹 안에서 모드 k 선택 (α_t)
        ▼
공유 action expert (DiT, flow matching) — 노이즈 행동 길이 T_k
        ▼
모드별 MLP decoder D_k → T_k개 명령 (H_k개 시연 step을 덮음, q_k = H_k / T_k)

모드는 K = 4개입니다(부록 C.3, Table 8·9).

세밀 모드 (q = 1) 양자화 모드
RoboCasa, DexJoCo, Franka, OpenArm (16, 16), (8, 8) (16, 8), (8, 4) → q = 2
LIBERO (16, 16), (8, 8) (16, 9), (8, 5) → q = 1.78, 1.6
ALLEX (24, 24), (12, 12) (24, 12), (12, 6) → q = 2

따라서 "적응형 시간 해상도"는 연속 값이 아니라 q ∈ {1, 2} 중 하나를 고르는 이진 선택에, 예측 구간 두 가지를 곱한 것입니다. 명령 수로 따진 이론 최대 속도는 2배입니다.

2.2 시간 양자화 규칙 (Sec. 3.1, 부록 A)

  • H개 시연 행동을 거의 같은 크기의 T개 연속 블록으로 나누고, 블록마다 명령 하나를 만듭니다.
  • 절대 행동(DexJoCo, 실물 관절 위치): 블록의 마지막 명령만 남깁니다(식 5). 끝점은 보존되고 중간 경유점은 사라집니다.
  • delta 자세 행동(RoboCasa, LIBERO): 이동은 고정 좌표계에서 더하고, 회전은 SO(3)에서 합성하고(식 6), 그리퍼는 마지막 값을 씁니다. 정규화된 행동은 제어기 좌표로 되돌려 합친 뒤 다시 정규화합니다.

2.3 공유 action expert + 모드별 decoder (Sec. 3.2)

action encoder와 DiT는 모든 모드가 공유하고, 모드마다 출력 MLP decoder D_k만 따로 둡니다. 모드 k는 길이 T_k의 노이즈 행동 열을 처리합니다. 학습 때는 K개 모드의 flow matching 손실(식 1)을 모두 계산합니다. 모드마다 노이즈와 flow 시간을 따로 뽑고, 길이가 다른 목표는 마스크로 평균합니다.

2.4 Quantizability 지도와 모드 선택 (Sec. 3.3, 부록 C.5, E)

  • 그룹 선택: judge가 낸 점수가 임계값 δ 이상이면 양자화 그룹, 아니면 세밀 그룹을 씁니다. δ의 값은 논문에 없습니다.
  • 모드 선택: 라우터 확률 α_t가 그룹 안의 모드를 고릅니다.
  • 점수 라벨 만들기:
    1. 과제마다 고정 양자화를 걸어 실행해 보고, 과제별 성공률을 단서로 씁니다.
    2. 그 단서와 시연 예시로 Claude Opus 5가 벤치마크별 판정 기준과 프롬프트를 만듭니다. 기준은 4–6개의 시각 체크로 쪼개고, 각각 1–5점으로 매깁니다.
    3. Gemini 3.8 Flash가 데이터셋 전체의 chunk마다 첫 프레임 영상, 지시문, 시연에서 계산한 사실을 보고 체크별 점수를 답합니다.
    4. 고정 가중치로 합쳐 [0, 1]로 정규화한 것이 라벨 y입니다. 가중치와 "계산한 사실"의 내용은 공개되지 않았습니다. 부록 E에 벤치마크별 프롬프트 6개가 원문으로 실려 있습니다.

2.5 학습 목표 (Sec. 3.4, 식 2–4)

L_policy = E[ Σ_k w_k ℓ_k + λ_sup KL(r ‖ α) + λ_bal L_bal ],   r_k ∝ exp(−ℓ_k / β)       (식 2)
L_conf   = E[ (J_ψ(sg(Φ_t)) − y)² ]                                                   (식 3)
L        = L_policy + λ_conf L_conf                                                    (식 4)
  • 라우터는 "예측 오차가 작은 모드"를 목표 분포 r로 삼아 KL로 학습합니다. 학습 가중치 w는 α와 균등 분포를 섞은 것이고, L_bal은 decoder 하나로 쏠리는 것을 막습니다.
  • judge는 VLM 특징에 stop-gradient를 걸고 라벨 y를 회귀합니다.
  • 설정값(Table 7): λ_sup 0.1, λ_bal 0.05, λ_conf 0.1(앞의 두 값은 5k iteration 동안 0에서 선형 증가), w 온도 0.5, r 온도 0.3, 최소 모드 확률 0.05, AdamW lr 1e-4, 60k iteration, VLM 고정.

2.6 제어기 설정 (Sec. 3.5, 부록 C.3·C.4)

양자화된 명령은 한 주기에 더 큰 변화를 요구하므로 제어기 이득을 올립니다.

  • 시뮬레이션: OSC 위치 이득 k_p를 과제마다 {150, 300, 600} 중에서 고르고, 모든 가속 방법에 같은 과제별 이득을 씁니다. 기준 GR00T N1.5만 기본 이득(150)을 씁니다. 이득을 어떤 절차로 골랐는지는 적혀 있지 않습니다.
  • 실물: Franka는 Cartesian 임피던스 강성 600 N/m(쌓기는 800), 그리퍼는 최대 속도와 최소 힘을 씁니다. OpenArm은 관절 PD 이득 K_p ∈ {240, 480} Nm/rad입니다.

3. Experiments

3.1 설정 (Sec. 4.1, 부록 B·C)

  • 시뮬레이션:
    • RoboCasa-Kitchen 24개 과제(과제당 시연 300개, PnP와 Others로 나눠 보고)
    • LIBERO 4개 suite(Short = Spatial·Object·Goal 평균, Long)
    • DexJoCo 한 팔 과제 6개
    • 백본은 GR00T N1.5와 RLDX-1-IMG 두 가지입니다.
  • 실물:
    • Franka + 그리퍼: Pick-and-Place, Air Fryer, Stack Cup
    • OpenArm 양팔 + 6-DoF 손: Table Sweeping, Pump and Scrub
    • ALLEX 휴머노이드 + 15-DoF 손: Conveyor Package Handling
    • 시연 수는 과제마다 50–320개이고, 백본은 GR00T N1.5뿐입니다.
  • 기준선:
    • 고정 양자화(Tang et al. VLASH): 기준 모델 출력을 추론 시 q = 2로 합칩니다.
    • DemoSpeedup: 엔트로피 기준으로 시연을 다운샘플링합니다.
    • SAIL: 저자들이 재구현했습니다. end-effector delta로 바꾸고 action scheduling은 껐습니다(부록 C.6).
  • 지표:
    • TPR (SAIL을 따름, 식 7) = 평균(S_i/t_i − (1−S_i)/t_max). t_i는 실행한 행동 step 수입니다.
    • ES (식 8) = T_base / T, T = L + (1−SR)/SR · t_max. L은 성공 시행의 평균 step이고, 실패 한 번에 t_max(RoboCasa·DexJoCo 1500, LIBERO 220–520)를 매깁니다.
    • 실물: 성공률(부분 점수 0.5 포함, 32회), 완전 성공 시행만의 평균 시간, ALLEX는 분당 처리 패키지 수(5회 × 10개)입니다.

해석 (재계산은 04_claim_verification.md §3과 analysis/table_check.py):

  • 표 내부는 정확히 맞습니다. ES를 SR, TPR, t_max만으로 다시 계산하면 36칸이 모두 ±0.005 안에서 재현됩니다(성공 궤적 길이는 TPR에서 조화평균으로 복원). Table 5의 "24개 과제 평균"(66.9, 2.75)도 PnP 8개와 Others 16개의 가중 평균(66.93, 2.747)으로 정확히 나옵니다. 과제 구성은 GR00T 저장소의 RoboCasa 표에서 확인했습니다.
  • ES는 성공률이 지배합니다. t_max = 1500이면 기준 모델의 "성공 1건당 step"에서 실패 몫이 PnP 78%, Others 65%, DexJoCo 55%입니다. 그래서 ES 순위는 속도보다 "성공률을 얼마나 지켰나"로 갈립니다.
  • 성공한 시행만 보면 기준선이 더 빠릅니다. t_max = 0(실패 비용 없음)일 때 PnP에서 고정 양자화 1.48, DemoSpeedUp 1.47, SAIL 1.44, PaceVLA 1.35입니다(03 §1.2). PaceVLA의 장점은 "더 빠르다"가 아니라 "덜 실패하면서 충분히 빠르다"입니다. 다만 순위가 뒤집히는 t_max는 14–115 step이라, 실패를 조금만 비용으로 쳐도 PaceVLA가 ES 1위입니다.
  • TPR은 1위가 아닌 칸이 많습니다. Table 1의 8칸 가운데 PaceVLA의 TPR이 가속 방법 중 1위인 칸은 2개뿐입니다. ES는 7칸, SR은 8칸에서 1위입니다. 굵게 표시된 칸만 보면 이 차이가 잘 드러나지 않습니다.
  • 기준 대비 SR 차이는 표본 오차 안입니다. 과제당 50회로 보면(시행 수 격자 검사로 확인) PnP 55.0 vs 52.3은 p = 0.48, Others 72.9 vs 72.4는 p = 0.87, DexJoCo 77.3 vs 76.3은 p = 0.85입니다. "성공률을 유지한다"는 주장과는 맞지만, "성공률도 오른다"고 읽으면 안 됩니다. 기준선 대비로는 유의합니다(Others에서 고정 양자화 대비 p = 3.6×10⁻⁵).

4. Limitations

4.1 저자가 밝힌 한계

judge와 라우터 때문에 추론이 조금 느려집니다(1.05배). 실패는 대부분 인식 한계에서 오므로, 깊이나 촉각 같은 더 나은 감지가 필요하다고 봅니다(부록 D.3).

4.2 분석하면서 추가로 발견한 한계와 의문점

  1. 판정 기준이 평가 결과를 보고 만들어졌습니다. quantizability 기준은 "과제별로 고정 양자화를 걸어 본 성공률"을 단서로 Claude가 다듬은, 벤치마크별 수작업 프롬프트입니다(부록 C.5, E). 저자들은 성공률을 판정기의 학습 목표로 쓰지 않았다고 밝힙니다. 그래도 평가 과제의 결과가 라벨 설계에 들어갔고, 기준선에는 이런 과제별 조정이 없습니다. 새 과제에 적용하려면 이 반복을 다시 해야 합니다.
  2. 재현에 필요한 값이 빠져 있습니다. judge 임계값 δ, 체크별 가중치, 프롬프트에 넣는 "계산한 사실", 과제별 k_p를 고른 절차, 시뮬레이션 시행 수, 시드가 없습니다. 시행 수는 표 수치에서 과제당 50회로 역산했습니다.
  3. 제어 이득이 교란 변수입니다. 가속 방법들은 과제별로 조정한 이득을 쓰고, 기준 모델은 기본 이득을 씁니다. 우리 toy에서는 추적 지연만 있는 과제라면 이득을 kp 150에서 300으로 올리는 것만으로 고정 q = 2의 성공률이 0에서 0.985로 바뀌었습니다(03 §2). 논문 과제에는 추적 지연 말고도 접촉 같은 실패 요인이 있으므로 toy를 그대로 옮길 수는 없습니다. 그래도 이득 조정 없이 같은 비교를 해야 기여를 분리할 수 있습니다.
  4. 빠진 기준선이 있습니다. "양자화 decoder를 학습시키고 항상 그것만 쓰기"가 없습니다. judge를 뺀 ablation은 라우터가 네 모드를 다 고르는 설정이라 이것과 다릅니다. 고정 양자화 기준선은 학습 없이 기준 모델 출력을 합친 것이라, 전용 decoder의 이득과 judge의 이득이 섞입니다.
  5. 실물 시간은 완전 성공 시행만의 평균입니다. 실패 비용이 빠져 있고, 성공한 시행만 고르는 선택 효과가 방법마다 다릅니다. 실물에는 시뮬레이션의 ES에 해당하는 지표가 없습니다(컨베이어 처리량은 예외).
  6. "적응형 해상도"의 범위가 좁습니다. 실제 선택지는 q ∈ {1, 2}(LIBERO는 1.6, 1.78)와 예측 구간 두 가지입니다. 이론 최대 속도는 2배이고, 실물 속도 1.5–1.8배는 그 상한에 가깝습니다.
  7. 기준선 구현이 원래와 다릅니다. SAIL은 핵심 장치인 action scheduling을 끄고 delta 행동으로 바꿔 재구현했습니다. DemoSpeedup의 적용 방법은 따로 설명되지 않았습니다.
  8. 컨베이어 과제 설명이 서로 맞지 않습니다. 본문은 "도착한 패키지를 라벨이 앞을 보게 돌려 놓는다", 부록 C.1은 "컨베이어에서 집어 하역 테이블에 놓는다", 지시문은 "바코드를 위로 해서 컨베이어 위에 놓는다"입니다. 또 ALLEX만 비동기 추론과 real-time chunking을 씁니다(부록 C.6).
  9. 코드와 라벨이 공개되지 않았고, 라벨링 비용도 없습니다. Gemini API로 데이터셋 전체의 chunk마다 영상 2–3장씩 질의한 비용이 보고되지 않았습니다.

1. TPR과 ES는 같은 시행 데이터의 두 요약이다

식 7과 8을 나란히 쓰면 다음과 같습니다(SR = s, 성공 시행의 step 수 t_i).

TPR = (1/N) Σ [ S_i / t_i − (1 − S_i) / t_max ] = s · E[1/t | 성공] − (1 − s)/t_max
ES  = T_base / T,   T = L + (1 − s)/s · t_max,   L = E[t | 성공]

첫 식에서 성공 궤적 길이의 조화평균 L_h = s / (TPR + (1 − s)/t_max)를 복원할 수 있습니다. L 자리에 L_h를 넣어 ES를 다시 계산하면 Table 1·3의 36칸이 모두 ±0.005 안에서 맞습니다(LIBERO Short는 t_max 220·280·300의 평균으로 근사). 따라서 두 지표는 내부적으로 일관되고, 성공 시행의 길이 분산도 작다고 볼 수 있습니다.

  • 실제 과제에는 접촉 역학, 물체 미끄러짐, 시각 피드백 지연처럼 이득으로 해결되지 않는 정밀도 요구가 있습니다. 논문에서 이득을 조정한 뒤에도 고정 양자화의 성공률이 떨어지는 것(Air Fryer −28.2%p)은 그런 요인 때문으로 보입니다. 이 toy는 메커니즘 하나만 보여 주는 것입니다.

q θ = 0.01 rad 0.03 rad 0.1 rad
2 0.0025° (0.3%) 0.022° (0.9%) 0.25° (3.1%)
4 0.0046° (0.4%) 0.040° (1.3%) 0.46° (4.2%)

4. 실물 결과의 구조

  • Fig. 1(b) = 6개 과제의 단순 평균입니다. 성공률(부분 점수 포함)과 속도(다섯 과제는 완전 성공 시행의 시간비, 컨베이어는 처리량비)를 섞어 평균했습니다. 판독값과 재계산값의 차이는 성공률 ±0.1%p, 속도 +0.02×이고, 속도 쪽 편차는 다섯 점에서 같은 방향이라 판독 눈금 오차로 보입니다.
  • PaceVLA와 고정 양자화의 시간비가 0.92–1.10입니다. PaceVLA가 세밀 모드로 돌아가는 구간이 짧다는 뜻입니다. 명령 수가 시간에 비례한다고 단순화하면 양자화 모드 비율은 Pick-and-Place 74%, Air Fryer 81%, Stack Cup 90%, Table Sweeping 67%, Pump and Scrub 79%입니다. 추론 지연과 안착 시간이 있으므로 실제 비율의 상한 추정으로 읽어야 합니다.
  • 시간은 완전 성공 시행만 셉니다. 성공률이 낮은 방법일수록 쉬운 초기 조건의 시행만 남아 시간이 짧게 측정될 수 있습니다. 실물에도 ES 같은 실패 비용 포함 지표가 있었다면 기준선들의 속도 이점은 더 줄었을 것입니다.

  • SO(3) toy(03 §3): q = 2에서 회전 벡터 단순 합과 SO(3) 합성의 차이는 스텝당 0.03 rad이면 0.02°입니다. 올바른 처리지만 성능을 가를 요소는 아닙니다.
  • 실물(03 §4): PaceVLA의 시간은 고정 양자화의 0.92–1.10배입니다. 시간을 완전 성공 시행만으로 재서 실패 비용이 빠져 있습니다.

Chronos Policy (chronospolicy/) 둘 다 "정책이 시간을 어떻게 다루는가"의 문제입니다. Chronos는 관측과 행동의 물리 시각을 time-aware RoPE로 넣어 센서 주기·지연의 변화에 강하게 만듭니다. PaceVLA는 같은 시간 축에서 명령 간격 자체를 바꿉니다. PaceVLA의 양자화 모드는 행동 하나가 덮는 실제 시간을 2배로 바꾸는데, 정책은 그 차이를 decoder 번호로만 압니다. Chronos식으로 행동마다 실행 시각을 넣으면 decoder 여러 개 대신 연속적인 실행 간격을 표현할 수 있을 것입니다(내 해석).
AW-0 (agentic_wam/) AW-0은 코드·subgoal 계획 스트림을 행동과 함께 생성합니다. PaceVLA의 judge가 보는 것도 "지금 어떤 국면인가(도달, 쥐기, 운반, 놓기)"입니다. 계획 스트림이 이미 있는 정책이라면 별도의 LVLM 라벨 없이 국면 정보를 judge 입력으로 쓸 수 있습니다(내 해석).
Hydra-0 (hydra0/) 행동 표현을 바꾸는 연구입니다. Hydra-0은 공간 표현(이미지 평면의 점 궤적)을 바꾸고, PaceVLA는 시간 해상도를 바꿉니다.
DexPolicy (dexpolicy/) 둘 다 "정밀한 국면과 여유 있는 국면은 다르게 다뤄야 한다"는 문제의식입니다. 다만 DexPolicy는 RL 학습 중의 탐색 잡음을 학습 step 함수로 줄이고, PaceVLA는 추론 시 실행 해상도를 상태 함수로 바꿉니다.
Contact-Grounded Policy (contact_grounded_policy/) PaceVLA의 실패 분석(부록 D.3)은 "접촉 영역이 가려져서"라고 결론짓고 촉각 입력을 제안합니다. CGP처럼 촉각을 쓰는 정책에서는 접촉 시작 신호를 judge 입력으로 직접 쓸 수 있습니다.

주제 관련성 근거 수준
AWE: Automatic Waypoint Extraction (Shi, Sharma, Zhao, Finn, 2023) 시연을 "선형 보간으로 복원 가능한 최소 waypoint"로 압축합니다. 시간 해상도를 구간마다 다르게 두는 비균일 양자화의 데이터 쪽 버전입니다. PaceVLA의 LVLM 라벨 대신 재구성 오차 기준으로 "합쳐도 되는 구간"을 정하는 대안이 됩니다. 내 사전 지식. 서지 확인 필요
Options / macro-action (Sutton et al., 1999) 여러 step을 하나의 결정으로 묶는 시간 추상화의 고전 틀입니다. PaceVLA의 모드는 길이가 정해진 option입니다. 내 사전 지식
사건 기반 제어·적응 샘플링 (제어 이론) 오차가 커질 때만 명령을 갱신하는 고전 기법입니다. judge 대신 추적 오차나 접촉 사건으로 세밀 모드를 켜는 규칙 기반 대조군이 될 수 있습니다. 내 해석
Bidirectional Decoding (BID) chunk를 샘플링할 때 이전 chunk와의 일관성과 미래 예측을 함께 봐서 chunk 길이의 trade-off를 다룹니다. 내 사전 지식. 서지 확인 필요
