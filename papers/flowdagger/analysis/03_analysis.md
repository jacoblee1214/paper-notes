# 03. 수치 재계산, 검정, 일관성 검사

모든 수치는 `analysis/recompute.py`(수 초, CPU, numpy·scipy만)가 계산하고 `analysis/recompute_results.json`에 저장합니다. 이 문서의 점검 항목은 **V1–V16**(보고 수치 재계산), **K1–K4**(우리가 만든 작은 numpy 실험), **C1–C10**(주장 판정)입니다. 논문 PDF 표를 손으로 옮겨 스크립트에 넣었고, 옮긴 값은 본문 표와 프로젝트 페이지의 같은 표가 일치함을 확인했습니다(프로젝트 페이지의 표 1–4는 PDF와 같은 값).

## 0. 입력과 가정

- **시행 수.** 표 1–3의 캡션은 아니고 §5.1 끝 문장이 "3 시드 × 25 롤아웃 평균"입니다. 표 3과 Fig. 3·4도 25 롤아웃을 씁니다. 표 4는 30 롤아웃(캡션), 부록 B의 Fig. 5·6은 점마다 15 롤아웃, 표 5의 하류 성공률은 3 시드 × 25 롤아웃(캡션)입니다.
- 시행 수가 모호한 칸은 **n = 25(단일 시드)와 n = 75(3 시드 합침)** 두 경우를 모두 계산하고, 값의 격자(1/25 = 0.04 간격, 1/75 = 0.0133 간격)가 어느 쪽과 맞는지로 추론했습니다. 3 시드를 합칠 때 시드 간 상관과 과제 내 군집은 무시합니다(p값은 낙관적).
- 검정: Fisher 정확 검정(양측), Wilson 95% 구간, 과제 단위 짝 비교(t, 윌콕슨, 부호 검정, 과제 부트스트랩). 다중 비교 보정은 Holm.
- 표 4는 소수 둘째 자리 표기이고, 30회에서 가능한 값(k/30)과 비교할 때 **반올림 또는 내림** 둘 다 허용해 점검했습니다.

## 2. 표 2: 정책군 비교 (π0.5 대 Cosmos-Policy)

### V4. 재계산과 교차 검사 (모두 일치)

- π0.5: 기준 평균 0.531, FlowDAgger 0.789, Δ +0.257. 보고 0.53, 0.79, +0.26. 과제별 Δ(0.25, 0.13, 0.23, 0.55, 0.15, 0.33, 0.16) 모두 일치.
- Cosmos-Policy: 기준 0.526, FlowDAgger 0.737, Δ +0.211. 보고 0.53, 0.74, +0.21. 과제별 Δ(0.40, 0.16, 0.28, 0.24, 0.12, 0.08, 0.20) 일치.
- π0.5 열은 표 1의 같은 과제 값과 모두 일치합니다. 표 2의 "Mean 0.79"는 7개 과제 평균이고 표 1의 12개 평균은 0.78입니다(서로 다른 평균이므로 모순 아님).
- **Cosmos 열의 14개 값이 모두 0.04의 배수(k/25)입니다.** 표 2 캡션과 본문은 시행 수를 말하지 않고, §5.1은 "3 시드 × 25"를 공통 프로토콜로 둡니다. Cosmos 열은 단일 시드 25회일 가능성이 큽니다. 같은 π0.5 열(표 1과 동일)은 3 시드 격자입니다.

### V5. Cosmos 과제별 유의성 (n = 25 가정)

기준 대비 FlowDAgger의 Fisher p: Assembly 0.004, Bin Picking 0.38, Box Close 0.089, Dial Turn 0.15, Hand Insert 0.46, Lever Pull 0.77, Stick Push 0.098. **7과제 중 1개만 p < 0.05**. 7과제를 합치면(각 25회, 175회) 92/175에서 129/175로 p = 6e-5. 7개 모두 방향은 개선입니다. 합산 증거는 강하고 과제별 증거는 약합니다.

| 단계별 FP (M = 5) | 0.87 (65/75) | 0.96 (72/75) |

- Assembly에서 단계별 FP 대 명시적 역은 p = 2e-4로 유의하지만, 대 Adam은 p = 0.28, 대 궤적 FP는 p = 0.20으로 **구분되지 않습니다**. Hammer에서는 세 대안 모두 p < 4e-4로 유의합니다. "Accurate inversion sets a strictly higher ceiling"은 Hammer에서는 잘 맞고 Assembly에서는 명시적 역에 대해서만 맞습니다.
- "명시적 역이 기본 정책 아래(0.59 대 0.64)로 만든다"의 차이는 p = 0.81입니다(기준 16/25 대 44/75). 노이즈 안입니다.
- **표 5의 기본 설정(단계별 FP, M = 5)과 표 1의 FlowDAgger가 같은 설정이면 Hammer가 0.96 대 0.84**입니다. 72/75 대 63/75에서 p = 0.027(표 1의 0.84를 k/25로 보면 p = 0.063). Assembly는 0.87 대 0.89로 일치합니다. 표 5는 전문가 청크 29개를 같은 방식으로 역변환하는 별도 프로토콜일 수 있으나 논문은 이 차이를 설명하지 않습니다.

### V16. 평가 수 정의와 시간 모델

- **본문 §4.1은 비용을 `K·M`(= 50, M = 5)번의 v 평가라고 쓰지만, 표 6은 40(M = 3), 60(M = 5), 110(M = 10)이고 이는 K(M+1)입니다.** 식 (3)의 시작점 x_k^(0) = x_{k+1}이면 첫 반복이 명시적 역 한 단계와 같아 M번 평가가 맞습니다. 공식 코드는 명시적 역 한 번 + FP M번이라 K(M+1)입니다(`04` D8). 논문 식과 코드가 반복 한 번만큼 다릅니다. 궤적 FP(k = 5, 20)의 110, 410은 K + 2Kk와 일치합니다.
- **궤적 FP의 시간은 모델 평가 수가 아니라 JIT 호출 수에 비례하는 것으로 보입니다.** 시간 = c × (호출 수) + e × (평가 수) 두 계수 선형 적합(여섯 개 측정, 호출 수는 Euler 2, 단계별 2, 궤적 2k + 2로 가정)에서 c ≈ 99 ms/호출, e ≈ 3.6 ms/평가이고 예측 대 실측은 270/315, 377/405, 448/456, 626/614, 1621/1662, 5672/5657 ms입니다. 같은 모델에서 궤적 FP(k = 5)를 2번 호출로 계산하면 626 ms로 단계별 FP(M = 10) 614 ms와 같아집니다. 공식 코드의 궤적 FP는 호출마다 접두(VLM) KV 캐시를 다시 계산하는 별도 JIT 함수 호출이라(`04` D8) 이 해석이 코드와 맞지만, 우리는 측정하지 않은 추정입니다.
- 결론: "같은 평가 수에서 2.7배 빠름"은 알고리즘 성질이 아니라 구현 방식(접두 캐시 재사용 여부)이 크게 기여한다고 읽는 것이 안전합니다. MSE의 우위(15배)는 구현과 무관합니다.

## 7. 우리가 만든 작은 실험 (numpy, CPU)

핵심 주장 하나만 검증합니다: **적은 단계(K = 10)에서 단계별 고정점이 명시적 역이나 궤적 단위 고정점보다 정확하다**(§4.1, 표 5). 흐름장은 무작위 은닉층 MLP(D = 32, 은닉 64, tanh)의 속도장이고 첫 인수에 대한 립시츠 상수의 상한을 L로 맞췄습니다. 목표 a\*는 기본 정책 출력에 작은 교란(전문가 행동이 기본 지지 집합에서 조금 벗어남)을 더한 것입니다. 30회 평균. 실제 π0.5가 아닙니다.

### K1. 방식별 복원 오차 (L = 3, K = 10)

| 방식 | MSE |
|---|---|
| 명시적 역 | 6.3e-4 |
| 궤적 FP k = 1 / 5 / 20 | 6.2e-7 / 5.7e-6 / 7.3e-4 |
| 단계별 FP (코드식: 명시적 역 + M회) M = 1 / 3 / 5 / 10 | 1.3e-6 / 7.6e-12 / 5.3e-17 / 2.9e-29 |
| 단계별 FP (식 3 시작점) M = 1 / 3 / 5 / 10 | 6.3e-4 / 3.2e-9 / 1.9e-14 / 7.5e-27 |

- 단계별 FP는 모든 M에서 명시적 역보다 낮고, M이 늘면 기하급수로 줄어듭니다(식 3의 수렴 주장과 방향이 같음). M = 1(식 3 시작점)은 명시적 역과 정확히 같은 값입니다(6.3e-4): 식 (3)의 M번째 값은 코드식의 (M − 1)번째 값과 같다는 구조적 사실입니다.
- **궤적 FP는 k가 늘면 좋아지지 않고 k = 20에서 명시적 역 수준으로 되돌아갑니다**(진동). 논문 부록 B.2의 "k를 5에서 20으로 올려도 개선 없음"과 같은 방향이고, 우리 toy에서는 악화까지 보입니다.

### K2. 립시츠 상수 스윕 (K = 10, Δt·L = 0.1–2.0)

| Δt·L | 명시적 역 | 궤적 FP (k = 5) | 단계별 FP (코드식, M = 5) |
|---|---|---|---|
| 0.1 | 9.0e-6 | 1.1e-9 | 2.2e-23 |
| 0.3 | 6.7e-4 | 6.7e-6 | 6.8e-17 |
| 0.6 | 1.1e-2 | 2.0e-3 | 8.5e-13 |

| 1.2 | 0.21 | 0.72 | 1.6e-8 |
| 2.0 | 1.7 | 8.3 | 2.3e-5 |

- 궤적 FP는 Δt·L ≈ 0.9부터 명시적 역보다 나빠집니다. **단계별 FP는 Δt·L = 2에서도 수렴합니다.** 논문 식 (3) 아래의 "Δt·L < 1이면 수축"은 충분조건이고, 상한 L은 실제 국소 기울기보다 크므로 이 조건을 넘어도 여전히 작동합니다. 다만 이 toy의 흐름장은 매끄럽습니다. 논문 §6이 말하는 "나쁜 조건의 생성 동역학"에서 FP가 깨지는지는 이 toy로 알 수 없습니다.

- 우리 toy에서 단계별 FP는 기계 정밀도 근처까지 내려갑니다. 반면 **논문 표 6은 M = 5에서 10으로 가도 MSE가 0.00168에서 0.00147에 그칩니다.** 실제 모델의 바닥이 FP 수렴 문제가 아니라 다른 오차원(bf16 정밀도, 전문가 청크의 패딩 구성, 기본 모델의 비매끄러움 등)에서 온다는 뜻입니다. 우리는 원인을 가려내지 못했습니다. 이 바닥은 공식 코드의 청크 제외 임계값 0.001(`04` D9)보다 큽니다.

### K4. 공식 코드의 DCT 기저 압축 (`noise_basis_k = 10`, 길이 50)

- K = 10인 DCT-II 기저의 열은 정규직교이고, N(0, I) 백색 잡음의 에너지 중 **20%만** 담습니다(K = 5는 10%, 20은 40%, 50은 100%). 계수를 N(0, 1)로 뽑아 기저로 펼치면 행당 분산이 0.2입니다(코드는 첫 훈련 롤아웃의 잡음을 이렇게 만듭니다, `04` D11).
- 시간으로 매끄러운(랜덤워크) 신호는 K = 10에서 잔차 에너지가 2.8%이고 백색 잡음은 79.7%입니다. 역변환된 w\*가 백색에 가까운지(대부분 잃음) 저주파인지(거의 보존)는 실제 π0.5 없이 알 수 없습니다. 압축이 행동에 얼마나 영향을 주는지는 이번에 측정하지 못했습니다.
